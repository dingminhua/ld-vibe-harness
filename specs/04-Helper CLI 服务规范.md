## 1. 价值判断

本文的价值，是让 AI Agent 通过一个稳定入口获得当前事项实际可用的 LDVH 信息与确定性能力，同时保留工作对象、来源、已检查范围、缺口和未完成部分。这样可以避免 AI 直接理解多个内部模块、把工具成功误当成工作完成，或者由不同环境入口各自改写同一服务语义。
本文承接 00 §7 的“AI 执行者主动调用”交付方式，定义 Helper CLI 这一基础服务形式的公开契约，不把它增列为语义构成要素。

本文主要服务：

1. V1 快速定位：发现并区分当前已定义的公开操作、实际实现、当次可调用范围及其输入入口；
2. V2 充分理解：把任务、工作对象、规则、事实、行动模板、能力结果和来源联系起来；
3. V3 边界识别：区分能力存在、当次可调用、结果成立、部分结果、拒绝和缺口；
4. V4 稳定推进：通过统一机器接口调用确定性读取、检查和受控操作；
5. V5 据实判断：使响应结论不超出当次输入、来源和实际执行结果；
6. V6 工作接续：让结果、来源、变化和未完成范围可以继续被 AI 消费；
7. V7 清晰沟通：为需要 Human 处理的拒绝、歧义和待决定事项保留明确交还信息。

Helper CLI 是 AI 的基础服务入口，不是所有普通求解的前置仪式。只有当前事项需要 LDVH 已定义的信息或能力时才调用相应服务；没有适用能力或具体规则时，不限制 AI 的普通求解路径。

## 3. 职责边界

本文负责定义：

1. Helper CLI 的公开入口、公开操作标识和机器输出共同约束；
2. 当前任务、工作对象定位符和必要上下文如何进入请求；
3. 如何发现并区分已经定义、已经实现、当次可调用、部分可用和不可用的能力；
4. 响应如何保留结果、来源、对象范围、披露层级、缺口、变化、回读和未完成范围；
5. 无变化、部分结果、拒绝、能力不可用、无效请求和执行错误的服务级语义；
6. 读取类调用与可能改变状态的调用之间的公开边界；
7. Helper 报告具体规则判断时必须保留的规则身份、对象、范围、依据和检查状态；
8. 当前任务相关信息和关联视图如何保留对象身份、关系来源、遗漏范围与派生边界；
9. 环境入口调用同一 Helper 服务时不得改变的请求与响应语义。

本文不定义：

1. 具体规则、事实类型、事实字段、状态、行动模板或 Human Gate 的领域语义；
2. 某项来源规则是否适用于当前事项，以及适用后应执行的具体义务；
3. Code 的模块、依赖、解析算法、缓存、索引、库、目录或测试实现；
4. 某个外部环境的事件、payload、安装位置或结果映射；
5. Web 的读取、呈现或交互；
6. 尚未由当前正式来源定义、尚未实现或尚未验证的能力。

## 4. 适用范围

本文适用于：

1. AI Agent 直接调用 Helper CLI；
2. Code 新增或修改公开 Helper 操作、参数、机器输出、退出语义、通用发现或当次操作可用性结果；
3. Helper 读取规则、事实或行动模板，调用确定性能力，或者请求受控状态变更；
4. Helper 返回部分结果、拒绝、不可用、错误、来源冲突或未检查范围。

内部函数、进程内调用和实现测试只有在承接或验证公开契约时受本文约束。纯内部重构若不改变公开请求、响应和可观察行为，不因本文单独进入 Human Gate。

## 5. 公开服务入口

### 5.1 入口与输出形式

Helper CLI 的公开可执行入口使用 `ldvh`。机器输出是默认且完整的服务输出，使用 UTF-8 JSON；面向 Human 的文本输出可以作为同一结果的可选呈现，但不得比机器输出拥有更多事实、规则或结果语义。

公开调用至少支持：

```text
ldvh capabilities
ldvh capabilities <operation_key>
ldvh call <operation_key>
```

不带 `operation_key` 的 `capabilities` 用于发现已经由当前规则源定义的公开操作、实现情况和调用所需输入，不对尚未提供的具体请求判断可用性。带 `operation_key` 的 `capabilities` 针对所提供的请求内容检查该操作在当次范围内是否可调用。`call` 通过稳定的 `operation_key` 调用某项公开操作。

所有公开入口读取请求时无条件等待 stdin 到达 EOF。调用方必须保证 stdin 闭合：经管道或重定向供给请求；无请求输入时以 `< /dev/null` 或等价方式闭合。无 tty 且 EOF 不可控的执行环境不得裸调任何入口。调用挂起类故障先按 stdin 未闭合排查，不得直接记为服务不可用。

公开操作标识（Public Operation Identifier）是由定义某项 Helper 公开操作语义的当前来源赋予、用于跨 AI、Code、tests 和环境入口稳定引用同一服务行为的标识，机器字段为 `operation_key`。它在全部当前公开操作中唯一；改名或移动不改变该标识，取消后的标识不得改派给其它操作。Code、tests 和环境入口不得反向创造该身份。已有当前来源但没有实现的操作可以被发现，但不能被调用为可用能力。只有当前来源、实际实现、可复核能力依据和当次条件同时成立的范围，才可以声明为当次可调用。仅有计划、占位符、内部函数或文档名称不得形成公开操作。

公开操作集合只回答 Helper 当前公开提供哪些服务，不回答 AI 被允许执行哪些行动。`operation_key`、`capabilities`、实现注册和当次 `availability` 均不得成为 AI 工具、命令或普通求解路径的白名单；不存在、无效、未实现或当次不可用的 Helper 操作，只能证明 Helper 不能按该公开操作承接请求，不能据此禁止 AI 在 Human 当前指令和适用来源规则允许的范围内使用其它能力继续求解。若另一项实际适用的来源规则把某个 Helper 操作规定为当前行动不可替代的前置条件，该操作不可用时仍按该来源暂停或分流；这种局部效力来自该来源，不来自 Helper 服务目录本身。

`capabilities` 是 Helper 的服务发现入口，不自行取得某个领域操作的 `operation_key`。通用发现响应中的 `operation_key` 为 `null`；针对单项操作检查和 `call` 响应回显请求提供的标识，其是否属于公开操作仍按当前规则源判断。

命令别名、自动补全和文本装饰属于实现便利，不得成为机器调用的唯一入口。公开操作不得要求 AI 知道内部 Python 模块、Web API、厂商环境机制或缓存路径。

本文授权 `helper-cli-request-response-fields` 附件承载上述三个入口的 JSON 输入通道、请求字段、共同响应字段、空值、闭集规则和 `capabilities` 结果结构。具体公开操作的 `arguments` 与 `result` Schema 仍由定义该操作语义的当前来源承担；附件不得替代领域来源。

具体公开操作的当前来源确实需要返回 full-v4 Working Tree 证据时，只能在该操作自身 `result` 的明确 object 字段中，按 `working-tree-test-evidence-fields` 授权附件的当前契约原样嵌入完整 DTO，并由该操作的 `result_contract` 精确回指定义章节。本文和 `helper-cli-request-response-fields` 不复制其字段，不把它增加为 Helper 共同响应顶层字段，也不得改塞进 `verification[].evidence`、`diagnostics[].details`、来源 `details` 或 Human 文本输出。Helper 对 DTO 的紧凑或诊断呈现不得改变其字段、状态、指纹、覆盖边界或 `changes`。

定义一个或多个公开操作的当前来源，必须在正文中使用附件定义的固定 Markdown 表格声明操作标识、摘要、读取或状态变更边界以及输入和结果契约位置。Code 只从当前规则源中的该表格发现领域公开操作；草案、普通示例、内部实现注册表和 tests 不得进入公开操作清单。同一 `operation_key` 重复、声明位置无法解析或契约位置不存在时，暂停受影响操作的发现和调用。

Helper 使用的规则源视图只由 01 §§6.3–6.4 确定。源码或 editable 环境使用导入 Code 所属同一 `working_tree`；不能定位该视图的普通安装只使用同一 Python distribution 内已经完整验证的 `installed_release_snapshot`。Helper 不接受请求字段、`cwd`、环境变量、管辖项目、缓存或同名目录选择规则源，也不得在一种视图失败时回退另一种视图。共同来源和验证证据必须保留实际视图身份；安装快照依赖发行版本与集合摘要时，使用授权附件已经定义的 `version` 和 `details` 字段，不升级或改变共同响应顶层契约。

### 5.2 请求共同内容

公开请求由命令入口和一个 JSON 请求对象共同组成。`operation_key` 由命令位置提供，其余共同内容按操作需要从 JSON 请求对象接收：

| 内容 | 要求 | 边界 |
|---|---|---|
| `operation_key` | `capabilities <operation_key>` 与 `call <operation_key>` 必填；稳定标识实际请求的公开操作 | 由命令位置提供；不编码版本、厂商环境或内部函数名 |
| `task` | 当操作需要理解当前目标时提供简明任务描述 | 只作当次输入，不因进入请求成为稳定事实或规则 |
| `work_object_locators` | 当操作涉及项目或对象专属信息时提供 | 语义服从 02；不得由 Helper 猜测未提供的管辖关系 |
| `arguments` | 按该操作来源契约提供的结构化参数 | 不得通过自由文本绕过领域 Schema 或授权边界 |
| `requested_disclosure` | 需要规范信息时可指定 01 定义的 L0–L4 | 不要求逐层调用；不得请求低层级后据此宣称没有规则 |
| `response_profile` | 可选指定 `compact` 或 `diagnostic`；默认为 `compact` | 只改变重复证据与诊断信息的组织粒度，不得改变领域结果、范围、外层结果、规则含义或状态变化 |
| `observed_context` | 当次环境、工具或调用方可观察且该操作确有需要的补充输入 | 必须保留输入来源；不直接成为稳定事实 |
| `authorization_reference` | 状态变更操作在来源规则要求授权时提供 | 只证明所引用决定及其作用范围，不证明技术结果 |

机器调用从标准输入接收至多一个 UTF-8 JSON 对象；空输入等同空对象。默认标准输出只包含一个完整 JSON 响应对象。无法解析的输入按 `invalid_request` 返回；进程尚未启动、可执行文件不存在或操作系统无法创建进程，不属于已经进入 Helper 服务后的响应范围。具体字段类型、默认空值、未知字段处理和文本呈现边界由授权附件定义。

操作不得要求与其职责无关的完整会话记录、模型内部推理或厂商私有 payload。缺少必需输入时必须指出具体缺口，不得以名称相似或历史缓存静默补足；只有具体操作来源明确把进程实际 `cwd` 定义为回退观察时，才能使用该目录，并必须保留其来源且不得覆盖显式工作对象定位符。

## 6. 能力发现与可用范围

### 6.1 通用发现

不带 `operation_key` 的 `capabilities` 只发现当前规则源已经定义的公开操作。每个结果至少说明：

1. `operation_key`；
2. 提供该操作语义的当前来源；
3. 操作属于读取还是可能改变状态；
4. 必需输入及可选输入；
5. 是否发现实际实现及其可复核依据；调用方不得把内部模块、文件路径或实现版本当成公开操作身份；
6. 已知的配置、工作对象、环境、授权或其它调用前提；
7. 本次发现的观察范围和时间。

通用发现没有获得具体操作参数和对象范围时，`availability` 必须为 `null`。缺少尚未请求的操作参数不得被写成 `unavailable_for_request`；结果应列出所需输入，让 AI 决定是否形成针对该操作的检查或调用。

Code 已能定位有效公开操作声明，但尚未机械确认该操作领域输入契约的完整字段时，仍须发现该操作并在操作 `gaps` 中报告输入清单未确定；此时 `required_inputs` 和 `optional_inputs` 暂为空数组，只表示当前发现结果没有形成可信输入清单，不得解释为该操作没有输入。只有 Code 已从操作来源契约形成可复核的完整字段清单后，才能填入这两个数组并移除相应缺口。

已有当前来源但没有实现的操作仍出现在发现结果中，`implementation.present` 为 `false`，不得声明为可调用。实现存在但没有当前来源支持其公开语义时，该实现不进入公开操作清单，也不取得 `operation_key`；如果检查实际发现这种情况，只能作为契约缺口诊断报告，并暂停把它作为公开能力使用。

### 6.2 当次操作可用性

带 `operation_key` 的 `capabilities` 使用已经提供的 `arguments`、工作对象和其它必要上下文，判断该公开操作对当次请求范围的可用性。`availability` 只使用以下互斥结果：

| 情况 | 可报告内容 |
|---|---|
| 没有实现、缺少足以支持调用的可复核能力依据，或者当次有效请求的零个子范围可调用 | `unavailable_for_request`，并列出实现、能力依据、配置、环境、输入、授权或其它实际缺口 |
| 当前来源与实现存在，当次有效请求至少一个独立子范围可调用、至少一个不可调用 | `partially_available`，并明确可用与不可用范围 |
| 当前来源、实现、可复核能力依据和当次条件均成立，当次有效请求的全部范围可调用 | `available_for_request` |

当次操作可用性（Request-specific Operation Availability）是某个已有当前来源的公开操作，在给定请求内容、对象范围和观察时点下实际可以调用到什么范围。它不是长期能力状态、调用执行结果或环境接入状态；机器字段为 `availability`。

当前来源不存在的名称不属于公开操作；调用方以该名称发起针对操作的 `capabilities` 或 `call` 时返回 `invalid_request`。`partially_available` 只在至少一个独立子范围可调用时优先于 `unavailable_for_request`；无法确定子范围或可复核依据时按零范围可调用处理。

能力发现是读取入口，不得为了证明写操作的瞬时权限而创建目录、锁、临时文件或其它状态。Code 可以根据已经存在且可安全观察的配置、路径类型或确定性访问缺口报告不可用；没有观察到缺口只表示当次条件允许尝试 `call`，不保证随后动态锁、权限或并发条件一定成立。真实调用在取得锁或执行前发现预期环境条件不足时，仍按实际范围返回 `unavailable` 和恢复条件。

通用发现和当次操作可用性都不证明调用已经执行或工作已经完成。缓存的结果必须标明观察时间和实际规则源视图身份；相关 Working Tree 内容、安装 distribution 版本或快照摘要、配置、实现、测试依据或环境变化后必须重新检查或标明过期。缓存不得在 `working_tree` 与 `installed_release_snapshot` 之间复用。

## 7. 机器响应契约

### 7.1 共同响应

Helper 进程已经开始处理请求后，每次公开调用必须只产生一个完整机器响应对象。授权附件定义共同字段的 JSON 类型、必填性、空值和闭集规则；正文定义其语义：

| 字段 | 要求 |
|---|---|
| `contract` | 固定标识响应遵循的 Helper 服务契约；当前值由授权附件定义，改变值不得静默改变既有字段语义 |
| `response_profile` | 回显本次实际采用的响应档位；只表示证据与诊断组织粒度 |
| `request_kind` | 区分 `capabilities` 与 `call`；不替代具体操作身份 |
| `operation_key` | 通用发现时为 `null`；针对单项操作检查或调用时回显请求提供的标识；无效请求中的回显不授予公开操作身份 |
| `outcome` | 使用 §7.2 的 Helper 服务结果 |
| `summary` | 对结果的简明说明，不得替代结构化结果 |
| `result` | 操作来源契约定义的结构化结果；没有结果时明确为空 |
| `scope` | 当次输入对象、成功覆盖范围、未覆盖范围及必要的管辖解析结果 |
| `sources` | 支持响应内容的来源回指；按信息需要保留版本、位置和观察时间 |
| `disclosure` | 返回规范信息时说明实际使用的 L0–L4 及展开原因 |
| `gaps` | 缺失输入、来源冲突、能力缺口、未检查范围和无法判断事项 |
| `changes` | 可能改变状态的调用所计划、实际发生、未发生和无法回读的变化；读取调用为空 |
| `verification` | 当次实际执行的检查、回读、结果及其可证明范围；未执行时如实说明 |
| `diagnostics` | 可定位错误或异常的结构化信息，不改变来源规则语义 |
| `follow_up` | 说明为接续本次结果仍需补充的输入、Human 决定、恢复条件和可选择的后续公开操作；没有 Helper 专属后续时明确为空 |

`compact` 是默认机器响应档位。它必须保留领域 `result`、完整范围、实际缺口、状态变化及足以复核结果的来源和验证，但可以把同类且作用范围一致的资格缺口、来源回指和机械检查聚合为集合级记录，避免为每个结果项重复同一契约与证据。资格缺口在 compact 中按规范化 `(code-or-null, normalized-summary, canonical-scope, canonical-source_refs)` 聚合；同一 key 最多一项，`member_count` 精确记录展开前成员数。不同 summary 只有在当前来源另行定义共同稳定语义 key 后才可合并，不得由实现临时概括。`diagnostic` 用于审计、排障和实现核对，应按具体操作来源逐项展开 Code 已掌握的证据、未证明条件与诊断信息，展开项不使用 `member_count`。两个档位不得改变 `outcome`、领域 `result` 内容、顶层 `scope`、`changes`、实际读写行为、授权判断或一次有效状态变更使用的 `event_at`；相同 before 和冻结 event_at 下最终载体 bytes 必须一致。调用方不得因紧凑档没有逐条列出聚合成员而把未证明条件解释为已证明。

共同 gap code `qualification_unproven` 表示当前 Code 尚未自动证明一项来源或契约资格条件；同一资格来源与作用范围下的逐项条件共享该稳定语义 key，compact 可以用一条固定 summary 和 `member_count` 表达，diagnostic 以各条件原文分别展开。该 code 只表示未证明条件，不表示领域操作不可用、被拒绝或失败。

`sources` 不使用无法回到具体出处的笼统标签。响应引用多种来源时，必须保持规范、事实源、Human 当次指令、外部资料、配置和当次观察各自身份，不得合并成看似同等权威的单一列表。

`follow_up` 只能重组来源规则和实际结果已经支持的后续信息，不得自行创造领域步骤、行动授权、Human Gate、完成条件或固定工作阶段。建议后续调用某个 `operation_key` 不证明该操作当次可用，也不要求 AI 放弃普通求解路径。

### 7.2 Helper 服务结果与退出码

Helper 服务结果（Helper Service Outcome）是 Helper 已经开始处理一次公开发现或调用请求后，对该请求在当次范围内是否全部完成、无需变化、部分完成、被拒绝、不可用、无效或发生实现错误所作的唯一外层分类，机器字段为 `outcome`。它不等于具体操作 `result` 中的领域内容，也不表示上层工作、Human Gate 或环境接入状态。

| `outcome` | 含义 | 进程退出码 |
|---|---|---:|
| `ok` | 有效请求的全部范围已按契约执行并形成相应结果；不自动表示上层工作完成 | `0` |
| `no_change` | 可能改变状态的有效请求已完成检查且允许继续，但目标已经满足或无需发生变化；规则或授权不允许变化时不使用本值 | `0` |
| `partial` | 至少一个独立子范围已经完成，至少一个子范围因拒绝、不可用或错误没有完成；必须逐项保留结果 | `3` |
| `rejected` | 请求结构有效且技术能力可识别，但适用规则不允许、授权不足或 Stop Conditions 被触发，因而未执行受影响范围 | `4` |
| `unavailable` | 请求结构有效且未被规则或授权拒绝，但实现、可复核能力依据、配置、依赖或环境条件不足 | `5` |
| `invalid_request` | 操作 key 未定义，或者请求结构、参数类型或契约要求的必需字段不成立 | `2` |
| `error` | 实现异常或无法按契约形成可信结果 | `1` |

退出码只便于调用方快速分流，机器响应中的 `outcome`、范围、来源和缺口才是完整语义。环境入口不得把非零退出码一律改写成同一种失败，也不得把 `0` 改写为 Human Gate 已通过、验证通过或工作完成。

结果选择先判断请求结构；结构不成立时统一为 `invalid_request`。结构成立后，如果至少一个可独立证明的子范围完成而其它子范围未完成，统一为 `partial`；如果没有子范围完成，再按规则或授权拒绝、技术条件不足、实现异常分别使用 `rejected`、`unavailable`、`error`。`no_change` 只用于允许执行且检查完成的状态变更请求，不能用于掩盖拒绝、不可用或错误。

`capabilities` 成功完成通用发现时使用 `ok`，即使其中存在尚未实现的已定义操作；该 `ok` 只说明发现请求完成。针对单项操作的可用性检查成功返回 `unavailable_for_request` 或 `partially_available` 时，外层发现请求仍可使用 `ok`，具体范围以 `result.operations[].availability`、`scope` 和 `gaps` 为准。只有发现过程本身未能完成相应范围时，外层才使用 `partial`、`unavailable` 或 `error`。

### 7.3 部分结果与错误

Helper 不得因一个对象、来源或子操作失败而丢弃已经取得且仍可独立成立的其它结果。返回 `partial` 时必须逐项区分：

1. 已完成范围及其来源和验证；
2. 未完成范围；
3. 未完成原因；
4. 是否发生状态变化以及变化能否回读；
5. 后续可以补充的输入、能力或 Human 决定。

无法形成可信范围或来源时不得包装为部分成功，应返回 `error` 或 `unavailable`。内部异常信息不得泄露无关敏感内容，但必须保留足以定位失败阶段和输入范围的诊断。

来源已经定义且可预期恢复的配置、依赖、权限、只读文件系统或锁取得条件不足属于 `unavailable`，前提是相应操作能够证明受影响 target、allocator、counter 或其它声明范围没有变化；结构和组合错误属于 `invalid_request`，规则、授权、CAS 或完整目标拒绝属于 `rejected`。无法形成可信残留结论、未知实现异常或写后回读失败且不能按具体操作契约确定回滚结果时使用 `error`。稳定 diagnostic code 必须由当前共同或具体操作来源定义；未知异常不得回显原始 exception message、环境秘密或无关路径。

## 8. 读取与受控状态变更

公开操作必须声明自身为读取操作或可能改变状态的操作。同一 `operation_key` 不得根据隐藏条件在两者之间切换。

读取操作：

1. 可以解析、索引、聚合、比较和返回派生信息；
2. 不得修改事实源、配置、Git refs、环境安装或其它工作对象；
3. 内部临时缓存不得在响应中冒充事实源或当前结果；
4. 读取 Working Tree 当前事实时遵守 03，不回退 `HEAD` 掩盖未提交内容。

可能改变状态的操作：

1. 必须由当前来源定义允许的对象、变化和验证要求；
2. 必须在执行前返回或能够确定实际目标、预期变化和停止边界；
3. 必须确认 Human 当前指令已经授权，且适用于该行动的全部来源规则许可条件已经成立；Helper 能够执行不能替代该行动允许条件；
4. 必须记录实际尝试、实际变化、拒绝、失败和未完成范围；
5. 写入或更新事实源后必须回读当前 Working Tree；其它变化按其来源规则执行等价的实际回读或探针；
6. 请求成功但回读失败时不得返回 `ok`，应按实际范围返回 `partial` 或 `error`。

`changes` 只报告当次调用可观察的变化，不创建永久“已安装”“已集成”或“已完成”状态。

Helper 的读取与受控状态变更面向 AI 执行者（00 §8.3），其完整机械校验与 CAS 边界不延伸至 Web：完整校验不通过可以阻止本章受控状态变更，但不是 Web 面向 Human 阅读呈现的前置条件；Web 的阅读边界由 08 §5 定义。

## 9. 规则信息与判断报告

Helper 提供规则信息时遵守 01 的 L0–L4。L0–L2 只能用于发现、初筛和关系上下文；L3 按精确标题机械边界返回原文切片，不证明语义上下文完整。AI 必须根据任务与已读内容判断是否增加其它 L3 选择或请求 L4，不得把未返回内容解释为不存在。

01 §9.10 的 `work-context-rule-orientation` 是基于既有 `read-specification-content` 的来源定义 profile，不新增 Helper 公开操作。LDVH 核心按该 profile 给出的精确选择调用既有 Helper，取得并如实返回原文、来源、完成范围和缺口；环境可以据此提示 AI 继续使用既有规范读取能力。核心不得读取任务文字、路径、工作对象、缓存或历史上下文来改变选择，也不得在该 profile 中执行管辖解析、事实发现、事实读取、规则适用、Human Gate、行动允许或完成判断。profile 失败时，核心不得用旧摘要、缓存或项目事实恢复伪造当前规则交付。

规则引导 profile 的定义、选择、组合读取和结果分类，均属于当前规则源约束下的 LDVH 核心职责。薄 Skill 只承载路由纪律，不代替 AI 调用这项服务；任何环境层都不得重新进行 profile 或标题选择、规则读取、事实恢复，或以任务相关性、规则适用、授权或完成判断改变请求或结果。规则源和 LDVH 核心能力的后续演进，应在这一核心职责范围内完成，不要求既有薄 Skill 文本改变其路由职责或对核心的稳定引用关系。

01 定义的规范上下文组合读取属于现有 L0–L4 原始内容的有界组织，不建立新的披露层级、规则适用模型或行动允许模型。该操作必须在同一规则源快照中完整交付调用方精确选择的主规则及同一规范要求的边界伴随内容，并保留每个部分的来源、行范围、内容摘要和机械 coverage。`compact` 只能聚合重复来源元数据、验证或缺口说明，不得删除、截断、改写或摘要替代完成项必需的适用范围、验证要求、Human Gate 或 Stop Conditions 原文；预算或环境反馈能力不足时，受影响选择保持未完成并返回 `partial`、`unavailable` 或实际错误，不得形成不完整的 `ok`。

规范候选、内容和组合上下文响应中的来源视图身份、完整载体摘要和逐片段内容摘要只构成可复核读取证据：它们证明响应列出的来源视图、职责标识符、标题范围、原文字节和机械 coverage 已被实际取得，并允许调用方发现后续漂移。这些证据不证明 AI 已阅读或理解内容，不证明候选来源已经找全或与当前任务相关，不证明具体规则适用、Human Gate 或 Stop Conditions 已触发或满足，也不证明 Human 授权、验证通过、行动允许或上层工作完成。Helper 不得把这些摘要包装成授权 receipt、会话级通行证、事实对象或所有普通行动的固定前置状态。

规则适用判断结果（Rule Applicability Evaluation Result）是 Helper 针对一条已定位的当前来源规则、一个明确对象范围和当次输入，报告是否已经完成适用判断，以及判断为适用、不适用、依据不足或尚未检查的结果，机器字段为 `applicability`。它不改变来源规则的含义、效力或优先级。

`applicability` 只是判断结果的报告载体，不授权 Helper 或 Code 解释自然语言规则。只有来源已把适用条件定义为可机械判定的结构化契约时，Code 才可以据实产生 `applies` 或 `does_not_apply`；依赖自然语言语义、当前事项理解或来源冲突取舍的判断必须由 AI 完成，Helper 只回传判断输入、结果、依据和未检查范围。判断来源或依据不足时必须返回 `insufficient_information` 或 `not_evaluated`，不得根据关键词、相似度或默认值推断适用性。

Helper 报告某条规则的当次判断时，至少保留：

1. 规则所在规范的 `spec_key`、当前路径和具体章节或结构位置；
2. 被判断的工作对象或事项范围；
3. 实际使用的输入和来源回指；
4. 来源规则自身定义的适用条件和效力；
5. 通过 `applicability` 字段返回 `applies`、`does_not_apply`、`insufficient_information` 或 `not_evaluated` 中的一项规则适用判断结果；
6. 判断为适用时需要继续执行的来源要求，或无法判断时缺少的依据；
7. 相关 Human Gate、Stop Conditions 和未检查范围。

上述检查结果只描述该规则对该对象和当次输入的判断，不建立跨规则通用优先级或新的效力模型。来源冲突时，Helper 原样列出冲突来源和受影响范围；没有当前来源定义处理方式时，不得自行选择更方便的一方。

### 9.1 当前任务相关信息

Helper 可以按当前任务组织相关信息，帮助 AI 联系目标、工作对象、候选规则、事实、行动模板、可用能力、已经稳定保存的既有工作结果和当前缺口。该组织结果必须满足：

1. 每项内容保留自身来源身份和工作对象范围；
2. 只纳入当次请求和来源实际支持的内容，不通过聊天记忆或名称相似补造历史；
3. 明确说明尚未读取、无法定位、来源冲突和因披露层级而省略的部分；
4. 当次整理、摘要或排序属于派生信息，不成为新的任务事实、规则或优先级；
5. 需要跨会话继续使用的结果仍须按实际来源规则写入事实源，而不是保存在 Helper 会话或缓存中。

Helper 不建立所有任务共用的固定阶段、进度状态或编排对象。具体 WorkCase、计划或其它事实类型只有在相应正式来源成立后才能进入结果。

### 9.2 关联视图

Helper 可以按请求把规范、事实、行动模板、工作对象和能力之间已经由来源定义的关系组织为列表、树或图等关联视图。每个关联视图必须：

1. 使节点回到稳定身份和当前来源；
2. 使关系回到定义其方向和含义的来源位置；
3. 区分来源已经定义的关系与 Helper 为展示形成的分组、排序或路径；
4. 标明无法解析、目标缺失、关系冲突、循环和未展开分支；
5. 不因视图可达、相邻或排序靠前而创造规范依据、事实关系、行动顺序或规则优先级。

关联视图是派生输出。来源变化后必须重新生成或标明过期；它不能替代 L3/L4 规则上下文、事实源或具体来源全文。

## 10. 环境机制与 Helper 结果的一致性

LDVH 的环境接入形态只有薄 Skill 与 Git Gate（00 §8.2）。薄 Skill 是路由文本，不代替 AI 调用 Helper；Git Gate 不经过 Helper 服务链，其事件输入、候选绑定与 allow/block 边界由 09 §5.7 唯一定义，检查合格条件由其领域来源定义。不存在映射 Helper 调用的环境程序层。

AI 经任何路径调用 Helper——薄 Skill 路由后的调用或直接 shell 调用——都必须使用同一公开 `operation_key`、请求内容和机器响应语义，不得因调用路径不同产生两套领域结果契约。

任何环境机制不得改写、吞掉或错误提升 Helper 的拒绝、部分结果、不可用或错误；环境侧的显示、阻断、递达或缺失不证明 Helper 结果正确，也不证明环境已经接入。

## 11. 兼容与变更边界

公开字段、`operation_key`、`outcome`、`availability` 或退出码语义改变时，必须先检查所有已知调用方、环境侧呈现和测试。共同请求与响应使用闭集；新增、删除、重命名顶层字段，改变类型、必填性、空值或结果语义，都必须同步更新授权附件并按实际调用方判断兼容影响。

本文不为历史命令、字段、事件或错误码建立兼容义务。实现只承接当前有效来源支持的契约，不默认建立双读、旧命令别名或迁移 fallback。

`contract` 只标识公开机器接口的兼容边界，不代表 LDVH 产品版本、规范版本或事实版本。当前契约使用授权附件定义的唯一值；本文不预设多版本并行维护机制。确需改变该值时，必须依据真实调用方和同步方案处理，不为低概率升级预建额外状态或流程。

## 13. Human Gate

以下事项必须进入 Human Gate：

1. 改变 Helper CLI 作为 AI 基础服务入口或环境共用服务的上位定位；
2. 允许 Helper 自行定义规则效力、事实语义、行动授权或 Human Gate；
3. 改变机器输出作为完整服务输出的基本边界；
4. 让状态变更操作在缺少适用授权、来源规则或实际回读时仍能返回成功；
5. 删除公开来源、范围、缺口或未完成范围，使调用方无法判断结果边界；
6. 需要对已经存在的调用方实施不兼容公开契约变更且无法提供安全同步方案。

普通新增操作仍必须满足本文来源、实现和测试要求，但不因新增本身自动进入 Human Gate。具体操作实际适用的 Human Gate 仍由相应来源规则决定。

## 14. Stop Conditions

出现以下任一情况时，必须暂停受影响操作、发布或能力声明：

1. 公开操作没有当前来源，却由实现或测试反向定义领域语义；
2. 通用发现与单项可用性检查混淆，无法区分未实现、未检查、当次不可用和部分可用，或把缓存结果冒充当前状态；
3. 响应丢失工作对象、来源、范围、缺口、实际变化或未完成部分，导致结果可能被扩大解释；
4. 读取操作发生未声明状态变化，或状态变更操作缺少授权、实际结果记录或回读；
5. 规则判断无法回到具体来源和完整上下文，或者 Helper 正在创造通用效力和优先级；
6. 环境入口改写、吞掉或错误提升 Helper 的拒绝、部分结果、不可用或错误；
7. 未实现、未接入或未验证的命令、操作或环境能力正被声明为 available、integrated、verified 或 completed；
8. 机器请求或响应不符合授权附件、结果与退出码冲突，或同一请求产生多个互相矛盾的最终响应；
9. 响应遗漏继续处理所必需的输入、Human 决定或恢复条件，或者 Helper 用后续建议创造领域步骤、行动授权和固定工作阶段。
10. Helper 公开操作、实现注册、`capabilities` 或 `availability` 正在被用作 AI 全部行动、工具或命令的白名单，或者 Helper 不支持某项请求正被解释为 AI 不得通过其它适用能力继续求解。
11. 规范上下文组合读取遗漏同一规范要求的适用范围、验证要求、Human Gate 或 Stop Conditions 原文，跨规则源快照拼接内容，静默截断后仍返回完整成功，或者把读取摘要、coverage 或未漂移状态表述为 AI 已理解、规则适用、Human 已授权、行动允许或工作完成。
12. 薄 Skill 或任何环境机制正在读取或解释规则、恢复或补造事实、选择披露内容，或者以任务相关性、规则适用、授权或完成判断改变核心请求或结果；无法承接的能力被旧行为伪装为已交付。

暂停范围及不受影响工作的处理按 00 §11 执行。

受影响范围只能在与触发原因对应的条件满足后恢复：公开来源和实现重新一致，能力范围与缺口已如实区分，响应重新保留来源与范围，未授权变化已停止或按来源规则处理，规则上下文已经补全，环境侧结果呈现已通过真实对照，或者声明已经缩小到当次证据实际支持的范围。
