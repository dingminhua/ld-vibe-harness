# 环境入口适配与部署规范

> 草案状态：04 系列重构草案，非正式规范
> 定位：定义各 AI 开发环境如何通过环境入口接入、部署并实时检查 LDVH 能力资产
> 适用范围：环境入口、薄引用、环境适配、部署步骤、实时检查、成功条件、失败处理、降级方式、Human Gate

本文是 AI 帮用户执行环境部署的直接依据。本文不定义 LDVH 能力资产本身，不记录长期用户本地安装状态，不把一次实时检查结果写成环境类型结论。

---

## 1. 本文解决的问题

本文解决以下问题：

1. 某个 AI 开发环境提供哪些环境入口；
2. 这些环境入口如何接入 04.02 定义的 LDVH 能力资产；
3. AI 如何在授权边界内帮助用户执行部署；
4. 部署前、部署后和声明完成前如何实时检查；
5. 接入失败、环境不支持、权限不足或证据不足时如何降级或 Human Gate。

用户本地实例状态不是长期事实源。它只能来自本文定义的实时检查，并由 Code 输出、Web 当前视图、Human Gate 记录、Task、Memo、Pitfall 或 ADR 按性质承载。

---

## 2. 基本概念

| 概念 | 含义 |
|---|---|
| 环境类型 | Trae Work CN、Codex App、Cursor、Claude Code 等 AI 开发环境类型 |
| 环境入口 | 环境提供的读取、加载、调用或触发位置或机制 |
| 薄引用 | 放在环境入口中，指向 LDVH 能力资产的最小引用 |
| 接入方式 | 薄引用、配置、安装、软链、受控复制、命令包装、人工降级等 |
| 部署步骤 | AI 在授权边界内把 LDVH 能力资产接入环境入口的步骤 |
| 实时检查 | 对当前环境入口接入是否有效进行现场检查 |
| 成功条件 | 本次部署或接入可以声明有效的最低条件 |
| 证据输出 | AI、Code 或 Web 向 Human 呈现的检查证据 |

---

## 3. 环境入口适配卡片字段

每个环境入口适配卡片至少包含：

| 字段 | 必填 | 含义 |
|---|---|---|
| 环境类型 | 是 | 适用的 AI 开发环境类型 |
| 环境入口 | 是 | 该环境实际读取、加载、调用或触发的位置或机制 |
| 对应 LDVH 能力资产 | 是 | 04.02 中定义的 Rules、Skill、Agent、Hook 或其它能力资产 |
| 接入方式 | 是 | 薄引用、配置、安装、软链、受控复制、人工降级等 |
| 部署步骤 | 是 | AI 如何帮用户接入该资产 |
| 写入权限 | 是 | 是否可自动写入，是否需要 Human Gate |
| 实时检查方式 | 是 | 如何现场判断接入已生效 |
| 成功条件 | 是 | 满足什么才能声明本次接入有效 |
| 失败处理 | 是 | 缺入口、无权限、不可读、环境不支持时如何处理 |
| 降级方式 | 是 | 无原生入口时如何模拟或人工降级 |
| 禁止声明 | 是 | 哪些情况下不得声明原生完整支持或部署完成 |
| 证据输出 | 是 | 应呈现给 Human 的证据 |
| 来源 | 是 | 官方资料、sources、实测证据、当前环境证据或 Human Gate |

## 4. 部署与实时检查规则

### 4.1 部署前检查

部署前必须确认：

1. 当前环境类型；
2. 当前工作区和目标项目边界；
3. 环境入口是否存在；
4. 目标 LDVH 能力资产是否存在；
5. 是否有写入权限；
6. 是否存在用户已有配置需要保护；
7. 是否触发 Human Gate。

### 4.2 部署执行

部署执行应优先使用薄引用、配置、软链或安装方式。只有在环境明确无法引用、且 Human 授权、且有退出方式时，才允许受控复制。

部署不得复制完整 specs 正文，不得创建第二事实源，不得覆盖用户已有配置而不保留备份和说明。

### 4.3 部署后检查

部署后必须实时检查：

1. 环境入口文件、配置或机制是否存在；
2. 薄引用是否指向正确的 LDVH 能力资产；
3. 目标资产是否可读；
4. 是否复制了不应复制的完整正文；
5. 是否满足该环境入口卡片的成功条件；
6. 是否仍需 Human Gate。

### 4.4 声明完成前检查

AI 声明部署完成前必须输出证据摘要。证据至少包含环境类型、环境入口、对应 LDVH 能力资产、检查时间、检查方式、检查结论、失败项和降级项。

未完成实时检查时，不得声明部署完成。实时检查失败时，不得把失败写成环境类型不支持，也不得把人工降级写成原生完整支持。

---

## 5. Human Gate

以下情况必须 Human Gate：

1. 写入、覆盖或删除用户环境入口；
2. 修改长期环境配置；
3. 启用自动触发、危险权限或跨工作区写入；
4. 受控复制 LDVH 能力资产全文；
5. 覆盖用户已有 Rules、Skill、Agent、Hook、instructions 或配置；
6. 声明任一环境完整支持 LDVH；
7. 将一次用户本地实时检查结果写成环境类型结论。

## 6. Trae Work CN 适配草案

### 6.1 Rules 环境入口

| 字段 | 内容 |
|---|---|
| 环境类型 | Trae Work CN |
| 环境入口 | Trae rules、AGENTS、用户级或工作区级可读规则入口，具体路径待 sources 和实测确认 |
| 对应 LDVH 能力资产 | `../rules/LDVH-AI-ENTRY.md` |
| 接入方式 | 薄引用 / 配置适配 |
| 部署步骤 | 在 Human 授权后，在 Trae 可读入口写入指向 LDVH Rules 资产的薄引用 |
| 写入权限 | 写入用户级或工作区级入口前需要 Human Gate |
| 实时检查方式 | 检查入口是否存在、薄引用是否指向 LDVH Rules 资产、是否未复制 specs 正文 |
| 成功条件 | 薄引用存在、目标资产可读、未形成第二事实源 |
| 失败处理 | 降级为会话显式要求 AI 读取 LDVH Rules 资产 |
| 降级方式 | 人工提示 / 会话级薄引用 |
| 禁止声明 | 未实测加载顺序和持久性前，不声明完整支持 |
| 证据输出 | 入口位置、引用内容摘要、目标资产路径、检查结论 |
| 来源 | 04.02、sources、当前环境证据、Human Gate |

### 6.2 Skill 环境入口

| 字段 | 内容 |
|---|---|
| 环境类型 | Trae Work CN |
| 环境入口 | Trae Skill 机制，具体目录、加载条件和元数据要求待 sources 和实测确认 |
| 对应 LDVH 能力资产 | `../skills/ldvh-spec-change-check/SKILL.md` |
| 接入方式 | 安装 / 配置适配 / 薄引用 |
| 部署步骤 | 在 Human 授权后，将 LDVH Skill 资产接入 Trae Skill 入口，避免改写 Skill 正文为环境事实源 |
| 写入权限 | 写入 Skill 目录或配置前需要 Human Gate |
| 实时检查方式 | 检查 Skill 入口是否存在、资产是否可读、描述是否保留边界 |
| 成功条件 | Skill 可被环境发现或可由 AI 显式调用，且边界未越界 |
| 失败处理 | 主控 AI 按 specs 手动执行 SOP 并记录降级 |
| 降级方式 | 指令化 SOP / 人工降级 |
| 禁止声明 | Skill 模拟 Hook 不得声明 Hook 原生完整支持 |
| 证据输出 | Skill 入口、资产路径、发现方式、检查结论 |
| 来源 | 04.02、sources、当前环境证据、Human Gate |

### 6.3 Agent 环境入口

| 字段 | 内容 |
|---|---|
| 环境类型 | Trae Work CN |
| 环境入口 | Trae Agent / subagent / 独立上下文候选，待 sources 和实测确认 |
| 对应 LDVH 能力资产 | `../agents/ldvh-spec-semantic-review.md` |
| 接入方式 | 配置适配 / 指令适配 / 人工降级 |
| 部署步骤 | 若环境支持 Agent 入口，在授权后接入 LDVH Agent 资产；否则由主控多视角模拟 |
| 写入权限 | 创建或启用长期 Agent 前需要 Human Gate |
| 实时检查方式 | 检查 Agent 能否读取任务边界、输出是否回主控、是否不可直接生效 |
| 成功条件 | Agent 输出包含证据、边界、未决问题和回主控建议 |
| 失败处理 | 主控多视角审查并记录降级风险 |
| 降级方式 | 主控模拟 / 人工审查 |
| 禁止声明 | 未验证独立上下文能力前，不声明完整支持 |
| 证据输出 | Agent 入口、输入、输出摘要、回主控证据 |
| 来源 | 04.02、sources、当前环境证据、Human Gate |

### 6.4 Hook 环境入口

| 字段 | 内容 |
|---|---|
| 环境类型 | Trae Work CN |
| 环境入口 | 原生 Hook / lifecycle 机制待确认 |
| 对应 LDVH 能力资产 | `../hooks/ldvh-lifecycle-check.md` |
| 接入方式 | 人工降级 / Command / Skill 提醒 / 入口 STOP 点 |
| 部署步骤 | 若无原生 Hook 证据，不部署为原生 Hook，只部署提醒或手动检查路径 |
| 写入权限 | 启用自动触发前必须 Human Gate |
| 实时检查方式 | 检查是否存在原生机制；若无，检查降级路径是否清楚 |
| 成功条件 | 原生 Hook 已验证，或降级路径明确且未声明完整支持 |
| 失败处理 | 降级为手动命令、Skill 提醒或人工清单 |
| 降级方式 | 人工触发 / 命令检查 / Skill 模拟提醒 |
| 禁止声明 | Skill 模拟或人工提醒不得写成 Hook 原生完整支持 |
| 证据输出 | Hook 证据、降级路径、检查结论 |
| 来源 | 04.02、sources、当前环境证据、Human Gate |

## 7. Codex App 适配草案

Codex App 当前多数环境入口仍需 sources 和实测确认。未确认前，应以指令适配、待确认或人工降级表达，不声明完整支持。

| 能力资产 | 环境入口候选 | 接入方式 | 实时检查重点 | 禁止声明 |
|---|---|---|---|---|
| Rules 资产 | 项目说明、会话入口、instructions 候选 | 指令适配 / 待确认 | 是否可稳定加载薄引用 | 不声明持久入口完整支持 |
| Skill 资产 | 流程复用入口候选 | 指令适配 / 待确认 | 是否有稳定 SOP 调用机制 | 不声明原生 Skill 完整支持 |
| Agent 资产 | 子任务、独立视角或 Agent 候选 | 待确认 / 人工降级 | 输出是否回主控 | 不声明未验证 Agent 能力 |
| Hook 资产 | lifecycle / hook 候选 | 待确认 / 人工降级 | 是否有可验证触发机制 | 不声明未验证 Hook 能力 |

Codex App 的每项部署必须在实时检查中确认当前入口是否存在、是否可读、是否可持续、是否会被上下文压缩影响。未确认时只能给出人工降级路径。

## 8. 规范落地要求

| 落地要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 上位约束承接要求 | 环境入口适配与部署必须承接 04.02 的 LDVH 能力资产定义 | 本文、04.02、Human Gate | 环境部署治理 | 能力资产或部署字段变化时 |
| 入口可见要求 | AI 执行部署前应能定位本文和对应环境入口卡片 | Rules 资产、薄引用、人工提示 | AI 执行入口提示 | 环境入口或部署步骤变化时 |
| 确定性执行要求 | 后续 Code 应能按本文字段执行或辅助实时检查 | Code、命令、测试样例 | 校验实现 | 字段稳定后 |
| Human 交互要求 | 写入环境入口、声明完整支持或覆盖用户配置前必须暂停确认 | Human Gate、Web、对话确认 | 部署确认 | 高影响部署动作前 |
| 生命周期触发要求 | 环境入口、LDVH 能力资产或部署证据变化后应重新实时检查 | Hook 资产、CI、人工检查 | 触发保障 | 环境或资产变化时 |
