## 一、本文定位

本文定义多角色思考行动模型在 Agent 层的执行内容。Agent 增强模式用于需要独立上下文、结论隔离、并行委派、不同权限边界或大量事实源读取的多角色思考场景。

本文不创建、导入、启用或修改任何 Agent，也不维护推荐自建 Agent 清单。Agent 的创建、调用、定义摘要、生命周期和权限边界以 `specs/04.03-Agent机制规范.md` 为准。

---

## 二、Agent 增强模式前提

多角色思考 Agent 增强模式的默认前提是：当前 Trae 环境已安装并可调用相关 Trae 预制 Agent。

前提检查结果分为：

| 结果 | 处理 |
|---|---|
| 已确认可调用 | 可进入 Agent 增强模式 |
| 未安装 | 降级为主上下文轻量模式或 Skill 辅助模式 |
| 不可确认 | 不得声称已执行 Agent 增强分析，应降级或询问用户 |
| 用户要求必须 Agent 增强 | 暂停并提示需要先安装或初始化相关 Agent |

未满足前提时，本行动不能执行 Agent 增强模式，但不影响轻量模式或 Skill 辅助模式执行。

---

## 三、适用条件

以下情况可考虑 Agent 增强模式：

1. 需要多个专业角色并行分析；
2. 单一主上下文无法承载大量事实源；
3. 需要不同角色独立形成结论，避免主上下文提前合并观点；
4. 需要不同权限边界或不同工具能力；
5. 分析主题涉及复杂前端、后端、性能、部署、AI 集成、安全或测试维度；
6. 用户明确要求使用已安装 Trae 预制 Agent 参与分析。

以下情况不应使用 Agent 增强模式：

1. 简单问答；
2. 单文件低风险修改；
3. 主上下文轻量模式足以完成；
4. 只是为了包装角色名称；
5. 相关 Agent 未安装且用户未要求先安装；
6. Skill 辅助模式已经能完成标准化报告。

---

## 四、预制 Agent 类型映射

在已安装并可调用的前提下，可按主题选择以下 Trae 预制 Agent 类型：

| 主题 | 可考虑的 Agent 类型 | 关注点 |
|---|---|---|
| UI、交互、视觉 | UI 设计 | 用户体验、视觉层次、交互风险 |
| 前端架构 | 前端架构 | 组件结构、状态管理、性能、可维护性 |
| 后端、API、数据 | 后端架构 | API、数据库、服务边界、业务逻辑 |
| API 可靠性 | API 测试 | 契约、性能、负载、接口验证 |
| 性能问题 | 性能优化 | 瓶颈、资源消耗、优化建议 |
| 部署、CI/CD、监控 | DevOps 架构 | 部署链路、基础设施、监控和回滚 |
| AI、模型、推荐、自动化 | AI 集成 | 模型集成、提示词、数据和自动化边界 |
| 安全相关 | 安全审查或主上下文安全视角 | 权限、密钥、破坏性操作、数据保护 |

该映射是调度建议，不表示 LDVH 已维护对应 Agent 定义摘要，也不替代 Trae 平台实际可用 Agent 列表。

---

## 五、调度流程

Agent 增强模式建议流程：

1. 主控识别多角色思考 Scenario；
2. 判断主上下文或 Skill 是否不足；
3. 检查相关 Trae 预制 Agent 是否可用；
4. 说明拟调用 Agent、输入 Context、权限边界和预期输出；
5. 如涉及高影响调度或权限变化，触发 Human Gate；
6. 用户显式调用或主控编排 Agent；
7. 各 Agent 独立输出分析结论；
8. 主控汇总一致结论、分歧、风险和回写建议；
9. 主控判断 Human Gate 和事实源回写；
10. 稳定事实按 03 和对象规范写回。

---

## 六、上下文分发

分发给 Agent 的 Context 应满足：

1. 只包含该 Agent 完成分析所需的最小事实源；
2. 明确分析主题、角色关注点和输出格式；
3. 明确只读或写入权限；
4. 明确不得将输出直接视为最终事实源；
5. 明确发现 Human Gate 时必须标注并停止相关修改；
6. 明确输出返回主控汇总。

不得向 Agent 分发密钥、令牌、Cookie 或与分析无关的敏感信息。

---

## 七、输出汇总

主控汇总 Agent 输出时，应检查：

1. 每个 Agent 的输入来源是否明确；
2. 每个 Agent 是否在权限边界内行动；
3. 是否存在互相冲突的结论；
4. 是否存在与 Git 文件事实源冲突的结论；
5. 是否存在需要 Human Gate 的建议；
6. 哪些内容只是过程分析；
7. 哪些内容需要回写为 Task、Memo、ADR、Risk、Evidence 或 Change。

Agent 输出不得绕过主控直接写入事实源，除非用户和规范明确授权且通过相应 Gate。

---

## 八、Human Gate

以下情况必须暂停确认：

1. 创建、导入、启用、停用、删除或重命名 Agent；
2. 修改 Agent Prompt、职责边界、触发方式或定义摘要；
3. 调整 Agent 权限、写入权限、网络权限或可调用范围；
4. 允许 Agent 调度其他 Agent；
5. 将 Agent 输出提升为稳定事实；
6. 将推荐 Agent 类型映射升级为正式 Agent 清单；
7. 用户要求必须使用 Agent 增强，但相关 Agent 未安装。

---

## 九、检查要求

| 检查项 | 标准 |
|---|---|
| 前提 | 已确认相关 Trae 预制 Agent 可调用，或已降级 |
| 门槛 | 满足独立上下文、结论隔离、并行委派或不同权限边界之一 |
| 调度 | 用户显式调用或主控编排，不自行触发 |
| Skill 边界 | 未由 Skill 调度 Agent |
| 权限 | 最小必要，敏感信息未分发 |
| 输出 | Agent 输出返回主控汇总 |
| 事实源 | Agent 输出未直接替代 Git 文件事实源 |
| Human Gate | Agent 创建、启用、权限和输出升级已评估门禁 |
