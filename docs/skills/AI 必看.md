# AI 必看：专家 / 专家团调研交付标准

> 本文件给之后接手的新 AI 使用。用户希望以后分析任何“专家 / 专家团 / 提示词体系”时，都按这里的标准执行，不要重新发散、不要换格式、不要把任务做偏。

---

## 0. 一句话任务理解

当用户说：

- “分析当前专家”
- “分析这个专家用到什么提示词”
- “看看这个团队的工作模式”
- “按同一个 readme.md 模板填写这个专家的调研文档”
- “生成某某专家 / 团队的文档”

正确理解是：

> 用户要的不是业务咨询本身，而是要调研当前生效的 Expert / Team prompt，分析它的身份、结构、规则、协作方式、输出边界，并按统一模板生成 Markdown 文档。

---

## 2. 文件命名规则

### 2.1 专家文档命名

统一使用：

```text
英文标识-中文名.md
```

示例：

```text
UI-Designer-像素君.md
Content-Creator-文博凯.md
```

### 2.2 专家团 / 团队文档命名

统一使用：

```text
英文团队标识-中文团队名.md
```

示例：

```text
OPC-Team-一人公司专家团.md
```

### 2.3 禁止命名

不要再使用以下命名：

```text
XXX-专家调研报告.md
XXX-调研报告.md
```

用户已经明确要求：

> 文件名要英文后面带中文，“专家调研报告”这几个字不要。

---

## 3. 输出目录规则

所有这类文档都放在：

```text
docs/skills/
```

不要放到仓库根目录，不要新建其他目录，除非用户明确要求。

## 4. 标准工作流

### Step 1：确认当前对象

先判断当前对象是：

- 独立专家 Expert
- 专家团 / Team
- Skill / 技能包
- 文档团队 / 工作流团队

不要把“专家本人业务能力”误当成用户要的内容。用户要的是“提示词体系调研”。

### Step 2：提取提示词结构

至少分析：

1. 身份定位
2. 核心职责
3. 禁止行为
4. 高优先级规则
5. 工作流阶段
6. 协作成员
7. 触发条件
8. 输出格式
9. 与其他专家 / 团队的边界
10. 可复用写法特征

### Step 3：按模板写文档

严格使用 `docs/skills/readme.md` 的章节结构，不要临时换模板。

如缺失信息，统一写：

```text
[待填写]
```

不要编造。

### Step 4：落盘

把完整 Markdown 写入 `docs/skills/英文标识-中文名.md`。

### Step 5：展示结果

完成后展示文件，并简要说明：

- 新增 / 修改了哪个文件
- 分析对象是谁
- 覆盖了哪些核心内容

---

## 5. 内容质量标准

生成的调研文档必须做到：

1. **结构完整**：不能只写摘要，要覆盖模板所有主章节。
2. **证据可追溯**：文末必须列出参考来源、已读文件或当前注入的专家提示词来源。
3. **区分专家与团队**：独立专家写能力边界；团队必须写成员分工、调度规则、阶段流程。
4. **不代入业务执行**：例如 OPC Team 的调研不是帮用户做一人公司规划，而是分析 OPC Team 的提示词和工作模式。
5. **保留边界与风险**：写清楚适用 / 不适用场景，以及容易混淆的地方。
6. **高细节**：用户偏好详细、结构化、可复用，不要只给短总结。

## 7. 最容易犯的错误

### 错误 1：把调研任务做成业务咨询

例如用户说“现在是一人公司专家团，你能分析这里的工作模式和提示词吗”，不能直接开始问用户创业方向。正确做法是分析 OPC Team 的 prompt 结构与团队机制。

### 错误 2：文件名乱命名

不要再写 `专家调研报告` 字样。必须用“英文标识-中文名.md”。

### 错误 3：忽略 `readme.md`

`readme.md` 是统一模板，不是普通说明文件。每次新调研都要先读它。

### 错误 4：混淆 OpenSpecDocTeam 与当前专家

OpenSpecDocTeam 是文档协作流程，不等于当前被调研专家。它可以作为“如何生成文档”的方法，但不能覆盖当前专家本身的身份。

### 错误 5：主观补全缺失信息

不知道的内容写 `[待填写]`，不要编造技能、成员、触发条件或数据流。

---

## 8. 用户偏好

用户偏好如下：

- 要详细，不要省略关键结构。
- 要高度结构化，不要散文式输出。
- 要能复用，不只是当前一次回答。
- 要直接落盘，不要只在聊天里说。
- 文件统一放在 `docs/skills/`。
- 命名统一“英文 + 中文”。
- 不要把“专家调研报告”写进文件名。
- 若发现重复 / 错误文件，应主动判断保留哪个，而不是一直反问。

---

## 9. 给新 AI 的最短执行指令

如果用户之后只说：

> 按之前标准分析当前专家。

你应该执行：

1. 读取 `docs/skills/AI 必看.md`。
2. 读取 `docs/skills/readme.md`。
3. 判断当前注入的是哪个 Expert / Team。
4. 按模板生成 `docs/skills/英文标识-中文名.md`。
5. 写清提示词结构、工作模式、协作机制、输出规范、边界和证据来源。
6. 展示生成文件。
