## 1. 本文解决的问题

本文解决 LDVH 如何把能力保障落实到具体环境的问题。

本文使用"环境"口径，不再沿用旧环境分类。当前只覆盖两个环境：

1. Trae Work CN；
2. Codex App。

具体适配措施见 `docs/specs/04.04-环境适配措施实践.md`。

如果后续需要新增 Cursor、OpenCode、Gemini、Zed、Qwen 或其他环境，AI 应根据本文字段自行调研该环境官方资料、项目 refs 和当前环境证据，形成环境能力清单后，按本文规则追加适配字段，并在 04.04 中追加适配措施。新增环境不得凭聊天记忆、模型经验或其他项目经验直接声明完整支持。

## 2. 环境能力清单边界

环境能力清单是客观输入，不是 LDVH 决策源。

环境能力清单只回答：

1. 环境有哪些可用于入口、流程、工具、触发、确认、校验或回写的能力；
2. 单项环境能力的来源证据是什么；
3. 当前能力是已验证、refs-only、待确认、不可用还是人工降级；
4. 能力有哪些权限、配置、上下文、压缩、安全或持久化限制；
5. 能力不能完整承载 LDVH 能力保障时，该环境应如何适配降级。

环境能力清单不得回答：

1. LDVH 是否应该提供某项能力保障；
2. 正式规范是否需要某项落地要求；
3. 其他环境是否应该降级；
4. 某项候选能力是否已经完成当前用户环境实测；
5. 环境工具输出是否可以替代 Git 文件事实源。

## 3. 环境适配状态

环境适配使用以下状态表达当前环境承载能力保障的方式：

| 适配状态 | 含义 |
|---|---|
| 原生承载 | 环境原生能力可直接承载能力保障，且已有 LDVH 可复用验证证据 |
| 配置适配 | LDVH 通过薄入口、配置、命令、脚本、Hook、Code wrapper 或环境配置形成适配措施，但语义不完全等价 |
| 指令适配 | 环境只能通过 Rules、AGENTS、Prompt、Instructions 或人工提示引导 AI 执行 |
| 人工降级 | 环境缺少对应能力或证据不足，只能人工执行、人工确认或人工记录证据 |
| 仅作参考 | 只作为设计参考或未来候选，不声明当前支持 |
| 待确认 | 尚未读取 refs 或完成实测，不能据此执行完整闭环 |

适配状态不是通过状态，不代表当前用户环境已经安装、启用、配置或验证。42 可以基于当前执行情况派生过程结论，但不得把过程结论回写为环境长期状态。

## 4. 环境适配字段

环境适配采用卡片表达，避免超宽表格。每张卡片至少包含：

| 字段 | 必填 | 含义 |
|---|---|---|
| 适配项 | 是 | 需要适配的环境入口、能力、要求或适配措施类型 |
| LDVH 要求 | 是 | 该适配项要满足的 LDVH 抽象要求 |
| 环境能力清单 | 是 | 当前环境客观能力、限制和证据状态摘要 |
| Trae Work CN 适配方式 | 是 | LDVH 在 Trae 中形成的入口、流程、校验、降级或缺口记录 |
| Codex App 适配方式 | 是 | LDVH 在 Codex App 中形成的入口、流程、校验、降级或缺口记录 |
| 来源 | 是 | specs、refs、research、旧 04.07 / 04.08、官方资料或实测证据；旧 04.08 只作为迁移输入，不自动构成 Codex App 实测证据 |
| 适配检查 | 是 | 如何证明适配未越界、未虚假支持、未把环境能力当成 LDVH 决策 |
| 适配降级 | 是 | 环境不足时如何人工降级或显式执行 |
| 待补齐事项 | 是 | 后续 refs、实测、Task、ADR、Code、Web 或规范事项 |

新增环境时，应在卡片中追加对应环境适配方式，或在结构化派生视图中追加环境字段。新增环境不得删除 Trae 与 Codex 的既有降级和证据边界。

具体适配卡片内容见 `docs/specs/04.04-环境适配措施实践.md`。

## 5. 新增环境规则

新增环境时，AI 应按以下步骤执行：

1. 明确环境名称、运行形态和适用范围；
2. 读取环境官方文档、项目 refs、已有研究和当前环境证据；
3. 形成环境能力清单，标注已验证、refs-only、待确认、不可用和人工降级；
4. 按本文 §4 字段和 04.04 的格式追加环境适配方式和适配措施；
5. 明确来源、适配检查、适配降级和待补齐事项；
6. 若声明完整支持、新增长期入口、启用自动触发或写入用户配置，必须 Human Gate。

新增环境时不得删除已有环境列，不得把新环境能力反向写成 LDVH 全局要求，不得把其他环境的降级路径当作新环境事实。

## 7. Human Gate 与检查要求

以下情况必须触发 Human Gate：

1. 声明任一环境完整支持 LDVH；
2. 新增或删除环境列；
3. 删除、重命名或改变旧 04.06 / 04.07 / 04.08 职责；
4. 允许缺少适配检查的环境项通过 42；
5. 将某环境能力提升为 LDVH 全局唯一底座；
6. 启用自动 Hook、危险权限、跨工作区写入或长期配置。

检查环境适配措施时，应确认：

| 检查项 | 标准 |
|---|---|
| 字段完整 | 每张卡片包含适配项、LDVH 要求、环境能力清单、环境适配方式、来源、检查、降级和待补齐 |
| 环境客观 | 环境能力来自 refs、官方资料或实测证据 |
| 主体正确 | LDVH 提供能力保障，环境只提供客观清单和承载边界 |
| 降级真实 | 不支持或证据不足时明确人工降级和残留风险 |
| 事实源边界 | 工具输出、入口、适配措施未替代正式规范 |
| 扩展可行 | 新环境可按本文字段自行调研和追加 |
