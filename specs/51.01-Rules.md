## 1. 本文定位

本文是 `specs/51-multi-role-thinking-多角色思考.md` 的附件型实践子文档（编号 51.01），承接 Rules 入口实践。本文不是独立行动模型，不得重新定义多角色思考的行动定位、准入条件、Context、Scenario、Gate、执行流程、事实源回写、证据留存或 Human Gate。发生冲突时，以 51 主文档和上位基础规范为准。

多角色思考的 Rules 入口由工作区 L0 Rules 承接，当前实体为 `../.trae/rules/ldvh-l0-rules.md`。该 Rules 入口只负责触发条件摘要和行动入口提醒，不替代 51 主文档或 51.06 契约。

Rules 入口应在以下内容变化时同步检查：

1. 51 主文档的触发条件、执行模式、Human Gate 或事实源回写要求变化；
2. 51.06 契约中的角色选择输出、角色定义来源或多角色报告结构变化；
3. `specs/11-LDVH-Trae-Solo-环境规范.md` §6 的 L0 Rules 生效方式、头部来源或维护边界要求变化；

---

## 2. Rules 入口摘要

多角色思考的 Rules 入口摘要内容如下：

```markdown
当用户要求多角色、多视角、跨模块影响评估、复杂变更风险审查，或 AI 判断单一主上下文可能遗漏风险时，应进入多角色思考行动模型。多角色子 Agent 模式也必须先从本 Rules 入口进入，不得由 Skill、Tools、MCP 或脚本直接触发。执行流程和角色定义见 `specs/51-multi-role-thinking-多角色思考.md` 及 `specs/51.06-Contract.md`。本入口不复制完整 Scenario、角色定义、执行流程或 Human Gate 条款。
```

---

## 3. 放置位置

多角色思考是跨项目基础能力，入口摘要应放置在 L0 工作区规则（`.trae/rules/ldvh-l0-rules.md`）。L0 文件名已提供命名空间，章节标题和压缩保护行不使用 `ldvh-` 前缀。

管辖项目如需在 L1 或 L2 规则中增加多角色思考入口，应引用 51 主文档，不复制完整内容。

---

## 4. 生效方式

1. Rules 入口摘要作为 L0 工作区规则的一部分，对所有项目生效；
2. AI 识别到入口摘要描述的触发场景时，应读取 51 主文档并按本文执行流程处理；
3. 入口摘要不替代 51 主文档的 Scenario 识别、角色选择、执行流程或 Human Gate 判断；
4. 压缩保护行中增加 `多角色思考见51`，确保入口在上下文压缩后仍可追溯。

---

## 5. 禁止承载内容

Rules 入口摘要不得承载以下内容：

1. 完整 Scenario 识别条件；
2. 角色定义、默认角色集合或角色选择规则；
3. 执行流程的详细步骤；
4. 输出格式模板；
5. Human Gate 完整条款；
6. 事实源回写规则；
7. 证据留存要求。

以上内容由 51 主文档和 51.06-Contract.md 承载。

---

## 6. 检查项

检查 Rules 入口是否合规时，应确认：

1. 入口摘要是否放置在 L0 工作区规则中；
2. 入口摘要章节标题是否与 L0 文件其他章节命名风格一致；
3. 入口摘要是否指向 51 主文档和 51.06-Contract.md；
4. 入口摘要是否未复制 51 主文档的完整 Scenario、角色定义、执行流程或 Human Gate 条款；
5. 压缩保护行是否包含多角色思考入口追溯信息。

---

## 7. Human Gate

1. 将多角色思考入口摘要从 L0 移除或移至其他层级时，应经 Human Gate 确认；
2. 入口摘要内容变更影响触发条件或执行流程描述时，应经 Human Gate 确认；
3. 新增 L1 或 L2 层级的多角色思考入口时，应经 Human Gate 确认。
