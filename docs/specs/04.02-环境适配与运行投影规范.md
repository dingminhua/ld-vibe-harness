# 环境适配与运行投影规范

> 创建日期：2026-06-08
> 定位：定义 LDVH 如何把规范落地要求和保障机制适配到具体开发环境，形成运行投影，并处理同步、降级和漂移检查
> 适用范围：LDVH 环境适配映射、运行投影同步、规范变更后的环境审计、运行投影漂移检查和环境不支持时的降级记录

## 1. 本文解决的问题

本文解决 LDVH 规范落地要求如何进入具体开发环境的问题。

环境适配是安装接入和LDVH落地与检查的现场确认输入之一。用户首次安装或接入 LDVH 时，应由 `docs/specs/42-ldvh-landing-check-LDVH落地与检查.md` 先确认当前 AI 环境，并按 `docs/specs/04.06-平台适配清单规范.md` 定位当前平台适配清单。AI 能明确判断当前平台时读取对应清单；判断不清时请求 Human 选择；清单缺失、未填写或证据不足时，不得宣称完整支持。当前已有清单包括 `docs/specs/04.07-Trae-Solo适配清单.md` 和 `docs/specs/04.08-Codex适配清单.md`。本文不要求创建独立环境检测器，项目内平台投影痕迹只能作为辅助线索。

`docs/specs/04.01-规范落地声明规范.md` 规定正式规范如何声明“要落地需要满足哪些要求”和“由什么保障机制保障”。本文只处理下一层：这些要求和保障机制在 Codex、Trae、Claude Code、Cursor、CI、Web、命令行或其他环境中如何映射成可见入口、可复用流程、子 Agent 调用、Code 检查、Human 交互、生命周期触发和运行投影。

本文不得反向改写正式规范。环境能力不足时，应记录降级方式和残留风险，而不是把规范要求改低。

## 2. 与 00 总纲的关系

00 定义开发环境是 LDVH 五类构成要素之一，同时要求 Code、Web、工作模型和工作流程围绕稳定事实源协作。环境适配和运行投影用于让正式规范在具体环境中被 AI、Human 和 Code 看见、调用和检查，但运行投影不是最终事实源。

本文承接以下链路的后两层：

```text
正式规范
→ 规范落地要求
→ 保障机制
→ 环境适配映射
→ 运行投影
→ 漂移检查与事实源回写
```

规范落地要求和保障机制的声明规则以 `docs/specs/04.01-规范落地声明规范.md` 为准。环境能力如何承接不同要求，以 `docs/specs/04.03-环境能力承接边界规范.md` 为准。平台差异、承接方法、证据、降级方式和 open_items 以 `docs/specs/04.06-平台适配清单规范.md` 和当前平台清单为准。本文只规定环境适配映射、运行投影、漂移检查和事实源回写的通用应用规则；术语定义统一以 `docs/specs/02-术语规范.md` 为准。

## 3. 术语应用关系

本文使用的环境、环境适配映射、运行投影、漂移、降级方式、LDVH落地等术语，按 `docs/specs/02-术语规范.md` 定义。以下小节只说明这些术语在环境适配和运行投影同步中的应用规则，不另行维护术语权威定义。

### 3.1 环境

按 `docs/specs/02-术语规范.md` 的术语边界，本文将 Codex、Trae、Claude Code、Cursor、CI、Web 工作台、命令行或其他被 LDVH 明确纳入适配的执行面作为环境适配对象。

环境不是规范事实源。环境中的规则、配置、Skill、Agent、Hook、命令、页面和缓存，都只是对 docs/specs 正式规范的运行投影或辅助入口。

### 3.2 环境适配映射

本文要求环境适配映射说明某项规范落地要求和保障机制，在特定环境中通过哪些机制、文件、配置、命令、工具、页面或降级策略实现。

环境适配映射回答：

1. 当前环境是否支持该落地要求；
2. 支持时映射到哪个环境能力或实体；
3. 调用入口、文件路径、配置位置或命令是什么；
4. 验证方式是什么；
5. 不支持时如何降级，是否需要 Human Gate 或后续任务。

具体平台能否作为 42 LDVH落地与检查的完整执行依据或 pass 依据，应由平台适配清单的要求响应矩阵、refs_evidence、degradation、check_evidence、open_items 和 42 现场检查结论判断。环境适配映射不得跳过清单机制，直接把平台名称写成完整支持。

环境适配映射不得反向改写规范本身。

### 3.3 运行投影

本文要求运行投影只作为环境适配映射后实际生成、维护或调用的入口、文件、命令、配置、工具、页面、Skill、Agent、Hook、CI 检查、摘要或降级记录。

运行投影用于帮助 AI 和 Human 在具体环境中执行、看见、检查或同步规范，但运行投影不是最终事实源。运行投影与 docs/specs 正式规范冲突时，以 docs/specs 正式规范为准。

### 3.4 漂移

本文将运行投影、环境适配映射或自动触发方式与 docs/specs 正式规范不一致，或规范已变更但运行投影未同步的情形，纳入漂移检查。

漂移检查可以由 Code、子 Agent 思考、Human Gate 或环境触发能力共同完成。检查结果不是最终事实源；默认只进入当前落地与检查报告。需要保留的结论应按内容性质另行回写到正式规范、Task、Memo、ADR 或其他权威位置。

## 4. 环境适配映射规则

环境适配映射应以规范落地要求为输入，不得以某个环境已有能力反向决定规范需要什么要求。

LDVH 不维护当前环境状态登记表。创建、修改、删除或宣称完成持久运行投影前，AI 应现场确认当前平台、当前平台适配清单、权限边界、Human 授权、真实文件或配置、验证方式和降级方式。确认结果只作为本次行动依据，并进入 42 落地与检查报告；需要沉淀为稳定事实的结论，应按内容性质另行写入 Task、Memo、ADR、正式规范、平台清单 open_items 或对应 Git 文件事实源。

管辖项目接入 LDVH 时，AI 应先读取工作区根目录 `LDVH-GOVERNED-PROJECTS.yaml`，确认当前项目是否已登记，再检查对应项目的 `ldvh-base/`、`docs/` 和必要的工作区级薄入口是否能把当前项目连接到 LDVH 管理链路。管辖项目一般不得创建平台规则文件、项目指令、Hook、Skill 或等价项目级入口；确需例外时，必须由 Human 明确授权并记录影响范围。

若当前平台清单缺失、关键要求证据不足或真实运行投影无法现场确认，AI 可以调研平台能力、草拟修改建议、执行临时分析和记录降级方式，但不得宣称某项环境适配映射或持久运行投影已经完整落地。

环境适配映射至少说明：

| 字段 | 含义 |
|---|---|
| 环境 | Codex、Trae、Claude Code、Cursor、CI、Web 或其他环境 |
| 落地要求 | 被适配的规范落地要求 |
| 保障机制 | 在该环境中使用的机制组合 |
| 运行投影 | 具体文件、配置、命令、Skill、Agent、Hook、页面或降级记录 |
| 验证方式 | 如何确认运行投影存在、可用、未漂移 |
| 降级方式 | 环境不支持时如何处理 |

不同环境可以用不同方式满足同一要求。例如生命周期触发要求在某些环境中可以映射为 Hook，在 CI 中可以映射为工作流检查，在其他环境中可以映射为规则条件、自动运行、主控流程或人工降级检查。

环境适配映射不得省略降级方式。只要某个环境不支持稳定触发、并行子 Agent、受控写入、Human 交互或其他要求，就必须说明降级检查如何发生。

## 5. 运行投影规则

运行投影必须保留权威来源。生成、维护或使用运行投影时，应能追溯到对应 docs/specs 正式规范、规范落地要求和环境适配映射。

运行投影不得承载以下内容：

1. 与 docs/specs 正式规范冲突的规则；
2. 未被正式规范吸收的 evals、refs 或临时判断；
3. 反向改变规范落地要求的环境能力假设；
4. 未经 Human Gate 授权的自动写入或自动覆盖规则；
5. 被当成最终事实源的缓存、摘要、工具输出或页面状态。

运行投影可以承载以下内容：

1. 入口摘要；
2. Skill、Agent、Hook、CI、命令或页面入口；
3. Code 校验命令或测试入口；
4. Human Gate 提示；
5. 降级检查方式；
6. 运行投影与正式规范的版本或路径关联。

运行投影必须限定在当前项目或当前环境授权范围内，并区分工作区入口视角、LDVH 管理入口视角和管辖项目自身事实源。

工作区入口视角用于所有管辖项目共同遵守和使用。LDVH落地需要让 AI 稳定进入 LDVH 时，AI 应在 Human 授权下检查对应平台的工作区级入口，并尽量只加入一条醒目的薄引用，把 AI 引向同一个 `../../LDVH-AI-ENTRY.md`。进入后，AI 应优先使用该文件中的工作区入口视角识别管辖项目、定位 `LDVH-GOVERNED-PROJECTS.yaml`、管辖项目自身 `docs/`、`ldvh-base/`、当前平台适配清单和必要工作流程。不同环境的配置位置和写法由环境适配映射决定；LDVH 正式规范只提出需要工作区级入口引导，不替用户维护全局配置正文。

LDVH 管理入口视角用于管理 LDVH 自身项目，包括修改 `docs/specs/`、`tools/`、`tests/`、`web/`、根目录配置、平台适配清单和运行投影。该视角也由同一个 `../../LDVH-AI-ENTRY.md` 承载，不另建第二个入口文件。管辖项目一般不得创建平台规则文件、项目指令或等价项目级入口，避免和用户项目原有入口冲突；确需例外时，必须由 Human 明确授权并记录影响范围。管辖项目可以在自身 `docs/`、`ldvh-base/` 或其他权威 Git 文件中创建项目事实、工作对象实例和按 LDVH 规范治理的记录；这些内容属于管辖项目自身事实源，不是运行入口，也不是 LDVH 自身项目的事实源。

AI 统一入口是入口可见要求的一类运行投影，不是独立构成要素，也不单独拆分为与 Skill、Agent、Hook 并列的专项规范。LDVH 自身项目应优先用根目录 `../../LDVH-AI-ENTRY.md` 同时承载工作区入口视角和 LDVH 管理入口视角；平台 Rules / Instructions、AGENTS、项目规则、工作区配置或等价入口只保留指向该文件的薄引用。

`../../LDVH-AI-ENTRY.md` 位于 LDVH 自身项目根目录，正文使用中文。它不是 docs/specs 正式规范，不是管辖项目默认文件，不是最终事实源，也不替代工作区根目录 `LDVH-GOVERNED-PROJECTS.yaml`、平台适配清单、42 落地与检查报告、工作对象、Code 校验或 Human Gate。

AI 统一入口应至少包含文件身份、事实源边界、入口角色区分、工作区入口视角、LDVH 管理入口视角、场景路由、索引定位、STOP 点和维护提示。入口不得包含完整正式规范正文、工作模型字段契约全文、工作流程执行正文、平台官方教程、管辖项目状态、任务验收结论、未吸收的 evals/refs 结论或未经 Human Gate 授权的自动写入规则。

## 6. 同步与漂移检查

运行投影同步包括 42 LDVH落地与检查中的现场检查和规范变更后的增量检查。

现场检查用于把 LDVH 的规范落地要求映射到当前执行环境。42 LDVH落地与检查应现场读取当前平台适配清单、真实入口、权限、工具和目标项目事实源，并在当前落地与检查报告中说明本次采用的承接方法、降级方式、Human Gate 和残留风险；不得默认创建初始化状态文档、检查状态文档或过程报告文档。规范变更同步用于在正式规范发生变化后检查对应运行投影是否需要更新。

运行投影出现以下情况时，应视为漂移风险：

1. 正式规范已变化，但入口摘要、Skill、Hook、Code、Web 或 CI 未同步；
2. 运行投影复制过期正文，和 docs/specs 正式规范冲突；
3. Code 校验逻辑与正式规范的检查要求不一致；
4. Web、Skill、Agent 或 Hook 依赖的路径、字段或规则已过期；
5. 环境不支持某落地要求，但没有降级记录；
6. 运行投影被当成事实源反向修改规范。

漂移检查发现问题时，应先判断问题属于规范缺口、环境适配缺口、运行投影过期、Code 实现缺口还是 Human Gate 缺口。不同缺口应回写到对应事实源，不得把检查输出直接提升为规范事实。

## 7. 环境能力核验

环境适配前应核验当前环境能力，不得只凭聊天记忆、未生效材料或其他项目经验判断。

环境能力核验来源按以下顺序处理：

1. 当前环境的官方文档、平台说明或当前配置；
2. 已纳入文档工作区 refs 的平台资料；
3. 当前项目中实际存在的运行投影、配置、脚本或工具；
4. Human 明确提供的环境约束或授权。

LDVH 正式规范不复制平台教程、参数手册或完整能力清单。平台客观能力和限制应由官方文档、refs 或当前配置承载；LDVH 正式规范只定义自身如何使用、限制、回写和降级这些能力。

当环境能力核验结果与既有运行投影冲突时，应视为运行投影漂移风险。稳定结论应回写到环境适配映射、LDVH 落地特别要求、个人落地特别要求、Task、Memo 或对应正式规范，不得停留在工具输出或对话中。

## 8. 规范落地要求

本文通过以下规范落地要求说明相关要求的同步、检查或审计触发条件。

| 落地要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 上位约束承接要求 | 环境适配映射必须消费 `docs/specs/04.01-规范落地声明规范.md` 规定的规范落地要求和保障机制，不得反向改写正式规范 | 本文 §4-§7、Human Gate、规范文档检查 | 环境治理 | 本文或 04.01 的落地要求类型、字段、保障机制规则变化时 |
| 入口可见要求 | AI 进行环境适配、运行投影同步或漂移检查时应能定位本文作为权威入口，并能定位 LDVH-AI-ENTRY.md 及平台薄入口 | 规范文档入口摘要、相关规范引用、LDVH-AI-ENTRY.md 或平台薄入口 | AI 执行入口提示 | 本文定位、适用范围、环境适配映射字段、运行投影规则或入口规则变化时 |
| Human 交互要求 | 创建、修改或删除持久运行投影、平台入口、Hook、自动化或工作区级配置前，应现场确认当前平台、权限边界、Human 授权、验证方式和降级方式 | Human Gate、42 落地与检查报告、人工降级检查 | 初始化确认 | LDVH 自身项目切换开发平台、权限边界变化、授权状态变化、创建或修改持久运行投影前 |
| 确定性执行要求 | 后续 Code 应能检查平台清单、运行投影路径、入口摘要和 42 落地与检查报告是否缺失、过期或与正式规范冲突 | `tools/specs_validate.py` 扩展、平台清单校验、后续漂移检查 Code、正反样例 | 校验实现 | 平台清单字段、运行投影字段、漂移检查规则或 Code 消费契约变化时 |
| 生命周期触发要求 | 正式规范、规范落地要求或环境能力变化后，应检查相关运行投影是否需要同步 | 环境触发映射、CI、Skill 流程、Code 检查或人工降级检查 | 触发保障 | 正式规范新增、重命名、删除、规范落地要求变化、环境接入变化或运行投影漂移时 |

具体环境不默认预建单独规范文档，也不默认创建当前环境状态登记表。本文只规定通用环境适配和运行投影规则；LDVH 自身项目或管辖项目实际采用某个环境时，应按 `docs/specs/04.06-平台适配清单规范.md`、42 LDVH落地与检查完成现场检查、过程报告和缺口分流建议，不默认创建状态、检查或过程报告文档。

## 9. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 允许运行投影成为最终事实源；
2. 改变环境适配映射与正式规范之间的权威边界；
3. 删除某项已被正式规范消费的运行投影；
4. 扩大自动同步、自动写入或自动覆盖运行投影的范围；
5. 允许环境能力不足时不记录降级方式；
6. 将某个具体环境实体提升为所有环境必须满足的全局要求；
7. 将不能机械验证的环境适配判断表述为完整 Code 校验通过；
8. 未现场确认当前平台、权限边界、Human 授权、验证方式和降级方式时继续创建持久运行投影；
9. 将会话级判断、工具输出或旧状态记录误用为当前环境事实；
10. 让 AI 统一入口或平台薄入口替代 docs/specs 正式规范；
11. 删除、重命名或移动 LDVH-AI-ENTRY.md，或扩大工作区级入口写入范围影响用户其他项目。

环境适配与运行投影检查至少包括：

| 检查项 | 标准 |
|---|---|
| 权威来源 | 环境适配映射指向正式规范和规范落地要求 |
| 现场确认 | 当前平台、权限边界、Human 授权、真实入口、工具能力、验证方式和降级方式已经在本次行动、42 落地与检查报告中确认 |
| 环境适配映射 | 具体环境实体只出现在环境适配映射或运行投影中 |
| 事实源边界 | 运行投影未替代 docs/specs 正式规范 |
| AI 统一入口 | LDVH-AI-ENTRY.md 只作为根目录运行投影，平台入口只作薄引用 |
| 触发边界 | 必须稳定触发的要求未只依赖 Skill 自动调用 |
| Code 适配 | 可机械化检查已按 `docs/specs/07-Code实现规范.md` 判断和验证 |
| 降级处理 | 环境不支持时已记录降级方式和残留风险 |
| 漂移检查 | 规范变更后已检查运行投影是否同步 |
