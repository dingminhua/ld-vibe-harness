## 1. 本文解决的问题

本文记录 LDVH 中经过实践验证的最佳实践案例。每个案例描述一种具体的工作流模式，说明如何组合使用 LDVH 对象（Memo、Task、ADR 等）和机制（Skill、Rules、Tools 等）来高效完成常见工作场景。

本文不定义新机制或新对象，只记录已有机制的有效组合方式。案例的结论来自实际使用经验，而非理论推导。

## 4. BP-01：Memo 驱动的调研与规划工作流

### 4.1 场景描述

当用户识别到一个需要调研的主题，但调研结果尚不明确、无法直接定义 Task 验收标准时，可以通过 Memo 作为轻量入口启动调研，待调研产出明确后再规划后续工作。

典型触发条件：

1. 用户发现一个值得深入的方向，但不确定可行性或优先级；
2. 用户需要收集信息、评估方案或验证假设，但尚无明确执行目标；
3. 调研可以独立进行，也可以与当前其他工作并行推进。

### 4.2 工作流步骤

```
用户识别调研需求
       ↓
  创建 Memo（记录调研主题、来源和期望产出）
       ↓
  AI 撰写可行性方案 / 调研报告 → 放入 docs/evals/
       ↓
  Memo 关联调研文档（related_docs 或 description 中引用）
       ↓
  调研完成 → 根据调研结论决定后续行动：
    ├─ 结论明确 → 创建 Task 执行
    ├─ 涉及长期决策 → 创建 ADR
    ├─ 需要进一步调研 → 更新 Memo 或创建新 Memo
    └─ 无需行动 → 关闭 Memo
```

### 4.3 关键实践要点

1. **Memo 作为轻量入口**：调研初期信息不充分，不应强制创建 Task（Task 需要明确验收标准）。Memo 的准入条件更低，适合承载"有保留价值但尚未任务化"的调研需求。

2. **分析文档独立存放**：AI 撰写的可行性方案或调研报告放入 `docs/evals/`，而非 `specs/`（LDVH 规范目录）或 `ldvh-base/`（结构化事实实例目录）。外部资料进入 `docs/refs/`；被采纳的稳定结论应吸收到 docs 正文区、ADR、Task、Intent 或 Memo。管辖项目文档定位依据 `specs/03.02-管辖项目文档规范.md`。

3. **Memo 与调研文档关联**：Memo 的 `description` 字段记录调研文档路径，确保从 Memo 可追溯到调研产出。关联方式示例：
   ```yaml
   description: |
     调研 XXX 技术方案的可行性。
     调研报告：docs/evals/xxx-feasibility.md
   ```

4. **独立或并行执行**：Memo 驱动的调研不阻塞其他工作。用户可以同时推进多个调研 Memo，也可以在执行 Task 的同时发起调研。调研完成后，再根据结论决定是否创建新 Task 或 ADR。

5. **调研结论驱动后续规划**：调研完成后的关键决策点是"调研结论是否足以定义下一步行动"。如果结论明确，应立即创建 Task 或 ADR；如果仍需更多信息，应更新 Memo 或创建新 Memo 继续调研。

### 4.4 对象状态流转

| 阶段 | Memo 状态 | 说明 |
|---|---|---|
| 创建调研 Memo | active | 记录调研主题和期望产出 |
| 调研进行中 | active | AI 撰写调研文档，Memo 关联文档路径 |
| 调研完成，结论明确 | closed | Memo 关闭，创建后续 Task 或 ADR |
| 调研完成，无需行动 | closed | Memo 关闭，记录关闭原因 |

### 4.5 与其他案例的关系

本案例是"轻量入口 → 调研产出 → 明确行动"模式的基线。后续案例可在此基础上扩展，例如：

- 多个调研 Memo 的优先级排序和资源分配；
- 调研结论触发 ADR 而非 Task 的判断标准；
- 调研文档的模板化和复用。

## 5. BP-02：Intent 驱动的任务全闭环工作流

### 5.1 场景描述

当用户在聊天中表达一个明确目标时，AI 应自动识别意图、创建 Intent 和关联 Task，根据上下文生成验收标准，经人类确认后执行并自动验收，完成后自动提交。这是 LDVH Core Loop 最核心的工作流模式。

典型触发条件：

1. 用户在聊天中表达了可执行的目标或需求；
2. 目标有明确的完成定义，可以拆解为可验证的验收条件；
3. 用户希望从意图表达到代码提交全流程自动化，仅在关键节点人工确认。

### 5.2 工作流步骤

```
用户在聊天中表达目标
       ↓
  AI 识别意图 → 调用 ldvh-intake Skill
       ↓
  创建 Intent（记录意图、成功标准和约束）
       ↓
  创建关联 Task（source_intent 引用 Intent）
  AI 根据上下文自动生成：
    - description：任务描述
    - acceptance：验收标准（- [ ] 检查列表格式）
    - verification：验证方式
       ↓
  Human Gate：展示 Intent + Task 草案，用户确认
       ↓
  用户确认 → Task 状态流转为 executing
       ↓
  AI 执行任务（按 acceptance 逐项完成）
       ↓
  执行完成 → Task 状态流转为 verifying
       ↓
  AI 自动验收（逐项检查 acceptance 是否 - [x]）
       ↓
  验收通过 → 调用 ldvh-commit Skill 提交变更
       ↓
  提交完成 → Task 状态流转为 closed
```

### 5.3 关键实践要点

1. **Intent 与 Task 自动关联**：用户表达目标后，AI 通过 `ldvh-intake` Skill 创建 Intent 和关联 Task。Task 的 `source_intent` 字段自动引用 Intent ID，确保意图与执行之间的可追溯性。Intent 记录"为什么做"，Task 记录"做什么和怎么验收"。

2. **上下文驱动的验收标准生成**：AI 根据用户聊天上下文自动生成 Task 的 `acceptance` 字段，使用 `- [ ]` 检查列表格式，每项为可独立验证的原子条件。验收标准不是事后补充，而是在 Task 创建时就明确，确保执行有据可依。

3. **Human Gate 作为质量关卡**：Task 创建和验收标准生成后，必须通过 AskUserQuestion 向用户展示草案，用户确认后才进入执行。这一环节防止 AI 误解意图或生成不合理的验收标准。用户可以修改、补充或取消。

4. **执行与自动验收**：AI 按 acceptance 逐项执行任务。执行完成后，AI 自行将 acceptance 中的 `- [ ]` 逐项勾选为 `- [x]`，验证每项是否满足。验收不通过则继续执行，直到全部通过。

5. **提交即闭环**：验收通过后，AI 调用 `ldvh-commit` Skill 提交变更，提交完成后 Task 流转为 closed。从意图到提交形成完整闭环，无需人工介入提交环节。

### 5.4 对象状态流转

| 阶段 | Intent 状态 | Task 状态 | 说明 |
|---|---|---|---|
| 意图识别 | active | — | 创建 Intent |
| Task 创建 | active | planned | 创建关联 Task，生成验收标准 |
| Human Gate 确认 | active | planned | 用户确认草案 |
| 开始执行 | active | executing | Task 进入执行态 |
| 执行完成 | active | verifying | AI 自动验收 |
| 验收通过+提交 | active | closed | 提交变更，Task 关闭 |
| 意图达成 | closed | closed | Intent 关闭 |

### 5.5 与 BP-01 的关系

BP-01 和 BP-02 构成 LDVH 两条核心工作流路径：

- **BP-01**（Memo 驱动）：目标不明确 → 调研先行 → 结论驱动行动，适合探索性工作
- **BP-02**（Intent 驱动）：目标明确 → 直接执行 → 自动验收提交，适合确定性工作

两条路径可以衔接：BP-01 调研结论明确后，可转入 BP-02 创建 Intent + Task 执行。

## 6. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 新增最佳实践案例时，应确认案例来自实际使用经验而非理论推导；
2. 修改已有案例的关键实践要点或工作流步骤时；
3. 将案例结论提升为正式规范规则时。

案例新增和修改检查至少包括：

| 检查项 | 标准 |
|---|---|
| 案例来源 | 来自实际使用经验，非纯理论推导 |
| 对象组合合规 | 案例中对象使用方式符合对应工作模型规范 |
| 目录归属 | 案例中文件存放位置符合 01 目录说明 |
| 状态流转 | 案例中对象状态流转符合对应状态机 |
| 案例索引 | 新增案例已更新案例索引表 |
