## 一、本文定位

Skill 是多角色思考的**轻量执行入口**，用于承接可复用、标准化的分析流程。它只在主上下文中运行，不调度 Agent，输出不作为最终事实源。

---

## 二、什么时候用 Skill

| 场景 | 是否用 Skill |
|---|---|
| 需要独立上下文、结论隔离、并行委派 | 否，考虑 Agent 增强模式 |
| 流程可复用、输入输出稳定、主上下文足以承载 | **是** |
| 只做一次性分析 | 否，主上下文直接处理 |

## 三、Skill 输入

执行多角色思考 Skill 时，至少应提供：

| 输入项 | 说明 |
|---|---|
| 分析主题 | 要分析什么 |
| 用户目标和约束 | 为什么分析、有什么限制 |
| 相关文件/事实源路径 | 基于哪些材料 |
| 期望输出深度 | 轻量/标准/深入 |
| 是否允许建议 Agent 增强 | 是否可以在报告中建议升级 Agent |
| 是否需要回写建议 | 是否要判断事实源回写 |

## 四、Skill 执行流程（精简）

1. 判断是否满足多角色思考准入（41 §4）
2. 读取 41 主文件和必要事实源
3. 识别变更类型 → 选择 3-8 个角色
4. 各角色分别输出：影响范围、结论、风险、建议动作
5. 汇总一致结论、分歧、风险、执行顺序
6. 判断是否建议 Agent 增强、是否触发 Human Gate
7. 输出事实源回写建议

**关键约束：** Skill 发现主上下文不足以承载时，**只能建议**使用 Agent 增强模式，**不得自行调度 Agent**。

## 五、Skill 输出声明

多角色思考 Skill 的报告必须额外声明：

1. 当前模式为 **Skill 辅助模式**
2. 读取了哪些事实源
3. 是否建议 Agent 增强及理由
4. 哪些是事实、哪些是建议
5. 哪些内容需要回写才成为稳定事实
6. 是否触发 Human Gate

## 六、从早期 Skill 迁移

早期 `pm-kit-multi-role-analysis` 仅作参考。迁移到 LDVH 版 Skill 时：

1. 删除绑定 PM Kit 旧路径和旧术语的内容
2. 使用 `ldvh-` 前缀重新命名
3. 明确 Skill 不调度 Agent、输出不是事实源
4. 经 Human Gate 确认后创建 Skill 实体
5. 不得直接覆盖早期 Skill，除非用户明确要求

## 七、门禁

创建、修改、删除、重命名多角色思考 Skill，或改变其部署位置、命名前缀，必须暂停确认。
