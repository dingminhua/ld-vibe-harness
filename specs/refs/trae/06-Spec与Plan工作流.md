## 1. 结论摘要

Trae 提供 Spec 和 Plan 两种工作流，应对不同复杂度的开发任务。Spec 工作流面向复杂系统级任务，生成三阶段文档组（spec.md / tasks.md / checklist.md），存储于 `.trae/specs/<任务名称>/`；Plan 工作流面向中小型任务，生成计划文档（plan.md），存储于 `.trae/documents/`。两种工作流均需用户确认后执行，支持手动编辑和 AI 自动调整。

## 2. 官方定位

Trae SOLO 提供 Spec 和 Plan 两种工作流，以应对不同复杂度的开发任务。

## 3. Spec 工作流

Spec 工作流面向更复杂的系统级任务。AI 根据需求生成完整的三阶段文档组，文档存储在项目根目录下的 `.trae/specs/` 目录中，按任务名称分组为独立文件夹。

### 3.1 生成文档

| 文件 | 描述 |
|---|---|
| spec.md | 大纲文档 |
| tasks.md | 任务列表 |
| checklist.md | 验收清单 |

### 3.2 执行流程

1. AI 根据需求生成三阶段文档组
2. 文档首次创建时，AI 暂停执行并等待用户确认
3. 用户可直接编辑文档内容，或用自然语言告知 AI 修改部分
4. 确认执行后，任务列表和验收清单的状态随执行进度自动更新

### 3.3 适用场景

| 场景 | 描述 | 为什么需要 Spec |
|---|---|---|
| 从零搭建新系统/模块 | 从零搭建完整的服务、模块或应用 | 需求范围大、架构决策多，须先对齐大纲 |
| 大规模重构 | 架构级重构或技术栈迁移 | 涉及大量文件和模块间依赖，需清晰拆解和验收标准 |
| 多人协作项目 | 多位工程师基于 AI 协同开发 | Spec 文档作为单一事实来源对齐理解 |
| 高质量/高稳定性项目 | 核心业务逻辑、支付系统、安全模块 | 需要详尽的验收清单确保每个环节达标 |
| 需长期维护的项目 | 持续迭代、有历史包袱的成熟项目 | Spec 文档留存为项目知识资产，降低维护成本 |

### 3.4 启用方式

- 在对话输入框中输入 `/`，然后从列表中选择 Spec
- 在对话输入框中输入 `/spec` 命令，然后按下回车键

## 4. Plan 工作流

Plan 工作流适用于中小型功能开发和模块级重构。启用后，AI 分析需求并规划任务，在 `.trae/documents/` 目录下生成计划文档（plan.md），待用户确认后一一执行计划中的任务。

### 4.1 执行流程

1. AI 分析需求并规划任务
2. 在 `.trae/documents/` 目录下生成 plan.md
3. 用户确认后 AI 逐一执行计划中的任务
4. 若计划不符合预期，可直接手动编辑，或向 AI 发送修改需求让其自动调整

### 4.2 启用方式

- 在对话输入框中输入 `/`，然后从列表中选择 Plan
- 在对话输入框中输入 `/plan` 命令，然后按下回车键

## 5. 文件存储位置

| 工作流 | 存储路径 | 文件 |
|---|---|---|
| Spec | `.trae/specs/<任务名称>/` | spec.md、tasks.md、checklist.md |
| Plan | `.trae/documents/` | plan.md |

## 6. SOLO 独立端特性

- Spec 和 Plan 工作流在 SOLO 网页版和桌面版均可使用
- Spec 文档可进行版本控制，作为项目知识资产长期保留
- Plan 文档支持手动编辑和 AI 自动调整两种修改方式
