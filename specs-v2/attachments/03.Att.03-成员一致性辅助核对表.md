## 1. 定位

本文承载 03 授权的成员一致性辅助核对表。

03 正文定义行动编排成员主文件的权威边界、成员身份原则、集合状态原则、接管关系、能力保障映射和 Human Gate。本文只维护辅助核对项，不得单独定义成员身份字段、骨架模板、执行流程、Gate、事实源回写、能力资产自描述、Code 输出 Schema 或测试治理标准。

## 2. 成员一致性辅助核对表

行动编排成员一致性辅助核对至少包括：

| 核对项 | 标准 |
|---|---|
| 文件编号一致 | 文件名编号、一级标题、`v2_spec.spec_id` 和 `v2_action_member.spec_id` 一致 |
| 成员区段有效 | 成员编号位于 30-59 |
| 身份块完整 | 同时存在 `v2_spec` 和 `v2_action_member` |
| 成员类型正确 | `v2_action_member.kind` 为 `action_process` |
| 状态闭集有效 | `collection_status` 属于 03 正文定义的闭集 |
| active 回指有效 | v2 未切换前，active 成员能回指 active v1 成员主文件，或有 Human Gate 记录说明新增授权 |
| 锚点完整 | active 成员具备 Scenario、Context、Gate、执行、问题分流、回写、证据和可测试性锚点 |
| 锚点可定位 | 成员锚点能定位到成员主文件正文中的对应章节 |
| 分流与暂停存在 | 成员主文件保留执行中问题分流与失败暂停章节，并承接 03 的闭集和反合理化边界 |
| 接管关系可回指 | `assurance_takeover` 能回指来源规范、保障要求和接管范围 |
| 能力映射不过界 | `capability_assets` 只登记流程能力需求和映射，不替代 06 的承载物自描述 |
| 非 active 不执行 | planned、candidate、reserved、removed、deprecated 不进入默认读取顺序或可执行流程 |
| 派生索引不过界 | Code 和知识地图派生成员集合视图，但不替代成员主文件 |

## 3. 典型诊断分流

| 诊断 | 分流 |
|---|---|
| 身份字段缺失、状态非法、锚点不可定位 | 回到成员主文件修正 |
| 成员状态想从非 active 升级为 active | 触发 03 Human Gate，并核对 active 事实源或新增授权 |
| `assurance_takeover` 无法回指来源保障要求 | 回到来源规范和成员主文件修正接管关系 |
| `capability_assets` 指向不存在、不可验证或权限不足的能力 | 回到 06、对应承载物、04/05/08 或人工降级检查 |
| Code 派生索引与成员主文件冲突 | 以成员主文件和 active 事实源为准，修正 Code 或成员身份 |
