## 一、本文定位

本文是 `specs/21-ADR-决策记录.md` 的附件型实践子文档（编号 21.02），承接 Skill 流程实践。本文不是独立事实模型，不得重新定义 ADR 的对象定位、准入条件、状态机、对象关系、Human Gate、字段契约、事实源回写或证据留存。发生冲突时，以 21 主文档和上位基础规范为准。

---

## 二、当前状态与实践目标

本文当前为 active-prep 状态，定义 ADR 创建、升级、推翻和废弃的可复用流程。当前不创建 `.trae/skills/ldvh-adr/` Trae Skill 实体，AI 可在主上下文中读取本文并按流程执行。

保留本文的目标是为 ADR 创建、升级和推翻提供稳定流程说明，确保 AI 在处理 ADR 时遵循准入条件、状态机、Human Gate 和事实源回写要求。后续如需创建 Trae Skill 实体，应按 `specs/11.02-Skill机制规范.md` 评估 Human Gate、补充实体路径和 Change 记录。

---

## 三、适用场景

1. AI 识别到满足 ADR 准入条件的判断，需要创建 ADR 时；
2. 已有 ADR 需要升级为 specs 或 Rules 时；
3. 已有 ADR 需要被推翻或废弃时。

---

## 四、实践边界

1. 本实践只约束 ADR 的 Skill 流程，不约束 Rules 入口、Agent 调度、Tools 辅助或 Web 展示；
2. ADR 的完整准入条件、状态机、Human Gate 和字段契约由 21 主文档定义；
3. Skill 流程中涉及的 Human Gate 判断以 21 §七 为准；
4. 本实践不替代 21 主文档的任何章节。

---

## 五、实践内容

### 5.1 ADR 创建流程

1. AI 识别到判断满足 ADR 准入条件（21 §3.3）；
2. AI 输出判断内容和准入条件匹配说明，提示用户确认是否创建 ADR；
3. 用户确认后，AI 创建 ADR YAML 实例，初始状态为 `proposed`；
4. ADR 实例写入 `ldvh-base/adrs/adr-{NNNN}-short-title.yaml`；
5. AI 在 `ldvh-base/changes/`创建 Change 记录；
6. ADR 从 `proposed → accepted` 需经 Human Gate 确认（21 §7.1）。

### 5.2 ADR 升级流程

1. AI 识别到 ADR 满足升级条件（21 §6.4）；
2. AI 输出升级理由和目标 specs 或 Rules 文件，提示用户确认；
3. 用户确认后，AI 将规则正文写入 specs 或 Rules；
4. ADR 保留原因和背景，不删除；
5. ADR 的 `related_rules` 字段记录升级后的规则文件；
6. 在 `ldvh-base/changes/`创建 Change 记录；
7. 升级操作须经 Human Gate 确认（21 §7.1）。

### 5.3 ADR 推翻流程

1. AI 识别到需要推翻已 accepted ADR；
2. AI 输出推翻原因和替代方案，提示用户确认；
3. 用户确认后，AI 创建新 ADR（初始状态 `proposed`），在新 ADR 的 `context` 中说明推翻原因；
4. 旧 ADR 状态变更为 `superseded`，`superseded_by` 字段引用新 ADR ID；
5. 在 `ldvh-base/changes/`创建 Change 记录；
6. 推翻操作须经 Human Gate 确认（21 §7.1）。

### 5.4 ADR 废弃流程

1. AI 识别到需要废弃已 accepted ADR；
2. AI 输出废弃原因，提示用户确认；
3. 用户确认后，AI 将 ADR 状态变更为 `deprecated`；
4. 在 ADR 的 `consequences` 或 `context` 中补充废弃原因；
5. 在 `ldvh-base/changes/`创建 Change 记录；
6. 废弃操作须经 Human Gate 确认（21 §7.1）。

---

## 六、Human Gate

1. ADR 创建后从 `proposed → accepted` 必须经 Human Gate 确认；
2. ADR 升级为 specs 或 Rules 必须经 Human Gate 确认；
3. ADR 推翻或废弃必须经 Human Gate 确认；
4. AI 不得自行执行任何需要 Human Gate 确认的 ADR 状态变更。

---

## 七、检查项

检查 ADR Skill 流程是否合规时，应确认：

1. ADR 创建时是否检查了准入条件（21 §3.3）；
2. ADR 初始状态是否为 `proposed`，未直接创建为 `accepted`；
3. ADR 状态变更是否合法（21 §5.2）；
4. 需要 Human Gate 的操作是否经用户确认；
5. ADR 推翻时是否创建了新 ADR 并在旧 ADR 中填写 `superseded_by`；
6. 每次状态变更是否在 `ldvh-base/changes/`创建了 Change 记录；
7. AI 是否未自行执行需要 Human Gate 确认的操作。
