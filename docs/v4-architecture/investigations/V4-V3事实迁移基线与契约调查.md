## 3. 不可变机器基线

`migration/v3-facts/baseline.json` 是首个机器闭集。每个源对象冻结：

- 排序稳定且唯一的 `source_key`；
- V3 类型、ID、原状态、POSIX 源路径和载体；
- byte size、SHA-256、Git blob OID、完整 snapshot commit；
- 原始 `created`、`updated` 和可取得的 `closed_at`/`resolved_at`，不修正、不补时区。

`tools/verify_v3_fact_baseline.py` 只读验证 manifest schema、commit/tree、92 项数量和状态分布、目录/文件名/type/ID 一致、YAML/Markdown 可解析、路径与 key 唯一、工作树 bytes 与冻结 blob/SHA 一致、没有源文件增删漂移，并拒绝 baseline-only 阶段出现 `facts/**` 文件。根级 `ldvh-base/` 出现旧载体对象时报告 `out-of-baseline`。

基线不包含语义映射、V4 target、状态结论或迁移完成声明；archive source 只能证明历史输入，不能单独证明当前结论、证据充分或终态成立。

## 4. 当前 blocker

1. 05 当前只允许 Code 分配当前身份与当前时间并创建合法初态；31/32 排除迁移，现有 Code 没有历史导入、批处理或 receipt 能力。
2. closed WorkCase 不能直接复制为 V4 `closed`。伪造 V4 review、approval、验证或当时发生过的生命周期不成立。
3. 92 项尚未逐源完成类型、状态、保留/退出内容、证据、拆分/合并和 target 审核。
4. 尚无全量双向 source↔target ledger、无写 dry-run、可恢复/幂等写入、全图关系验证和批次 Git anchor 机制。

在这些 blocker 关闭前不得创建生产 V4 迁移实例。

## 5. 当时的后续契约候选

当时提出的正式准入与实现候选如下；它们未取得规则效力，也不再构成当前建设计划：

1. 类型与状态不机械映射。`pending` 不自动为 `open`，`resolved` 不自动为 `routed`，`active` 不自动保持 current，closed WorkCase 默认重新分类其仍有价值的内容。
2. 每个 target 的 `source_refs` 至少回指全部贡献 V3 源文件及冻结 commit；archive 引用不替代当前 evidence。
3. 1:N 与 N:1 映射必须双向对称；每个 source 恰有一个主 ledger 项且最终 target 非空，每个 target 反列全部 source。
4. `related_*`、`resolved_to` 和 `input_refs` 只是关系候选；只有来源类型允许、方向真实且目标 current 时才形成 V4 relation，其它内容进入 source、正文或 ledger。
5. 全量 dry-run 必须先稳定生成目标 bytes/digest。写入时目标不存在才创建；相同 bytes 视为已完成；不同 bytes fail closed；不覆盖、不盲重试。
6. 批次以稳定 batch ID 和输入/输出 tree digest 关联。对象提交不自写自身 commit SHA；最终收口提交回填前序 batch commit anchors。
7. pilot 必须同时覆盖非终态、resolved、discarded、closed WorkCase 有/无旧确认、缺时区、Study URL、拆分、合并和关系修复。

## 7. 当时的全量迁移待决定项（不再是当前 Gate）

当时的正式契约方案要求两个全局决定：

1. **历史身份与时间。** 推荐把全部 V4 target 视为当前新建 successor，使用新 V4 身份与迁移时点；V3 ID 和原始时间只保存在 immutable ledger/source refs，不猜测 28 个缺时区对象。
2. **无法合法归入五类型的历史对象。** 推荐坚持五类型语义重新分类，不新增“历史记录”伪类型或迁移专用终态；某项仍无合法承接时单项交还 Human。

这两个决定当时不影响基线提交，但会阻断全量迁移契约和生产实例写入。选择性吸收决定生效后，它们不再是当前路线的前置事项；未来只在 Human 选中的具体范围确有相应问题时重新判断。

## 8. 当时建立的 decision-independent V3 source characterization

机器基线完成后，下一阶段 subagent PRE review 最初对“semantic ledger foundation”提出 `REQUEST CHANGES`：当前尚未逐项判断内容、target、状态、证据或拆分/合并，不能使用 semantic ledger 名称或完成口径。处置后，本阶段严格改为 `V3 source characterization`，不等待 §7 的两个 Human 决定即可机械建立，但不得进入正式迁移契约或实例写入。

`migration/v3-facts/source-characterization.json` 与 baseline 92 项 1:1 join，并由 `tools/verify_v3_fact_characterization.py` 确定性重建和验证。当前 artifact 只记录：

- 1,882 个顶层字段的完整 key、JSON kind、空值标志和内容 digest；
- 全部 797 个递归 time-shaped leaf，包括 `created`、`updated`、任意 `*_at` 和通用 `at`；其中 631 个带 offset、89 个 naive datetime、5 个 date-only、50 个空字符串、22 个 null，仅保留 pointer、kind、canonical digest/长度和分类，不复制原值、不补时区、不转换、不推断历史真实性；
- 3,353 个递归 legacy reference observations，按 exact fact ID、fact path、document path、URL、opaque、empty/null 等语法分类；只保留 pointer、kind、canonical digest/长度和语法分类，可唯一命中 baseline 的旧 ID 只回指 source key，全部固定 `v4_relation_decision: undecided`；
- frontmatter 与 Study body/H1/H2 section 的结构定位、长度和 digest，共 211 个 content regions，不复制或总结其语义；
- 唯一一组 exact title collision：`spark-0027` 与 `workcase-0009`，只记录机械碰撞，不形成合并候选决定；
- 每项原 V3 type/status 和“不得机械映射”的风险码。

artifact 顶层固定 `semantic_reviewed_count: 0`、`target_decided_count: 0`；每项固定 `review_state: not_started`，`target_identity`、`target_type`、`target_status` 和 `split_merge` 均为 `undecided`。验证器只读：它只能验证已有 artifact 或向 stdout render canonical JSON，不提供文件写入参数；并拒绝符号链接/非普通 artifact、任何字段增删、重复 JSON key、非 canonical bytes、baseline 漂移、观察遗漏/误分类或决策字段提前变化，并继续通过 baseline validator 保证 `facts/**` 为零。

该 characterization 只降低后续逐项审核的机械漏读风险。它不等于 semantic ledger，不表示 92 项中任何一项已经选择 V4 target、完成内容取舍、建立 V4 relation 或开始迁移。
