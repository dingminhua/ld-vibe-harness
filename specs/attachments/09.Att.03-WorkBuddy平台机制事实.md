## 1. 角色定位

**WorkBuddy 专家团 = 承载 WC 独立复核的协作 Worker 载体。** 执行 WC 流程时，在创建复核 / PlanΔ 复核 / 结果复核（复核位置见 21 §4.5）环节，由主控（Controller）**临时 TeamCreate 组建专家团、spawn 成员做只读第二视角**。专家团自身的预建与打包（Team 型专家包）见 §4 指针，不属 LDVH 执行期动作。

## 2. 平台机制事实

### 2.1 复核载体

| 载体 | WorkBuddy 实际承载 | LDVH 接入注意 |
|---|---|---|
| 协作 Worker | 专家团（多 Agent 协作） | 复核时承载 `collaboration-worker-read-only` |
| subagent | Agent 工具派生的只读子代理 | 复核时承载 `subagent-read-only` |

### 2.2 模型指定

只能三档：`default`（默认）、`reasoning`、`lite`，不能指定任意模型名。`reviewer_policy.model` 只能取三档之一。

### 2.3 专家团协作格式（执行期临时组建时须遵守）

- **团队建立**：主控（Controller）亲自 TeamCreate，严禁委派成员创建团队
- **成员调度**：Agent 工具 `name` 参数传 Agent ID（agents/ 下 MD 文件名），不用中文名
- **成员产出**：成员独立产出专业结论，主控只编排汇编、不代写
- **消息流**：跨成员信息必须经主控中转，不得直连
- **5 条红线**：禁跳过 TeamCreate 模拟成员、禁代写成员产出、禁跳阶段、禁成员直连、禁 spawn 主控自己
- **裁决型角色**必须给明确结论，不得回避

### 2.4 SOP 编排（多成员复核时）

- **并行 Phase**：无数据依赖的成员，同一条消息 spawn 多个
- **串行 Phase**：等前一 Phase 全部回传后，结论传入下一 Phase
- 对应 LDVH：委派 1–2 视角独立复核时各视角并行；分阶段复核时串行
