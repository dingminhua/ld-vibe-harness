## 1. 定位

本文承载 08 授权的测试同步触发矩阵。

## 2. 触发矩阵

| 变化类型 | 应检查 |
|---|---|
| 规范新增、删除、重命名、编号占用、引用或章节结构变化 | 上层测试要求、文档结构校验、回归入口 |
| 事实模型字段、状态机、对象关系、事实源边界或受控写入变化 | 事实模型测试、写入前检查、对象样例、Web 展示 |
| 行动编排 Context、Scenario、Gate、流程、回写或证据变化 | 成员可测试性锚点、流程正反例、失败原因 |
| Code CLI、输入输出、错误码、诊断、写入、目录假设或模块结构变化 | Code 完整验证入口、单元测试、综合校验、下游消费 |
| Web API、页面、组件、缓存、白名单、Confirm UI、i18n 或来源呈现变化 | API contract、页面受限状态、来源回指、Web 回归入口 |
| 运行时扩展入口、Rules、Skill、Agent、Hook 或环境适配变化 | 入口加载、薄引用、权限边界、适配检查 |
| 测试目录、命令、夹具、Mock、构建入口或验证入口变化 | 归属矩阵、实现域文档、验证声明标准 |
| 工作项关闭、验收、发布、迁移或删除实现 | 验证证据是否可复现、残留风险是否可接受 |

## 3. 分流规则

触发后应先判断变化属于上层测试要求、实现测试细则还是测试实现。上层规则进入 specs，当前参考实现细节进入 `code/docs/` 或 `web/docs/`，可执行测试进入 `tests/`。
