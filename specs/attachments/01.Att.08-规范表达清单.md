## 2. 不推荐表达结构

不推荐表达表使用以下结构：

| 字段 | 含义 |
|---|---|
| `不推荐表达` | 应避免的新正文表达 |
| `推荐表达` | 应替换为的表达 |
| `处理方式` | `改写`、`按上下文拆分`、`保留历史原文` 或 `待确认` |
| `说明` | 为什么不推荐或如何判断 |

不推荐表达的处理方式闭集为：

| 处理方式 | 含义 |
|---|---|
| `改写` | 新正文应直接替换为推荐表达 |
| `按上下文拆分` | 原表达覆盖多个语义，应按具体上下文拆成更准确表达 |
| `保留历史原文` | 仅在引用旧文、历史记录或迁移来源时保留，不作为新正文推荐写法 |
| `待确认` | 替代写法、影响范围或术语边界需要后续确认 |

本文中的处理方式只约束本附件内部表达条目维护，不得扩展为事实模型状态、行动编排状态或 Code 输出状态。

## 3. 不推荐表达与替代写法

| 不推荐表达 | 推荐表达 | 处理方式 | 说明 |
|---|---|---|---|
| 知识图谱 | 知识地图 | 改写 | v2 推荐“知识地图”，强调由规范结构和 Code 派生的定位关系 |
| 图谱投影 | 知识地图 / 派生视图 | 按上下文拆分 | 指整体关系视图时用知识地图；指展示结果时用派生视图 |
| 工作闭环 | 运行闭环 | 改写 | v1 已要求优先使用运行闭环；v2 00 不展开生命周期细则 |
| 平台 | 环境 | 改写或保留历史原文 | 吸收到规范正文时应改写为环境 |
| 平台能力 | 环境能力 | 改写 | 避免把外部产品能力误写成 LDVH 全局能力 |
| 能力项 | 环境能力 / 适配项 / 适配措施 | 按上下文拆分 | 区分环境客观能力、适配卡片条目和具体适配措施 |
| 承接机制 | 保障机制 / 适配方式 / 适配措施 | 按上下文拆分 | 规范层用保障机制，环境层用适配方式，具体结果用适配措施 |
| 机制混同关系 | 规范保障要求 + 能力保障 + 环境适配 | 拆分 | 不得把三层机制写成一个关系 |
| 机制承接关系 | 规范保障要求 + 能力保障 + 环境适配 | 拆分 | 无法确认环境实体时先进入待补齐事项 |
| 事实对象 | 工作对象 / 工作对象实例 | 改写 | 避免与事实源混淆 |
| 状态 | 对象状态 / 集合状态 / 检查过程状态 / 派生状态 / 适配措施状态 | 加限定词 | 状态必须说明类型 |
| 检查报告 | 具体检查结果 / 部署适配检查报告 | 按上下文拆分 | 不作为固定流程输出名称 |
| 待补齐项 | 待补齐事项 | 改写 | 中文显示统一使用待补齐事项 |
| 输入材料 | 参考与研究材料 | 改写 | 不作为正式层级使用 |
| 来源文档 | 来源 | 改写 | 来源可能包括规范、sources、studies、命令输出、Human Gate 记录或其他事实源 |
| 人工 | Human / AI / Code / Web / 环境 / 手动命令 | 按上下文拆分 | 不得把“人工”作为默认执行主体；必须说明真实主体或具体动作 |
| 用户确认 | Human 确认 / Human Gate / 项目所有者确认 / 环境所有者确认 | 按上下文拆分 | LDVH Gate 口径使用 Human；“用户”仅在安装者、环境所有者、项目所有者等非 Gate 身份语境保留 |
| 人工核对 / 人工检查 / 人工复核 / 人工审查 | Human 复核 / AI 回读核对 / 文件事实源核对 / Code 校验 / 手动命令核对 | 按上下文拆分 | 只有真实人类判断才使用 Human；AI 读文件或执行核对不得写成人工 |
| 人工降级 / 人工降级检查 / 人工降级路径 | 废止表达；按问题拆为工具不可用、工具输出不足、能力缺口、事实冲突、环境入口缺口、AI 回读核对、文件事实源核对或 Human Gate | 保留历史原文 | 旧表达同时混淆执行主体和 legacy 降级概念；新正文不得作为正式机制、状态、诊断名或推荐输出 |

## 4. 执行主体命名规则

执行主体命名必须让 AI 和 Human 能看见“谁在执行、谁在判断、谁在展示、谁在承载”。新正文不得用“人工”“用户”“工具”“系统”“平台”“机制”等含混词替代明确主体。

| 主体类别 | 推荐主语 | 适用动作 | 禁止写法 |
|---|---|---|---|
| 默认执行主体 | AI / 主控 AI | 读取入口、回读事实源、综合判断、编排任务、交还结果 | 人工处理、系统自动理解 |
| 真实人类判断 | Human / Human Gate / Human 确认 | 授权、确认、方向校正、验收、长期风险接受 | 用户确认、人工确认、AI 代确认 |
| 子任务执行者 | 子 Agent | 主控 AI 分配的调查、复查、分析或执行片段 | 子 Agent 独立决定状态流转、子 Agent 拥有事实源状态 |
| 确定性实现 | Code / 测试 / 校验器 / 命令入口 | 结构化解析、机械校验、诊断、投影、回归验证 | 人工检查、Code 判断价值取舍 |
| Human-facing 展示 | Web / Human-facing 页面 | 展示、交互、同步态势、Confirm UI | Web 确认事实、页面替代事实源 |
| 环境与部署 | 环境 / 运行时扩展 / 已部署副本 / 适配措施 | 可触达性、部署状态、入口接入、权限和适配状态 | 固定资产存在等于环境已支持、平台能力裸用 |
| 事实与追溯 | Git / Git commit records / 工作对象 / Study / Spark | 事实源修改追溯、事实承载、研究结论、火花记录 | 工作对象执行检查、Study 授权规则 |
| 手动操作 | 手动命令 / 手动步骤 | Human 或 AI 在环境中按命令执行的非自动化操作 | 人工降级路径、手动步骤等于完整支持 |

旧表达出现在历史引用、迁移来源、待检测输入样本或废止表达说明中时，必须显式说明其不是 active 推荐写法。吸收历史对象时，应保留来源可追溯性，并把当前有效结论写成明确主体、具体核对动作、问题原因或后续承接事实源。

## 5. 中文定语规则

中文“规则”“技能”“代理”“智能体”“工具”“程序”“展示”“机制”等词不得裸用，除非上下文已经通过标题、表格字段或段落首句明确限定其语义。

| 场景 | 推荐用语 | 避免裸用 |
|---|---|---|
| specs 中的稳定条款 | 正式规范、规范规则、规范要求 | 规则 |
| 事实模型字段、状态、验收、检查 | 字段规则、状态规则、验收规则、对象检查 | 规则 |
| 行动编排 Context、Scenario、Gate、执行、回写、证据 | 行动规则、Scenario 识别条件、Gate 条件、回写要求 | 规则、触发规则 |
| 检查、校验、验证、审计 | 检查方式、校验命令、验证证据、审计范围 | 检查、校验、验证、审计裸用且无上下文限定 |
| 写入和回写 | 写入动作、受控写入、事实源回写、回写位置 | 写入、回写裸用且无事实源或权限限定 |
| AI 泛称 | AI 执行者、AI 代理能力、子 Agent | 代理、智能体 |
| 确定性实现 | Code 实现、工具、脚本、校验器、命令入口 | 程序 |
| Web 能力 | Web、Human-facing 页面、信息同步、受控交互 | 展示 |
| 运行时扩展 | Rules、Skills、Agents、Hooks、运行时扩展承载物 | 机制、能力裸用且无上下文限定 |

| 检查项 | 标准 |
