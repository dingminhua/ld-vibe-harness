## 1. 本文定位

本文是 `specs/22-Change-变更记录.md` 的历史机制文件（编号 22.04），承接 Tools 契约式校验实践。本文不是独立工作模型，不得重新定义 Change 的对象定位、准入条件、状态机、对象关系、Human Gate、字段契约、事实源回写或证据留存。发生冲突时，以 22 主文档和上位基础规范为准。

本文是 Change Tools 命令、参数、测试和能力声明的权威位置。Change 的 commit message 格式校验依据 `specs/22.06-Contract.md`。

---

## 2. 实践目标

为 Change 提供可重复、可校验的 Tools 辅助能力，帮助 AI 和人在提交前检查 commit message 是否符合 `specs/22-Change-变更记录.md` §8 定义的格式规范，以及是否与 `specs/22.06-Contract.md` 定义的契约一致。

当前 Tools 为只读校验，不执行任何写入操作。commit 写入由 Git 原生命令执行，不需要 Tools 受控写入。

---

## 3. 适用场景

1. AI 在 commit 前自检 commit message 格式是否合规；
2. 产品审计时批量检查历史 commit 是否符合格式规范；
3. 持续检查项目中最近 N 条 commit 的格式合规率。

---

## 4. 实践边界

1. 当前 Change Tools 实体路径为 `tools/commit_validate.py`；
2. 当前 Change Tools 为只读校验工具，不执行写入操作；
3. 当前 Change Tools 通过 `git log --format` 读取 commit 历史，按 `specs/22.06-Contract.md` 定义的格式契约进行校验；
4. Change Tools 输出属于运行时派生结果，不是最终事实源；Git commit 历史是 Change 的最终事实源；
5. Change Tools 字段校验依据 `specs/22.06-Contract.md`，不得自行扩张契约；
6. Change Tools 不替代 Human Gate，不执行 commit 操作。

---

## 5. 实践内容

`tools/commit_validate.py` 当前提供以下能力：

| 能力 | 说明 |
|---|---|
| 格式查询 | `--show-format`：展示正确的 commit message 格式规范，供 AI 在构造 commit message 时参考 |
| 提交前预检 | `--check-message`：在提交前校验拟提交的 message 文本是否符合 `specs/22.06-Contract.md` |
| git log 审计 | 默认模式：读取最近 N 条 git commit，按格式契约逐条校验 |
| type 校验 | 检查 type 是否在 `specs/22.06-Contract.md` 定义的有效枚举中 |
| scope 校验 | 检查 scope 是否在推荐枚举中（非强制，warning） |
| subject 长度校验 | 检查 subject 是否超过 72 字符 |
| Refs 存在性检查 | 检查是否包含 Refs: 行（非强制，warning） |

### 5.1 命令参数

| 参数 | 说明 |
|---|---|
| `--show-format` | 展示正确的 commit message 格式规范（供 AI 参考，不涉及 git） |
| `--check-message MSG` | 提交前预检：校验拟提交的 message 文本，有 error 时 exit 1 |
| `-n N` / `--count N` | 检查最近 N 条 commit（默认 10，仅在默认模式下有效） |
| `--no-warnings` | 只显示 error，不显示 warning |

### 5.2 命令调用示例

```bash
# 查询正确格式
python3 tools/commit_validate.py --show-format

# 提交前预检（commit 前必须执行）
python3 tools/commit_validate.py --check-message "spec(tools): commit message text

Body text

Refs: 22-Change-变更记录"

# 检查最近 20 条 commit，只显示 error
python3 tools/commit_validate.py -n 20 --no-warnings
```

### 5.3 提交前强制预检制度

AI 在执行 `git commit` 前，必须调用 `--check-message` 校验拟提交的 commit message。预检不通过（exit code ≠ 0）时不得执行 commit。

流程：
1. AI 构造 commit message 文本
2. AI 调用 `python3 tools/commit_validate.py --check-message "<message>"` 预检
3. 预检通过 → 执行 commit
4. 预检不通过 → 修正 message，重新预检，直至通过

### 5.4 测试

测试文件路径：`tests/tools/test_commit_validate.py`

测试命令：

```bash
python3 -m pytest tests/tools/test_commit_validate.py -v
```

测试覆盖范围：
- type 有效/无效枚举校验
- scope 有效/无效推荐值校验
- subject 长度超限校验
- 第一行格式解析（含/不含 scope）
- Refs 缺失 warning
- 空 subject 检测
- 中文字符检测

### 5.5 Contract 消费关系

| 消费项 | `tools/commit_validate.py` 行为 |
|---|---|
| 格式结构 | 校验第一行是否符合 `<type>(<scope>): <subject>` |
| type 枚举 | 校验 type 是否属于 `specs/22.06-Contract.md` §3.1 |
| scope 推荐值 | 校验 scope 是否属于 `specs/22.06-Contract.md` §3.2，非推荐值输出 warning |
| subject 约束 | 校验 subject 不为空且不超过 72 字符 |
| Refs 规则 | 校验 Refs 行存在时内容不可为空 |
| 中文字符检测 | 校验 subject 或 body 中至少包含一个中文字符 |
| 历史审计 | 从 Git commit 历史读取 message 并按同一契约校验 |

### 5.6 同步要求

以下变化发生时，必须同步检查 Change Tools 实现和测试：

1. `specs/22.06-Contract.md` 修改 commit message 格式结构、type 枚举、scope 推荐值、subject 约束、Refs 规则或中文字符检测规则；
2. `specs/22-Change-变更记录.md` 修改提交纪律、准入变更范围或 Change 最终事实源边界；
3. `tools/commit_validate.py` 修改输入参数、输出格式、warning/error 语义或 exit code；
4. `ldvh-commit` Skill 修改提交前预检流程或 commit message 生成要求；
5. Rules 修改准入变更触发条件或提交纪律入口。

---

## 6. Human Gate

以下情况应评估 Human Gate：

1. Change Tools 扩展为执行 commit 写入操作；
2. Change Tools 改变 commit message 格式校验依据；
3. Change Tools 将运行时派生结果持久化为新的事实源。

---

## 7. 检查项

检查 Change Tools 契约式校验实践是否合规时，应确认：

1. `tools/commit_validate.py` 是否读取 Git commit 历史并将校验结果输出为运行时结果；
2. Change 格式校验是否依据 `specs/22.06-Contract.md`；
3. Tools 输出是否未被当作 Change 最终事实源；
4. Tools 是否未替代 Human Gate、未执行 commit 操作；
5. 新增或修改 Tools 能力时是否同步更新 `tests/tools/test_commit_validate.py`；
6. 结构化契约文件变更后，Change Tools 实现和测试是否已同步更新。
