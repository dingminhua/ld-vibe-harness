# 第三方Skill接管落地选项

> 创建日期：2026-06-08
> 更新日期：2026-06-09
> 定位：定义第三方 Skill、平台 Skill 和类似外部可复用 AI 能力在 LDVH 中作为默认可用接管路径时的落地、取消、降级和重新启用规则
> 适用范围：LDVH 自身项目和管辖项目中使用第三方 Skill、平台 Skill、外部 Skill、用户导入 Skill 或类似外部可复用 AI 能力的场景
> 上位依据：`specs-v2/11-非LDVH来源内容治理规范.md`
> 相关规范：`specs-v2/02-术语规范.md`、`specs-v2/04.03-环境适配映射与运行投影记录模板.md`、`specs-v2/04.04-环境能力承接边界.md`、`specs-v2/04.05-LDVH落地特别要求.md`、`specs-v2/06-工作流程基础规范.md`、`specs-v2/07-Code实现规范.md`、`specs-v2/08-Web信息同步规范.md`、`specs-v2/09-事实源边界与承载规范.md`、`specs-v2/10-运行闭环测试规范.md`、`specs-v2/12-最佳实践.md`

## 1. 本文解决的问题

本文解决第三方 Skill 在 LDVH 中是否默认可作为接管路径落地，以及用户如何通过 AI 取消、降级或重新启用这一落地选项的问题。

第三方 Skill 只是非 LDVH 来源内容的一种。它可以帮助生成脚手架、候选代码、候选文档、外部分析或专项输出，但默认不了解 LDVH 的事实源边界、工作模型、工作流程、Human Gate、Code 验证和运行闭环。

本文不是最佳实践文档。本文定义一个默认启用的可选落地项：

```text
第三方 Skill 接管落地选项默认启用；
用户可以通过 AI 请求取消；
取消后，第三方 Skill 不再作为默认落地能力使用。
```

取消本文定义的落地选项，不等于取消 `specs-v2/11-非LDVH来源内容治理规范.md`。无论本文是否启用，所有非 LDVH 来源内容仍必须遵守 11 的识别、准入、隔离、接管、验证、回写和 Human Gate 要求。

---
## 2. 与 00 和 11 的关系

00 要求 LDVH 围绕 Git 可追踪事实源、工作模型、工作流程、Code、Web 和 Human Gate 形成可验证、可回写、可演进的工程闭环。

11 定义所有非 LDVH 来源内容进入 LDVH 管辖时必须遵守的共同治理规则。本文是 11 的专题子文档，只处理第三方 Skill 这一类外部可复用 AI 能力的默认落地方式。

本文只定义第三方 Skill 作为落地选项时的启用、取消、降级和重新启用边界，不复制第三方 Skill 教程，不定义具体平台能力的官方行为，不替代 04、06、07、08、09、10 或 12。

---
## 3. 术语应用关系

本文使用的非 LDVH 来源内容、已接管、未接管、主控接管、信任等级、最佳实践和第三方 Skill 接管落地选项等术语，以 `specs-v2/02-术语规范.md` §10 为准。本文只说明这些术语在第三方 Skill 接管落地场景中的应用关系。

### 3.1 第三方 Skill

第三方 Skill 包括：

1. 平台内置但不是 LDVH 自建的 Skill；
2. 外部开发者提供的 Skill；
3. 用户导入、复制或改造但尚未被 LDVH 接管的 Skill；
4. 与 Skill 等价的外部可复用 AI 能力、模板生成器或平台流程入口。

第三方 Skill 是否来自可信平台，不改变其非 LDVH 来源内容属性。只有完成接管、验证和归属后，它的输出才可进入对应事实源或后续实践。

### 3.2 默认落地

默认落地表示：当用户没有取消本文落地选项，且当前环境支持相关能力时，AI 可以把第三方 Skill 作为候选材料生成、脚手架生成、外部能力接管或包装 Skill 评估的默认可用路径之一。

默认落地不表示：

1. 第三方 Skill 可以直接改写权威事实源；
2. 第三方 Skill 输出可以直接成为任务完成证据；
3. 第三方 Skill 可以绕过 11 的主控接管；
4. 第三方 Skill 可以绕过 Human Gate、Code 验证、事实源边界或工作流程；
5. AI 必须优先调用第三方 Skill。

---
## 4. 默认启用规则

本文定义的第三方 Skill 接管落地选项默认启用。

默认启用时，AI 可以在以下场景中评估使用第三方 Skill：

1. 从空目录生成候选脚手架、初始页面、样例结构或基础配置；
2. 生成候选代码、候选文案、候选测试、候选设计稿或候选配置；
3. 在不直接写入权威事实源的前提下提供专项分析；
4. 辅助理解外部技术、第三方库、平台功能或第三方文档；
5. 对外部资料进行初步整理，供 LDVH 主控后续接管；
6. 在当前 Task 或明确授权范围内完成可验证的局部生成任务；
7. 为是否创建 LDVH 包装 Skill、LDVH 自建 Code 或最佳实践提供 Dogfood 素材。

默认启用时，AI 调用第三方 Skill 前仍应完成：

1. 说明为什么需要第三方 Skill；
2. 判断它只生成候选材料，还是会执行动作；
3. 说明预计影响哪些文件、目录、事实源或运行入口；
4. 检查当前是否已有 Task、验收标准或人工授权；
5. 判断验证方式是否已知；
6. 按 11 判断信任等级、权限限制、主控接管和 Human Gate。

目标不清楚、验证方式不清楚、权限范围不可控或影响范围过大时，不应默认调用第三方 Skill。

## 5. 使用边界

### 5.1 可用路径

第三方 Skill 最稳定的落地路径通常是：

```text
明确目标
  -> 限制输入和输出
  -> 生成候选材料
  -> LDVH 主控接管
  -> 验证与风险检查
  -> 按归属回写
  -> 决定直接使用、包装、降级、沉淀为最佳实践或废弃
```

脚手架场景可使用：

```text
脚手架生成
  -> 治理接管
  -> 审计改造
  -> 持续开发回到 LDVH
```

### 5.2 不适用路径

第三方 Skill 不适合作为以下能力的默认落地路径：

1. 直接修改正式规范；
2. 直接修改工作对象状态；
3. 直接修改字段契约、状态机或 Human Gate 条件；
4. 自动提交、推送、发布或删除；
5. 访问敏感信息、外部账号或高权限环境；
6. 作为持续开发主控；
7. 绕过 11 的主控接管；
8. 替代 Code、Web、运行闭环测试或 Human Gate。

上述场景如果确实需要借助第三方 Skill，只能让其生成候选材料，并由 LDVH 主控按对应规范完成接管。

### 5.3 直接使用与包装

以下情况可以直接使用第三方 Skill，并由当前任务承担接管检查：

1. 首次试用；
2. 低频使用；
3. 产出物主要是候选材料；
4. 不涉及权威事实源直接写入；
5. 接管和验证可以在当前任务内完成；
6. 尚无足够实践证据证明需要包装。

以下情况可以考虑创建 LDVH 包装 Skill：

1. 同类第三方 Skill 被反复用于相似场景；
2. 调用前上下文装配稳定；
3. 调用中限制稳定；
4. 调用后接管检查稳定；
5. 多次出现遗漏事实源边界、Human Gate 或验证步骤的风险；
6. 包装后能降低执行摩擦，而不是增加抽象负担。

包装 Skill 的职责是装配 LDVH 上下文、限制输入输出、提示接管检查和交还主控。包装 Skill 不应复制第三方 Skill 教程，不应新增正式规范规则，也不应绕过 Human Gate。

## 6. 取消落地选项

用户可以通过 AI 请求取消本文定义的第三方 Skill 默认落地选项。

取消请求可以使用自然语言表达，例如：

```text
取消第三方 Skill 默认落地。
以后不要默认使用第三方 Skill。
这个项目禁用第三方 Skill 接管选项。
```

AI 收到取消请求后，应按以下流程执行：

1. 读取 `specs-v2/11-非LDVH来源内容治理规范.md`、本文和 `specs-v2/04.03-环境适配映射与运行投影记录模板.md`；
2. 检查根目录 `LDVH-ENVIRONMENT-INITIALIZATION.md` 是否存在；
3. 向用户说明取消的影响范围和降级后果；
4. 触发 Human Gate，等待用户确认；
5. 用户确认后，在 `LDVH-ENVIRONMENT-INITIALIZATION.md` 中登记第三方 Skill 接管落地选项为“已取消”或等价状态；
6. 记录取消时间、确认人、适用范围、降级方式和重新启用条件；
7. 后续 AI 遇到第三方 Skill 场景时，应先提醒该选项已取消，不得默认调用。

如果 `LDVH-ENVIRONMENT-INITIALIZATION.md` 不存在，AI 不得为了取消选项而自行创建持久运行投影；应先提醒用户按 04.03 完成当前环境初始化记录，再继续取消登记。

### 6.1 取消后的降级方式

取消后，第三方 Skill 只能作为以下内容出现：

1. 一次性外部参考；
2. 候选输入；
3. 用户明确授权的临时能力；
4. 待接管外部能力；
5. 后续重新启用评估对象。

取消后，第三方 Skill 不得作为：

1. 默认脚手架生成路径；
2. 默认包装 Skill 候选；
3. 持续开发入口；
4. 默认工具链组成部分；
5. 自动触发或运行投影实体；
6. 未经 Human Gate 的事实源写入能力。

### 6.2 取消后的 AI 提醒

当 AI 在取消状态下判断第三方 Skill 可能有帮助时，应提醒：

1. 当前项目已取消第三方 Skill 默认落地选项；
2. 若用户仍想使用，需要明确授权本次临时调用，或重新启用该选项；
3. 即使临时调用，仍必须遵守 11 的非 LDVH 来源内容治理规则；
4. 若要长期恢复默认能力，应按本文 §7 重新启用。

---
## 7. 重新启用

用户可以通过 AI 请求重新启用第三方 Skill 接管落地选项。

重新启用应按以下流程执行：

1. 读取 11、本文和当前 `LDVH-ENVIRONMENT-INITIALIZATION.md`；
2. 检查取消原因、当前环境能力、权限边界和用户授权状态是否已经变化；
3. 说明重新启用后的默认行为、风险和降级方式；
4. 触发 Human Gate，等待用户确认；
5. 用户确认后，在 `LDVH-ENVIRONMENT-INITIALIZATION.md` 中登记该选项为“已启用”或等价状态；
6. 记录重新启用时间、确认人、适用范围和必要限制；
7. 后续 AI 可按本文 §4-§5 评估第三方 Skill。

---
## 8. 接管检查清单

使用第三方 Skill 后，应检查：

| 检查项 | 问题 |
|---|---|
| 选项状态 | 当前环境初始化记录中第三方 Skill 接管落地选项是否启用；若取消，是否获得本次临时授权 |
| 产出范围 | 生成或修改了哪些文件、配置、文档或命令 |
| 事实源 | 是否直接修改或冒充权威事实源 |
| 状态机 | 是否直接修改对象状态、字段或状态流转 |
| Human Gate | 是否涉及删除、安装、发布、提交、推送、授权或高风险变更 |
| Code 风险 | 是否引入依赖、脚本、远程服务、自动更新或不可审计代码 |
| Web 风险 | 是否生成绕过受控写入或事实源同步的 UI |
| 验证 | 是否完成 lint、typecheck、test、build、运行验证或人工检查 |
| 回写 | 稳定结论是否写入对应事实源，未验证项是否记录 |

检查发现硬边界缺失时，不应只修改本文，应回到 11 或对应正式规范处理。

## 9. 与最佳实践的关系

第三方 Skill 的默认落地、取消、降级和重新启用规则由本文承载，不进入 12。

以下内容可以进入最佳实践：

1. 某次第三方 Skill 接管成功案例；
2. 某类脚手架接管后的改造经验；
3. 某类失败模式的处置经验；
4. 包装 Skill 是否值得创建的经验判断；
5. 第三方 Skill 接管后的测试和审阅节奏。

如果最佳实践中反复出现同一硬边界，应回到本文、11 或对应正式规范吸收，不得长期留在最佳实践中作为隐性规则。

## 10. 规范落地要求

本文通过以下规范落地要求说明相关要求的同步、检查或审计触发条件。

| 落地要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 上位约束承接要求 | 第三方 Skill 接管落地选项不得弱化 11 的非 LDVH 来源内容治理规则，也不得替代 04、06、07、08、09、10 的硬边界 | 11 接管流程、本文启用/取消流程、Human Gate | 外部能力接管治理 | 使用、取消、降级或重新启用第三方 Skill 默认落地选项时 |
| 入口可见要求 | AI 使用第三方 Skill 或类似外部可复用 AI 能力时，应能定位本文作为默认落地选项入口，并检查当前环境初始化记录中的启用状态 | 01 编号分区、11 相关规范引用、`LDVH-ENVIRONMENT-INITIALIZATION.md` | AI 执行入口提示 | 第三方 Skill 使用入口、包装 Skill 建议、环境初始化记录或选项状态变化时 |
| Human 交互要求 | 取消或重新启用第三方 Skill 默认落地选项必须经 Human Gate 确认，并写入当前环境初始化记录 | Human Gate、影响范围说明、环境初始化记录 | 人工确认 | 用户请求取消、重新启用或扩大第三方 Skill 默认落地范围时 |
| 生命周期触发要求 | 本文选项状态变化后，应检查当前环境初始化记录、包装 Skill、运行投影、最佳实践和相关任务是否需要同步 | 环境初始化记录检查、运行投影漂移检查、任务接管检查 | 触发保障 | 取消、重新启用、降级方式、包装 Skill 边界或第三方 Skill 使用入口变化时 |

## 11. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 取消第三方 Skill 默认落地选项；
2. 重新启用第三方 Skill 默认落地选项；
3. 将某个第三方 Skill 作为持续开发入口、包装 Skill 或默认工具链能力；
4. 第三方 Skill 需要写入、覆盖、删除、迁移或发布 Git 文件事实源；
5. 第三方 Skill 需要安装依赖、访问网络、读取敏感信息或获得高权限；
6. 第三方 Skill 输出将改变正式规范、事实源边界、工作模型、工作流程、Code、Web 或状态机；
7. 当前环境初始化记录缺失、过期或与实际环境不一致。

第三方 Skill 接管落地检查至少包括：

| 检查项 | 标准 |
|---|---|
| 选项状态 | 已检查当前环境初始化记录中该选项是否启用、取消或临时授权 |
| 取消流程 | 取消时已说明影响范围、触发 Human Gate 并写入环境初始化记录 |
| 重新启用流程 | 重新启用时已说明风险、触发 Human Gate 并写入环境初始化记录 |
| 11 承接 | 未绕过非 LDVH 来源内容治理规范 |
| 权限限制 | 已限制输入、输出、写入、网络、依赖和敏感信息范围 |
| 主控接管 | 输出已回到 LDVH 主控判断，不由第三方 Skill 直接生效 |
| 事实源边界 | 稳定事实已按归属回写，候选内容未冒充事实源 |
| 验证证据 | 已完成验证或记录验证缺口和残留风险 |
