## 1. 本文定位

本文是 `specs/21-ADR-决策记录.md` 的附件型实践子文档（编号 21.04），承接 Tools 契约式校验与执行实践。本文不是独立事实模型，不得重新定义 ADR 的对象定位、准入条件、状态机、对象关系、Human Gate、字段契约、事实源回写或证据留存。发生冲突时，以 21 主文档和上位基础规范为准。

本文是 ADR Tools 命令、参数、测试和能力声明的权威 ADR 子文档位置。21.02-Skill.md 只引用本文声明的能力，不重复维护命令清单或参数说明。

---

## 2. 实践目标

为 ADR 提供可重复、可校验、可追溯的 Tools 辅助能力，帮助 AI 和人从 Git 文件事实源读取 ADR 实例，生成运行时索引、查询结果、状态统计、关联查询结果、字段校验结果，并在获得显式 Human Gate 确认参数后执行受控写入。

本文当前声明的 active 状态表示 ADR 只读、查询、统计、校验和受控写入执行能力已形成实体实现与测试验收。ADR Tools 只读输出属于运行时派生结果，不自动成为执行依据；ADR Tools 受控写入仅执行已授权、可机械化、可校验的写入动作，不产生授权本身，不替代 ADR 准入判断、适用性判断、流程性判断或 Human Gate 编排。

---

## 3. 适用场景

1. 需要列出当前项目 ADR 摘要时；
2. 需要按关键词、状态或关联规范查询 ADR 时；
3. 需要查看单个 ADR 详情时；
4. 需要统计 ADR 状态分布时；
5. 需要校验 ADR YAML 实例字段完整性、状态合法性和文件命名时；
6. 已获得 Human Gate 确认并需要执行 ADR 创建、状态流转、关联规则回写、废弃或推翻等受控写入时。

---

## 4. 实践边界

1. 当前 ADR Tools 实体路径为 `tools/adr_index.py`；
2. 当前 ADR Tools 读取 `ldvh-base/adrs/` 下的 ADR YAML 实例，并可在显式 Human Gate 确认参数存在时执行受控写入；
3. 当前 ADR Tools 已实现能力包括读取、索引、查询、统计、字段校验、状态校验、文件命名校验、关联查询、编号生成、ADR 草案生成、ADR 创建、状态流转写入、关联规则回写、废弃写入、推翻写入、Change 记录生成（依据 specs/22-Change-变更记录.md）和写入后验证；
4. ADR Tools 输出属于运行时派生结果，不是最终事实源；ADR YAML 和 Change YAML 写入目标属于 Git 文件事实源；
5. ADR Tools 字段和状态校验依据 `specs/21.06-Contract.md`，不得自行扩张 ADR schema；
6. ADR Tools 不得替代 Human Gate，不得生成授权，不得自动执行未授权状态流转；
7. ADR Tools 不得承担 ADR 准入判断、读取适用性判断、流程性判断或 Human Gate 编排；
8. ADR Tools 当前不直接写入 specs 或 Rules 正文。ADR 升级为 specs 或 Rules 时，Tools 只承担 ADR 侧关联字段回写和 Change 记录生成（依据 specs/22-Change-变更记录.md）；规范正文写入仍应由 AI 或人按 specs / Rules 规范执行。

## 5. 实践内容

`tools/adr_index.py` 当前提供以下命令：

| 命令 | 能力 |
|---|---|
| `list` | 列出所有 ADR 摘要 |
| `search <keyword>` | 按关键词搜索 ADR |
| `status <status>` | 按状态筛选 ADR |
| `show <adr_id>` | 显示单个 ADR 详情 |
| `stats` | 显示 ADR 状态统计 |
| `validate` | 校验 ADR 实例字段完整性、状态合法性和文件命名 |
| `related <spec>` | 显示与指定 specs 文件关联的 ADR |
| `next-id` | 根据现有 ADR 计算下一个 ADR ID |
| `draft` | 生成符合 Contract 的 proposed ADR YAML 草案并输出到 stdout |
| `create` | 经显式 Human Gate 确认参数授权后创建 proposed ADR YAML |
| `transition` | 经授权后执行合法状态流转，并拒绝非法流转和终态重开 |
| `link-rule` | 经授权后更新 ADR `related_rules` |
| `deprecate` | 经授权后执行 `accepted → deprecated` 并回写废弃原因 |
| `supersede` | 经授权后创建替代 ADR，并将旧 ADR 标记为 `superseded` |

写入类命令必须携带 `--human-gate-confirmed`、`--confirmed-by` 和 `--confirmation-context`。需要生成 Change 记录时，应显式携带 `--write-change`（依据 specs/22-Change-变更记录.md）

写入类命令（`create`、`transition`、`link-rule`、`deprecate`、`supersede`）在存在 YAML 解析失败的 ADR 文件时将被拒绝执行，需先修复解析失败文件。

`create` 和 `transition` 命令会将 Human Gate 确认记录（确认人、确认时间、确认上下文）追加到 ADR YAML 的 `context` 字段末尾，确保确认信息持久化到 Git 文件事实源。

### 5.1 只读查询能力

依据 21.02-Skill.md，ADR 读取与适用判断流程包含 ADR 列表、关键词查询、状态筛选、详情查看、关联查询、统计和契约校验等可机械化只读步骤。当前 `tools/adr_index.py` 已实现这些步骤中可由 Tools 承担的只读查询和校验能力。

ADR Tools 只读查询能力如下：

| 能力 | 说明 |
|---|---|
| 列表读取 | 从 `ldvh-base/adrs/` 读取 ADR YAML 实例并列出摘要 |
| 关键词查询 | 按关键词搜索 ADR 标题、背景、决策或后果等内容 |
| 状态筛选 | 按 `proposed`、`accepted`、`deprecated`、`superseded` 或 `rejected` 筛选 ADR |
| 详情查看 | 按 ADR ID 显示单个 ADR 详情 |
| 关联查询 | 按 specs 或 Rules 文件路径查询相关 ADR |
| 状态统计 | 输出 ADR 状态分布 |
| 契约校验 | 校验字段完整性、状态合法性和文件命名 |

只读查询结果仅帮助 AI 或人定位 ADR，不自动判断某个 ADR 是否可作为当前执行依据。读取结果适用性由 AI 或 Skill 按 21 主文档状态语义判断。

### 5.2 受控写入能力

依据 21.02-Skill.md，ADR 创建、升级、推翻和废弃流程包含 ADR YAML 创建、状态流转写入、关联字段回写、废弃原因回写和 Change 记录生成（依据 specs/22-Change-变更记录.md）等可机械化写入步骤。当前 `tools/adr_index.py` 已实现这些步骤中可由 Tools 承担的受控写入执行能力。

ADR Tools 受控写入能力如下：

| 能力 | 说明 |
|---|---|
| 编号生成 | 根据 `ldvh-base/adrs/` 中已有 ADR 计算下一个 `adr-{NNNN}` |
| ADR 草案生成 | 根据 Contract 输出符合字段契约的 YAML 草案，不直接写入 |
| ADR 创建写入 | 经 Human Gate 确认参数授权后写入 `ldvh-base/adrs/adr-{NNNN}-short-title.yaml` |
| 状态流转写入 | 经授权后执行合法状态流转，并阻止非法流转和终态重开 |
| 关联字段回写 | 经授权后更新 `related_rules` |
| 推翻写入 | 经授权后写入新 ADR，并更新旧 ADR 的 `status: superseded` 和 `superseded_by` |
| 废弃写入 | 经授权后写入 `status: deprecated` 和废弃原因 |
| Change 记录生成 | 在写入命令携带 `--write-change` 时生成对应 Change 记录（依据 specs/22-Change-变更记录.md） |
| 写入后验证 | 写入前执行字段、状态和命名校验，写入后可通过 `validate` 重新校验 |

### 5.3 命令调用示例

```bash
# 只读命令
python3 tools/adr_index.py list
python3 tools/adr_index.py search "关键词"
python3 tools/adr_index.py status accepted
python3 tools/adr_index.py show adr-0001
python3 tools/adr_index.py stats
python3 tools/adr_index.py validate
python3 tools/adr_index.py related specs/21-ADR-决策记录.md
python3 tools/adr_index.py next-id

# 写入命令（adr_id 和 status 为位置参数）
python3 tools/adr_index.py create \
  --slug short-title \
  --title "决策标题" \
  --context "决策背景" \
  --decision "决策内容" \
  --consequences "决策后果" \
  --date 2026-06-03 \
  --human-gate-confirmed \
  --confirmed-by user \
  --confirmation-context "确认上下文"

python3 tools/adr_index.py transition adr-0001 accepted \
  --human-gate-confirmed \
  --confirmed-by user \
  --confirmation-context "确认接受决策"

python3 tools/adr_index.py transition adr-0001 rejected \
  --human-gate-confirmed \
  --confirmed-by user \
  --confirmation-context "确认否决决策"

python3 tools/adr_index.py link-rule adr-0001 \
  --rule specs/21.06-Contract.md \
  --human-gate-confirmed \
  --confirmed-by user \
  --confirmation-context "关联规则"

python3 tools/adr_index.py deprecate adr-0001 \
  --reason "废弃原因" \
  --human-gate-confirmed \
  --confirmed-by user \
  --confirmation-context "确认废弃"

python3 tools/adr_index.py supersede \
  --old-adr-id adr-0001 \
  --slug new-decision \
  --title "新决策标题" \
  --context "决策背景" \
  --decision "决策内容" \
  --consequences "决策后果" \
  --human-gate-confirmed \
  --confirmed-by user \
  --confirmation-context "确认推翻"
```

测试文件为 `tests/tools/test_adr_index.py`。测试命令为：

```bash
python3 -m pytest tests/tools/test_adr_index.py
```

新增或修改 ADR Tools 能力时，应同步补充或更新对应 pytest 测试，执行测试验收，并在任务证据或人工验收材料中记录测试命令和结果（依据 specs/22-Change-变更记录.md）测试未通过时，不得声称 ADR Tools 能力已经完成落地或验收通过。

## 6. Human Gate

以下情况应评估 Human Gate：

1. ADR Tools 从只读能力扩展为写入 ADR YAML、规范、Rules 或变更记录；（依据 specs/22-Change-变更记录.md）
2. ADR Tools 改变 ADR 字段契约、状态流转或文件命名校验依据；
3. ADR Tools 将运行时派生结果持久化为新的事实源；
4. ADR Tools 绕过 21 主文档定义的 Human Gate 自动执行状态变更；
5. ADR Tools 承担 ADR 准入判断、读取适用性判断、流程性判断、授权生成或 Human Gate 编排。

---

## 7. 检查项

检查 ADR Tools 契约式校验与执行实践是否合规时，应确认：

1. `tools/adr_index.py` 是否读取 Git 文件事实源并将派生查询结果输出为运行时结果；
2. ADR 字段、状态和文件命名校验是否依据 `specs/21.06-Contract.md`；
3. Tools 输出是否未被当作 ADR 最终事实源；
4. Tools 只读查询结果是否未被自动当作执行依据；
5. Tools 是否未替代 Human Gate、未生成授权、未自动执行未授权状态流转；
6. Tools 是否未承担 ADR 准入判断、读取适用性判断或 Skill 流程判断；
7. 新增或修改 Tools 能力时是否同步更新 `tests/tools/test_adr_index.py`；
8. ADR Tools 测试验收是否已执行，并在任务证据或人工验收材料中记录测试命令和结果；（依据 specs/22-Change-变更记录.md）
9. 契约子文档变更后，ADR Tools 实现和测试是否已同步更新；
10. ADR Skill 流程中的可机械化读取步骤是否已有对应 Tools 只读查询能力；
11. ADR Skill 流程中的可机械化写入步骤是否已有对应 Tools 受控写入能力；
12. 写入类命令是否要求显式 Human Gate 确认参数；
13. 写入类命令是否在写入前执行字段、状态和命名校验，并阻止非法状态流转和终态重开。
