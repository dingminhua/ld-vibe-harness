# Cursor 内置工具与安全机制

> 创建日期：2026-06-08
> 来源：Cursor 官方文档
> 定位：外部资料引用，不直接成为 LDVH 强制规则

---

## 1. 结论摘要

Cursor Agent 内置文件操作、终端操作、网络操作和 MCP 工具四类工具。安全机制采用分层模型：读操作自动执行，写操作和终端命令默认需用户确认（Accept/Reject）。Yolo 模式可跳过所有确认，但存在安全风险。建议配合 Git 使用以确保可回滚。

## 2. 内置工具清单

### 2.1 文件操作

| 工具 | 功能 |
|------|------|
| read_file | 读取文件 |
| write_file | 写入文件 |

| 工具 | 功能 |

### 2.3 网络操作

| 工具 | 功能 |
|------|------|

| web_fetch | 获取网页内容 |

### 2.4 MCP 工具

动态加载，取决于 MCP 服务器配置。

## 3. 安全审查机制

### 3.1 分层安全模型

**自动执行（无需确认）**：

- 读取文件
- 搜索代码
- 列出目录
- 网络搜索/浏览

**需要确认（默认）**：

- 写入/创建文件
- 编辑文件
- 执行终端命令
- 删除操作

### 3.2 确认方式

- Agent 提出操作建议，显示 diff 或命令内容
- 用户点击 Accept / Reject 按钮
- 可选择 Accept All 批量接受

## 4. Yolo 模式（自动执行模式）

- 开启方式：Cursor Settings 中启用，或在 Agent 对话中切换
- 效果：所有操作自动执行，跳过确认步骤
- 风险：Agent 可以不经确认直接修改文件、执行命令
- 适用场景：对项目有充分信心、需要快速迭代时
- 安全建议：配合 Git 使用，确保可以回滚；不建议在生产项目中使用

## 5. 与 Trae 安全机制的关键差异

| 能力 | Trae | Cursor |
|------|------|--------|
| 安全模型 | MCP 自动运行 + 命令白/黑名单 | 分层确认（读自动/写确认） |
| 自动执行模式 | 始终自动运行 | Yolo 模式 |
| 批量接受 | 不支持 | Accept All |
| diff 展示 | 不适用 | 每步操作显示 diff |
| 沙箱隔离 | 不适用 | 不支持（依赖用户确认） |
