## 2. 逐条审计

### 2.1 规范源（Specification Source）

- **必要性**：00 §1 设计理念与 §3 规范模型定义长期使用「规范源」但未登记、未在正文定义；新 §4 使其成为承载全部边界与流程规范的上位概念，跨规范引用（03/06/09 等均以 `ldvh-root` 为依据）需要稳定双语名称。
- **中英文候选**：规范源（采用；00 既有用词）／规则源（既有登记条目，转为其他有效表达）；Specification Source（采用，与 Specification/Spec 家族一致）／Rule Source（既有，与「当前规则源 Current Rule Source」共享词根，保留于有效表达）。
- **相邻概念**：与「当前规则源」的关系为全集与子集——规范源 = 全部 Specs 及其授权附件的统一承载；当前规则源 = 其中满足 `specification-model-foundation` §6 生效条件的子集。与「规范模型」的关系：规范模型是规范源的组织方式（01 职责），规范源是被组织的承载本身。
- **正例**：「规范收录于规范源，不等于已经生效」（00 §4）；「规范源由全部 Specs 及其授权附件构成」（00 §4）。
- **反例**：不得以「规范源」指称仅当前生效的子集（那是当前规则源）；不得以聊天、工具输出充当规范源（00 §4 第 3 段）。
- **替换与使用扫描**：00 §1 第 3 项、§3 规范模型定义句、§4 全章；01.Att.01 既有「规则源」行并入本行；01 正文中「规则源」出现于「当前规则源」「规则源视图」「规则源不一致」等复合用法，均与本条兼容，无需改动。

### 2.2 边界系统（Boundary System）

- **必要性**：00 §4 章标题与 §1 设计理念的核心概念，指称规范源规定的全部规范边界相互关联形成的整体；无现成条目可承担。
- **中英文候选**：边界系统（采用，Human 定夺）；Boundary System（采用）／Boundary Framework（未采用，Framework 暗示实现结构）。
- **不是统一简称的证明**（对照 `specification-model-foundation` 对「给一组性质不同的内容提供统一简称」的禁止）：清单成员共享共同本质属性——均为规范源规定的规范边界（含义、对象、范围、条件和效力由规范源规定）；「系统」指其相互关联（行动边界依赖授权边界、验证边界约束声明边界等）形成的整体语义，而非为异质内容提供称呼便利。00 §4 同时明示「边界系统不是新的语义构成要素」，不承担归类职责。
- **相邻概念**：与「行动边界」是整体与成员关系；与「规范源」是内容与承载关系；与「五类构成要素」无归口关系。
- **正例**：「各类边界均由规范源规定，构成边界系统」（00 §2）；「这些边界相互关联，共同构成 LDVH 的边界系统」（00 §4）。
- **反例**：不得把某个具体边界（如事实源边界）称为边界系统；不得把边界系统当作第六类构成要素或新的规则来源。
- **替换与使用扫描**：00 §1 第 3 项、§2 第 1 项与支撑方向句、§4；无其它 specs 使用该词（全文扫描确认「系统」此前仅出现于文件系统、操作系统、权限系统等软件语境）。

### 2.3 行动边界（Action Boundary）

- **必要性**：00 §1 最终目标、§4 第 1 条与三层判断框架反复使用的承重概念，原「行动边界与流程规范」理念项的前半。
- **中英文候选**：行动边界（采用）；Action Boundary（采用）／Action Scope（未采用，scope 与管辖范围语义冲突）。
- **相邻概念**：边界系统的成员之一，最直接约束行动的一支；与「行动允许」不同——行动边界规定要求本身，行动允许是对当次行动能否推进的判断结论。
- **正例**：「行动边界。规定行动涉及的对象、范围与条件……」（00 §4 第 1 条）。
- **反例**：不得以行动边界指称事实源边界、服务边界等非行动类边界。
- **替换与使用扫描**：00 §1、§2（支撑方向句已按 Human 决定改为「边界系统」）、§4；06 §6 的授权边界用法兼容。

### 2.4 流程规范（Process Specification）

- **必要性**：00 §1 理念项与 §4 第 2 条的承重概念，指规范源通过行动模板对重复行动流程的规定。
- **中英文候选**：流程规范（采用）；Process Specification（采用，与 Specification 家族一致）／Procedure Rules（未采用，rules 与规范文档层级混淆）。
- **相邻概念**：与「行动模板」是规定与载体的关系——流程规范由行动模板承载，行动模板的内容构成由 00 §3 定义；与「行动边界」并列构成规范源对行动的两类直接作用。
- **正例**：「规范源通过行动模板规定重复场景中可复用的行动流程」（00 §4 第 2 条）。
- **反例**：不得把一次性计划、当次自由求解称为流程规范。
- **替换与使用扫描**：00 §1 第 3 项、§4；06 对模板流程的规定兼容。

### 2.5 行动允许（Action Permission）

- **必要性**：00 §4 三层判断（生效、适用、行动允许）的第三层，是复核 P1-2 修正后的核心判断概念，跨 §2、§4、06 使用。
- **中英文候选**：行动允许（采用）；Action Permission（采用）／Action Allowance（未采用，非常用词）。
- **相邻概念**：与「授权」不同——授权由 Human 对话或来源规则给予，行动允许是「Human 当前指令授权范围 + 适用于该行动的全部来源规则许可条件」双重成立后的判断结论；与「生效」「适用」依次递进，互不替代。
- **正例**：「行动允许则要求该行动处于 Human 当前指令给予的授权范围内，并且适用于该行动的全部来源规则许可条件已经成立」（00 §4）。
- **反例**：不得把规范生效或模板适用表述为行动已经允许；不得把 Human 当前指令单独视为行动允许（仍需来源规则许可条件成立）。
- **替换与使用扫描**：00 §2 约束判断项、§4；06 §6.2「模板适用不等于行动已获授权」兼容。
