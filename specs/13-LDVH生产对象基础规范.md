## 三、生产对象的定义与定位

### 3.1 生产对象的定义

LDVH 生产对象是 LDVH 对工程生产事实的自定义建模，将项目中的意图、任务、决策、风险、依赖、证据、变更、产物、检查项和经验沉淀等内容，抽象为具有明确字段契约、状态流转和验收标准的结构化对象。

### 3.2 生产对象的核心特征

生产对象必须具备以下核心特征：

1. **规范由 LDVH 定义**：对象的准入条件、字段契约、状态流转、事实源边界和验收规则由 LDVH 规范体系定义；
2. **实例由项目拥有**：每个项目按规范创建的对象实例属于项目，存放在项目的结构化事实源目录中；
3. **服务工程生产**：对象用于让 AI、人和工具围绕同一组项目事实协作，支持任务拆解、状态追踪、证据回写、决策追溯和变更审计；
4. **Git 可追溯**：对象实例必须以 Git 可追踪文件的形式承载，优先使用 YAML 格式（适合结构化字段）或 Markdown 格式（适合说明性内容）；
5. **单一事实源**：每个对象实例只能有一个权威承载位置，其他位置只能引用或聚合，不得复制并维护独立事实。

### 3.3 生产对象与临时信息的区别

| 维度 | 临时信息 | 生产对象 |
|---|---|---|
| 性质 | 执行过程中的局部选择、临时判断、聊天内容 | 结构化、可追溯、可验证的工程事实 |
| 持续时间 | 一次性，仅在当前执行上下文中有效 | 长期，可跨会话、跨执行轮次追踪 |
| 复用价值 | 无，仅服务当前执行 | 有，可被其他对象引用、可被 AI 后续执行参考 |
| 追踪需求 | 不需要独立追踪 | 需要独立追踪、状态流转和验收标准 |
| 承载位置 | 聊天记忆、工具缓存、命令输出等临时位置 | Git 文件事实源（specs/、ldvh-base/（工作区级目录）、docs/ 等） |

## 四、生产对象模型

### 4.1 生产对象模型定义

生产对象模型是 LDVH 对某一类工程生产事实的标准化建模结构，用于统一描述该对象的对象定位、准入条件、事实源边界、状态机、对象关系、Human Gate、字段契约、事实源回写要求、证据留存要求、AI 协作、Tools 辅助、工具展示、落地前决策、价值与要素审查、落地初始化、落地审计、合规检查和待补齐事项。

每个 21-49 具体生产对象规范，都是一个具体生产对象模型的定义文档。

### 4.2 生产对象模型的标准组成

一个生产对象模型应包含以下内容：

1. 对象定位与准入条件；
2. 事实源边界；
3. 状态机；
4. 与其他对象的关系；
5. Human Gate；
6. 字段契约；
7. 事实源回写要求；
8. 证据留存要求；
9. AI 协作适配；
10. Tools 辅助适配；
11. Web 展示适配；
12. 附件型实践子文档按需拆分规则；
13. 落地前决策；
14. 价值与要素审查；
15. 落地初始化；
16. 落地审计；
17. 合规检查；
18. 待补齐事项。

### 4.3 生产对象模型与对象实例

生产对象模型定义对象类别的规则，对象实例是项目中按模型创建的具体事实。

生产对象模型承载于 `specs/20-49`，对象实例承载于 `ldvh-base/`（工作区级目录，位于工作区根目录，与 ld-vibe-harness/ 同级）。模型不得承载具体实例状态，实例不得重新定义模型规则。

### 4.4 生产对象模型与行动模型

生产对象承载工程生产事实，行动模型控制 AI 如何行动。两者关系如下：

| 维度 | 生产对象 | 行动模型 |
|---|---|---|
| 核心问题 | 项目事实如何结构化、流转和沉淀 | AI 如何读取、判断、执行、停下和回写 |
| 规范区段 | `specs/20-49` | `specs/50-79` |
| 实例事实 | 对象实例承载于 `ldvh-base/`（工作区级目录） | 行动执行结果按事实类型回写 |
| 关键约束 | 准入、字段、状态机、验收和对象关系 | Context、Scenario、Gate、回写、证据 |

行动模型可以创建、更新、检查或引用生产对象，但不得重新定义生产对象字段、状态机、验收标准或对象实例事实源边界。生产对象可以被行动模型创建、更新、检查或引用，但生产对象规范不得定义行动模型的 Context、Scenario、Gate、执行流程或事实源回写规则。

### 4.5 生产对象模型与工具实现

工具可以依据生产对象模型开发解析、校验、聚合、展示和受控写入能力。工具实现不得替代生产对象模型本身，也不得绕过模型定义的事实源边界和 Human Gate。

### 4.6 生产对象文件命名与附件型实践子文档

21-49 主文件均为生产对象规范，文件名不重复"生产对象规范"字样，格式为：

```text
NN-{英文名}-{中文名}.md
```

生产对象主文档必须完整定义对象模型。生产对象附件型实践子文档用于在主模型完整定义后，按需承接某个生产对象围绕 Rules、Skill、Agent、Tools 和 Web 的机制实践内容。附件型实践子文档不重新定义对象模型，不是模型完整性的默认要求，不得为空占位。

具体生产对象规范应在主文档中定义字段规则、状态规则、验收规则、事实源回写要求、证据留存要求、AI 协作适配、Tools 辅助适配、Web 展示适配、落地前决策、价值与要素审查、落地初始化、落地审计和合规检查。若某类 Rules、Skill、Agent、Tools 或 Web 实践内容复杂、需要独立维护，且经 Human Gate 确认，可创建对应附件型实践子文档。主文档应保留摘要、适用条件和引用，不得把对象核心规则迁移到子文档中。

附件型实践子文档统一命名如下：

| 编号 | 文件名 | 内容 | 语义定义 |
|---|---|---|---|
| `NN.01` | `NN.01-Rules.md` | Rules 实践内容 | Rules 在该生产对象中的行为约束、入口摘要、放置位置和禁止承载内容 |
| `NN.02` | `NN.02-Skill.md` | Skill 实践内容 | Skill 在该生产对象中的标准化复用流程、准入判断和事实源回写边界 |
| `NN.03` | `NN.03-Agent.md` | Agent 实践内容 | Agent 在该生产对象中的调度方式、参数注入、上下文分发和汇总规则 |
| `NN.04` | `NN.04-Tools.md` | Tools 实践内容 | Tools 在该生产对象中的校验、聚合、上下文包生成和受控写入能力定义 |
| `NN.05` | `NN.05-Web.md` | Web 实践内容 | Web 在该生产对象中的展示、Human Gate UI、受控编辑入口和协同入口实践 |
| `NN.06` | `NN.06-Contract.md` | 结构化契约、字段 schema、接口契约和数据结构 | 该生产对象的结构化数据契约，是契约字段的权威位置 |

`NN.01-Rules.md`、`NN.02-Skill.md`、`NN.03-Agent.md`、`NN.04-Tools.md`、`NN.05-Web.md` 均为附件型实践子文档，`NN.06-Contract.md` 为契约子文档。对象自身的字段规则、状态规则、验收规则和实例检查要求应留在 `NN` 主文件，不应转移到附件型实践子文档。

当某类机制（Rules、Skill、Agent、Tools 或 Web）经判断不需要为该生产对象创建时，对应附件型实践子文档只需说明不创建的理由，不需要展开该机制的边界约束、不承载内容、可建议行为或检查项。此类子文档的骨架不适用 `specs/03-Specs文档规范.md` §5.3 的模型实践子文档完整骨架，只需包含本文定位、不创建理由和检查项。后续如需创建，应按 Human Gate 流程更新子文档内容，并补齐完整骨架。

当某类机制经判断当前不需要实现但未来可能需要时，对应附件型实践子文档应说明当前状态、未来能力定义、实现前提和边界约束。此类子文档的骨架不适用 `specs/03-Specs文档规范.md` §5.3 的完整骨架，只需包含本文定位、当前状态与未来能力定义、实现前提和边界约束、检查项。主文档应在子文档清单中标注该子文档为 active-prep 状态。后续如需升级为 active，应按 Human Gate 流程更新子文档内容，并补齐完整骨架。

当某类机制经判断需要创建时，对应附件型实践子文档应遵循 `specs/03-Specs文档规范.md` §5.3 的模型实践子文档完整骨架，包含本文定位、实践目标、适用场景、实践边界、实践内容、Human Gate、检查要求和待补齐事项。

附件型实践子文档标题格式和命名维度规则依据 `specs/02-LDVH术语规范.md` §7.1，本文不重复维护。契约子文档标题格式为：`{主模型名} — 契约`。

契约子文档（NN.06）定义结构化数据契约，是契约字段的权威位置。契约子文档不承载执行逻辑、流程步骤或 Human Gate 条款。实践子文档和工具可以消费契约子文档，但不得复制维护契约字段第二事实源。修改契约子文档属于规范变更，应评估 Human Gate 并记录 Change。

### 4.7 落地前决策、价值与要素审查、落地初始化、落地审计与合规检查

生产对象规范应按需要定义落地前决策、价值与要素审查、落地初始化、落地审计和合规检查要求。落地前决策用于判断某一生产对象模型在具体项目中需要落地哪些 Rules、Skill、Agent、Tools、Web、契约或附件型实践子文档。落地前决策不是落地初始化，不表示对应实践已经存在。

落地前决策完成后、实际落地初始化开始前，必须基于 `specs/00-LD-Vibe-Harness理念与纲要.md` 执行价值与要素审查。该审查用于确认拟落地方案是否服务 LDVH 价值实现标准，是否仍符合五类构成要素的分工，是否存在为机制而机制、制造第二事实源、绕过 Human Gate 或偏离 AI 第一服务对象的问题。

价值与要素审查至少应覆盖：

1. 是否有助于 V1 稳定理解、V2 受控执行、V3 门禁识别、V4 证据沉淀、V5 事实回写、V6 人类确认质量或 V7 持续改进中的一项或多项；
2. 是否明确归属于介质、Trae Solo 环境机制、LDVH 工具、LDVH 生产对象或 LDVH 行动模型之一，且未混淆五类构成要素边界；
3. 是否仍以 AI 执行者为第一服务对象，帮助 AI 读取事实源、创建和更新对象实例、触发 Human Gate 和回写事实；
4. 是否避免把工具缓存、Web 状态、Agent 输出、Skill 输出或聊天过程当作最终事实源；
5. 是否避免创建无必要的规则、Skill、Agent、工具或对象，导致体系膨胀但不提升可控性；
6. 是否明确需要 Human Gate 的事项，并在确认后再进入落地初始化。

价值与要素审查的结论应成为落地初始化的前置输入。审查不通过时，应回到落地前决策修正方案、标记暂缓或停止落地；不得直接进入初始化。

落地初始化应说明在落地前决策和价值与要素审查完成后，该对象模型进入项目实践时需要实际创建或确认的目录、实例命名规则、索引引用、Rules 摘要、Skill、Agent、Tools、Web、初始化产物、暂缓项和 Human Gate。

落地审计应说明如何审查该对象模型的实践是否真实落地、持续有效、与 Git 文件事实源一致、未绕过 Human Gate，并识别初始化缺口、过期实践和需要整改的附件型实践子文档。

合规检查应说明对象规范写作、对象实例字段、状态流转、关系引用、事实源边界、事实源回写、证据留存、Human Gate、AI 协作适配、Tools 辅助和 Web 展示是否符合本对象模型和上位规范。

### 4.8 完整方案形成流程

生产对象完整方案按以下顺序形成：

1. 创建或更新 `NN` 主文件，完整定义对象模型；
2. 定义实例事实源位置、字段契约、状态机、关系规则、Human Gate、事实源回写要求、证据留存要求、AI 协作适配、Tools 辅助适配和 Web 展示适配；
3. 定义落地前决策、价值与要素审查、落地初始化计划、落地审计要求和合规检查标准；
4. 判断 Rules、Skill、Agent、Tools 或 Web 实践是否复杂到需要独立维护；
5. 完成落地前决策后，依据 00 总纲执行价值与要素审查；
6. 仅在按需且经 Human Gate 确认时创建附件型实践子文档；
7. 修改规范、附件型实践子文档、协作机制或实例事实源时记录 Change。

## 五、生产对象准入与分类原则

### 5.1 对象分类原则

LDVH 生产对象可按治理用途分为以下几类：

1. **核心执行实体**：最小可执行、可追踪、可验证、可关闭的对象；
2. **意图和入口**：承载人的目标、范围、成功标准和约束，以及未任务化但有保留价值的输入；
3. **决策和风险**：已确认的决策记录、已识别的风险、前置条件或外部约束；
4. **支撑和记录**：执行摘要、验证结果、关闭证据、验收记录、可引用产物、检查项、变更记录和踩坑经验。

### 5.2 对象清单归属

具体生产对象清单、编号归属、维护状态和区段关系由 `specs/20-生产对象集合索引.md` 维护。本文只定义生产对象的通用分类和准入原则。

### 5.3 预留编号区段

编号区段 33-49 预留用于未来新增生产对象，不得未经 Human Gate 确认提前占用。

### 5.4 准入条件原则

一个内容需要满足以下条件之一，才应成为生产对象：

1. **需要独立追踪状态**：该内容有明确的状态流转，需要跨会话或跨执行轮次追踪；
2. **需要可验证的完成标准**：该内容有明确的验收条件，需要验证是否完成；
3. **需要关闭证据**：该内容完成后需要记录证据，供后续追溯或审计；
4. **需要关联其他对象**：该内容需要被其他对象引用，或引用其他对象；
5. **需要被工具展示、排序、过滤、聚合或审计**：该内容需要被工具处理，以降低人和 AI 的维护成本；
6. **不成为生产对象就会导致进度、责任、完成标准或验证结果不可追踪**：该内容如果不结构化，就会导致项目事实漂移或不可追溯。

不满足以上条件的内容，应按其性质分流：
- 可以在当前对话中直接回答或处理的信息 → 留在聊天记忆中，不写入事实源；
- 已有明确目标和完成标准，但不需要独立追踪 → 作为现有 Task 的子步骤，不单独创建对象；
- 属于长期规则或决策，但不需要独立状态机 → 写入 specs/ 或 .trae/rules/；
- 属于项目背景或参考资料 → 写入 docs/ 或 specs/refs/；
- 属于临时执行策略 → 留在当前执行上下文中。

## 六、生产对象的通用规范

### 6.1 事实源边界原则

生产对象的事实源边界依据 `specs/10-事实源边界与承载规范.md` 定义的原则执行，本文不重复维护。生产对象的适配说明如下：

1. **介质选择适配**：依据 10 §六，生产对象实例优先使用 YAML 格式承载（适合任务、状态、结构化关系和审计字段），说明性内容可使用 Markdown 格式；
2. **目录归属适配**：依据 10 §八 和 `specs/01-LDVH目录说明.md` §3.2，生产对象规范承载于 specs/20-49，生产对象实例承载于 ldvh-base/（工作区级目录），管辖项目资料承载于 docs/，外部资料承载于 specs/refs/。

### 6.2 状态流转原则

生产对象的状态流转遵循以下原则：

1. **状态变更先于执行**：执行者在执行对象相关操作时，必须同步更新事实源中的对象状态；
2. **终态不可重开**：对象进入终态后，不得直接重开；如需重新处理，必须新建对象承接；
3. **状态流转可追溯**：状态变更必须留下可追溯的记录，包括变更时间、变更人和变更原因；
4. **Human Gate 触发原则**：关键状态流转必须触发 Human Gate，等待人类确认后方可继续。

### 6.3 字段契约原则

生产对象的字段契约遵循以下原则：

1. **基础字段对齐**：所有生产对象应包含基础字段（id、type、title、status、created、updated）；
2. **扩展字段明确**：具体对象的扩展字段由该对象的规范明确定义，包括字段名、类型、是否必填、约束条件；
3. **字段语义一致**：相同字段名在不同对象中的语义应保持一致；
4. **引用完整性**：引用其他对象的字段应确保引用的对象存在且有效。

### 6.4 检查标准原则

生产对象的检查标准遵循以下原则：

1. **可验证**：检查标准必须是可验证的，不能是模糊的主观判断；
2. **明确**：检查标准必须明确，不能有歧义；
3. **可追溯**：检查完成后必须记录检查证据，包括检查时间、检查人和检查结果；
4. **按对象性质选择检查类型**：以完成为目标的对象应定义验收标准；不以完成为目标的对象应定义检查要求；
5. **检查要求进入主文件**：合规检查标准、落地初始化计划和落地审计要求应在具体生产对象主文件中定义；附件型实践子文档只承接复杂机制实践的展开内容，不承载对象核心检查标准。

### 6.5 AI 协作适配原则

AI 协作适配定义 AI 如何读取、创建、更新和检查生产对象。AI 协作适配遵循以下原则：

1. **按事实源读取**：AI 读取对象实例时必须按事实源边界读取，不依赖聊天记忆、工具缓存或数据库派生视图；
2. **按规范创建**：AI 创建对象实例时必须按对象规范的字段契约创建，不得自行添加、省略或修改字段；
3. **按状态机更新**：AI 更新对象实例时必须按对象规范的状态机流转，状态变更先于执行；
4. **按验收标准检查**：AI 检查对象实例时必须按对象规范的验收标准检查，检查结果留存证据；
5. **不得绕过规范**：AI 不得绕过对象规范定义的字段契约、状态机、验收标准或事实源边界；
6. **Human Gate 评估**：AI 创建、更新或删除关键对象实例时，应评估是否需要触发 Human Gate；
7. **机制回指**：AI 协作适配中涉及 Rules、Skill、Agent 的使用边界，必须回指 `specs/11-LDVH-AI协作规范.md` 及其子文档。

### 6.6 事实源回写适配原则

AI 完成执行后的事实源回写，依据 `specs/10-事实源边界与承载规范.md` §七定义的回写条件执行，本文不重复维护。生产对象的适配说明如下：

1. **对象实例回写触发**：AI 按行动模型执行完毕后，应判断执行结果是否需要创建或更新对象实例；若需要，必须按 10 §七回写；
2. **回写与 Gate 联动**：关键对象实例的创建和更新应评估 Human Gate，依据本文、具体对象规范和相关基础规范判断；
3. **回写验证**：对象实例回写后应验证字段完整性、状态合法性和引用完整性；
4. **机制输出回写**：Skill 或 Agent 输出只有写入对应 Git 文件事实源后才成为稳定对象实例；
5. **报告回写分流**：审计报告、分析报告或管辖项目资料应按 02、03 和具体对象规范判断进入 docs/、ldvh-base/（工作区级目录）或 specs/。

### 6.7 证据留存适配原则

生产对象的证据留存遵循以下原则：

1. **对象创建留证**：对象创建时应记录创建原因、创建者和创建依据；
2. **状态变更留证**：状态变更时应记录变更时间、变更人、变更原因和变更前状态；
3. **验收检查留证**：验收检查时应记录检查时间、检查人、检查结果和检查证据；
4. **Human Gate 确认留证**：Human Gate 确认时应记录确认事项、确认人和确认结果；
5. **过程信息不冒充事实**：聊天、临时分析、命令输出和 Agent 输出不得直接冒充稳定证据；
6. **关闭前可追溯**：涉及任务、审计或 Review 的对象，在关闭前应能追溯关键证据。

## 七、与 20-49 具体对象规范的关系

### 7.1 20 生产对象集合索引

20 是生产对象集合索引，不定义对象字段、状态机、模型实践子文档或行动流程，只提供该区段内文档的清单、关系映射、状态和维护信息。

### 7.2 21-49 具体生产对象规范

21-49 是具体生产对象规范，每个规范定义一个具体生产对象模型。具体生产对象规范应依据 §4.2 定义的生产对象模型标准组成展开，并在具体对象语境下定义更具体的对象规则。

具体生产对象规范不得在缺少说明的情况下省略 §4.2 中的标准组成；如某一组成项暂不适用或待补齐，应在对应章节说明原因或进入待补齐事项。

### 7.3 关系原则

本文与 20-49 具体生产对象规范的关系遵循以下原则：
1. 本文定义生产对象的通用规则和生产对象模型的标准组成，20-49 定义具体生产对象模型；
2. 具体生产对象规范不得与本文的通用规则矛盾；
3. 具体生产对象规范可以在本文的通用规则基础上，定义更具体的规则；
4. 发生冲突时，以本文的通用规则为准，除非具体生产对象规范明确说明例外情况并经 Human Gate 确认。

## 八、Human Gate 与检查要求

### 8.1 Human Gate 触发条件

以下情况应评估 Human Gate：
1. 新增生产对象；
2. 删除生产对象；
3. 重命名生产对象；
4. 重排生产对象编号区段；
5. 改变生产对象的通用规则；
6. 改变生产对象的事实源边界原则；
7. 将原本不属于生产对象的内容升级为生产对象；
8. 将原本属于生产对象的内容降级为非生产对象；
9. 改变生产对象模型的标准组成；
10. 新增、删除、重命名或改变生产对象附件型实践子文档；
11. 改变 AI 协作适配边界（AI 如何创建、更新、检查生产对象）；
12. 改变生产对象与行动模型的交互边界；
13. 改变检查要求的执行边界。

当 AI 识别到上述情况时，至少必须暂停当前变更动作，向人提醒该操作可能触发 Human Gate，并说明涉及的事实源、影响范围和建议确认事项。

### 8.2 检查要求

生产对象规范写作检查至少包括：
| 检查项 | 标准 |
|---|---|
| 上位依据 | 已声明上位依据 |
| 对象定位 | 头部定位、适用范围、上位依据和相关规范清晰 |
| 引用纪律 | 未复制其他权威文档的规则正文 |
| 架构术语一致性 | 与五类构成要素、生产对象、生产对象模型和行动模型术语一致 |
| 模型组成 | 具体生产对象规范覆盖生产对象模型的标准组成，缺项已说明原因 |
| 附件型实践子文档 | 已说明是否需要附件型实践子文档；如创建，已确认按需、非空、不替代主模型且经 Human Gate |
| 落地前决策 | 已定义实际初始化前需要完成的落地范围、暂缓项和 Human Gate 决策 |
| 价值与要素审查 | 已说明落地前决策后需依据 00 总纲审查价值实现标准和五类构成要素边界 |
| 落地初始化 | 已按需要定义设计进入实践的初始化计划、初始化产物和暂缓项 |
| 落地审计 | 已按需要定义实践是否真实落地并持续有效的审计要求 |
| 合规检查 | 已定义对象规范写作、实例字段、状态流转、事实源回写、证据留存和事实源边界的符合性检查标准 |
| 文件命名 | 主文件和附件型实践子文档命名符合 §4.6，未重复维护区段性质或对象归属 |
| 事实源边界 | 符合 `specs/10-事实源边界与承载规范.md` 的事实源边界原则 |
| 目录归属 | 符合 `specs/01-LDVH目录说明.md` 的目录规划 |
| AI 协作适配 | AI 读取、创建、更新和检查对象实例的规则符合 11 系列规范和本文 §6.5 |
| 事实源回写 | AI 创建或更新对象实例后的回写符合 10 事实源边界原则和本文 §6.6 |
| 证据留存 | 对象创建、状态变更、验收检查和 Human Gate 确认有可追溯证据要求，符合本文 §6.7 |
