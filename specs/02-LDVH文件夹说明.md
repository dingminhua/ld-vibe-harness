# LDVH 文件夹说明

> 创建日期：2026-05-29
> 定位：LD Vibe Harness 项目文件夹规划说明
> 适用范围：LD Vibe Harness 项目及所有接入 LD Vibe Harness 的管辖项目
> 上位依据：`specs/00-LD-Vibe-Harness理念与纲要.md`
> 相关规范：`specs/01-specs文档结构规范.md`、`specs/03-事实源边界与承载规范.md`

---

## 一、本文解决的问题

本文回答 LD Vibe Harness 项目文件夹层级、主要目录用途、目录事实源性质和目录间关系，并为后续事实源边界、工具规范、生产对象规范和行动模型规范提供目录语境。

文件夹说明提供项目结构地图和目录事实源性质声明。本文回答“内容应放在哪个目录”和“该目录在事实源体系中的性质”；事实源权威性的判断原则、单一事实源规则和工具输出回写规则，由 `specs/03-事实源边界与承载规范.md` 定义。

---

## 二、与 00 总纲的关系

00 定义 LD Vibe Harness 的产品理念、价值实现标准、五类构成要素和基础规范索引。本文承接 00 中“介质、Trae Solo 环境机制、Harness 工具、Harness 生产对象、Harness 行动模型共同组成工程驾驭体系”的架构判断，专门定义这些内容在项目文件夹中的承载位置。

本文是 LD Vibe Harness 项目文件夹规划和目录事实源性质声明的权威位置。00 只保留基础规范索引，不重复维护项目目录说明；03 定义事实源权威性判断原则，本文依据 03 的原则声明各目录在事实源体系中的性质，但不定义原则本身。

---

## 三、文件夹规划

本文的权威领域是 LD Vibe Harness 项目文件夹规划、一级目录用途、目录之间的内容归属关系、目录事实源性质声明和管辖项目定义。

### 3.1 管辖项目定义

本文中的“管辖项目”，指接入并使用 LD Vibe Harness 进行需求、任务、证据、变更、审计或交付治理的实际项目。

### 3.2 一级目录说明

| 目录 | 定位 | 主要内容 | 事实源性质 |
|---|---|---|---|
| specs/ | LD Vibe Harness 规范目录 | 00-99 specs 文档，包括理念总纲、基础规范、生产对象规范、行动模型规范和内部调研 | 规范事实源；70-89 内部调研不直接构成强制规则 |
| docs/ | 管辖项目资料目录 | 管辖项目资料、管辖项目审计结果、报告、操作说明、产品资料和非规范性实践 | 管辖项目文档事实源；不是 LDVH 基础规范事实源 |
| references/ | 外部资料目录 | 第三方文档、外部案例、外部方法资料和参考材料 | 非规范事实源；不能直接作为 LDVH 强制规则 |
| ldvh-base/ | 结构化对象实例目录 | Task、ADR、Evidence、Change、Pitfall 等 Harness 生产对象实例 | 结构化生产对象实例事实源 |
| web/ | Web Tools 实现目录 | LD Vibe Harness Web Tools 的前端、后端、页面和相关实现 | 非最终事实源；工具实现和运行状态不能替代事实源 |
| tools/ | 程序辅助工具目录 | 脚本、校验器、聚合器、受控写入工具和其他程序辅助工具 | 非最终事实源；工具实现和运行结果不能替代事实源 |

各目录的事实源性质依据 `specs/03-事实源边界与承载规范.md` 定义的原则判断。目录名称和内容归属本身不自动决定事实权威性；事实是否为最终事实源、同一事实由哪里权威承载，必须依据 03、对应对象规范和行动模型判断。

### 3.3 specs 目录

specs/ 承载 LD Vibe Harness 的规范体系和内部调研文档，包括：

1. 00 理念与纲要；
2. 01-07 基础规范；
3. 10-39 Harness 生产对象规范；
4. 40-69 Harness 行动模型规范；
5. 70-89 内部调研；
6. 90-99 保留扩展。

specs/ 的编号、文档类型、子文档、实践文档和引用纪律由 `specs/01-specs文档结构规范.md` 定义。

### 3.4 docs 目录

docs/ 承载管辖项目资料、管辖项目审计结果、报告、操作说明、产品资料和非规范性实践。

docs/ 面向人的阅读、确认、审查和操作需要，不用于承载 LD Vibe Harness 基础规范正文。

### 3.5 references 目录

references/ 承载外部资料、第三方文档、外部案例、外部方法资料和参考材料。

references/ 下的文档可使用两位数字前缀按新增顺序自然增长；该编号只用于排序和引用便利，不属于 specs 规范编号体系。

### 3.6 ldvh-base 目录

ldvh-base/ 承载结构化 Harness 生产对象实例，例如 Task、ADR、Evidence、Change、Pitfall 等。

ldvh-base/ 下各对象实例的目录结构、字段、状态和验收规则由 10-39 Harness 生产对象规范定义。

### 3.7 web 与 tools 目录

web/ 承载 LD Vibe Harness Web Tools 的实现。

tools/ 承载程序辅助工具、脚本、校验器、聚合器和受控写入工具。

Web Tools 和程序辅助工具的角色边界由后续 `specs/05-LDVH工具基础规范.md` 定义。

## 五、Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 新增、删除、重命名或改变本文定义的一级目录；
2. 改变一级目录的定位；
3. 改变一级目录的事实源性质声明；
4. 将某类内容迁移到与本文目录规划不一致的位置；
5. 将目录用途说明扩展为事实源判断原则、对象规则或行动流程规则。

当 AI 识别到上述情况时，至少必须暂停当前变更动作，向人提醒该操作可能触发 Human Gate，并说明涉及的目录、影响范围和建议确认事项。

文件夹规划检查至少包括：

| 检查项 | 标准 |
|---|---|
| 目录存在性 | 一级目录规划清晰 |
| 内容归属 | 文件放置符合本文目录用途说明 |
| 边界不扩张 | 本文未替代事实源、对象或行动模型规则 |
| 引用一致性 | specs 文档结构和事实源规则指向对应权威规范 |
