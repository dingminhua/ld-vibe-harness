## 2. 输入范围

| 范围 | 状态 | 规则 |
|---|---|---|
| `active_specs` | 当前 active 规范输入 | 只读解析 active `specs/` 中的 v2 身份块、章节和关系；Code 默认输入范围 |
| `specs_v2` | 兼容别名 | 仅为旧脚本和历史测试保留；语义等同 `active_specs`，不得被解释为仍存在独立 `specs-v2/` 当前入口 |
| `entry_navigation` | 入口任务导航组合范围 | 组合读取 `active_specs`、`runtime_extensions` 和 `governed_projects`，用于 Rules 入口、工作对象、规范变更和同步影响的同一任务视图；不包含 Git history，历史图谱未实现时必须通过诊断说明能力缺口 |
| `history_specs_v1` | 非当前验收范围 | 仅在用户显式要求历史追溯、迁移审计或价值提取时作为后置研究输入；当前知识地图不要求覆盖历史规范图谱，不覆盖 active `specs/` |
| `governed_projects` | 显式只读范围 | 读取工作区 `LDVH-GOVERNED-PROJECTS.yaml` 和登记项目 `ldvh-base/`，实时投影 WorkCase、ADR、Pitfall、Spark、Study 节点和对象关系；不修改项目清单、事实对象或项目 docs |
| `runtime_extensions` | 显式只读范围 | 只读解析带稳定自描述、来源规范和 canonical path 的固定 Rules、Skill、Agent、Hook 或等价运行时扩展承载物；用于入口导航和同步影响提示，不生成事实源缓存；不作为默认范围 |
| Git history | 不作为知识地图输入范围 | 需要追溯时使用 Git 原生命令按需查询；LDVH 不建立 Git 图谱或专用查询层。Git 配合只要求稳定事实源修改形成真实 Git commit records，并符合 07 commit message 契约 |

| `PLAN.md`、`MIGRATION-MAP.md`、临时审计 | 排除 | 可用于历史诊断或 review hints，不生成可信节点边 |
