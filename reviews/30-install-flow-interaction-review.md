# 30 文档安装流程交互完善建议

评估对象：`specs/30-安装配置与验证行动模板.md`

评估范围：只读评估安装向导交互流程的清晰度、美观度、可执行性与 Human Gate 表达；未修改源文件。

> 协作说明：本次调度中，`doc-auditor` 曾出现一次网络代理连接失败；另一次审核回传了可用结论。以下建议基于已成功回传的审核意见与已读取的 30 文档内容整理。

## 1. 总体判断

30 文档的安装流程底层结构已经比较稳：五步状态机、最终确认前不写入、检查事实与用户选择分离、Human Gate 和回滚验证要求都比较清楚。当前更适合做“呈现层优化”，不是推翻流程。

优化重点应放在：让用户一眼知道自己处在哪一步、系统查到了什么、现在是否安全、自己需要做什么决定、执行后具体会改变什么。

## 2. 当前流程优点

- 五步结构稳定：路径确认 → 安装前检查 → 安装选项 → 安装方案预览 → 最终确认。
- 明确最终确认前不写入，可降低误装、误改 Hook、误声明 integrated 的风险。
- `👉 / ✅ / 空白` 的状态表规则简洁，避免流程噪音。
- 已要求把系统检查事实与 Human 选择分离，避免把事实伪装成选项。
- 方案预览覆盖写入对象、写入位置、动作、验证、失败处理、回滚与残留风险，闭环意识强。

## 3. 可美化 / 完善建议

### P0：优先完善

1. **增加“用户视角摘要卡”**
   - 每一步开头用 3 行以内说明：本步目的、不会做什么、你需要决定什么。
   - 这样可以降低长表格带来的阅读压力。

2. **统一风险图例**
   - 固定解释 `✅ 通过`、`⚠️ 注意`、`⚠️ 需安装`、`⚠️ 需升级`、`⛔ 阻断`、`➖ 不适用`。
   - 尤其要让用户区分“注意”和“阻断”。

3. **方案预览突出“净变化”**
   - 建议按“将新增 / 将修改 / 将不做 / 需后置确认 / 回滚方式”分组展示。
   - 用户关心的不是所有信息，而是“执行后到底会变什么”。

### P1：建议完善

1. **路径确认增加可复制路径块**
   - 表格适合概览，但长路径不易复制；可在表格后追加代码块。

2. **安装前检查表增加“下一步处理”列**
   - 例如：纳入方案预览、保留不变、阻断需更换路径、后置确认。

3. **选择题文案更口语化**
   - 保持单选 / 编号规则不变，但问题可以更像用户语言。
   - 例如：“请选择是否调整管辖项目配置”。

### P2：体验优化

1. **增加进度安全提示**
   - 例如：“已完成 2/5，尚未写入任何文件”。

2. **最终确认前增加安全声明**
   - 强调“选择执行后才会开始写入”。

3. **不可验证项单独归组**
   - 避免残留风险淹没主方案。

## 4. 可直接采用的呈现样式示例

```markdown
### 安装向导 2/5：安装前检查

本步只读检查，不会写入文件。你暂时不需要决定安装，下一步才会收集选项。

| 状态 | 步骤 | 决策 / 结果 |
|---|---|---|
| ✅ | 1/5 📍 路径确认 | LDVH=/path/ldvh；工作区=/path/workspace |
| 👉 | 2/5 🔎 安装前检查 | 只读检查中 |
|  | 3/5 ⚙️ 安装选项 |  |
|  | 4/5 🔒 安装方案预览 |  |
|  | 5/5 🛠️ 最终确认 |  |

#### 状态图例

| 标记 | 含义 | 是否阻断 |
|---|---|---|
| ✅ 通过 | 当前项目满足要求 | 否 |
| ⚠️ 注意 | 有风险或需用户知情 | 不一定 |
| ⚠️ 需安装 / 需升级 | 需要纳入安装方案 | 否，进入方案预览 |
| ⛔ 阻断 | 当前不能继续执行 | 是 |
| ➖ 不适用 | 本场景无需处理 | 否 |

#### 检查结果

| 项目 | 结果 | 说明 | 下一步处理 |
|---|---|---|---|
| 🧾 工作区配置 | ✅ 通过 | 配置存在且字段有效 | 保留并展示清单 |
| 🔌 环境入口 | ⚠️ 需升级 | 指向旧路径 | 纳入方案预览 |
| 🪝 Git Hook | ⛔ 阻断 | 目标不是 Git worktree | 更换项目路径后继续 |
```

## 5. 不建议改动的边界

- 不建议取消固定五步，否则会削弱可验证性和一致性。
- 不建议把“返回修改”做成最终确认第三选项；可用自然语言回退到前一步。
- 不建议把配置位置做成选项；目标工作区根目录固定规则应保留。
- 不建议在方案预览前写入、创建目录或安装 Hook。
- 不建议用图标替代状态文字、路径、验证结论或 Human Gate。

## 6. 一句话结论

这份 30 文档的流程骨架已经够稳，下一步最值得做的是把每一步包装成“摘要卡 + 状态表 + 事实表 + 下一步处理 + 安全提示”的交互模板，让它不只是合规，还更像一个用户能轻松跟上的安装向导。
