# 规范落地要求与环境触发调查

> 创建日期：2026-06-08
> 定位：LDVH v2 对规范落地要求、环境实现和自动触发边界的内部评估
> 调研边界：不直接构成强制规则；稳定结论需吸收到 specs-v2 正文区后才生效
> 执行效力：无；规范规则需进入 specs-v2 正文区，环境映射需进入 `specs-v2/04.02-环境适配与运行投影规范.md` 或当前环境初始化记录后才生效
> 上位依据：`specs-v2/00-LD-Vibe-Harness理念与纲要.md`
> 相关规范：`specs-v2/03-文档基础规范.md`、`specs-v2/03.01-规范文档规范.md`、`specs-v2/14-Code实现规范.md`

---
## 1. 本文解决的问题

本文评估 LDVH v2 中规范落地要求应如何定义，以及规范文档在声明落地要求时，是否应直接写 Rules、Skill、Agent、Hook 等环境实体。

本文同时评估 Skill 与 Hook 的触发边界：当 LDVH 需要某项规范要求稳定触发时，是否可以只依赖 Skill 的模型判断，还是需要生命周期触发要求。

---
## 2. 结论

LDVH 正文规范不应直接把某个环境实体写成落地要求。正文规范应先声明这条规范要落地需要满足哪些要求，例如入口可见要求、流程复用要求、子 Agent 思考要求、确定性执行要求、Human 交互要求和生命周期触发要求。

环境适配映射再说明这些落地要求在 Codex、Trae、Claude Code、Cursor 或其他环境中如何实现，例如写成规则入口、Skill、Agent、Hook、命令、CI 检查、Web 页面或降级检查。

如果某项规范要求必须稳定触发，不应只依赖 Skill 的自动调用。Skill 适合承接可复用流程，但其触发通常依赖用户显式调用或模型根据描述判断相关性；需要事件级稳定触发时，应声明生命周期触发要求，并在环境映射中决定使用 Hook、自动运行、规则条件、命令、CI 或其他等价实现。

---
## 3. 规范落地要求判定标准

规范落地要求用于说明一条稳定规范要落地，需要满足哪些要求。一个事项只有同时满足以下条件，才适合作为规范落地要求进入正式规范：

1. 能消费 specs-v2 正文中的稳定规则、字段契约、流程要求、检查要求或权限边界；
2. 能在一个或多个开发环境中找到对应机制实现、入口、配置、命令、工具、页面或降级方式；
3. 本文变化会导致对应运行投影需要同步检查；
4. 它不是单个字段、单个产物、单个工具文件或某个环境的专有名称。

规范落地要求描述规范要落地需要满足哪些要求；环境适配映射描述该要求在具体环境中通过哪些机制实现。

## 4. 建议规范落地要求

| 落地要求 | 要求含义 | 环境实现示例 |
|---|---|---|
| 入口可见要求 | 让 AI 进入项目或工作区时能读取并遵守稳定规则、入口摘要、边界和路径 | Codex instructions / AGENTS，Trae Rules，Claude project instructions，Cursor Rules |
| 流程复用要求 | 将重复执行步骤封装成可复用流程，降低提示词重复和执行漂移 | Codex Skill，Trae Skill，Claude Skill，命令入口 |
| 子 Agent 思考要求 | 需要脱离主上下文、使用特定专业视角、或并行展开多个视角；独立、专项、并行是可组合维度 | Codex subagent，Trae 自定义 Agent / SOLO 调用，Claude subagent |
| 确定性执行要求 | 提供解析、聚合、校验、测试、上下文压缩、受控写入和稳定反馈 | LDVH Code 实现、脚本、测试、命令、CI |
| Human 交互要求 | 让 Human 看见状态、风险、证据和待确认事项，并完成确认或受控轻写入 | LDVH Web、对话确认、环境提问工具 |
| 生命周期触发要求 | 在事件发生时触发检查、提醒、阻断、上下文注入或记录，避免只依赖 AI 想起规则 | Codex Hooks，Claude Code Hooks，CI / pre-commit，Trae 自动运行或外部自动化降级 |

上述落地要求可以被同一环境实体共同实现，也可以由多个环境机制组合满足。例如“修改规范后必须校验”可以映射为 Skill 提供流程，Hook 或 CI 保证触发，Code 执行确定性校验。

子 Agent 思考要求中的维度可以组合。例如独立 + 专项用于让一个安全视角 Agent 脱离主上下文审查；专项 + 并行用于多个不同专业视角同时检查；独立 + 专项 + 并行用于多个独立 Agent 分别从文档一致性、Code 可验证性和环境映射风险等视角审计后汇总。

## 5. 不建议单列的事项

| 事项 | 判断 |
|---|---|
| Validator | 不建议单列为机制；它是确定性执行要求的一种，归入 Code。 |
| Tools / PyTools | 不建议单列为机制；它是 Code 的实现形态。 |
| Contract / Schema | 当前先作为契约产物，由 Code 和 Web 消费；除非未来出现独立契约加载、同步和校验体系。 |
| MCP / Connector | 当前不作为 LDVH 核心机制；LDVH 暂不构建 MCP，MCP 可作为环境工具来源或外部连接实现。 |
| Human Gate | 不建议单列为机制；它是治理条件和停顿要求，可由 Web、对话确认、环境工具、Hook 或 Rules 类入口实现。 |
| Context Loading | 不建议单列为机制；它是工作流程中的上下文要求，可由入口可见要求、Code、Skill 或环境上下文机制实现。 |

## 6. 环境调查摘要

### 6.1 Codex

Codex Skill 支持显式调用和基于描述的隐式调用。隐式调用由 Codex 判断任务是否匹配 Skill 描述，因此适合流程复用，但不适合作为必须触发的事件保障。

Codex subagent workflow 支持并行子 Agent，但官方手册说明 Codex 不会自动派生 subagent，通常需要用户或主控提示明确要求并行或子 Agent 工作。

Codex Hooks 支持生命周期事件，例如工具使用前后、用户提示提交、会话停止、压缩前后、子 Agent 启停等。Hook 适合承接事件触发能力，用于触发 Code 检查、阻断风险动作、注入上下文或记录结果。

来源：Codex Manual `Agent Skills`、`Subagents`、`Hooks` 章节。

### 6.2 Trae

Trae Skill 支持手动调用和 AI 根据 description 自动调用，适合流程复用，但触发仍依赖模型判断。

Trae Rules 支持始终生效、指定文件生效、智能生效和手动触发生效，并支持子目录规则。该能力适合映射入口可见要求和部分条件加载要求。

Trae Agent 支持自定义智能体，并可由 SOLO Agent 调用自定义智能体。Trae 的 Agent 能力可映射子 Agent 思考要求和多智能体编排实现。

Trae 自动运行支持自动运行命令和自动运行 MCP，但当前已整理资料中未看到与 Codex / Claude Code 同类的通用生命周期 Hook。若 LDVH 需要事件级稳定触发，Trae 环境映射可以考虑 Rules 条件生效、SOLO Agent 编排、自动运行命令、外部 CI 或人工检查降级。

来源：`specs/refs/trae/01-Rules规则机制.md`、`specs/refs/trae/02-Skills技能机制.md`、`specs/refs/trae/03-Agent智能体机制.md`、`specs/refs/trae/07-自动运行与安全性.md`。

### 6.3 Claude Code

Claude Code Skill 支持自动发现并由 Claude 根据请求自主决定是否使用。该能力适合映射流程复用要求。

Claude Code Hooks 文档显示其支持多种生命周期事件，并且部分事件可以阻断动作。该能力适合映射生命周期触发要求。

来源：Claude Code Skills 文档、Claude Code Hooks 文档。

### 6.4 Cursor

Cursor Rules 支持 Always、Auto Attached、Agent Requested 和 Manual 等规则应用方式。该能力适合映射入口可见要求和部分条件加载要求。

当前调查未确认 Cursor 提供与 Codex / Claude Code 同类的通用生命周期 Hook。若需要事件级稳定触发，应在环境映射中使用 Cursor 可用的规则模式、命令、外部 CI 或降级检查。

来源：Cursor Rules 文档。

## 7. 对规范写法的建议

正式规范中的规范落地要求应避免直接写环境实体名称。推荐写法如下：

| 正文规范应写 | 环境映射再判断 |
|---|---|
| 需要成为 AI 进入规范文档工作区时可读取的入口约束 | 写成 Codex instructions、Trae Rules、Cursor Rules、Claude instructions 或其他入口 |
| 需要在规范文档变更后执行文档结构和引用校验 | 写成 Hook、CI、命令、Skill 流程、自动运行或人工降级检查 |
| 需要复用规范审计步骤 | 写成 Skill、命令或 Agent 调度流程 |
| 需要独立、专项或并行的子 Agent 思考 | 写成 Codex subagent、Trae 自定义 Agent、Claude subagent 或人工二次审阅 |
| 需要 Human 确认 | 写成 Web 确认、环境提问工具、对话确认或 Hook 阻断提示 |

当某项要求只要求 AI 知道“应该怎么做”时，可以声明入口可见要求或流程复用要求；当某项要求要求“到了某个时机必须发生”时，应声明生命周期触发要求，并在环境映射中选择 Hook、CI、自动运行或降级检查。
