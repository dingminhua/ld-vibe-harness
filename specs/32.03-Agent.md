## 1. 本文定位

本文是 `specs/32-Pitfall-踩坑记录.md` 的附件型实践子文档（编号 32.03），承接 Agent 上下文隔离实践。本文不是独立事实模型，不得重新定义 Pitfall 的对象定位、准入条件、状态机、对象关系、Human Gate、字段契约、事实源回写或证据留存。发生冲突时，以 32 主文档和上位基础规范为准。

---

## 2. 不创建专用 Agent 的理由

Pitfall 当前不需要创建专用 Agent，理由如下：

1. Pitfall 的整理、筛选和读取流程可由主上下文读取 32 主文档、32.01-Rules.md 和 32.06-Contract.md 后执行，或未来由 Skill 承接；
2. Pitfall 创建和状态流转需要 Human Gate，专用 Agent 不能替代人类确认；
3. Pitfall 实例写入可由未来 Tools 受控写入能力承接，不需要 Agent 维护写逻辑；
4. Pitfall 作为经验沉淀类事实模型，场景稳定、上下文规模可控，不需要独立上下文隔离；
5. 创建专用 Agent 会增加维护成本，但不会提升 Pitfall 事实源回写的可控性。

---

## 3. 检查项

检查 Pitfall Agent 不创建决策是否合规时，应确认：

1. 是否未创建 Pitfall 专用 `.trae/agents/` 实体；
2. Pitfall 的整理、筛选和读取是否仍由主上下文或未来 Skill 执行；
3. Pitfall Human Gate 是否未被 Agent 替代；
4. Pitfall 字段、状态校验和受控写入是否未由 Agent 维护第二套规则；
5. Pitfall 经验整理是否未在 Agent 内维护与 32 主文档独立的准入判断逻辑。
