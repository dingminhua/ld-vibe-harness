## 1. 价值判断

本文存在的价值，是把重复出现的 AI 行动沉淀成可复用结构，让 AI 在相似任务中能少猜步骤、少漏验证、少丢证据，并知道何时等待 Human 确认、分流问题或呈现结果。

行动模板降低的是进入行动、排序、暂停、验证、回写和交还成本，不是汇编来源规则全文。若某个行动必须复述来源规则才能执行，应回到来源规范、附件或实现域补齐，而不是在行动模板中形成第二规则源。

行动模板主要服务 V1、V2、V4、V5、V6、V7、V8 和 V9：它把 Context、Scenario、Gate、执行、验证、回写和交还组织成稳定路径，让 AI 能快速进入场景、理解边界、按步骤执行、在 Gate 或 Human Gate 触发时等待 Human 明确确认、执行指定验证、按格式回写，并把缺口和复用经验分流到对应承接位置。行动模板不是规则源，也不是授权器；它只组织来源规则、当前上下文、执行步骤、验证和回写。

## 2. 权威依据

本文承接 `specs/00-理念与构成.md` 的行动模板定位、`specs/01-保障与衔接.md` 的行动指南和消费时机规则、`specs/02-AI行为规范.md` 的主控责任、`specs/03-事实源与Git溯源规范.md` 的证据回写边界，以及 `specs/04-规范体系基础规范.md` 的结构规则。

若行动模板与来源规范冲突，以来源规范和上位规范为准。若行动模板需要授权、风险接受或验收，必须进入 Human Gate。

## 3. 归口边界

本文归口定义行动模板的基础结构、能力输出交还、问题分流、验证和回写边界。

本文不归口定义事实对象字段、Code 输出 schema、Web 页面、runtime payload、Hook 安装、commit message 契约、管辖项目配置字段、测试治理或 30+ 成员的具体模板全文。这些内容分别由 05、07、08、01/07、03、10、09 和对应行动模板成员承接。本文可以定义具体模板的准入和结构要求，但不得把行动步骤写成环境入口安装授权、配置事实源契约、Code 实现细节或 integrated 状态证明。

## 4. 适用范围

本文适用于：

1. AI 反复执行、需要稳定步骤和验证入口的任务；
2. 需要进一步组织 Context、Scenario、Gate 和执行顺序的任务；
3. V2 行动成员迁移候选的准入判断；其中 LDVH 安装初始化配置已由 `specs/30-安装配置与验证行动模板.md` 承载，Git 提交行动已由 `specs/31-Git提交行动模板.md` 承载。

## 5. 行动模板结构

行动模板应至少表达以下结构：

| 结构 | 职责 |
|---|---|
| Context | 当前行动前最小必要事实源、对象、证据和约束。 |
| Scenario | 何时适用该模板，AI 如何识别进入信号。 |
| Gate | 必须暂停、分流、验证或进入 Human Gate 的条件。 |
| 执行 | 可复用的步骤顺序、能力调用和失败处理。 |
| 验证 | 完成声明前需要的测试、命令、回读、Human 确认或等价验证。 |
| 回写 | 哪些结论、证据、风险或缺口需要回到事实源。 |
| 交还 | 向 Human 或下一轮 AI 交还的状态、证据和残留风险。 |

行动模板应引用来源规则，不复制来源规则。模板不能用自身步骤重定义 specs、事实对象、Code、Web、测试或事实源规则。

### 5.1 引用与复制的判断标准

行动模板引用来源规则，是指出"这一步按哪条来源规则执行"和"Human 在这一步需要决定什么"；复制来源规则，是把来源规则的字段闭集、字段定义、枚举完整列表、判定顺序、冲突处理或策略表在模板中重述。

判断规则：

| 模板中写的内容 | 引用 | 复制 |
|---|---|---|
| 步骤名称和执行顺序 | 是 | 否 |
| 回指来源 spec 的路径和段落 | 是 | 否 |
| 来源 spec 的字段名（仅提到名称，不展开定义） | 是 | 否 |
| Human 在该步需要确认或决定的事项 | 是 | 否 |
| 该步的进入条件和暂停条件 | 是 | 否 |
| 模板自身的 Human Gate、Stop Conditions、待补齐事项 | 是（模板自身规则） | 否（不属复制来源 spec） |
| 来源 spec 的字段闭集、字段定义、枚举值完整列表 | 否 | 是 |
| 来源 spec 的判定顺序、冲突处理规则 | 否 | 是 |
| 来源 spec 的策略表、分类表完整内容 | 否 | 是 |
| 来源 spec 的验证契约字段定义、类型或约束 | 否 | 是 |
| 来源 spec 的示例（含正例、反例、命令样例） | 否 | 是 |

模板自身规则只包括行动编排规则：进入信号、步骤顺序、Gate 放置、Human 需决定事项、失败信息包、验证入口、回写目标和交还类别。模板自身规则不得定义或重述字段契约、状态或分类闭集、判定算法、策略表、CLI 参数、输出 schema、测试样例、实现命令或 UI 渲染细节。

本节所称来源规则包括 specs 正文、attachments、事实对象规范、Code / Web / tests / hooks 实现域文档、CLI 或 Code 输出契约和可执行测试。行动模板可以回指这些来源，但不得把其内容复制成模板规则。

模板展开的是"AI 和 Human 在这一步做什么、决定什么、回指哪里"，不展开"来源规则说了什么"。来源规则的内容应在来源 spec 的对应段落找到，模板只回指来源 spec 对应段落。

若某步骤必须展开来源规则原文才能让 AI 执行，说明来源规则的颗粒度不足，应回到来源 spec 补齐，而不是在模板里重述形成第二规则源。来源 spec 把行动步骤组织回指行动模板时，行动模板不再反向回指来源 spec 的行动步骤组织，只回指来源 spec 的非行动规则（字段、枚举、判定顺序、冲突处理、策略表等）。

### 5.2 七结构粒度要求

七结构应按以下粒度书写：

| 结构 | 应写内容 | 不应写内容 |
|---|---|---|
| Context | 列出需要读取的事实源、对象、证据的名称和回指路径；回指路径至少到 spec 文件或附件文件级别，不要求到段落级别 | 不重述来源 spec 的字段定义或字段闭集 |
| Scenario | 列出进入信号和适用条件 | 不展开来源 spec 的场景分类或判定顺序 |
| Gate | 列出暂停、分流、Human Gate 的触发条件 | 不重述来源 spec 的规则细节或冲突处理 |
| 执行 | 列出步骤名称、每步回指的来源规则段落、该步 Human 决定事项 | 不重述来源规则的正文内容 |
| 验证 | 列出验证入口、回指 09.Att.01 和验证声明所需字段名列表 | 不展开来源 spec 验证字段的定义、类型、约束或枚举值 |
| 回写 | 列出回写目标和回指路径 | 不重述事实对象的字段闭集 |
| 交还 | 列出交还项和残留风险 | 不重述来源 spec 的交还规则 |

每个结构应包含必要来源回指；Gate 结构必须列出暂停、分流、Human Gate 和 Stop Conditions 触发条件。其它结构只在本结构自身存在暂停、分流或交还要求时写对应条件，不得为了可检查性把 Gate 条件重复塞入每个结构。

行动模板组织 AI 进入来源 spec 或实现域入口执行行动的路径，不替代来源规则内容，也不维护第二规则源或第二事实源。

独立成篇指独立 spec 文件且独立编号（如 30、31 等）。独立成篇的行动模板成员同样适用本粒度要求，不得因独立成篇而展开来源规则原文。

模板候选只有在具备正式规则来源、验证方式、回写边界和测试闭环后，才能成为正式行动模板。正式行动模板成员的七结构内容以各自 spec 正文为准；本文不承载具体模板示范。

### 5.3 模板自有编排边界

正式行动模板成员可以按自身场景定义行动阶段、Human 决策点、Gate 放置、失败分流、验证入口、回写目标和交还类别，但这些内容必须能映射回 Context、Scenario、Gate、执行、验证、回写或交还之一。

不能映射到七结构的内容，不应作为行动模板主体规则长期保留；应回到来源 spec、附件、实现域文档、测试或待补齐事项承接。表格列、图标、控件、命令样例、输出字段、实现模块名和 UI 展示实践，默认属于实现域或运行时输出；除非上位规范明确授权为模板规则，否则不得写入行动模板正文。

## 6. 能力输出与主控责任

行动模板可以组织 Code、Web、测试、Hook、子 Agent、外部工具或环境包装的输出，但这些输出都必须交还主控 AI 判断。

| 输出来源 | 可提供 | 不得替代 |
|---|---|---|
| Code | 解析、诊断、read_plan、preflight、runtime receipt | 事实源、Human Gate、完成结论 |
| 子 Agent | 旁路审查、专题分析、候选建议 | 主控责任、最终判断 |
| 测试 | 验证证据、失败信号、回归样例 | 规则正文、Human 验收 |
| Web | Human-facing 状态、风险、证据展示 | 事实源和行动判断 |
| Skill 或外部包装 | 可复用步骤和环境入口 | V3 顶层机制和规则权威 |

能力输出不可回指来源规则、事实源或验证范围时，只能作为过程输出，不得作为完成证明。

## 7. 保障措施

| 要求 | 机制 | 触发 | 证据 | 缺口处理 |
|---|---|---|---|---|
| 来源回指要求 | 行动模板必须回指来源 specs、事实对象或 Human 决策；由本文、03 source_refs、07 Code 保障 | 新建或迁移模板时 | 模板 identity block、source_refs、来源 specs 或 Human 决策记录 | 缺少来源时保持候选，不进入正式模板 |
| Gate 显式要求 | 模板必须写出暂停、分流和 Human Gate 条件；由本文、01、02 保障 | 模板涉及写入、提交、验收或风险接受时 | Gate、Human Gate、Stop Conditions 和交还中的阻断说明 | 缺少 Gate 时停止执行，回到来源规范补齐 |
| 验证要求 | 模板必须说明完成声明前的验证入口或不可验证说明；由本文、09 保障 | 模板声明完成、提交或关闭时 | 验证方法、验证摘要、测试或 Human 确认证据 | 缺少验证时按 09 写为未验证或阻断 |
| 能力输出边界 | Code、Skill、Agent、Web、Hook 输出必须交还主控；由本文、02 保障 | 模板使用外部能力时 | 过程输出、诊断、source_refs 和主控交还记录 | 外部输出不得直接放行；交还主控判断或分流 |

## 8. 验证方法

验证本文规则时应检查：

| 检查类别 | 检查内容 | 不满足时 |
|---|---|---|
| 结构检查 | 模板是否具备 Context、Scenario、Gate、执行、验证、回写和交还 | 保持为候选，不进入正式模板 |
| 来源检查 | 模板是否回指来源规则，不复制来源规则；按 §5.1 判断表判定引用/复制 | 回到来源规范或模板重写 |
| 粒度检查 | 模板各结构是否按 §5.2 粒度表书写，是否按 §5.1 判断表判定引用/复制 | 按 §5.2 调整粒度，或回到来源 spec 补齐 |
| 编排边界检查 | 模板规范性句子是否能归类为模板编排规则或来源回指；额外主体小节是否能映射回七结构 | 不能归类时移到来源 spec、附件、实现域文档、测试或待补齐事项 |
| 能力边界检查 | 外部输出是否只作为过程输出并交还主控 | 停止完成声明或转为 diagnostic |
| 验证检查 | 完成声明是否有测试、命令、回读、Human 确认或等价验证 | 按 09 写为未验证或阻断 |

## 9. Human Gate

以下情况必须进入 Human Gate：

1. 将候选行动模板提升为正式可执行模板；
2. 改变模板 Gate、风险接受、提交拆分、事实源回写或完成判断；
3. 安装、覆盖或扩大外部环境入口、Hook、Rules、Skill 包装能力；
4. 允许能力输出跳过主控 AI、事实源边界或验证声明；
5. 接受模板长期缺少验证、回写或失败分流的风险。

## 10. Stop Conditions

出现以下情况时，AI 必须暂停：

1. 模板无法说明来源规则或减少的 AI 负担；
2. 模板复制来源规则的字段闭集、枚举、判定顺序、冲突处理、策略表、CLI 契约或实现域细节形成第二规则源；
3. 模板复制事实对象、状态、过程输出、验证输出或环境观察，形成第二事实源或伪事实源；
4. Skill、Hook、Rules 或 Agent 被写成 V3 顶层机制；
5. Gate 或 Human Gate 被模板步骤绕过；
6. 无验证证据却声明模板执行完成。
