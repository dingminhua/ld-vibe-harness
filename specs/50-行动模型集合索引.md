## 一、定位

本文是 50-79 行动模型规范区段的集合索引，服务于 AI 和人在进入具体行动规范前快速了解行动清单、编号归属、关系映射、状态和维护边界。

本文不定义具体行动流程、Context 要求、Scenario 识别、Gate 触发条件、Skill / Agent 调度规则或事实源回写流程。行动模型通用规则以 `specs/14-LDVH行动模型基础规范.md` 为准，具体行动规则由 51-79 对应行动规范承载。

---

## 二、索引范围

50-79 用于承载 LDVH 行动模型规范：

1. 50 为行动模型集合索引；
2. 51-60 为当前规划的具体行动规范；
3. 61-79 为未来新增行动预留编号。

新增、删除、重命名或重排行动编号，应依据 `specs/14-LDVH行动模型基础规范.md` 的 Human Gate 要求处理。

## 四、模型关系

当前行动模型按治理用途分为七类：

| 分类 | 行动 | 关系说明 |
|---|---|---|
| 协作增强行动 | 多角色思考 | 在复杂变更、决策或跨模块影响判断前，通过多视角分析提高 AI 判断质量 |
| 初始化行动 | 项目初始化 | 建立项目可被 LDVH 管辖的基础上下文和目录结构 |
| 需求规划行动 | 对话转需求、需求转任务 | 将人的输入转化为可追踪、可执行的事实源对象 |
| 任务执行行动 | Task 执行、Task 阻塞处理 | 推动最小执行对象流转并记录证据、阻塞和决策需求 |
| Review 行动 | Review 执行 | 检查执行结果、证据和关闭条件 |
| 审计行动 | 项目审计 | 发现项目状态、事实源和执行闭环中的问题 |
| 管理行动 | 对象创建、对象状态更新 | 管理结构化对象和状态的受控变更 |

Rules、Skill、Agent 的机制选择和治理边界由 `specs/11-LDVH-AI协作规范.md` 及其子文档定义。本文只维护行动规范区段的索引关系，不重复定义 AI 协作机制规则。

## 五、Human Gate

以下情况应评估 Human Gate：

1. 新增、删除、重命名或重排 50-79 区段编号；
2. 改变某个编号对应的行动归属；
3. 将 61-79 保留编号升级为具体行动规范；
4. 将本文清单中的 planned 行动正式创建为具体行动规范；
5. 让本文定义具体行动流程、Gate 触发条件、Skill / Agent 调度规则或事实源回写流程。

---

## 六、维护说明

1. 新增 51-79 具体行动规范后，应同步更新本文文档清单中的文档名、状态和说明；
2. 行动模型通用规则变更时，应优先修改 `specs/14-LDVH行动模型基础规范.md`，本文只同步索引信息；
3. 具体行动的 Context、Scenario、Gate、证据和回写规则稳定后，应在具体行动规范中定义，不在本文维护；
4. 本文变更应按项目规则追加 `ldvh-base/changes/`（工作区级目录）变更记录。
