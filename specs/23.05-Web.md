---

## 2. 当前状态与未来能力定义

### 2.1 当前状态

Pitfall Web 信息同步当前未创建（active-prep），原因：

1. LDVH Web 信息同步层整体为零实现，不存在 Web 页面基础设施；
2. Pitfall 实例数量不足，Web 展示和筛选需求尚未充分验证；
3. Web 层的设计决策（框架、部署方式、与 Tools 的接口）尚未在 LDVH 层面完成；
4. 在不具备 Web 基础设施的前提下创建 Pitfall 页面会导致孤岛。

### 2.2 未来能力定义

Pitfall Web 信息同步应具备以下能力：

1. **展示**：列出项目所有 active Pitfall，按状态、标签、适用范围、严重程度分组展示；
2. **筛选与搜索**：按关键词、标签、关联对象、时间范围筛选 Pitfall；
3. **详情查看**：展示单个 Pitfall 的完整字段，包括问题、根因、解决方式、验证结果、规避策略和关联对象；
4. **关联视图**：展示 Pitfall 引用的 Task、Evidence、Memo、Change、ADR 和相关 Rules；
5. **Human Gate UI**：提供创建、激活、归档、替代 Pitfall 的确认入口；
6. **替代链追踪**：展示 Pitfall 的 `superseded` / `superseded_by` 关系链。

Web 不得维护第二事实源，所有写入必须通过 Tools 受控写入回写到 `ldvh-base/pitfalls/`。

---

## 3. 实现前提

在创建 Pitfall Web 信息同步之前，应满足以下前提：

1. LDVH Web 信息同步层基础设施已建立（页面框架、部署方式、聚合数据接口）；
2. Pitfall Tools 至少具备读取、解析、聚合和受控写入能力；
3. `ldvh-base/pitfalls/` 存在一定数量的实例可以驱动展示和筛选验证；
4. Pitfall 与其他对象的关联引用可在 Tools 层面聚合。

---

## 4. 边界约束

1. Web 只能作为派生视图或受控入口，不得成为 Pitfall 第二事实源；
2. Web 写入能力必须通过 Tools 受控写入或等价校验流程，不得绕过 Human Gate 直接写文件；
3. Web 不得维护独立的 Pitfall 状态判断或准入条件判断；
4. Web 展示的 Pitfall 状态应与 Git 文件事实源保持一致。

---

## 5. 检查项

检查 Pitfall Web 当前 active-prep 状态是否合规时，应确认：

1. Pitfall Web 页面是否未在实现前提满足前创建；
2. Pitfall 信息是否未通过 Web 或其他非 Git 媒介形成第二事实源；
3. 未来 Web 设计的 Human Gate UI 是否保留了与 32 主文档 Gate 操作一致的确认点。

---

## 6. 待补齐事项

1. LDVH Web 信息同步层启动后，Pitfall 应作为前期展示对象之一；
2. Pitfall Tools 实现后，Web 与 Tools 的数据接口和更新机制待定义；
3. Pitfall 与其他对象的关联视图设计待关联关系实例验证后细化。
