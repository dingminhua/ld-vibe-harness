> 创建日期：2026-06-08

## 1. 本文解决的问题

本文解决 LDVH 中术语应如何命名、解释、引用和变更的问题。

术语规范的目标不是复制各专项规范的规则正文，而是让 AI 和 Human 在阅读、编写和执行 LDVH 文档时，能够稳定区分项目、工作区、规范、索引文档、规范落地、能力保障、环境适配、适配措施、构成要素、环境能力、工作对象、字段内容格式、状态、检查、校验、验证、审计、写入、回写、审阅和审核等概念。

---
## 2. 与 00 总纲的关系

00 定义 LDVH 的产品定位、五类构成要素、事实源原则、运行闭环标准和 Human Gate 原则，是本文的上位概念来源。本文承接 00，将后续正式规范、工作模型、工作流程、Code、Web 和环境适配需要复用的概念整理为统一术语边界。

本文不得反向改写 00 的产品定位和上位概念。若术语治理发现需要调整 00 中的上位概念，应单独触发 Human Gate，而不是在本文或其他规范中隐式覆盖。

除 00 的上位概念表达外，本文是 LDVH 术语定义和术语变更治理的权威位置。01、03、04、05、06、07、08、09、10 以及后续工作模型和工作流程规范可以说明术语在本规范中的应用规则，但不得并行维护同一术语的权威定义。术语建议被吸收后，应以本文为准；未吸收内容不得作为 LDVH 语义依据。

## 3. 术语归口规则

术语定义原则上归口到本文。00 负责提供上位概念来源，不被本文反向管辖；其他规范可以使用术语、引用术语，或说明某个术语在本规范场景中的应用规则，但不得重复定义同一术语。

## 4. 项目、工作区与文档分区术语

| 术语 | 定义 | 边界 |
|---|---|---|
| LDVH 自身项目 | 承载和维护 LDVH 规范体系、文本能力资产、Code、Web 和 dogfood 事实实例的项目 | 当前项目使用 `docs/specs/` 作为规范资产和规范事实源 |
| 管辖项目 | 安装并使用 LDVH 进行需求、任务、证据、变更、审计或交付治理的用户项目 | 管辖项目不默认创建 `docs/specs/` 或 `specs/`，使用 `docs/` 承载项目文档 |
| 管辖项目配置 | 工作区根目录 `LDVH-GOVERNED-PROJECTS.yaml`，用于说明当前工作区 LDVH 管理实例并登记管辖项目最小清单 | 根字段只包含 `product_name`、`product_description`、`projects`；每个项目只强制 `id` 和 `path`，可选 `name` 和 `description`；不承载初始化状态、落地状态、检查状态、项目状态、项目类型、环境适配、适配措施或工作对象关系 |
| LDVH 文档工作区 | 承载 LDVH 规范正文、内部调研分析和外部引用的文档工作区 | 在 LDVH 自身项目中为 `docs/`，其下并列设置 `docs/specs/`、`docs/research/` 和 `docs/refs/` |
| 规范正文区 | 承载 LDVH 正式规范正文的文档分区 | 在 LDVH 自身项目中为 `docs/specs/`；管辖项目不默认创建 |
| 管辖项目文档工作区 | 承载管辖项目正文、内部分析和外部引用的文档工作区 | 在管辖项目中为 `docs/` |
| 正文区 | 文档工作区中承载稳定正文的根层级 | `research/` 和 `refs/` 不属于正文区 |
| research | 内部评估、方案分析或内部调研区 | 不直接构成正式规范，结论需要吸收到正文区或工作对象后生效 |
| refs | 外部引用、第三方资料、官方文档摘录或引用副本区 | 不直接构成正式规范，不反向维护正文区规则 |
| 来源 | 说明某项结论、适配、字段、证据或判断所依据的规范、refs、research、命令输出、现有清单、Human Gate 记录或其他事实源 | 不固定写作“来源文档”；来源不自动等于权威事实源，应按来源类型判断是否需要吸收、验证或回写 |
| 吸收 | 将 research、refs 或临时分析中的结论转入正文区、工作对象、ADR、Task、Memo 或其他权威位置的治理动作 | 只引用 research、refs 或临时材料路径，不构成吸收 |
| 参考与研究材料 | `docs/refs/`、`docs/research/` 或临时分析中用于调研、参考、对照、候选方案或阶段性推进计划的材料 | 不是正式资产，不是权威事实源，也不是环境适配层；稳定结论必须吸收到正式规范、工作对象、ADR、Task、Code、Web 或其他对应权威位置后才生效 |
| 待补齐事项 | 已识别但尚未完成调研、验证、实现、回写、清理或决策的后续事项 | 不是失败状态，不等于已批准任务；字段名可保留 `open_items`，中文显示统一使用“待补齐事项” |

## 5. 规范体系术语

| 术语 | 定义 | 边界 |
|---|---|---|
| 正式规范 | `docs/specs/` 正文区中定义稳定规则、对象边界、流程要求、Code 要求、Web 要求、环境适配要求或检查要求的规范文档 | 正式规范应遵守 03 的文档骨架，并按 04.01 判断规范落地要求 |
| 资产 | LDVH 可被复用、承接、加载、触发、执行或展示的能力本体、规则本体、实现本体或界面本体 | 资产不等同于目录容器、适配措施、过程输出或工作对象实例；是否为事实源取决于具体资产类型 |
| 规范资产 | `docs/specs/` 中承载稳定规则、模型、流程、合同和检查要求的规范正文资产 | 同时是规范事实源；不得由环境薄入口、Rules、Skill、Agent、Hook、Code 输出或 Web 状态替代 |
| 文本能力资产 | `rules/`、`skills/`、`hooks/`、`agents/` 中面向 AI 的规则、能力、触发策略、角色或多角色模板等 Markdown 文本资产 | 只承载可复用文本能力，不替代正式规范、工作流程、Code、Web 或工作对象事实源 |
| Code 能力资产 | `tools/` 中 LDVH 提供的可执行检查、校验、解析、生成、迁移、受控写入、上下文压缩或报告输出的确定性参考实现资产 | Code 输出不是最终事实源；稳定结论必须回写到对应 Git 文件事实源 |
| Web 能力资产 | `web/` 中面向 Human 的展示、审阅、确认、检查、矩阵展示或受控轻写入界面资产 | Web 页面状态不是最终事实源；写入和回写必须受正式规范、Code 合同和 Human Gate 约束 |
| 工作对象事实源 | `ldvh-base/` 或管辖项目对应命名空间中承载 WorkArea、TaskPlan、Task、SubTask、ADR、Memo、Pitfall、Change 等工作对象实例的事实源 | 不是能力资产；可以记录资产相关决策、任务、证据或踩坑，但不承载可复用能力资产本体 |
| 候选事项 | 尚未创建、尚未生效或需要后续讨论、吸收、废止、保留的事项 | 候选事项不得被当作已经生效的规则执行 |

## 6. 索引文档术语

| 术语 | 定义 | 边界 |
|---|---|---|
| 索引文档 | 用于定位编号区段、文档集合、状态清单或输入清单的文档 | 不替代对应基础规范或具体规范 |
| 说明性索引 | 只帮助查找文档、章节或资料，不定义稳定治理规则的索引文档 | 不默认属于正式规范 |
| 规范型集合索引 | 维护正式编号区段或规范集合的清单、状态、编号占用、关系、落地与检查输入或 Human Gate 规则的索引文档 | 属于正式规范，规则由 `docs/specs/03.03-索引文档规范.md` 规定 |

## 7. 规范落地与环境适配术语

| 术语 | 定义 | 边界 |
|---|---|---|
| 规范落地要求 | 一条稳定规范要落地需要满足的要求 | 不等于 Rules、Skill、Agent、Hook、CI、命令、工具文件或 Web 页面 |
| 能力保障 | LDVH 为满足规范落地要求而提供的能力组合，包括入口提示、流程复用、确定性检查、Human Gate、Code、Web、Agent、生命周期触发或人工检查 | 能力保障由 LDVH 提供，不由环境替 LDVH 选择；具体环境只影响执行方式和降级方式 |
| 保障机制 | 能力保障中用于让某项规范落地要求被执行、检查、复用、触发或确认的具体机制 | 必须与规范落地要求绑定；无法保障时应记录能力缺口或适配降级 |
| 环境适配 | LDVH 基于环境能力清单，将能力保障落实到具体环境入口、配置、命令、工具、页面、Skill、Agent、Hook、CI、检查和降级方式的过程 | 不得反向改写正式规范；环境只提供客观能力清单，不是 LDVH 决策源 |
| 环境能力清单 | 某个环境可用于入口、流程、工具、触发、确认、校验或回写的客观能力、来源证据、限制和证据状态的登记载体 | 环境能力清单是集合和证据结构，不是单项环境能力；由 `docs/specs/04.03-环境适配规范.md` 规定；不得写成 LDVH 全局要求 |
| 适配措施 | 能力保障在具体环境中形成的入口、文件、命令、配置、工具、页面、Skill、Agent、Hook、CI 检查、摘要或降级记录 | 不是最终事实源；不得替代正式规范、工作对象事实源或 Code 验证 |
| 适配措施状态 | 某个适配措施在当前环境中的存在、可用或维护状态，例如已存在、计划创建、缺失、部分可用、已废止或不适用 | 不是适配措施本体，只用于即时标注、检查和漂移判断，不持久化保存 |
| 环境 | AI 和 Human 实际执行工作的具体工具、产品或运行面实例 | 环境是具体执行对象；开发环境是 LDVH 五类构成要素之一；当前 04.03 只覆盖 Trae Work CN 与 Codex App；其他环境需先调研再追加环境适配 |
| AI 开发环境 | AI 工具及其上下文入口、权限、指令、命令、Hook、MCP、Agent、Human 确认方式等承载条件的具体组合 | 是环境的一类具体语境，不替代 00 中“开发环境”构成要素；不得写作平台或平台能力 |
| 环境实体 | 具体环境中可被定位、配置、调用或维护的文件、规则、Skill、Agent、Hook、命令、页面、CI 配置或环境入口 | 只能作为环境适配或适配措施的一部分 |
| 环境能力 | 具体环境中可被 LDVH 用来落实能力保障的单项入口、机制、工具或运行面 | 环境能力是单项能力，不是环境能力清单；能力边界由 `docs/specs/04.03-环境适配规范.md` 规定；环境能力不得反向成为 LDVH 全局要求 |
| 适配边界 | 某类环境能力适合承载什么适配措施、不适合承载什么适配措施，以及何时需要组合其他能力或降级处理的边界 | 具体规则由 `docs/specs/04.03-环境适配规范.md` 规定 |
| 适配检查 | 用于检查环境适配声明是否真实、可定位、可验证、未越界且能追溯到权威事实源的检查方式 | 没有适配检查或等价检查的适配声明，只能作为待确认、适配降级或参考处理 |
| 适配降级 | 环境能力不足、适配措施缺失、适配检查不可用或稳定触发无法保证时，记录的替代检查、人工确认、后续任务或残留风险处理方式 | 不得用于降低正式规范要求；应说明降级原因、残留风险和后续补齐位置 |
| 工作区级入口 | 用户当前开发环境或工作区配置中用于引导 AI 进入 LDVH 管理入口、管辖项目配置或 LDVH 事实源的薄引用 | 属于用户工作区，不随 LDVH 项目提交；初始化时只应写入醒目的单句引用或等价薄入口 |
| 项目级入口 | LDVH 自身项目仓库内用于说明本项目如何被当前环境治理的薄入口、环境规则文件、项目指令或等价入口 | 默认只用于 LDVH 自身项目；管辖项目一般不创建项目级入口，避免和用户项目原有入口冲突 |
| AI 统一入口 | LDVH 自身项目根目录 LDVH-AI-ENTRY.md，用于向 AI 提供最小读取顺序、场景路由、STOP 点和权威路径提示的适配措施 | 不是 docs/specs 正式规范，不替代管辖项目配置、环境能力清单、42 落地与检查报告、工作对象事实源或 Code 验证；具体规则由 `docs/specs/04.02-LDVH能力保障规范.md` 规定 |
| LDVH 项目事实源 | 管辖项目中由 LDVH 创建、维护或消费的命名空间事实源、工作对象实例或受控记录 | 可以在管辖项目内创建；不得伪装成用户项目原有入口或替代用户项目业务文件 |
| 项目接入说明 | 解释某个管辖项目如何通过工作区级入口、管辖项目配置、`ldvh-base/` 或 `docs/` 进入 LDVH 治理的叙述性说明 | 不是工作区根目录管辖项目清单；不得承载初始化状态、落地状态、检查状态、环境能力核验、适配措施正文或环境入口正文 |
| 能力缺口 | LDVH 尚未提供能力完整保障某项规范落地要求，或能力存在但缺少必要配置、入口、Code、测试、权限或 Human Gate | 不得通过改低正式规范要求解决，应记录能力建设需求、适配降级或待补齐事项 |
| 环境缺口 | 当前环境不能完整承载某项能力保障，或缺少必要环境能力、配置、入口、权限、检查方式或证据 | 不得写成 LDVH 能力缺口；应在环境适配中记录适配降级或待补齐事项 |
| 漂移 | 适配措施、环境适配或自动触发方式与 docs/specs 正式规范不一致，或规范已变更但适配措施未同步 | 漂移检查结果不是最终事实源，稳定结论需要回写 |
| LDVH 运行纪律 | LDVH 自行设定、跨环境适配措施时需要遵守的运行纪律，例如薄入口、LDVH 自建 Skill 命名和 Skill 触发边界 | 由 `docs/specs/04.02-LDVH能力保障规范.md` 规定 |
| 个人环境特别要求 | 当前个人、维护者或当前执行环境中的特殊命令、路径或环境约定 | 由 `docs/specs/04.05-个人环境特别要求规范.md` 登记；不自动推广为 LDVH 通用规则 |
| 启用 | 将已登记的 LDVH 落地特别要求或个人落地特别要求应用到特定环境、项目、适配措施、Code 配置或 Human 选择中的动作 | 未启用事项不得被 AI 当成当前项目规则执行 |
| 薄入口 | 适配措施中的入口内容只承担发现、触发、导航、提醒和交还职责，不复制完整规范正文，不维护第二事实源 | 不等于信息不足；细则应回到正式规范、环境能力清单、管辖项目配置、42 流程、Code 实现或其他权威位置读取 |

规范落地要求定义要达成什么，能力保障定义 LDVH 提供什么组合保障，保障机制定义组合中的具体机制，环境适配定义机制如何落到当前环境，适配措施定义落地后形成的入口、配置、命令、页面或降级记录。

规范落地要求类型包括上位约束承接要求、入口可见要求、流程复用要求、子 Agent 思考要求、确定性执行要求、Human 交互要求和生命周期触发要求。各类型的规则以 `docs/specs/04.01-规范落地声明规范.md` 为准。

## 8. 构成要素与环境能力术语

| 术语 | 定义 | 边界 |
|---|---|---|
| 开发环境 | LDVH 五类构成要素之一，提供 AI 与 Human 实际执行工作的环境能力 | 开发环境是构成要素类型，不等于某个具体环境实例；不是最终事实源 |
| 工作模型 | LDVH 五类构成要素之一，用于承载项目工作事实、对象字段、状态和验收规则 | 通用规则由 `docs/specs/05-工作模型基础规范.md` 承载 |
| 工作对象 | 依据工作模型创建、维护和检查的具体事实实例，例如 WorkArea、TaskPlan、Task、SubTask、ADR、Memo、Change 或 Pitfall | 不等同于普通 Markdown 文档；具体对象字段和状态由对应工作模型规范定义；管辖项目配置不是工作对象 |
| 工作字段 | 工作模型或工作对象中用于承载特定事实、关系、状态、证据或引用的字段 | 字段命名、类型和内容格式由工作模型规范和 `docs/specs/05.01-工作字段内容格式规范.md` 定义 |
| 字段内容格式 | 工作字段中用于组织叙述、清单、证据、决策、引用或结构化值的内容表达格式 | Narrative、Checklist、Evidence、Decision 等是内容格式，不是工作对象；不得把 Evidence 或 Decision 直接当作对象实例 |
| 对象状态 | 单个工作对象实例在其状态机中的状态 | 只适用于具备对象状态机的工作对象；不得泛化为集合状态、检查过程状态或派生状态 |
| 集合状态 | 集合、索引或清单对一组对象、文档或条目的汇总状态 | 不等同于单个对象状态；不得直接驱动对象状态流转 |
| 检查过程状态 | 一次检查、校验、验证或审计过程中的临时执行状态 | 不是长期事实源状态，稳定结论需要回写到对应权威位置 |
| 派生状态 | 由工具、Web、报告或查询结果根据事实源计算出的展示状态 | 不是事实源本体；不得替代对象状态、集合状态或正式规范判断 |
| Change commit | 由 Git commit 承载的 Change 事实实例或变更记录 | Change 是工作模型语境，事实实例优先由 Git commit 承载；不得把 Change 误写成独立 YAML 对象 |
| 工作流程 | LDVH 五类构成要素之一，用于约束 AI 如何识别场景、读取事实、执行、验证、回写和暂停 | 通用规则由 `docs/specs/06-工作流程基础规范.md` 承载 |
| Code | LDVH 五类构成要素之一，用于确定性执行、解析、校验、聚合、测试、上下文压缩和受控写入 | 工具、脚本、校验器和命令入口都是 Code 的实现形态 |
| Web | LDVH 五类构成要素之一，用于 Human-facing 展示、确认、授权、验收和受控轻写入 | Web 页面状态不是最终事实源 |
| 受控写入 | 由正式规范、工作流程、Code 校验、权限边界或 Human Gate 约束的写入动作 | 不等于任意文件修改；高影响写入、状态流转、长期配置和权限扩大必须遵守对应 Human Gate |
| 受控轻写入 | Web 在规范授权范围内，对已定义字段、状态或人工标记执行的有限写入 | 不是开放式事实源编辑；写入入口、校验规则和事实源回写仍必须由对应 Code 能力或正式规范约束 |
| Rules / Instructions | 环境中用于入口可见、硬约束摘要、事实源边界提示或项目入口提示的能力或实体 | 只是适配措施，不是最终规范事实源 |
| Skill | 环境中用于复用多步骤流程、标准化输入输出或受控检查步骤的能力或实体 | 不负责调度子 Agent；需要稳定触发时应组合 Hook、CI、自动运行或降级检查 |
| LDVH 自建 Skill | 由 LDVH 为承接自身工作流程、治理动作、检查步骤或适配措施而创建或要求维护的 Skill | 不等于管辖项目业务 Skill、第三方环境 Skill 或一次性实验 Skill |
| LDVH 包装 Skill | LDVH 为封装、调用或约束第三方能力、项目能力或既有流程而维护的 Skill | 不改变被包装能力的事实源边界，也不得绕过 LDVH 自建 Skill 的正文边界要求 |
| Agent | 环境中用于独立上下文、专项视角、并行审查或权限边界差异的能力或实体 | Agent 输出必须回到主控或 Human，稳定结论回写后才生效 |
| Hook / 自动触发 | 环境中用于生命周期事件触发、提醒、阻断、记录或自动检查的能力或实体 | 不定义规范正文或工作流程本身 |
| MCP / 模型上下文协议 | 环境中用于向 AI 提供外部工具、数据源或上下文扩展的协议和连接能力 | MCP 是环境能力类型之一，不是 LDVH 构成要素；MCP Server 输出不是最终事实源；LDVH 不自建 MCP Server 作为核心能力 |

Tools 和 PyTools 不作为核心构成要素或独立机制术语。需要指向具体实现时，优先使用 Code、工具、脚本、校验器、命令入口或 `tools/` 目录实现。

## 9. 工作流程、运行闭环、初始化、审计与检查术语

| 术语 | 定义 | 边界 |
|---|---|---|
| 运行闭环 | LDVH 从 WorkArea、TaskPlan、Execute、Verify、Record 到 Learn 的端到端质量闭环 | 不等同于单个工作流程 |
| 具体工作流程 | 40-59 区段中单一行动或行动族的执行规范，约束 Context、Scenario、Gate、执行、验证、回写和暂停 | 具体工作流程是工作流程构成要素在运行闭环中的组成单元 |
| 行动 | 由工作流程控制的一次执行或行动类别 | 不等同于工作流程全文、普通命令或任意步骤 |
| Scenario 识别条件 | 工作流程用于判断某个行动是否进入的场景条件 | 不应由 Rules / Instructions 维护完整正文 |
| 适用场景 | 文档、能力、入口或规则适合使用的普通范围说明 | 不等同于工作流程中的 Scenario 识别条件 |
| 步骤 | 具体工作流程内部的顺序动作 | 不等同于阶段标签、状态机或事实源状态 |
| 阶段标签 | 用于标识 Entry、Plan、Apply、Verify、Review、Recheck 等流程阶段的标签 | 不是状态机，不得作为对象状态或事实源状态使用 |
| Apply | 工作流程中执行已授权行动、写入、修复、生成或落地动作的阶段标签 | 中文名暂不固定；不得将未授权修复、危险写入或高影响变更直接并入 Apply |
| Verify | 工作流程中生成验证证据、证明结果成立或确认执行结果的阶段标签 | 不等同于 Human 已审核，也不等同于事实源已回写 |
| Review | 工作流程中审阅结果、证据、风险和建议的阶段标签 | 不等同于 Verify 或 Recheck；若产生批准、否决、放行或关闭权限，应进入审核或 Human Gate 语境 |
| Recheck | 修复、回写、复验或复审后再次检查的阶段标签 | 不替代 Verify、Review 或 Human Gate |
| Gate | 工作流程中的暂停、进入、退出、确认或授权条件 | Human Gate 是高影响场景中的人类确认机制 |
| Human Gate 记录 | Human Gate 触发时保留的确认人、确认范围、风险说明、影响范围和执行前暂停证据 | 不是普通聊天摘要；不能被工具输出或 Web 页面状态替代 |
| LDVH落地 | 将 LDVH 规范体系真正转化为项目可用实践的落地环节 | 不单独作为长期状态登记；具体执行与检查由 42 LDVH落地与检查承接 |
| 环境确认 | 在 42 LDVH落地与检查中现场确认当前环境、权限、工具、入口、适配措施和适配降级的动作 | 不是长期状态登记；结论默认只进入当前落地与检查报告，不创建状态文档 |
| LDVH落地与检查 | 42 统一工作流程，先只读检查当前 LDVH 落地链路并输出缺口，再经 Human 授权逐项落地、复检并给出当前落地与检查报告 | 报告默认只在当前对话或调用结果中输出；不创建初始化状态、落地状态、检查状态或过程报告文档 |
| 当前落地与检查报告 | 42 在当前执行过程中输出的落地链路检查、缺口、候选行动、适配降级、验证和回写建议报告 | 不是长期状态文档，不替代工作对象事实源；不推荐写作当前过程报告、检查报告、42 过程报告或首次检查报告 |
| 检查 | 依据规范、工作对象、工作流程或 Code 契约，对文档、实例、行动、输出或适配措施进行符合性判断 | 检查结果不是最终事实源，稳定结论需要回写 |
| 校验 | 由 Code、工具、测试或 CI 执行的机械性规则判断 | 不替代人工检查、Human Gate 或语义验证 |
| 验证 | 通过测试结果、命令输出、证据链、人工确认或复现步骤证明某个结果成立 | 不等同于普通检查清单，也不等同于 Human 已审核或事实源已回写 |
| 审计 | 对规范、事实源、工作对象、流程、适配措施或运行闭环进行系统性、周期性或跨对象的合规审查 | 不应泛用为普通检查、校验或验证 |
| 审阅 | 阅读结果、证据、风险和建议并形成判断或意见的动作 | 不自带批准、否决、放行或验收含义 |
| 审核 | 带有批准、否决、放行、验收、关闭或授权含义的审查动作 | 高影响审核应进入 Human Gate 或对应授权流程 |
| 写入 | 对文件、字段、状态、配置或记录执行修改的动作 | 不自动表示稳定事实已进入权威事实源；应按写入对象判断是否需要受控写入或 Human Gate |
| 回写 | 将经过吸收、验证或确认的稳定结论写回对应权威事实源的动作 | 不等同于普通写入；推荐在需要强调事实源归属时写作事实源回写 |
| 事实源回写 | 将稳定事实写入正式规范、工作对象、Code、Web、ADR、Task、Memo 或其他指定权威位置的回写动作 | 不得由缓存、页面状态、聊天摘要或工具临时输出替代 |

“工作闭环”不作为推荐术语；优先使用“运行闭环”。

## 10. 非 LDVH 来源内容与最佳实践术语

| 术语 | 定义 | 边界 |
|---|---|---|
| 非 LDVH 来源内容 | 不是由 LDVH 正式规范、LDVH 自建 Code、LDVH 自建 Skill、LDVH 初始化产物或已被 LDVH 接管的事实源直接提供的内容、能力、资产或产物 | 可被读取、参考、调用或转换，但不能未经接管直接生效 |
| 已接管 | 非 LDVH 来源内容已经完成来源识别、用途判断、影响范围判断、主控审查、必要验证、事实源归属和必要 Human Gate | 已接管不等于成为强制规则；是否生效取决于写入的权威位置 |
| 未接管 | 非 LDVH 来源内容尚未完成接管要求，只能作为候选输入、参考材料、临时能力或待验证产物 | 不得直接作为 LDVH 规则、事实、状态、证据或验收结果 |
| 主控接管 | LDVH 主控对外部输入或外部能力输出进行审查、筛选、验证、归属、回写、降级或废弃的治理动作 | 外部能力不得替代主控进行事实源归属、最终验收、跨流程调度或 Human Gate 决策 |
| 信任等级 | 非 LDVH 来源内容在当前接管状态下可被如何使用的分级判断 | 正式等级和准入规则尚未进入 docs/specs 正文区；未吸收前不得作为 LDVH 规则执行 |
| 最佳实践 | 经过实践验证、可复用但不直接产生强制规则的最佳做法、案例或经验入口 | 不能定义新的工作模型、工作流程、字段、状态机、事实源、Human Gate 或 Code 硬规则 |
| 实践升级 | 将最佳实践中反复稳定出现的经验，按内容性质吸收到正式规范、工作对象、Code、Web、测试或其他权威位置的治理动作 | 升级后是否具备强制效力，取决于被吸收的权威位置 |
| 第三方 Skill 接管落地选项 | 第三方 Skill、环境 Skill、外部 Skill 或类似外部可复用 AI 能力作为默认可用接管路径时的启用、取消、降级和重新启用选项 | 默认启用，但用户可以通过 AI 请求取消；取消不影响 11 的非 LDVH 来源内容治理规则 |

## 11. 中文术语定语规则

中文“规则”“技能”“代理”“智能体”“工具”“程序”“展示”“机制”等词不得裸用，除非上下文已经通过标题、表格字段或段落首句明确限定其语义。

推荐用法如下：

| 场景 | 推荐用语 | 避免裸用 |
|---|---|---|
| docs/specs 中的稳定条款 | 正式规范、规范规则、规范要求 | 规则 |
| 工作模型字段、状态、验收、检查 | 字段规则、状态规则、验收规则、对象检查 | 规则 |
| 工作流程 Context、Scenario、Gate、执行、回写、证据 | 行动规则、Scenario 识别条件、Gate 条件、回写要求 | 规则、触发规则 |
| 检查、校验、验证、审计 | 检查方式、校验命令、验证证据、审计范围 | 检查、校验、验证、审计裸用且无上下文限定 |
| 写入和回写 | 写入动作、受控写入、事实源回写、回写位置 | 写入、回写裸用且无事实源或权限限定 |
| 审阅和审核 | 审阅结果、审核结论、Human Gate 审核 | Review、审核、审阅混用 |
| 证据 | 验证证据、关闭证据、Human Gate 记录、Change commit 证据 | 证据裸用且无来源或用途限定 |
| 环境入口约束 | Rules / Instructions 入口、入口摘要、硬约束摘要 | 规则 |
| 普通能力说明 | 能力、功能、流程、方法 | 技能 |
| AI 泛称 | AI 执行者、AI 代理能力、子 Agent | 代理、智能体 |
| 确定性实现 | Code 实现、工具、脚本、校验器、命令入口 | 程序 |
| Web 能力 | Web、Human-facing 页面、信息同步、受控交互 | 展示 |
| 环境适配 | 环境能力、环境实体、适配措施 | 机制 |

## 12. 不推荐表达与替代写法

本节用于帮助 AI 识别不推荐表达，并改写为当前正式术语。历史文件名、路径引用或迁移说明中保留的不推荐表达只作为兼容信息；正文语义仍按推荐术语理解。

| 不推荐表达 | 推荐处理 | 说明 |
|---|---|---|
| 工作闭环 | 运行闭环 | 优先使用运行闭环 |
| 平台 | 环境 | 正式模型使用环境；平台只可作为外部产品、历史资料或文件名兼容信息 |
| 平台能力 | 环境能力 | 避免把外部产品能力误写成 LDVH 全局能力 |
| 平台适配清单 | 环境适配规范 / 环境适配措施实践 / 旧环境清单迁移输入 | 当前 04 系列已拆分为 04.03 规范层和 04.04 实践层；历史清单只作迁移输入 |
| 能力项 | 环境能力 / 适配项 / 适配措施 | 根据上下文区分环境客观能力、适配卡片条目和具体适配措施 |
| 能力支持状态 | 适配状态 / 适配措施状态 / 检查过程状态 | 不得把固定分类或现场判断写成长期状态机 |
| 承接项 | 适配项 | 当前 04 系列使用适配口径，不再以承接项作为正式术语 |

## 13. 固定机制子文档边界

固定机制子文档指围绕工作模型或工作流程默认拆出的 `NN.01` 至 `NN.06` 文件，例如 Rules、Skill、Agent、Tools、Web 和 Contract 文件。

固定机制子文档不构成工作模型或工作流程的默认完整性要求。机制相关内容应按内容性质进入主规范、规范落地要求、环境适配、Code 规范、Web 规范、工作流程规范、结构化契约或待补齐事项。

## 14. 术语变更治理

术语变更治理用于防止局部文档隐式改写术语含义。

新增、改名、废止或改变本文定义的术语时，应先判断：

1. 是否影响 00 的五类构成要素、事实源原则或运行闭环标准；
2. 是否影响 01 的目录分区或编号分区；
3. 是否影响 03 的文档结构、引用或索引文档规则；
4. 是否影响 04 的规范落地要求、能力保障、保障机制、环境适配、适配措施或 AI 统一入口；
5. 是否影响 07 的 Code 实现边界；
6. 是否需要同步工作模型、工作流程、Web、事实源、运行闭环测试、非 LDVH 来源内容治理、第三方 Skill 接管落地选项或最佳实践规范；
7. 是否需要 Human Gate。

## 16. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 改变五类构成要素的术语边界；
2. 将环境能力、环境实体或适配措施提升为最终事实源；
3. 将环境确认等同于LDVH落地；
4. 改变规范落地要求、能力保障、保障机制、环境适配、适配措施或 AI 统一入口之间的术语关系；
5. 改变 Code、工具、脚本、校验器或 `tools/` 目录实现之间的术语边界；
6. 将固定机制子文档恢复为默认完整性要求；
7. 长期保留不推荐表达对照而不安排收敛；
8. 允许其他规范并行维护本文已定义术语的权威定义。

术语检查至少包括：

| 检查项 | 标准 |
|---|---|
| 上位来源 | 00 是本文的上位概念来源，本文未反向改写 00，00 未以本文作为自身规范依据 |
| 术语归口 | 术语定义归口本文，其他规范只说明应用规则 |
| LDVH落地 | LDVH落地未被环境确认替代 |
| 环境适配 | 环境能力、环境实体和适配措施未混同 |
| AI 统一入口 | AI 统一入口被视为适配措施，不是正式规范或最终事实源 |
| 构成要素 | 开发环境、工作模型、工作流程、Code、Web 未互相替代 |
| 中文定语 | 高风险中文裸词已有上下文限定或改为推荐用语 |
| 不推荐表达 | 不推荐表达已有替代写法 |
