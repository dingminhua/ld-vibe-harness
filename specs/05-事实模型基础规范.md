## 1. 价值判断

本文存在的价值，是让 AI 能把任务、决策、经验、风险、证据和缺口放到稳定事实对象中，而不是留在聊天、工具输出或临时记忆里漂移。

事实模型主要服务 V1、V2、V3、V7 和 V9：它通过对象类型、字段、状态、关系和证据边界帮助 AI 定位事实入口、理解当前状态、判断对象化价值、按格式回写稳定事实，并把可复用经验、反复问题和体系缺口沉淀到可承接对象中。它不替代事实源整体，而是在 03 的事实源边界内组织需要对象化、状态化或证据化管理的事实。

## 2. 权威依据

本文承接 `specs/00-理念与构成.md` 的事实模型构成要素定位、`specs/01-保障与衔接.md` 的缺口分流、`specs/02-AI行为规范.md` 的诊断处理责任、`specs/03-事实源与Git溯源规范.md` 的事实源边界，以及 `specs/04-Specs基础规范.md` 的结构规则。

若事实模型规则与 03 的事实源边界冲突，以 03 为准。事实对象业务状态必须同时服从 04 的状态归口原则和本文的对象规则；若事实对象状态或字段规则需要 Human 取舍，应进入 Human Gate。

## 3. 归口边界

本文归口定义事实模型和事实对象的父层规则：什么内容需要对象化，事实实例与规范规则如何分开，字段、状态、证据和关系应具备哪些共同边界，过程输出与证据如何稳定承接。

本文不归口定义具体事实对象的完整字段表、完整状态机、CLI、Web 表单或测试夹具。Spark、WorkCase、ADR、Pitfall 和 Study 已分别由 `specs/20-Spark-火花.md`、`specs/21-WorkCase-工作项.md`、`specs/22-ADR-决策.md`、`specs/23-Pitfall-踩坑经验.md`、`specs/24-Study-研究报告.md` 承接成员规范；真实实例位于 `ldvh-base/` 并由 Code/tests 校验字段 schema、状态和关系。

## 4. 适用范围

本文适用于：

1. 后续事实对象成员规范；
2. 需要对象化管理的任务、决策、经验、风险、研究、验证证据和缺口；
3. AI、行动模板、Code、Web 和测试对事实对象的读取、回写、展示和验证；
4. V2 20-24 事实对象和 `02.Att.*` 的迁移判断。

## 5. 事实模型与事实实例

事实模型定义某类事实的对象边界、准入条件、状态、字段、证据、关系和验证规则。事实实例承载某个具体项目或行动中的具体事实。

事实模型和事实实例必须分开：

| 对象 | 职责 | 不得做 |
|---|---|---|
| 事实模型规范 | 定义对象规则、字段含义、状态边界、证据要求和验证口径 | 不承载某个实例的当前状态 |
| 事实实例 | 承载具体事实、状态、证据、关系和关闭材料 | 不重新定义对象规则或 Human Gate |
| Code/Web 派生视图 | 读取、校验、聚合和展示事实 | 不维护第二事实源 |

事实实例只有位于 03 允许的 Git 可追踪事实源位置，才可能成为稳定事实。实例字段、状态和证据不能只存在测试夹具、Web 缓存或 Code 输出中。

事实实例不得定义、重写或授权任何事实模型规则、字段闭集、状态机、验证口径或 Human Gate。测试夹具不得被写成事实实例；它只能提供验证输入或负例样例。已从工作树删除的迁移材料不得被写成事实实例；历史迁移记录只可在审计追溯、争议复核或历史取证时查询，不作为当前 V3 规则、实例字段或验收依据。

## 6. 事实对象准入与分流

内容满足以下条件之一时，可以考虑进入事实模型或既有事实对象：

1. 需要独立追踪状态；
2. 需要可验证的完成标准、证据或关闭判断；
3. 需要长期引用、关联、回写或复盘；
4. 不结构化会导致 AI 后续无法定位、接续或判断；
5. 需要被 Code 校验、Web 展示或测试回归。

不满足准入条件的内容应分流：

| 内容性质 | 分流 |
|---|---|
| 临时判断 | 保留在当前上下文，不写成稳定事实 |
| 规则缺口 | 回到对应 specs 或待补齐事项 |
| 行动步骤 | 回到 06 行动模板或当前执行计划 |
| 长期决策 | 后续 ADR 成员规范或当前决策事实对象承载位置 |
| 可复用经验 | 后续 Pitfall 成员规范或经验事实对象承载位置 |
| 研究材料 | 后续 Study 成员规范、来源材料或研究事实对象承载位置 |
| 未成型想法 | 后续 Spark 成员规范或候选缺口 |

AI 不得因为内容重要、方便展示或容易解析，就绕过准入条件新增事实对象。

准入判断必须同时说明对象化价值和预期减少的 AI 负担；无法说明时，应留在当前上下文、迁移材料或待补齐事项，不得直接新增事实对象。

## 7. 字段、状态与证据边界

字段用于表达对象的稳定属性；状态用于表达对象生命周期位置；证据用于支持判断、验证、关闭或溯源。

本文只授权事实源对象的业务状态。事实对象状态必须由对应成员规范定义闭集，并写入 03 允许的 Git 可追踪事实源实例；它不得由 Code 输出、Web 展示、测试夹具、运行时 receipt、环境审计或安装检测结果反向定义。

Specs / attachments 自身生命周期状态归 04 及其附件承接，不归本文。除 specs / attachments 生命周期状态和事实对象业务状态外，其它 `status`、`state` 或“状态”只能作为当前运行、验证、审计、交互、交还或展示输出，不得进入事实模型冒充业务状态。

字段、状态和证据必须满足：

1. 能回指对象规则或上位规范；
2. 语义稳定，不因 Web 标签、测试夹具或 Code 实现便利而改变；
3. 变更有事实源回写和 Git 溯源；
4. 验证证据能说明来源、范围和结论；
5. Human Gate 结果不得由字段默认值、测试通过或 Web 按钮替代。
6. 字段名不得与 `specs/attachments/04.Att.06-术语表.md` 中的术语含义冲突；确需复用术语时，必须说明字段语义和术语边界。

字段注册表的列结构、列闭集和消费元数据由 `specs/attachments/05.Att.01-字段注册表结构.md` 承接；该附件不得表达具体事实模型字段存在性、必填性、状态条件、关闭条件或完整 schema。

V2 `02.Att.*`、20-24 成员文件和事实对象 CLI 仅保留为历史审计语境，不作为当前 V3 事实模型的后续来源、验收依据或删除阻断。20-24 成员规范已进入 V3；管辖项目配置和事实源入口边界已由 `specs/10-安装与配置规范.md` 承接；真实 `ldvh-base/` 实例已落在事实源中，字段级 Code/tests schema 已建立。具体成员完整字段表、成员模板、完整状态机和 WorkCase `orchestration` 长表后续如需补充，必须作为 V3-owned 字段契约、附件、Code/tests schema 或明确 WorkCase 推进。

## 8. 保障措施

| 保障要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 对象准入要求 | 新增事实对象前必须说明对象化价值和减少的 AI 负担 | 本文、00 价值门、02 AI 行为 | 模型治理 | 新增或恢复事实对象类型时 |
| 实例边界要求 | 事实实例不得重写模型规则 | 本文、03 事实源边界、Code 校验 | 事实源治理 | 写入或迁移事实实例时 |
| 证据分流要求 | warning、follow-up、unverifiable 和长期证据必须有承接位置 | 01 缺口分流、02 诊断处理、06 行动模板 | 缺口治理 | 出现过程输出或诊断时 |
| 字段状态同步要求 | 字段、状态和证据规则变化后应同步 Code、Web 和 tests | 07、08、09 | 生命周期同步 | 修改对象规则或迁移成员规范时 |
| 状态归口要求 | 事实对象业务状态必须由成员规范定义闭集并落入事实源，运行时输出不得反向定义对象状态 | 本文、03、04、20-24 | 状态治理 | 新增或修改事实对象状态、迁移实例或消费 Code/Web 输出时 |

## 9. 验证方法

验证本文规则时应检查：

| 检查类别 | 检查内容 | 不满足时 |
|---|---|---|
| 准入检查 | 对象化是否减少 AI 负担，并满足状态、证据、引用或回写需求 | 保留为当前上下文、待补齐事项或候选 |
| 边界检查 | 模型规则和实例事实是否分开 | 回到模型规范或事实实例修正 |
| 证据检查 | 证据是否能回指来源、范围和验证方式 | 标为 unverifiable 或回写缺口 |
| 同步检查 | 字段、状态和证据变化是否同步 Code/Web/tests | 记录对应构成要素缺口 |
| 状态归口检查 | 事实对象状态是否由成员规范定义并写入事实源，Code/Web/test/runtime 输出是否没有反向定义业务状态 | 停止回写并回到 04 状态归口原则或成员规范 |

## 10. Human Gate

以下情况必须进入 Human Gate：

1. 新增、删除、恢复或重命名事实对象类型；
2. 改变事实对象状态机、关闭条件、关键字段或 Human Gate 字段；
3. 接受事实实例无法回写、无法溯源或无法验证的长期风险；
4. 将测试夹具、Web 状态、Code 输出或迁移材料升级为事实实例；
5. 批量迁移 V2 20-24 事实对象成员。

## 11. Stop Conditions

出现以下情况时，AI 必须暂停：

1. 无法判断内容是否应对象化；
2. 事实实例正在反向定义对象规则；
3. 字段或状态规则只有 Code/Web/tests 表达、没有规范承载；实例事实或证据、实例状态只有 Code/Web/tests/runtime 输出表达、没有事实对象或 Git 文件事实源承载；
4. blocker 被写成普通 follow-up 或长期缺口被静默；
5. 需要恢复旧 TaskPlan、Task、SubTask 或其它 V2 清退对象作为当前事实对象。
