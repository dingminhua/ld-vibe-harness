# 多角色思考 — Skill 边界实践

> 创建日期：2026-05-31
> 定位：多角色思考行动模型的附件型实践子文档，说明多角色思考不需要创建 LDVH 版 Skill，以及 Skill 不承载本文执行流程的边界
> 上位依据：`specs/41-multi-role-thinking-多角色思考.md`
> 相关规范：`specs/04.02-Skill机制规范.md`、`specs/04-LDVH-AI协作规范.md`

---

## 一、本文定位

本文是 `specs/41-multi-role-thinking-多角色思考.md` 的附件型实践子文档（编号 41.02），承接 Skill 边界实践。本文不是独立行动模型，不得重新定义多角色思考的行动定位、准入条件、Context、Scenario、Gate、执行流程、事实源回写、证据留存或 Human Gate。发生冲突时，以 41 主文档和上位基础规范为准。

---

## 二、不创建 LDVH 版 Skill 的理由

多角色思考不需要创建 LDVH 版 Skill，理由如下：

1. **触发判断由 Rules 承接**：进入多角色思考的触发判断由 L0 工作区规则入口摘要提醒，AI 读取 41 主文档后按流程执行，不需要 Skill 作为入口；
2. **执行流程由规范承载**：多角色思考的完整执行流程、角色选择、输出格式和 Human Gate 判断由 41 主文档和 41.06-Contract.md 承载，不需要 Skill 重复承载；
3. **两种模式均不需要 Skill**：主上下文轻量模式由 AI 在主上下文中按角色分析；多系统子 Agent 模式由主控通过 Task 工具启动子 Agent 并注入角色参数，两种模式均不依赖 Skill 机制；
4. **避免体系膨胀**：创建 Skill 会增加维护成本但不提升可控性，违反价值与要素审查原则。

---

## 三、Skill 不承载的内容

Skill 不得承载以下多角色思考内容：

1. 角色定义或默认角色集合；
2. 角色选择规则；
3. 执行流程步骤；
4. 输出格式模板；
5. Human Gate 条款；
6. 事实源回写规则；
7. 多系统子 Agent 调度规则。

---

## 四、Skill 可建议但不执行的边界

如果项目中存在其他 Skill，且该 Skill 的执行过程中发现需要多角色思考，该 Skill 可以：

1. 建议用户或主控判断是否进入多角色思考；
2. 在输出中标注"建议进入多角色思考"及触发原因；
3. 不自行调度多角色思考执行流程；
4. 不自行选择角色或启动子 Agent。

---

## 五、检查项

检查 Skill 边界是否合规时，应确认：

1. 是否未创建多角色思考 LDVH 版 Skill；
2. 现有 Skill 是否未承载多角色思考的执行流程、角色定义或 Human Gate 条款；
3. 现有 Skill 建议进入多角色思考时，是否只做建议而不自行执行。
