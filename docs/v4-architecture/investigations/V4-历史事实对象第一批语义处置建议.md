## 1. 判断口径

V3 的 `closed`、`pending` 或其它历史状态不直接决定 V4 处置。首轮记录了每项与当前 V4 的覆盖关系，但 Human 随后明确：最终处置必须以它对 LDVH 未来是否具有明确净价值为主，而不是以旧对象完成、V4 存在部分等价能力或旧路线变化为主。

1. **已由 V4 承接**：当前 V4 规则、能力或验证已经承担其仍有价值的责任；不创建同题 V4 实例；
2. **仅保留 archive**：该对象作为旧执行载体、研究证据或已完成工作保留；关联问题是否仍有价值，由下一批 Spark/Study 单独判断；
3. **已经过时**：对象目标依赖已被 V4 明确放弃的 V3 架构或版本迁移前提；只保留历史回读价值。

因此，本文件中的“已由 V4 承接”“仅保留 archive”“已经过时”均降为覆盖核对信号，须按 `V4-历史事实对象选择性吸收决定.md` 的未来价值四问重新确认后，才形成最终处置。已明确需要优先复评的对象是 `workcase-0017` 与 `workcase-0018`：前者可能保留为跨环境 payload/target 完整性 Spark，后者可能保留为安装验收与 doctor/bootstrap Spark。

V4 WorkCase 仍必须由 Human 明确选择当前目标、范围和成功标准后才可建立；V3 的旧 `orchestration`、阶段和审核记录不得整体迁入。

当前 V4 对照来源为：WorkCase 生命周期与分流见 `specs/21-WorkCase-工作项.md`；事实判定、受控创建和生命周期处置见 `specs/05-事实模型基础规范.md` 与 31/32 行动模板；Git 提交见 `specs/03-事实源与信息溯源规范.md` §9 与 `specs/30-Git提交行动模板.md`；环境接入见 `specs/09-环境接入规范.md` 与 33 行动模板；本机 Codex 已观察范围见 `active/V4-Codex环境接入-安装与真实验证记录.md`。
