路径归一化原则：

| 步骤 | 处理 | 说明 |
|---|---|---|
| 1 | 解析真实路径 | 消除符号链接、`.` 和 `..`，结果应与 `os.path.realpath` 或等价系统调用一致 |
| 2 | 分隔符统一 | 将所有分隔符统一为 POSIX 风格 `/` |
| 3 | 大小写统一 | macOS 和 Windows 统一转为小写；Linux 保留原始大小写但建议也统一为小写以便跨平台配置共享 |
| 4 | 尾部分隔符去除 | 去除路径末尾的 `/`（根目录 `/` 除外） |

跨平台差异：

| 平台 | 差异处理 | 说明 |
|---|---|---|
| macOS | 大小写不敏感，统一转为小写 | APFS 默认不敏感，归一化后以小写比较 |
| Linux | 大小写敏感，但仍建议统一为小写后再比较 | 配置可能在多平台间共享 |
| Windows | drive letter 统一为小写，反斜杠转为正斜杠，去除尾部反斜杠 | 例如 `C:\Projects\` 归一化为 `c:/projects` |

管辖项目命中条件：

| 命中方式 | 条件 | 优先级 |
|---|---|---|
| 精确匹配 | 与管辖项目 `normalized_path` 完全一致 | 高 |
| 前缀匹配 | 是管辖项目 `normalized_path` 的子路径（即以项目路径为前缀） | 中 |
| Git common-dir | 通过 `git.common_dir` 匹配 worktree 身份 | 低（仅作为路径匹配的补充） |

前缀匹配：

| 条件 | 说明 |
|---|---|
| 前缀相同 | target 的归一化路径以管辖项目的归一化路径为前缀 |
| 边界有效 | 紧随前缀的字符是路径分隔符或字符串结尾 |

路径相等判定：

| 顺序 | 判定 |
|---|---|
| 1 | 双方各自通过 `normalize_path` 归一化 |
| 2 | 归一化后的字符串逐字符比较 |
| 3 | 不依赖文件系统存在性；路径不存在时仍保留明确归一化结果 |

与 `git.common_dir` 的关系：

| 场景 | 处理 |
|---|---|
| target 或 cwd 位于 Git worktree 子目录 | 通过 `git rev-parse --git-common-dir` 获取 common-dir，与配置中的 `git.common_dir` 比较 |
| 路径前缀匹配失败但 Git common-dir 匹配 | 输出 `governed_via=git.common_dir` 并记录到 resolution 证据 |
| path 和 `git.common_dir` 都不匹配 | 输出 `status=not_governed` 或 `ambiguous` |

规范化函数契约：

| 契约 | 要求 |
|---|---|
| 函数签名 | `normalize_path(path: str) -> str` |
| 输入 | 任意操作系统的文件系统路径 |
| 输出 | POSIX 风格分隔符、已解析真实路径、大小写已统一、无尾部分隔符的字符串 |
| 幂等性 | `normalize_path(normalize_path(p)) == normalize_path(p)` |
| 可测试 | 必须有对应的单元测试覆盖 §1 中所有平台差异场景 |

保障措施：

| 要求 | 机制 | 触发 | 不满足时 |
|---|---|---|---|
| 归一化一致性 | Code 中所有路径比较都经过 `normalize_path` | 新增路径比较逻辑时 | 回归测试失败 |
| target resolution 证据完备 | 每条 target resolution 记录都包含 `normalized_path` | 执行 target-first 解析时 | 补全 resolution 字段 |
| 跨平台覆盖 | 测试覆盖 macOS/Linux/Windows 的路径语义 | 新增平台支持或路径处理代码时 | 补测试 |

检查方法：

| 检查类别 | 检查内容 | 不满足时 |
|---|---|---|
| 归一化正确性 | 路径按 §1 步骤归一化后，输出符合预期 | 修正归一化函数 |
| 命中判定正确性 | 管辖项目命中判定符合 §2 的比较规则 | 修正解析逻辑 |
| 函数幂等性 | 多次调用 `normalize_path` 结果不变 | 修正函数实现 |
| 平台差异覆盖 | 测试覆盖 macOS/Linux/Windows 的路径语义差异 | 补测试用例 |
