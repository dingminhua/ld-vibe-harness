## 1. 本文解决的问题

本文定义 LDVH 工作对象如何作为过程、证据、决策、任务和经验的承载面。

本文解决：

1. 哪些内容应进入工作对象，而不是停留在聊天、review 或工具输出中；
2. Spark、WorkCase、ADR、Pitfall、Study 等对象的上位归口如何区分；
3. warning、follow-up、缺口和后续查询如何找到承载位置；
4. 后续具体工作对象规范如何衍射，而不把所有对象规则塞进本文。

本文不定义具体对象字段、状态机、schema、CLI、Web 展示或行动编排流程。这些由后续对象成员、Code、Web 或行动编排承接。

## 3. 构成要素归属与价值判断

本文属于会衍射对象成员的基础规范。

| 价值 | 本文如何服务 | 减少的 AI 负担 |
|---|---|---|
| V1 快速定位 | 让 AI 知道过程事项应进入哪类对象 | 定位负担 |
| V3 正确判断 | 防止用聊天、review 或工具输出替代工作对象 | 判断负担 |
| V7 证据沉淀 | 给过程证据、缺口和经验提供承载方向 | 回写负担 |
| V8 可靠回写 | 让任务、决策、经验和研究结果有稳定位置 | 回写负担 |

## 4. 适用范围与事实源边界

本文适用于 LDVH 工作对象体系的共同边界。

聊天、Code 输出、Skill 输出、子 agent 审核和 review 收据不是工作对象事实源。它们只有写入对应工作对象或规范后，才成为稳定事实。

## 5. 本地规则

工作对象默认归口：

| 对象类型 | 承载内容 |
|---|---|
| Spark | 未成形但值得保留的想法、线索、方向和后续查询 |
| WorkCase | 具有目标、成功标准、执行项、验证和关闭判断的工作 |
| ADR | 需要长期保留的决策和取舍 |
| Pitfall | 已解决且可复用的踩坑经验 |
| Study | 研究、资料整理和来源吸收结果 |

AI 不得用工作对象替代 specs 规则。工作对象记录过程、证据和结果；规则仍回到 specs。

## 7. 验证与证据

AI 声称已完成工作对象分流前，必须说明：

1. 为什么选择该对象类型；
2. 是否已有对应对象；
3. 证据来源和回指位置；
4. 后续应由哪个对象或规范承接。

## 8. Human Gate / Stop Conditions

以下情况必须暂停：

1. 新增、删除、合并或重命名工作对象类型；
2. 用工作对象替代 specs 规则；
3. 把 review、聊天或工具输出直接升级为工作对象事实；
4. 工作对象归口存在争议且会影响长期事实源。
