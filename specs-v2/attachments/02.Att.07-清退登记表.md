## 1. 定位

本文承载 02 授权的清退登记条目，包括已清退对象、旧入口和废弃字段。

02 正文定义已清退对象不得重新成为当前事实模型入口的原则；本文只能维护登记清单，不得单独扩大或缩小清退边界，不得定义兼容读取策略、迁移流程、字段注册表本体、具体模型 schema、Code 输出 Schema 或 Web 页面契约。

本文以“清退登记”为单一信息对象。已清退对象、旧入口和废弃字段都只是清退登记的条目类型；若后续对象清退和字段清退出现独立授权、独立生命周期或独立 Code 消费规则，应按 01 附件规则拆分为独立附件。

## 2. 已清退对象入口

以下对象入口已经清退，不得作为当前事实源、Code 入口、Web 入口或测试夹具维护对象：

| 清退对象 | 旧入口或旧目录 | 当前替代承载 |
|---|---|---|
| `TaskPlan` | `ldvh-base/taskplans/`、`taskplan`、`taskplans` | WorkCase 的工作组织和 `orchestration.execution_items` |
| `Task` | `ldvh-base/tasks/`、`task`、`tasks` | WorkCase、ExecutionItem 或对应事实对象字段 |
| `SubTask` | `ldvh-base/subtasks/`、`subtask`、`subtasks` | WorkCase 内部执行拆分或对应事实对象字段 |

历史文档、commit message 或研究材料中出现旧名称时，Web 和 Code 不得把它们自动提升为当前对象入口。

## 3. 废弃字段登记

以下旧字段不得作为 active 对象字段扩展或新写入入口：

| 废弃字段或字段族 | 边界 | 当前表达方式 |
|---|---|---|
| `taskplans` | 不作为对象类型、引用字段或目录入口 | 使用当前对象字段、文档路径或 Git 引用 |
| `related_taskplans` | 不作为 active 关联字段 | 使用当前对象关系字段或 `related_docs` |
| `related_tasks` | 不作为 active 关联字段 | 使用当前对象关系字段或 WorkCase 内部执行项 |
| `source_tasks` | 不作为 active 来源字段 | 使用当前 `source_*` 字段和 WorkCase 来源关系 |
| `tasks` | 不作为 active 列表字段 | 使用 WorkCase 的 `orchestration.execution_items` |
| `completion_evidence` | 不作为 active 通用证据字段 | 使用 `verification_evidence`、`closure_evidence` 或具体模型证据字段 |
| `deliverables` | 不作为 active 通用交付字段 | 使用验收、验证、结果或对象特有字段 |
| `affected_docs` | 不作为 active 通用文档字段 | 使用 `related_docs` 或对象特有字段 |

需要表达执行拆分时使用 WorkCase 的 `orchestration.execution_items`。需要表达关联关系时使用当前对象字段、文档路径或 Git 引用。

## 4. 清退登记辅助核对表

清退登记辅助核对至少包括：

| 核对项 | 标准 |
|---|---|
| 对象入口 | 旧对象未作为当前事实源目录、CLI 类型、Web 路由或测试夹具 |
| 字段入口 | 废弃字段未作为 active 对象字段扩展或新写入入口 |
| 替代承载 | 需要表达的语义已回到 WorkCase、当前对象字段、文档路径或 Git 引用 |
| 不越界 | 本文未定义兼容读取策略、迁移流程、Code 输出 Schema 或 Web 页面契约 |

本核对表用于发现清退对象复用、废弃字段复用和入口漂移；核对结论不能替代 02 主文档规定的高影响确认。
