## 1. 价值判断

本文的价值，是让 AI 和 Human 能区分“LDVH 文件或包存在”“LDVH 核心、Helper、Git Gate 或 Hook Gate 可直接调用”“环境入口已安装”“目标环境真实自动触发”和“当次接入范围已验证”，并让普通环境 Hook 通过相应 LDVH 核心交付当前规则与能力，直接客户端按需调用 Helper，或仅在其它来源已经定义纯机械闭集时调用同一 Git Gate 或 Hook Gate 核心，而不是各自复制规则、模板、事实 Schema 或判断逻辑。

本文主要服务：

1. V1 快速定位：每个环境只有一个 LDVH 接入单元，能够回指实际 LDVH 核心、其内部 Helper 和目标工作对象；
2. V2 充分理解：环境结果保留 LDVH 核心及其中 Helper 的来源、范围、部分结果、失败和未证明条件；
3. V3 边界识别：区分环境协议、Helper 契约、管辖配置、安装观察和真实触发；
4. V4 稳定推进：安装、升级、禁用、卸载和失败回滚具有清楚边界；
5. V5 据实判断：接入声明绑定目标环境、版本、入口、事件和当次实际证据；
6. V6 工作接续：环境入口能够在其真实支持的 lifecycle 中把同一当前信息入口交给后续 AI；
7. V7 清晰沟通：能力不足、授权、断点、失败、回滚和未验证范围能够如实交还。

环境接入的价值来自降低每个环境重复实现和错误宣称的成本，不来自要求所有环境具有相同事件、阻断能力、安装方式或表现。

## 2. 规范依据

本文直接依据：

1. `ldvh-root`：规定环境自动触发的价值交付方式，环境 Hook、插件和 adapter 经相应 LDVH 核心交付结果，Helper CLI、Hook、Git Gate 和 Hook Gate 所需的确定性程序由 Code 实现，并保留 AI、Code、Web、Human 与三类语义构成要素的上位边界；
2. `work-object-governance-scope`：规定环境入口必须使用的工作对象、工作区根、管辖项目配置和解析结果；
3. `source-of-truth-traceability`：规定环境观察、安装结果、触发结果、诊断和回滚结果的信息作用、当前性及来源回指；
4. `helper-cli-service-contract`：规定 adapter 必须忠实转换的公开请求、响应、能力、部分结果和错误边界。

`code-engineering-practices` 约束 adapter Code 与 tests，但不定义环境接入语义。`action-template-foundation` 及具体安装模板可以组织重复行动，但不反向定义本文的成立条件。厂商资料和单一 adapter 正式来源只定义对应环境的事件、manifest、权限、payload、安装接口与实现边界。

## 3. 职责边界

本文负责定义：

1. 外部环境事件、工具调用和上下文经相应 LDVH 核心接入，或在其它来源已定义时接入原生阻断型机械 Gate 的共享 Hook 行为与环境薄引用分层和共同转换边界；
2. LDVH 核心结果及其内部 Helper 结果映射回环境时的忠实性、能力差异、失败、未验证范围和缺口交还；
3. 环境能力发现、静态安装观察、LDVH 核心或 Helper 的直接可调用、真实自动触发和当次接入验证之间的非等价关系；
4. 环境接入安装、检查、升级、禁用、卸载、共存和回滚的共同成立条件；
5. 环境接入声明所需的目标环境、版本、入口、事件、调用、映射、失败路径与回滚证据；
6. 跨环境共同规则与单一厂商 adapter 契约、实现和 tests 的分界。

本文不负责定义：

1. `LDVH-GOVERNED-PROJECTS.yaml` 的位置、字段、发现、有效性或管辖判定；
2. Helper 命令、请求/响应字段、退出码、领域操作、规则或事实语义；
3. 某厂商事件名、manifest、payload、权限、安装路径、命令、缓存目录或 UI；
4. adapter 的语言、模块、算法、内部状态、日志格式、fixture 或测试命令；
5. 事实对象、永久安装记录、运行 receipt、环境状态对象或 Web 展示；
6. 某次安装、修改、卸载或外部环境操作已经获得 Human 授权；
7. 所有环境必须支持固定 lifecycle、阻断、自动写入或相同结果表现。

02 唯一定义管辖配置；04 唯一定义 Helper 外部服务；07 定义 Code/tests 共同工程要求；具体环境来源定义厂商协议；行动模板只组织一次行动。本文不改变这些责任。

## 4. 适用范围

本文适用于：

1. 环境 Hook、插件、扩展、Skill、Agent 入口或外部 adapter 准备经 LDVH 核心接入，直接调用 Helper，或接入其它来源已定义的原生阻断型机械 Gate；
2. 安装、启用、配置、检查、升级、迁移、禁用、卸载或回滚一个 LDVH 环境接入单元；
3. 环境事件、工具输入、cwd、target、工作区或其它上下文准备映射为由 LDVH 核心使用的 Helper 请求；
4. LDVH 核心或 Helper 的成功、部分结果、拒绝、不可用、诊断或未知范围准备返回目标环境；
5. 准备声明某一环境中的 LDVH 入口可用、已真实触发、已接入或已验证；
6. 目标环境能力不足、协议变化、安装冲突、真实触发失败或卸载残留需要分流。

只直接调用 Helper、但不声明环境自动连接的普通 AI 行动，仍受 04 和具体领域来源约束；不因本文存在而必须先安装 adapter。环境实现说明只有在说明具体实现时受本文约束，不因记录现状而成为规则源。

## 5. 单一接入单元与协议映射

### 5.1 单一入口与权威边界

一个目标环境只应安装、启用或配置一个承接 LDVH 的接入单元，不得按行动模板、事实类型或项目分别安装多套规则副本。接入链路必须区分三个层次：具体环境来源定义的原生 Hook 事件；由当前正式来源支持、可供不同环境共同复用的环境无关 LDVH 核心行为（以下简称“共享 Hook 行为”）；04 定义的 Helper 公开操作。原生事件只提供触发时机和环境上下文，不定义共享 Hook 行为或 Helper 语义；共享 Hook 行为按当前规则源组织已有 Helper 操作并把结果交给 AI，不取得 Helper 之外的语义权威。

LDVH 提供环境无关的接入方法，不负责预先调查或维护全部 AI 开发环境的厂商步骤。用户可以让目标环境中的 AI 依据该环境当前官方或实际权威资料，识别能够自动触发的扩展或事件机制、实际输入与反馈能力、安装位置、权限和验证入口，再对照本文与 LDVH 当前交付入口形成当次方案。厂商是否使用 `Hook` 这一名称不决定能力是否存在；判断对象是该机制能否自动调用所需 LDVH 核心、直接 Helper 或机械 Gate，并承接相应必需输入与反馈。

目标环境能够把原生机制直接配置到一个已经存在且适用的 LDVH 入口时，可以在完成来源核对与 Human Gate 后进入安装验证。若连接必须新增 manifest、启动脚本或薄 adapter，则安装分支停止；该对象先按具体环境来源、07 和普通 Code 计划独立设计、实现与验证，完成后才可作为 33 的候选接入单元。AI 自助接入不允许用自然语言提示或安装模板跳过这项分流。

唯一例外是 Git Gate 或 Hook Gate：只有其它当前正式来源已经独立定义封闭的纯机械合格条件，且目标环境的原生事件确实只能就地允许或阻断时，共享 Hook 行为才可不经过 Helper 服务链，直接调用该条件的唯一核心 Code 实现。Git Gate 或 Hook Gate 只接收实际事件提供的输入，必须在同一实际候选、来源、管辖和 Index 身份上得到可验证绑定；输出只限 allow/block 与可回查诊断。任一绑定缺失、读取失败或漂移均阻断。Git Gate 或 Hook Gate 不得写入 message、Index 或历史，不得判断本地最小增量、自然语言语义、行动授权、验证充分性或完成，也不得建立第二份 Schema、规则源、状态、登记或语义权威。

同一机械检查另有 Helper 公开操作供 AI 主动预检时，不表示 Git Gate 或 Hook Gate 改为调用 Helper，也不允许形成两套检查。Helper 与 Git Gate 或 Hook Gate 必须按照同一当前来源形成检查输入，观察各自当次绑定候选并调用同一份确定性检查实现；Helper 以结构化结果支持 AI，Git Gate 或 Hook Gate 以真实环境事件输入重新检查并只映射 allow/block。任一入口的旧结果不得替代另一入口对其当次实际输入的检查。

本文的 Git Gate 或 Hook Gate 是由 Code 实现、按来源已定义闭集条件自动执行的机械检查；Human Gate 是来源规范保留给 Human 的判断、授权、方向校正、风险接受或验收节点，三者互不替代。

Git Gate 或 Hook Gate 的闭集只属于其来源明确指定的同一原生事件，不是目标环境内 AI 行动的许可白名单。adapter、Hook 和共享行为不得维护“允许的全部工具/命令/动作”登记，也不得把未映射、未识别或新增的工具名称默认判为 block。只有当前原生事件已进入来源定义的 Gate，才能就该事件的实际候选、目标、候选副作用和必需输入输出 allow/block；来源明确规定候选绑定或必需输入缺失时 fail-closed 的，阻断仍只作用于这一次原生事件。其它行动是否允许按 Human 当前指令和各自适用来源判断。

原生事件与共享 Hook 行为不预设一一对应，多个原生事件可以映射到同一行为。只有具体环境来源与相应当前规则共同支持，且实际触发时机、输入和反馈能力不会改写共享 Hook 行为或 LDVH 核心结果语义时，才可建立映射；否则仅在具体来源允许时 no-op，或拒绝当前事件并交还无法确定的映射范围，不得按事件名称猜测最接近的行为。映射是否成立由 AI 对照这些来源判断；Code 只执行已经成立的确定性映射，不判断原生事件与共享 Hook 行为是否语义对应。

共享 Hook 行为是环境交付的 LDVH 核心实现实践，只组织已有交付入口与来源已定义能力；它不形成新的语义构成要素、规则源、事实对象、行动模板、状态或 Helper 公开协议。每项行为及其实际 LDVH 核心和内部 Helper 调用，或原生阻断型机械 Gate 对其它当前来源核心实现的直接调用，都必须回指相应当前来源；本文不定义共享 Hook 行为的固定闭集、统一标识、中央登记、统一 payload、receipt 或状态机。

共享 Hook 行为及原生阻断型机械 Gate 的唯一实现必须随 LDVH 核心分发，并通过明确入口供已成立的 adapter 直接调用；不得只放在某一环境的 adapter 或 bundle 中，再以尚无第二个消费者为由延后。这个要求只确定实现归属和显式调用路径，不要求统一目录、事件名、payload 或登记机制。

当前发行物必须提供可检查的接入面说明或唯一发现入口，使目标环境 AI 能够取得当前实际存在的共享行为、LDVH 核心、Helper、Git Gate 或 Hook Gate 核心入口，以及每项入口的适用来源、输入、输出、`partial`/错误、超时和反馈边界。该说明只投影既有来源与实现，不建立统一厂商 payload、通用事件路由、默认语义、adapter 登记或新的 Helper 操作；实现中发现必须新增这些公开合同时，应停止并回到相应规范责任重新判断。

在新的、恢复的、压缩后继续的或受委派的工作上下文中，LDVH 核心默认执行 01 §9.10 的 `work-context-rule-orientation` profile，并把其中实际返回的规则原文、来源、已完成范围和缺口交给 AI，同时提示 AI 可继续使用既有规范读取能力。该默认交付不调用管辖解析、项目候选、事实发现、事实读取或事实恢复；事实侧状态必须明确为 `not_requested`，并与规则交付的 coverage 分开表示。规则引导所需的配置、验证和调用不得把事实恢复 runner、管辖 workspace 或项目事实配置作为隐式前提；这些条件只在明确进入事实消费分支或显式验证该分支时处理。profile 的选择不能由 cwd、任务文字、工作对象、缓存或父上下文改写。LDVH 核心可以在来源允许时调用其它 01 定义的规范候选、内容或上下文组合读取能力；这些读取同样只帮助 AI 定位和理解规则，不形成环境层的适用判断、Human Gate 判断、Human 决定证据、行动允许或完成裁决。某次环境事件没有取得规则引导或规范组合上下文，只能据实形成读取或接入缺口；除非另一项当前来源已经对同一原生事件封闭定义了相应机械 Gate 及失败方式，不得仅因缺少规则读取摘要、组合上下文或通用 receipt 而阻断该事件或后续普通求解。

当 AI 已依据当前目标明确进入 05 §8.1 的事实消费分支时，共享上下文恢复才可以把多次 Helper 只读结果组织为有界事实恢复投影。项目候选、binding、事实 coverage、WorkCase 候选和按需展开必须由共享 Code 按 02、05 与 21 唯一解释；投影至少保留每次实际操作的 operation identity、outcome、scope/coverage、来源 locator、gap/diagnostic 摘要、项目与 WorkCase binding 状态及按需展开入口。可以不把完整 Helper JSON、完整事实对象或规则全文无条件注入环境上下文；缩减不得吞掉 `partial`、未读 cursor、无效/不可读对象、输入不足或来源缺口，也不得把候选写成当前任务绑定。

有界投影必须分开 Helper 实际 coverage 与 AI 交付的 `delivery_coverage`。规则引导和事实恢复还必须分别报告各自交付状态；默认规则引导中的事实状态为 `not_requested`，不得写成 `unresolved`、`complete` 或事实为空。进入事实恢复后，若全部登记项目候选无法在当次 byte 预算内容纳，`delivery_coverage` 必须为 `incomplete`，项目与 WorkCase binding 均为 `unresolved`。若项目 binding 已独立成立，但全部必需 F1 卡片无法容纳，必须保留既有 `project_binding=bound`，设置 `delivery_coverage=incomplete` 和 `workcase_binding=unresolved`，不得声称已完整审阅 F1 或继续责任绑定。两种情形都必须保留总数、已交付数、省略数、来源和继续展开入口。byte 预算只约束交付投影，不得改写 Helper 返回的 coverage、不得静默截断后继续报告 complete。

原生事件到共享 Hook 行为的薄引用路径，只承担按已成立映射定位共享实现、投影环境实际字段、调用和转换结果；它是环境内部的稳定引用，不形成跨环境通用的公开身份。adapter 不得复制共享 Hook 行为流程，也不得保存或复制行动模板正文、规范正文、事实 Schema、领域状态机、自然语言适用判断、Human Gate 判断或另一套完成规则。环境要求的 manifest、声明、权限和薄启动代码不是规则副本，但其中不得重写共享 Hook 行为、Helper 或领域语义。

adapter 只能验证并传递环境实际 payload 与共享 Hook 行为的核心结果投影，不得从核心或 Helper 原始 JSON 重新解释或重新选择项目、WorkCase、coverage、binding 或错误。环境未提供精确 `current_workcase_ref` 时不得补造；环境只提供事件、source 与 cwd 时，这些字段不能被提升为自然语言任务身份。

环境接入单元必须能够回指当次实际适用并被调用的 LDVH 核心入口及其内部实际调用的 Helper 入口，或 Git Gate 或 Hook Gate 核心入口、版本或当前实现身份，以及当次使用的工作对象范围。不得从任意 `cwd`、同名目录、旧缓存或历史安装路径猜测 LDVH root、工作区根或管辖项目。

原生 Git `commit-msg` Git Gate 的每一安装实例以实际触发事件的一个 Git worktree 为唯一对象。只有既有管辖解析针对该 worktree 返回 `governed_single`，才能在其中安装本地 Hook；不同实际 worktree 可以各自持有指向同一核心的薄对象，但不因此形成多套环境接入单元、规则副本、登记或新的 Helper Schema。adapter 只能使用 Git 事件或环境创建/设置接口明确交付、并由核心重新验证的目标实际 Git worktree 身份；该接口明确交付的 cwd 可以作为身份输入。不得从任意或隐式 cwd、common Git directory、相邻 worktree 或历史路径推断它。

### 5.2 已迁移 Hook 的稳定薄引用

已完成迁移的既有环境 Hook 是稳定薄引用。它只接收目标环境原生事件实际提供的输入，调用其既定的 LDVH 核心入口，并如实映射该入口形成的结果。它不得自行读取或选择规则、恢复事实、选择信息交付方式、补造环境未提供的信息、解释结果，或判断信息相关性、规则适用、授权、风险接受、验证充分性和工作完成。

一次迁移完成后，既有 Hook 的实现、职责边界及其对 LDVH 核心的引用路径均被冻结。LDVH 核心可以依照当前规则源继续演进，但不得因此要求既有 Hook 改变职责、补充输入、解释结果或变更引用路径。这里的稳定只指 Hook 与核心之间的引用关系稳定，不建立跨环境通用的公开事件身份或 payload。

### 5.3 事件扩展与独立 Hook

只有当前规则源已经定义所需核心能力、目标环境协议已经明确原生事件及其实际输入输出承载方式、并且当次确有接入需要时，才可新增事件注册或独立 Hook；不得预先登记尚未使用或尚未证实支持的事件。

新事件的实际输入能够不经补造或语义解释而满足既有稳定薄引用的输入边界，且环境能够如实承载其结果、不改变该结果含义时，可以新增该事件指向同一稳定薄引用的注册。此类新增只扩大注册范围，不得改写既有 Hook 的实现、职责或核心引用路径。

输入、输出或事件语义任一不兼容时，必须新增独立 Hook，并按具体环境来源与 07 完成设计、实现和验证；不得为取得表面兼容而改写既有 Hook。

### 5.4 未承接范围与历史入口边界

既有 Hook 或其固定核心入口不能承接某项新能力时，结果必须如实说明未交付的能力、不兼容的输入或输出、既有 Hook 实际仍可交付的范围，以及另行接入所需条件。不得把未承接表述为已交付、自动保障或完整成功。

不得因不兼容而静默调用旧上下文恢复入口或任何其他历史交付路径作为替代。历史入口仅可在其自身来源已经规定的前提和范围内独立使用，不得被解释为新能力已经由既有 Hook 承接。

### 5.5 输入投影

已迁移 Hook 只把目标环境实际提供的原生输入原样传递给其固定 LDVH 核心，不形成或补造 Helper 请求。面向 Helper 的直接 adapter 才能把目标环境实际提供且当前 Helper 操作接受的信息投影为请求。工作对象、locator、cwd、target、工具输入、事件上下文和调用时间必须保持各自身份；不得用 cwd 覆盖显式 target，不得把环境会话身份伪造成项目身份，也不得补造环境没有提供的字段。

面向 Git Gate 或 Hook Gate 的薄引用只能原样传递当前原生事件可证明的输入，并由核心 Code 绑定实际候选、来源、管辖和 Index；不得把它伪造成 Helper 请求、环境会话或项目身份，也不得为 Git Gate 或 Hook Gate 另建 payload Schema、默认值或语义补全。

本文不定义全部环境、工具或行动共用的原生事件 Schema、action envelope、preflight receipt、授权 token、统一允许状态或运行时状态机。具体来源已经封闭定义的机械 Gate 可以在其同一原生事件内要求瞬时候选输入，但 adapter 只能投影环境实际提供的字段，核心只能检查该来源定义的机械条件；AI 形成的适用判断、Human 回应转述、规则读取摘要或 coverage 不得被 adapter 包装成不可伪造的 Human 决定或跨事件行动允许。

环境输入不足以满足 LDVH 核心或直接 Helper 请求时，接入单元必须如实报告核心或 Helper 给出的缺失信息和实际影响范围。只有具体环境来源和相应核心或 Helper 契约共同支持时，才能使用明确的机械默认值；不得根据自然语言猜测管辖、规则适用、行动授权或事实语义。

未知事件、未知字段和未来协议版本不得静默映射到“最接近”的已知动作。能够安全 no-op 的事件按具体环境来源 no-op；可能改变阻断、写入、完成或反馈语义时，必须拒绝当前事件并交还不可验证范围。

这里的拒绝或阻断只作用于当前正在映射且其语义无法安全确定的原生事件，不得扩张为环境会话、工具系统或 AI 后续行动的全局暂停。未进入某项来源已定义 Gate 的未知工具或普通行动，不得仅因 adapter 没有映射而被该 Gate 拦截。

### 5.6 结果映射与环境能力差异

接入单元必须保留 LDVH 核心结果及其中需要保留的 Helper 结果的成功、部分完成、拒绝、不可用、来源、范围、诊断和未证明条件，不得把 `partial` 映射为完整成功，把警告映射为阻断，把建议映射为授权，或把环境 UI 的成功提示映射为工作完成。核心返回 `unavailable` 时，adapter 必须如实传递该结果及其诊断说明，不得因结果格式验证失败而丢弃该结果；`unavailable` 结果中的 `event_name` 可以为 null，adapter 不应因此拒绝该结果。

目标环境不支持 LDVH 核心结果或其中 Helper 结果要求的阻断、结构化反馈、上下文注入或其它表现时，只能使用该环境真实支持的最接近承载方式，并明确能力差异。不能实施的强制行为不得被表述为已经自动保障；必要规则仍由 AI 依据当前来源执行，环境能力缺口不能被解释为规则失效。

完整接入的能力状态必须区分 `unsupported` 与 `unverified`。只有当前官方或实际权威资料，或者对实际环境的范围匹配观察，肯定证明不存在能够自动调用所需 LDVH 入口并承接必需输入与反馈的机制时，才能把相应完整接入判为 `unsupported`。尚未调查、没有找到资料、权限不足、版本不明或当前不可观察均为 `unverified`；发现候选机制也只表示可以继续调查，不能替代安装和真实触发证据。`partial` 只描述已经完成的实际子范围，不得掩盖 `unsupported` 或 `unverified`。

`unverified` 只表示当次证据不足，不表示以完成接入或验收为目标的行动已经闭合。阻塞该目标的 `unverified` 必须保留目标特定的原因、当前责任方、最小恢复动作、需要返回的原始观察和复跑入口；只有目标明确排除、Human 明确拒绝/未授权，或当前来源已定义的停止依据成立时，才可把该阻塞作为当次停止依据。不得用并列厂商名称、历史环境或泛化的“未配置”替代实际目标与恢复交还。

环境层不得吞掉 LDVH 核心或其内部 Helper 调用失败、超时、解析失败或目标不明。若环境本身无法向 AI 或 Human 呈现完整诊断，至少必须提供可回查入口，并把无法呈现的范围列为接入缺口。

原生阻断型机械 Gate 只能把同一事件的 allow/block 与原始诊断映射回环境；不得把 allow 写成 AI、Human 或语义审核已经通过，也不得把 block 改写为成功提示或静默 no-op。

环境提供的 `Stop`、完成回调或等价事件只能承接来源已封闭定义的机械检查，或者把实际结果与规则上下文交给 AI 继续判断；它不得自动裁决当次全部适用 Specs 已经找全、全部验证已满足、Human Gate 已完成或上层工作可以结束。`PostToolUse` 或其它事后事件只能观察和报告已经发生的实际结果，不能倒推事前授权成立，也不能用诊断替代必要回滚、修复或 Human 决定。

## 6. 安装、部署、接入与验证边界

### 6.1 四层职责与环境专属事件表

一次环境行动必须把以下四层分别说明，不能以其中任一层的完成替代另一层：

1. **安装**：取得并安装固定版本的 LDVH 核心及其依赖，只说明核心在约定位置可供后续使用；
2. **部署**：把具体环境实际需要的既有接入单元、配置、权限或受管安装对象放到目标环境可观察、可调用的位置；部署不等于原生事件已经连接；
3. **接入**：由具体环境的原生事件实际连接既有 LDVH 核心入口，且输入、结果与反馈能力均与来源定义相符；它不因核心可直接调用而自动成立；
4. **验证**：按当次接入单元承接的实际事件取得静态、直调、真实触发、主要风险和回滚或不适用范围的相称证据，并如实交还未验证范围。

在形成方案、逐事件交还或验收结论前，执行者还必须区分并锁定**执行环境**与**目标环境**：前者是 AI 当次实际运行并进行观察的产品/运行器、版本、平台和可观察运行位置；后者是本次拟安装、检查或验证接入单元的环境、版本、平台和目标位置。交还必须说明两者是同一环境、不同但可访问、不同且当前不可访问，还是尚未确认，并回指当次识别依据。目标尚未锁定时，只能继续无副作用调查，或按 33 交还目标确认请求；不得把候选环境列表写成接入或 Hook 配置结论。

AI 开发环境的生命周期 Hook 以目标环境原生插件作为接入单元，并部署在该环境的用户级范围；具体插件身份、目录、manifest、缓存、信任、启用方式和可触发会话范围必须由该环境的当前正式来源与当次观察确认，不能从其它环境复制或猜测。该插件或 adapter 由处理该目标环境的 AI 在该环境自己的仓库开发，不在 LDVH 仓库收纳；LDVH 仓库只附带一个参考实现供对照。该交付约束不适用于原生 Git Gate 或 Hook Gate；它们仍按各自来源和实际 Git worktree 安装。

具体环境或 adapter 的当前正式来源必须声明它实际承接的原生事件及版本/单元范围；未被该来源声明或无法确认的事件不得写入“已接入”结论。本文只规定这项责任，不维护跨厂商事件登记、环境状态或永久事实对象。一次行动如何逐事件交还，由 33 定义。

### 6.2 静态安装、可调用与真实触发

下列观察互不替代：

1. 包、文件、manifest、Hook 或配置存在，只证明当次静态对象被观察到；
2. Helper 可以从 shell 或测试入口直接调用，只证明当次直接调用路径；
3. 普通环境 Hook 所稳定引用的 LDVH 核心可以从 shell 或测试入口直接调用，只证明该核心入口，不证明环境已经自动触发；
4. Git Gate 或 Hook Gate 核心可以从测试入口直接调用，只证明当次机械检查入口，不证明环境已经自动触发或产生 allow/block；
5. adapter 可以用 fixture 或手工输入调用，只证明该输入和测试入口；
6. 目标环境在代表性真实事件中自动调用接入单元，普通接入经稳定薄引用调用相应 LDVH 核心并形成可回指的核心及其内部 Helper 请求与结果映射，或者让 Git Gate 或 Hook Gate 对同一实际候选形成可回指的 allow/block 与诊断，才证明相应分支当次真实触发；
7. 只有来源要求的安装、映射、成功、失败、能力差异和回滚检查均取得范围匹配证据，才能声明相应环境、版本、入口与事件范围已经验证。

任何一项通过都不得自动扩张到后续项目、会话、环境版本、其它事件、阻断能力或永久接入状态。环境或安装对象变化后，原证据只能作为历史输入，必须重新检查受影响范围。

环境无关 doctor 只允许读取当前 LDVH 发行版本与核心入口、显式提供的工作对象和管辖解析、LDVH 自有配置可读性、已交付接入面静态存在及当前调用或验证缺口。根级 `docs/` 是临时说明材料；其存在、缺失、文件名、内容、打包状态或新旧程度不得成为 doctor、环境接入、能力可用性、`ready` 状态、Gate、发行或实现验证的输入或成立条件。它不得扫描、猜测或修改未显式提供的目标环境配置，不得把历史真实触发解释为当前仍已接入，也不得写用户或全局配置、安装外部工具、登录、接受信任或触发重启。doctor 成功完成只证明诊断本身可用，不证明任何目标环境已经接入。

当前环境无关诊断入口为 `ldvh-doctor`，输出合同为 `ldvh-doctor/1`。调用方必须显式提供绝对 `workspace_root`、非空 `work_object_locator` 和绝对可执行 `helper_executable`；runner 使用最多 20 秒的单次 Helper 调用边界，先读取 Helper capabilities，再调用 04 已定义的 `resolve-governance-scope`，不新增 Helper 操作。输出至少包含合同、总体 `status`、当前 distribution 身份、Helper 调用观察、配置与管辖结果、已交付接入面的静态可用性、逐项 checks、limitations 和 diagnostics；接入面成员只投影当前发行物已有 console entry point、角色与来源，不复制其输入输出协议。

doctor 的 `status` 只使用 `ready`、`attention`、`unavailable`：Helper 和显式配置/管辖均可用且已交付接入面静态存在时为 `ready`；诊断完成但配置、管辖或静态入口存在缺口时为 `attention`；输入无效、Helper 无法形成合同响应或诊断本身无法完成时为 `unavailable`。`ready` 与 `attention` 进程退出 0，`unavailable` 退出 1；三者均不表示目标环境已经安装、自动触发或通过真实验证。

### 6.3 安装与变更计划

安装、升级、修复、禁用、卸载或迁移前，必须先只读确认：目标环境及版本、工作区和工作对象范围、当前规则源与当次实际适用的 LDVH 核心入口及其内部 Helper 入口，或 Git Gate 或 Hook Gate 核心入口可达性、现有接入对象、用户既有配置、权限要求、冲突、计划写入或删除、明确不变范围、验证入口及回滚方式。

安装位置及其可触发会话范围（例如目标环境实际支持的用户级、工作区级或项目级范围）必须在计划中单独确认。该范围只说明接入单元可能在哪些会话被触发，不等同于项目已纳入管辖、当前任务相关、规则已经适用或项目事实已经读取。范围覆盖多个工作区或项目时，范围内事件仍只经既定薄引用交付当前核心的基础规则引导；Hook 和 adapter 不得依据项目路径、名称、`cwd` 或任务文字筛选、改变或停止该交付。是否继续取得项目事实，仍由 AI 依当前目标和来源规则决定。

环境变更计划必须将 LDVH 管理对象与未知或用户管理对象分开。不得覆盖、截断或删除无法证明由 LDVH 管理的 Hook、配置、插件或脚本；需要替换、合并或放弃既有用户配置时，进入 Human Gate。

执行只能覆盖 Human 当前指令已授权，且适用于该行动的全部来源规则许可条件已经成立的目标、环境和写入范围。安装授权不自动包含管辖项目登记、事实源初始化、Git commit、重启环境、接受平台信任提示、删除旧资产或安装其它工具；这些行动分别依据实际适用的来源规则和 Human 当前指令判断。

Human 在当前指令或确认方案中明确授权某一项目×环境的工作树创建或设置流程时，可以覆盖该环境在该项目中、由当前流程明确交付且逐个解析为 `governed_single` 的实际 worktree 内，方案已列明且由当前来源和实际能力唯一确定的 Hook 设置；每次仍须对该 worktree 回读目标、管辖和用户资产。该授权不建立持久授权或登记，也不涵盖其它项目、环境、用户资产、信任/权限、未列删除、管辖配置、Git commit 或需要新的取舍的分支。

### 6.4 管辖配置边界

安装流程可以读取 02 定义的 `workspace_root` 和 `LDVH-GOVERNED-PROJECTS.yaml`，并调用实际可用的管辖解析能力验证目标范围；不得在 09、adapter 或安装模板中复制字段和解析算法。

安装 LDVH 或环境接入单元不自动新增、删除或修改管辖项目。Human 明确要求同时登记项目时，必须把该变化作为独立计划项，使用 02 的当前字段与验证规则，展示实际写入和回读；安装成功不能证明管辖配置成立，管辖配置成立也不能证明环境已接入。

### 6.5 升级、禁用、卸载与回滚

升级必须重新检查协议、权限、安装对象、当次实际适用的 LDVH 核心入口及其内部 Helper 入口，或 Git Gate 或 Hook Gate 核心入口兼容性、用户配置冲突和受影响事件，不能仅替换文件后沿用旧验证结论。禁用必须证明目标环境不再自动调用该接入单元；卸载还必须处理 LDVH 管理的安装对象和短期过程数据，并保留或恢复安装前未知用户资产。对已迁移 Hook 的维护不得改变其实现、职责或核心引用路径；需要改变其中任一项时，不属于升级既有 Hook，应按 §5.3 作为新增独立 Hook 处理。

每项可能写入或删除的对象都必须在执行前具有可理解的回滚或恢复方向。失败后只能恢复当次实际改变且有基线依据的对象；缺少原始内容、权限或可验证恢复入口时，不得承诺完整回滚，并应在写入前交还风险。

回滚完成必须通过目标环境和实际安装对象重新观察：LDVH 接入不再自动触发或已经恢复到变更前连接，同时无关用户配置未被破坏。运行命令成功、备份文件存在或安装器返回成功不能单独证明回滚成立。

经授权正常删除实际 worktree 时，只有有效 Hook 路径确实位于该 worktree 内的 LDVH 管理 Hook 安装对象才会随目录物理消失；这只证明该本地对象已移除，不证明 common Git directory、全局或外部路径、其它 worktree 的 Hook 或配置已经删除。手工删除目录遗留的 Git 管理信息和其它外部残留必须如实交还，不以此补造注销、状态迁移、完整禁用/卸载或真实触发结论。

## 7. 真实环境验证与证据边界

### 7.1 最小证据

准备声明某一接入范围已经真实触发或通过验证时，至少必须回指：

1. 目标环境名称、版本和实际运行位置；
2. 接入单元身份、安装位置或可复核入口及其当前内容；
3. 被验证的环境原生事件、工具调用或 lifecycle 范围；
4. 原始环境上下文如何经薄引用进入共享 Hook 行为，并形成该行为实际使用的输入；
5. 共享 Hook 行为的来源回指、实际 LDVH 核心入口及其内部 Helper 请求/结果，或原生阻断型机械 Gate 的当前来源、核心入口、同一候选绑定与 allow/block 诊断，以及结果如何返回环境和 AI；
6. 至少一个代表性成功路径，以及一个与主要风险匹配的输入缺失、映射拒绝、能力缺口、失败或未验证范围；
7. 实际副作用、未发生副作用、未覆盖事件和环境能力缺口；
8. 安装前后或回滚前后的真实对象回读。

上述链路只要求当次证据可以相互核对，不因此建立统一追踪契约或持久状态；Helper 的部分结果、不可用和未证明范围仍按 04 与 §5.6 保留。

证据只覆盖当次目标环境、版本、入口、事件、工作对象和实际路径。截图、日志、诊断、测试和 Human 观察只在其真实产生范围内作为当次依据，不自动成为稳定事实；需要跨会话保留时必须进入适用事实类型或稳定项目文档，而不是由 adapter 建立永久状态。

### 7.2 断点与 Human 观察

真实验证需要重启、打开新会话、接受平台信任、在目标 UI 操作或观察只有 Human 可见的结果时，AI 必须把断点组织为可恢复的最小验收说明：目标环境、Human 必须执行的动作、正常可观察表现、需要返回的原始结果、复跑入口和当前未验证范围。

Human 只承担环境强制保留给 Human 的授权、信任、重启、界面操作和观察，不负责解释 Helper 契约或判断技术验证是否通过。AI 在恢复后必须重新读取当前安装和来源，不依赖聊天记忆把断点前计划当作当前结果。

当目标环境身份、版本、位置或与执行环境的关系只能由 Human 确认或暴露时，AI 必须先交还最小目标确认请求，而不是要求 Human 猜测技术路径。该请求至少说明当前执行环境和识别依据、待确认目标及候选依据、为何无法由 AI 只读确认、Human 需要返回的原始信息，以及确认后的复跑入口和仍未验证的事件；Human 的确认本身不等于安装、部署、接入或真实触发。

手工 adapter 调用、fixture 或 shell 直调可以用于诊断，但不能替代目标环境真实自动触发。目标环境无法在当前执行环境中验证时，应保持相应范围未验证，并交还取得真实证据的入口，不得伪造跨环境结论。

## 8. 具体环境来源与 adapter 实现

每个目标环境都必须依据当前官方或实际权威资料核验其事件、payload、权限、安装接口、生命周期、错误表现和可观察入口。厂商协议变化快或只服务一个 adapter 的内容留在该 adapter 的正式来源、实现说明与 tests；只有形成稳定外部契约且满足 01 §13 时，才建立普通规范或授权附件。

这项核验由处理该目标环境的 AI 在用户当前任务中完成；LDVH 只提供调查输入、接入面说明、状态判定、验证与回滚方法，不承诺预制每个厂商的配置步骤或兼容矩阵。这是 LDVH 的设计原则而非临时状态：LDVH 核心只提供环境无关入口，不主动为每个 AI 开发环境提供 adapter；当前发行物附带的单一 adapter 实现仅作为参考，其它 AI 开发环境的 adapter 由处理该目标环境的 AI 在该环境自己的仓库开发，不在 LDVH 仓库收纳或维护。AI 必须保留所用资料的 URL 或稳定定位、观察时间、目标产品版本与平台，并把"未找到"与"肯定不存在"分开。

adapter 实现必须等待本文、04、07 及当次具体环境所需来源成立。Code/tests 可以实现协议解析、输入投影、调用、结果转换、安装器和验证探针，但不能用实现字段反向定义本文语义。mock、fixture 和静态 tests 必须清楚标明替代的真实环境范围。

若不新增任何对象即可把环境原生机制直接配置到既有 LDVH 入口，配置方案可以进入 33；若需要 manifest、脚本或薄 adapter，必须先结束当前安装分支并形成独立普通 Code 计划。adapter 的 Code、tests 和可安装对象完成前，33 只能保存调查结果与缺口，不能把候选设计写成已经存在的接入单元。

一个 adapter 的成功不证明其它环境兼容。多个 adapter 可以复用当前来源已定义的环境无关 LDVH 核心行为、内部 Helper 调用和无厂商语义的机械能力，但不得把厂商协议抽象为通用原生事件或共享 Hook 行为闭集。

## 9. 代表性场景

| 场景 | 处理 |
|---|---|
| 插件文件存在，LDVH 核心或 Helper shell 直调成功，但没有环境事件证据 | 只报告静态对象与直接调用已观察；环境真实触发和接入保持未验证 |
| 环境事件缺少 LDVH 核心或 Helper 必需的工作对象 | 报告缺失输入和影响；仅在具体来源明确允许时 no-op，否则不形成猜测请求并交还未完成范围；不使用 cwd 或会话名猜测 |
| LDVH 核心或 Helper 返回部分结果，环境只能显示一条消息 | 消息必须说明部分范围并提供完整结果入口；不得显示为完整成功 |
| 目标环境没有阻断 Hook | 如实声明只能提示或不能承接相应强制行为；不把提示表述为阻断保障 |
| 环境新增一个 adapter 未登记的只读工具 | “只读”必须由实际 payload、权威环境语义或可观察副作用证明，不根据工具名猜测；若它未进入任何来源定义的原生 Gate，不得因名称未知默认 block；若确实触发某项 Gate，只按该来源对同一事件的实际候选、目标、候选副作用和缺失输入处理 |
| 原生事件没有通用规则 receipt | 本文不定义这种全局前置状态；先按实际事件能力向 AI 交付规则读取缺口。只有另一来源已对同一事件定义机械 Gate 时，才按该来源的候选输入和失败方式处理，不得把缺少通用 receipt 扩张为环境会话阻断 |
| `Stop` 事件能够运行检查脚本 | 只证明该原生事件和脚本可触发；脚本只能执行来源封闭定义的机械检查或交付实际结果，不得据此宣称全部适用规范、Human Gate、验证与完成条件已经自动判断 |
| 目标环境资料没有使用 Hook 一词，但提供可自动触发的扩展事件 | 按实际输入、反馈和生命周期判断能力，不因术语不同写成 unsupported |
| 调查未找到自动扩展资料或当前账号无权查看配置 | 保持 unverified 并交还缺口；不把资料缺失写成环境无 Hook |
| 权威资料或实际观察肯定证明没有能够承接所需输入与反馈的自动机制 | 相应完整接入为 unsupported；已可用的非自动直接调用能力仍按其实际范围单独表达 |
| 连接既有 LDVH 入口必须新建 manifest 或薄 adapter | 停止安装分支，先按具体环境来源与 07 建立独立 Code 计划；完成后再进入 33 |
| 安装时发现用户自建同名 Hook | 不覆盖；形成冲突与共存方案并进入 Human Gate |
| Human 要求安装并把当前项目纳入管辖 | 分开列出环境安装和 02 管辖配置变化；分别授权、执行、回读和验证 |
| 卸载命令成功但环境仍自动触发旧入口 | 回滚未成立，继续定位残留，不声明卸载完成 |
| 当前环境不能启动目标环境 | 完成静态检查和可行诊断，交还真实环境验收入口，保持 integrated/verified 未成立 |

## 10. 验证要求

共享 Hook 行为、adapter 映射和目标环境真实触发是三个独立验证层；任一层通过均不得替代或倒推其它层。

| 验证对象 | 验证时机 | 成立条件 | 可接受依据 | 验证入口 | 可证明范围 | 未满足时的处理 |
|---|---|---|---|---|---|---|
| 规范身份与责任 | 新建、修改或准备启用本文时 | YAML、直接依据、结构和职责边界符合 00、01、02、03、04；没有复制配置、服务字段、实现或厂商协议 | 当前规则源、准入记录与本文 | 规范回读、机械解析、责任和引用检查 | 当次规范身份与正文 | 保持草案或停止依赖，修正重复、遗漏和错误归口后复核 |
| 单一入口与权威 | 新建或修改环境接入单元时 | 普通环境 Hook 只经其稳定薄引用连接相应 LDVH 核心，直接客户端按需调用 Helper，或只在其它来源已定义时接入同一 Git Gate 或 Hook Gate；adapter 未复制规则、模板、事实 Schema或判断 | 当前来源、adapter/manifest、安装对象 | 来源扫描、Code review、静态与真实调用检查 | 当次环境与接入单元 | 删除重复权威，回到 LDVH 核心、Helper、Git Gate 或 Hook Gate 核心和当前来源修正 |
| 共享 Hook 行为 | 新增或修改承接该行为的共享实现时 | 每项行为及实际 LDVH 核心和内部 Helper 调用，或 Git Gate 或 Hook Gate 对其它当前来源核心实现的直接调用可回指相应当前来源；唯一实现已随 LDVH 核心分发且有明确可调用入口；tests 只固定来源已定义的可观察输入、调用与结果边界 | 当前来源、核心及其内部 Helper 原始请求/响应或 Git Gate 或 Hook Gate 的同一候选绑定与 allow/block 诊断、AI 对照来源的 Code review 与实现级 tests | 先直接调用共享实现，再验证 adapter | 当次共享 Hook 行为、操作与受测输入 | 停止供 adapter 引用；删除无来源、语义判断或越权行为，不以 adapter 映射或真实触发结果倒推通过 |
| 已迁移 Hook 冻结性 | 迁移既有 Hook 后，或核心规则、事实或交付能力演进时 | Hook 仅投影实际原生输入、调用固定核心入口、如实映射结果；核心新增能力不要求修改既有 Hook | 原生输入、既有 Hook、固定核心引用、核心结果与差异 | Hook contract tests、核心回归与差异审核 | 当次既有 Hook、核心调用及结果映射 | 停止将该能力接入旧 Hook，改报未交付范围 |
| 同一薄引用的事件新增 | 新增事件注册时 | 当前规则源、环境协议、实际输入输出兼容性与接入需求均有依据；新增仅为事件注册 | 当前来源、环境资料、原生输入输出与既有引用边界 | 来源回读、映射 contract tests 与需要时真实触发 | 当次新事件与既有薄引用 | 删除预注册或不兼容注册 |
| 独立 Hook 分流 | 新事件或能力与既有薄引用不兼容时 | 新 Hook 独立设计、实现和验证，既有 Hook 未被改写 | 不兼容依据、独立实现与验证记录 | 07 规划和 tests、09 接入验证 | 当次新 Hook 与既有 Hook 的边界 | 撤回表面兼容设计 |
| 历史入口非回退 | 既有 Hook 或核心不能承接新能力时 | 不兼容路径不会自动调用历史上下文恢复或旧策略；若历史入口被调用，能证明其自身前提成立 | 调用记录、配置、核心结果与来源 | negative tests、调用审查与实际映射 | 当次未承接范围与历史入口调用 | 报告未交付或不兼容，不得宣称新能力已交付 |
| Helper 与 Git Gate/Hook Gate 双入口一致性 | 同一机械检查同时提供 AI 主动预检和原生环境阻断时 | 两入口按照同一当前来源形成检查输入，观察各自当次绑定候选并调用同一份确定性检查实现；Helper 返回结构化机械结果，Git Gate 或 Hook Gate 以真实事件输入重新检查且只映射 allow/block；入口代码未复制规则或校验逻辑 | 当前来源、Helper 请求与响应、Git Gate 或 Hook Gate 实际输入与诊断、实现依赖，以及同一绑定候选与 message 或等价底层输入的一致性 tests | Helper 直接调用、Git Gate 或 Hook Gate 直接调用、真实 Git 事件和 Code review | 当次来源、机械检查、候选及两个受测入口 | 停止接入或能力声明；删除重复逻辑并回到同一来源和检查实现，重新完成双入口和真实事件验证 |
| 输入与结果映射 | 新增事件、字段、操作或反馈时 | 输入身份未被猜测或覆盖；结果保留成功、部分、失败、来源和能力差异 | 环境原始输入、LDVH 核心及其内部 Helper 请求/结果、映射输出 | contract tests、fixture 与真实环境事件对照 | 当次事件和映射 | 拒绝错误映射，或仅在来源允许时 no-op，并交还输入、能力或验证缺口；不启用错误映射 |
| 原生 Gate 与 AI 行动边界 | 新增或修改阻断型事件、行动分类或 adapter 映射时 | allow/block 只作用于来源绑定的同一原生事件与实际候选；不存在全局工具、命令或动作白名单；未登记名称和无关行动不会被外推阻断 | 00、07、Gate 来源、原始事件、实际候选、已知与未知名称样例、环境反馈 | shared core tests、adapter negative tests 与代表性真实事件 | 当次 Gate、adapter、原生事件、候选和受测无关行动 | 停止接入或阻断声明；删除默认拒绝与名称白名单，按来源、事件、目标和副作用重新限定 |
| 安装和变更 | 写入前后 | 目标、现状、安装位置和可触发会话范围、授权、计划写入、用户资产、验证和回滚清楚；实际变化完整回读 | Human 指令、安装前后对象、环境与安装器结果 | 只读检查、受控执行和安装对象回读 | 当次授权与实际变化 | 不写入、回滚可恢复变化或交还残留与风险 |
| 真实自动触发 | 声称环境接入或 integrated 时 | 目标环境实际事件自动进入接入单元，普通接入经稳定薄引用调用相应 LDVH 核心并忠实映射核心结果；Git Gate 或 Hook Gate 仅在其来源已定义时调用同一核心并忠实返回 allow/block；成功与主要失败路径有当次依据 | 环境事件/日志、核心及其内部 Helper 调用、Git Gate 或 Hook Gate 调用、反馈和观察 | 目标环境代表性真实触发 | 当次环境、版本、入口和事件 | 只声明静态安装或直接可调用；保持真实接入未验证 |
| 禁用、卸载与回滚 | 准备声明连接已移除或恢复时 | 目标环境不再自动触发或已恢复基线；LDVH 管理对象已处理；无关用户资产未受损 | 前后基线、安装对象、环境事件和残留检查 | 卸载/回滚后回读与真实触发反例 | 当次目标和可观察范围 | 不声明回滚完成；继续修复或交还不可恢复范围 |
| 证据与声明范围 | 使用安装、测试或触发结果支持能力结论时 | 对象、环境、版本、入口、事件、时间、结果和未验证范围可回指，结论未扩大 | 实际输出、日志、回读、Human 观察和 tests | AI 对照来源审核 | 当次取得证据的范围 | 缩小或撤回声明，补充范围匹配证据 |

本文所涉 adapter、安装器、环境 Hook、测试与平台配置的能力声明，按 00 §9 及上表对应验证对象判断。

## 11. Human Gate

以下事项必须进入 Human Gate：

1. 安装、升级、启用、禁用、卸载或迁移环境插件、Hook、扩展、Skill、adapter 或配置；
2. 接受平台信任、权限、登录、重启或其它只能由 Human 完成的环境动作；
3. 覆盖、合并、删除或放弃无法证明由 LDVH 管理的既有用户资产；
4. 修改管辖项目配置、初始化项目事实源或扩大安装到其它工作区、项目、用户或环境；
5. 在目标环境不具备所需能力时，决定是否接受已说明的能力缺口、受影响保障和残留风险；
6. 无法完整回滚、恢复基线或确认无关用户配置不受影响时仍决定执行；
7. 改变跨环境共同责任、让 adapter 复制规则/模板，或把某厂商协议提升为通用规则。

Human 决定的复用按 00 §10 执行；安装授权不能替代技术验证，风险接受不能把未验证写成通过，当前环境授权也不能扩张到其它环境。

## 12. Stop Conditions

出现以下任一情况时，暂停受影响的安装、环境触发或接入声明：

1. 目标环境、版本、工作区、工作对象、当前规则源，或者实际适用的 LDVH 核心入口及其内部 Helper 入口，或原生 Gate 核心入口无法确定；
2. adapter 正在复制规范、模板、事实 Schema、领域状态机或自然语言判断；
3. 环境输入缺失或未知，却准备猜测 target、cwd、管辖、授权或操作；
4. LDVH 核心或其中 Helper 的部分、失败、拒绝、来源或能力缺口被环境映射吞掉或改写；
5. 计划写入、删除、权限、用户既有资产、验证入口或回滚方式不清楚；
6. 缺少覆盖实际副作用的 Human 授权；
7. 准备把安装文件存在、fixture、手工调用或 shell 直调声明为真实自动触发或 integrated；
8. 目标环境真实事件没有经稳定薄引用调用相应 LDVH 核心，或原生阻断型机械 Gate 没有在同一候选、来源、管辖和 Index 身份上调用同一核心实现，或结果无法回指当次请求与反馈；
9. 禁用、卸载或回滚后仍存在自动触发、未知残留或无关用户配置损坏；
10. 当前环境无法验证目标环境，却准备作出跨环境通过结论；
