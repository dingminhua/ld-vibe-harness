## 1. 本文定位

本文定义 Memo 事实模型使用的结构化数据契约。本文解决 Memo YAML 实例应包含哪些字段、字段类型和约束是什么、文件命名规则是什么、状态流转契约是什么，以及工具实现应如何消费本契约的问题。

本文是 Memo 事实模型契约字段的权威位置。本文是 `specs/25-Memo-备忘.md` 的附件型契约子文档，不是独立事实模型。本文不得重新定义 Memo 的对象定位、准入条件、状态机语义、Human Gate、事实源回写或证据留存要求。发生冲突时，以 25 主文档和上位基础规范为准。

本文不承载执行逻辑、流程步骤或 Human Gate 条款（依据 `specs/04-LDVH模型子文档规范.md` §7.1）。

## 2. Memo YAML Schema

### 2.1 基础字段

Memo 基础字段遵循 `specs/13-LDVH事实模型基础规范.md` §7.3 的字段契约原则，所有事实模型应包含基础字段。

| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | Memo 对象 ID，格式为 `memo-{NNNN}` |
| `type` | string | 是 | 固定为 `memo` |
| `title` | string | 是 | 备忘标题 |
| `status` | string | 是 | Memo 状态，必须属于标准状态枚举 |
| `created` | date | 是 | 对象创建日期 |
| `updated` | date | 是 | 最近更新日期 |

### 2.2 扩展字段

| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `description` | string | 是 | 备忘详细描述 |
| `source` | string | 是 | 来源 |
| `category` | string | 是 | 分类：`discovery`/`reminder`/`question`/`gap`/`preference` |
| `priority` | string | 否 | 优先级：`low`/`medium`/`high`，默认 `low` |
| `resolved_to` | string | 条件必填 | 仅当 `status` 为 `resolved` 时必须填写，分流目标对象 ID |
| `resolved_at` | date | 条件必填 | 仅当 `status` 为 `resolved` 时必须填写 |
| `related_tasks` | list of string | 否 | 关联 Task ID 列表 |
| `related_adrs` | list of string | 否 | 关联 ADR ID 列表 |
| `related_evidence` | list of string | 否 | 关联 Evidence ID 列表 |

### 2.3 完整 YAML 示例

```yaml
id: memo-0001
type: memo
title: 规范文档中缺少错误处理章节
status: resolved
created: 2026-06-04
updated: 2026-06-04
description: 在审查 specs/13 时发现缺少错误处理和异常场景的统一规范，需要后续补充
source: 执行 task-0003 过程中的发现
category: gap
priority: medium
resolved_to: task-0012
resolved_at: 2026-06-04
related_tasks:
  - task-0003
related_adrs: []
related_evidence: []
```

## 3. 字段约束

1. `status` 必须属于 Memo 标准状态枚举：`draft`、`active`、`resolved`、`archived`；
2. `type` 必须固定为 `memo`；
3. `category` 必须属于分类枚举：`discovery`、`reminder`、`question`、`gap`、`preference`；
4. `priority` 必须属于优先级枚举：`low`、`medium`、`high`；未填写时默认为 `low`；
5. `resolved_to` 仅在 `status: resolved` 时必填，其他状态下不得填写；
6. `resolved_at` 仅在 `status: resolved` 时必填，其他状态下不得填写；
7. `resolved_to` 应引用已存在的事实模型 ID（如 `task-{NNNN}`、`adr-{NNNN}`、`intent-{NNNN}`），引用无效时应标记为校验警告；
8. `related_tasks` 应引用已存在的事实模型 ID，引用无效时应标记为校验警告；
9. `related_adrs` 应引用已存在的事实模型 ID，引用无效时应标记为校验警告；
10. `related_evidence` 应引用已存在的事实模型 ID，引用无效时应标记为校验警告；
11. `id` 格式必须为 `memo-{NNNN}`，编号固定 4 位，从 `0001` 起递增；
12. `created` 和 `updated` 使用 ISO 8601 日期格式（`YYYY-MM-DD`）；
13. `resolved_at` 使用 ISO 8601 日期格式（`YYYY-MM-DD`）；
14. `related_tasks`、`related_adrs`、`related_evidence` 为列表类型，可为空列表，不得省略字段后以 null 替代空列表。

## 4. 文件命名契约

Memo 实例文件命名规则：

```text
memo-{NNNN}-short-title.yaml
```

约束：

1. 编号从 `0001` 起递增，固定 4 位；
2. 英文短标题使用小写短横线命名；
3. 每个项目独立编号，不使用跨项目全局编号；
4. 文件存放位置为 `ldvh-base/memos/`；
5. 文件名变化必须同步检查所有引用该 Memo 的 `related_tasks`、`related_adrs`、`related_evidence` 和其他关联字段。

## 5. 状态流转契约

Memo 状态语义和流转规则由 `specs/25-Memo-备忘.md` §5 定义，本文只提供结构化枚举和流转矩阵供 Tools 校验消费。

### 5.1 标准状态枚举

| 标准状态 |
|---|
| `draft` |
| `active` |
| `resolved` |
| `archived` |

状态含义依据 `specs/25-Memo-备忘.md` §5.1。

### 5.2 合法状态流转

| 当前状态 | 可流转至 |
|---|---|
| `draft` | `active`, `archived` |
| `active` | `resolved`, `archived` |
| `resolved` | `archived` |
| `archived` | 无 |

`draft` → `archived` 为直接归档流转，表示记录后判断不需要保留。
`active` → `resolved` 为分流流转，必须填写 `resolved_to` 字段。

流转语义和约束依据 `specs/25-Memo-备忘.md` §5.2。

## 6. 契约消费声明

1. Tools 辅助程序解析 Memo 时应依据本文定义的 YAML schema 和字段约束，不得自行扩张格式契约（依据 `specs/12.01-Tools辅助规范.md` §6.1）；
2. Tools 辅助程序校验 Memo 时应覆盖字段完整性、状态合法性、条件必填和引用有效性；
3. Tools 辅助程序读取 Memo 时可依据本文状态枚举和字段契约执行状态筛选、详情解析和关联字段解析，但 Memo 读取结果是否可作为当前执行依据由 25 主文档和 Skill 流程判断；
4. 实践子文档和工具可以消费本文契约，但不得复制维护契约字段第二事实源（依据 `specs/04-LDVH模型子文档规范.md` §7.2）；
5. 修改本文契约属于规范变更，应评估 Human Gate 并记录 Change（依据 `specs/04-LDVH模型子文档规范.md` §7.3）（依据 specs/22-Change-变更记录.md）；
6. 契约子文档应先于工具实现创建，工具实现不得在没有契约子文档的情况下自行定义字段名、字段类型或字段约束（依据 `specs/04-LDVH模型子文档规范.md` §7.4）；
7. 本文契约变更时，消费本文的 Tools 实现和对应测试必须同步更新（依据 `specs/04-LDVH模型子文档规范.md` §7.4、§8）。

## 7. 检查项

检查本文是否被正确使用时，应确认：

1. Memo YAML 实例字段是否完整，必填字段是否齐全；
2. `status` 是否属于标准状态枚举；
3. `type` 是否固定为 `memo`；
4. `category` 是否属于分类枚举；
5. `priority` 是否属于优先级枚举（未填写时默认 `low`）；
6. `resolved` 状态的 Memo 是否已填写 `resolved_to` 和 `resolved_at`；
7. `resolved_to` 引用的事实模型 ID 是否有效；
8. `related_tasks` 引用的事实模型 ID 是否有效；
9. `related_adrs` 引用的事实模型 ID 是否有效；
10. `related_evidence` 引用的事实模型 ID 是否有效；
11. 文件命名是否符合 `memo-{NNNN}-short-title.yaml` 格式；
12. 状态流转是否合法，是否存在非法流转；
13. 终态 Memo 是否存在重开情况；
14. 工具实现是否依据本文 schema 解析和校验，未自行扩张格式契约；
15. 修改本文是否记录 Change，并在必要时触发 Human Gate（依据 specs/22-Change-变更记录.md）
