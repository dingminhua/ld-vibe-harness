## 1. 定位

本文承载 01 授权的 `v2_attachment` 字段表和附件身份状态闭集。

01 正文定义附件授权、附件命名、附件权威边界、Human Gate 和 Code 覆盖边界；本文只能维护 `v2_attachment` 字段表和字段值域，不得单独改变附件授权原则、附件命名规则、附件权威边界、父规范确认规则或 Code 输出 Schema。

规范身份字段表由 `attachments/01.Att.04-规范身份字段表.md` 承载。身份一致性辅助核对表由 `attachments/01.Att.06-身份一致性辅助核对表.md` 承载。

## 2. `v2_attachment` 字段表

附件必须提供 `v2_attachment` 或等价身份块。字段契约如下：

| 字段 | 出现要求 | 含义 |
|---|---|---|
| `attachment_id` | 必须出现 | 附件编号，必须与文件名一致 |
| `title` | 必须出现 | 附件标题，必须与一级标题一致 |
| `status` | 必须出现 | 附件状态；必须使用本文定义的闭集 |
| `authority` | 必须出现 | 权威状态；必须使用本文定义的闭集 |
| `parent_spec` | 必须出现 | 授权父规范路径 |
| `canonical_path` | 必须出现 | 附件真实路径 |
| `purpose` | 必须出现 | 附件用途 |
| `migration_sources` | 必须出现 | 迁移来源；无来源时使用空列表 |
| `code_consumption` | 必须出现 | Code 或知识地图消费该附件的类别提示 |

## 3. 附件身份状态闭集

附件身份块使用以下闭集：

| 字段 | 允许值 | 含义 |
|---|---|---|
| `status` | `draft` | 写作中，未完成父规范核对，未 active |
| `status` | `ready_for_review` | 已完成本轮写作，等待随父规范核对 |
| `status` | `active` | 已随父规范确认并切换为 active |
| `status` | `deprecated` | 已废弃或被替代；必须说明替代事实源或关闭理由 |
| `authority` | `not_active_until_parent_and_human_approved` | 未经父规范授权和 Human 确认前的附件权威状态 |
| `authority` | `active_with_parent` | 已随父规范成为 active 附件 |
| `authority` | `deprecated_by` | 已由其它 active 事实源替代 |
