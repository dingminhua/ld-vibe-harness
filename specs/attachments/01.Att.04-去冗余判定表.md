## 判定分类

| 分类 | 含义 | 处理方式 |
|---|---|---|
| `parent_rule` | 多个子规范重复的通用 doctrine | 上收到父层规范 |
| `local_delta` | 子规范特有场景、边界、例外或更严格要求 | 保留在子规范 |
| `parse_skeleton` | Code 解析需要的身份块、章节角色、表格结构 | 保留结构，压缩重复正文 |
| `code_check` | 可由 Code 机械检查的重复要求 | 转为 schema / validator / diagnostics |
| `guide_projection` | 可由 Action Guide 当次生成的读取、停止、影响和下一步查询 | 不手写为长期重复清单 |
| `migration_evidence` | 临时扫描、样板、对照和过程记录 | 留在 `_migration/`，不进入正式规范 |
| `do_not_reduce` | 删除会损害本地边界或 Human Gate 的内容 | 不做去冗余 |

## 必须保留的内容

1. 本地 Human Gate；
2. 本地事实源边界；
3. 行动特有 Scenario、Context、准入条件和执行流程差异；
4. 本地回写、验证和证据要求；
5. 影响 Code 确定性解析的 identity block、章节角色、状态、附件引用和 source refs。

## 优先上收或生成的内容

1. 通用 Human Gate doctrine；
2. 通用事实源 doctrine；
3. 通用 Code 不授权、不写入、不替代事实源声明；
4. 重复成员一致性检查；
5. 重复读取路线；
6. 重复停止条件和 next_queries。

## 判断问题

每次去冗余前必须回答：

1. 删除或上收后，AI 是否更少读、更少猜、更容易停止；
2. 子规范是否仍能表达本地 delta；
3. Code 是否仍能确定性解析；
4. Action Guide 是否能回指来源；
5. Human Gate 是否仍清楚；
6. 是否制造了第二事实源。
