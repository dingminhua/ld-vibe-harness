## 1. 定位

本文承载 07 授权的过程输出回写辅助核对表。

07 正文定义过程输出和工具输出的回写原则；本文只提供检查用清单，不得定义新的回写条件、事实模型字段、行动编排步骤、Code 输出 Schema 或 Web 写入能力。

## 2. 应判断回写的内容

过程输出中的内容满足以下任一条件时，应按对应规范判断是否回写 Git 文件事实源：

| 条件 | 可能归属 |
|---|---|
| 形成任务、决策、经验、风险、缺口、火花、验收、关闭判断或事实源修改追溯 | WorkCase、ADR、Pitfall、Spark、Git commit records |
| 形成规范规则、目录边界、对象字段、状态机、Human Gate 条件或长期协作约束 | 正式规范、附件、ADR |
| 形成管辖项目配置、正式报告正文、长期资料或可复用项目事实 | 管辖项目配置、docs 正文、Study、docs/sources |
| 形成验证结论、测试证据、失败诊断、降级说明或残留风险，且后续流程需要稳定追溯 | WorkCase、Git commit records、Pitfall、ADR、Human Gate 记录或 08 授权的验证声明回指 |
| 形成需要 Human 确认、授权、接受或驳回的事实性记录 | Human Gate 记录、ADR、WorkCase、对应事实源字段 |

测试输出本身不得被提升为独立事实源。只有稳定验证结论、残留风险、失败诊断或 Human 验收记录按对应事实模型、Git 追溯、Human Gate 或 08 验证声明规则写入权威位置后，才形成可追溯事实。

## 3. 禁止直接回写的内容

以下内容不得直接回写为稳定事实：

1. 未标明来源或无法复查的模型判断；
2. 未通过必要 Human Gate 的授权、验收、状态流转或高影响结论；
3. 未验证且被表述为已验证的测试结果、检查结论或完成判断；
4. 与现有权威事实冲突且未完成冲突处理的候选内容；
5. 只为当前对话可读性生成的摘要、排序、筛选、UI 状态或缓存内容；
6. 安装、初始化、环境确认、工具可用性、入口存在性或适配措施现场状态的长期登记；
7. v2 切换前历史事实源中的旧状态、旧字段或旧目录，未经过 v2 归属、核对和 Human Gate 就直接继承为新事实。

## 4. 无法回写时的交还要求

无法完成回写时，过程输出应说明：

| 内容 | 要求 |
|---|---|
| 未回写原因 | 说明是缺少来源、缺少 Human Gate、冲突未解、目标事实源不明确、验证不足还是权限不足 |
| 残留风险 | 说明不回写会带来的执行、追溯或判断风险 |
| 建议权威位置 | 给出候选事实源路径、对象类型、规范编号或附件归口 |
| 后续分流 | 说明应创建 WorkCase、ADR、Spark、Pitfall、Study，还是等待 Human 确认 |

不得把“已展示”“已输出”“已生成候选草案”“已由工具发现”表述为稳定事实已形成。

## 5. 辅助核对表

| 核对项 | 标准 |
|---|---|
| 来源可复查 | 可回指路径、对象 ID、commit hash、章节锚点、命令或 Human 输入 |
| 归属明确 | 已判断目标事实源或说明无法判断 |
| Human Gate | 高影响确认、授权、验收和状态流转已通过必要确认 |
| Git 追溯 | 写入后能通过 Git commit records 追溯 |
| 不制造第二事实源 | 过程输出没有与权威事实源并行维护同一事实 |
| 历史提取受控 | 历史记录内容进入新事实源前已完成最小事实提取和 v2 归属判断 |
