# 专业文档生成组工作机制说明（独立版）

> 这份文档用于说明“这个专家团是怎么工作的”，包括：
> - 整体工作流含义
> - 专家（成员）之间如何协作
> - 什么时候触发哪些流程
> - 最终怎么产出可交付内容

## 一、什么是“工作流”

在这个专家团中，**工作流**的意思是：

- 不再靠单一角色“拍脑袋”完成任务；
- 而是将任务拆成多个阶段；
- 每个阶段由固定角色接力处理；
- 每一阶段都有明确输入输出；
- 每一步失败都有退化/重试策略。

一句话总结：

> **工作流 = 角色分工 + 阶段闭环 + 规则化触发 + 可追溯结果的协作方式。**

## 二、整体协作机制（团队机制）

### 1) 参与角色

- **主理人（总编辑）**：项目统筹、拆解章节、维护参数一致性、阶段调度、最终汇编交付。
- **检索员**：负责资料检索与证据链整理，提供可追溯来源。
- **生成员**：基于检索材料生成章节正文与结构化表述。
- **审核员**：做质量审核，输出 PASS/REVISE 及修改项。

### 2) 主理人机制

主理人不直接替成员“写文档内容”，而是负责：

- 明确文档目标（类型、行业、范围、质量要求）
- 生成项目参数卡（项目名、核心参数、约束、已完成章节摘要）
- 为每个成员下发任务输入，保证上下文一致
- 把检索结果转给生成员，把生成稿转给审核员
- 合并通过审核后的章节，进行跨章引用、编号、术语、格式统一

### 3) 三层一致性机制

1. **输入一致性**：每个角色每次都共享同一版“项目参数卡”。
2. **事实一致性**：检索与引用必须有来源；无来源时标记缺口，不允许编造。
3. **格式一致性**：统一章节层级、引用格式、术语标注、待补充标记。

## 三、六阶段主线（通用骨架）

### Phase 1：需求分析

- 明确文档类型（方案/说明书/手册/报告等）
- 明确行业与场景（建筑/IT/金融/医疗等）
- 生成章节目录与每章要点
- 形成初版项目参数卡

### Phase 2：知识检索

- 按章节检索行业标准、历史案例、技术参数、关联信息
- 输出结构化检索报告：来源、相关性、引用边界
- 若检索无结果：不虚构，转入缺口声明逻辑

### Phase 3：内容生成

- 基于检索报告与参数卡，生成该章正文
- 输出 Markdown 结构：标题、段落、表格、引用、清单等
- 不确定值统一标注为 `[待填写]`

### Phase 4：质量审核

- 从逻辑、规范一致、参数、完整性、格式、跨章一致性六维审视
- 输出 PASS / REVISE
- REVISE 时返回明确修改项，最多循环 2 次后继续推进

### Phase 5：整合汇编

- 按章节序汇总
- 自动生成目录
- 校验章节引用、术语表、统一编号与版式
- 聚合“信息缺口声明”和“审核警告”

### Phase 6：交付输出

- 输出完整文档（封面、目录、正文、附录、待完善事项、免责声明）

## 四、触发与路由（何时走哪条机制）

### 1) 单一动作路由

| 用户意图 | 处理方向 |
|---|---|
| 只要查资料 | 直接进入检索员机制 |
| 已有资料要写章节 | 直接进入生成员机制 |
| 只要审稿/一致性检查 | 直接进入审核机制 |

### 2) 完整任务路由（含 A-F）

| 请求类型 | 采用流程 |
|---|---|
| 帮我写一份方案/说明/手册（未注明草稿） | 完整工作流（A） |
| 按模板生成/按模板填写 | 模板填充流程（B） |
| 补写某章或重写部分章节 | 增量流程（C） |
| 快速草稿/免审核 | 草稿流程（E） |
| 只要审一篇已有文档 | 独立审核流程（D） |
| 章节较多且要求加速 | 并行机制（F） |

## 五、A-F 补充说明（每条都对应一套执行清单）

### Workflow A：完整长文档生成（默认）

**适用**：用户说“帮我写一份方案/说明/手册”等完整任务，未注明快速/增量/仅审核。

**执行内容**：

1. 主理人先定义文档范围与受众，生成章节目录与参数卡。
2. 每一章按“检索→生成→审核”循环：
   - Phase 2 调 `doc-researcher` 输出可追溯检索报告
   - Phase 3 调 `doc-generator` 输出该章初稿
   - Phase 4 调 `doc-auditor` 做 6 维审核
3. 循环通过后，主理人进入 Phase 5 全文汇编。
4. 最终交付 Phase 6 的完整版本（含免责声明与待完善事项）。

**关键输出**：一份完整文档及章节级更新日志。

### Workflow B：模板填充

**适用**：用户上传/粘贴模板，或说“按这个模板填写”。

**执行内容**：

1. 主理人先抽取模板章节结构，快速形成目录。
2. 对每个模板条目循环执行 Phase 2→3→4（检索可按需要触发）。
3. Phase 5 仅做最小化整合：保留用户模板原有编号与表格结构。
4. 输出时把缺失值统一写 `[待填写]`，避免出现 XX/___。

**关键输出**：保持模板骨架的可发布版本。

### Workflow C：增量修订/补章

**适用**：用户说“补写第X章”“重写某一章”。

**执行内容**：

1. 主理人基于原文上下文提炼该章目标与上下文边界。
2. 只对目标章节走 Phase 2→3→4。
3. 若用户只要该章，不执行全局 Phase 5；只做局部核对。
4. 输出该章修订稿，必要时附修改说明。

**关键输出**：独立章节稿或若干章节更新。

### Workflow D：独立审核（只评估）

**适用**：用户说“帮我审一下这篇文档”或“检查一致性”。

**执行内容**：

1. 主理人先解析文档结构（分章/分节）。
2. 每章单独提交给 `doc-auditor`。
3. 审核结束后汇总为统一报告：
   - 必须修复项
   - 优化建议
   - 全文一致性风险

**关键输出**：问题清单与修订建议（不直接改正文）。

### Workflow E：快速草稿（跳审核）

**适用**：用户明确“快速生成”“草稿即可”“不需要审核”。

**执行内容**：

1. 仍做需求拆解与章节规划。
2. 跳过 Phase 4 审核，直接执行 Phase 3（生成）后进入简化汇编。
3. 明确提示“本次为草稿，未经审核”。

**关键输出**：时效优先版本，带风险边界提示。

### Workflow F：多章节并行加速

**适用**：文档章节数较多（通常 >5）且用户要求并行提速，且章节间耦合度不高。

**执行内容**：

1. 主理人先划分可并行章节簇（如“设备/结构/给排水”分别独立）。
2. 同步调度多位检索员并行产出。
3. 并行收口：并行传给生成员，再统一串行汇总给审核员做跨章一致性复核。
4. 一旦发现冲突，由主理人裁定并回流对应生成员修订。

**关键输出**：更快的总产出速度，依赖“参数卡+跨章复核”兜底一致性。

### 退化与边界（适用于 A-F）

- 任何检索缺口都必须以 `[待填写]` 显式落地；
- Phase 4 两次修订仍不通过时，按第 3 轮强制通过并追加审核警告；
- 如果团队成员临时不可用，主理人按规则重试一次并向用户说明降级方案。

## 六、专家机制（每位专家的“职责闭环”）

### 1) 检索员机制

**输入：**章节标题、要点、项目参数卡、检索模式。
**产出：**结构化检索报告（来源、相关度、适用范围、缺口）。
**重点约束：**无结果不编造；缺口必须显式标注。

### 2) 生成员机制

**输入：**检索报告、项目参数卡、模板（如有）。
**产出：**章节正文（可直接进入审核）。
**重点约束：**严格围绕输入材料写作；统一引用格式；缺值用 `[待填写]`。

### 3) 审核员机制

**输入：**待审章节内容 + 检索报告 + 参数卡。
**产出：**PASS/REVISE + 修改清单。
**重点约束：**6 维度审核；不做正文重写。

### 4) 主理人机制

**输入：**用户需求 + 全局参数 + 各成员输出。
**产出：**最终交付版本。
**重点约束：**不能跳过检索/审核关键环节（除用户明确要求快速草稿），保持过程可追溯。

## 七、常见误区与说明

1. **“工作流不是单个模型的对话”**
   不是让一个人一口气完成全部，而是“多人分工+阶段校验”。

2. **“专家团不是会互相私下沟通”**
   信息统一由主理人中转，减少偏差与重复。

3. **“没有来源就不硬写”**
   对于关键数字、规范条文、参数约束，必须可追溯；缺口留待后续补充。

4. **“快模式并不代表低质量无限制”**
   快速草稿会跳过审核，但会明确标注风险边界。

## 八、一句话版总结

> 这个专家团通过“需求分解 + 资料证据 + 人工校验 + 分阶段交付”形成可重复流程：
> **主理人**负责流程控制，**检索员**负责证据，**生成员**负责写作，**审核员**负责质量，最终形成可追溯、可修订的文档输出。
