## 1. 本文解决的问题

本文解决 LDVH 中工作流程区段如何登记、讨论、检查和被初始化或审计流程消费的问题。

本文是 40-59 工作流程区段的规范型集合索引。AI 和 Human 在进入具体工作流程前，应先通过本文确认：

1. 哪些编号已经占用；
2. 哪些工作流程是 active、next、planned、candidate、reserved 或 removed；
3. 哪些候选流程尚未生效；
4. 每个候选流程在正式创建前需要先讨论哪些边界；
5. 产品初始化和产品审计应读取哪些 active 工作流程，并把哪些 planned 工作流程作为讨论输入；
6. 后续讨论顺序如何表达。

本文不定义具体工作流程的 Context、Scenario、Gate、执行流程、证据规则、事实源回写要求或行动特有检查。这些内容由 41-59 具体工作流程规范承载。

---
## 2. 与 00 和 06 的关系

00 定义 LDVH 工作流程是五类构成要素之一，用于控制 AI 如何读取、判断、执行、验证、回写和暂停。06 定义工作流程的基础规则、标准组成、准入条件、主控调度、事实源回写和检查要求。

本文承接 06，只维护工作流程集合的清单、状态、候选来源、讨论顺序和产品级初始化/审计输入。本文不得反向改写 06 的通用规则，也不得替代 41-59 具体工作流程规范。

## 5. 工作流程集合闸门

创建、删除、恢复或调整工作流程前，必须先通过本文判断集合状态，再决定是否创建或修改 41-59 文档。

集合闸门规则如下：

1. `active` 项可以作为当前权威工作流程入口；
2. `next` 项是下一优先讨论对象，不表示对应主文档已经生效；
3. `planned` 项已确认需要成为具体工作流程，但创建主文档前仍需讨论 Context、Scenario、Gate、事实源回写、机制适配和测试锚点；
4. `candidate` 项不得因为已有 Skill 或临时参考资料而自动生效；
5. `candidate` 项在正式创建前必须先判断是否应归为工作流程、Skill、Code、Web、最佳实践、工作对象规则或一次性执行策略；
6. `reserved` 编号不得绕过 Human Gate 占用；
7. 临时参考资料和临时 Skill 只能作为候选输入，不自动成为当前权威规范。

每个候选流程进入讨论时，至少应确认：

1. 该事项是否满足 06 的工作流程准入条件；
2. 是否需要独立主文档，还是应并入已有流程、工作模型、Code、Web、最佳实践或运行投影；
3. 该流程的核心 Context、Scenario、Gate、执行、回写、证据和失败降级是什么；
4. 是否需要 Skill、Agent、Rules / Instructions、Code、Web、Hook、CI 或人工降级共同承接；
5. 是否存在临时 Skill、固定机制子文档、临时路径、不推荐表达或与当前规范不一致的内容；
6. 行动特有可测试性锚点如何写入主文档；
7. 创建或修改该流程是否触发 Human Gate。

## 6. 临时参考吸收边界

工作区根目录 `临时参考/` 是当前维护环境中的候选输入，不属于 LDVH 权威事实源，也不属于管辖项目安装后默认存在的目录。

吸收临时参考资料时，应遵守以下规则：

1. 只吸收意图、流程经验、触发场景、输入输出和风险提示，不复制临时路径、临时编号或固定机制子文档结构；
2. 临时 Skill 不直接定义工作流程，必须回到 06、03.05、本文和 41-59 主文档重写；
3. 临时 Skill 中涉及非当前路径的内容，应按 `docs/specs/` 和 20-39 工作模型规范重新定位；
4. 临时 Skill 与当前规范冲突时，以 `docs/specs/` 正式规范为准；
5. 临时 Skill 内部如果出现互相冲突的 Human Gate 描述，应在具体流程讨论时重新判定，不得按临时 Skill 原文执行；
6. 临时 Skill 中“Skill 调用 Agent”“Skill 内部链式调度 Skill”等写法，应按 06 的主控唯一调度原则改写；
7. 临时参考资料中的完成勾选或验证结论，不等于当前正式规范已创建或已生效。

## 8. 初始化与审计输入

产品初始化和产品审计读取本文时，应至少确认：

1. 40 集合索引是否存在且与 01、03.03、06、03.05 一致；
2. active 工作流程是否均有当前主文档；
3. next、planned 和 candidate 项未被当作已经生效的具体工作流程执行；
4. 临时 Skill 和 `临时参考/` 未被当作当前权威事实源；
5. 每个 active 流程是否能说明其规范落地要求、环境适配映射、运行投影、Code/Web 联动和测试锚点；planned 流程是否已登记创建前需要讨论的上述边界；
6. 具体工作模型规范中的“后续由工作流程承接”事项，是否已在本文登记为 planned、candidate 或待补齐事项；
7. 41-59 具体流程变化后，是否同步检查 20 工作模型集合索引和对应工作模型规范。

本文只提供初始化和审计输入，不定义产品初始化或产品审计的完整执行流程。

## 9. 集合一致性检查

集合一致性检查至少包括：

| 检查项 | 标准 |
|---|---|
| 编号一致性 | 40-59 编号未重复、未越界，59 未绕过 Human Gate 占用 |

| 状态一致性 | active、next、planned、candidate、reserved、removed 的含义未混用 |
| 集合闸门 | candidate 项未因 Skill 或临时参考资料存在而自动生效 |
| 引用一致性 | 01、03.03、03.05、06、10 和具体工作流程规范对 40 的引用一致 |
| 边界一致性 | 本文未定义具体流程的 Context、Scenario、Gate、执行流程、证据规则或事实源回写要求 |
| 初始化输入 | 产品初始化和审计只把 active 工作流程作为已生效流程输入，把 next/planned/candidate 作为讨论输入 |
| 输入材料边界 | 临时参考资料只作为输入材料，未直接覆盖 `docs/specs/` 正文区结论 |

## 11. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 新增、删除、重命名或重排 40-59 编号；

7. 让本文定义具体流程的 Context、Scenario、Gate、执行流程、证据规则或事实源回写要求；
8. 恢复固定机制子文档作为工作流程完整性要求；
