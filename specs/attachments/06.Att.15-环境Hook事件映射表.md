## 1. 定位

本文承载环境原生 Hook 名称到 LDVH canonical event 的归一化映射表。

LDVH core 只认 canonical event：
- `session-start`
- `pre-tool-use`
- `git.commit-msg`

环境可以用不同的原生事件名，但必须先映射到 canonical event。Rules 方式不走环境原生映射，直接以 `trigger_source=rules` 模拟触发 canonical event。

## 2. 映射表

| 环境原生事件 | 典型环境叫法 | LDVH canonical event | trigger_source | 说明 |
|---|---|---|---|---|
| `SessionStart` | WorkBuddy / Codex / Claude Code | `session-start` | `hook` | 会话开始、恢复或重新握手的入口事件 |
| `UserPromptSubmit` | WorkBuddy / Codex / Claude Code | `pre-tool-use` | `hook` | 用户输入提交后的前置检查入口，可作为工具前检查家族的一种原生事件 |
| `PreToolUse` | WorkBuddy / Codex / Claude Code | `pre-tool-use` | `hook` | 工具调用前检查、阻断或补充上下文的入口事件 |
| `commit-msg` | Git | `git.commit-msg` | `hook` | Git 提交层事件，不属于 AI Hook |
| AI 自觉模拟触发 | Rules | `session-start` / `pre-tool-use` / `git.commit-msg` | `rules` | AI 按 Runtime Protocol 主动模拟触发同一 canonical event |

## 3. 使用规则

1. 环境 adapter 只能把原生事件归一化为 canonical event，不得把环境私有命名写入 core handler 规则。
2. 统一 dispatcher 只处理 canonical event + `trigger_source`。
3. Rules 方式直接触发 canonical event，不经过环境原生事件命名。
4. 触发来源不同，不影响 handler 逻辑的唯一性。

## 4. 待补齐事项

1. 后续如发现更多环境原生事件名，应优先归入本表的既有 canonical event 家族，而不是新建并行事件体系。
2. 若某环境无法提供稳定原生事件名，应回到 Rules 方式或环境入口薄引用路径，不得伪造 Hook 原生语义。
