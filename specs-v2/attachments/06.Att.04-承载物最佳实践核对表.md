## 2. 核对表

| 核对项 | 标准 |
|---|---|
| 薄引用优先 | 不复制完整规范正文、字段契约、状态机或长规则清单 |
| 执行转换清晰 | 能把规范转为步骤、检查顺序、STOP 点、输入输出和交还方式，但不新增规则 |
| 上下文经济 | 默认入口只放广泛适用、移除后会导致错误的规则 |
| 发现条件明确 | 描述、触发条件、matcher、输入 schema 或调用方式清楚 |
| 风险匹配 | 高风险操作有具体命令、审批点和恢复方式 |
| 输入输出明确 | 说明读取事实源、接收输入、产出结果和写回位置 |
| 权限分层 | 写入、提交、外部工具、敏感数据、长期配置或成本风险有审批路径 |
| 失败可见 | 工具不可用、环境不支持、权限不足、引用缺失或校验失败有降级方式 |
| 可观测可验证 | 输出命令、退出码、测试结果、截图、结构化 JSON、文件引用或 Human 审批记录 |
| 多视角审查 | active 前从 Human、Code、Web、AI 执行和行业实践角度审查 |
| 事实源不分叉 | 不复制 specs、工作对象状态、部署状态或环境检查结果为第二事实源 |
| 环境中立 | 权威资产在 LDVH 仓库维护，不等同于环境中已安装文件 |
