## 1. 本文定位

本文是 `specs/23-Pitfall-踩坑记录.md` 的附件型实践子文档（编号 23.04），承接 Tools 契约式校验与执行实践。本文不是独立工作模型，不得重新定义 Pitfall 的对象定位、准入条件、状态机、对象关系、Human Gate、字段契约、事实源回写或证据留存。发生冲突时，以 32 主文档和上位基础规范为准。

---

## 2. 当前状态与未来能力定义

### 2.1 当前状态

Pitfall 专用 Tools 当前未创建（active-prep），原因：

1. LDVH 通用对象校验框架和通用原子写入工具尚未实现；
2. Pitfall 实例数量不足，解析和校验模式的稳定规则尚未充分验证；
3. 当前 LDVH Tools 层只有 ADR 和 Change 的局部实现，通用 YAML 事实实例解析/校验尚处于设计阶段；
4. 在通用工具框架稳定前，为 Pitfall 单独创建 Tools 会导致重复实现和维护成本。

### 2.2 未来能力定义

Pitfall Tools 应具备以下能力：

1. **读取**：读取 `ldvh-base/pitfalls/` 下所有 YAML 实例并解析字段；
2. **解析**：依据 `specs/23.06-Contract.md` 解析 Pitfall YAML 字段；
3. **校验**：字段完整性校验、状态合法性校验、条件必填校验（如 `superseded` 状态必须填写 `superseded_by`）、引用有效性检查；
4. **聚合**：按状态、标签、适用范围、关联对象、严重程度和可复现性筛选和聚合；
5. **受控写入**：创建 Pitfall draft、激活 Pitfall、归档或替代 Pitfall、更新核心经验字段，写入前校验字段和状态，写入后生成 Change 记录；
6. **缺口报告**：识别缺少 active Pitfall 的项目、`superseded` 但 `superseded_by` 引用无效的实例、各项目 Pitfall 标签分布和覆盖率。

Tools 不得生成授权，不得替代 Human Gate，不得自行判断经验的复用价值。

---

## 3. 实现前提

在创建 Pitfall Tools 之前，应满足以下前提：

1. LDVH 通用 YAML 事实实例解析/校验框架已实现或至少具备可复用的解析和校验基类；
2. `specs/23.06-Contract.md` 字段稳定，无大范围变更；
3. `ldvh-base/pitfalls/` 存在至少一个实例可用于工具测试；
4. Pitfall 状态流转规则、字段约束和 Human Gate 检查点可通过 Contract 驱动校验。

---

## 4. 边界约束

1. Tools 应依据 `specs/23.06-Contract.md` 解析和校验，不得自行扩张字段契约（依据 `specs/06-Python与Web工具规范.md §4` §6.1）；
2. 受控写入命令必须携带显式 Human Gate 授权参数，不得绕过 Gate 写入；
3. Tools 不生成授权，不替代 ADR 准入判断、Pitfall 准入判断、流程性判断或 Human Gate 编排；
4. Tools 不得为 Pitfall 维护第二事实源，只读写 `ldvh-base/pitfalls/`；
5. 工具实现不得在没有 `specs/23.06-Contract.md` 的情况下自行定义字段名、字段类型或字段约束。

---

## 5. 检查项

检查 Pitfall Tools 当前 active-prep 状态是否合规时，应确认：

1. Pitfall Tools 是否未在实现前提满足前创建；
2. 当前 AI 是否按 32 主文档和 Contract 的人工方式执行 Pitfall 创建、校验和写入；
3. 人工写入是否已记录降级原因和字段检查。

---

## 6. 待补齐事项

1. 通用对象校验框架实现后，应同步评估 Pitfall Tools 是否满足实现前提；
2. 通用原子写入工具实现后，Pitfall 受控写入命令应作为首批接入对象之一；
3. Pitfall Tools 测试文件应在 Tools 实现时一并创建并声明测试覆盖范围。
