# 规范文档规范

> 创建日期：2026-06-08
> 定位：定义 LDVH `specs-v2/` 规范文档工作区的正式规范、evals、refs、历史规范迁移、机制承接关系和规范文档治理规则
> 适用范围：LD Vibe Harness 自身 `specs-v2/` 文档工作区
> 上位依据：`specs-v2/03-文档基础规范.md`
> 相关规范：`specs-v2/00-LD-Vibe-Harness理念与纲要.md`

---
## 1. 本文定位

本文是 `specs-v2/` 规范文档工作区的应用剖面规范。`specs-v2/` 继承 `specs-v2/03-文档基础规范.md` 的文档工作区三分契约、命名、结构、引用和吸收规则；本文只定义 `<W>=specs-v2` 时的特有规则。

LDVH 自身规范工作区的三分映射如下：

```text
specs-v2/        LDVH v2 正式规范正文区
specs-v2/evals/  LDVH v2 内部评估和设计分析
specs-v2/refs/   LDVH v2 外部资料引用
```

旧 `specs/` 在 v2 重建期间作为迁移素材库。旧 `specs/` 中尚未迁入 `specs-v2/` 的内容，不自动构成 v2 权威规范。

---

## 2. specs-v2 正文区

### 2.1 正文区定位

`specs-v2/` 根目录正文区承载 LDVH v2 正式规范。正式规范可以定义稳定规则、对象边界、字段契约、状态机、工作流程、Human Gate、机制承接关系和检查要求。

正式规范正文区不得引用 `specs-v2/evals/`、`specs-v2/refs/`、旧 `specs/evals/` 或旧 `specs/refs/` 作为规范依据。evals、refs 或旧规范素材中的稳定规则必须吸收到 `specs-v2/` 正文区后才成为 v2 权威规则；长期决策可以进入 ADR；可执行工作或暂存发现可以进入 Task、Memo 等工作对象，但这些对象不因此成为规范规则。

### 2.2 编号分区

specs-v2 正文区使用重建后的编号分区。编号分区、编号占用和新增编号判断在 v2 迁移阶段由本文 §11 待补齐事项承接；旧 `specs/01-目录说明.md` 只作为迁移素材，不在 v2 中直接生效。

正式规范文档使用两位编号，格式为 `NN-标题.md`。应用剖面子文档使用 `NN.SS-标题.md`。历史机制文件和结构化契约文件沿用既有编号时，必须遵守本文 §6。

### 2.3 正式规范文档骨架

正式规范文档建议采用以下骨架：

```markdown
# {规范标题}

> 创建日期：YYYY-MM-DD
> 定位：...
> 适用范围：...
> 上位依据：`specs-v2/00-LD-Vibe-Harness理念与纲要.md`
> 相关规范：...（可选）

---
## 1. 本文解决的问题

## 2. 与 00 总纲的关系

## 3～N-2. 核心规则

## N-1. Human Gate 与检查要求

## N. 待补齐事项
```

工作模型、工作流程和其他专项规范的专用骨架待迁入 v2 后定义。迁入前，旧 `specs/07-工作模型基础规范.md`、`specs/08-工作流程基础规范.md` 等只作为迁移素材，不直接约束 v2 正式规范。00 总纲作为顶层文档，可不声明上位依据。

正式规范文档不得设置“本文不做什么”“边界说明”等反向边界章节。职责边界应通过定位、适用范围、上位依据、相关规范和正文正向规则表达。

## 3. specs-v2/evals

`specs-v2/evals/` 继承 `specs-v2/03-文档基础规范.md` §3.4 和 §3.6 的 evals 与吸收规则。本文只定义 `<W>=specs-v2` 时的特例。

specs-v2/evals 文档特例：

1. `specs-v2/evals/` 承载 LDVH v2 内部评估、设计探索、方案比较、外部项目借鉴分析和项目内部临时参考；
2. specs-v2/evals 可以引用 specs-v2 正文区作为评估依据和上位规范；
3. 稳定规范规则必须吸收到 specs-v2 正文区后，才能被正式规范文档作为规则消费；
4. 长期决策可以吸收到 ADR，可执行工作或暂存发现可以吸收到 Task、Memo 等工作对象，但不得被正式规范直接当成规则引用；
5. specs-v2/evals 不需要 Human Gate 与检查要求章节。

specs-v2/evals 文档建议采用以下骨架：

```markdown
# {评估标题}

> 创建日期：YYYY-MM-DD
> 定位：LD Vibe Harness 对 {评估对象} 的项目级借鉴评估
> 调研边界：不直接构成强制规则
> 执行效力：无；规范规则需进入 specs-v2 正文区，决策或工作事实需进入对应工作对象后才生效
> 上位依据：`specs-v2/00-LD-Vibe-Harness理念与纲要.md`
> 相关规范：...（可选）

---
## 1. 本文解决的问题

## 2. 结论

## 3. 评估正文

## N. 待补齐事项
```

## 4. specs-v2/refs

`specs-v2/refs/` 继承 `specs-v2/03-文档基础规范.md` §3.5 和 §3.6 的 refs 与吸收规则。本文只定义 `<W>=specs-v2` 时的特例。

specs-v2/refs 文档特例：

1. `specs-v2/refs/` 承载与 LDVH v2 规范体系相关的外部资料引用副本；
2. specs-v2/refs 文档头部必须声明外部资料来源；
3. 被采纳的外部资料结论必须吸收到 specs-v2 正文区、ADR、Task 或其他权威出口后才生效；
4. specs-v2/refs 文档不得包含对 specs-v2 正文区文件的路径引用、关联规范声明或依据引用。

specs-v2/refs 文档建议采用以下骨架：

```markdown
# {引用标题}

> 创建日期：YYYY-MM-DD
> 来源：{外部资料来源}
> 定位：外部资料引用，不直接成为 LDVH 强制规则

## 2. 引用正文
```

## 6. 历史机制文件与结构化契约

### 6.1 固定机制子文档取消

LDVH 不再要求每个工作模型或工作流程默认拆分固定 `NN.01` 至 `NN.06` 机制子文档。历史上存在的 Rules、Skill、Agent、Tools、Web、Contract 文件只作为迁移前过渡资料或遗留契约保留。

新增或稳定后的机制内容应按机制归属进入 v2 对应权威位置。相关权威位置尚未迁入 v2 时，应进入待迁移事项，不得直接引用旧 `specs/` 作为 v2 权威：

1. 主规范机制承接关系；
2. 开发环境适配规范；
3. 工作流程基础规范；
4. `specs-v2/14-Code实现规范.md`；
5. Web 信息同步规范；
6. 运行 Rules / Skill 实体、Agent 定义摘要或契约能力。

### 6.2 历史机制文件

历史机制文件不是独立规范，也不是工作模型或工作流程完整性的默认要求。历史机制文件只能说明对应模型或流程在某个机制下曾如何实践，不得重新定义主模型、主流程、字段契约、状态机、Context、Scenario、Gate、事实源边界或 Human Gate。

历史机制文件的迁移、保留和删除规则待 v2 工作模型、工作流程和开发环境适配规范迁入后定义。迁入前，旧机制文件只作为迁移素材，不构成 v2 子文档机制要求。

### 6.3 结构化契约

结构化契约可以作为字段契约、schema、接口契约或机器消费契约存在，但不构成固定 `NN.06` 子文档要求。新增或稳定后的契约优先回并到 v2 主规范契约章节，或由 Code（含 Tools / PyTools 实现）和 Web 实现消费主规范契约。对应主规范尚未迁入 v2 时，应记录为待迁移事项。

## 7. 机制承接与环境适配

v2 将规范到运行环境的同步拆成两层：

1. **机制承接关系**：说明某段稳定规范由 Rules / Instructions、Skill、Agent、Validator、Tools、Web、Contract、MCP、Hooks、Automation 或其他抽象机制能力承接；
2. **环境适配映射**：说明某类机制能力在 Trae、Codex、Claude Code、Cursor 或其他开发环境中映射到哪个文件、配置、工具、入口或降级策略。

机制承接关系不是普通引用、文档重要性声明或上位依据声明。只有当某个机制能力直接消费本文中的可执行规则、字段契约、状态机、流程步骤、触发条件、权限边界或校验要求，并且本文变化会导致该机制能力需要同步检查或更新时，才声明机制承接关系。

机制承接关系至少包含：

| 字段 | 含义 |
|---|---|
| 承接机制 | Rules / Instructions、Skill、Agent、Validator、Tools、Web、Contract、MCP、Hooks、Automation 等 |
| 承接能力 | 入口摘要、流程编排、校验实现、受控写入、展示视图、审批提示、命令权限等 |
| 同步类型 | 初始化、规则摘要、校验实现、展示同步、契约消费、审计输入等 |
| 触发条件 | 初始化、来源章节变化、字段契约变化、状态机变化、Human Gate 变化、审计或规则漂移诊断 |

必要时可补充来源章节、验证方式和降级处理。具体环境实体不得直接写入机制承接关系表，除非该文档本身就是环境适配映射文档。

旧文档中的“机制落地关系”进入 v2 时，应先拆解为机制承接关系和环境适配映射两层。无法确认环境实体的内容，只能先迁入机制承接关系或待迁移事项。

## 8. Specs-v2 修改执行顺序

AI 新增、修改或审计 specs-v2 正式规范文档时，应按以下顺序执行：

1. 根据任务场景确定基础入口：文档工作区、命名、引用、evals/refs 或应用剖面边界读取 `specs-v2/03-文档基础规范.md`；specs-v2 正式规范、机制承接关系或历史机制文件读取本文；
2. 判断拟修改内容属于哪个规范权威领域；
3. 读取目标规范及其 v2 上位依据、相关规范；目标主题尚未迁入 v2 时，读取旧 `specs/` 作为迁移素材；
4. 按需读取 00 中与本次变更相关的产品定位、五类构成要素、价值实现标准、运行闭环标准和 Human Gate 要求；
5. 判断变更是否符合 00 上位原则，是否弱化事实源边界、Human Gate、验证纪律或五类构成要素分工；
6. 若涉及高影响变更，触发 Human Gate；
7. 修改目标规范；
8. 判断文档结构、引用、迁移边界和机制承接关系检查是否已有适配工具；
9. 若检查 Code 实现缺失或旧实现假设与 specs-v2 冲突，按 `specs-v2/03-文档基础规范.md` §9.1 形成文档检查 Code 缺口，并按 `specs-v2/14-Code实现规范.md` 完成 Code 需求准入、最小实现和测试验证；
10. 运行适配后的文档结构校验和引用校验；
11. 检查是否需要更新机制承接关系；
12. 若变更影响运行投影，检查是否存在对应环境适配映射；不存在时记录为待迁移事项。

## 9. 机制承接关系

本文通过以下机制承接关系说明相关机制能力的同步、检查或审计触发条件。

| 承接机制 | 承接能力 | 同步类型 | 触发条件 |
|---|---|---|---|
| Rules / Instructions | specs-v2 编辑入口摘要 | AI 执行入口提示 | 本文的正式规范文档骨架、specs-v2/evals、specs-v2/refs、应用剖面子文档、历史机制文件或机制承接关系变化时 |
| Validator | specs-v2 文档结构和引用校验 | 校验实现 | 本文的章节编号、章节引用、路径引用、specs-v2/evals、specs-v2/refs 或文档治理检查变化时 |

上述机制承接关系的具体环境实体待环境适配映射补齐。旧 `.trae/rules/`、`tools/` 或其他环境实体在 v2 中不自动成为权威映射。

## 10. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 重命名或重排 specs-v2 正式规范文档；
2. 改变 specs-v2 正文区、specs-v2/evals 或 specs-v2/refs 的引用方向规则；
3. 将 specs-v2/evals、specs-v2/refs 或旧 `specs/` 迁移素材结论直接作为强制规则使用；
4. 新增、删除或重命名应用剖面子文档；
5. 恢复或新增固定机制子文档结构；
6. 改变机制承接关系或环境适配映射规则，或新增、修改、删除会影响运行投影同步检查、产品初始化、审计或规则漂移诊断的机制承接关系；
7. 历史机制文件新增或扩张基础规范；
8. 新增、替换或扩大 specs-v2 文档检查 Code 实现的判定范围。

规范文档检查至少包括：

| 检查项 | 标准 |
|---|---|
| 上位依据 | 正式规范文档已声明上位依据，00 除外 |
| 编号分区 | 文档编号符合 specs-v2 当前编号分区，或已记录为待迁移事项 |
| 文档结构 | 文档骨架符合正式规范、工作模型、工作流程、evals、refs 或应用剖面要求 |
| 应用剖面 | 子文档只定义特例，未复制父规范通用规则 |
| 历史机制文件 | 未恢复固定机制子文档结构 |
| 引用方向 | specs-v2 正文区未引用 evals、refs 或旧 specs 作为规范依据 |
| 机制承接关系 | 仅声明实际消费的抽象机制能力 |
| 环境适配映射 | 未把具体环境实体混入普通机制承接关系 |
| Code 适配 | 检查 Code 实现适配 specs-v2；缺失时已按 `specs-v2/03-文档基础规范.md` §9.1 和 `specs-v2/14-Code实现规范.md` 处理 |
| 校验 | specs-v2 修改后已运行适配后的文档结构和引用校验，或记录降级原因与残留风险 |
