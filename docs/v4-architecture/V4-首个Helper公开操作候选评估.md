# V4 首个 Helper 公开操作候选评估

> 记录性质：Helper 领域公开操作的建设顺序与来源准入评估，不是规则源，不定义正式操作名称、`operation_key`、字段或实现契约。
> 评估日期：2026-07-13

## 1. 推荐结论

第一个领域公开操作建议暂以下列工作描述进入 Human 审核：

> 读取 Working Tree 中通过当前已实现机械检查的规范候选载体及授权附件的 L0–L2 信息，并同时报告规则源资格缺口。

这只是候选工作描述，不是正式中英文名称，也没有预先创建 `operation_key`。

建议责任严格限定为：

1. 读取 L0 发现信息、L1 概览信息和 L2 关系信息；
2. 按稳定 key 精确选择，或读取 Working Tree 中全部通过当前已实现机械检查的候选载体；
3. 保留层级、稳定 key、当前路径、字段来源和来源回指；
4. 逐项报告规则源资格中尚未自动证明的条件、不完整范围和未知 key；
5. 不从自然语言任务猜测“相关规范”；
6. 不判断规则适用性，不返回 L3 规则上下文或 L4 全文；
7. 不要求先完成管辖范围解析；
8. 明确将结果称为机械检查候选及其资格缺口，不把它们冒充为已经完整证明资格的当前规则源成员。

## 2. 候选比较

| 工作描述 | V1–V8 价值 | 来源成熟度 | 当前实现前置 | 反向创造语义风险 | 建议 |
|---|---|---|---|---|---|
| 读取 L0–L2 机械检查候选与资格缺口 | 直接提供 V1，并以来源、层级和缺口支持 V2、V3 与 V5 | 高；01 已定义候选、当前规则源和 L0–L2 边界 | 小；现有 Code 已生成 36 项派生信息、来源位置和资格缺口 | 低，前提是不做相关性、适用性或规则源资格推断 | 第一项 |
| 管辖范围解析 | 主要补强对象边界的 V3 与 V5，并支持 V1、V2 和 V7 | 高；02 与 02.Att.01 已有主要语义 | 中至高；需配置、定位符、路径与 Git 身份解析 | 低至中 | 第二项候选 |
| 当前任务的规则适用判断 | 潜在支持 V2–V5 与 V7，但必须完整保留适用条件、Human Gate 和 Stop Conditions | 不足；04 只定义报告形态，不定义通用判断算法 | 高；需 L3/L4、对象范围及各来源的适用条件 | 高 | 延后 |

第一项可直接复用当前 36 项派生信息与已有来源回指，改动面和失败范围最小，符合 07 按风险选择增量和测试范围的要求。

## 3. 唯一定义来源

若 Human 接受上述责任，领域语义的唯一定义来源应当是 `specification-model-foundation`，即当前 01。原因是 L0–L4 的含义、内容、渐进式披露、来源回指与证明边界由 01 定义。

04 只定义 Helper 共同服务契约，不应替代 01 定义该领域操作；Code、tests 和实现注册表不得赋予操作身份。

Human 确认后，01 才可进入以下正式设计：

1. 在正文中增加固定的 `Helper 公开操作` 声明表；
2. 在同一来源内定义输入契约章节；
3. 在同一来源内定义结果契约章节；
4. 按 01 的术语要求审核正式中英文描述和 `operation_key` 候选。

不把这些领域字段写入 04、04.Att.01 或双语术语附件。

## 4. 最小契约边界建议

输入建议：

- 使用共同字段 `requested_disclosure`，当前操作只接受 L0、L1 或 L2，默认 L0；
- `arguments` 只增加一个可选稳定 key 列表；空列表精确表示 Working Tree 中全部通过当前已实现机械检查的候选载体；
- 不要求 `task`、`work_object_locators` 或管辖解析；
- 不增加载体类型、路径模式、全文搜索或模糊匹配；未知 key 不得回退到名称相似或路径搜索。
- 请求 L3 或 L4 时必须明确报告该层级不在本操作支持范围，不得静默降级到 L2；具体 `outcome` 映射由正式契约起草时对照 04 确定。

结果建议：

- 返回实际读取的机械检查候选条目，不授予它们完整当前规则源资格；
- 每项包含 `layer`、稳定 key、载体类型、当前路径、该层内容和逐字段来源回指；
- 共同响应 `disclosure` 记录请求层级和实际返回层级；
- 每次结果都逐项保留未自动证明的规则源资格条件；未知 key、规则源问题、不完整范围和不支持的披露层级继续使用 04 的 `gaps`、`diagnostics`、`scope` 与 `outcome`，不新建第二套错误模型。

L1/L2 的披露语义建议采用累积返回：L0；L0+L1；L0+L1+L2。这可以让每个结果保留定位身份，同时不强制 AI 逐层调用。

## 5. 需要 Human 确认的边界

1. 第一个领域公开操作只提供 Working Tree 中通过当前已实现机械检查的候选载体及资格缺口的 L0–L2 信息，不把它们冒充为已经完整证明资格的当前规则源成员，也不承担任务相关性和规则适用判断；
2. 它不依赖管辖范围解析，也不使用自然语言任务推断规范；
3. 默认披露为 L0，L1/L2 采用累积返回；稳定 key 列表使用精确选择，空列表表示全部通过当前已实现机械检查的候选载体，未知 key 不做模糊回退，L3/L4 请求必须明确报告不受支持而不静默降级；
4. 01 是该操作领域语义、输入和结果契约的唯一定义来源；
5. 管辖范围解析排在其后，规则适用判断等 L3/L4 安全披露和相应来源责任成熟后再评估。

只有 Human 接受上述责任边界后，才进入正式中英文描述、`operation_key` 候选、字段契约、术语复核和独立审核。
