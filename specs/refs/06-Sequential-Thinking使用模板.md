# Sequential Thinking 使用模板

> 日期：2026-05-21
> 来源：Sequential Thinking MCP 官方文档
> 定位：外部资料引用，不直接成为 LDVH 强制规则

## 模板1：复杂业务逻辑拆解

适用场景：复杂业务规则梳理、多条件判定、状态机拆解等逻辑复杂的业务分析。

```
用 Sequential Thinking 分析以下业务逻辑，逐步拆解为可实现的子任务：

场景：{描述业务场景，如"多条件组合的状态判定"}
约束：{列出已知约束，如"最多 N 种状态、支持组合条件、边界条件处理"}
期望输出：{如"数据结构设计 + 计算步骤伪代码"}
```

## 模板2：跨项目接口变更影响分析

适用场景：跨项目接口变更、数据模型调整等涉及多项目的改动。

```
用 Sequential Thinking 分析以下变更的影响范围：

变更：{描述变更，如"接口新增字段"}
涉及项目：{列出可能受影响的项目}
当前契约：{引用正式事实源中的相关定义，如 docs/07、docs/08、docs/10-19 或 ADR}
请逐步分析每个项目需要做的适配，以及是否有遗漏的风险点。
```

## 模板3：Bug 根因排查

适用场景：推理结果异常、通信断连、数据不一致等问题排查。

```
用 Sequential Thinking 排查以下 Bug：

现象：{描述 Bug 表现}
复现条件：{描述如何复现}
相关代码：{列出涉及的文件/模块}
已排除的原因：{列出已确认不是根因的方向}
请逐步推理可能的根因，每步给出判断依据和验证方法。
```

## 模板4：技术方案选型

适用场景：技术选型、架构决策、第三方库选择等需要对比评估的场景。

```
用 Sequential Thinking 对比以下技术方案：

目标：{描述要解决的问题}
候选方案：
- 方案A：{描述}
- 方案B：{描述}
评估维度：{如"性能、复杂度、可维护性、与现有架构的契合度"}
请逐步对每个维度打分并给出最终推荐。
```

## 模板5：数据流追踪

适用场景：数据从采集到展示的完整链路分析，排查数据丢失或变形问题。

```
用 Sequential Thinking 追踪以下数据流的完整路径：

数据：{描述数据，如"一条请求从客户端到服务端"}
起点：{如"客户端采集"}
终点：{如"服务端存储或展示"}
问题：{如"某字段在服务端收到后丢失"或"无问题，仅梳理链路"}
请逐步追踪每个环节的数据变换，标注字段是否完整传递。
```
