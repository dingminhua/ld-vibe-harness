## `ldvh call` 最小调用形态

请求 JSON 经 stdin 传入；最小可运行形态如下（示例只展示结构，不定义任何操作的参数）：

```bash
echo '{"arguments": {}}' | ldvh call <operation_key>
```

无请求输入的入口（如通用 `ldvh capabilities`）同样无条件读 stdin 至 EOF：交互终端之外的调用必须闭合 stdin，例如 `ldvh capabilities < /dev/null`。stdin 不闭合时调用挂起，该挂起不表示服务不可用（04 §5.1）。

共同请求字段闭集与默认值以 `specs/attachments/04.Att.01-Helper CLI 请求与响应字段表.md` 的当次内容为准；各操作自己的必填与可选参数先经 `ldvh capabilities`（通用发现即返回每项操作的 `required_inputs`、`optional_inputs` 与契约来源回指）或 `ldvh capabilities <operation_key>` 现取，再按回指章节的当次内容构造 `arguments`。试调返回 `invalid_request` 时读取响应 `gaps` 与 `diagnostics` 中的契约问题并据以修正，不得变换参数值盲目重试。

## 技能登记字段值

目标环境登记技能要求提供字段时，各字段值的权威来源：技能名称、描述与指令正文照抄 `skill/SKILL.md`（`skill-template` 行）frontmatter 与正文的当次内容，不重述不改写；许可证与作者署名见仓库 `LICENSE` 当次版权声明行；发行名称与版本见 `pyproject.toml` `[project]`；仓库 URL 见 `git remote` origin；图标素材见 `skill-icons` 行。环境私有扩展字段（厂商专属 frontmatter 键或 sidecar 文件）不由本发行物预填，按目标环境当次官方资料在接入时判定。本附件不登记任何厂商目录、表单或字段名。

## 入口选择

目标环境 AI 必须先读取当前环境资料，再判断原生事件与上述入口的语义是否对应：

1. 普通生命周期事件形成工作上下文时，环境的默认交付是把原生事件实际提供的对象传给 `ldvh-work-context`；核心按 01 §9.10 的 `work-context-rule-orientation` profile 执行规则读取。不得仅因该事件、cwd 或任务文字调用 `ldvh-context-recovery`。环境必须能够提供调用所需的实际路径和反馈通道。
2. AI 在理解 Human 目标后明确需要项目事实时，才可使用 `ldvh-context-recovery`；也可以按来源定义直接使用相应 `ldvh call` 事实读取能力。两种入口都不判断事实适用、行动允许或完成。
3. AI 主动读取或变更 LDVH 能力时，使用 `ldvh capabilities` 和来源已定义的 `ldvh call` 操作，不从环境事件猜测 Helper 字段。
4. 只有实际 Git `commit-msg` 事件才能连接 `ldvh-git-commit-msg`；AI 环境中名称相似的阻断事件不能自动视为等价。
5. `ldvh-git-hook` 是安装管理入口，不是通用 AI 环境 adapter。
6. 具体环境来源必须先声明当前单元实际承接的原生事件及版本/范围；每次行动再按 33 为这些事件形成一次性的验证矩阵。入口清单不维护跨厂商事件登记，也不证明任何事件已真实触发。
7. 如果原生机制能够直接配置到既有入口，按 `specs/09-环境接入规范.md` 和 Human Gate 形成安装方案；如果必须新增 manifest、启动脚本或薄 adapter，先停止安装，按具体环境资料和 `specs/07-Code 实践与测试规范.md` 建立独立 Code 计划。该独立 Code 计划在目标 AI 环境自己的仓库建立，不在 LDVH 仓库，也不在 LDVH 仓库提交其它厂商 adapter 或环境侧实现。

不得为了适配方便另造统一厂商 payload、通用事件路由、默认语义或 adapter 登记。若当前入口不能承接目标环境真实输入和反馈，应保持 `unverified` 或依据肯定证据报告 `unsupported`，不能改写入口契约；`ldvh-context-recovery` 不是环境 Hook 对新能力不兼容时的替代路径。

## 环境侧实现边界

LDVH 接入面不存在环境 Hook、插件或 adapter 层（`specs/09-环境接入规范.md` §5.1）；本仓库不收纳、不维护任何具体 AI 环境的环境侧实现。需要为新环境新增 manifest、启动脚本或薄 adapter 时，按上述入口选择第 7 项在目标环境自己的仓库建立独立 Code 计划，不得在 LDVH 仓库提交其它厂商实现。
