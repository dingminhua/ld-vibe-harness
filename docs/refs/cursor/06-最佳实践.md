## 1. 结论摘要

Cursor 的最佳实践围绕 Rules 写法、Agent 使用、性能优化和常见问题四个维度。Always 规则控制在 3-5 条以内，description 要写清楚以便 Agent Requested 类型判断。Agent 使用时应明确描述需求、分步执行复杂任务、善用 Rules、及时审查 diff。性能优化需精简 Rules、合理使用 Auto Attached、控制上下文和只启用必要的 MCP 服务器。

## 2. Rules 写法建议

### 2.1 Always 规则

```markdown
---
description: 项目全局规范
alwaysApply: true
---

# 项目规范

- 技术栈：React + TypeScript + Tailwind CSS
- 包管理器：pnpm
- 测试框架：Vitest
- 代码风格：遵循 ESLint + Prettier 配置
- 组件风格：函数式组件 + Hooks
- 状态管理：Zustand
```

### 2.2 Auto Attached 规则

```markdown
---
description: Python 编码规范
globs: **/*.py
---

# Python 规范

- 使用 Python 3.12+ 特性
- 类型注解必须完整
- 使用 ruff 格式化
- docstring 使用 Google 风格
- 异步代码使用 asyncio
```

### 2.3 Agent Requested 规则

```markdown
---
description: 数据库专家，当涉及 SQL、数据库迁移、ORM 配置时使用
---

# 数据库规范

- ORM：SQLAlchemy 2.0+ (async)
- 迁移工具：Alembic
- 命名：表名 snake_case，列名 snake_case
- 所有表必须有 id, created_at, updated_at
- 软删除使用 deleted_at 字段
- 索引命名：idx_{table}_{columns}
```

### 2.4 关键建议

- Always 规则控制在 3-5 条以内，避免上下文浪费
- description 要写清楚，Agent Requested 类型依赖它判断是否加载
- 规则内容要具体、可操作，避免模糊描述
- 每条规则聚焦一个主题，不要把所有规范塞进一个文件
- 使用 Markdown 格式，结构清晰

## 3. Agent 使用建议

1. **明确描述需求**：越具体越好，包含期望的输入输出
2. **分步执行复杂任务**：大任务拆分为小步骤，逐步确认
3. **善用 Rules**：把项目规范写入 Rules，避免每次重复说明
4. **及时审查**：每步操作后检查 diff，不要盲目 Accept All
5. **配合 Git**：在 Agent 操作前创建分支，方便回滚
6. **利用上下文**：通过 @files 等引用关键文件，帮助 Agent 理解项目

## 4. 性能优化

1. **精简 Rules**：Always 规则不要过长，每条控制在 50 行以内
2. **合理使用 Auto Attached**：避免过于宽泛的 globs 匹配
3. **控制上下文**：不要引用过多文件，只引用必要的
4. **MCP 工具选择**：只启用必要的 MCP 服务器，减少工具数量
5. **模型选择**：简单任务用快速模型，复杂任务用强力模型

## 5. 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| Agent 忽略 Rules | Always 规则过多或描述不清 | 精简规则，确保描述明确 |
| Agent 修改了不该改的文件 | 缺乏约束规则 | 添加 Auto Attached 规则限制 |
| 上下文丢失 | 对话过长 | 开启新对话，引用关键文件 |
| MCP 工具不可用 | 配置错误或服务器未启动 | 检查 mcp.json 和服务器状态 |
| Agent 步骤过多 | 任务描述不清或过于复杂 | 拆分任务，明确每步目标 |
| Yolo 模式误操作 | 缺少确认环节 | 配合 Git，定期 commit |
