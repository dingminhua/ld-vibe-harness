> 文件状态：active；本文只承载 33 授权的目标环境插件差异速查和记录口径。本文不是目标环境 Hook API 的完整文档，不授权 integrated 结论，不定义 LDVH 规则、runtime payload 字段闭集、命令分类、target 归口、diagnostic 分流、read_plan、repair、bypass、completion 或状态推进。

| 使用边界 | 口径 |
|---|---|
| 官方文档优先 | 目标环境官方文档优先。本文只作速查入口；正式编写或更新插件前，必须回读目标环境当时的官方 Hook / plugin / extension / settings 文档。 |
| 当前环境验收 | 当前 AI 环境只能验收本环境真实 lifecycle。Codex 会话不能替代 WorkBuddy lifecycle 验收，WorkBuddy 会话也不能替代 Codex lifecycle 验收；跨环境只能审计样例包、adapter、配置或目标环境回传的当次原始输出。 |
| 样例边界 | repo-local 样例包只证明本仓库样例结构和 shim 行为，不证明目标环境已经安装、启用或 integrated。 |
| 能力边界 | 环境插件差异只记录“环境能提供什么能力”。LDVH canonical event、target scope、shared classifier、preflight、receipt、diagnostic、completion、Human Gate 和事实源回写属于 LDVH 规则 / Code / specs，不得写成目标环境自己的规则。 |

| 维度 | 目标环境提供 | LDVH 定义 / 承接 |
|---|---|---|
| 入口形态 | 插件、扩展包、settings hook、package、adapter 脚本或其它等价机制 | 是否符合 33 的目标环境入口要求 |
| 原生事件 | 环境自己的 lifecycle event 名称、触发时机和 matcher 能力 | 映射后的 `ldvh.session_start`、`ldvh.pre_tool_use`、`ldvh.completion_claim` 等 canonical event |
| payload | 环境能交出的 cwd、tool_name、command_text、target、session、transcript、用户提示或等价字段 | `runtime_adapter.py` 可消费的 payload 投影、字段归一化和缺字段诊断 |
| 阻断协议 | 环境是否支持写前 deny / allow / warning / continue 等输出协议 | 是否由 LDVH preflight 形成阻断、no-op、warning 或 completion 检查结果 |
| 安装与回滚 | 目标环境的安装位置、启用方式、禁用方式、授权 / trust 和卸载方式 | 30 的安装 / 验收 / rollback 交还与 integrated 判定 |
| 只读跳过 | 环境只提供工具名、命令文本和协议输出 | 共享 LDVH Code / shared classifier 判断是否只读；环境入口只翻译 no-op / allow 输出 |

| 字段 | 要求 |
|---|---|
| 目标环境 | 环境名称和版本 / surface；未知版本写明 unknown |
| 依据来源 | 官方文档链接、目标环境当次输出、repo-local 样例或用户回传证据；不得只写“看起来支持” |
| 入口形态 | 插件、扩展包、settings hook、package、adapter 脚本或其它等价机制 |
| 原生事件候选 | 目标环境自己的事件名；不得写成 LDVH 事件名 |
| LDVH 映射 | 原生事件如何映射到 `ldvh.*` canonical event；多个原生事件组合时必须说明 |
| payload 能力 | 当前能取得的 cwd、tool_name、command_text、target、session、verification_evidence 等字段 |
| 阻断能力 | 是否支持写前阻断；缺阻断能力时只能写 capability_gap |
| 安装 / 回滚 | 安装位置、启用方式、禁用或卸载方式，真实写入由 30 承接 |
| 当前验收边界 | 当前 AI 环境能验证什么、不能验证什么 |
| 差异风险 | 缺事件、缺字段、缺阻断、缺回滚、payload 不稳定、只能本地干跑等风险 |

| 目标环境 | 当前依据 | 原生事件候选 | LDVH 映射口径 | 当前边界 |
|---|---|---|---|---|
| Codex | repo-local 样例 `hooks/environment-plugins/codex-ldvh-v3/`；正式编写 / 更新前仍需回读 Codex 当时官方插件和 hook 文档 | 样例覆盖 `SessionStart`、`PreToolUse`、`PostToolUse`、`UserPromptSubmit`、`Stop`、`Notification` | 稳定接入口径只映射核心三类：`SessionStart` -> `ldvh.session_start`，`PreToolUse` -> `ldvh.pre_tool_use`，`Stop` -> `ldvh.completion_claim`；其它原生事件只作研究采样，不得直接新增 LDVH canonical event | Codex 会话只能验收 Codex 当前真实 lifecycle；repo-local 样例语法、fixture 和 shim 直测不等于 integrated |
| WorkBuddy | repo-local 样例 `hooks/environment-plugins/workbuddy-ldvh-v3/`；真实 WorkBuddy 状态只能由 WorkBuddy 当前环境当次输出或用户回传证据判断 | 样例覆盖 `SessionStart`、`PreToolUse`、`Stop` | `SessionStart` -> `ldvh.session_start`，`PreToolUse` -> `ldvh.pre_tool_use`，`Stop` -> `ldvh.completion_claim` | Codex 会话不能验收 WorkBuddy lifecycle；发现 V1 stale path 或旧安装位置时按 33 更新场景和 30 安装 / 验收流程处理 |
| 未登记环境 | 官方文档和当次能力分析尚未进入本文 | unknown | 只能先输出 requirements、capability_gap 和 30 验收入口 | 不得复制 Codex / WorkBuddy 标本后声明支持；必须先完成环境分析 |

| 写法 | 原因 |
|---|---|
| “目标环境支持 `ldvh.pre_tool_use` 原生事件” | `ldvh.*` 是 LDVH canonical event，不是环境原生事件名 |
| “repo-local 样例存在，所以目标环境已 integrated” | 样例存在不等于真实环境安装、启用、触发或阻断 |
| “Codex 当前会话已证明 WorkBuddy hook 正常” | 当前 AI 环境不能替代另一个目标环境 lifecycle 验收 |
| “每个环境都必须有 manifest + hooks.json + Python shim” | 33 要求职责等价，不要求文件结构相同 |
| “环境插件内自行判断 sed/find/xargs 是否只读” | 只读 / 写入副作用分类归共享 LDVH Code / shared classifier |
| “环境插件内实现 target 归口或 diagnostic 分流” | target scope 和 diagnostic routing 归 LDVH Code / specs |

| 更新要求 | 内容 |
|---|---|
| 来源 | 先记录官方文档或当次原始输出来源。 |
| 范围 | 只新增环境能力、字段、安装 / 回滚和验收边界。 |
| 缺口 | 发现环境能力无法覆盖核心三事件、写前阻断、payload 或回滚时，写 capability_gap，不补环境专属规则。 |
| 薄引用 | 发现样例 shim 中出现规则判断、命令分类、target 归口、diagnostic 分流或状态推进时，按 33 薄引用边界迁回共享 LDVH Code。 |
| 验证 | 修改本文后必须运行 specs 校验；涉及 repo-local 样例或 shared classifier 时同步运行环境插件测试。 |
