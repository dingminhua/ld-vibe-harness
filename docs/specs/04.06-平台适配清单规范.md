## 1. 本文解决的问题

本文定义三环境承接矩阵机制。

三环境承接矩阵不是环境能力说明书，也不是环境官方文档摘要。它的主轴是 LDVH 资产、规范落地要求、运行投影要求和检查要求；环境只是在每个承接项下回答：如何承接、承接类型是什么、来源是什么、如何承接检查、不能完整承接时如何承接降级、还有哪些待补齐事项。

本文首轮只覆盖三个 AI 开发环境：

| 环境 | 本轮定位 | 来源 |
|---|---|---|
| Trae Work CN | 当前主执行环境和优先试点环境 | 既有 `docs/specs/04.07-Trae-Solo适配清单.md`、`docs/refs/trae/` |
| Codex App | App / AGENTS / approval 对照环境 | 既有 `docs/specs/04.08-Codex适配清单.md`、`docs/refs/codex/` |
| Claude Code CLI | 第三个跨环境验证环境 | 既有 `docs/refs/claude-code/`，不新增独立 04.09 |

本文不处理 Cursor、OpenCode、Gemini、Zed、Qwen、Terminal-only、云端托管、网页端或移动端。后续如需扩展环境，应先经 Human Gate 判断是否扩展本文矩阵或另行建立后续规范。

## 2. 矩阵事实源边界

三环境承接矩阵应写入本文，作为三环境承接字段规则、承接类型规则和最小横向对比事实源。

| 内容 | 权威位置 |
|---|---|
| 三环境承接矩阵字段规则 | 本文 |
| Trae Work CN 承接输入 | `docs/specs/04.07-Trae-Solo适配清单.md`、`docs/refs/trae/` |
| Codex App 承接输入 | `docs/specs/04.08-Codex适配清单.md`、`docs/refs/codex/` |
| Claude Code CLI 承接输入 | `docs/refs/claude-code/`，后续直接进入本文矩阵 |
| LDVH落地与检查过程结果 | 当前对话或调用结果中的 42 落地与检查报告 |
| 需要长期保留的检查结论 | Task、Memo、ADR、Pitfall、正式规范、待补齐事项或对应 Git 文件事实源 |
| 实际运行投影入口 | LDVH-AI-ENTRY.md、环境规则、Skill、Agent、Hook、CI、命令、MCP、Web 或人工入口 |
| LDVH落地与检查执行规则 | `docs/specs/42-ldvh-landing-check-LDVH落地与检查.md` |

矩阵不得复制环境官方文档全文，不得把聊天判断当作环境事实，不得把尚未验证的能力写成完整承接结论，不得替代 42 LDVH落地与检查的现场判断。

04.07 和 04.08 是迁移输入，不再作为长期独立维护目标。二者内容被吸收到本文矩阵并完成引用迁移、42 消费和校验后，才允许进入删除流程。

## 3. 承接类型

三环境承接矩阵使用以下中文承接类型。英文对照只用于和外部参考材料对齐，不作为 LDVH 正式模型词。

| 承接类型 | 英文对照 | 含义 |
|---|---|---|
| 原生承接 | Native | 环境原生提供该能力，且已有 LDVH 可复用的验证证据 |
| 适配承接 | Adapter-backed | 环境通过薄入口、配置、命令、脚本、MCP、Hook 或 Code wrapper 承接该能力，但语义不完全等价 |
| 指令承接 | Instruction-backed | 环境只能通过规则、指令、AGENTS、Prompt 或人工步骤引导 AI 执行，缺少强制运行时机制 |
| 人工降级 | Manual-degraded | 环境缺少对应能力，当前只能人工执行、人工确认或人工记录证据 |
| 仅作参考 | Reference-only | 只作为设计参考或未来候选，不声明当前支持 |
| 待确认 | Unknown | 尚未读取 refs 或完成实测，不能据此执行完整闭环 |

承接类型不是通过状态，不代表当前用户环境已经完成安装、配置、启用或验证。42 可以基于当前执行情况派生过程结论，但不得把过程结论回写为矩阵状态。

## 4. 矩阵字段

三环境承接矩阵采用承接卡片表达，避免超宽表格。每张承接卡片必须包含以下字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| 承接项 | 是 | 需要被环境承接的 LDVH 资产、规范落地要求、运行投影要求或检查要求 |
| LDVH 要求 | 是 | 该承接项在 LDVH 中必须满足的正式要求 |
| Trae Work CN | 是 | Trae Work CN 的承接类型、承接方式和主要边界 |
| Codex App | 是 | Codex App 的承接类型、承接方式和主要边界 |
| Claude Code CLI | 是 | Claude Code CLI 的承接类型、承接方式和主要边界 |
| 来源 | 是 | 正式规范、refs、research、既有清单或实测证据来源 |
| 承接检查 | 是 | 42、Code、人工或等价方式如何检查该承接声明 |
| 承接降级 | 是 | 环境不能完整承接时的替代方式、残留风险和后续处理 |
| 待补齐事项 | 是 | 后续需要补齐的 refs、实测、Task、ADR、Code、Web 或规范事项 |

矩阵可以派生 JSON、表格视图或 Web 展示，但派生视图不得替代本文字段规则。

## 6. 42 使用矩阵的规则

42 LDVH落地与检查必须围绕本文三环境承接矩阵执行和验证，而不是围绕某个环境名称或环境能力清单硬编码执行。

AI 应按以下顺序处理：

1. 确认当前环境；
2. 定位本文三环境承接矩阵；
3. 读取本次任务依赖的承接项；
4. 对每项依赖读取当前环境列、LDVH 要求、来源、承接检查、承接降级和待补齐事项；
5. 若关键承接项只有人工降级、待确认或缺少承接检查，42 只能按承接降级执行并记录残留风险；
6. 若关键承接项缺失、来源缺失、承接检查缺失或待补齐事项阻断当前目标，不得宣称完整 LDVH落地与检查通过；
7. Trae Work CN、Codex App、Claude Code CLI 是当前矩阵列，不得把任一环境名写成唯一执行逻辑。

## 7. 04.07 / 04.08 迁移规则

04.07 和 04.08 是既有环境清单，不再作为长期独立扩展方向。

迁移顺序如下：

1. 先将 04.07 / 04.08 中有价值内容吸收到本文三环境承接矩阵；
2. Claude Code CLI 直接进入本文矩阵，不新增独立 04.09；
3. 42 / landing-plan 能消费本文矩阵后，再标记 04.07 / 04.08 为历史参考、待合并或删除候选；
4. 删除 04.07 / 04.08 前必须完成引用迁移和校验；
5. 删除或改变二者职责必须触发 Human Gate。

## 9. Human Gate 与检查要求

以下情况必须触发 Human Gate：

1. 将任一环境声明为完整承接或作为完整通过依据；
2. 将未经 42 检查的承接矩阵作为完整落地依据；
3. 删除、重命名或改变 04.07 / 04.08 职责；
4. 新增或删除三环境矩阵列；
5. 把某个环境能力提升为 LDVH 全局唯一底座；
6. 允许缺少承接检查的环境承接项通过 42；
7. 改变本文字段或 42 依赖三环境承接矩阵的规则。

检查三环境承接矩阵时，应确认：

1. 每张承接卡片包含承接项、LDVH 要求、三环境承接、来源、承接检查、承接降级和待补齐事项；
2. 承接类型使用本文 §3 的中文枚举；
3. 承接检查、承接降级和待补齐事项相互匹配；
4. 未把环境官方文档、聊天判断或工具缓存当成最终事实；
5. 未把 Code 执行、Web 与预览、证据与回写误写为环境能力本身；
6. 04.07 / 04.08 是迁移输入，不是写死在 42 中的环境逻辑。
