# 规范落地与环境投射基础规范

> 创建日期：2026-06-11
> 定位：定义 LDVH 正式规范如何提出落地要求，LDVH 如何建设或选择能力保障这些要求，并如何基于环境客观能力清单主动形成环境投射
> 适用范围：LDVH 正式规范、规范落地要求、LDVH 能力保障、环境能力清单、环境投射、运行投影、降级路径、缺口记录和 42 LDVH 落地与检查的上位口径
> 上位依据：`docs/specs/00-LD-Vibe-Harness理念与纲要.md`
> 参考来源：`docs/research/26-LDVH环境投射技术经验吸收研究.md`

---
## 1. 本文解决的问题

本文解决 LDVH 正式规范如何进入具体 AI 开发环境和运行环境的问题。

04 系列不以某个环境已有能力为起点，也不把环境视为主动承接方。04 系列的基本链路是：

```text
正式规范提出落地要求
  ↓
LDVH 建设或选择能力保障
  ↓
LDVH 读取环境客观能力清单
  ↓
LDVH 主动形成该环境中的环境投射、运行投影、降级路径和缺口记录
```

环境只提供客观能力清单、约束、证据和当前可用性边界。环境能力不足不能降低 LDVH 的规范要求，也不能阻止 LDVH 为其他环境建设更优能力。例如 Trae 暂无稳定 Hook 能力时，只能在 Trae 投射中降级；如果 Codex 或其他环境具备更稳定的 Hook / lifecycle 能力，LDVH 仍应保留并建设该能力路径。

---
## 2. 与 00 总纲的关系

00 将开发环境列为 LDVH 构成要素之一，同时要求 Code、Web、工作模型、工作流程和事实源协同运行。本文承接 00 的治理边界：

1. 正式规范仍是规则事实源；
2. Git 文件仍是稳定事实源的默认承载；
3. Code 提供确定性执行、校验和受控写入；
4. Web 提供 Human-facing 派生视图和受控交互；
5. AI 环境入口、Skill、Agent、Hook、Command、配置和缓存都只是运行投影或环境投射表达；
6. Human Gate 负责授权、暂停、确认和高影响决策。

04 系列只定义规范落地和环境投射的基础规则，不替代 00 的理念、事实源边界、工作对象规范、Code 规范、Web 规范或 42 检查流程。

## 5. 基础原则

1. **规范先行**：只有正式规范提出落地要求后，才进入能力保障和环境投射判断；
2. **LDVH 主动**：环境投射是 LDVH 的主动行为，不是环境承接 LDVH；
3. **环境客观**：环境只提供能力清单、限制、证据状态和当前可用性；
4. **能力不降级**：弱环境只能在自身投射中降级，不能降低 LDVH 对强环境的能力建设；
5. **薄入口**：环境入口只保留摘要、路径、触发、STOP 点和交还方式，不复制正式规范正文；
6. **事实源回写**：环境工具输出、运行投影、Web 视图和对话结论不是最终事实源；
7. **显式降级**：无法完整投射时，应写明降级方式、残留风险和后续补齐事项；
8. **Human Gate**：高影响写入、长期配置、权限扩大、完整支持声明和删除历史清单前必须暂停确认。

## 6. 环境扩展规则

本文当前只要求 `04.03` 写 Trae Work CN 与 Codex App。若后续需要新增其他环境，应按以下顺序处理：

1. AI 读取该环境官方资料、项目 refs 和当前环境证据；
2. AI 形成环境客观能力清单，区分已验证、refs-only、待确认、不可用；
3. AI 按 `04.03` 的投射卡片字段补齐环境投射方式；
4. AI 写明来源、投射检查、投射降级和待补齐事项；
5. 完整支持声明、新增环境列或长期投影创建前触发 Human Gate。

不得因为某个环境未写入当前环境范围，就把该环境视为不支持；也不得因为某个环境有候选能力，就声明 LDVH 已在该环境完整落地。

## 7. Human Gate 与检查要求

以下情况必须评估 Human Gate：

1. 改变 04 系列三层主轴；
2. 将环境能力反向提升为 LDVH 全局能力要求；
3. 声明某环境完整支持 LDVH；
4. 新增、删除或长期维护环境投射文件；
5. 删除、重命名或历史化旧 04.06 / 04.07 / 04.08；
6. 允许运行投影替代正式规范或 Git 文件事实源；
7. 允许弱环境降级结果影响强环境能力建设。

检查 04 系列时，应确认：

| 检查项 | 标准 |
|---|---|
| 三层方向 | 规范提需求、LDVH 建能力、LDVH 基于环境清单主动投射 |
| 术语一致 | 使用环境投射、环境能力清单、运行投影、降级路径，不把环境写成主动承接方 |
| 文件边界 | 04.01、04.02、04.03、04.04、04.05 职责未混同 |
| 事实源边界 | 投射、入口、工具输出、Web 视图未成为最终事实源 |
| 环境扩展 | 新环境通过调研和卡片追加，不凭记忆补写 |
| 降级处理 | 环境不足只影响本环境投射，保留强环境高质量路径 |
