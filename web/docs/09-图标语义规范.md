# 图标语义规范

> 路由范围：LDVH Web 全部页面
> 图标库：`lucide-react`
> 上位规范：[`specs/08-Web信息同步实现规范.md`](../../specs/08-Web信息同步实现规范.md)
> 关联文档：[`01-全局设计约束.md`](./01-全局设计约束.md)、[`03-ObjectList.md`](./03-ObjectList.md)、[`04-ObjectDetail.md`](./04-ObjectDetail.md)

## 1. 目标

图标用于帮助 Human 快速识别对象类型、状态、集合语义和操作入口。图标不是装饰，不应因为局部视觉效果随意替换。

本文解决四类图标的边界：

1. 对象类型图标：回答“这是什么对象”；
2. 状态图标：回答“它处于什么执行态势”；
3. 操作图标：回答“点这里会做什么”；
4. 分区提示符：回答“这里是一个阅读分区或分组”。

## 2. 基本规则

1. 同一对象类型在导航、列表、详情、引用卡片和右侧扩展阅读区中必须使用同一个对象类型图标。
2. 同一操作在所有页面中必须使用同一个操作图标，不随对象类型改变。
3. 状态图标只表达状态，不替代对象类型图标。
4. 对象身份标题必须使用对象类型图标；包括 WorkArea、TaskPlan、Task、SubTask 的列表卡片标题、详情页标题和任务队列行标题。
5. 页面大区块、状态分组和任务队列标题如果只是阅读分区，不承担对象身份识别，统一使用小圆点，不额外引入语义图标。
6. 业务页面不得直接导入对象类型标准图标表达对象身份，必须通过 `ObjectTypeIcon`、`CollectionTitleIcon` 或 `OBJECT_TYPE_ICONS` 映射取得。
7. plain 行中的右侧操作图标默认是中性 ghost；类型色只用于左侧类型识别、ID 或短标签。
8. 复制完整路径是稳定工具动作，默认和 hover 都保持中性 ghost；扩展阅读、进入箭头等导航/阅读动作可在行 hover、当前打开或明确选中时继承所在分组/状态色。
9. 如果现有 lucide 图标不能准确表达对象类型，应新增本地语义封装或设计自定义图标，不用相近但语义错误的图标凑合。

## 3. 对象类型图标

对象类型图标只用于识别对象类型。禁止用对象类型图标表达状态。

| 对象类型 | 标准图标 | 用途 | 备注 |
|---|---|---|---|
| Dashboard | `LayoutDashboard` | 主导航、页面入口 | 仪表盘入口图标 |
| WorkArea | `Layers` | 工作域导航、工作域引用、WorkArea 详情身份识别 | 表达长期工作域/层级承载；不得用 `MapPinned` |
| TaskPlan | `ClipboardList` | 任务计划导航、TaskPlan 标题和 TaskPlan 引用 | 表达计划清单；不得用 `GitBranch` |
| Task | `ListTodo` | Task 引用、Task 列表和详情身份识别 | 表达 AI 可执行事项，不使用计划清单图标 |
| SubTask | `ListTree` | SubTask 引用、子任务集合和详情身份识别 | 表达 Task 下的叶子执行事项 |
| ADR | `FileSignature` | 决策导航和决策引用 | 表达已记录的决策 |
| Pitfall | `Lightbulb` | 踩坑经验导航和踩坑经验引用 | 表达可复用踩坑经验，不得用 `Bug` 避免误解为缺陷列表 |
| Memo | `StickyNote` | 备忘导航和引用 | 表达未任务化信息 |
| Profile | `IdCard` | 项目画像入口和引用 | 表达项目身份信息 |
| Change | `GitCommit` | 变更记录入口和引用 | 表达 Git 提交/变更 |
| Validate | `Shield` | 校验入口 | 表达校验边界 |
| Gate | `ShieldCheck` | Human Gate 入口 | 表达确认/授权 |
| Changelog | `ClipboardCheck` | 变更日志入口 | 表达记录与完成项 |

### 3.1 Task / SubTask 图标说明

Task 和 SubTask 不再借用状态图标作为对象类型图标。当前采用 lucide 原生图标作为第一版稳定语义：

| 图标 | 语义 |
|---|---|
| `ListTodo` | Task 是可执行事项，有清单但不代表计划集合 |
| `ListTree` | SubTask 是 Task 下的叶子事项，带层级关系 |

TaskFlow 状态图标仍可在任务队列行中表达执行态势，但对象引用、父子对象入口和类型标签应优先使用上述对象类型图标。

## 4. 状态图标

状态图标由 `TaskFlowStatus` 统一表达，只用于任务态势和执行状态。

| 态势 | 当前图标 | 使用位置 |
|---|---|---|
| ready / planned | `CircleDashed` 或等待态图标 | 待执行、计划中 |
| executing | `CirclePlay` | 执行中 |
| verifying | `ClipboardCheck` | 验证中 |
| absorbing / review_needed | `BadgeCheck` | 已验证待吸收/待关闭 |
| blocked | `Hourglass` | 等待前置 |
| closed | `CheckCircle2` | 已关闭 |
| risk | `CircleAlert` | 风险或异常 |

状态图标可使用状态色和弱背景；对象类型图标不使用状态语义。

## 5. 操作图标

操作图标只表达动作。它们默认不承担对象类型或状态表达。

| 操作 | 标准图标 | 规则 |
|---|---|---|
| 复制完整路径 | `Copy`，成功后 `Check` | 统一通过 `CopyPathButton`；点击必须 `stopPropagation()` |
| 打开右侧扩展阅读 | `PanelRightOpen` | 用于对象或文档预览入口 |
| 关闭当前扩展阅读 | `PanelRightClose` | 当前行已在右侧展开时切换 |
| 进入详情主路由 | `ArrowRight` | 只用于主路由入口；默认弱灰，hover 轻微右移 |
| 展开/收起集合 | `ChevronDown` / `ChevronRight` | 只表达折叠状态，不表达对象类型 |
| 外部链接 | `ExternalLink` | 只用于外部 URL |

plain 行和状态色背景行中，`Copy`、`PanelRightOpen/Close`、`ArrowRight` 默认同级弱灰；状态表达交给左侧状态图标、行背景和态势条。状态色背景行 hover 时，`PanelRightOpen/Close` 和 `ArrowRight` 可切到该行背景对应的状态色；`Copy` 只有自身 hover 时才变色。

## 6. 标题图标与分区圆点

标题前的视觉符号分为两类：对象身份图标和分区圆点。不要混用。

| 场景 | 标准表达 | 示例 |
|---|---|---|
| 对象标题 | `ObjectTypeIcon(type)` | WorkArea 卡片标题、TaskPlan 详情标题、Task 队列行标题、SubTask 行标题 |
| 对象引用行 | `ObjectTypeIcon(type)` | 决策 / 备忘 / 踩坑经验 / Task 引用 |
| 阅读大区块 | 小圆点 | 属性、关闭判断、任务队列、关联材料 |
| 状态分组标题 | 小圆点 | WorkArea 卡片/详情中的“3 个活跃计划”“2 个待关闭计划” |
| 任务队列标题 | 小圆点 | TaskPlan 卡片和 TaskPlan 详情中的“任务队列” |
| 状态态势 | `TaskFlowStatus` 状态图标 | Task 行左侧的执行中、验证中、已关闭等状态 |

如果 lucide 图标对某个对象类型过于抽象，应先在 `SemanticIcon.tsx` 新增本地语义封装；必要时可使用短文字徽标，例如 ADR，但仍必须通过统一组件输出，不在页面里临时拼写。

## 7. 颜色规则

1. 对象类型图标按所在层级决定颜色：对象卡片标题和详情页主标题使用对象类型色；状态色行或状态色分组内的对象图标继承标题文字颜色，不单独使用对象类型色或 `ldvh-accent`；plain 引用行可使用对象类型色。
2. 状态图标使用状态色，例如执行中绿色、验证中蓝色、已验证/待关闭紫色、等待 amber。`verifying` 必须始终使用 blue 系列，`review_needed` / TaskFlow absorbing 必须始终使用 violet 系列，避免“验证中”和“已验证”混淆。
3. 操作图标默认使用 `text-ldvh-text-secondary/70` 或等价弱灰。
4. 当前行处于状态色背景时，左侧状态图标、行背景和态势条承担状态表达；对象类型图标不得再叠加另一种彩色。
5. 右侧操作图标默认保持中性弱灰；复制图标只有自身 hover 时切到该行背景对应的状态色。
6. 类型色和状态色冲突时，优先保持状态判断清晰；对象类型可降级为继承文字色或弱标签。

## 8. 实现建议

图标映射集中在 `web/src/components/SemanticIcon.tsx`，页面不得自行散落对象类型和集合标题图标选择。

```typescript
export const OBJECT_TYPE_ICONS = {
  workarea: Layers,
  taskplan: ClipboardList,
  task: ListTodo,
  subtask: ListTree,
  adr: FileSignature,
  pitfall: Lightbulb,
  memo: StickyNote,
  profile: IdCard,
  change: GitCommit,
};
```

语义组件：

1. `ObjectTypeIcon`：按对象类型返回标准图标；
2. `CollectionTitleIcon`：仅保留给确有集合身份识别需要的旧入口；普通页面分区优先使用小圆点。

操作图标暂由 `CopyPathButton`、`ReferenceCard` 和页面内按钮承接；后续如继续扩展操作种类，再抽 `ActionIconButton`。

## 9. 当前待收敛项

1. 核心对象入口已接入集中映射：Sidebar、Dashboard 统计/活动、AttentionTest、ObjectList、ObjectDetail、ReferenceCard、ReadingPanel。
2. 后续如继续扩展操作种类，可抽 `ActionIconButton`，进一步收敛复制、扩展阅读、进入详情和外部链接的尺寸与 hover。
3. 如果后续认为 `ListTodo` / `ListTree` 与 LDVH 任务语义仍不够贴合，再新增本地自定义 Task / SubTask 图标；在此之前不得回退到状态图标或通用层级图标。
