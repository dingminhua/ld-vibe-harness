# LDVH 能力保障规范

> 创建日期：2026-06-11
> 定位：定义 LDVH 如何提供和组合能力，以保障正式规范提出的落地要求，并定义能力输出必须遵守的运行纪律
> 适用范围：Rules / Instructions、Skill、Command、Agent、Hook、Code、Web、Human Gate、CI、工作流程、人工降级检查、能力缺口分流、薄入口、AI 统一入口、入口分层、LDVH 自建 Skill、Skill 元数据和 Skill 正文边界
> 上位依据：`docs/specs/04-规范落地与环境适配基础规范.md`、`docs/specs/04.01-规范落地声明规范.md`
> 参考来源：`docs/specs/04.03-环境能力清单与环境适配规范.md`、`docs/research/26-LDVH环境投射技术经验吸收研究.md`

参考来源路径中的“投射”等历史术语只作为文件名兼容保留。本文正文按 `docs/specs/02-术语规范.md` 使用能力保障、环境适配和能力输出。

## 1. 本文解决的问题

本文解决 LDVH 如何满足规范落地要求，以及 LDVH 能力输出应遵守哪些运行纪律的问题。

04.01 只说明正式规范提出了什么要求；本文说明 LDVH 应提供哪些能力、如何组合这些能力、能力不足时如何形成建设需求或降级检查。环境能力清单和具体适配方式由 04.03 处理。

LDVH 能力保障不是环境能力盘点，也不是由环境决定。即使当前主用环境缺少某项能力，LDVH 仍可以为了其他环境、Code、CI、Web 或后续演进建设该能力；具体环境只影响承载方式、适配检查和适配降级。

LDVH 运行纪律不是环境客观能力，也不是个人环境偏好。它用于避免能力输出膨胀、入口分裂、Skill 命名混乱和环境配置替代事实源。

## 2. 能力保障池

LDVH 当前能力保障池包括以下类型：

| 能力 | 适合保障 | 不适合保障 | 边界 |
|---|---|---|---|
| Rules / Instructions / AI 入口 | 入口可见、硬约束摘要、事实源边界、最小读取顺序、STOP 点 | 完整规范正文、低频流程、临时判断、状态记录 | 只做薄入口和导航，不是事实源 |
| Skill | 流程复用、多步骤 SOP、稳定输入输出、检查步骤 | 稳定规则正文、Human Gate 判断本身、独立上下文 | Skill 不能替代正式规范，不能调度子 Agent 作为默认假设 |
| Command | 显式流程入口、重复 Prompt、命令包装、Code 调用 | 环境事实源、长期状态、绕过审批的自动写入 | Command 是入口或执行包装，不是事实源 |
| Agent / subagent | 独立上下文、专项审查、并行视角、复杂争议 | 简单问答、单文件小改、稳定结论直接生效 | 输出必须回主控，稳定结论回写后才生效 |
| Hook / lifecycle | 生命周期触发、提交前后检查、工具调用前后检查、会话停止检查 | 规范正文、语义判断、无授权写入 | 触发不等于通过，必须受 Human Gate 和 Code 约束 |
| Code / CI / 测试 | 解析、校验、聚合、受控写入、漂移检查、确定性执行 | Human 授权、价值判断、复杂语义结论 | Code 按 07 规范实现，输出需分流回事实源 |
| Web / Human 入口 | 态势呈现、确认、授权、验收、受控轻写入 | 第二事实源、绕过 Code 校验的后台 | Web 是派生视图和交互面，不维护独立事实 |
| 人工降级检查 | 环境能力不足、机制未实现、证据不足时的显式替代 | 假装完整支持、长期静默跳过 | 必须记录残留风险和后续补齐事项 |

## 3. 要求到能力的默认映射

| 规范落地要求 | 默认能力保障组合 | 常见补充 |
|---|---|---|
| 上位约束承接要求 | 规范引用、索引、入口摘要、42 检查、Code 引用检查 | Human Gate、ADR、Task |
| 入口可见要求 | Rules / Instructions、AI 统一入口、薄引用、40 索引 | Skill 入口、Command、环境说明 |
| 流程复用要求 | Skill、Command、工作流程、操作清单 | Code wrapper、Web 表单、Task 模板 |
| 子 Agent 思考要求 | Agent / subagent、44 多角色思考、主控汇总 | Human Gate、审阅清单、并行工作区 |
| 确定性执行要求 | Code、命令入口、CI、测试、结构化输出 | Web 展示、Command 包装、Task 验证 |
| Human 交互要求 | Human Gate、Web、结构化问询、对话确认 | diff、预览、审批提示、风险说明 |
| 生命周期触发要求 | Hook、CI、自动运行、命令检查、人工降级检查 | Skill 提醒、入口 STOP 点、42 增量检查 |

默认映射只是 LDVH 提供能力保障的起点。具体环境适配时，04.03 应根据环境能力清单说明能力输出如何由当前环境承载，并记录适配检查、适配降级或待确认事项。

## 4. 能力提供原则

LDVH 提供能力保障时，应遵守以下原则：

1. **要求先行**：先读取 04.01 或正式规范中的落地要求，再提供能力保障；
2. **组合优先**：重要要求通常需要入口、流程、Code、Human Gate 或触发机制组合保障；
3. **强路径保留**：某环境缺少能力时，不删除 LDVH 对强环境或 Code / CI 的高质量能力路径；
4. **薄入口优先**：入口类能力只保留导航、触发、STOP 点和权威引用；
5. **确定性外移**：能机械判断的规则应优先进入 Code、测试或 CI；
6. **授权前置**：高影响写入、长期配置、权限扩大和完整支持声明必须 Human Gate；
7. **证据回写**：能力输出中的稳定事实必须回写到 Git 文件事实源。

## 5. 能力缺口与环境缺口处理

当 LDVH 尚未提供能力完整保障某项落地要求时，应记录能力缺口。当 LDVH 已有能力保障但当前环境不能完整承载时，应记录环境缺口。处理顺序如下：

1. 检查是否已有正式规范、Code、Skill、Command、Web、工作流程或人工检查可复用；
2. 若已有能力只需扩展，应形成最小扩展和验证方式；
3. 若 LDVH 能力不存在，应形成能力建设需求，说明来源要求、输入、输出、失败条件、验证方式和降级方式；
4. 若 LDVH 已有能力但当前环境不支持，应在 04.03 对该环境记录环境缺口和适配降级，不降低 LDVH 要求；
5. 若涉及高影响写入、权限、长期配置或完整支持声明，应触发 Human Gate；
6. 稳定需求应分流到 Task、ADR、Memo、Code 需求、Web 需求或正式规范。

能力缺口和环境缺口不得通过以下方式解决：

1. 删除正式规范中的落地要求；
2. 把弱环境的限制写成 LDVH 全局限制；
3. 宣称 Skill 可以替代 Hook、Code、Human Gate 或 Agent；
4. 把人工降级写成完整支持；
5. 把 research、refs 或工具输出直接写成事实源。

## 6. 能力输出边界

能力保障落实到环境后会形成能力输出。能力输出可以是：

1. 入口摘要或薄引用；
2. Skill、Command、Agent、Hook、CI 或 Web 入口；
3. Code 校验命令、测试入口或报告摘要；
4. Human Gate 提示、审批记录或对话确认证据；
5. 人工降级检查方式和残留风险说明。

能力输出不得承载：

1. 与正式规范冲突的规则；
2. 完整规范正文或字段契约全文；
3. 未被正式规范吸收的 research / refs 结论；
4. 未经 Human Gate 授权的自动写入；
5. 被当成最终事实源的缓存、页面、工具输出或聊天摘要。

## 7. Rules / Skill / Agent 边界细则

Rules / Instructions、Skill 和 Agent / subagent 应按以下边界组合使用：

| 能力 | 允许承载 | 禁止承载 | 必须交还主控 | 必须回写 | Human Gate 触发 |
|---|---|---|---|---|---|
| Rules / Instructions | 入口摘要、硬约束摘要、事实源边界、STOP 点、权威引用、Skill 或流程入口提示 | 完整规范正文、完整流程正文、字段契约全文、状态机正文、长期过程状态、Agent 结论 | 需要执行多步骤流程、需要判断是否进入 Skill / Agent、需要修改事实源或扩大入口范围时 | Rules 发现的新稳定规则、入口漂移、事实源边界变化 | 新增长期入口、放宽薄入口、复制规范正文、改变事实源边界或跨工作区写入 |
| Skill | 可复用流程、标准化输入输出、检查步骤、失败处理、STOP 点、交还方式、受控写入流程入口 | 稳定规则正文、字段契约全文、状态机正文、Human Gate 判断本身、默认调度 Agent、直接声明稳定结论生效 | 需要独立上下文、并行审查、权限隔离、Human Gate 判断或超出 Skill 输入输出边界时 | Skill 产出的稳定事实、验证证据、变更结论、流程缺口 | 创建、修改、删除、重命名 LDVH 自建 Skill；允许 Skill 新增稳定规则、状态或 Human Gate 条件 |
| Agent / subagent | 独立上下文分析、专项审查、并行视角、复杂争议、权限边界差异判断 | 简单问答、单文件小改、替代主控决策、绕过 Human Gate、直接写入稳定事实源、直接让结论生效 | 输出完成后、发现事实源冲突、需要 Human 确认、需要 Code 验证或需要回写稳定结论时 | 被主控采纳后的稳定结论、证据路径、风险、未决问题、后续 Task / ADR / Memo | 启用长期 Agent、扩大权限、并行写入、声明完整支持、采纳高影响结论 |

Rules 可以指向 Skill 或工作流程入口，但不得复制 Skill 流程正文。Skill 可以提示主控评估是否需要 Agent / subagent，但不得默认调度 Agent，不得把 Agent 输出直接并入稳定结论。Agent / subagent 输出不得直接生效，必须回到主控或 Human，经必要验证和回写后才成为稳定事实。

Agent / subagent 输出至少应包含：

1. 任务边界；
2. 已读取事实源；
3. 分析结论；
4. 证据路径；
5. 未决问题；
6. 需 Human Gate 项；
7. 回主控建议；
8. 不可直接生效声明。

以下写法应视为反例：

1. 在 Rules 中复制正式规范、Skill 流程或字段契约全文；
2. 在 Skill 中新增稳定规则、状态机、字段契约或 Human Gate 条件；
3. 在 Skill 中写入默认调度 Agent 或自动采纳 Agent 输出；
4. 将 Agent 输出直接写成验收结论、事实源变更或完整支持声明；
5. 用环境能力存在反推 LDVH 必须使用某个 Rules、Skill 或 Agent。

LDVH 当前运行纪律包括以下要求：

| 编号 | 要求 | 内容 | 适用范围 | 默认效力 | 适用位置 | 风险控制 |
|---|---|---|---|---|---|---|
| LDR-01 | 薄入口要求 | 能力输出只能保留入口摘要、触发条件、关键检查项、STOP 点、权威引用、交还方式和降级提示，不得复制完整规范正文 | Rules / Instructions、Skill、Agent 定义摘要、Hook、CI、Command、Web / Human 入口 | 默认适用 | 04.03 环境适配、能力输出、入口摘要 | 防止能力输出成为第二事实源 |
| LDR-02 | AI 统一入口要求 | `../../LDVH-AI-ENTRY.md` 是默认 AI 统一入口，环境入口只做指向该文件的薄引用 | LDVH 自身项目、工作区入口、环境用户级入口 | 默认适用 | `../../LDVH-AI-ENTRY.md`、环境薄入口 | 防止多份入口漂移 |
| LDR-03 | 入口分层要求 | 区分工作区入口视角、LDVH 管理入口视角和管辖项目自身事实源 | 工作区级入口、LDVH 自身项目、管辖项目 | 默认适用 | AI 统一入口、管辖项目配置、42 | 防止用户工作区配置和 LDVH 管理入口混同 |
| LDR-04 | LDVH 自建 Skill 命名要求 | LDVH 通用 Skill 使用 `ldvh-` 前缀，稳定标识使用小写字母、数字和连字符 | LDVH 自建 Skill 和包装 Skill | 默认适用 | Skill 实体、04.03 环境适配 | 防止 LDVH Skill、业务 Skill 和第三方 Skill 混淆 |
| LDR-05 | Skill 元数据触发要求 | Skill 描述应说明能力、触发时机、不适用场景和必读权威入口 | LDVH 自建 Skill、包装 Skill | 默认适用 | Skill 元数据、环境适配 | 降低误触发和漏触发 |

## 9. 薄入口与统一入口

薄入口可以包含：

1. 入口身份、适用范围和权威来源；
2. 触发条件和不适用场景；
3. 必读正式规范、环境适配卡片、42 流程、Code 入口或工作对象路径；
4. 关键检查项、STOP 点、Human Gate 提醒和降级方式；
5. 输入、输出、交还主控和回写出口；
6. 能力输出与正式规范之间的路径或版本关联。

薄入口不得包含：

1. 完整规范正文、字段契约、状态机、工作流程全文或环境教程；
2. 未被正式规范吸收的 research、refs 或输入材料结论；
3. 与正式规范并行维护的规则正文；
4. 未经 Human Gate 授权的写入、覆盖、删除或状态流转规则；
5. 稳定事实、决策或验收结论的唯一记录。

LDVH 默认只维护一个 `../../LDVH-AI-ENTRY.md` 作为 AI 统一入口。环境入口应只做薄引用，指向该文件并说明按工作区入口视角识别管辖项目、事实源和执行边界。

环境薄引用应遵守：

1. 使用当前用户真实绝对路径指向 `../../LDVH-AI-ENTRY.md`；
2. 不复制 `../../LDVH-AI-ENTRY.md` 正文；
3. 不复制正式规范清单全文；
4. 不在管辖项目内默认创建项目级环境入口；
5. 确需创建项目级入口时，必须 Human Gate 并记录退出方式；
6. 环境位置、格式和持久性由 04.03 的环境适配卡片处理。

Trae 与 Codex 的具体入口位置不得在本文写成完整支持结论。它们应在 04.03 中作为环境适配方式和待实测事项表达。

## 10. LDVH 自建 Skill 边界

LDVH 自建 Skill 的稳定标识应遵守：

1. 使用 `ldvh-` 前缀；
2. 前缀后使用表达能力或治理动作的短名；
3. 只使用小写字母、数字和连字符；
4. 不绑定具体业务项目名、个人名、环境名或临时阶段名；
5. 不使用版本号、状态词或营销式名称作为稳定标识。

Skill 的描述或等价元数据应说明：

1. 该 Skill 能保障什么能力；
2. 何时使用；
3. 何时不使用；
4. 关键触发词或生命周期阶段；
5. 需要读取的权威入口。

Skill 正文应使用中文，除非环境字段或技术标识要求使用英文。环境元数据必须英文时，Skill 正文仍应保留中文可读的定位、触发条件和边界说明。

## 11. 运行纪律启用与降级

LDR-01 至 LDR-06 默认适用于 LDVH 自建能力输出。AI 创建、修改、审计或迁移能力输出时，应先检查本文，再由 04.03 判断具体环境适配方式。

如果环境无法完整承载本文要求，应按以下顺序处理：

1. 确认是否可以通过环境入口、Skill、Command、Code、Web、42 或人工检查满足；
2. 仍不能满足时，记录适配降级和残留风险；
3. 若会削弱事实源边界、Human Gate 或验证纪律，应触发 Human Gate；
4. 不得通过复制规范正文、放宽 Skill 命名或让入口自成事实源来规避缺口。

---
## 12. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 将某项能力提升为 LDVH 全局必须能力；
2. 改变 Rules、Skill、Agent、Hook、Code、Web、Command 或 Human Gate 的边界；
3. 允许能力输出直接成为最终事实源；
4. 新增稳定工具、自动触发或受控写入入口；
5. 允许环境能力不足时不记录降级；
6. 关闭关键能力缺口或声明能力完整可用。
7. 新增、删除或改变本文登记的 LDVH 运行纪律；
8. 放宽薄入口要求，允许能力输出复制完整规范正文；
9. 改变 `ldvh-` 前缀的适用范围；
10. 允许管辖项目业务 Skill 使用 `ldvh-` 前缀；
11. 创建、修改、删除、重命名、搬移或启用 LDVH 自建 Skill；
12. 允许 Skill 新增稳定规则、字段、状态或 Human Gate 条件；
13. 删除、重命名或移动 `../../LDVH-AI-ENTRY.md`，或改变 AI 统一入口默认职责。

能力保障检查至少包括：

| 检查项 | 标准 |
|---|---|
| 要求来源 | 能力保障来自正式规范落地要求 |
| 能力边界 | 各能力未互相替代或越权 |
| Rules / Skill / Agent 边界 | Rules 不复制流程正文，Skill 不默认调度 Agent，Agent 输出回主控后才可采纳 |
| Agent 输出 | Agent / subagent 输出包含任务边界、事实源、证据路径、未决问题、Human Gate 项和不可直接生效声明 |
| 组合完整 | 入口、流程、Code、Human Gate、触发和降级按需组合 |
| 强路径保留 | 弱环境降级未删除强环境能力路径 |
| 缺口分流 | 能力缺口已进入 Task、Code、Web、ADR、Memo 或 open item；环境缺口已进入 04.03 适配降级或待补齐事项 |
