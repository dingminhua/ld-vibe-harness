# Trae 旧清单迁移输入说明

> 创建日期：2026-06-09
> 收口日期：2026-06-11
> 定位：保留 Trae 旧清单的迁移入口，说明旧 Trae 资料如何迁入当前环境能力清单与投射规范
> 适用范围：Trae 旧资料、Trae refs 线索、Trae Work CN 环境投射待核对事项
> 上位依据：`docs/specs/04.03-环境能力清单与投射规范.md`、`docs/specs/04.06-环境能力清单规范.md`

---
## 1. 本文解决的问题

本文不再作为 Trae 当前环境投射事实源，也不再维护独立 Trae 要求响应矩阵。

Trae Work CN 当前环境能力清单、投射方式、投射检查、投射降级和待补齐事项，以 `docs/specs/04.03-环境能力清单与投射规范.md` 为准。

本文只保留为 Trae 旧资料迁移输入，用于后续核对：

1. Trae 入口、Rules、Skill、Agent、Command、Human Gate、Code / 终端候选；
2. Trae refs 中可作为环境客观能力清单的证据线索；
3. 旧清单中仍需转写到 04.03 的待确认事项；
4. 旧 Trae Solo 口径与当前 Trae Work CN 口径之间的差异。

---
## 2. 迁移边界

| 内容类型 | 处理方式 |
|---|---|
| Trae 入口、Rules、Skill、Agent、Command、Human Gate、Code / 终端候选 | 可作为迁移线索，需按 04.03 字段重写 |
| Trae refs 路径和旧实测待办 | 可作为来源线索，不能直接等同当前可用证据 |
| Trae Solo 已完整支持类结论 | 不迁移为当前结论 |
| 非 LDVH 能力保障范围内容 | 不迁入 04.03 当前能力保障范围 |
| 旧承接口径 | 改写为 LDVH 主动环境投射口径 |

---
## 3. 使用规则

AI 需要处理 Trae 环境投射时，应先读取 `docs/specs/04.03-环境能力清单与投射规范.md`。

只有在需要追溯旧 Trae 资料时，才读取本文。读取本文后，AI 必须执行以下检查：

1. 该内容是否仍适用于 Trae Work CN；
2. 是否有当前 refs、官方资料或实测证据支持；
3. 是否属于 LDVH 能力保障范围；
4. 是否需要写成待确认、人工降级或不迁移；
5. 是否会把旧环境能力反向写成 LDVH 全局要求。

---
## 4. Human Gate 与检查要求

以下情况必须触发 Human Gate：

1. 将本文重新作为 Trae 当前事实源；
2. 声明 Trae Work CN 已完整支持 LDVH；
3. 删除、重命名或移动本文；
4. 把旧 Trae Solo 结论直接写成 Trae Work CN 当前结论；
5. 启用长期入口、自动触发、跨工作区写入或高影响配置。

检查本文时，应确认：

| 检查项 | 标准 |
|---|---|
| 当前事实源 | Trae 当前投射以 04.03 为准 |
| 历史边界 | 本文只作为旧资料迁移输入 |
| 证据状态 | 未把 refs-only 或待确认内容写成已验证 |
| 投射主体 | LDVH 主动投射，Trae 只提供客观能力清单 |
| 降级路径 | 证据不足时写为待确认或人工降级 |

---

3. 调整 42，使 Trae 投射检查消费 04.03；
