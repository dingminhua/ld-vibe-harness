## 1. 定位

本文承载 01 授权的规范身份字段、规范身份状态闭集、active 身份块能力提示、附件身份字段、附件身份状态闭集和身份辅助核对表。

01 正文定义规范身份治理原则、必要章节、目录登记、附件授权、Human Gate 和 Code 覆盖边界；本文只能维护这些已授权的字段表、状态闭集和辅助核对信息，不得单独改变身份治理原则、必要章节、目录规则、附件权威边界、active 切换规则或 Code 输出 Schema。

## 2. v2_spec 字段表

`v2_spec` 字段契约如下：

| 字段 | 出现要求 | 含义 |
|---|---|---|
| `spec_id` | 必须出现 | 规范编号，必须与文件名编号一致 |
| `spec_kind` | 必须出现 | 规范类型；必须使用本文定义的闭集 |
| `title` | 必须出现 | 规范标题，必须与一级标题一致 |
| `status` | 必须出现 | 规范状态；必须使用本文定义的闭集 |
| `authority` | 必须出现 | 权威状态；必须使用本文定义的闭集 |
| `canonical_path` | 必须出现 | 当前文件路径，必须与真实路径一致 |
| `created` | 必须出现 | 创建日期，格式为 `YYYY-MM-DD` |
| `updated` | 必须出现 | 最近正文变更日期，格式为 `YYYY-MM-DD`，不得早于 `created` |
| `parent_spec` | 必须出现 | 父规范路径；无父规范时使用空字符串 |
| `relation` | 必须出现 | 与父规范的关系；无父规范时使用空字符串 |
| `positioning` | 必须出现 | 本规范定位 |
| `scope` | 必须出现 | 本规范适用范围 |
| `basis` | 必须出现 | 上位依据；无上位依据时使用空列表 |
| `related_specs` | 必须出现 | 相关规范；无相关规范时使用空列表 |
| `migration_sources` | 必须出现 | 迁入、吸收或参考的来源；无来源时使用空列表 |
| `active_fact_source` | 必须出现 | 当前 active 事实源；无 active 对应物时使用空列表并在待补齐事项说明 |
| `code_consumption` | 必须出现 | Code 或知识地图消费的字段、关系、结构或诊断入口 |
| `migration_status` | 必须出现 | 迁移状态；必须使用本文定义的闭集 |

## 3. v2_spec 状态闭集

v2 写作期规范身份块使用以下闭集：

| 字段 | 允许值 | 含义 |
|---|---|---|
| `spec_kind` | `spec` | 根规范 |
| `spec_kind` | `member_spec` | 经所属主规范授权的专题成员规范；不得由普通目录草案自行声明 |
| `status` | `draft` | 写作中，未完成单篇核对，未 active |
| `status` | `ready_for_review` | 已完成本轮写作，等待 Human 单篇核对 |
| `status` | `active` | 已经 Human 单篇确认并切换为 active |
| `status` | `deprecated` | 已废弃或被替代；必须说明替代事实源或关闭理由 |
| `authority` | `not_active_until_human_approved` | 未经 Human 单篇确认前的 v2 写作区权威状态 |
| `authority` | `active` | 已成为 active 正式规范依据 |
| `authority` | `deprecated_by` | 已由其它 active 事实源替代 |
| `migration_status` | `not_migrated` | 尚未开始迁入 active 来源内容 |
| `migration_status` | `partially_migrated` | 已迁入部分内容，但尚未完整核对来源职责 |
| `migration_status` | `ready_for_review` | 已完成本轮迁入，等待 Human 单篇核对 |
| `migration_status` | `migrated` | 已完成迁入并经 Human 单篇确认 |
| `migration_status` | `not_applicable` | 无 active v1 对应来源或不涉及迁移 |

## 4. active 身份块能力提示

v2 规范进入 active 时，active 身份块至少需要保持以下能力：

| 能力 | 含义 |
|---|---|
| 编号、标题、路径和状态可校验 | Code 或人工降级核对能判断身份块与文件事实一致 |
| 上位依据、相关规范、父规范和附件授权可派生 | 知识地图能生成可回指的关系边 |
| `positioning` 与 `scope` 可读 | AI 能判断读取价值和权威范围 |
| `code_consumption` 可读 | Code、Web、运行时扩展或知识地图能判断消费类别 |
| 来源和确认可追溯 | 迁移到 active 时，能追溯来源、active 事实源和 Human 单篇确认记录 |

本文只维护 active 身份块能力提示，不定义 active 切换流程，不直接改变当前 active `ldvh_doc` 字段。

| 字段 | 出现要求 | 含义 |
|---|---|---|

| `title` | 必须出现 | 附件标题，必须与一级标题一致 |
| `status` | 必须出现 | 附件状态；必须使用本文定义的闭集 |
| `authority` | 必须出现 | 权威状态；必须使用本文定义的闭集 |
| `parent_spec` | 必须出现 | 授权父规范路径 |
| `canonical_path` | 必须出现 | 附件真实路径 |

## 6. v2_attachment 状态闭集

附件身份块使用以下闭集：

| 字段 | 允许值 | 含义 |
|---|---|---|
| `status` | `draft` | 写作中，未完成父规范核对，未 active |
| `status` | `ready_for_review` | 已完成本轮写作，等待随父规范核对 |
| `status` | `active` | 已随父规范确认并切换为 active |
| `status` | `deprecated` | 已废弃或被替代；必须说明替代事实源或关闭理由 |
| `authority` | `not_active_until_parent_and_human_approved` | 未经父规范授权和 Human 确认前的附件权威状态 |
| `authority` | `active_with_parent` | 已随父规范成为 active 附件 |
| `authority` | `deprecated_by` | 已由其它 active 事实源替代 |

## 7. 身份辅助核对表

身份辅助核对至少包括：

| 核对项 | 标准 |
|---|---|
| 文件名一致 | 规范编号或附件编号与文件名一致 |
| 标题一致 | 身份块 `title` 与一级标题一致 |
| 路径一致 | `canonical_path` 与真实路径一致 |
| 日期有效 | `updated` 不早于 `created` |
| 状态闭集 | 状态字段属于本文定义的闭集 |
| 父级关系 | `parent_spec`、`relation` 与父规范或附件授权关系一致 |
| 来源边界 | `migration_sources` 和 `active_fact_source` 不被解释为 active 权威 |
| 消费提示 | `code_consumption` 只表达消费类别，不定义 Code 输出 Schema 或命令入口 |

本核对表用于发现身份字段缺失、路径漂移、状态误写和附件授权漂移；核对结论不能替代 01 主文档规定的高影响确认。
