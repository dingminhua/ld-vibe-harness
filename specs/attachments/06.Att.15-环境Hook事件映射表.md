## 1. 定位

本文承载环境原生 Hook 名称到 LDVH canonical event 的归一化映射表。

LDVH core 只认 canonical event：
- `session-start`
- `acknowledge-read-plan`
- `pre-tool-use`
- `git.commit-msg`

环境可以用不同的原生事件名，但必须先映射到 canonical event。Rules 方式不走环境原生映射，直接以 `trigger_source=rules` 模拟触发 canonical event。

## 2. 映射表

| 环境原生事件 | 典型环境叫法 | LDVH canonical event | trigger_source | 说明 |
|---|---|---|---|---|
| `SessionStart` | WorkBuddy / Codex / Claude Code | `session-start` | `hook` | 会话开始、恢复或重新握手的入口事件 |
| AI 消费确认 | Rules / 支持 session receipt 的 Hook 环境 | `acknowledge-read-plan` | `rules` / `hook` | AI 按 receipt 回读 P0/P1 read_plan 后写入消费证据；不要求环境原生 Hook 自动触发 |
| `UserPromptSubmit` | WorkBuddy / Codex / Claude Code | `pre-tool-use` | `hook` | 用户输入提交后的前置检查入口，可作为工具前检查家族的一种原生事件 |
| `PreToolUse` | WorkBuddy / Codex / Claude Code | `pre-tool-use` | `hook` | 工具调用前检查、阻断或补充上下文的入口事件 |
| `commit-msg` | Git | `git.commit-msg` | `hook` | Git 提交层事件，不属于 AI Hook |
| AI 自觉模拟触发 | Rules | `session-start` / `acknowledge-read-plan` / `pre-tool-use` / `git.commit-msg` | `rules` | AI 按 Runtime Protocol 主动模拟触发同一 canonical event |
| `SubagentStart` | WorkBuddy / Claude Code / Codex | — | — | **不映射**。子 Agent 不支持 SessionStart 语义，且插件子 Agent 可能完全禁用 Hook。子 Agent 统一走 Rules 路径 |

## 2.1 Payload 字段归一化

环境 adapter 或 dispatcher 必须把环境私有 payload 字段归一化为 LDVH core 可消费字段。当前已知字段如下：

| 环境 / 来源 | 事件字段 | 工具字段 | 会话字段 | target 字段 | 说明 |
|---|---|---|---|---|---|
| 通用 LDVH Hook payload | `event` / `hook_event` / `event_name` | `tool_name` | `session_id` | `target` / `target_paths` / `path` / `file_path` / `workdir` | 推荐字段；用于自定义 adapter 或测试 payload |
| Codex App Hook payload | `hook_event_name` | `tool_name` | `session_id` | `tool_input.file_path` / `tool_input.path` / `tool_input.command` | Codex command hook 会通过 stdin 传入该字段形态；不应因 argv 为空或字段名不同误判为空事件 |

若新环境字段不同，应扩展 adapter 的字段归一化测试，不得把环境私有字段直接写入 LDVH core handler 规则。

## 3. 使用规则

1. 环境 adapter 只能把原生事件归一化为 canonical event，不得把环境私有命名写入 core handler 规则。
2. 统一 dispatcher 只处理 canonical event + `trigger_source`。
3. Rules 方式直接触发 canonical event，不经过环境原生事件命名；Rules CLI 必须能用 `--target` 表达与 Hook payload 等价的工作对象。
4. 触发来源不同，不影响 handler 逻辑的唯一性。
5. adapter 必须把环境私有 payload 和 Rules CLI 参数归一化为同一个 canonical event context；同一 cwd + target 下，Hook 路径与 Rules 路径的管辖结果必须一致。
6. 支持 `session_id` 的环境应生成或查验会话 receipt；没有 `SessionStart` 可见输出时，不得仅凭界面不可见判定 Hook 失效。
7. 写类工具和提交路径必须检查 `read_plan_consumed.status=acknowledged`；缺失时阻断，普通只读命令不得误阻断。写类工具无法确定 target 时必须阻断并要求显式 target。
8. 当 Hook 路径只剩 cwd fallback 而未显式提供 payload/target，且操作已落到管辖项目或写类门禁相关范围时，dispatcher 应附加 `HOOK_ADAPTER_PAYLOAD_GAP` 诊断，提示 adapter 需要把 raw payload 或 canonical context 传入；该诊断不得替代 `HOOK_UNKNOWN_TARGET`。

## 4. 待补齐事项

1. 后续如发现更多环境原生事件名，应优先归入本表的既有 canonical event 家族，而不是新建并行事件体系。
2. 若某环境无法提供稳定原生事件名，应回到 Rules 方式或环境入口薄引用路径，不得伪造 Hook 原生语义。
