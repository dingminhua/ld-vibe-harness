# 11A Human Gate 构成变更补救记录

阶段：11A

目的：补齐 V3 构成体系调整的程序性记录，避免把早期迁移中的结构性改动继续留在未说明状态。

## 触发背景

审计指出 V3 迁移中存在以下高影响结构变化：

1. 六类构成要素收口为五类构成要素；
2. “运行时扩展”不再作为构成要素，转入保障与衔接层和环境适配归口；
3. “行动编排”统一改为“行动模板”；
4. “工作对象”统一收口到事实对象 / 受管项目 target 语义；
5. Rules / Skill 顶层机制取消；
6. 知识地图降为 legacy_alias，由 Action Guide / 行动指南承接。

这些变化影响 V2 运行体系判断，按 V2 / V3 的 Human Gate 精神，不应只由 AI 在迁移中单方面完成。

## 当前 Human 指令

当前对话中 Human 在看到阶段 11 计划后要求：“推进吧 一直到 11 全部完成”。

本记录将该指令解释为：Human 授权执行阶段 11 的补救工作，并允许以当前 V3 五类构成、保障与衔接层、Rules/Skill 顶层取消和环境适配规范为后续整改基线。

本记录不声称早期迁移发生前已经存在完整确认，也不把迁移过程中的程序缺口抹掉。它只补齐从阶段 11 起继续推进 V3 主线所需的 Human Gate 补救记录。

## 补救结论

1. 五类构成要素继续作为 V3 正式骨架；
2. 保障与衔接层不是第六类构成要素；
3. Rules / Skill 顶层机制保持取消，不作为后置入口；
4. 环境入口归口进入 `specs/11-环境适配规范.md`；
5. 后续新增、删除、改名或重排构成要素、环境入口类型或接入状态闭集，仍必须重新进入 Human Gate。

## 边界

本记录不能授权环境自动接入、Hook 扩大安装、Web 通用写入、事实源迁移、风险接受或验收通过。
