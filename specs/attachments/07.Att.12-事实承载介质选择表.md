## 1. 定位

本文承载 07 授权的事实承载介质选择表。

07 正文定义事实源原则；本文只说明 Markdown、YAML、代码文件和派生数据适合承载什么，不得定义目录归属、字段存在性、状态机、Human Gate 或 Code 输出 Schema。

## 2. 介质选择表

| 介质 | 适合承载 | 不得承载 |
|---|---|---|
| Markdown 正文 | 背景、原因、解释、设计语境、理念、规范说明、项目资料、调研、报告和人类需要阅读审查的长文本事实 | 可机械解析的字段注册表权威结构、运行时缓存、Code 输出缓存 |
| YAML 或等价结构化块 | 工作项、状态、结构化关系、审计字段、身份元信息、字段契约、配置清单、机器可读索引和最小状态字段 | 长篇规则解释、Human 判断替代物、未授权字段扩展 |
| 代码文件 | 确定性实现、校验器、聚合器、解析器、Web 信息同步实现、测试实现和工具入口 | 规范规则本体、字段存在性、状态机、Human Gate、对象证据正文 |
| 派生数据或命令输出 | 导航、诊断、聚合、展示、临时报告、迁移辅助和工具运行中间结果 | 最终事实源、集合事实源、长期状态或权威目录 |

## 3. 使用规则

文件格式和编程语言是承载形式，不是事实源权威来源。一个事实能否成为稳定事实，取决于它是否写入对应权威位置、是否符合事实源边界、是否经过必要 Human Gate、是否能被 Git 追溯，而不是取决于它使用 Markdown、YAML、代码或 JSON。

派生数据必须能从 Git 文件事实源重新生成，或在形成稳定事实后回写到对应权威位置。不能重新生成、不能回指来源或无法说明事实源边界的派生数据，只能作为临时过程材料。

## 4. 辅助核对表

| 核对项 | 标准 |
|---|---|
| 介质匹配 | 事实类型与承载介质匹配 |
| 权威位置 | 内容写在对应权威事实源，而不是仅写在方便的文件格式里 |
| 派生可重建 | 派生数据能从 Git 文件事实源重新生成 |
| 不替代规范 | 代码文件没有替代规范规则本体 |
| 不替代字段 | Markdown 说明没有替代 YAML 字段契约或注册表 |
