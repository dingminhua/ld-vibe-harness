## 1. 定位

本文承载 01 授权的规范保障要求类型闭集、类型说明、声明写法和保障声明辅助核对表。

01 正文定义规范保障要求的声明原则、五字段契约和行动编排接管边界；本文只承载类型表、写法示例和判定辅助信息。

本文不是行动编排规范，不定义具体行动流程、Scenario、Context、Gate、证据位置、回写规则或成员自描述；这些内容只能由后续 active 行动编排主文件定义。行动编排接管建议矩阵由 `attachments/01.Att.07-行动编排接管建议矩阵.md` 承载。

## 2. 保障要求类型闭集

规范保障要求使用以下类型闭集：

| 保障要求 | 含义 | 后续消费 |
|---|---|---|
| 上位约束承接要求 | 本规范需要被其它规范、流程、实现或运行时承载物遵守 | 规范体系、行动编排、Code 引用检查、知识地图影响判断 |
| 入口可见要求 | AI 或 Human 在执行、审计、迁移或确认时必须能定位本规范或其入口摘要 | README、Rules、运行时扩展入口、Web 展示、知识地图 |
| 流程复用要求 | 本规范中的判断、顺序或步骤需要形成可复用 SOP、Skill、临时步骤或行动流程 | 行动编排、Skill、临时核对动作、命令入口 |
| 工作流程接管要求 | 本规范的某项保障要求需要由 active 行动编排承担执行、验证、证据、Human Gate、缺口分流和同步责任 | 30-59 行动编排、成员自描述、Code 派生索引、Human Gate |
| 子 Agent 思考要求 | 本规范涉及独立审查、分角色判断、争议分析或高风险多视角复核 | Agent 能力、主控复核、人工独立审查 |
| 确定性执行要求 | 本规范存在可机械检查、解析、聚合、验证或回指的结构或规则 | Code、测试、CI、命令验证、临时核对动作 |
| Human 交互要求 | 本规范涉及确认、授权、验收、方向校正或高影响选择 | Human Gate、Web、对话确认、决策记录 |
| 生命周期触发要求 | 本规范或相关对象变化后需要触发复查、同步、迁移判断或问题分流 | Hook、CI、命令、Skill 提醒、入口 STOP 点、临时核对动作 |

新增、删除、重命名或改变以上类型含义时，不得在本文内直接处理，应回到 01 正文统一判断。本文不得单独扩展保障要求类型。

## 3. 声明写法

规范保障要求的 `保障机制` 字段可以写现有保障、临时核对动作和建议接管，但必须区分状态。

没有 active 专属行动编排时，来源 specs 可以临时写保障要求、落地提示和能力对接线索，但必须标明临时核对动作、建议接管或候选接管状态。已有 active 专属行动编排后，来源 specs 应保留规则权威、保障要求来源、触发理由和边界约束；面向该行动的执行步骤、能力资产映射、环境边界、验证证据、失败分流和缺口分流，应转由对应行动成员主文件承接。

推荐写法：

| 场景 | 写法 |
|---|---|
| 尚无 active 专属行动编排 | `临时核对动作；来源 specs 临时保留落地提示和能力对接线索；建议由“规范审核行动编排”接管，未 active 前不得宣称已接管`；建议接管对象应能回指 `01.Att.07` 或后续 active 行动编排 |
| 已有 active 专属行动编排 | `由 specs/NN-xxx.md 接管执行、验证、证据、Human Gate、能力资产映射、环境边界和同步责任；来源规范只保留规则权威、保障要求来源、触发理由和边界约束` |
| 需要 Code 但尚未实现 | `Code 缺口；当前临时核对动作；后续由 Code 规范和对应行动编排共同承接` |
| 需要 Agent 审查但无固定 Agent | `主控 AI 可调用子 Agent 或人工独立复核；输出必须交还主控，不得直接生效` |

禁止写法：

| 写法 | 问题 |
|---|---|
| `由流程处理` | 无法定位 active 行动编排或接管范围 |
| `已有保障机制` | 未说明保障机制、证据、问题原因和触发条件 |
| `Code 检查通过即完成` | Code 只提供确定性诊断，不替代 AI 判断、Human Gate 或事实源回写 |
| `Skill 接管流程` | Skill 是复用外壳，不是行动编排事实源，不能替代主流程接管 |
| `Web 显示 ready` | Web 展示不是最终事实源，不等于保障准备度完成 |

## 4. 保障声明辅助核对表

保障声明辅助核对至少包括：

| 检查项 | 标准 |
|---|---|
| 类型闭集 | 保障要求类型属于本文 §2 |
| 字段完整 | 保障要求表使用 01 定义的五字段契约 |
| 机制状态清晰 | 保障机制区分现有保障、建议接管、待接管缺口和临时核对动作 |
| 接管不冒充 | 没有把建议行动编排写成 active 接管事实 |
| 接管后不回流 | 已有 active 专属行动编排时，来源 specs 未继续维护该行动的执行步骤、能力资产映射、环境落地细节或验证证据 |
| 附件不越界 | 本文未定义父规范未授权的新规则、流程 Gate、事实源边界或执行步骤 |
| 能力不替代流程 | Skill、Agent、Code、Web、Hook、CI 或环境入口没有替代行动编排接管责任 |

本核对表用于发现保障声明漂移、接管关系误写、附件越界和能力资产替代流程的风险；核对结论不能替代 01 主文档规定的高影响确认。
