## 1. 价值判断

Spark 为跨行动或会话仍有保留价值、但尚未形成确定承接位置的信息提供一个可召回、可继续判断、可明确处置的临时事实入口。没有 Spark 时，这类输入容易只留在聊天记忆中，导致遗忘、重复讨论和上下文断裂；过度使用 Spark 时，它又会成为任务池、报告容器或“不知道放哪里”的垃圾箱。

本文主要服务：

1. V1 快速定位：能够找回仍需处置的议题及其当前状态；
2. V2 充分理解：从当前摘要、关键演变、来源和关系恢复问题焦点与剩余不确定性；
3. V3 边界识别：区分未形成承接位置的信息、已经明确的行动、长期决定、复用经验、研究产物和普通文档；
4. V5 据实判断：把完整当前叙述、来源、已验证证据、关联对象和完整承接判断分开；
5. V6 工作接续：使议题能够跨会话继续判断，而不依赖逐条对话和过程日志；
6. V8 持续积累：让反复出现的缺口和发现进入正确承接位置，并让已经处置的入口退出待处理集合。

Spark 新增一项事实类型发现入口、一份 Schema 和相应迁移与实现成本，也会增加创建前查重和终态判断负担。相对地，它消除的是跨会话未收敛信息反复丢失、重复讨论、被过早升级为行动或决定以及无法明确退出入口的持续成本；这些问题不能由普通文件或其它四类对象在不混淆责任的情况下自然承担。通过单一对象粒度、九个公共字段复用、一个小型结构、条件字段省略和三状态闭集，新增维护面被限制在实现其独有价值所需的最小范围。因此 V1、V2、V3、V5、V6、V8 的持续净收益高于发现、Schema、迁移和实现成本；V4 稳定推进由后续行动承接，V7 清晰沟通由来源、处置边界和需要时的 Human Gate 交还辅助实现，二者都不作为扩大 Spark 职责的理由。

Human 已确认保留 Spark 类型，因此本文不重复决定是否建立该类型；本文仍必须证明具体语义、对象边界和 Schema 的独立必要性。Spark 保留跨会话捕获价值，但收紧对象粒度、统一来源与关系，并把终态解释为入口职责结束而不是下游工作完成。

## 3. 职责边界

本文负责定义：

1. `spark` 的类型语义、对象粒度、准入和非准入边界；
2. Spark 的唯一当前承载位置、稳定身份、完整 Schema 和未知内容处理；
3. Spark 的状态集合、状态转换、终态处置、来源、证据和关系语义；
4. Spark 创建、更新、更正、拆分、合并、处置、删除和停止使用时的领域边界；
5. Spark 的验证要求、Human Gate、Stop Conditions 和最小失败范围。

本文不负责定义：

1. WorkCase、ADR、Pitfall、Study 或普通文档的类型语义、准入、Schema 和生命周期；
2. Helper 请求或响应、Code API、文件分配算法、CLI 命令、Web 表单或页面写入白名单；
3. 非当前 Spark 载体的自动迁移、兼容读取或继续生效；
4. 当前行动是否获准、下游工作是否完成、长期决定是否成立或研究结论是否正确；
5. 逐条聊天、执行日志、临时分析、派生索引或 Git 历史的替代副本。

AI 负责判断信息是否需要 Spark、是否与已有事实语义重复、当前摘要和处置结论是否准确；Code 只可依据当前来源检查固定结构、值闭集、引用和状态条件。08 §8.2 的 已取消的 Web 创建 是唯一窄例外：Human 明确选择 Spark 并提交其完整当前内容，Code 可以先创建通过精确身份查重的 `open` Spark，把自然语言语义比较留给后续明确的 AI reconciliation opportunity。该例外不使 Code 取得语义判断权，也不授予任何消费方通用写入或删除权限。

## 4. 适用范围

本文适用于管辖项目中准备创建、读取、更新、关联、拆分、合并、处置或消费 Spark 的场景，以及 Spark 与其它稳定事实位置之间的承接判断。

一个信息单元只有同时满足以下条件，才可以形成 Spark：

1. 跨当前行动或会话仍有具体保留价值；
2. 当前尚不能自然写入已有事实对象、规范、文档或其它稳定来源；
3. 尚未形成清楚的执行目标与验收边界、长期决定、已验证复用经验或完整研究产物；
4. 能表达为一个可独立判断“是否仍需处置”的信息需求、发现、问题或缺口；
5. 已召回并比较现有 Spark 和相邻稳定事实，没有可无损更新的现有入口；
6. 至少一个来源可以按所需精度回指，且没有把推测改写成已验证事实。

普通 AI 创建在写入前满足上述全部条件。08 §8.2 的 Web direct capture 只把第 5 项的自然语言比较后移：当次仍须满足 Spark 类型选择、单一粒度、来源、合法 `open` 初态和全状态精确身份扫描；语义相似但精确 identity 不同不由 Code 拒绝，后续按 §7 的 F2/F3 opportunity 比较。该例外不能用于其它输入来源、事实类型或写操作。

当前行动中可以直接处理且不需跨会话保留、已经由现有位置完整承载、已经具有明确行动目标、已经形成长期决定或复用经验、完整研究报告、过程日志、逐条聊天、工具输出和单纯执行提醒，不应单独形成 Spark。多条潜在分流方向仍只是同一共同线索、且尚未各自形成独立目标、判断或跟踪价值时，可以保留在同一 Spark 中；潜在多路分流本身不要求立即拆分。多个已经可以独立处置的问题不得长期捆成一个 Spark；相关子问题一旦具有独立目标、判断或跟踪价值，必须拆分。共同线索仍影响某个子 Spark 时，该子对象必须以实际适用的 对象自有语义字段 定位原共同来源，并同时在 `intent` 或 `summary` 中直接保留当前共同理解；不得把泛化 `related-to` 关系伪装成拆分谱系，或要求 Web 从关系、标题或 Git 历史推断共同线索。

### Schema 与对象载体

Spark 对象使用 UTF-8 YAML，一文件一对象，当前权威位置固定为管辖项目仓库中的 `ldvh-base/sparks/<object_id>.yaml`。`object_id` 必须匹配 `spark-[0-9]{4,}`；文件名必须与 `object_id` 完全一致，分配后的身份不得因短标题、路径、状态或内容改变。`title` 只用一句短语或问题标识核心议题，不承担创建原因、当前判断或处置结论；`intent` 回答为什么创建并保留该入口；`summary` 表达当前已经形成的语义快照。三者不得互相复制后冒充分工成立。未知或不适用的条件字段必须省略，不使用显式 `null`、空字符串、空数组、占位时间或默认关系。

完整 Schema 由统一登记的 `fact-object` 直接字段、本节绑定、类型专属字段定义及 `value_structure` 递归组合。Spark 不得出现未登记字段，也不得向共享 历史引用结构 添加类型私有扩展；来源触发内容必须由精确 locator 指向原始来源，创建原因由 `intent` 据实提炼，当前内容由 `summary` 表达，三者不得互相冒充。本文没有授权附件，Schema、Code 常量和 test fixture 都只能从当前来源派生。

## 6. 对象语义与生命周期

一个 Spark 只表达一个能够独立判断是否仍需处置的核心信息需求、发现、问题或缺口。`intent` 稳定记录为什么创建并保留这个 Spark，以及希望后续澄清、判断或分流的核心问题；它不随普通进展改写成当前结论。形成 `intent` 时，AI 必须先从原始输入剥离“把它加入 Spark”“新建/记录这个对象”“请 AI 执行”等对象操作，以及说话人、时间、渠道和 locator，再保留其中的实质议题、保留价值与待判断问题；所得文本必须脱离原对话独立成立，可以是陈述或问题，但必须同时能回答“为什么这个议题需要被保留”和“后续要判断什么”，并据实说明若不跨行动保留会增加何种后续定位、重新分析、分流、复核或上下文恢复负担。仅剩操作指令、来源摘抄、标题扩写、当前结论、待办或行动计划的文本不是有效 `intent`。原话仍由 对象自有语义字段 定位，不能借由复制到 `intent` 冒充提炼完成。`summary` 从当前实际存在且仍影响判断的来源、对话、已有事实与判断、边界和未决问题中进行结构化提炼，是完整的当前语义快照；它不是完整对话副本，也不是为列表或 Helper 卡片准备的一句话简介。这里的“完整”表示语义充分，不表示穷举全部历史内容；Spark 不因此增加 `body` 或其它正文副本字段。`summary` 必须使未读取原聊天和过程日志的后续执行者能够理解当前究竟已经知道什么、如何判断以及仍需处置什么，并根据对象实际内容表达已有事实与当前判断、相关边界或排除项、风险、候选方向与仍未确定或尚待分流的内容；某类信息并不存在时不得补造，只有其缺失本身影响当前判断时才如实说明缺口。`summary` 可为了解释当前判断简要回指 `intent`，但不得复制一段“创建原因”冒充当前摘要。当 `open` Spark 已有部分或多路承接时，`summary` 还必须直接说明每个承接目标覆盖的范围、仍未承接的内容以及为什么保持 open；不得只列出关系，要求读者从目标标题、类型或 Git 历史自行推断。

当 `summary` 同时包含多个观点、判断、边界、风险、候选方向或未决事项时，必须使用适合实际内容的 Markdown 段落、以明确强调语法表达的简短分组标签、小标题、编号或列表，使各项信息角色及其关系可以直接识别；不得把这些内容埋入连续大段文字，要求读者自行推断结构。列表形式由内容关系决定：只有顺序、优先级、依赖、步骤或需要稳定逐项引用的次序本身影响含义时才使用编号；各项互为并列条件、边界、观察、风险或特征，调换位置不改变含义时使用无序列表。不得仅因项目有多项就使用编号。可见结构不等于固定模板：不规定统一标题、顺序、段落数量、标记种类或关键词，也不要求每个 Spark 使用标题；AI 必须根据对象内容选择足够且不过度的结构。字符数、Schema 非空、机械分段或套用统一文章骨架都不能替代语义充分性与结构可读性审核。

`summary` 与 `evolution` 的归位顺序固定如下：先问某段内容是否仍是后续执行者在当前 Spark 中必须直接使用的实践框架、判断、检查项、边界、风险或未决事项；是则必须写入 `summary`，即使它由刚发生的发现、测试或讨论得出。再问后续执行者是否还需要知道该当前理解相对创建时或上一快照发生了什么转折及其影响；是则以一条简短 `evolution` 说明变化关系。前一问的内容不得只存在于 `evolution`，后一问不能借复制完整当前摘要、检查清单或讨论总结回答。比如一次环境实测形成、且当前仍要使用的多层诊断框架属于 `summary`；对应 evolution 只说明“该实测使当前摘要新增此框架，以及它改变了哪些原有判断”。反过来，已经不再影响当前判断的过程细节既不进入 `summary`，也不因发生过而进入 `evolution`。这是一项 AI 语义归位判断，不以长度、标题数、列表数或 Markdown 形状代替。

`evolution` 为直接理解当前 Spark 保留少量关键语义转折，也可在首条保留仍影响理解的创建缘由；Git 只负责历史溯源，不能替代当前对象中仍影响理解的演变记录。每次普通 AI 创建或经授权更新前，AI 必须先按前段完成内容归位，再对照原始创建上下文或当前对象的变更前快照与目标快照，明确判断问题焦点、边界、判断方向或承接方向是否发生实质变化；若发生且后续恢复需要理解变化前后关系，必须在同一目标快照中追加一项直接说明“发生了什么变化及其影响”的 `evolution`，不得以已重写 `summary`、存在 Git commit、更新时间变化或 来源原文 代替。原始 Human 输入或形成语境仍是理解对象起点的关键内容时，普通 AI 创建或后续 AI reconciliation 的首条 `evolution` 必须直接说明该起点及其影响；这不是把来源逐字抄入页面，也不把初始上下文伪造成后续变化。没有这种变化且创建缘由不再影响理解时应省略 `evolution`，不得把每次创建、对话、操作、提交或普通摘要润色伪造成演变。已取消的 Web 创建 初次机械创建只精确保存 Human 字段，不进行本项 AI 语义对照，不自动补写 `evolution`，其缺口仍按 §7 reconciliation 处理。每次更新都必须复核全部已有 evolution 条目：只有某项已不再帮助理解当前问题焦点、边界、判断方向或承接方向时，才可以由 AI 合并、压缩或删除；不得仅因 Git 中存在提交、摘要提及相同事实、数量或时间阈值而机械删除。当前对象最多保留 8 项关键转折；超过时必须先进行语义压缩、重写完整当前摘要或拆分对象，不得继续追加。Spark 不承载下游对象的正文、计划、状态或验收。

**归位示例。**

- 正例：ZCode 实测后，五层安装诊断框架及其“目前只在 ZCode 得到直接证据”的边界写入 `summary`；`evolution` 只写“实测显示静态资产、可执行性与真实触发不可互相替代，因此摘要新增五层诊断框架”。
- 反例：将五层的逐层定义、检查步骤、已知故障机制和跨环境待验证事项完整塞入一条 `evolution`，而 `summary` 无法独立说明当前框架。
- 分流例：一次故障的症状、复现、根因和修复由 Pitfall 承接；Spark `summary` 只保留该经验对当前未决问题仍有何影响，`evolution` 只记录该影响何时改变。

状态闭集为：

| status | 语义 | 必须成立 |
|---|---|---|
| `open` | Spark 仍有未被稳定位置完整承接的内容，需要继续召回、判断、拆分或分流；面向 Human 的状态词为“待处理”，不把它泛化表述为“未关闭” | `priority` 必填；`disposition_summary` 与 `closed_at` 不得出现；已有关系不等于完整承接 |
| `routed` | 原始信息需求已经由一个或多个稳定当前位置完整承接，Spark 不再承担待处置入口 | `priority` 禁止；`disposition_summary`、`closed_at`、自然语言验证说明 必填；非 Spark、非 Study 的事实对象承接使用 `routed-to`，Spark 接替遵守 §7 的 `supersedes` 单边规则，普通文件承接由证据引用定位 |
| `discarded` | 明确决定该信息不再继续跟踪；这是不产生承接目标的废弃终态，不是分流 | `priority` 禁止；`disposition_summary`、`closed_at` 必填，自然语言验证说明 仅在实际存在且支持当前声明的稳定材料时出现；不得仅因暂时无行动或优先级低而废弃 |

正常状态转换只有 `open → routed` 和 `open → discarded`。终态不直接重开；后来出现新的未处置信息时创建新 Spark，并用 `supersedes` 指向旧 Spark。若原终态记录本身错误，应按 05 的事实更正规则修正，而不是把更正伪装成领域状态转换。

`routed` 只表示 Spark 入口职责结束，不表示目标工作完成、决策正确、经验有效或报告结论成立。Study 只承载研究报告，可以作为 Spark 的来源、证据或 `related-to` 关联，并可以改变当前摘要中的理解；Study 的存在、关联或报告完成均不表示原问题已经承接，也不得成为 `routed-to` 或单独支持 Spark 进入 `routed`。若报告之后仍有行动、决定、规则或其它未承接缺口，Spark 必须保持 open。普通文档或一个或多个非 Study 的稳定承接位置只有在确实完整覆盖原信息需求时才可以支持 routed；多个承接位置共同完整覆盖时不强迫选取虚假主目标，分别保留关系或证据，并在 `disposition_summary` 说明覆盖判断。

`discarded` 同样只结束 Spark 入口，但它是无承接目标的否定处置：其 `disposition_summary` 只说明决定不再跟踪的理由，不得声明任何承接位置、后续处理、部分或完整分流，也不得以 `routed-to` 关系伪造处置完成。废弃本身不要求外部证据；没有稳定、可重新定位且实际支持当前说明的材料时，必须省略 自然语言验证说明，不得用临时会话 locator、测试命令或其它不可复核占位满足字段。若后来出现需要继续处置的新信息，必须新建 `open` Spark，并按 §7 以 `supersedes` 指向该旧终态；这不把旧对象改写为分流。

## 7. 来源、证据、关系与处置

每个 Spark 至少具有一项 对象自有语义字段。来源记录形成或保留该议题的原始输入和直接材料，可以是 Human 输入、对话、规范、事实对象、项目文档、外部资料，或确实构成议题形成上下文的代码与测试观察；`kind` 必须描述实际来源，`locator` 必须达到重新定位当前摘要所需的精度。没有稳定对话标识时不得伪造 locator，也不得用泛化的 `conversation` 字符串冒充可重新定位来源。对象自有语义字段 只承担来源定位、版本与观察边界，不是 Spark 的页面阅读区、`intent` 或当前正文；Helper、Code、Web 和其它消费者不得因 locator 中含有 Human 原话、问题或形成背景，就把它重命名、推导或投影为 `intent`、`summary` 或其它对象语义。原始 Human 输入或形成语境仍是理解对象起点的关键内容时，普通 AI 创建或后续 AI reconciliation 必须在 `evolution` 的首条条目中用自己的话说明该起点及其影响；不得用 来源原文 原话代替，也不得把 来源原文 另起“来源”区。已取消的 Web 创建 初次机械创建只保留原始来源，等待后续 AI reconciliation 判断是否需要该条目。

自然语言验证说明 只在支持当前摘要中已核对的观察，或支持处置判断时出现。为调查而顺带读取、却不支撑任何当前声明的代码、测试、文件或工具输出不得写入任一引用字段。`routed` 的证据必须支持全部原始问题已经被稳定位置承接；`discarded` 不因终态本身要求证据，只有存在稳定材料且它实际支持处置说明时才记录。Human 指令可以成为处置依据，但只有具有可重新定位的实际来源时才可作为长期引用；不能重新定位的当次对话应由 `evolution` 据实说明，不得制造 `conversation://current-task/...` 等伪 locator。关系存在、文件存在或测试命令成功本身不自动充分。来源与证据都不因此成为事实对象关系；它们保留为引用字段，不得伪装成 `relations`。Spark 页面中的项目内文档仅限实际面向阅读的项目文档；代码、测试、构建产物、配置、运行观察和其它非文档文件即使作为来源或证据，也不得仅因路径位于仓库或使用 `repository-path` 而进入“关联”、另建阅读区或扩展阅读投影。

Spark 的 `relation_key` 闭集为：

| relation_key | 目标、基数与方向 | 跨项目、缺失、自指与循环 | 对状态的影响 |
|---|---|---|---|
| `routed-to` | 当前 Spark 指向实际承接其部分或全部信息需求的 current 非 Spark、非 Study 事实对象；可以有一项或多项 | 可以跨项目，但跨项目目标必须带完整 governance refs；目标缺失或不再 current 时关系及 routed 判断失效；禁止自指；全部 routed-to 边必须无环 | 单独存在不改变状态；只有目标内容实际承接相应范围、全部原始内容被关系与其它稳定位置共同覆盖且证据充分时才能 routed |
| `related-to` | 当前 Spark 指向任意 current 事实对象，表示主题相关但不声明承接；可以有零项或多项 | 可以跨项目并按公共结构保留 governance refs；目标缺失时该关系失效但不自动改变 Spark 状态；禁止自指；允许互相或成环，因为每条边只表达局部相关性，不派生承接或反向权威 | 不构成处置证据，也不因关系数量改变状态 |
| `supersedes` | 一个 `open` 新 Spark 指向被其完整接替的 `routed` 或 `discarded` 旧 Spark；可以指向一项或多项旧对象，反向只作为派生索引 | 只允许同一管辖项目；目标缺失时关系失效；禁止自指；全部 supersedes 边必须无环，不得让两个入口互相替代 | 只说明新入口与旧身份的接替关系；不重开或改写旧对象，也不单独证明旧对象原处置正确 |

`routed-to` 的目标类型必须是已经具有当前唯一定义来源、能够自然承载相应信息的非 Spark、非 Study 事实类型；不能指向 Spark、Study、缓存、派生索引或只因字段相似而选择的对象。Study 的报告正文不替代行动、决定、经验或其它正式承接位置。Spark 拆分或替代只由新 `open` Spark 通过 `supersedes` 单向指向旧终态 Spark；旧对象以 `disposition_summary` 和 自然语言验证说明 定位新入口，不再写一条反向 `routed-to` 权威关系。判环时，`routed-to` 按当前 Spark 到承接对象的方向检查，`supersedes` 按新 Spark 到旧 Spark 的替代方向单独检查；不得用任何关系环证明完整承接。反向导航由 Code 派生，不得为了反向展示写入第二条含义不同的权威关系。

`routed-to` 的唯一权威身份始终是目标的 `governed_project_id`、`fact_type_key` 与 `object_id` 三元组。关系中不得复制、人工维护或以 `object_id` 冒充目标名称；面向 Human 的完整名称只能从该目标当前对象的非空 `title` 派生读取。对同一管辖项目的目标，Helper 的项目级关系检查必须实际读取目标并确认该 `title` 可呈现：目标不存在、机械无效或缺少非空 `title` 时，source Spark 的关系无效；目标当前不可读取时，结果保持 `unavailable`。Web 不得把读取到的名称变成关系权威，也不得以编号作为名称回退。

普通 Markdown、配置或其它非事实对象不能伪装成 `relation-target`；它们按实际作用进入 对象自有语义字段 或 自然语言验证说明。按目标类型拆分的 `related_*`、`input_refs` 和单值 `resolved_to` 不进入 Schema。

创建前必须按主题、来源、相邻对象和已知引用召回现有 Spark 与稳定事实。完全重复或同一对象的自然更新应更新现有入口；语义范围不同且需要独立处置时才新建并建立必要关系。Code 可以做精确 key、locator 和文本检索，不能裁决自然语言是否同义。只有下节 已取消的 Web 创建 可以在完成确定性全状态精确扫描后，把自然语言语义比较推迟到明确的 AI reconciliation opportunity；这不是对普通创建查重责任的放宽。

### Web 创建边界

Web 不创建 Spark。Spark 只可依 31 的受控创建行动形成，并由类型自有字段表达创建理由与当前内容。

### 主动召回与消费时机

Spark 在当前行动进入新主题、准备结束或交还、准备创建新事实对象，或当前输入命中已知来源、关系或未处置议题时产生召回机会。F2 Spark 候选卡只直接投影 `object_id`、`title`、`status`、`priority` 和 `updated_at`，并按 05 的统一候选契约携带从命中的 `intent` 或完整 `summary` 形成的有界确定性摘录、原字段路径及其完整/截断标记；摘录不是事实字段、AI 摘要或第二权威。旧对象缺失 `intent` 时只能从实际存在的 `summary` 召回，不得为了候选卡补造创建原因。默认候选只包含与当前主题可能相关的 `open` Spark，`priority` 只影响这些候选的比较顺序，不能单独证明相关或要求当次处置。上下文压缩后只恢复当次已判断相关且仍未承接的 `open` Spark 卡片，不全量注入全部 `open` Spark；任何需要判断对象语义、边界或剩余问题的消费都必须按稳定引用展开 F3 完整对象。

`routed` 和 `discarded` Spark 不进入普通未处置候选；只在当前输入精确引用、需要追溯来源或处置依据、检查 `routed-to`/`supersedes` 关系，或判断新信息是否构成新入口时才作为历史对象展开。AI 展开候选后必须重新比较当前主题、来源、摘要、处置状态和稳定承接位置；Spark 被召回不表示应创建 WorkCase、恢复旧议题或提高其优先级。

## 8. 创建、更新与停止使用边界

普通 AI 创建 Spark 前必须确认准入条件、召回结果、对象粒度、来源、独立 `intent` 和完整当前摘要。`intent` 必须准确说明为什么创建并保留该 Spark，并明确后续待判断的问题；不得用标题扩写、来源摘抄、当前结论、待办、行动计划，或“新建/加入/记录 Spark”等操作指令代替。AI 必须逐项确认原始输入中的实质议题与待判断问题已经保留，而对象操作、说话人、时间和 locator 已留在来源身份中而未被抄入 `intent`。AI 同时审核 `summary` 的语义充分性与结构可读性：内容应足以让后续执行者脱离原聊天恢复当前问题，并表达对象中实际存在的已知判断、适用边界和剩余不确定性；当存在多种信息角色时，其层次和关系还必须通过适合内容的 Markdown 结构直接可见。不能只写方向口号、标题改写、待办一句话或无法独立理解的来源概括，不能把扩写后的内容堆成连续散文，也不能用固定段落、统一标题和字符下限冒充充分。已取消的 Web 创建 仅按 08 §8.2 和 §7 的全状态精确扫描后创建，Human 提交的 `intent` 必须原样映射为创建原因，`description` 必须作为完整 `summary` 保存；该入口不能冒充已经完成自然语言召回、语义查重或 AI 内容充分性审核，这些缺口必须在后续 F2/F3 reconciliation opportunity 中保留。

创建后的任何更新都必须确认 Human 当前指令已经授权，且适用于该行动的全部来源规则许可条件已经成立，随后写入当前权威文件，回读 Working Tree，并验证 Schema 与状态条件；本文不因定义更新规则而授权 AI、Helper、Code 或 Web 修改文件。本节新增的摘要要求只在普通 AI 创建或当次已获授权实质改写 `summary` 时进入相应审核，不授权批量迁移或自动改写既有对象；既有对象未在当次实质改写摘要时，不因旧摘要尚未满足本节结构要求而自动触发迁移，也不因此阻断来源允许的其它生命周期判断。

统一登记中 `spark-intent` 的 `conditional` 只是为了在迁移暂停期间不把全部旧 Spark 机械判为 Schema 无效，不表示当前新建可选。普通 AI 新建与 v2 四字段 Web capture 都必须具有 `intent`；旧对象可暂时缺失，但不得被声称已完成创建原因审核，也不得从标题、`summary` 或来源机械推导。本节不授权批量补全旧对象。

只有原始创建原因记录不准确，或对象边界已经被合法纠正时，才修正 `intent`；普通进展只更新当前 `summary`。修正 `summary` 前必须完成本节对变更前/后语义的对照；只有会影响后续恢复的关键语义转折才在同一变更中追加 `evolution`，不得遗漏后再以 Git 历史补充，也不得为普通润色伪造条目。优先级变化只改变召回排序，不推进状态。新增关系必须说明方向语义，不复制目标正文。拆分必须让每个新 Spark 具有独立问题边界、来源和身份，并由原对象或新对象保留关系；合并、替代或删除不得丢失仍适用来源、证据和承接关系。

Spark 可以保留终态文件作为历史参考。归档只在未来当前来源另行定义明确位置与消费边界后成立；本文不建立独立 archived 状态。删除仅在来源规则允许、稳定身份与引用已经处置且不会丢失仍适用事实时成立，不能用删除代替 discarded。

Spark 类型停止新增、合并、替代或取消时，必须按 05 处理唯一定义来源、全部当前对象、引用消费者和仍适用事实。任何非当前对象若需重新承接，都必须逐项判断来源、当前价值、状态与字段映射；缺少时区、稳定 locator 或 `routed` 所需承接证据时必须报告不完整，不能生成默认值。

## 10. Human Gate

以下情况必须进入 Human Gate：

1. 废弃、合并、拆分、替代或删除可能实质丢失仍有价值的入口、来源、证据或关系；
2. 依据不足但准备宣布一个或多个位置已经完整承接全部原始问题；
3. 多个承接位置或权威来源冲突，适用来源规则与证据无法确定保留或放弃哪一处；
4. Spark 的处置实质改变产品方向、长期规则、重大风险接受或其它需要 Human 决定的领域事项；
5. 当次创建、更新或处置超出已有 Human 授权。

Human 决定的复用按 00 §10 执行；Human 当前指令已经授权创建、补充来源、修正摘要或建立普通可逆关系，且适用于该行动的全部来源规则许可条件已经成立时，不因对象类型是 Spark 而重复进入 Human Gate。Human 决定不能替代 Schema、来源回读、证据充分性和写后验证，也不能使未完整承接的 Spark 自动 routed。

08 §8.2 下每次点击只授权创建该次闭集请求的一个 `open` Spark；产品方向决定不替代逐次点击，也不授权真实项目测试写入、更新、处置、迁移、commit、远程部署或其它事实类型。后续 F2/F3 语义比较不自动产生 lifecycle 变更授权。

## 11. Stop Conditions

出现以下任一情况时，必须暂停受影响 Spark 的新建、更新或处置：

1. 普通创建未召回已有对象，存在重复或同义 Spark 风险；或 Web direct capture 未完成 §7 全状态精确扫描、coverage 与来源 identity 复核；
2. 信息已经由现有事实源自然、完整承载，或已经满足其它正确承载位置的边界；
3. 没有可回指来源，或 locator 无法达到当前声明所需精度；
4. 正在把推测写成已验证事实，把关系存在写成完整承接，或把终态写成下游完成；
5. 一个对象混入多个独立议题，无法判断何时结束入口职责；
6. 仍有未承接内容，却准备标记 routed；
7. 处置目标缺失、失效或无法稳定定位，或者普通文件被伪装成事实对象关系；
8. 正在用 Spark 长期替代明确行动、长期决定、复用经验、完整报告或普通文档；
9. 使用未登记字段、空值占位、按目标类型拆分关系字段或实现私有扩展；
10. 写入、删除或高影响处置没有实际授权、没有写后回读或没有范围匹配验证；
11. 只因生成报告、建立关联、运行命令或收到 Human 回应就声称 Spark 已完成处置。
12. 把 Study 的存在、关联、报告完成或研究结论写成 Spark 已完整承接，或把 Study 写入 `routed-to`。
13. 普通 AI 创建或当次经授权实质改写后的 `summary` 只是标题改写、方向口号、待办一句话或来源概括，无法让后续执行者脱离原聊天恢复当前问题及实际存在的判断、边界和剩余不确定性；
14. 普通 AI 创建或当次经授权实质改写后的 `summary` 包含多个观点、判断、边界、风险、候选方向或未决事项，却仍以连续大段散文呈现，信息角色和关系必须由读者自行推断；
15. 普通 AI 创建或当次经授权实质改写 `summary` 时，为满足结构要求而机械套用统一标题、顺序、段落数量、关键词或大字号文章骨架，导致实际内容关系被扭曲或阅读负担增加。
16. 准备新建 Spark，却缺失非空 `intent`；或在普通 AI 创建/纠正中，`intent` 未经语义审核且不能说明为什么创建该对象；Web 初次机械 capture 只停止于字段缺失或映射失真，不冒充 AI 语义审核；
17. 准备从标题、`summary`、来源原文 或历史 v1 Web capture 自动推导 `intent`，或把当前结论改写成伪造的原始创建原因。
18. 普通 AI 新建或经授权纠正的 `intent` 含有“新建/加入/记录 Spark”等对象操作、说话人、时间或 locator，或者未能同时说明保留该议题的实质理由与后续待判断问题。
19. 普通 AI 新建或经授权纠正的 `intent` 未能据实说明不跨行动保留会增加何种定位、重新分析、分流、复核或上下文恢复负担；Web 初次机械 capture 保留该语义审核缺口，不冒充已经满足。
20. 当次经授权实质改写后的 open `summary` 已有部分或多路承接，却只列关系而未直接说明各目标承接范围、残留内容和仍保持 open 的原因。
21. 普通 AI 创建或经授权更新已经使问题焦点、边界、判断方向或承接方向发生影响后续恢复的实质变化，却未先进行变更前/后语义对照、未在同一目标快照保留对应 `evolution`，或准备以 Git、更新时间、来源原文 或重写后的 `summary` 代替演变记录；已取消的 Web 创建 初次机械创建不得冒充已经完成该 AI 审核。
22. 在普通 AI 创建或后续 AI reconciliation 中，原始 Human 输入或形成语境仍是理解 Spark 创建缘由的关键内容，却只保留在 来源原文、关联、Git 或对话中，未由首条 `evolution` 直接说明其起点与影响。
23. 准备把 `discarded` 的处置理由、关系或后续新 Spark 写成分流、承接目标或 `routed-to`，或者把 `routed` 与 `discarded` 混成同一种终态。
24. 当前仍会影响后续判断或行动的实践框架、检查清单、判断、边界、风险或未决事项只写入 `evolution`，使未读演变的执行者无法从 `summary` 恢复当前理解；或将这些当前内容的完整副本塞入演变，以“发生了变化”替代变化及其影响的简短说明。

暂停范围与允许继续的行动按 00 §11 执行；对 Spark，只有与实际触发原因对应的条件成立后才能恢复相应对象、候选或处置声明，包括重复风险消除、来源与对象边界成立、Schema 修正、创建原因据实形成并与标题/摘要分工清楚、当前内容与历史转折已经按字段职责归位、摘要按来源完成语义与结构审核、Study 不再被作为承接目标且已补齐非 Study 的完整承接或保持 open、全部内容获得稳定承接或废弃依据充分、实际变更完成回读。未在当次改写的既有摘要不因第 13–15、第 20 或第 24 项触发迁移或全对象停止；旧对象缺失 `intent` 不因第 16 或第 19 项自动触发批量补全。
