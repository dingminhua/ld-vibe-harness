# LDVH 特别落地要求规范

> 创建日期：2026-06-11
> 定位：定义 LDVH 自身跨环境运行投影必须遵守的特别落地要求
> 适用范围：薄入口、AI 统一入口、LDVH 自建 Skill、Skill 元数据、Skill 正文边界、入口分层、运行投影纪律和环境投射时的 LDVH 特别要求响应
> 草案性质：调研区重写草案，不是正式规范；正式吸收前不得替代 `docs/specs/04.04-LDVH落地特别要求规范.md`
> 上位依据：`04-规范落地与环境投射基础规范.md`、`04.02-LDVH能力保障规范.md`、`04.03-环境能力清单与投射规范.md`
> 参考来源：`docs/specs/04.04-LDVH落地特别要求规范.md`、`docs/research/26-LDVH环境投射技术经验吸收研究.md`

---
## 1. 本文解决的问题

本文解决 LDVH 自己设定的跨环境运行纪律如何登记、投射和检查的问题。

LDVH 特别落地要求不是平台客观能力，也不是个人环境偏好。它是 LDVH 为避免运行投影膨胀、入口分裂、Skill 命名混乱、平台配置替代事实源而设定的统一纪律。

具体平台如何实现这些要求，由 04.03 按环境能力清单投射；平台不足时只能降级记录，不得放宽本文要求。

## 3. 薄入口细则

薄入口可以包含：

1. 入口身份、适用范围和权威来源；
2. 触发条件和不适用场景；
3. 必读正式规范、环境投射卡片、42 流程、Code 入口或工作对象路径；
4. 关键检查项、STOP 点、Human Gate 提醒和降级方式；
5. 输入、输出、交还主控和回写出口；
6. 运行投影与正式规范之间的路径或版本关联。

薄入口不得包含：

1. 完整规范正文、字段契约、状态机、工作流程全文或平台教程；
2. 未被正式规范吸收的 research、refs 或输入材料结论；
3. 与正式规范并行维护的规则正文；
4. 未经 Human Gate 授权的写入、覆盖、删除或状态流转规则；
5. 稳定事实、决策或验收结论的唯一记录。

---
## 4. AI 统一入口与平台薄引用

LDVH 默认只维护一个 `LDVH-AI-ENTRY.md` 作为 AI 统一入口。环境入口应只做薄引用，指向该文件并说明按工作区入口视角识别管辖项目、事实源和执行边界。

平台薄引用应遵守：

1. 使用当前用户真实绝对路径指向 `LDVH-AI-ENTRY.md`；
2. 不复制 `LDVH-AI-ENTRY.md` 正文；
3. 不复制正式规范清单全文；
4. 不在管辖项目内默认创建项目级环境入口；
5. 确需创建项目级入口时，必须 Human Gate 并记录退出方式；
6. 平台位置、格式和持久性由 04.03 的环境投射卡片处理。

Trae 与 Codex 的具体入口位置不得在本文写成完整支持结论。它们应在 04.03 中作为环境投射方式和待实测事项表达。

## 5. LDVH 自建 Skill 细则

LDVH 自建 Skill 的稳定标识应遵守：

1. 使用 `ldvh-` 前缀；
2. 前缀后使用表达能力或治理动作的短名；
3. 只使用小写字母、数字和连字符；
4. 不绑定具体业务项目名、个人名、平台名或临时阶段名；
5. 不使用版本号、状态词或营销式名称作为稳定标识。

Skill 的描述或等价元数据应说明：

1. 该 Skill 能保障什么能力；
2. 何时使用；
3. 何时不使用；
4. 关键触发词或生命周期阶段；
5. 需要读取的权威入口。

Skill 正文应使用中文，除非平台字段或技术标识要求使用英文。平台元数据必须英文时，Skill 正文仍应保留中文可读的定位、触发条件和边界说明。

## 6. 启用与环境投射

LDR-01 至 LDR-07 默认适用于 LDVH 自建运行投影。AI 创建、修改、审计或迁移运行投影时，应先检查本文，再由 04.03 判断具体环境投射方式。

如果平台无法完整投射本文要求，应按以下顺序处理：

1. 确认是否可以通过环境入口、Skill、Command、Code、Web、42 或人工检查满足；
2. 仍不能满足时，记录投射降级和残留风险；
3. 若会削弱事实源边界、Human Gate 或验证纪律，应触发 Human Gate；
4. 不得通过复制规范正文、放宽 Skill 命名或让入口自成事实源来规避缺口。

---
## 7. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 新增、删除或改变本文登记的 LDVH 特别落地要求；
2. 放宽薄入口要求，允许运行投影复制完整规范正文；
3. 改变 `ldvh-` 前缀的适用范围；
4. 允许管辖项目业务 Skill 使用 `ldvh-` 前缀；
5. 创建、修改、删除、重命名、搬移或启用 LDVH 自建 Skill；
6. 允许 Skill 新增稳定规则、字段、状态或 Human Gate 条件；
7. 删除、重命名或移动 `LDVH-AI-ENTRY.md`，或改变 AI 统一入口默认职责。

LDVH 特别落地要求检查至少包括：

| 检查项 | 标准 |
|---|---|
| 薄入口 | 运行投影只保留入口摘要、触发、检查、STOP、引用、交还和降级信息 |
| 统一入口 | 环境入口只薄引用 `LDVH-AI-ENTRY.md` |
| 入口分层 | 工作区入口、LDVH 管理入口和管辖项目事实源未混同 |
| Skill 命名 | LDVH 自建 Skill 使用 `ldvh-` 前缀且不与业务 Skill 混淆 |
| Skill 边界 | Skill 未新增稳定规则、状态或完整规范正文 |
| 环境投射 | 平台不足时记录降级，不放宽 LDVH 特别要求 |

## 8. 规范落地要求

| 落地要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 上位约束承接要求 | LDVH 运行投影、入口分层和 Skill 治理应遵守本文特别要求 | 本文、04.02、04.03、Human Gate | 运行投影治理 | 新增、修改或审计 LDVH 运行投影时 |
| 入口可见要求 | AI 处理 LDVH 特别落地要求时应能定位本文 | 04 父文档、入口摘要、42 引用 | AI 执行入口提示 | 本文标题、定位、登记表或特别要求编号变化时 |
| 流程复用要求 | 薄入口检查和 Skill 检查应形成可复用步骤 | Skill、Command、Code、人工检查 | 流程复用 | 创建、修改、重命名、迁移或审计运行投影和 Skill 时 |
| 确定性执行要求 | 后续 Code 应能检查薄入口、Skill 命名、入口引用和正文边界 | `tools/specs_validate.py` 扩展、正反样例 | 校验实现 | 字段稳定或正式吸收时 |
| Human 交互要求 | 改变统一入口、Skill 前缀或特别要求前应暂停确认 | Human Gate、Web、对话确认 | 运行投影治理确认 | 高影响入口或 Skill 变更时 |
| 生命周期触发要求 | 正式规范、运行投影或 Skill 实体变化后应检查本文是否同步 | 42、Hook、CI、人工降级检查 | 触发保障 | 入口、Skill、Code、Web、Agent、Hook、CI 边界变化时 |
