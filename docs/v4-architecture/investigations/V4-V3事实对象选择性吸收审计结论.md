# V4 对 V3 事实对象选择性吸收审计结论

> 记录性质：本文件是 `../active/V4-V3事实对象选择性吸收决定.md` 的只读审计证据。它不是规范、行动模板、迁移清单、映射表或写入授权，也不定义任何 V4 对象、类型、状态、字段或公开接口。
>
> 记录日期：2026-07-16

## 1. Human 决定与替代范围

V4 对 V3 事实对象采取**选择性吸收**，不再以“92 项全部逐条形成 V4 承接”为当前目标。此前已经冻结的 92 项 V3 输入及其机械 characterization 继续作为可回读历史范围，但不构成任何对象必须迁入 V4 的承诺。

每次未来吸收只在 Human 明确选择具体来源、价值和当前用途后重新开始。选择性吸收不恢复 V3 Schema、路径、实现、身份、状态、时间、审批、关系或环境结论，也不使任何 V3 内容自动成为 V4 事实。

## 2. 已完成的只读审核范围

本轮已在不写入 V4 事实、不修改 Specs、行动模板、公开 API 或实现的前提下，完成以下 V3 源的分组只读审核：

| 组别 | 冻结源数量 | 审核结论范围 |
|---|---:|---|
| Spark | 49 | 当前议题、重叠簇、终态和暂停领域风险 |
| WorkCase | 24 | 历史责任、关闭/审批不可继承、可能的重新承接方向 |
| Study | 17 | 历史研究价值、外部来源当前性、缺失或临时输入风险 |
| Pitfall | 2 | 可复用经验候选、当前证据和机制拆分风险 |

当前 Git 跟踪的 `facts/**` 仍为零。本轮没有创建 V4 对象、目标映射、logical key、ledger、validator、迁移工具、durable journal、receipt 或批处理协议。

## 3. 共同边界

1. 新 V4 对象只能在未来实际创建时取得新的 ID 和当前创建时间；V3 ID、时间及缺失时区只能作为 archive 来源事实，不能伪装为 V4 历史。
2. V3 的 `closed`、`resolved`、`discarded`、phase、审核、批准、执行、关闭、关系和旧测试结果都不能直接继承为 V4 当前状态或证据。
3. V3 archive 可以作为精确来源回指，但不自动证明当前外部环境、软件版本、网页内容、实现能力或验证结论。缺失、临时路径或不可重读输入不得被虚构为证据。
4. 旧 `related_*`、路径和字符串引用只保留为重新判断的候选；只有未来实际存在且当前语义成立的 V4 对象之间才可能建立关系。
5. 选择性吸收不因“历史对象存在”而创建当前 WorkCase，也不因旧计划、日志或建议而自动开启 Web、Windows、CI 或环境实现工作。

## 4. 四组主要发现

### Spark

49 项中存在多个强重叠簇：事实路由与类型边界、Agent/环境接入、规则读取分层、流程与能力资产、Web 呈现，以及外部研究吸收。少数旧终态和高演进记录不能直接转为 V4 终态。Web、Windows 和环境接入相关项仍受当前暂停范围约束；未来若选择吸收，应先确认具体当前问题，而不是复用旧实施计划。

### WorkCase

24 项都不应直接重建为 V4 WorkCase。旧关闭、阶段、创建审核、执行批准和关闭确认不是 V4 已发生的生命周期事实。它们中有些可在未来选择性承接为历史研究、可复用 Pitfall 或当前 Spark；是否重新成为 WorkCase 必须由 Human 明确给出当前工作意图。

### Study

多数项可在未来收窄为明确历史边界的研究候选，但涉及当前外部产品、标准、服务或版本的结论必须重新读取实际来源。`study-0010` 是迁移/吸收索引，不能作为 V4 Study 承接。`study-0009` 缺失关键原研究，`study-0015` 依赖临时截图路径，`study-0017` 依赖临时审计附件；三者在稳定来源或 Human 缩减决定之前不能完整吸收。`study-0007` 是 Web 执行计划，应随 Web 恢复后另行判断，而不是伪装为研究。

### Pitfall

`pitfall-0001` 是一个可能仍有价值的关闭责任分流经验，但需要当前 V4 下实际发生、解决和验证的证据。`pitfall-0002` 混合了环境协议转换、命令路径和重复 hook 配置等不同机制；若未来吸收，必须先决定其当前价值和是否拆分。两项的 V3 验证与环境事实均不能直接作为 V4 当前证据。

## 5. 集中未决项

未来恢复选择性吸收前，Human 需要只就实际拟吸收范围决定：

1. 哪些旧议题仍有当前价值，以及它们应成为当前 Spark、严格历史边界的 Study、重新验证后的 Pitfall，还是不吸收；
2. 是否以及何时明确建立新的 V4 WorkCase；旧 WorkCase 本身不携带当前工作意图；
3. 对明显混合的旧对象，是否允许在具体吸收时拆分，或改为只吸收其中有独立价值的部分；
4. 对缺失或临时来源，提供稳定可回读输入、授权删去相应结论，或决定不吸收；
5. 对 Web、Windows、CI 和环境接入相关项，是否在相应暂停解除后再单独选择，而不是在本轮恢复。

这些是集中决策类别，不构成对象级映射、优先级、执行授权或“92 项必须完成”的新承诺。

## 6. 暂停与恢复条件

V3→V4 吸收现已暂停。未来仅在 Human 选定具体来源和当前用途后恢复相应的最小范围；届时先重新回读所选 archive 源、核实当前规则和必要证据，再决定是否创建 V4 对象。

恢复不自动授权任何写入。任何未来创建仍须使用当时已有的 V4 合法创建边界、no-overwrite、写后回读和独立 Git 提交；未选定的 V3 源继续保持 archive，不产生 V4 承接。
