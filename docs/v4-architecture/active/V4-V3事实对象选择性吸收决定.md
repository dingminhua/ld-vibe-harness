# V4 V3 事实对象选择性吸收决定

> 记录性质：本文记录 Human 对 V3 事实实例进入 V4 的当前范围决定。它不是规则源，不授权写入，也不使任何 V3 内容自动取得 V4 身份。
> 决定日期：2026-07-15
> 当前状态：全量逐项处置进行中；尚未完成对象级选择或实例吸收

## 1. Human 决定

V4 对 V3 事实对象采取选择性吸收，不再以 92 项全部逐条形成 V4 承接为当前目标，也不把全量迁移作为 bootstrap/resume、真实 dogfood 或发布的前置条件。

已经冻结的 92 项不可变基线与 decision-independent source characterization 继续作为可回读的历史库存和机械调查证据。它们只证明 V3 历史输入的范围与形态，不表示任何一项必须进入 V4，也不构成迁移进度。

该决定不恢复 V3 Schema、字段、状态、路径、身份、时间、关系、实现或历史生命周期效力。V3 内容只有在 Human 选择后，才可能依据当时有效的 V4 来源重新判断。

2026-07-19 Human 调整当前工作顺序：先完成 92 项 V3 历史输入的逐项处置，再开启 V4 Web 观察。处置完成不等于把 92 项批量复制到 V4；每项仍须形成“当前 V4 事实、已由 V4 承接、仅保留 archive 或已经过时”之一的结论。只有 Human 确认仍具当前价值且需要继续推进的最小内容，才按当时有效的 V4 来源创建新的当前事实；旧 WorkCase 默认先作为 Spark 候选重新判断，除非 Human 另行确认它已经是当前真实责任并应建立新的 V4 WorkCase。

2026-07-19 Human 随后将当前迁入收口范围扩展至 V2 与 V3 两份历史事实源。V3 专属的上述记录继续保留；当前完整范围、V2 基线、跨版本谱系合并和推进顺序以 `V4-历史事实对象选择性吸收决定.md` 为准。

## 2. 选择与吸收边界

每次吸收只处理 Human 明确选择的具体来源、当前价值和用途，并遵守以下边界：

1. 重新读取所选 archive 源、当前规则和必要证据，不从旧状态、旧计划或 characterization 推断 V4 结论；
2. 只吸收满足当前用途的最小内容，可以不吸收、收窄、拆分、合并或改用另一合法事实类型；
3. 旧 WorkCase 不携带当前工作意图；是否建立新的 V4 WorkCase 必须由 Human 依据当前工作另行决定；
4. 选择本身不授权创建或更新。实际写入必须使用当时已有且适用的 V4 合法边界，并完成回读、验证和 Git 留痕；
5. 如果现有来源或 Code 不能合法承载所选最小范围，停止该项并单独评估缺口，不以迁移为由自动新增兼容层、迁移状态机、中央登记、专用行动模板或批处理 Code。

未被选择的 V3 对象继续留在 archive，不产生待办、缺口或 V4 承接义务。

## 3. 与当前推进路线的关系

当前工作顺序是：

1. 先按 §2 完成 92 项 V3 输入的逐项处置与 Human 对实际拟吸收范围的选择；
2. 对已选择、仍具当前价值且需要继续推进的最小范围，使用现有 V4 合法创建边界重新建立当前事实；
3. 迁入收口后恢复 V4 Web 只读观察，以当前 V4 事实源呈现所选对象的列表、详情与状态；
4. 随后由 Human 选择真实受管辖工作，完成事实读取、必要创建、CAS 更新、强制中断、换会话恢复、验证、Git 留痕、结果交还和关闭的纵向 dogfood；不得为证明流程制造事实；
5. dogfood 后依据实测决定必要的减法或修正，再恢复其它 Web V4 bridge 范围、原生 Windows、LDVH 自身 CI 和发布准备。

Windows、CI 或环境工作不会因某个 V3 对象提及它们而自动恢复。V4 Web 只读观察只在上述迁入收口后按单独范围恢复；现有 92 项机器基线、characterization 和只读验证器继续保留，但不承担对象级处置结论。
