# LDVH Install Wizard Practice

本文是 Code 实现域文档，承接 `specs/30-LDVH安装初始化管辖项目配置行动模板.md` 的安装向导交互实践。本文不定义新的安装授权，不替代 Human Gate，不表示任何插件、Hook 或用户环境已经安装。

## 展示原则

安装向导是正常安装流程，不区分测试版和正式版。是否执行只在最终确认时由 Human 决定。

用户主流程使用普通词：

| 用词 | 用途 |
|---|---|
| 路径确认 | 展示完整步骤，确认 LDVH 本体和目标工作区 |
| 安装前检查 | 只读检查当前状态 |
| 安装选项 | 收集需要 Human 决定的选项 |
| 安装方案预览 | 汇总检查结果、选择、后置项、验证和回滚 |
| 最终确认 | Human 选择执行或不执行 |

避免把内部检查、环境接管状态等技术口径作为用户主标题。这些术语只应出现在技术细节、验证摘要或环境状态说明中。

每一步开头先给三行以内摘要：

| 摘要项 | 写法 |
|---|---|
| 本步目的 | 说明当前步骤要完成什么 |
| 不会做什么 | 说明本步是否只读、是否不会写入或不会安装 |
| 需要决定什么 | 只写当前需要 Human 决定的事项；没有就写本步不需要选择 |

## 状态表模板

每次展示向导时，先给流程状态表。当前步骤使用 `👉`，已经完成的步骤使用 `✅` 并把决策或结果写进最后一列，尚未发生的步骤保持空白。

| 状态 | 步骤 | 决策 / 结果 |
|---|---|---|
| 👉 | 1/5 📍 路径确认 |  |
|  | 2/5 🔎 安装前检查 |  |
|  | 3/5 ⚙️ 安装选项 |  |
|  | 4/5 🔒 安装方案预览 |  |
|  | 5/5 🛠️ 最终确认 |  |

状态列不要写“待进行 / 待选择 / 待确认”。空白已经表示尚未发生。

每次进入安装前检查时，先展示状态图例：

| 标记 | 含义 | 是否阻断 | 下一步处理 |
|---|---|---|---|
| ✅ 通过 | 满足当前要求 | 否 | 保留结果 |
| ⚠️ 注意 | 需要知情或关注 | 不一定 | 写入方案或残留风险 |
| ⚠️ 需安装 | 缺少需要安装的入口 | 否 | 纳入安装方案预览 |
| ⚠️ 需升级 | 已存在但过时或指向旧路径 | 否 | 纳入升级方案预览 |
| ⛔ 阻断 | 当前不能继续执行 | 是 | 停止并说明解除条件 |
| ➖ 不适用 | 本场景无需处理 | 否 | 不纳入执行动作 |

## 信息分类

安装向导必须分开展示三类信息：

| 类型 | 来源 | 是否问 Human |
|---|---|---|
| 系统检查事实 | 只读检查、Code 输出、目录回读 | 不问 |
| 用户决策 | Human 需要取舍的安装选项 | 问 |
| 需授权动作 | 安装、升级、禁用、卸载插件或外部 Hook | 最终确认前展示方案 |
| 本次后置 | 当前不支持、未授权或需要单独 Gate 的事项 | 不作为主选项 |

示例：

| 内容 | 分类 | 表达 |
|---|---|---|
| `ldvh-base/` 已存在 | 系统检查事实 | 写入安装前检查结果，不再询问是否创建 |
| 目标工作区根目录 | 用户决策 | 确认工作区，不询问配置文件放项目内 |
| 项目内或用户级配置目录 | 本次后置 | 说明不是支持位置，不放入主选项 |
| 用户环境插件未安装 | 需授权动作 | 标为 `⚠️ 需安装`，进入安装方案预览 |
| 用户环境插件过时 | 需授权动作 | 标为 `⚠️ 需升级`，进入升级方案预览 |
| 管辖项目不是 Git repo | 阻断 | 标为 `⛔ 阻断`，说明管辖项目必须是 Git 仓库 |
| 管辖项目 Git Hook 未安装 | 需授权动作 | 标为 `⚠️ 需安装`，逐 repo 进入安装方案预览 |
| 管辖项目 Git Hook 过时或非 V3 managed | 需授权动作 | 标为 `⚠️ 需升级`，逐 repo 进入升级方案预览 |

## 图标与选择表模板

需要 Human 选择时，每次只问一个问题。配置位置固定为目标工作区根目录；选择表只用于确认 LDVH 本体路径、目标工作区根目录或多个候选。

流程状态列使用 `👉` 表示当前步骤，使用 `✅` 表示已完成步骤，未发生步骤保持空白。步骤名称固定使用 `📍 路径确认`、`🔎 安装前检查`、`⚙️ 安装选项`、`🔒 安装方案预览`、`🛠️ 最终确认`。

安装前检查结果列固定使用 `✅ 通过`、`⚠️ 注意`、`⚠️ 需安装`、`⚠️ 需升级`、`⛔ 阻断`、`➖ 不适用`。路径确认、安装前检查和方案预览的项目列应使用固定图标：

| 表格 | 项目图标 |
|---|---|
| 路径确认 | `📦 LDVH 本体路径`、`🗂️ 目标工作区根目录`、`🧾 配置文件完整路径` |
| 安装前检查 | `📦 LDVH 本体`、`🧾 工作区配置`、`⚠️ 配置层级`、`📁 事实源目录`、`🔎 配置解析`、`🔌 环境入口`、`🪝 Git Hook` |
| 安装方案预览 | `🧾 工作区配置`、`🗑️ 项目内旧配置`、`📁 事实源目录`、`🔌 环境插件`、`🪝 管辖项目 Git Hook`、`🧪 验证`、`↩️ 回滚` |

| 项目 | 路径 | 说明 | 限制 | 建议 |
|---|---|---|---|---|
| 📦 LDVH 本体路径 | `<ldvh-root>` | 存放 LDVH specs、Code、安装模板和验证工具 | 不等于目标工作区 | 候选必须有 `specs/30...` 和 `code/specs_validate.py` 证据 |
| 🗂️ 目标工作区根目录 | `<workspace-root>` | LDVH 要管理的工作区范围 | 项目内配置不是支持位置 | 确认后配置为 `<workspace-root>/LDVH-GOVERNED-PROJECTS.yaml` |
| 🧾 配置文件完整路径 | `<workspace-root>/LDVH-GOVERNED-PROJECTS.yaml` | 登记该工作区管辖项目的配置文件 | 不放项目根或用户级目录 | 默认且唯一支持位置 |

如果当前界面支持选择框 / 单选控件，多个 LDVH 本体候选或多个目标工作区候选应使用 UI 控件；不可用时使用等价编号选项。

目标工作区没有 LDVH 文件时，AI 仍应从 LDVH 本体读取安装模板。允许的 bootstrap discovery 是有限、只读、有证据的搜索：优先使用当前已知 LDVH root、`LDVH_ROOT` / `LDVH_HOME`、插件 / Hook / wrapper 中记录的 LDVH root、cwd 向上的 LDVH 本体候选、常见工作区父目录有限深度搜索；多个候选必须展示证据并让 Human 选择，找不到时要求 Human 提供 LDVH 本体路径。

确认目标工作区根目录时，必须检查从工作区根目录到当前项目路径链上的 `LDVH-GOVERNED-PROJECTS.yaml`。如果工作区根目录和项目内同时存在配置，安装方案预览应显示配置层级冲突，并停止在最终确认前；用户需要先删除、迁移或明确保留其中一个配置文件。

长路径应同时放在表格和可复制路径块中。路径块只用于复制，不替代表格里的说明、限制和建议。

```text
LDVH_ROOT=<ldvh-root>
WORKSPACE_ROOT=<workspace-root>
GOVERNED_CONFIG=<workspace-root>/LDVH-GOVERNED-PROJECTS.yaml
```

## 最终确认

最终确认前不得写入。4/5 安装方案预览只确认是否进入最终确认，不是执行授权。主界面优先展示普通用户需要判断的信息：会改变什么、不会改变什么、执行后还需要验证什么、是否存在阻断。技术明细附后或折叠展示，并按净变化列出：

1. 将新增；
2. 将修改或升级；
3. 将保持不变；
4. 不会执行；
5. 需后置确认；
6. 验证命令和预期结果；
7. 不可验证范围；
8. 回滚方式；
9. 残留风险。

完整安装方案必须同时覆盖两类入口：AI 环境 Hook 插件和每个已选择管辖项目的 Git `commit-msg` Hook。Git Hook 预览必须逐 repo 展示 repo 路径、`core.hooksPath`、active hook、当前是否 V3 managed、将执行的 install / upgrade / no-op、验证命令和 rollback 命令。未能确认 repo 或 Human 未授权时，不得把 Git Hook 写成已安装，也不得声明完整安装完成。

每个已选择管辖项目必须是有效 Git worktree。安装前检查发现目标不是 Git 仓库时，必须停在安装前检查或安装方案预览，标为 `⛔ 阻断`，并说明管辖项目必须是 Git 仓库；不得继续进入最终执行，也不得创建 Git Hook 替代 Git 初始化。

安装后验证必须可复现。AI 环境 Hook 至少要验证插件安装状态、Hook 配置指向 V3 shim、直接 shim 正反输入；如果真实 Codex / IDE lifecycle 不能在当前回合触发，必须写明不可验证范围，不得声明 integrated。Git Hook 必须验证 `governed_hook_adapter.py status`、`core.hooksPath`、managed `commit-msg` 文件和可执行位，并直接执行 hook 文件跑有效 commit message 放行和无效 commit message 阻断。

不可验证范围单独列出，不能混入“验证通过”。常见不可验证项包括真实 Codex / IDE lifecycle 触发、外部环境自动触发和卸载后自动触发状态。

最终确认只提供两个主选项。5/5 不再重复安装前检查表，也不把执行后验证写成新的只读验证选项；只列出将写入对象和不写入对象。Human 选择 `1 执行方案` 后，AI 必须立即执行已确认写入并进行写入后验证；Human 要求调整方案时回到对应前一步，但不作为第三个主选项展示：

| 选项 | 说明 | 结果 |
|---|---|---|
| 1 | 执行方案 | 按方案执行并验证 |
| 2 | 不执行，停止安装 | 停止，不写入 |

### 4/5 安装方案预览

本步目的：让 Human 看懂执行后会改变什么。
不会做什么：不会在最终确认前写入。
需要决定什么：是否进入最终确认；这不是执行授权。

#### 一句话方案

这次会处理：工作区项目清单、LDVH 资料目录、Codex/工具入口插件、Git 提交消息检查。
现在不会写入；只有 Human 在 5/5 选择“执行方案”后才会开始。
Codex/工具入口插件即使可见，也只能先记为“可见 / 需验证”，不声明已自动接入并验证可阻断。

#### 执行后你会看到的变化

| 范围 | 这次怎么处理 | 位置 | 对你的影响 |
|---|---|---|---|
| 🧾 工作区项目清单 | 新建 / 更新 / 保留 | `<workspace>/LDVH-GOVERNED-PROJECTS.yaml` | LDVH 知道哪些项目归它管理 |
| 📁 LDVH 资料目录 | 创建缺失目录 / 保留现有目录 | `<project>/ldvh-base/` | 用来放工作项、决策、踩坑、想法和研究报告 |
| 🔌 Codex/工具入口插件 | 安装 / 升级 / 保留 / 本次不处理 | 用户环境插件位置 | 让 LDVH 入口可见；自动触发仍需验证 |
| 🪝 Git 提交消息检查 | 安装 / 升级 / 保留 | 已选择的 Git 项目 | 提交时检查 commit message |

4/5 的选项只允许表达为进入最终确认或暂停，不得写成执行授权：

| 选项 | 结果 |
|---|---|
| 1 | 进入 5/5 最终确认，仍不写入 |
| 2 | 暂停在方案预览，不写入 |

#### 技术明细

| 分组 | 内容 |
|---|---|
| 将新增 | 缺少的事实源目录、未安装的环境插件、未安装的管辖项目 Git Hook |
| 将修改或升级 | stale V2 path 插件、旧版本插件、非 V3 managed Git Hook |
| 将保持不变 | 已有效的工作区配置、已有效的事实源目录 |
| 不会执行 | 未选择项目、非本工作区 target、未授权的外部环境写入 |
| 需后置确认 | 真实 lifecycle 验证、卸载后自动触发状态、跨项目批量接入 |
| 验证 | specs validator、governed-projects、environment audit、Git Hook status 和正反样例 |
| 不可验证范围 | 当前回合无法触发的 Codex / IDE lifecycle |
| 回滚 | 插件 uninstall / rollback、Git Hook uninstall / rollback、配置恢复路径 |

### 5/5 最终确认

本步目的：由 Human 选择执行或停止。
