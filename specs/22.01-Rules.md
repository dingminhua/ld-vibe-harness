## 1. 本文定位

本文是 `specs/22-Change-变更记录.md` 的附件型实践子文档（编号 22.01），承接 Rules 入口实践。本文不是独立事实模型，不得重新定义 Change 的对象定位、准入条件、状态机、对象关系、Human Gate、字段契约、事实源回写或证据留存。发生冲突时，以 22 主文档和上位基础规范为准。

本文是 Change Rules 层面提交提醒和提交纪律的权威位置。Rules 入口是安全带和高频提醒，不是 Change 完整流程。commit message 格式契约由 22.06-Contract.md 承接，格式校验工具由 22.04-Tools.md 承接。

---

## 2. 实践目标

让 AI 在提交代码变更前，自动触发提交前提醒和提交纪律检查，确保每次 commit 都经过 diff 展示、message 展示、格式预检和用户确认，减少未展示即提交、格式不合规、未经确认即提交等违规行为。

---

## 3. 适用场景

1. AI 完成代码修改，准备执行 `git commit` 时；
2. AI 跨多个 Git 仓库提交时；
3. AI 在 commit 后发现格式违规，需要审计和整改时。

---

## 4. 实践边界

1. 本实践只约束 Rules 层对 Change 的提交前提醒和提交纪律；
2. commit message 格式规范由 22 主文档 §8 定义；
3. commit message 字段契约由 22.06-Contract.md 承载；
4. 格式校验和预检工具由 22.04-Tools.md 承接；
5. 本实践不替代 22 主文档的任何章节。

---

## 5. 实践内容

### 5.1 提交前提醒

AI 在准备 commit 时，必须依次完成以下提醒步骤：

1. **diff 展示**：展示 `git diff --stat` 和 `git diff`，让用户清楚知道哪些文件被修改、修改了什么；
2. **message 展示**：展示完整 commit message，让用户确认描述准确；
3. **格式预检**：调用 `python3 tools/check_22_commit_format.py --check-message "<message>"` 校验 message 格式；
4. **跨仓库检查**：遍历工作区所有目录和子目录（至少到深度 3），对每个目录检查是否存在 `.git`。有 `.git` 的目录按以下步骤逐仓库执行：展示 diff → 展示 message → 格式预检。无 `.git` 的目录向用户报告 `未发现 Git 仓库，跳过`，继续遍历。

预检不通过（exit code ≠ 0）时，必须修正 message 后重新预检，直至通过方可继续。

### 5.2 提交纪律

AI 在 commit 时必须遵守：

1. 逐文件 `git add`，不可 `git add -A` 或 `git add .`；
2. commit message 必须使用中文编写（type、scope 可使用英文）；
3. commit message 第一行（subject）必须遵循 `<type>(<scope>): <中文简描述>` 格式；
4. commit message 必须包含 body 说明变更原因和内容，并包含 `Refs:` 关联对象；
5. 涉及 Human Gate 的修改，body 中必须说明确认情况；
6. 跨仓库变更时，每个受影响的仓库独立提交；
7. 未完成以上提醒步骤和用户确认前，不可执行 commit。

### 5.3 禁止承载内容

Rules 层不得承载以下内容：

1. commit message 的 type 枚举、scope 枚举、字段格式正则（由 22.06-Contract.md 承载）；
2. 格式校验工具的参数、输出格式、exit code 约定（由 22.04-Tools.md 承载）；
3. Git 操作手册、命令语法、分支策略（不应出现在 Change 规范中）。

---

## 6. Human Gate

编辑本 Rules 子文档或变更提交纪律时，应经 Human Gate 确认。

---

## 7. 检查项

检查 Change Rules 入口实践是否合规时，应确认：

1. 工作区 L0 Rules 和项目 L1 Rules 是否包含引用本 Rules 入口的提交纪律提醒；
2. AI 在实际 commit 时是否遵守提交前提醒步骤（diff 展示、message 展示、格式预检）；
3. commit message 是否使用中文编写；
4. 每次 commit 是否只包含 AI 当前会话修改的文件，未混入无关变更；
5. 跨仓库变更是否逐仓库独立提交，未遗漏。
