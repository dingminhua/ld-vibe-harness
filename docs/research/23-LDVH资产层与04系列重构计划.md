## 1. 本文解决的问题

本文用于记录一个比 22 更底层的问题：LDVH 最终的能力资产放在哪里，哪些目录属于资产，哪些目录属于事实源，哪些目录只属于参考与研究材料，资产如何被 AI 开发环境承接，以及 04 系列应如何正式规范这件事。

本文集中回答：

1. `docs/specs/` 在当前阶段是否维持在 `docs/` 中；
2. specs、rules、skills、hooks、agents、tools、web、refs、research、ldvh-base 分别属于什么层；
3. LDVH 资产层、事实源层、环境承接层如何区分，参考与研究材料如何定位；
4. 04 系列是否需要新增或重构专门章节来规范资产层与环境承接关系；
5. 04.06、04.07、04.08 和未来三环境承接矩阵的关系；
6. 哪些事项需要 ADR、Task、Human Gate 或后续重构计划。

本文不直接执行目录迁移，不直接修改 04 系列正式规范，不创建资产目录，也不删除 04.07 / 04.08。

## 2. 已确认判断

### 2.1 docs 不是资产类别，docs/specs 是规范资产

已确认：`docs` 本身不应作为资产类别。

更准确的分层是：

| 路径 / 类型 | 当前判断 |
|---|---|
| `docs/specs/` | 规范资产，也是规范事实源 |
| `docs/refs/` | 参考材料，不是正式资产 |
| `docs/research/` | 研究 / 推进材料，不是正式资产 |

已确认：当前阶段不推进 `docs/specs/` 迁出，仍维持在 `docs/` 内。需要明确的是：`docs` 不是资产类别，但 `docs/specs/` 是规范资产和规范事实源；`docs/refs/` 与 `docs/research/` 是参考与研究材料。

### 2.2 ldvh-base 不是资产

已确认：`ldvh-base/` 不属于资产层。

`ldvh-base/` 是工作对象事实源，承载 ADR、Task、Memo、Pitfall 等工作对象实例。它记录决策、任务、备忘、踩坑、状态、证据和关系，但它不是可复用能力本体，也不应被环境薄入口加载为能力资产。

### 2.3 tools 和 web 都是资产

已确认：`tools/` 和 `web/` 都属于 LDVH 能力资产。

| 路径 | 资产类型 | 说明 |
|---|---|---|
| `tools/` | Code 能力资产 | 可执行检查、校验、解析、生成、迁移、受控写入或报告输出能力 |
| `web/` | Web 能力资产 | Human-facing 展示、审阅、确认、检查、矩阵展示或受控轻写入界面 |

### 2.4 rules / skills / hooks / agents 是文本能力资产

已确认：当前阶段最多只需要考虑以下文本能力资产类型：

1. `rules`；
2. `skills`；
3. `hooks`；
4. `agents`。

这些资产本质上主要是 Markdown 文本资产，供 AI 开发环境读取、引用、加载或投影。它们不应被设计成 ECC 式安装包、运行时状态库或多环境分发系统。

### 2.5 环境只承接资产，不拥有资产

已确认：Trae Work CN、Codex App、Claude Code CLI 是 AI 开发环境，不是 LDVH 资产本体。

环境只能通过环境薄入口、运行投影或承接降级来承接 LDVH 资产。环境薄入口不能复制、改写或替代规范资产正文。

## 3. 建议分层模型

### 3.1 三类正式关系与参考材料

LDVH 后续应明确三类正式关系，并单独说明参考材料：

```text
资产层
事实源层
环境承接层

参考材料：docs/refs、docs/research
```

资产层、事实源层和环境承接层是 04 系列需要正式规范的关系。参考材料不是与三者并列的正式层级，只用于承载调研、外部资料、阶段性判断和候选方案。部分目录可能同时属于多个身份，例如 `docs/specs/` 同时是规范资产和规范事实源。

### 3.2 资产层

资产层用于承载可复用能力、规则、实现或界面。

| 资产类型 | 建议位置 | 说明 |
|---|---|---|
| 规范资产 | `docs/specs/` | 正式规则、模型、流程、合同 |
| 文本能力资产 | `rules/`、`skills/`、`hooks/`、`agents/` | AI-facing Markdown 能力资产 |
| Code 能力资产 | `tools/` | 可执行检查、校验、生成、迁移、受控写入等能力 |
| Web 能力资产 | `web/` | Human-facing 交互、检查、审阅、确认或轻写入能力 |

### 3.3 事实源层

事实源层用于承载 LDVH 稳定事实。

| 事实源类型 | 位置 | 是否资产 |
|---|---|---|
| 规范事实源 | `docs/specs/` | 是，同时是规范资产 |
| 工作对象事实源 | `ldvh-base/` | 否 |
| Change 事实承载 | Git commit | 否，不单独建立 `changes/` 资产目录 |

`ldvh-base/` 不是资产层。它可以记录资产相关 ADR、Task、Memo 或 Pitfall，但不承载可复用能力资产本体。

### 3.4 参考与研究材料

参考与研究材料用于承载调研、参考、候选方案或外部来源。

| 材料类型 | 位置 | 说明 |
|---|---|---|
| 外部参考 | `docs/refs/` | 外部项目调研、平台机制资料、参考任务 |
| 内部研究 | `docs/research/` | 阶段性判断、计划、候选方案、暂不生效结论 |

参考与研究材料不是正式资产，不是权威事实源，也不是环境承接层。稳定结论必须进入 specs、ADR、Task、Code、Web 或其他对应事实源后才生效。

### 3.5 环境承接层

环境承接层用于说明 AI 开发环境如何承接 LDVH 资产。

| 承接对象 | 说明 |
|---|---|
| 三环境承接矩阵 | 记录 Trae Work CN、Codex App、Claude Code CLI 如何承接 LDVH 资产或承接项 |
| 环境薄入口 | 环境侧用于加载、引用、触发或降级的轻量入口 |
| 运行投影 | 资产在某个环境中实际存在或被调用的入口、文件、配置、命令、Skill、Agent、Hook、CI 检查、Web 页面、摘要或降级记录 |
| 承接检查 | 检查环境是否正确承接资产 |
| 承接降级 | 环境不能完整承接时的替代方式 |

环境承接层不是资产库，不是事实源库，也不是运行状态库。

## 4. docs/specs 维持现状的判断

### 4.1 当前不迁出 specs

已确认：当前阶段不推进 `docs/specs/ → specs/` 迁移，`docs/specs/` 仍维持在 `docs/` 下。

原因：

1. 当前主线仍是 LDVH 落地相关事项；
2. 04 系列重构尚未完成，不宜同时推进目录迁移；
3. `docs/specs/` 已被大量规范、refs、research、tools、入口规则和检查命令引用；
4. 迁移会引入大规模引用更新和工具兼容工作；
5. 当前真正需要先解决的是资产层、事实源层和环境承接层的模型定义，而不是目录移动。

### 4.2 维持现状不改变资产判断

`docs/specs/` 继续位于 `docs/` 下，并不改变它的身份：

1. `docs/specs/` 仍是规范资产；
2. `docs/specs/` 仍是规范事实源；
3. `docs/refs/` 仍是参考材料；
4. `docs/research/` 仍是研究 / 推进材料；
5. `docs` 仍不作为资产类别。

后续 04 系列需要明确：目录容器不是资产类别，资产身份由子目录职责决定。

### 4.3 后续只保留为远期可能事项

`docs/specs/` 是否迁出可以作为远期目录治理问题保留，但不进入当前 04 系列重构主线。

若未来重新讨论迁出，需要单独创建 ADR、Task、引用迁移计划、工具兼容计划和回滚方案。

## 6. 从环境到资产的沉淀路径

### 6.1 基本链路

环境中的观察、refs、实测或承接差异，不会自动成为 LDVH 资产。

建议链路：

```text
环境 refs / 实测 / 承接差异
  ↓
三环境承接矩阵归类
  ↓
判断是否具备跨环境复用价值
  ↓
形成候选资产或候选改动
  ↓
Task / ADR / Human Gate
  ↓
写入 specs、rules、skills、hooks、agents、tools 或 web
  ↓
环境薄入口引用或触发资产
  ↓
42 / landing-plan 检查承接情况
```

### 6.2 资产归属判断

| 情况 | 归属 |
|---|---|
| 稳定规则、模型、流程、合同 | specs |
| AI-facing 规则或入口文本 | rules |
| AI-facing 任务能力 | skills |
| 生命周期触发提示或检查策略 | hooks |
| 角色、子 Agent 或多角色模板 | agents |
| 可执行检查、校验、生成、迁移或受控写入 | tools |
| Human-facing 展示、审阅、确认或轻写入 | web |
| 决策、任务、备忘、踩坑 | ldvh-base，作为事实源，不是资产 |
| 外部参考或阶段性研究 | docs/refs 或 docs/research，不是正式资产 |

### 6.3 环境薄入口边界

环境薄入口可以：

1. 引用资产；
2. 加载资产；
3. 触发资产；
4. 摘要说明资产入口；
5. 在环境不支持时说明承接降级。

环境薄入口不得：

1. 复制 specs 正文作为长期规则；
2. 改写 LDVH 资产语义；
3. 保存资产状态；
4. 替代资产事实源；
5. 把环境工具输出升格为资产；
6. 绕过 Human Gate 或事实源回写边界。
