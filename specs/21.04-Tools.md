## 一、本文定位

本文是 `specs/21-ADR-决策记录.md` 的附件型实践子文档（编号 21.04），承接 Tools 契约式校验与执行实践。本文不是独立事实模型，不得重新定义 ADR 的对象定位、准入条件、状态机、对象关系、Human Gate、字段契约、事实源回写或证据留存。发生冲突时，以 21 主文档和上位基础规范为准。

---

## 二、实践目标

为 ADR 提供可重复、可校验、可追溯的 Tools 辅助能力，帮助 AI 和人从 Git 文件事实源读取 ADR 实例，生成运行时索引、查询结果、状态统计和字段校验结果。

---

## 三、适用场景

1. 需要列出当前项目 ADR 摘要时；
2. 需要按关键词、状态或关联规范查询 ADR 时；
3. 需要查看单个 ADR 详情时；
4. 需要统计 ADR 状态分布时；
5. 需要校验 ADR YAML 实例字段完整性、状态合法性和文件命名时。

---

## 四、实践边界

1. 当前 ADR Tools 实体路径为 `tools/adr_index.py`；
2. 当前 ADR Tools 只读取 `ldvh-base/adrs/` 下的 ADR YAML 实例，不写入 ADR 实例、规范或 Rules；
3. ADR Tools 输出属于运行时派生结果，不是最终事实源；
4. ADR Tools 字段和状态校验依据 `specs/21.06-Contract.md`，不得自行扩张 ADR schema；
5. ADR Tools 不得替代 Human Gate，不得自动执行 ADR 状态流转；
6. 后续如扩展受控写入能力，Tools 只能执行已授权、可机械化、可校验的写入动作，不得产生授权本身或替代 ADR Skill 流程中的准入判断和 Human Gate 编排。

---

## 五、实践内容

`tools/adr_index.py` 当前提供以下命令：

| 命令 | 能力 |
|---|---|
| `list` | 列出所有 ADR 摘要 |
| `search <keyword>` | 按关键词搜索 ADR |
| `status <status>` | 按状态筛选 ADR |
| `show <adr_id>` | 显示单个 ADR 详情 |
| `stats` | 显示 ADR 状态统计 |
| `validate` | 校验 ADR 实例字段完整性、状态合法性和文件命名 |
| `related <spec>` | 显示与指定 specs 文件关联的 ADR |

测试文件为 `tests/tools/test_adr_index.py`。测试命令为：

```bash
python3 -m pytest tests/tools/test_adr_index.py
```

新增或修改 ADR Tools 能力时，应同步补充或更新对应 pytest 测试，执行测试验收，并在 Change 记录、任务证据或人工验收材料中记录测试命令和结果。测试未通过时，不得声称 ADR Tools 能力已经完成落地或验收通过。

---

## 六、Human Gate

以下情况应评估 Human Gate：

1. ADR Tools 从只读能力扩展为写入 ADR YAML、规范、Rules 或 Change 记录；
2. ADR Tools 改变 ADR 字段契约、状态流转或文件命名校验依据；
3. ADR Tools 将运行时派生结果持久化为新的事实源；
4. ADR Tools 绕过 21 主文档定义的 Human Gate 自动执行状态变更；
5. ADR Tools 承担 ADR 准入判断、流程性判断、授权生成或 Human Gate 编排。

---

## 七、检查项

检查 ADR Tools 契约式校验与执行实践是否合规时，应确认：

1. `tools/adr_index.py` 是否只读取 Git 文件事实源并输出运行时派生结果；
2. ADR 字段、状态和文件命名校验是否依据 `specs/21.06-Contract.md`；
3. Tools 输出是否未被当作 ADR 最终事实源；
4. Tools 是否未替代 Human Gate 或自动执行状态流转；
5. 新增或修改 Tools 能力时是否同步更新 `tests/tools/test_adr_index.py`；
6. ADR Tools 测试验收是否已执行，并在 Change 记录、任务证据或人工验收材料中记录测试命令和结果；
7. 契约子文档变更后，ADR Tools 实现和测试是否已同步更新（依据 `specs/04-LDVH模型子文档规范.md` §7.4、§八）。
