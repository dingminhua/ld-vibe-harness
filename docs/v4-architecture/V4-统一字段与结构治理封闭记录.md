# V4 统一字段与结构治理封闭记录

> 记录日期：2026-07-13。本文只记录阶段 4 在开始 Spark 前完成的治理审核与验证结果，不取得规范定义权。长期规则以 `specs/05-事实模型基础规范.md` 及其授权附件 `specs/attachments/05.Att.01-事实对象统一字段登记.md` 为准。

## 1. 封闭结论

统一字段与结构治理基础已经完成，可以按 `Spark → WorkCase → ADR → Pitfall → Study` 的顺序开始具体类型定义。后续类型仍必须逐类完成完整定义、登记、机械检查和独立复核；本结论不使任何具体类型、事实对象服务、迁移、Web 或写入能力自动成立。

## 2. 已封闭范围

1. 全部字段使用全局稳定 `field_key`，全部 JSON object 成员结构使用全局稳定 `structure_key`；`current` 与 `retired` 共同参与身份、位置和查重治理。
2. `definition_scope` 与 `applies_to` 分离；类型专属字段或结构被第二个类型需要时，先提升为 `foundation` 唯一定义，再由多个类型引用。
3. 每个字段与结构只有一个定义位置；登记、定义、适用范围、容器、值结构和状态形成可解析闭包。
4. 全部直接字段统一登记 `base_presence: required | conditional`；类型绑定只使用 `required | conditional | forbidden`，不得放宽基础必填。
5. 类型正式新增、复用、提升或区分字段与结构前，必须检索全部 `current`、`retired` 登记和该类型完整提案集合，并留下可解析准入记录与独立复核引用。
6. Code 只检查可确定的表形、身份、引用、唯一性、闭包、覆盖和组合约束；自然语言语义等价、复用是否无损以及新增是否必要仍由 AI/Human 判断。
7. 中央登记错误与具体类型局部错误已经隔离；类型局部错误只隔离受影响类型，不错误撤销统一登记与 05。
8. `fact_type_key`、`field_key`、`structure_key` 的跨 Git 历史不可改派仍明确列为当前 Code 未自动证明的条件，未伪装成已自动验证。

## 3. 独立复核

本轮由两个独立审议方向复核当前工作树，没有并行定义多个事实类型：

| 复核方向 | 主动检查范围 | 最终结论 |
|---|---|---|
| 规范治理 | 结构与字段是否同等级治理、串行 Gate、出现规则、独立复核、验证与 Stop Conditions 是否对称 | 所有 P1 已关闭；可以开始 Spark |
| Code 与 tests | 中央/类型错误隔离、出现规则、结构闭包、定义映射、retired tombstone、声明来源与准入防绕过 | 初始 Gate 问题已修正；五类型全局归并时又补齐字段与结构准入唯一性的对称检查，以及有限共享字段与结构各自恰一 promote 来源 |

复核发现并完成的修正包括：结构成员的机器可读出现规则、移除含混 `optional`、部分共享结构准入覆盖、准入决定与比较集合一致性、仅普通 spec 可声明事实类型、字段与结构在验证和停止条件中的对称覆盖，以及全局归并阶段补充的重复 `information_need`、重复 `resulting_*_key` 和有限共享字段/结构单一 promote 来源检查。
