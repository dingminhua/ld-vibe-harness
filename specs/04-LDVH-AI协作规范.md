> 上位依据：`specs/00-LD-Vibe-Harness理念与纲要.md`

## 一、本文解决的问题

本文解决 LD Vibe Harness 如何使用 Rules、Skill 和 Agent 三类可落地 AI 协作机制，以及 AI 在具体场景中应如何在 Rules、Skill、Agent 之间选择合适承载方式的问题。

04 系列只治理 LDVH 当前可定义、可创建、可检查、可治理的核心协作资产。

## 二、与 00 总纲的关系

00 定义 Trae Solo 环境机制是 LD Vibe Harness 的五类构成要素之一，并明确 LDVH 对 Trae Solo 环境机制的态度是利用、不重新定义、规范不替代和适配不绑定。

本文承接 00 的该判断，只选择 Rules、Skill 和 Agent 作为 04 系列正式治理对象。三者共同回答：AI 如何被规则约束、何时进入可复用流程、何时进入独立上下文或专业智能体。

## 三、权威领域与子文档分工

本文是 Rules、Skill、Agent 三者选择边界的唯一事实源。04.01、04.02、04.03 分别展开各机制内部设计细则，不重复维护三者对比选择规则。

04 系列子文档分工如下：

| 文档 | 类型 | 权威领域 |
|---|---|---|
| `04-LDVH-AI协作规范.md` | 主文档 | Rules、Skill、Agent 总体边界、三者选择规则、事实源回写总原则和 Human Gate 总规则 |
| `04.01-Rules机制规范.md` | 子文档 | L0/L1/L2 规则分层、Trae Rules 生效方式、规则唯一事实源、规则变更检查 |
| `04.02-Skill机制规范.md` | 子文档 | Skill 准入、命名、部署边界、输出原则、Agent 边界和 Human Gate |
| `04.03-Agent机制规范.md` | 子文档 | Agent 创建或调用门槛、调度规则、定义摘要、生命周期、权限边界和 Human Gate |

子文档不得另建 Rules、Skill、Agent 对比选择表。需要判断某件事应进入 Rules、Skill 还是 Agent 时，以本文第五节为准。

## 四、LDVH 与 Trae 三类机制的关系

Trae Rules、Skill 和 Agent 是 LDVH 可利用的协作底座。LDVH 不重新定义 Trae 官方能力，不替代 Trae 的产品说明，也不保证 Trae 机制的运行行为始终稳定不变。

LDVH 对三类机制的治理原则如下：

1. **利用不重新定义**：LDVH 定义如何使用 Rules、Skill 和 Agent，不重新定义 Trae 官方机制本身。
2. **规范不替代**：LDVH 的机制规范是 Trae 使用约束和最佳实践，不替代 Trae 官方文档。
3. **适配不绑定**：LDVH 适配 Trae Solo 的能力模型，但不假设 Trae 是唯一可用 AI 编程环境。
4. **机制不等于事实源**：Rules、Skill 和 Agent 是执行机制或协作入口，不直接成为最终事实源。
5. **稳定事实必须回写**：三类机制产生的稳定结论、规则、任务、证据、决策或变更，必须写入 specs/、ldvh-base/、docs/ 或其他对应 Git 文件事实源后才成为 LDVH 稳定事实。

## 五、Rules / Skill / Agent 选择边界

本节是 AI 判断“这件事应该放入 Rules、Skill 还是 Agent”的唯一对比事实源。04.01、04.02、04.03 可引用本节，但不得复制维护另一套选择规则。

| 机制 | 适合承载 | 不适合承载 | 进入条件 |
|---|---|---|---|
| Rules | 必须遵守、绝对禁止、事实源边界、Human Gate 入口、L0/L1/L2 高频硬约束 | 大段教程、完整 SOP、低频流程、角色隔离分析 | 需要稳定约束 AI 或人，且规则应长期生效 |
| Skill | 可复用多步骤流程、标准化输入输出、轻量评估、受控写入流程 | Human Gate 判断本身、稳定规则正文、需要独立上下文或并行委派的任务 | 流程可复用、可在主上下文执行、边界和输出稳定 |
| Agent | 独立上下文、结论隔离、并行委派、不同权限边界、长期专业入口 | 简单问答、单文件小改、可由 Skill 完成的流程、仅包装角色名称 | 主上下文或 Skill 不足，且存在隔离、并行或权限差异需求 |

选择顺序：

1. 能通过稳定约束解决的问题，优先进入 Rules；
2. 需要可复用流程但可在主上下文完成的问题，进入 Skill；
3. 需要独立上下文、结论隔离、并行委派或不同权限边界的问题，才考虑 Agent；
4. 不能因为某个流程“看起来专业”就升级为 Agent；
5. 不能因为某个步骤“经常出现”就写入 Rules，若它是流程，应优先判断 Skill；
6. 不能在正式规范中提前创建具体 Skill 清单或 Agent 清单，除非对应对象规范、行动模型或实践文档已稳定支撑。

## 六、参考资料处理原则

本次 04 系列建设以 references/ 中的 Trae Rules、Skill、Agent 机制调研资料作为外部参考，并将前期 AI 协作规范草稿中的可复用判断转入 04 系列正文。04 正式规范不保留对草稿文档的运行时引用，避免形成第二事实源。

1. `references/01` 和 `references/04` 可作为 Trae Rules、Skill、Agent 机制的外部参考，不直接成为强制规则。
2. 前期 AI 协作规范草稿中的通用机制判断已转入 04 系列正文；草稿路径不作为 04 正式规范的依赖引用。
3. PM Kit 专属对象、路径、标准技能清单、推荐 Agent 清单和多角色矩阵不进入 04 正式规范。

多角色讨论和自建 Agent 清单相关判断已被转入“不得在 04 正式规范中创建具体多角色矩阵、不得创建 LDVH 推荐自建 Agent 清单”的边界规则；如未来需要保留完整清单，应作为 70-89 内部调研处理。

## 七、事实源回写原则

Rules、Skill、Agent 运行过程中产生的信息按以下规则处理：

1. Skill 输出、Agent 分析和临时计划默认都是过程信息；
2. 过程信息只有满足 `specs/03-事实源边界与承载规范.md` 的回写要求，并写入对应 Git 文件事实源后，才成为稳定事实；
3. 规则类事实应写入 specs/ 或 `.trae/rules/` 对应规则文件；
4. 结构化生产对象事实应写入 `ldvh-base/` 对应对象目录；
5. 管辖项目资料、报告或审计结果应写入 docs/；
6. 外部资料和第三方参考应写入 references/，不得直接作为 LDVH 强制规则；
7. Skill 或 Agent 的输出不得与 Git 文件事实源并行维护同一稳定事实。

## 八、Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 新增、删除、重命名或改变 04 系列规范编号和职责分工；
2. 创建、修改、删除或启用/禁用规则、Skill 或 Agent；
3. 调整 Agent 权限、可写文件范围、网络访问范围或可调用范围；
4. 将外部参考、Agent 输出、Skill 输出或工具缓存提升为稳定事实；
5. 在 04 正式规范中新增具体 LDVH 标准 Skill 清单、自建 Agent 推荐清单或多角色矩阵；
6. 改变 Rules、Skill、Agent 与 LDVH 事实源边界、生产对象或行动模型之间的职责关系。

04 系列一致性检查至少包括：

| 检查项 | 标准 |
|---|---|
| 机制范围 | 04 系列只治理 Rules、Skill、Agent 三类机制 |
| 选择边界 | 三者对比选择规则只在本文维护 |
| 子文档分工 | Rules、Skill、Agent 分别进入对应子文档 |
| 事实源回写 | 稳定事实必须回写 Git 文件事实源 |
| 参考边界 | 外部参考和 PM Kit 资料未直接成为 LDVH 强制规则 |
| PM Kit 去专属化 | 未迁移 PM Kit 专属路径、标准 Skill 清单或推荐 Agent 清单 |
| Human Gate | 高影响机制变更已识别并说明确认要求 |
