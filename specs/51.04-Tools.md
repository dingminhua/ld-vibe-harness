## 二、当前状态

本文当前作为规范准备文档，记录未来工具可提供的能力定义。当前阶段不实现程序化工具，主上下文轻量模式和多角色子 Agent 模式均可由 AI 直接读取规范后执行，不需要工具辅助。

---

## 三、未来工具能力定义

当项目具备 MCP Server 或脚本基础设施后，可考虑实现以下工具能力：

### 3.1 Context 包生成

- 输入：分析主题、变更类型、影响范围
- 输出：按角色裁剪的最小事实源摘要
- 用途：降低主控为每个子 Agent 构造 context_pack 的成本

### 3.2 角色映射校验

- 输入：选定的角色列表和变更类型
- 输出：校验角色选择是否覆盖必要维度（治理、风险、验证等必选角色是否包含）
- 用途：防止遗漏必选角色

### 3.3 报告结构校验

- 输入：多角色报告内容
- 输出：校验报告是否包含 51.06-Contract.md MultiRoleReport 契约的必填字段
- 用途：防止报告缺项

### 3.4 回写候选检查

- 输入：多角色报告的 WriteBackSuggestion
- 输出：校验回写目标是否与事实源边界一致
- 用途：防止回写到错误位置

---

## 四、工具边界

工具不得：

1. 直接决定角色结论；
2. 直接调用 AI、Skill 或 Agent；
3. 将工具缓存或派生视图作为最终事实源；
4. 替代 Human Gate；
5. 修改 51.06-Contract.md 中的角色语义。

---

## 五、实现前提

实现本文定义的工具能力前，应满足：

1. 项目已建立 MCP Server 或脚本基础设施；
2. 多角色思考执行频率足以支撑工具化投入；
3. 工具实现已按 12-LDVH工具基础规范.md 评估 Human Gate；
4. 工具输出不得与 Git 文件事实源并行维护同一稳定事实。

---

## 六、检查项

检查 Tools 辅助是否合规时，应确认：

1. 工具是否未直接决定角色结论；
2. 工具是否未将缓存或派生视图作为最终事实源；
3. 工具是否未替代 Human Gate；
4. 工具输出是否能追溯到 51.06-Contract.md 契约字段和 Git 文件事实源。
