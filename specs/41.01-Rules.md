## 一、本文定位

Rules 在多角色思考中只做一件事：**提供入口提醒和场景触发**。完整的多角色思考 Scenario 识别、执行流程、角色矩阵和报告模板在 41 主文件中，不得搬入 Rules。

---

## 二、核心决策：是否需要在 Rules 中提醒多角色思考

| 项目情况 | 是否需要 Rules | 放置位置 |
|---|---|---|
| 仅在用户明确要求时使用 | 不必 | 无 |
| 频繁做规范/Rules/Skill/Agent/跨模块变更 | 需要 | L1 一句摘要 |
| 有规范重构、高风险操作场景 | 需要 | L2 场景 Rules |
| 希望强制所有任务前都多角色思考 | 不建议 | 会造成过度分析 |

## 三、Rules 内容边界

**可写入：**
- 压缩摘要（1-2 句）+ 指向 41 主文件的引用

**不得写入：**
- 完整 Scenario 识别条件、角色矩阵、报告模板、Agent 调度细节、Skill SOP、长篇背景

## 四、推荐摘要

可在 L1 或 L2 中直接使用的压缩摘要：

```text
复杂变更、规范/Rules/Skill/Agent/工具调整、跨模块影响或高风险操作前，应评估是否进入 41 多角色思考。完整 Scenario、Gate、执行流程和回写要求以 specs/41-multi-role-thinking-多角色思考.md 为准。多角色思考输出默认不是事实源；稳定结论必须按事实源边界回写。Skill 不得调度 Agent；Agent 增强模式仅在相关 Trae 预制 Agent 已安装且可调用时执行，未满足时降级。
```

## 五、Rules 变更门禁

新增、删除、重命名或改变 L0/L1/L2 Rules 文件时，必须暂停确认。不得将多角色思考完整流程复制进 Rules，不得让 Rules 承载 Agent 调度或事实提升。
