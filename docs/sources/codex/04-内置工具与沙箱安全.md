## 1. 结论摘要

Codex CLI 内置 5 个核心工具：shell（执行任意 shell 命令）、apply_patch（结构化多文件 diff 编辑）、update_plan（内部 todo/计划追踪器）、view_image（加载本地图片到对话）和 web_search（内置网络搜索）。沙箱机制采用 OS 内核级隔离（macOS 使用 Apple Seatbelt，Linux 使用 Landlock + seccomp），提供 read-only、workspace-write（默认）和 danger-full-access 三级模式。审批策略支持 untrusted、on-request 和 never 三种。

## 2. 内置工具

| 工具 | 功能 | 说明 |
|------|------|------|
| shell | 执行任意 shell 命令 | 读取文件、写入、搜索、导航、构建、管理进程等 |
| apply_patch | 结构化多文件 diff 编辑 | 用于非平凡的代码编辑；简单写入仍可用 shell heredoc |
| update_plan | 内部 todo/计划追踪器 | 由 Codex 运行时完全管理 |
| view_image | 加载本地图片到对话 | 让模型"看到"图片 |
| web_search | 内置网络搜索 | Codex 自有的搜索能力；也可通过 MCP 回调使用外部搜索 |

## 3. 沙箱机制

### 3.1 三级沙箱模式

| 模式 | 行为 | 适用场景 |
|------|------|----------|
| read-only | 只能读不能写，每个 shell 命令需审批 | 安全探索陌生代码库 |
| workspace-write（默认） | 只能修改当前项目目录 | 日常开发，天然满足事实源边界原则 |
| danger-full-access | 无限制 | 明确的高风险入口，需谨慎使用 |

### 3.2 OS 内核级隔离

| 操作系统 | 隔离机制 |
|----------|----------|
| macOS | Apple Seatbelt（sandbox-exec） |
| Linux | Landlock + seccomp |

AI 无法通过"话术"绕过——比应用层校验更可靠。

### 3.3 网络访问控制

network_access 可配置，可以禁止 AI 在沙箱中访问外部 API。

## 4. 审批策略

| 策略 | 行为 | 适用场景 |
|------|------|----------|
| untrusted | 每次文件写入和命令执行都需人工审批 | 高风险操作 |
| on-request | Codex 自行判断何时需要审批 | 日常开发（推荐） |
| never | 永不审批（全自动） | CI/CD 自动化 |

## 5. TUI 交互式审批

- 每次操作显示 diff
- 用户可确认/拒绝/修改
- 选项：Allow once / Allow for this session / Deny

## 6. 权限配置文件

```toml
# config.toml
default_permissions = ":workspace"    # 默认允许工作区内写入
# default_permissions = ":read-only"  # 只读模式
# default_permissions = ":danger-no-sandbox"  # 无沙箱（危险）
```

也支持自定义权限配置：

```toml
[permissions.my-custom]
# 自定义权限规则
```

## 7. 自动运行模式

| 标志 | 效果 |
|------|------|
| --full-auto | 沙箱内自动批准文件变更 |
| --yolo | 无沙箱，无审批（最快，最危险） |

## 8. 与 Trae 安全机制的关键差异

| 能力 | Trae | Codex CLI |
|------|------|-----------|
| 沙箱隔离 | 应用层校验 | OS 内核级隔离 |
| 审批粒度 | MCP 自动运行 + 命令白/黑名单 | untrusted/on-request/never 三级策略 |
| 网络控制 | 无明确控制 | 可配置 network_access |
| 文件写入范围 | 无明确限制 | workspace-write 限制在项目目录 |
