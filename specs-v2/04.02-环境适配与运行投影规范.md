# 环境适配与运行投影规范

> 创建日期：2026-06-08
> 定位：定义 LDVH v2 如何把规范落地要求和保障机制适配到具体开发环境，形成运行投影，并处理同步、降级和漂移检查
> 适用范围：LDVH 环境适配映射、运行投影同步、规范变更后的环境审计、运行投影漂移检查和环境不支持时的降级记录
> 上位依据：`specs-v2/04-规范落地与环境适配基础规范.md`
> 相关规范：`specs-v2/00-LD-Vibe-Harness理念与纲要.md`、`specs-v2/04.01-规范落地要求规范.md`、`specs-v2/04.03-环境能力承接边界.md`、`specs-v2/04.04-特别说明与豁免.md`、`specs-v2/14-Code实现规范.md`

---
## 1. 本文解决的问题

本文解决 LDVH v2 规范落地要求如何进入具体开发环境的问题。

`specs-v2/04.01-规范落地要求规范.md` 定义正式规范如何声明“要落地需要满足哪些要求”和“由什么保障机制保障”。本文只处理下一层：这些要求和保障机制在 Codex、Trae、Claude Code、Cursor、CI、Web、命令行或其他环境中如何映射成可见入口、可复用流程、子 Agent 调用、Code 检查、Human 交互、生命周期触发和运行投影。

本文不得反向改写正式规范。环境能力不足时，应记录降级方式和残留风险，而不是把规范要求改低。

---
## 2. 与 00 总纲的关系

00 定义开发环境是 LDVH 五类构成要素之一，同时要求 Code、Web、工作模型和工作流程围绕稳定事实源协作。环境适配和运行投影用于让正式规范在具体环境中被 AI、Human 和 Code 看见、调用和检查，但运行投影不是最终事实源。

本文承接以下链路的后两层：

```text
正式规范
→ 规范落地要求
→ 保障机制
→ 环境适配映射
→ 运行投影
```

规范落地要求和保障机制以 `specs-v2/04.01-规范落地要求规范.md` 为准。环境能力如何承接不同要求，以 `specs-v2/04.03-环境能力承接边界.md` 为准。本文只定义环境适配映射和运行投影。

---
## 3. 基本概念

### 3.1 环境

环境是 AI 和 Human 实际执行工作的工具、平台或运行面。环境可以包括 Codex、Trae、Claude Code、Cursor、CI、Web 工作台、命令行或其他被 LDVH 明确纳入适配的执行面。

环境不是规范事实源。环境中的规则、配置、Skill、Agent、Hook、命令、页面和缓存，都只是对 specs-v2 正式规范的运行投影或辅助入口。

### 3.2 环境适配映射

环境适配映射用于说明某项规范落地要求和保障机制，在特定环境中通过哪些机制、文件、配置、命令、工具、页面或降级策略实现。

环境适配映射回答：

1. 当前环境是否支持该落地要求；
2. 支持时映射到哪个环境能力或实体；
3. 调用入口、文件路径、配置位置或命令是什么；
4. 验证方式是什么；
5. 不支持时如何降级，是否需要 Human Gate 或后续任务。

环境适配映射不得反向改写规范本身。

### 3.3 运行投影

运行投影是环境适配映射后实际生成、维护或调用的入口、文件、命令、配置、工具、页面、Skill、Agent、Hook、CI 检查、摘要或降级记录。

运行投影用于帮助 AI 和 Human 在具体环境中执行、看见、检查或同步规范，但运行投影不是最终事实源。运行投影与 specs-v2 正式规范冲突时，以 specs-v2 正式规范为准。

### 3.4 漂移

漂移是指运行投影、环境映射或自动触发方式与 specs-v2 正式规范不一致，或规范已变更但运行投影未同步。

漂移检查可以由 Code、子 Agent 思考、Human Gate 或环境触发能力共同完成。检查结果不是最终事实源；需要保留的结论应回写到正式规范、Task、Memo、ADR、审计报告或其他权威位置。

---
## 4. 环境适配映射规则

环境适配映射应以规范落地要求为输入，不得以某个环境已有能力反向决定规范需要什么要求。

环境适配映射至少说明：

| 字段 | 含义 |
|---|---|
| 环境 | Codex、Trae、Claude Code、Cursor、CI、Web 或其他环境 |
| 落地要求 | 被适配的规范落地要求 |
| 保障机制 | 在该环境中使用的机制组合 |
| 运行投影 | 具体文件、配置、命令、Skill、Agent、Hook、页面或降级记录 |
| 验证方式 | 如何确认运行投影存在、可用、未漂移 |
| 降级方式 | 环境不支持时如何处理 |

不同环境可以用不同方式满足同一要求。例如生命周期触发要求在某些环境中可以映射为 Hook，在 CI 中可以映射为工作流检查，在其他环境中可以映射为规则条件、自动运行、主控流程或人工降级检查。

环境适配映射不得省略降级方式。只要某个环境不支持稳定触发、并行子 Agent、受控写入、Human 交互或其他要求，就必须说明降级检查如何发生。

---
## 5. 运行投影规则

运行投影必须保留权威来源。生成、维护或使用运行投影时，应能追溯到对应 specs-v2 正式规范、规范落地要求和环境适配映射。

运行投影不得承载以下内容：

1. 与 specs-v2 正式规范冲突的规则；
2. 未被正式规范吸收的 evals、refs 或临时判断；
3. 反向改变规范落地要求的环境能力假设；
4. 未经 Human Gate 授权的自动写入或自动覆盖规则；
5. 被当成最终事实源的缓存、摘要、工具输出或页面状态。

运行投影可以承载以下内容：

1. 入口摘要；
2. Skill、Agent、Hook、CI、命令或页面入口；
3. Code 校验命令或测试入口；
4. Human Gate 提示；
5. 降级检查方式；
6. 运行投影与正式规范的版本或路径关联。

---
## 6. 同步与漂移检查

运行投影同步包括初始化同步和规范变更后的增量同步。

初始化同步用于第一次把规范落地要求映射到当前环境。规范变更同步用于在正式规范发生变化后检查对应运行投影是否需要更新。

运行投影出现以下情况时，应视为漂移风险：

1. 正式规范已变化，但入口摘要、Skill、Hook、Code、Web 或 CI 未同步；
2. 运行投影复制旧正文，和 specs-v2 正式规范冲突；
3. Code 校验逻辑与正式规范的检查要求不一致；
4. Web、Skill、Agent 或 Hook 依赖的路径、字段或规则已过期；
5. 环境不支持某落地要求，但没有降级记录；
6. 运行投影被当成事实源反向修改规范。

漂移检查发现问题时，应先判断问题属于规范缺口、环境适配缺口、运行投影过期、Code 实现缺口还是 Human Gate 缺口。不同缺口应回写到对应事实源，不得把检查输出直接提升为规范事实。

---
## 7. 环境能力核验

环境适配前应核验当前环境能力，不得只凭聊天记忆、旧规范或其他项目经验判断。

环境能力核验来源按以下顺序处理：

1. 当前环境的官方文档、平台说明或当前配置；
2. 已纳入文档工作区 refs 的平台资料；
3. 当前项目中实际存在的运行投影、配置、脚本或工具；
4. Human 明确提供的环境约束或授权。

LDVH 正式规范不复制平台教程、参数手册或完整能力清单。平台客观能力和限制应由官方文档、refs 或当前配置承载；LDVH 正式规范只定义自身如何使用、限制、回写和降级这些能力。

当环境能力核验结果与既有运行投影冲突时，应视为运行投影漂移风险。稳定结论应回写到环境适配映射、特别说明与豁免、Task、Memo 或对应正式规范，不得停留在工具输出或对话中。

## 8. 规范落地要求

本文通过以下规范落地要求说明相关要求的同步、检查或审计触发条件。

| 落地要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 上位约束承接要求 | 环境适配映射必须消费 `specs-v2/04.01-规范落地要求规范.md` 定义的规范落地要求和保障机制，不得反向改写正式规范 | 本文 §4-§7、Human Gate、规范文档检查 | 环境治理 | 本文或 04.01 的落地要求类型、字段、保障机制规则变化时 |
| 入口可见要求 | AI 进行环境适配、运行投影同步或漂移检查时应能定位本文作为权威入口 | 规范文档入口摘要、相关规范引用 | AI 执行入口提示 | 本文定位、适用范围、环境适配映射字段或运行投影规则变化时 |
| 确定性执行要求 | 后续 Code 应能检查环境适配映射和运行投影是否缺失、过期或与正式规范冲突 | `tools/specs_validate.py` 扩展、后续漂移检查 Code、正反样例 | 校验实现 | 环境适配映射字段、运行投影字段、漂移检查规则或 Code 消费契约变化时 |
| 生命周期触发要求 | 正式规范、规范落地要求或环境能力变化后，应检查相关运行投影是否需要同步 | 环境触发映射、CI、Skill 流程、Code 检查或人工降级检查 | 触发保障 | 正式规范新增、重命名、删除、规范落地要求变化、环境迁移或运行投影漂移时 |

具体环境剖面待后续补齐。本文只定义通用环境适配和运行投影规则。

## 9. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 允许运行投影成为最终事实源；
2. 改变环境适配映射与正式规范之间的权威边界；
3. 删除某项已被正式规范消费的运行投影；
4. 扩大自动同步、自动写入或自动覆盖运行投影的范围；
5. 允许环境能力不足时不记录降级方式；
6. 将某个具体环境实体提升为所有环境必须满足的全局要求；
7. 将不能机械验证的环境适配判断表述为完整 Code 校验通过。

环境适配与运行投影检查至少包括：

| 检查项 | 标准 |
|---|---|
| 权威来源 | 环境适配映射指向正式规范和规范落地要求 |
| 环境映射 | 具体环境实体只出现在环境适配映射或运行投影中 |
| 事实源边界 | 运行投影未替代 specs-v2 正式规范 |
| 触发边界 | 必须稳定触发的要求未只依赖 Skill 自动调用 |
| Code 适配 | 可机械化检查已按 `specs-v2/14-Code实现规范.md` 判断和验证 |
| 降级处理 | 环境不支持时已记录降级方式和残留风险 |
| 漂移检查 | 规范变更后已检查运行投影是否同步 |
