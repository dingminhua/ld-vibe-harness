# V4 事实对象行动模板准入与边界调查

## 1. 调查对象

本调查不以候选标题或编号为前提，检查两类反复出现的行动责任是否值得由独立普通规范承载：

1. 面对可能需要长期保留的信息时，召回现有事实、判断是否对象化、选择事实类型、核对创建条件与授权、形成草案、受控创建和回读；
2. 面对既有事实对象时，读取当前快照与关系，区分事实更正、普通更新、生命周期变化和多对象承接，按可用原子能力写入、回读并交还。

调查范围包括 00、01、04、05、06、20–24、现有 30、事实 Helper/Code/tests，以及普通求解、现有规范章节、事实对象和 Code 实现等替代承载位置。

## 2. 候选稳定规则

第一类责任准备唯一定义：

1. 创建候选的进入、排除和不确定边界；
2. F0/F1/F2/F3 召回、相邻对象查重、对象化判断和类型选择之间的行动关系；
3. 类型来源、Human Gate、授权、草案准备、受控创建和写后回读的顺序；
4. 已有对象、多对象替代、普通文件和不持久化方向的分流；
5. 创建失败、并发、过期、残留和未证明范围的交还。

第二类责任准备唯一定义：

1. 既有对象变更候选的进入、排除和影响闭包；
2. 更正、普通更新、单对象生命周期变化和多对象承接的分类；
3. 当前快照、CAS 指纹、关系闭包、授权与类型来源之间的行动关系；
4. 单对象 CAS 与多对象原子能力的分流；
5. 关闭、路由、替代或退出时的剩余事实与责任承接；
6. 并发、拒绝、回滚、部分结果、能力缺口和写后回读的交还。

## 3. 已有来源对照与删除项

| 候选内容 | 已有权威 | 调查处置 |
|---|---|---|
| 事实对象共同准入、字段、来源、更新共同边界 | 05 | 不复制；模板只组织何时读取和消费 |
| 五类对象的创建条件、合法初态、状态、阶段、转换、关系、证据与 Gate | 20–24 | 不复制；作为每次行动的领域唯一来源 |
| Helper 共同 envelope 和领域操作参数/结果 | 04、05 | 不复制 API；模板只按实际能力调用 |
| CAS、锁、原子写入、回滚、解析和测试 | Code/tests | 从模板删除实现细节 |
| 单次目标、临时步骤、命令和运行进度 | Human 指令与当次计划 | 不提升为模板规则 |
| Git commit | 03 与 30 | 不并入事实模板；另行授权与组合 |
| 事实对象当前状态和长期证据 | 事实对象及类型来源 | 模板只回写并回读，不创建运行记录 |

移除上述重复后，两类候选仍分别保留稳定进入条件、行动分支、原子范围、失败闭环和交还责任；不是已有领域规则的摘要，也不是 Code API 说明。

## 4. 承载位置比较

| 承载位置 | 结果 |
|---|---|
| 05 或 20–24 的现有章节 | 不适合。它们定义事实语义与领域成立条件；加入可复用行动组织会混淆“什么变化合法”和“如何执行一次变化” |
| 06 的现有章节 | 只能定义所有模板共同规则；写入两类具体分支会使基础规范包含实例并形成行动闭集 |
| 事实对象 | 不适合。对象保存当前事实，不定义规则效力和跨对象通用行动结构 |
| Code/tests | 不适合。可以实现确定性能力，但不能定义对象化、类型选择、授权或语义适用 |
| 普通说明或一次性计划 | 不能提供稳定 key、统一发现入口、来源关系和跨环境复用；相同边界会重复推理 |
| 两份独立具体行动模板规范 | 能分别提供唯一责任、稳定身份、正反场景、失败闭环和退出条件，并共同服从 06 |

两类责任不合并为一份，是因为第一类可以在没有既有目标对象时成立，核心失败是重复建档、选型或创建不成立；第二类必须从既有对象和当前快照出发，核心失败是并发覆盖、非法转换或多对象不一致。它们可以组合，但适用入口和失败闭环独立。

## 5. 正例、反例与相邻边界

### 第一类责任

正例：Human 要求把已成立决定形成 ADR；AI 先召回相邻 ADR，确认没有可无损更新对象，读取 22 的创建条件，取得实际授权，准备草案，受控创建并回读。

反例：Human 只要求解释一个当前文件；内容无需独立身份、状态或证据管理。此时普通求解，不因信息重要就创建事实对象。

失败场景：F1/F2 尚未完成却以“未发现”证明没有重复；candidate ID 被当作预留；WorkCase 缺少工作意图确认；需要 supersedes 却先孤立创建新对象。

### 第二类责任

正例：已有 WorkCase 取得当前计划批准，需要在当前指纹基础上推进 phase；AI 读取完整对象和 21，形成完整快照，通过 CAS 更新并回读。

反例：只需创建一个无承接关系的新 Study。此时由第一类责任判断并创建，不先进入既有对象生命周期变更。

失败场景：用普通内容更新偷渡状态推进；使用旧指纹覆盖并发变化；用多个单对象写入拼接 supersedes；关闭旧对象但没有承接仍适用责任。

## 6. 数量与拆分结论

不按五种事实类型或动作词数量拆分模板。Spark 路由、WorkCase phase/status 推进、普通内容更新、关闭、退出和 ADR/Pitfall/Study 替代的领域规则不同，但行动骨架共享“当前快照—分类—类型来源—授权—原子范围—写入—回读—交还”。关系建立、普通更新、路由、关闭和替代暂不形成独立模板。

直接从 20–24 推导的事实域模板数量为两份：一份承接判定与受控创建，一份承接生命周期变更与承接处置。独立复核、委派与并行执行属于跨领域能力；Git 提交由 30 独立承担，不计入这两份事实域模板。

## 7. V1–V8 价值与成本

两份模板提高 V1 定位、V2 规则与对象共同理解、V3 创建/更新/替代边界识别、V4 原子推进、V5 对失败和未验证范围据实判断、V6 跨会话交还、V7 Human 可理解结果，以及 V8 统一维护行动结构。

新增成本包括两份规范读取、模板候选选择和来源跳转。通过统一 Helper 候选/内容读取、只返回机械候选、AI 按目标选择、模板不复制类型规则，以及将相似动作保留为同一模板分支控制成本。净价值成立的前提，是模板继续保持薄组织层；一旦退化为状态机副本或 API 手册，应缩减或退出。
