# 基础设施工具设计文档格式兼容性调查 Spec

## Why

用户提出"规则上下文路由器 + Context Pack 生成器 + 通用对象校验框架"作为第一优先级基础设施工具，拟以 `docs/` 设计文档承载。需要调查现有文档格式（specs/01、03、12.01）是否支持，并从多视角审查该方案。

## What Changes

- 调查 `docs/` 目录的事实源性质、格式约束和治理要求
- 对比 `docs/` 设计文档 vs. `specs/` 模型实践子文档两种承载方式
- 多视角审查：格式合规、12.01 原则承接、治理与维护、风险
- 输出调查结论和建议

## Impact

- Affected specs: 01、03、04、12.01
- Affected code: 无（纯调查）
- 不涉及任何文件写入或修改

## ADDED Requirements

### Requirement: 格式兼容性调查

系统 SHALL 调查 `docs/` 目录和 `specs/` 模型实践子文档两种承载方式对基础设施工具设计文档的兼容性。

#### Scenario: docs/ 格式兼容性确认

- **WHEN** 调查 `specs/01` §3.4 中 `docs/` 的定义
- **THEN** 明确 `docs/` 的事实源性质（管辖项目文档事实源）、准入条件（不承载 LDVH 基础规范正文）、格式约束（不入 03 的正式规范文档骨架要求）

#### Scenario: 12.01 原则承接确认

- **WHEN** 调查 `specs/12.01` §12 中"具体模块、命令和 API 契约稳定后，进入实现目录或模型实践子文档"
- **THEN** 明确基础设施工具设计文档是否属于 12.01 预期的"实现目录或模型实践子文档"范围

#### Scenario: 多视角审查

- **WHEN** 完成格式调查
- **THEN** 从以下视角输出审查结论：
  - 格式合规视角：文档是否满足对应目录的格式要求
  - 原则承接视角：文档是否与 12.01 原则一致
  - 治理与维护视角：文档的更新触发条件、与 specs/12.01 的同步风险
  - 风险视角：文档错放目录的后果、跨文档不一致风险
