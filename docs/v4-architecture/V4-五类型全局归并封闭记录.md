# V4 五类型全局归并封闭记录

> 记录日期：2026-07-13。本文只记录阶段 4 全局归并 Gate 的审核与验证结果，不取得事实类型、字段或实现定义权。当前规则以 05、`05.Att.01` 与 20–24 为准。

## 1. 结论

Spark、WorkCase、ADR、Pitfall、Study 已按严格串行顺序完成唯一定义来源、统一字段与结构登记、逐类型机械验证和两路独立复核。五类型全局归并又完成跨类型语义、共享字段、状态与关系、来源证据、Code 机械闭包和当前控制面审计；全部 P1/P2 已关闭，两路终审均确认“阶段 4 全局 Gate PASS”。

阶段 4 因此完成。下一步可以规划阶段 5 的共享事实 Schema、读取、校验与受控回写，但本文不授权或证明事实对象 parser/validator、Helper 事实操作、迁移、写入、Web 或环境接入已经实现。

## 2. 最终归并结果

- 当前规则源：14 份 Specs（含根规范）与 4 份授权附件；
- 事实类型：Spark、WorkCase、ADR、Pitfall、Study；
- 统一结构：5 个；
- 统一字段：46 个；
- 全部字段和结构具有唯一稳定 key、位置、定义归口、适用闭集和准入结论；
- 有限共享字段与结构必须恰有一个 promote 来源；
- 五类没有分别恢复 `id/type/created/updated/source/related_*` 等 V3 同义字段；
- 类型定义完成不继承 V3 实例当前性，也不产生事实服务能力。

## 3. 全局审核修正

全局审核及关闭后的字段说明专项复查共关闭三组 P2：

1. Code 原只对字段准入拒绝重复需求和重复结果 key，结构准入可保留并行权威，且有限共享结构缺少单一 promote 来源检查。修正后字段与结构完全对称，并增加重复需求、重复结果、零 promote 和双 promote 失败测试。
2. 推进总纲和 V3 覆盖清单仍保留旧阶段、16 项 Helper 结果、332 tests、12+4 文档以及“首个类型尚未成立”等过期表述。修正后控制面统一使用阶段 4 已完成、18 项、当前 tests 与 14+4 文档，并明确阶段 5 尚未规划或实现。
3. 类型专属字段的详细约束同时出现在“类型字段使用绑定”和“类型专属字段定义”，形成同一类型内部的潜在第二权威。首次修正曾让 required type 字段写 `none`、conditional type 字段只写出现条件；2026-07-14 的继续收敛进一步取消全部绑定中的 `field_path` 和自然语言约束列，统一改为 `field_key + presence + constraint_ref`。无类型差异时写 `inherit`，确有差异时只回指同一类型正文的唯一 H2；路径、JSON 类型和共同定义只能从统一登记派生。Code 和失败测试阻止跨来源、悬空引用及 conditional 无条件归口，AI/Human 继续审核被引用自然语言规则的充分性。
4. 2026-07-14 的外部事实对象审计指出 WorkCase 关闭结果、V3 execution items 去向、Pitfall 经验消费和 Study 时效消费存在可读性或可执行性疑问。回查确认 V3 的 51 次 `pass_with_followups` 是复核状态，作为 WorkCase `closure_outcome` 的次数为零，因此没有恢复该枚举；当前来源改为明确五种关闭结果的互斥条件、逐项规定 execution items 的迁移分流、限制 avoidance 的消费权威，并明确 Study 只有在受影响结论需要超出原观察边界的当前性时才重新观察必要来源。历史 Study URL 用途说明、Pitfall tags 和长 evolution 是否存在未承接价值，保留为阶段 5 代表 fixture 的 Schema 冻结前检查，不凭字段存在直接恢复。

逐类型终审曾发现并修正的字段重复、准入唯一性、关系基数、时间约束、Study limitations 双写和来源时效矩阵等问题，分别保留在五份类型封闭记录中。
