## 1. 价值判断

本文的价值，是让 Human 能通过 Web 看清项目当前状态、来源、风险、证据、未知范围和待决定事项，并让 Web 交互结果回到实际来源和能力，而不是停留在页面状态中。Web 直接服务 Human；Human 据此形成的判断、确认和验收结果再为 AI 提供可继续行动的输入，形成 Web→Human→AI 的价值传递。

本文主要服务：

1. V1 快速定位：让 Human 定位项目、对象、来源和主要信息入口；
2. V2 充分理解：把状态、证据、关系、风险和上下文组织成可以继续阅读的视图；
3. V3 边界识别：区分事实源内容、派生内容、未知范围、Human 待决定事项和实际能力；
4. V5 据实判断：让呈现内容和交互结果不超出当前来源、观察时间和实际回读支持的范围；
5. V6 工作接续：使页面导航、复制和操作结果能够回到项目中稳定保存的信息；
6. V7 清晰沟通：为 Human 的方向校正、决定和验收提供清楚对象、影响、依据和结果；
7. V8 持续积累：使项目已有事实、经验和变化更容易被 Human 发现和复用。

Web 的价值来自清楚、可信和可操作的呈现，不来自增加第二套事实、状态或规则。视觉、组件和交互复杂度只有在提升上述价值时才有纳入基础。

## 2. 规范依据

本文直接依据：

1. `ldvh-root` 对 Web 交互协作交付方式、Web 直接服务 Human、通过 Human 帮助 AI、从相应信息源独立读取、不经 Helper 以及 Web 不属于 Code 的边界；
2. `work-object-governance-scope` 对工作对象、管辖项目和对象范围的定义；
3. `source-of-truth-traceability` 对当前信息、Working Tree、来源回指、派生信息、事实源更新和回读的定义；
4. `fact-model-foundation` 对事实对象共同字段、来源回指、唯一 worktree、确定性发现与受控创建的定义；
5. `spark-fact-type` 对 Spark 准入、合法 `open` 初态、召回与后续语义协调的定义；
6. `code-engineering-practices` 对 Web tests 共同适用的风险驱动测试、同步、质量和证据边界要求；本文只据此约束 Web tests，不把 Web 实现或 Web tests 的物理归属转交给 Code。

本文不重新定义工作对象、事实源、事实类型、规则、Human Gate、验证成立条件或 Code 能力。具体页面使用的事实字段、状态、关系和可写操作，必须来自当时已经生效的具体来源，不能由本规范或 Web 实现提前定义。

## 3. 职责边界

本文负责定义：

1. Web 读取允许范围内当前项目信息的边界；
2. 页面和 API 形成派生内容时的身份、观察时间、过期与来源差异呈现；
3. 事实、证据、风险、未知范围和待确认事项的来源呈现、复制和导航要求；
4. Web 默认只读，以及获得适用授权后请求受控操作的边界；
5. 交互结果、失败、部分完成、回读失败和未完成范围的呈现；
6. Human 操作与 Human Gate、验收、技术验证和完成结论之间的边界；
7. 支持的语言、视口和交互方式下内容身份、来源与主要操作的可识别性；
8. 既有 Web 进行行为保持型重构或有意行为变更时的边界与验证要求。
9. Web 实现与 Web tests 在 LDVH 仓库中的顶层资产归属，以及与 `code/tests/` 中 Code tests 的位置边界。

本文不定义：

1. 具体事实类型、字段、状态、关系、规则或行动模板；
2. 除本文明确的 Web 顶层资产归属外，Web API 路由、内部 DTO、组件、CSS、图标、布局、内部目录、框架或构建工具；
3. Helper CLI 请求和响应；Web 不通过 Helper 服务 Human；
4. Code 内部模块、解析算法、Schema 实现和 `code/tests/` 中的 Code 测试文件；
5. 认证、远程多用户部署或权限系统尚未出现的未来设计；
6. 当前 `web/` 已经符合当前规范或应该原样长期保留的结论。

## 4. 适用范围

本文适用于：

1. Web 页面和 Web API 读取、聚合、筛选、排序和呈现项目信息；
2. Web 缓存、索引、摘要、计数、标签、趋势或其它派生内容；
3. 来源导航、复制、扩展阅读、空态、错误和未知范围呈现；
4. 表单、按钮、确认、验收、状态修改或其它可能请求改变项目内容的交互；
5. 多语言、响应式、键盘和辅助技术支持范围；
6. 既有 Web 的实现整治、行为保持型重构与有意行为变更。

Web 内部开发说明和设计文档只有在说明实现时受本文约束；它们不因记录了现状而取得规则或事实定义权威。

### 4.1 Web 与 Web tests 的仓库位置

在 LDVH 仓库中，承载 00 所定义交互呈现职责的 Web 实现统一位于根级 `web/`；Web API、页面、组件、样式、设计实现以及为 Web 服务的脚本与配置均归入 Web 实现，不得因具有可执行形态而移入 `code/`。`web/` 内部如何组织由 Web 当前实现设计与实际工具链决定。

Web API、component、E2E、可访问性和响应式测试统一位于 `web/tests/`，不得与 `code/tests/` 中的 Code tests 混放；仓库根目录不设置 `tests/`。Web tests 仍接受 07 的共同测试工程要求，并按本文验证其实际覆盖的 Web 行为。统一测试执行入口可以依次调用 Code 与 Web 测试，但不得因此合并两类测试的维护责任、依赖和结论范围。

## 5. 信息读取与来源范围

### 5.1 读取边界

Web 从实际适用的信息源独立读取，不经过 Helper CLI。读取项目专属信息时必须限定在当次选择且能够由 02 支持的管辖项目和工作对象范围内；无法确定范围时，不得通过目录遍历、名称相似或历史缓存扩大读取。

管辖项目范围的解析（`resolve-governance-scope`）允许 Web 调用 Helper CLI 完成：该解析涉及 Git 身份、链接工作树、符号链接、路径规范化和配置冲突等多层边界判断，在 Web 侧重写存在语义漂移风险。但 Web 必须满足：

1. 对 Helper 返回的管辖范围逐项独立校验（配置状态、范围状态、对象解析、身份证据），不得盲信后直接使用；
2. 校验失败或证据不完整时，如实呈现为范围不可确认，不得降级为目录遍历或名称相似匹配；
3. 范围确定之后的项目内容读取（事实 YAML、文件、Git 信息）仍由 Web 独立读取，不经过 Helper CLI；
4. Helper CLI 只是解析请求的执行通道，其输出不成为页面事实权威。

Web 可以复用由 Code 实现的共享 Schema、纯解析库和只读校验能力，但必须满足：

1. 字段和状态语义仍回到正式来源；
2. Code 输出、内部 DTO、诊断或缓存不成为页面的事实权威；
3. Web 能保留或重建当前呈现所需的来源回指；
4. 共享实现失败时，Web 能如实呈现不可读、部分可读或无法验证范围。

Web 不得为满足页面、筛选或统计需要自行创建事实字段、状态机、对象类型、规则分类或来源优先级。真实产品需要新增这些内容时，先回到正确的规范、事实模型或具体来源进行准入和定义。

### 5.2 当前内容

读取当前项目事实时使用 Working Tree 中的实际内容，包括未提交修改和新文件。当前内容位于适用来源规则允许的位置、满足相应内容规则，并在需要对象化、状态化或证据化管理时满足事实模型，即可作为稳定事实呈现；单个文件的 Git 状态不改变这一判断。条件不足时只能标明为当次可观察信息。不得默认使用 `HEAD`、Index、缓存或上次 API 结果覆盖当前内容。

页面读取显式历史版本时，必须标明仓库、ref 或 commit、对象路径和历史身份；历史视图不得与当前视图混合后统一标记为“当前”。

读取失败、文件正在变化或只能获得部分对象时，Web 应保留已能独立成立的部分，并明确缺失和观察时间，不得以空列表、零计数或旧缓存掩盖失败。

## 6. 派生内容与当前性

Web 可以生成导航、摘要、聚合、计数、排序、筛选、关系视图和视觉编码。这些内容是派生信息，不是事实源，也不因被用户看到或复制而成为稳定事实。

每项可能被误解为当前事实的派生内容必须能够说明：

1. 使用了哪些来源对象和版本；
2. 观察或生成时间；
3. 使用的筛选、范围或转换；
4. 当前来源是否已经变化；
5. 无法读取、未纳入或存在冲突的范围。

来源变化后，派生内容必须重新生成或显著标明过期。`Cache-Control: no-store`、浏览器刷新或请求成功只能说明某项缓存行为，不能单独证明页面与当前来源一致。

Web 检测到派生内容与当前来源不一致时，应优先呈现差异和刷新入口；不得静默选择旧值，也不得把派生结果回写覆盖当前来源以消除差异。

## 7. 面向 Human 的呈现

### 7.1 来源和判断边界

事实、状态、证据、风险、规则、诊断、验证结果和待确认事项在页面中出现时，必须保留能够回到其实际来源的入口。来源入口可以根据场景呈现为项目、对象、文件、规范章节、commit、外部地址或实际命令与观察范围，但不得只显示无法复核的“系统生成”“AI 判断”或颜色标签。

事实对象的对象自有语义字段只能按具体类型来源规定的来源身份呈现；Web 不得因 locator 含有 Human 输入、问题描述或形成背景，就把它重命名、推导或投影为对象不存在的 `intent`、正文、判断或其它事实字段。需要呈现来源内容时仍须保留其来源身份，并与对象当前正文分开。

同一状态码在不同事实类型中出现时，Web 必须按该类型来源的语义和面向 Human 的状态词呈现，不得用通用词表抹平类型差异；例如 20 定义的 Spark `open` 必须显示为“待处理”，不得显示为“未关闭”。Web 只负责显示，不由此改变状态码、状态机或转换。

具体事实类型已经定义面向 Human 的详情阅读投影时，Web 必须按该来源规定的区段顺序、字段身份和中文标题分别呈现实际存在的字段；这些标题只是阅读词，不是新事实字段、派生摘要或字段别名。Web 不得用全局字段词表、历史文案或实现方便替代类型来源的标题，不得将多个字段并入一段、补造缺失区段，或从标题、关系、Git 历史和其它材料推断字段内容。视觉样式与交互仍由 Web 实现负责，但不得改变该投影的语义分工。

Spark 阅读中的“关联”呈现正式事实对象关系及可供继续阅读的项目内文档；不得把原始输入归类为“外部资料与输入”塞入关联区，也不得因 `repository-path` 一律伪装为“文档”。项目内文档必须是实际面向阅读的项目文档；代码、测试、构建产物、配置、运行观察和其它非文档文件不得进入 Spark 的关联区。对象自有语义字段与自然语言说明不自动生成“来源”或“证据”阅读区，也不得把代码、测试或运行观察重复投影为 Spark 的扩展阅读。普通 AI 创建或后续 AI 更新确认原始 Human 输入仍是理解 Spark 形成原因的关键上下文时，首条 `evolution` 必须直接说明它。页面不得把原话改名为 `intent` 或替代当前摘要。Spark 不另建“扩展阅读”区；关联是唯一的附加阅读入口。

Spark 详情必须把对象实际存在的 `intent`、当前 `summary` 和 `evolution` 分别呈现为可识别区段；每项 `evolution` 必须直接呈现对象中的 `at` 与 `summary`，不得隐藏、并入摘要、从 Git/更新时间/来源原文重建或补写。对象没有 `evolution` 时，Web 只如实不显示该区段，不得推断“没有发生演变”。`routed` Spark 的分流区只呈现实际 `closed_at` 的日期和时间与 `disposition_summary`；它不重复呈现状态节点，不另设“分流目标”或“分流时间”标签，顶部也不将同一终态时点另作“关闭时间”与更新时间并列。`discarded` Spark 必须以“废弃”而非“分流”呈现其终态处置；同样只呈现实际 `closed_at` 的日期和时间与 `disposition_summary`，不得显示分流、分流目标、分流时间或虚构承接内容。实际 `routed-to` 关系只在 Spark 的“关联”区呈现：名称从当前目标对象的 `title` 读取，不能显示 `object_id` 作为对象名称；目标尚未读到或不可读时如实呈现读取状态，不以编号猜测或替代名称。两种终态记录都应与演变记录使用同一层级的时间与正文卡片组织；Web 不得从任一种终态处置推断新的承接内容。

Study 详情页的摘要层（research_intent、abstract、recommendation_summary）在主内容区呈现，完整 Markdown 正文默认在侧栏阅读面板中打开，实现渐进阅读。正文以独立的阅读面板承载，使 Human 可同时看到主内容区的摘要和侧栏的正交结构、标题和正文结构。正文的 Markdown 标题、列表、表格和链接必须忠实渲染，保持源文的段落、编号、嵌套关系和语义分组结构。

事实对象文本字段通过 Markdown 语法明确表达段落、强调式分组标签、小标题、编号、无序列表或嵌套关系时，Web 必须忠实渲染源文已经表达的结构，并保持这些结构可被 Human 扫描识别；编号与无序列表的选择同样保持源文原义，Web 不得相互替换。语义上类似标签但没有 Markdown 标记的普通文本仍按普通段落呈现；Web 不得根据文本含义自动猜测、补写或重写结构，不得擅自把普通文本提升为标签或标题、合并或拆分段落、重新编号、生成列表或套用统一文章骨架。结构选择属于事实内容形成责任，不属于 Web 派生责任。

Web 消费**精确事实读取结果**时，必须保留其中已有的 `canonical_path`、`carrier` 与 `check_status` 作为源元数据；它们不是对象字段、Web 新事实或独立 DTO 定义。候选发现卡不承诺这些元数据或正文；需要打开对象预览、复制源路径或阅读正文时，Web 必须先对该稳定事实引用取得精确读取结果。`canonical_path` 存在时，任何实现内部的 `path` 投影、对象路径复制和来源定位都必须等于它，不得以 `object_id`、路由 `target`、列表键或其它导航值替代。`target` 只可作为导航/控制定位信息，不能充当源文件路径。`canonical_path` 缺失时，页面可以如实显示路径不可用，但不得复制或显示对象 ID 假装是文件路径。

05 定义的 `canonical_path` 只是预期权威位置，不单独证明文件存在、可读或机械有效。只有 `check_status` 表明精确读取已取得可消费对象和正文时，页面才可把它作为正文来源进入详情或深入阅读；`invalid`、`not_found` 或 `unavailable` 时，页面只能以“预期位置”连同实际读取状态、问题和未读取范围呈现，不能渲染、拼装或暗示已经读到正文，也不能从无效内容推断对象状态。

已知事实正文的内容格式必须由返回的 `carrier` 或其类型来源规定的载体解释，而不是由 `canonical_path` 后缀、对象 ID 或路由猜测。声明为 Markdown 的正文及其深入阅读预览必须渲染 Markdown 的标题、列表、表格和链接；不得因路径投影缺失或文件名没有 `.md` 而退化为原样 `##`、`|` 等标记文本。无法取得已知正文的载体信息时，必须呈现来源/读取范围不可确定，而不是静默选择另一种格式或伪造正文结构。

页面必须区分：

1. 当前事实源内容；
2. Web 派生内容；
3. Code 或测试产生的当次诊断与结果；
4. Human 当前输入或待决定事项；
5. 尚未读取、无法判断或尚未验证的范围。

风险颜色、徽标、计数、排序、筛选、空态和成功提示都只是呈现手段，不得替代上述身份和来源。

### 7.2 导航、扩展阅读与复制

摘要、列表、详情和扩展阅读必须指向同一来源对象或清楚说明转换关系，不得由不同页面各自维护互相冲突的内容副本。

复制事实、证据、规则或诊断时，应在不妨碍正常使用的前提下保留对象身份和来源信息；复制派生摘要时必须能够识别其为派生内容。来源受限或包含敏感内容时，只复制允许范围，并说明省略部分。

### 7.3 支持范围内的可识别性

在产品声明支持的语言、视口和交互方式下，用户必须能够识别页面身份、信息来源、当前/历史或过期状态、主要操作及其结果。对已取得可消费对象的事实详情和对象预览，身份区必须同时可识别地呈现类型、该类型的状态词和稳定 object ID；对无效、缺失或不可用读取则呈现读取状态与未知范围，不得猜测其领域状态。不能只依赖颜色、悬停或单一视觉位置传达关键状态。

具体设计 token、组件和布局留在 `web/docs/` 与实现中。实现可以演进，但不得破坏本文定义的信息身份、来源和操作结果边界。支持范围必须由真实测试证明，不得用设计文档或组件存在代替。

## 8. Web 交互边界

### 8.1 默认只读

Web 默认只读。页面、API 或表单的存在不授予 Web 修改事实源、配置、规范、Git refs、环境或外部系统的权力。

可能改变状态的交互只有同时满足以下条件才能开放：

1. 当前有效来源已经定义目标对象、允许变化、前置条件和验证要求；
2. Human 当前指令已经授权，且适用于该行动的全部来源规则许可条件已经成立；
3. 存在实际可用的 Code 能力承接操作，Web 不自行复制领域写入逻辑；
4. 操作前能够呈现对象、范围、预期变化、依据、风险和失败影响；
5. 操作后能够回读实际目标，并呈现实际变化、失败、部分完成和未完成范围。

具体能力尚未实现或无法回读时，Web 可以呈现说明或交还入口，但不得显示为可完成操作。

### 8.2 禁止 Web 创建 Spark

Web 只读呈现事实对象；不得提供创建、直接捕获、写入或由表单生成 Spark 的入口。

### 8.3 Human 操作的证明边界

点击、提交、选择、确认、取消、暂缓或页面成功状态只证明当次 Web 交互及其实际记录范围。它们不自动证明：

1. Human Gate 已经满足；
2. 技术验证已经通过；
3. 事实源已经成功更新；
4. 环境已经接入或能力可用；
5. 工作已经完成。

只有来源规则明确将 Human 的特定决定作为成立条件，并且 Web 记录能回指决定对象、选项、作用范围和时间时，该记录才能证明相应 Human 决定。技术状态仍须由实际 Code、测试、环境触发或回读证明。

### 8.4 操作结果

受控操作的呈现必须区分：已执行、未发生变化、部分完成、被拒绝、能力不可用、请求无效、执行错误和回读失败。Web 可以使用适合 Human 的文案，但不得把这些结果折叠成笼统的成功或失败。

实际写入与回读不一致时，页面必须以当前来源为准并暴露差异；不得保留乐观 UI 状态冒充写入结果。操作失败后仍然成立的部分结果和残留变化必须保留，不得通过刷新清空。

## 9. 既有 Web 的行为保持与变更边界

Web 可以对内部模块、组件、类型、数据读取、样式组织、构建和测试结构进行整治。行为保持型重构不得改变受当次改动影响的任何既有可观察行为，包括：

1. 视觉、布局、文案、图标和信息层级；
2. 路由、导航、表单、按钮和其它交互流程；
3. Web API 的可观察输入、输出、错误和数据呈现；
4. 响应式布局、加载、空状态、错误状态和部分结果；
5. 键盘操作和既有可访问性行为。

实现规划必须明确当次保持对象、观察范围、已知缺口、实现边界和风险匹配的测试。尚未建立基线或无法由当前依据证明行为保持的范围，必须缩小或暂停受影响重构，同时标明为未验证；不得将“未验证”作为继续重构的替代条件，不得从保持责任中自动排除，也不得仅以构建成功、页面可打开、单一截图或内部类型通过声称外部表现未变。

需要有意改变上述可观察行为时，该工作不再属于行为保持型重构；必须区分行为变更与内部结构变更，同时取得定义该行为的当前来源支持与 Human 对对象、变更前后、作用范围和验收依据的明确决定。

Web API 或前端不得作为事实类型、字段、ID、初始状态和状态转换的定义来源。实际写入必须由具体来源定义契约并由实际 Code 能力执行，Web 只请求操作并呈现回读结果。

## 11. Human Gate

以下事项必须进入 Human Gate：

1. 改变 Web 直接服务 Human、独立读取或不经过 Helper 的上位关系；
2. 新增、扩大或移除 Web 可能改变项目状态的能力；
3. 允许 Web 页面、API、DTO 或 Code 输出成为事实、字段、状态或规则定义来源；
4. 改变 Web 对 Human 决定对象、选项、影响范围或记录方式，可能改变 Human 原意；
5. 接受无法呈现关键来源、风险、未知范围或回读失败的产品方案；
6. 有意改变任何受当次改动影响的视觉、文案、导航、交互、API、响应式或可访问性行为；
7. 扩大到认证、远程访问或多用户写入等会实质改变安全和授权边界的部署范围。

不改变上述可观察行为的内部组件、模块、类型、数据读取或样式组织重构，不因本文单独进入 Human Gate。

## 12. Stop Conditions

出现以下任一情况时，必须暂停受影响的 Web 呈现、交互或符合性声明：

1. Web 正在越过可支持的工作对象范围读取或暴露项目内容；
2. 页面使用旧缓存、历史版本、Code 输出或内部 DTO 覆盖当前来源，却仍标记为当前事实；
3. Web 派生字段、状态机或对象类型正在反向成为事实或规则定义来源；
4. 关键状态、证据、风险、未知范围或待决定事项无法回到实际来源；
5. 可能改变状态的交互缺少当前来源、授权、实际 Code 能力或操作后回读；
6. 页面点击、成功提示或 Human 输入正在被扩大为 Human Gate、技术验证、环境接入或完成证明；
7. 实际写入失败、部分完成或与回读不一致，却由页面乐观状态掩盖；
8. 既有 Web 没有行为保持或有意变更所需的范围匹配依据，却被声明为未变、已符合、available、verified 或 completed。
9. Web 正在根据事实文本含义自动生成、提升、拆分、合并或重排 Markdown 结构，或者用统一文章骨架覆盖源文结构。
10. Spark 详情隐藏、并入摘要或从 Git、更新时间、来源原文重建对象实际存在的 `evolution`，或者把字段缺失自动呈现为“没有发生演变”。
11. Spark 页面把对象自有语义字段或自然语言说明自动生成“来源”“证据”区，或把代码、测试、构建产物、配置、运行观察等非文档文件仅因 `repository-path`/仓库位置投影进“关联”或扩展阅读。
12. `routed` Spark 在分流区重复状态或“分流时间”标签、把 `closed_at` 显示为“关闭时间”并与顶部更新时间重复，或以与演变不一致的属性表替代终态日期/时间与处置说明。
13. `discarded` Spark 被呈现为“分流”，显示分流目标、分流时间或虚构承接内容，或者复用 routed 的分流文案来解释废弃理由。

暂停范围及不受影响工作的处理按 00 §11 执行。

受影响范围只能在与触发原因对应的条件满足后恢复：读取范围重新可确认，页面已回到当前来源并标明历史或过期内容，派生与来源身份重新分开，来源回指已经补齐，受控操作重新取得来源、授权、Code 能力和回读，交互声明已经缩小，Spark 详情已逐项回读并独立呈现实际存在的 `intent`、`summary` 与 `evolution`，关联只保留正式关系和实际面向阅读的项目文档且没有来源/证据或扩展阅读重复投影，行为保持已取得范围匹配证据，有意变更已取得当前来源支持、Human 明确决定和范围匹配测试，或者 Markdown 源文与渲染结构已经逐项对照且语义推断型转换已经移除。Human 决定或普通行为变更证据不能授权 Web 猜测事实内容结构。
