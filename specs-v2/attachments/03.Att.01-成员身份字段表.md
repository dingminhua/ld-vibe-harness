## 1. 定位

## 2. `v2_action_member` 字段表

`v2_action_member` 字段契约如下。所有集合状态都必须填写成员身份字段；只有 active 成员必须填写可执行锚点、接管关系和能力保障映射。非 active 成员缺少可执行锚点时，必须在成员主文件说明不可执行原因、后续条件、替代入口或清退原因。

| 字段 | 出现要求 | 含义 |
|---|---|---|
| `spec_id` | 必须出现 | 两位成员编号，必须与文件名和 `v2_spec.spec_id` 一致 |

| `name_en` | 必须出现 | 英文名，必须与文件名英文段一致 |
| `name_zh` | 必须出现 | 中文名，必须与文件名中文段一致 |
| `collection_status` | 必须出现 | 集合状态，必须使用 03 正文定义的闭集；本文 §3 只提供字段级辅助说明 |
| `canonical_path` | 必须出现 | 成员主文件路径，必须与真实路径一致 |
| `scenario_anchor` | active 成员必须出现 | Scenario 章节锚点 |
| `context_anchor` | active 成员必须出现 | Context 章节锚点 |
| `gate_anchor` | active 成员必须出现 | Gate 章节锚点 |
| `execution_anchor` | active 成员必须出现 | 执行流程章节锚点 |

## 3. 成员字段闭集

以下闭集从 03 正文承接。若本文与 03 正文冲突，以 03 正文为准；本文不得单独增删或改变集合状态含义。

| 字段 | 允许值 | 含义 |
|---|---|---|
| `kind` | `action_process` | 行动编排成员 |
| `collection_status` | `active` | 已是当前 active 行动编排集合成员；v2 未切换前必须能回指 active v1 成员主文件 |
| `collection_status` | `planned` | 已有明确规划和编号意向，但尚未形成可执行成员主文件 |
| `collection_status` | `candidate` | 候选行动编排，概念或草案仍需论证 |
| `collection_status` | `reserved` | 编号预留，不得被解释为已存在行动编排 |
| `collection_status` | `removed` | 已移除或清退，不得作为当前流程入口 |
| `collection_status` | `deprecated` | 已废弃或被替代，必须说明替代入口或关闭理由 |

## 4. 接管与能力映射字段辅助说明

`assurance_takeover` 只登记行动编排接管关系的最小机器可读索引，不替代正文接管说明。每一项应能表达：

```text
source_spec=specs-v2/NN-xxx.md; requirement=保障要求名称或锚点; scope=接管范围摘要
```

`capability_assets` 只登记行动编排对能力保障的需求和当前映射，不替代 06 定义的运行时扩展承载物自描述。每一项应能表达：

```text
type=rule|skill|agent|hook|code|web|ci|command|environment; path=相对路径或能力标识; purpose=保障目的摘要; status=required|optional|degraded|planned
```

`capability_assets.status` 只说明该能力在本行动编排中的保障需求状态，不说明能力资产自身是否 active、是否部署、是否完整支持某环境。固定 Rules、Skill、Agent 或 Hook 的资产身份、来源规范、消费场景、输入输出、验证方式、同步触发和废弃规则由 06 及对应承载物自描述承接。
