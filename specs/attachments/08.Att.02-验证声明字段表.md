## 1. 定位

本文承载 08 授权的验证声明字段。

## 2. 字段表

| 字段 | 要求 |
|---|---|
| 验证目标 | 说明本次验证覆盖的变更、规则或风险 |
| 验证方式 | 自动化测试、命令校验、等价验证、Human 验收或回归验证 |
| 验证入口 | 命令、测试文件、页面、API、人工检查步骤或 Human 确认记录 |
| 输入范围 | 说明样例、事实源路径、对象范围、版本或环境范围 |
| 关键输出 | 说明退出状态、关键摘要、失败前表现、通过条件或人工观察 |
| 结论 | 通过、失败、未运行、部分覆盖或等价验证 |
| 残留风险 | 未覆盖范围、无法自动化原因、环境限制或后续补齐位置 |
| 证据回指 | 回指命令输出、测试入口、事实源、截图说明、Human 记录或提交记录 |

命令清单不是验证结论。验证声明必须把“运行了什么”和“由此能证明什么、不能证明什么”分开表达。

## 3. 完整验证条件

声称完整验证时，验证声明必须同时满足：

1. 验证目标与本次变更范围匹配；
2. 验证入口可复现；
3. 输入范围明确；
4. 关键输出或通过条件明确；
5. 未覆盖范围已经写入残留风险；
6. 证据能回指命令、测试、事实源或 Human 记录。

只运行局部测试、只做人工阅读、只跑格式检查或只看工具输出时，不得写成完整验证。

## 4. 禁止写法

以下写法不得作为验证声明：

1. 只列命令，不写结论；
2. 未运行测试但暗示已验证；
3. 把局部测试通过写成完整验证；
4. 把工具无报错写成 Human 已确认；
5. 把“看起来正确”写成验证结论。
