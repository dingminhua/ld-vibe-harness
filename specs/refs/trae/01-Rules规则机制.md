# Trae Rules 规则机制

## 1. 结论摘要

Trae Rules 支持全局规则和项目规则两级体系：全局规则基于个人习惯在所有项目中生效，项目规则仅在所配置项目中生效。项目规则有 4 种生效方式（始终生效、指定文件生效、智能生效、手动触发生效），通过 `alwaysApply`、`globs`、`description` 等字段控制。规则目录至多支持 3 层嵌套，子目录下的 `.trae/rules/` 在相关文件被读取/提及时自动生效。SOLO 独立端仅支持全局规则，项目规则需通过 AGENTS.md 替代。

## 2. 官方定位

规则（Rules）用于规范 AI 在 Trae 内的行为，包括代码风格、语言与框架、交互方式等，使 AI 的输出更符合个人偏好和项目要求。

主要应用场景：提升效率（可复用配置减少沟通成本）、统一标准（团队规范结构化）、保障质量（明确核心约束避免常见错误）。

## 3. 规则类型

| 类型 | 描述 |
|---|---|
| 全局规则 | 基于个人使用习惯为 AI 定制，在所有项目中生效。示例：语言风格偏好、操作系统适配、内容深度、交互方式 |
| 项目规则 | 针对当前项目 AI 需遵循的规则，仅在所配置的项目中生效。示例：代码风格、语言与框架、API 限定 |

## 4. 项目规则生效方式

项目规则支持 4 种生效方式：

| 生效方式 | 描述 | 属性设置 |
|---|---|---|
| 始终生效 | 在当前项目下所有 AI 对话中生效 | `alwaysApply: true` |
| 指定文件生效 | 仅在匹配 globs 字段指定文件时生效 | `alwaysApply: false`，需配置 `globs` 字段（如 `*.js`、`src/**/*.ts`，多个用逗号分隔） |
| 智能生效 | AI 根据 description 字段判断相关性并决定是否使用 | `alwaysApply: false`，需配置 `description` 字段（描述适用场景） |
| 手动触发生效 | 仅在对话中使用 `#Rule` 提及某规则时才生效 | `alwaysApply: false` |

`#Rule` 优先级最高：对于"指定文件生效"或"智能生效"的规则，若通过 `#Rule` 提及，AI 也会在本次对话中使用。

## 5. 多层规则嵌套

当项目根目录规则较多时，可在 `.trae/rules/` 目录下创建子文件夹归类。系统自动递归读取，至多支持 **3 层嵌套**。

```
.trae/rules/
├── global-rules.md
├── module-a/              # 第 1 层
│   ├── rules-a.md
│   └── submodule-a1/      # 第 2 层
│       └── rules-a1.md
│       └── submodule-a2-b1/ # 第 3 层（最深可识别）
│           └── rules-a2-b1.md
│           └── submodule-a2-b1-c1/ # 第 4 层（无法识别）
└── module-b/
    └── rules-b.md
```

## 6. 子目录规则

Trae 支持读取项目中任意子目录下的 `.trae/rules/` 文件夹。当对话提及该目录下文件或 AI 读取该目录下文件时，系统自动携带并应用该目录下的专属规则。

```
my-project/
├── .trae/rules/              # 项目根目录规则
├── frontend-module/
│   ├── AGENTS.md             # 仅 frontend-module 相关文件被读取/提及时生效
│   └── .trae/rules/          # 仅 frontend-module 相关文件被读取/提及时生效
└── backend-module/
    └── .trae/rules/          # 仅 backend-module 相关文件被读取/提及时生效
```

## 7. AGENTS.md / CLAUDE.md 兼容性

- **AGENTS.md**：位于项目根目录的轻量级 Markdown 文件，向 AI 提供行为指引。定义的规则为项目级，仅在当前项目中生效。可在其他支持 AGENTS.md 的 IDE 中复用。
- **CLAUDE.md / CLAUDE.local.md**：Trae 兼容这两个文件。从 Claude Code 导入项目时会被一并导入。
- 生效方式：需在 设置 > 规则 > 导入设置 中打开"将 AGENTS.md 包含在上下文中"和"将 CLAUDE.md 包含在上下文中"开关。

## 8. Git Commit Message 规则

Trae 支持为 AI 生成的提交内容设置规则，使用 `scene: git_message` 字段配置。

- `scene: git_message` 与 `alwaysApply`、`description`、`globs` 等字段兼容
- 只要规则文件包含该字段，AI 生成提交内容时都会遵循，不受其他字段配置影响
- 多个规则文件均包含 `scene: git_message` 时，AI 同时遵循所有规则

配置方式：

```markdown
---
scene: git_message
---
正文：生成提交内容时应遵守的规范
```

也可通过 源代码管理面板 > 配置提交信息生成规则 自动生成 `.trae/rules/git-commit-message.md` 文件。

## 9. SOLO 独立端规则

SOLO 独立端与 IDE 模式在规则上的差异：

- **仅支持全局规则**：SOLO 独立端目前仅支持全局规则，不支持项目规则
- **AGENTS.md 替代项目规则**：通过 AGENTS.md 文件提供项目级行为指引（仅桌面版支持）
- **运行环境区分**：规则可区分本地/云端环境，本地规则仅对桌面版本地任务生效，云端规则对网页版和桌面版云端任务生效
- **CLAUDE.md 兼容**：同样兼容 CLAUDE.md 和 CLAUDE.local.md（仅桌面版）

## 10. 最佳实践

官方文档给出的 Rules 最佳实践包括：

- 控制单条规则内容粒度，避免一条规则包含过多信息，保持清晰、聚焦、易于理解
- 各条规则之间不得彼此冲突或相互覆盖
- 指定文件路径时使用相对于项目根目录的相对路径，以确保 AI 能准确定位文件
- 引用规则时优先选择与当前对话或任务强相关的规则
- 新建或修改规则后建议开启全新对话再使用，避免历史上下文与新规则冲突
- 若项目已有大量不符合规范的代码，模型可能沿用现有风格而非遵循新规则。建议：明确说明当前任务为“重构”、在特定场景强制要求 AI 遵循新规则、启动专门重构项目逐步提升代码质量

官方博客补充的 Rules 实践要点包括：

1. 规则本质上是提示词，应清楚具体地描述 AI 需要执行的行为，避免使用模型难以绑定到实际操作的模糊概念；
2. 团队最佳实践可以从既有团队文档、项目结构和开源项目规则中提炼，但规则稳定后不宜频繁变更，团队场景下修改前应先达成共识；
3. 规则适合承载所有 Agent 都应遵守的项目标准或个人偏好，单个 Agent 专属提示词不应放入共享规则；
4. 路径引用应写完整的项目相对路径，避免只写文件名导致 AI 查找错误；
5. 规则冲突会降低遵循效果，用户输入、Agent 提示词、用户规则和项目规则之间存在优先级差异；
6. 规则修改后若历史对话仍受旧上下文影响，开启新对话是推荐处理方式；
7. 当项目既有代码大量不符合新规则时，应明确声明当前任务是重构或在特定场景强制执行新规则。

## 11. 常见失效原因

Trae 官方博客列出的 Rules 常见失效原因包括：

1. 规则概念不清楚，AI 无法把规则中的词语映射到具体生成行为；
2. 文件路径不是项目根目录相对路径，导致 AI 查找错误；
3. 多层规则之间存在冲突或覆盖；
4. 规则描述依赖侧边栏、Diff、Apply、Reject、Run Command 等界面概念，AI 无法理解；
5. 当前对话历史与新规则冲突；
6. 项目既有代码风格与新规则冲突，模型沿用现有代码风格。
