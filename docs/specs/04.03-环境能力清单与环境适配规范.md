# 环境能力清单与环境适配规范

> 创建日期：2026-06-11
> 定位：定义 LDVH 如何读取环境能力清单，并将 LDVH 能力保障落实到具体环境
> 适用范围：环境能力清单、环境适配字段、Trae Work CN、Codex App、能力输出、适配检查、适配降级、环境扩展和旧 04.06 / 04.07 / 04.08 迁移
> 上位依据：`docs/specs/04-规范落地与环境适配基础规范.md`、`docs/specs/04.02-LDVH能力保障规范.md`
> 参考来源：`docs/research/26-LDVH环境投射技术经验吸收研究.md`

参考来源路径中的历史术语只作为文件名兼容保留。本文正文按 `docs/specs/02-术语规范.md` 使用环境适配、能力输出、适配检查和适配降级。

---
## 1. 本文解决的问题

本文解决 LDVH 如何把能力保障落实到具体环境的问题。

本文使用“环境”口径，不再沿用旧环境分类。当前只覆盖两个环境：

1. Trae Work CN；
2. Codex App。

如果后续需要新增 Cursor、OpenCode、Gemini、Zed、Qwen 或其他环境，AI 应根据本文字段自行调研该环境官方资料、项目 refs 和当前环境证据，形成环境能力清单后再追加环境适配。新增环境不得凭聊天记忆、模型经验或其他项目经验直接声明完整支持。

---
## 2. 环境能力清单边界

环境能力清单是客观输入，不是 LDVH 决策源。

环境能力清单只回答：

1. 环境有哪些可用于入口、流程、工具、触发、确认、校验或回写的能力；
2. 单项环境能力的来源证据是什么；
3. 当前能力是已验证、refs-only、待确认、不可用还是人工降级；
4. 能力有哪些权限、配置、上下文、压缩、安全或持久化限制；
5. 能力不能完整承载 LDVH 能力保障时，该环境应如何适配降级。

环境能力清单不得回答：

1. LDVH 是否应该提供某项能力保障；
2. 正式规范是否需要某项落地要求；
3. 其他环境是否应该降级；
4. 某项候选能力是否已经完成当前用户环境实测；
5. 环境工具输出是否可以替代 Git 文件事实源。

## 3. 环境适配状态

环境适配使用以下状态表达当前环境承载能力保障的方式：

| 适配状态 | 含义 |
|---|---|
| 原生承载 | 环境原生能力可直接承载能力保障，且已有 LDVH 可复用验证证据 |
| 配置适配 | LDVH 通过薄入口、配置、命令、脚本、Hook、Code wrapper 或环境配置形成能力输出，但语义不完全等价 |
| 指令适配 | 环境只能通过 Rules、AGENTS、Prompt、Instructions 或人工提示引导 AI 执行 |
| 人工降级 | 环境缺少对应能力或证据不足，只能人工执行、人工确认或人工记录证据 |
| 仅作参考 | 只作为设计参考或未来候选，不声明当前支持 |
| 待确认 | 尚未读取 refs 或完成实测，不能据此执行完整闭环 |

适配状态不是通过状态，不代表当前用户环境已经安装、启用、配置或验证。42 可以基于当前执行情况派生过程结论，但不得把过程结论回写为环境长期状态。

## 4. 环境适配字段

环境适配采用卡片表达，避免超宽表格。每张卡片至少包含：

| 字段 | 必填 | 含义 |
|---|---|---|
| 适配项 | 是 | 需要适配的环境入口、能力、要求或能力输出类型 |
| LDVH 要求 | 是 | 该适配项要满足的 LDVH 抽象要求 |
| 环境能力清单 | 是 | 当前环境客观能力、限制和证据状态摘要 |
| Trae Work CN 适配方式 | 是 | LDVH 在 Trae 中形成的入口、流程、校验、降级或缺口记录 |
| Codex App 适配方式 | 是 | LDVH 在 Codex App 中形成的入口、流程、校验、降级或缺口记录 |
| 来源 | 是 | specs、refs、research、旧 04.07 / 04.08、官方资料或实测证据；旧 04.08 只作为迁移输入，不自动构成 Codex App 实测证据 |
| 适配检查 | 是 | 如何证明适配未越界、未虚假支持、未把环境能力当成 LDVH 决策 |
| 适配降级 | 是 | 环境不足时如何人工降级或显式执行 |
| 待补齐事项 | 是 | 后续 refs、实测、Task、ADR、Code、Web 或规范事项 |

新增环境时，应在卡片中追加对应环境适配方式，或在结构化派生视图中追加环境字段。新增环境不得删除 Trae 与 Codex 的既有降级和证据边界。

## 5. 最小环境适配矩阵

### 5.1 入口可见

| 字段 | 内容 |
|---|---|
| 适配项 | Entry visibility |
| LDVH 要求 | 环境入口只允许薄引用，不复制正式规范正文，能定位 `../../LDVH-AI-ENTRY.md`、04 系列和 42 |
| 环境能力清单 | Trae 有 Rules / AGENTS / 会话入口候选；Codex App 有项目说明、会话入口或等价指令入口候选；两者均需实测加载、压缩和持久性证据 |
| Trae Work CN 适配方式 | 指令适配 / 配置适配：用户级 Rules、AGENTS 或会话入口指向 `../../LDVH-AI-ENTRY.md`，不在项目内复制规范正文 |
| Codex App 适配方式 | 指令适配 / 待确认：通过 Codex App 可用的项目说明、会话入口或等价指令入口指向 `../../LDVH-AI-ENTRY.md`，具体持久化入口待 refs 和实测确认 |
| 来源 | 04.04、旧 04.07、旧 04.08、`docs/refs/trae/`、Codex App 官方资料或当前实测；旧 04.08 仅作迁移输入 |
| 适配检查 | 检查入口是否真实存在、是否只做薄引用、是否未复制 specs 正文、是否能定位 42 |
| 适配降级 | 入口缺失时，由 Human 在会话中显式要求 AI 读取 `../../LDVH-AI-ENTRY.md` 和相关 specs |
| 待补齐事项 | 补齐 Trae / Codex 真实入口路径、加载顺序和上下文压缩影响 |

### 5.2 Rules / Instructions

| 字段 | 内容 |
|---|---|
| 适配项 | Rules / Instructions |
| LDVH 要求 | Rules 和 Instructions 只做入口、边界、STOP 点和约束摘要，不维护第二事实源 |
| 环境能力清单 | Trae Rules、AGENTS、Skill 描述可作为入口候选；Codex App 项目说明、会话指令或等价入口可作为候选 |
| Trae Work CN 适配方式 | 指令适配：用户级 Rules 或等价入口写薄引用和关键 STOP 点 |
| Codex App 适配方式 | 指令适配 / 待确认：通过 Codex App 可用入口写薄引用和关键 STOP 点，具体机制待 refs 和实测确认 |
| 来源 | 04.02、04.04、旧 04.07、旧 04.08、Trae refs、Codex App refs；旧 04.08 不作为 Codex App 已验证能力依据 |
| 适配检查 | 检查是否复制正式规范正文，是否混淆 research、refs 和正式规范 |
| 适配降级 | 指令入口不可用时，降级为会话显式读取和人工核对 |
| 待补齐事项 | 明确两环境入口优先级、压缩保护和持久性差异 |

### 5.3 Skill / Command

| 字段 | 内容 |
|---|---|
| 适配项 | Skill / Command |
| LDVH 要求 | Skill / Command 只保障流程复用、薄入口、触发说明或显式执行，不替代正式规范和事实源 |
| 环境能力清单 | Trae 有 Skill、Command 候选；Codex App 是否存在稳定流程复用或命令入口，必须以 Codex App refs 和当前实测为准 |
| Trae Work CN 适配方式 | 配置适配 / 指令适配：用 Skill 或 Command 保障重复流程，正文保持薄入口和流程边界 |
| Codex App 适配方式 | 指令适配 / 待确认：仅通过已确认可用的 Codex App 入口或会话步骤表达显式流程；未验证能力不写入适配结论 |
| 来源 | 04.02、04.04、旧 04.07、旧 04.08、Trae refs、Codex App refs；旧 04.08 不作为 Codex App 已验证能力依据 |
| 适配检查 | 检查 Skill / Command 是否越界成为事实源、是否绕过 Human Gate、是否有输入输出和失败处理 |
| 适配降级 | 无稳定能力时由主控 AI 按 specs 手动执行并记录风险 |
| 待补齐事项 | 明确 LDVH 自建 Skill 与环境 Skill、Command 之间的映射 |

### 5.4 Agent / subagent

| 字段 | 内容 |
|---|---|
| 适配项 | Agent / subagent |
| LDVH 要求 | Agent 输出只作为主控输入，稳定结论回写后才生效，不得绕过 Human Gate |
| 环境能力清单 | Trae Agent / 自定义 Agent 候选需实测；Codex App 的 Agent、子任务或等价独立视角能力需 refs 和实测确认 |
| Trae Work CN 适配方式 | 配置适配 / 待确认：复杂问题用 Trae Agent 候选，能力不足时使用主控多视角降级 |
| Codex App 适配方式 | 待确认：若 Codex App 支持 Agent、子任务或等价独立视角能力，输出必须回主控；否则人工降级 |
| 来源 | 04.02、44、旧 04.07、旧 04.08、Trae refs、Codex App refs；旧 04.08 仅作待核对迁移输入 |
| 适配检查 | 检查 Agent 输出是否回到主控或 Human，是否保留证据和边界说明 |
| 适配降级 | Agent 不可用时由主控按 44 进行轻量多角色思考 |
| 待补齐事项 | 补齐两环境 Agent / subagent 最大能力、并发边界和上下文继承证据 |

### 5.5 Hook / lifecycle

| 字段 | 内容 |
|---|---|
| 适配项 | Hook / lifecycle |
| LDVH 要求 | 生命周期触发必须受 Human Gate、事实源和 Code 验证约束；默认不启用静默自动写入 |
| 环境能力清单 | Trae 当前不声明有稳定 Hook 等价能力，主要人工降级；Codex App 是否具备生命周期触发或等价提醒能力需 refs 和实测确认 |
| Trae Work CN 适配方式 | 人工降级：用 42、Command、手动命令或入口 STOP 点触发检查，不声明 Hook 等价完整支持 |
| Codex App 适配方式 | 待确认 / 人工降级：不声明未验证 Hook 能力；如 Codex App 无稳定生命周期触发，则降级为手动检查和会话提醒 |
| 来源 | 04.02、旧 04.07、旧 04.08、Trae 当前 refs、Codex App refs；旧 04.08 仅作待核对迁移输入 |
| 适配检查 | 检查是否自动写入、是否绕过 Human Gate、是否能关闭或降级、是否有 Code 验证 |
| 适配降级 | 默认降级为人工触发、命令校验、CI 手动运行或关闭自动化 |
| 待补齐事项 | 补齐 Codex App 生命周期触发边界和 Trae lifecycle 替代证据 |

### 5.6 Code / CI / 确定性执行

| 字段 | 内容 |
|---|---|
| 适配项 | Code / CI / deterministic checks |
| LDVH 要求 | 可机械检查的规则应进入 Code、测试、CI 或命令验证，不依赖环境语义判断 |
| 环境能力清单 | Trae 可通过终端、命令、内置工具候选执行；Codex App 是否具备确定性执行入口，必须以 Codex App refs 和当前实测为准 |
| Trae Work CN 适配方式 | 配置适配：手动或授权后运行 `python3 tools/specs_validate.py`、测试和相关命令 |
| Codex App 适配方式 | 待确认 / 人工降级：不声明未验证命令能力；如 Codex App 无确定性执行入口，则由 Human 或其他本地环境运行校验命令 |
| 来源 | 07 Code、42、旧 04.07、旧 04.08、Codex App refs 或当前实测；旧 04.08 仅作待核对迁移输入 |
| 适配检查 | 检查命令、退出码、输出、diff、权限和降级记录 |
| 适配降级 | 命令不可运行时进行人工检查并记录 blocked / degraded |
| 待补齐事项 | 补齐环境适配字段级校验、正反样例和 42 消费检查 |

### 5.7 Human Gate

| 字段 | 内容 |
|---|---|
| 适配项 | Human Gate |
| LDVH 要求 | 高影响写入、长期配置、危险权限、事实源变更和完整支持声明前必须暂停确认 |
| 环境能力清单 | Trae 有结构化问询、Plan / Spec、对话确认候选；Codex App 有对话确认、审批提示或等价 Human Gate 候选，具体形态待确认 |
| Trae Work CN 适配方式 | 配置适配：结构化问询、Plan / Spec 确认、命令批准或对话确认 |
| Codex App 适配方式 | 配置适配 / 待确认：使用 Codex App 可用的对话确认、审批提示、diff 展示或等价 Human Gate，不声明未验证权限控制能力 |
| 来源 | 00、04.01、04.02、42、旧 04.07、旧 04.08、Codex App refs 或当前实测；旧 04.08 仅作待核对迁移输入 |
| 适配检查 | 检查确认人、确认范围、风险说明、影响范围和执行前暂停证据 |
| 适配降级 | 缺结构化能力时降级为对话确认并记录证据 |
| 待补齐事项 | 标准化 Trae / Codex Human Gate 证据模板 |

## 6. 新增环境规则

新增环境时，AI 应按以下步骤执行：

1. 明确环境名称、运行形态和适用范围；
2. 读取环境官方文档、项目 refs、已有研究和当前环境证据；
3. 形成环境能力清单，标注已验证、refs-only、待确认、不可用和人工降级；
4. 按本文 §4 字段追加环境适配方式和能力输出；
5. 明确来源、适配检查、适配降级和待补齐事项；
6. 若声明完整支持、新增长期入口、启用自动触发或写入用户配置，必须 Human Gate。

新增环境时不得删除已有环境列，不得把新环境能力反向写成 LDVH 全局要求，不得把其他环境的降级路径当作新环境事实。

## 8. Human Gate 与检查要求

以下情况必须触发 Human Gate：

1. 声明任一环境完整支持 LDVH；
2. 新增或删除环境列；
3. 删除、重命名或改变旧 04.06 / 04.07 / 04.08 职责；
4. 允许缺少适配检查的环境项通过 42；
5. 将某环境能力提升为 LDVH 全局唯一底座；
6. 启用自动 Hook、危险权限、跨工作区写入或长期配置。

检查环境适配矩阵时，应确认：

| 检查项 | 标准 |
|---|---|
| 字段完整 | 每张卡片包含适配项、LDVH 要求、环境能力清单、环境适配方式、来源、检查、降级和待补齐 |
| 环境客观 | 环境能力来自 refs、官方资料或实测证据 |
| 主体正确 | LDVH 提供能力保障，环境只提供客观清单和承载边界 |
| 降级真实 | 不支持或证据不足时明确人工降级和残留风险 |
