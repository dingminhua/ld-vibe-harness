## 3. 任务导航字段

知识地图面向 AI 入口导航时，`nodes` 和 `edges` 不能作为唯一行动输出。Code 必须同时生成以下任务导航字段，供 Rules 入口、AI 审核、行动编排和 Human-facing 摘要消费：

| 对象 | 字段 |
|---|---|
| `navigation` | `task_type`、`start_node`、`resolved_start_node`、`input_scope`、`effective_input_scope`、`layer`、`project_scope`、`result_status`、`issue_causes`、`suggested_action`、`summary` |
| `read_plan[]` | `path`、`node_id`、`title`、`priority`、`role`、`reason`、`source_relation`、`source_refs`，必要时补充 `suggested_sections`、`project_namespace`、`object_id` 或 `field_path` |
| `next_queries[]` | `purpose`、`command`、`input_scope`、`layer`、`start_node`、`reason` |
| `stop_conditions[]` | `condition`、`reason`、`fallback`、`source_refs` |
| `impact_summary` | `node_type_counts`、`relation_type_counts`、`semantic_relation_type_counts`、`omitted_semantic_relation_type_counts`、`affected_specs`、`affected_runtime_extensions`、`affected_fact_objects` |

`read_plan.priority` 至少应能区分 `P0`、`P1`、`P2` 和 `P3`：`P0` 表示任务起点或必须先读的权威原文，`P1` 表示上位依据、父规范、source_specs、Human Gate 或直接影响判断所需原文，`P2` 表示关联上下文、附件、消费方或验证入口，`P3` 表示可选扩展和后续调查。`read_plan.role` 至少应覆盖 `start`、`authority`、`context`、`impact`、`verification` 和 `fallback`。

`result_status` 用于声明当前投影是否足以支撑任务判断；`issue_causes` 用于列出工具不可用、输出不足、输入不足、证据不足、事实冲突或能力缺口等原因；`suggested_action` 用于给出补充查询、退回事实源、创建后续缺口承接对象或触发 Human Gate 的建议。

历史实现输出中的 `degraded` 字段和 `navigation.degraded` 字段仅作为 legacy compatibility 保留。调用方不得把该布尔值解释为可接受方案、关闭结果、Human-facing 主展示态或当前 Schema 的 active 目标字段；新实现应优先写入 `result_status`、`issue_causes` 和 `suggested_action`。

`next_queries` 用于渐进式获取信息，不得鼓励一次性全量上下文注入。若当前 `input_scope` 无法定位 `start_node`，或任务同时涉及 Rules 入口、active specs 和工作对象，Code 应优先提示 `entry_navigation` 或等价组合查询；若工具不可用、输出不足、来源回指缺失或输出与原文冲突，`stop_conditions` 必须提示退回 active specs、事实对象、Rules 入口、07 Git 文件事实源或 Human Gate。

`start_node` 解析优先服务 AI 可复现调用，不以 Human 自然语言搜索为当前 Schema 目标。跨项目事实对象应优先使用带项目命名空间的稳定节点 ID、明确路径或 Code 已能确定唯一性的标题；裸对象 ID、别名、模糊匹配和交互式补全属于后续 Human-facing 查询体验，不得作为当前 Code 投影通过条件。

`impact_summary.relation_type_counts` 只统计当前投影层实际返回的边。为保持渐进读取，entry 层不得因为存在事实对象语义边就展开全量 `consumes`、`validates` 或 `impacts`；但 Code 可以在 `semantic_relation_type_counts` 或 `omitted_semantic_relation_type_counts` 中提示当前范围内可展开的语义边分布，并通过 `next_queries` 引导调用方使用 neighbors 或 expand 查看。语义边摘要只能作为导航提示，不替代节点、边、来源回指或事实对象原文。

## 4. 当前实现边界

当前 `v2-check` 与 `knowledge-map` 已能输出 active specs、runtime extensions 和 governed projects 显式范围内的只读投影目标顶层字段、节点字段、边字段和来源回指。该输出仍是当次 Code 实时投影，不得被称为事实源、缓存或长期运行状态。

历史规范输入不属于当前知识地图验收目标；只有用户显式请求历史范围时，才用诊断、review hints、排除项、`issue_causes` 或 legacy `degraded` 兼容字段暴露当前不支持的历史图谱能力。Web 接入能力短期只作为 05 待办和未来回归线保留，不作为当前 Code 知识地图投影通过条件。Git history 不属于知识地图输入范围，历史追溯使用 Git 原生命令按需展开；Git 配合要求落到真实 commit records，而不是知识地图缓存或派生边。
