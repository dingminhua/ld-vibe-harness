> 文件状态：`active`；当前工作树中的本附件及父规范同时满足 `specification-model-foundation` §6.2 和 §11 的其余条件时，本附件在父规范授权范围内进入 LDVH 当前规则源；是否已经提交不决定当前内容能否生效或被消费。它只承载结构化字段契约，不单独定义管辖语义、适用范围、Human Gate 或 Stop Conditions。

## 配置根字段

| 字段 | 要求 | 含义与边界 |
|---|---|---|
| `governance_instance_name` | 必填非空字符串 | 当前 LDVH 工作区或管理实例的 Human 可读名称；不是外层产品署名，不得写入 `change_log.signature.product_name` 或 `LDVH-Product-Name` |
| `product_description` | 必填非空字符串 | 当前工作区用途说明，不产生项目事实或规则效力 |
| `projects` | 必填列表 | 管辖项目条目；没有登记项目时使用空列表 |
| `default_project_id` | 可选非空字符串；出现时必须精确等于一个 `projects[].id`；`projects=[]` 时不得出现 | Human 界面启动或重置选择时的默认管辖项目；不参与 Git 身份、工作对象管辖判定、当前内容范围或行动授权。旧配置未出现该字段时，Web 只可按配置列表顺序临时回退到首个项目，并应在设置页清楚标记为未显式设置 |

根字段使用闭集，不得增加安装状态、验证状态、环境接入状态、Human Gate 状态或项目事实字段。

## 项目字段

| 字段 | 要求 | 含义与边界 |
|---|---|---|
| `id` | 必填非空字符串；全配置唯一 | 管辖项目稳定 ID，不使用当前编号、路径或分支名代替 |
| `path` | 必填非空字符串；规范化后全配置唯一 | 本地项目登记入口；相对路径以配置文件所在工作区根目录为基准；验证和消费时必须能复核为有效 Git worktree；不替代对象实际 worktree 根 |
| `name` | 可选非空字符串 | Human 可读项目名称 |
| `description` | 可选非空字符串 | 项目用途说明，不替代项目事实 |

项目字段使用闭集。不得加入 `status`、`initialized`、`integrated`、`verified`、`audit_state`、事实源路径或运行时状态。

项目条目不复制 Git common-dir、remote URL、默认分支或当前分支。Code 必须从 `path` 指向的实际 Git worktree 现场读取 Git common-dir，并以当次 Git 结果验证项目身份和配置内唯一性。

## 管辖范围解析结果字段

管辖范围解析结果使用本节定义的单一 JSON object。顶层使用“聚合解析字段”，其中 `object_resolutions` 的成员使用“逐对象解析字段”。顶层、逐对象和下述复用对象均使用字段闭集；不得增加未定义字段，也不得把两个表解释成可以独立返回或互相替代的结果。

### 逐对象解析字段

| 字段 | JSON 类型 | 必填性与空值 | 含义与边界 |
|---|---|---|---|
| `locator_index` | integer | 必填；大于或等于 `0` | 当次输入范围从 `0` 开始的顺序；重复定位符仍使用不同序号 |
| `locator` | string | 必填非空 | 显式输入的原始路径字符串；`cwd` 回退时为当次实际 `cwd` 绝对路径 |
| `resolved_identity` | string 或 null | 必填；能够复核真实路径或预期路径时为绝对路径，否则为 `null` | 当次工作对象解析后的路径身份；不替代实际 Git worktree 根 |
| `identity_evidence` | array | 必填；成员使用 04 附件“来源回指字段”；`governed` 或 `not_governed` 时非空 | 支持路径边界、Git worktree、Git common-dir 或项目匹配的当次可观察依据 |
| `source` | string | 必填；只允许 `explicit_locator` 或 `cwd` | 原始定位输入来自共同请求还是进程实际 `cwd` 回退 |
| `status` | string | 必填；只允许 `governed`、`not_governed` 或 `unknown` | 逐工作对象管辖判定 |
| `governed_project_id` | string 或 null | 必填；`governed` 时为非空 string，其它状态为 `null` | 唯一命中的管辖项目 `id` |
| `registered_project_path` | string 或 null | 必填；`governed` 时为非空绝对路径，其它状态为 `null` | 当前配置中的本地登记入口；不得替代对象实际 worktree 根 |
| `governed_via` | string 或 null | 必填；`governed` 时只允许 `path` 或 `git.common_dir`，其它状态为 `null` | 唯一命中的主要方式 |
| `git_worktree_root` | string 或 null | 必填；能够复核对象位于有效 Git worktree 时为非空绝对路径，否则为 `null` | 当次对象实际所在 Git worktree 根；决定当前内容读取、修改和验证边界 |
| `git_common_dir` | string 或 null | 必填；能够现场复核时为非空绝对路径，否则为 `null` | 当次对象的 Git common-dir；只说明共享本地 Git 仓库关系，不替代 `git_worktree_root` |
| `source_refs` | array | 必填非空；成员使用 04 附件“来源回指字段” | 定位符、配置和逐对象结论的来源回指 |
| `unknown_reason` | string 或 null | 必填；`unknown` 时为非空 string，其它状态为 `null` | 配置、身份、冲突或证据不足的实际原因 |

对象在不穿透 submodule 或其它嵌套 Git worktree 边界的前提下位于 `registered_project_path` 内，并且该路径与 Git common-dir 依据指向同一项目时，`governed_via` 固定为 `path`，同时在 `identity_evidence` 保留 Git 依据。其它 linked worktree 通过唯一 Git common-dir 命中时使用 `git.common_dir`。

### 聚合解析字段

| 字段 | JSON 类型 | 必填性与空值 | 含义与边界 |
|---|---|---|---|
| `workspace_root` | string 或 null | 必填；唯一确认时为非空绝对路径，否则为 `null` | 本次显式选择或从唯一配置路径确认的工作区根 |
| `config_path` | string 或 null | 必填；唯一发现配置文件时为非空绝对路径，否则为 `null` | 本次实际读取的 `LDVH-GOVERNED-PROJECTS.yaml`；冲突候选通过 `source_refs` 分别保留 |
| `config_status` | string | 必填；只允许 `valid`、`missing`、`invalid` 或 `conflict` | 配置文件的领域状态；必需读取操作未执行完成时不伪造本字段结果 |
| `scope_status` | string | 必填；只允许 `governed_single`、`multiple_governed_projects`、`non_governed`、`scope_unknown` 或 `mixed_scope` | `object_resolutions` 当前已完成条目的确定性聚合；外层 `scope` 另行说明请求是否全部完成 |
| `object_resolutions` | array | 必填；成员使用“逐对象解析字段”；按 `locator_index` 升序且不得重复 | 已按契约完成的逐对象解析结果，不得只保留聚合布尔值 |
| `registered_project_candidates` | array | 必填；`config_status=valid` 时包含全部完整有效登记条目并使用“登记项目候选字段”，其它状态为空 | 供 `work-object-governance-scope::8.4 登记项目候选与恢复绑定边界` 所述恢复消费的机械候选；不参与 `scope_status` 或逐对象命中 |
| `source_refs` | array | 必填非空；成员使用 04 附件“来源回指字段” | 工作区根、配置、定位输入和当次观察的来源回指 |

配置、对象身份和项目匹配的未解决缺口统一使用 04 定义的共同响应 `gaps`，不在领域结果中复制。聚合解析结果不得增加与 `scope_status` 重复的顶层 `governed: true/false`，也不得包含行动授权、规则命中、Human Gate 完成、能力可用、环境接入或工作完成字段。

### 登记项目候选字段

`registered_project_candidates[]` 成员使用以下字段闭集：

| 字段 | JSON 类型 | 必填性与空值 | 含义与边界 |
|---|---|---|---|
| `governed_project_id` | string | 必填非空 | 当前有效配置中全局唯一的项目 `id` |
| `registered_project_path` | string | 必填非空绝对路径 | 配置登记入口；不替代其它实际 worktree |
| `git_worktree_root` | string | 必填非空绝对路径 | 从登记入口现场复核的实际 Git worktree 根 |
| `git_common_dir` | string | 必填非空绝对路径 | 从登记入口现场复核的 Git common-dir |
| `source_refs` | array | 必填非空；成员使用 04 附件“来源回指字段” | 支持配置登记与现场 Git 身份的当次来源 |

候选按 `governed_project_id` 的 Unicode code point 顺序排列且不得重复。它只表示当前配置中的完整有效登记候选，不表示输入工作对象命中该项目、恢复已经选定项目、当前任务相关、规则适用或行动获授权。
