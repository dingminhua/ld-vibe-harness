## 1. 本文定位

本文是 `specs/21-ADR-决策记录.md` 的附件型实践子文档（编号 21.05），承接 Web 信息同步实践。本文不是独立事实模型，不得重新定义 ADR 的对象定位、准入条件、状态机、对象关系、Human Gate、字段契约、事实源回写或证据留存。发生冲突时，以 21 主文档和上位基础规范为准。

---

## 2. 当前状态与未来能力定义

本文当前为 active-prep 状态，记录 ADR Web 信息同步的未来能力定义。当前阶段不实现 ADR Web 页面，ADR 列表、查询、统计和校验由 `tools/adr_index.py` 及对话输出满足基本使用需求。

当前所有 ADR Web 能力均为未来能力定义，不表示已存在 `web/` 实现、API 或页面。未来 Web 信息同步只能作为 Git 文件事实源或 Tools 派生输出的读取入口、状态提示或受控编辑入口，不得替代 ADR YAML 实例事实源。

未来如建立 Web 信息同步，可考虑提供以下能力：

1. ADR 列表、状态分布、影响范围和关联对象同步；
2. 待确认 ADR、终态 ADR 和被替代 ADR 的筛选视图；
3. ADR 与 specs、Rules、Task、Memo、Evidence 的关联信息同步；
4. 状态变更操作前的 Human Gate 提示；
5. 基于 Tools 派生结果的只读信息同步或受控编辑入口。

---

## 3. 实现前提和边界约束

实现 ADR Web 信息同步前，应满足：

1. Web 信息同步层事实源边界已由 `specs/12.02-Web展示规范.md` 确认；
2. Web 信息同步输入可追溯到 Git 文件事实源或 Tools 派生输出；
3. Web 不维护与 ADR YAML 实例不一致的权威状态；
4. Web 读取或筛选 ADR 时，应展示 ADR 状态适用提示，不得将 `proposed`、`deprecated`、`superseded` 或 `rejected` 自动呈现为当前执行依据；
5. Web 写入必须调用受控写入能力并遵守 Human Gate；
6. Web 页面不得替代 `ldvh-base/adrs/` 中的 ADR 实例事实源。

---

## 4. 检查项

检查 ADR Web 信息同步准备状态是否合规时，应确认：

1. 当前是否未创建 ADR Web 页面；
2. ADR Web 未来能力是否仅作为派生信息同步或受控入口，不作为事实源；
3. Web 状态是否不会替代 ADR YAML 实例状态；
4. Web 读取或筛选 ADR 时是否保留状态适用提示，未将非 accepted ADR 自动作为当前执行依据；
5. 后续实现 Web 时是否先评估 Human Gate 并记录 Change。
