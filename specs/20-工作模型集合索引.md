## 1. 定位

本文是 20-49 工作模型规范区段的集合索引，服务于 AI 和人在进入具体工作模型规范前快速了解对象清单、编号归属、关系映射、状态和维护边界。

本文不定义对象字段、状态机、验收标准或行动流程。工作模型通用规则以 `specs/07-工作模型基础规范.md` 为准，具体对象规则由 21-49 对应对象规范承载。

---

## 2. 索引范围

20-49 用于承载 LDVH 工作模型规范和生产概念编号：

1. 20 为工作模型集合索引；
2. 21-34 为当前已使用或已预留讨论的生产对象编号，其中并非所有编号都表示应创建独立工作模型；
3. 35-49 为未来新增工作模型或生产概念预留编号。

新增、删除、重命名或重排工作模型编号，应依据 `specs/07-工作模型基础规范.md` 的 Human Gate 要求处理。

## 4. 生产对象边界

当前 20-49 区段不再把所有生产概念都默认视为独立工作模型。生产对象分为三类：

1. **已落地工作模型 / Active fact models**：已有主规范、事实源边界和最低可用契约，可在 Dogfood 中创建实例；
2. **高优先级待落地工作模型 / High-priority planned fact models**：已经确认需要独立对象，但尚未创建主规范；
3. **暂作字段、文档或模板的生产概念 / Deferred concepts**：有生产价值，但目前更适合作为现有对象字段、Markdown 文档、模板或派生视图，不急于创建独立工作模型。

### 4.1 已落地工作模型 / Active fact models

| Object | 中文 | 编号 | 作用 |
|---|---|---|---|
| ADR | 决策记录 | 21 | 记录长期决策、决策依据和适用状态 |
| Change | 变更记录 | 22 | 以 Git commit 承载事实源变更 |
| Pitfall | 踩坑记录 | 23 | 记录已解决且具有复用价值的错误模式和经验 |
| Intent | 意图 | 24 | 记录人的原始目标、成功标准和约束 |
| Task | 任务 | 27 | 记录 AI 可执行工作单元、验收标准和状态 |
| Memo | 备忘 | 25 | 记录尚未任务化但有保留价值的输入、发现和提醒 |
| Profile | 项目画像 | 26 | 记录项目身份、路径映射、项目名册和接入配置 |

### 4.2 高优先级待落地工作模型 / High-priority planned fact models

当前无高优先级待落地工作模型。25 Memo、26 Profile 已落地为精简版规范。

### 4.3 暂作字段、文档或模板的生产概念 / Deferred concepts

| Concept | 中文 | 当前编号 | 当前承载方式 | 升级条件 |
|---|---|---|---|---|
| Risk | 风险 | 31 | 先作为 Task、Memo 或 ADR 字段 | 需要独立状态、负责人、缓解计划、Web 聚合或审计时升级 |
| Dependency | 依赖 | 30 | 先作为 Task 字段，如 `blocked_by`、`blocks`、`relation_type` | 依赖关系本身需要生命周期、证据、负责人或独立审计时升级 |
| Artifact | 产物 | 32 | 先作为 Task 输出字段或被引用结果物路径 | 产物需要版本、状态、归档、权限或多对象复用时升级 |

| Roadmap | 路线图 | 34 | 先作为 Markdown 文档或 evals/17 产品方向入口 | 需要多路线图、阶段状态、完成度统计或 Web 聚合时升级 |

### 4.4 Gstack 参考边界

Gstack 对 LDVH 的参考价值在于流程和产物连续交接，而不是事实对象模型本身。Gstack 中常见的 dependency、checklist、artifact、roadmap 等概念主要通过以下形式承载：

1. Plan、Issue、Backlog item、TODO.md 等文档或外部系统项；
2. Review / QA / Ship 等 Skill 的 section、模板和报告；
3. `tasks-{phase}-{datetime}.jsonl` 这类阶段性 Implementation Tasks 聚合产物；
4. ship sections 中的 tests、test-coverage、plan-completion、review-army、changelog、pr-body 等发布产物；
5. 本地运行时 artifacts、报告、截图、缓存和日志。

因此，LDVH 不应因为 Gstack 中存在某类生产概念，就把它直接升级为 20-49 独立工作模型。是否升级，应回到 `specs/07-工作模型基础规范.md` §6.4 的工作模型准入条件，并优先判断它是否只是现有对象的字段、模板、Markdown 文档或派生视图。

### 4.5 删除、降级与不吸收清单 / Removed, downgraded and non-adopted items

本轮生产对象梳理必须同时记录“要做什么”和“明确不做什么”。以下内容从默认 planned 独立工作模型或默认吸收范围中删除、降级或暂缓：

| Item | 中文 | 处理结论 | 原因 |
|---|---|---|---|
| Evidence | 证据 | removed | 与 Task 职责重叠，Task 可直接引用结果物和记录关闭证据，Evidence 不再作为独立工作模型 |
| TaskSet | 任务集 | removed | 与 Intent 职责重叠，Intent 承接目标、背景、约束、成功标准、关联任务和完成判断，TaskSet 不再作为独立工作模型 |
| Risk | 风险 | 从优先 planned 工作模型降级为字段候选 | 当前更适合挂在 Task、Memo 或 ADR 上；只有风险本身需要状态、负责人、缓解计划或审计时才升级 |
| Dependency | 依赖 | 从优先 planned 工作模型降级为关系字段 | 当前更像 Task 的 `blocked_by`、`blocks`、`relation_type` 等关系属性；不应为了“前置/阻塞”单独建对象 |
| Artifact | 产物 | 从优先 planned 工作模型降级为路径或输出字段 | 当前更适合作为 Task 输出字段或被引用结果物路径；只有需要版本、权限、归档状态或多对象复用时才升级 |
| Checklist | 检查清单 | 从优先 planned 工作模型降级为模板、字段或 Skill section | 当前更适合作为 Task 验收项、执行前后检查模板；执行结果由 Task 记录 |
| Roadmap | 路线图 | 不进入 YAML 工作模型优先队列 | 当前更适合作为 Markdown 产品方向、阶段规划或 evals/17 入口；只有需要多路线图状态、完成度统计或 Web 聚合时再升级 |
| Gstack runtime artifacts | Gstack 运行时产物 | 不直接吸收为 LDVH 权威事实源 | Gstack 的缓存、日志、JSONL、ship sections 可借鉴为流程产物，但不能替代 Git 文件事实源和 Human Gate |
| Browser daemon / remote tunnel | 浏览器守护进程 / 远程隧道 | 当前不吸收 | 与当前 Trae-native、Git 事实源和最小闭环优先原则不匹配 |
| Large role skill set | 大量角色 Skill | 当前不吸收 | 推荐 Agent / Skill 清单只能作为候选池，必须满足 05 §7 / 05 §8 准入条件，不一次性扩张 |
| Auto commit / auto publish / auto merge | 自动提交 / 自动发布 / 自动合并 | 不吸收 | 与 Human Gate、提交纪律和 Change 可追溯要求冲突；提交必须按 `ldvh-commit` Skill 执行 |
| Local hidden state as authority | 本地隐藏状态目录作为权威事实源 | 不吸收 | LDVH 权威事实源仍是 Git 可追踪文件，隐藏目录只能作为缓存或派生状态 |

上述“删除/降级”不表示这些概念没有价值，而是表示它们当前不应占用独立工作模型主规范建设优先级。后续如满足 §6.4 准入条件，应通过 Human Gate 重新评估并更新本文。

## 5. 对象关系

当前工作模型按治理用途分为四类：

| 分类 | 对象 | 关系说明 |
|---|---|---|
| 核心执行实体 | Task / 任务(27) | Task 是最小执行单位；Task 归属 Intent 承载的目标和约束 |
| 意图和入口 | Intent / 意图(24)、Memo / 备忘(25)、Profile / 项目画像(26) | Intent 承载正式目标、约束和关联任务；Memo 承载尚未任务化但有保留价值的信息；Profile 承载项目身份和接入配置 |
| 决策和风险 | ADR / 决策记录(21)、Risk / 风险(31，暂作字段) | ADR 承载已确认决策；Risk 当前先作为字段承载，暂不作为优先工作模型 |
| 支撑和记录 | Change / 变更记录(22)、Pitfall / 踩坑记录(23)、Artifact / 产物(32，暂作字段)、Checklist / 检查清单(33，暂作字段/模板) | Change 承载变更；Pitfall 承载复用经验；Artifact 和 Checklist 暂不独立建模；验证和关闭证据由 Task 直接引用结果物承接 |
| 阶段规划 | Roadmap / 路线图(34，暂作文档) | Roadmap 当前作为 Markdown 产品方向或阶段规划入口，不作为 YAML 工作模型；阶段结果可通过 Task、Change 和 Pitfall 体现 |

对象实例的权威承载位置由 `specs/07-工作模型基础规范.md` 和未来具体对象规范定义。本文只维护对象规范区段的索引关系，不承载对象实例事实。

## 6. Human Gate

以下情况应评估 Human Gate：

1. 新增、删除、重命名或重排 20-49 区段编号；
2. 改变某个编号对应的工作模型归属；
3. 将 35-49 保留编号升级为具体对象规范；
4. 将本文清单中的 planned-high 对象正式创建为具体对象规范；
5. 将 deferred-field 或 deferred-doc 概念升级为独立工作模型；
6. 让本文定义对象字段、状态机、验收标准或行动流程。

---

## 7. 维护说明

1. 新增 21-49 具体对象规范后，应同步更新本文文档清单中的文档名、状态和说明；
2. 对象通用规则变更时，应优先修改 `specs/07-工作模型基础规范.md`，本文只同步索引信息；
3. 对象实例目录、字段和状态稳定后，应在具体对象规范中定义，不在本文维护；
4. 本文变更应按项目规则记录变更（依据 specs/22-Change-变更记录.md）；
5. 本文同时维护对象升级和对象降级结论，避免过时 planned 清单继续推动不必要的工作模型扩张。
