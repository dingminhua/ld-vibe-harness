## 1. 本文定位

本文是 `specs/21-ADR-决策记录.md` 的附件型实践子文档（编号 21.02），承接 Skill 流程实践。本文不是独立事实模型，不得重新定义 ADR 的对象定位、准入条件、状态机、对象关系、Human Gate、字段契约、事实源回写或证据留存。发生冲突时，以 21 主文档和上位基础规范为准。

本文不是 Trae Skill 实体定义，不包含可直接部署的 `SKILL.md` 元数据。后续如创建 `.trae/skills/ldvh-adr/` 实体，应以本文为设计依据，并按 `specs/11.02-Skill机制规范.md` 评估 Human Gate、实体路径和 Change 记录。【暂缓：Change 记录机制待替换，见 L1 规则】

---

## 2. 当前状态与实践目标

本文当前为 active-prep 状态，定义 ADR 读取、创建、升级、推翻和废弃的可复用流程。当前不创建 `.trae/skills/ldvh-adr/` Trae Skill 实体，AI 可在主上下文中读取本文并按流程执行。

保留本文的目标是为 ADR 读取、创建、升级、推翻和废弃提供稳定流程说明，确保 AI 在处理 ADR 时遵循读取适用规则、准入条件、状态机、Human Gate 和事实源回写要求。后续如需创建 Trae Skill 实体，应先确认本文读取流程、写入流程和 21.04-Tools.md 能力声明一致。

---

## 3. 适用场景

1. AI 在修改 specs、Rules、Tools、事实模型边界或处理影响长期执行方式的判断前，需要读取相关 ADR 时；
2. AI 需要判断已读取 ADR 是否可作为当前执行依据时；
3. AI 识别到满足 ADR 准入条件的判断，需要创建 ADR 时；
4. 已有 ADR 需要升级为 specs 或 Rules 时；
5. 已有 ADR 需要被推翻或废弃时。

---

## 4. 实践边界

1. 本实践只约束 ADR 的 Skill 契约式行动流程，不约束 Rules 入口约束、Agent 上下文隔离、Tools 契约式校验与执行或 Web 信息同步；
2. ADR 的完整准入条件、状态机、Human Gate 和字段契约由 21 主文档定义；
3. Skill 流程中涉及的 Human Gate 判断以 21 §7 为准；
4. Skill 负责 ADR 读取、创建、升级、推翻和废弃中的流程性判断、准入说明、适用性判断、Human Gate 编排和写入意图确认；
5. Tools 在授权后承接只读查询、字段校验、状态流转校验、编号生成、受控写入和 Change 记录生成【暂缓：Change 记录机制待替换，见 L1 规则】等可机械化执行动作；
6. AI 在主上下文中执行本文流程时，应优先使用 21.04-Tools.md 声明的对应只读或受控写入能力；只有当 Tools 能力缺失或不适用时，才可按本文和 21 主文档降级为人工读取或人工写入，并记录原因；
7. 本实践不维护 ADR Tools 命令清单和参数说明，具体命令、参数、测试和能力边界由 21.04-Tools.md 承载；
8. 本实践不替代 21 主文档的任何章节。

## 5. 实践内容

### 5.1 ADR 读取与适用判断流程

1. AI 识别当前任务是否需要读取 ADR，典型场景包括修改 specs、Rules、Tools、事实模型边界、处理长期决策问题或检查既有决策冲突；
2. AI 明确读取目标，包括关键词、状态、关联 specs 或 Rules、影响范围、ADR ID 或需要验证的决策主题；
3. AI 优先使用 21.04-Tools.md 声明的只读查询能力读取 ADR；Tools 不可用或不适用时，可直接读取 `ldvh-base/adrs/` 下 ADR YAML 实例；
4. AI 必须根据 ADR 状态判断读取结果适用性：`accepted` 可作为当前执行依据，`proposed` 只作为待确认信息，`deprecated`、`superseded` 和 `rejected` 只作为历史信息；
5. AI 读取 `superseded` 状态 ADR 时，应继续追踪 `superseded_by` 指向的新 ADR；无法追踪时应标记为读取缺口；
6. AI 输出命中的 ADR ID、标题、状态、适用性、与当前任务的关联原因、冲突或缺口；
7. 如读取结果显示缺少决策依据、存在决策冲突、已 accepted ADR 需要修改、推翻、废弃或升级，应转入对应流程并按 21 主文档评估 Human Gate。

### 5.2 ADR 创建流程

1. AI 识别到判断满足 ADR 准入条件（21 §3.3）；
2. AI 输出判断内容、准入条件匹配说明、影响范围和建议初始状态，提示用户确认是否创建 ADR；
3. 用户确认后，AI 调用 21.04-Tools.md 声明的对应受控写入能力创建 ADR YAML 实例，或在 Tools 不可用时按 21 主文档和 21.06-Contract.md 人工写入；
4. ADR 实例写入 `ldvh-base/adrs/adr-{NNNN}-short-title.yaml`，初始状态为 `proposed`；
5. 创建操作应按事实源回写要求记录 Change。【暂缓：Change 记录机制待替换，见 L1 规则】
6. ADR 从 `proposed → accepted` 需另经 Human Gate 确认，并按合法状态流转执行。

### 5.3 ADR 升级流程

1. AI 识别到 ADR 满足升级条件（21 §6.4）；
2. AI 输出升级理由、目标 specs 或 Rules 文件、拟写入规则正文范围和影响范围，提示用户确认；
3. 用户确认后，AI 或人应按目标事实源对应规范完成 specs 或 Rules 正文写入；涉及 Rules 时应回到 11.01，涉及 specs 时应回到 03；
4. ADR 保留原因和背景，不删除；
5. ADR 侧 `related_rules` 字段应记录升级后的规则文件，该回写可由 21.04-Tools.md 声明的对应受控写入能力承接；
6. 升级操作应按事实源回写要求记录 Change。【暂缓：Change 记录机制待替换，见 L1 规则】
7. 升级操作须经 Human Gate 确认。

### 5.4 ADR 推翻流程

1. AI 识别到需要推翻已 accepted ADR；
2. AI 输出推翻原因、替代方案、旧 ADR 影响范围和新 ADR 草案要点，提示用户确认；
3. 用户确认后，AI 调用 21.04-Tools.md 声明的对应受控写入能力创建替代 ADR，或在 Tools 不可用时按 21 主文档和 21.06-Contract.md 人工写入；
4. 新 ADR 初始状态为 `proposed`，并在 `context` 中说明推翻原因；
5. 旧 ADR 状态变更为 `superseded`，`superseded_by` 字段引用新 ADR ID；
6. 推翻操作应按事实源回写要求记录 Change。【暂缓：Change 记录机制待替换，见 L1 规则】
7. 推翻操作须经 Human Gate 确认。

### 5.5 ADR 废弃流程

1. AI 识别到需要废弃已 accepted ADR；
2. AI 输出废弃原因、后续处理和影响范围，提示用户确认；
3. 用户确认后，AI 调用 21.04-Tools.md 声明的对应受控写入能力将 ADR 状态变更为 `deprecated`，或在 Tools 不可用时按 21 主文档和 21.06-Contract.md 人工写入；
4. 在 ADR 的 `consequences` 或 `context` 中补充废弃原因；
5. 废弃操作应按事实源回写要求记录 Change。【暂缓：Change 记录机制待替换，见 L1 规则】
6. 废弃操作须经 Human Gate 确认。

---

## 6. Human Gate

1. 只读查询和适用性判断本身通常不触发 Human Gate；
2. ADR 创建后从 `proposed → accepted` 必须经 Human Gate 确认；
3. ADR 升级为 specs 或 Rules 必须经 Human Gate 确认；
4. ADR 推翻或废弃必须经 Human Gate 确认；
5. AI 不得自行执行任何需要 Human Gate 确认的 ADR 状态变更；
6. 使用 ADR Tools 写入命令时，必须传入显式 Human Gate 确认参数；Tools 不生成授权。

---

## 7. 检查项

检查 ADR Skill 流程是否合规时，应确认：

1. ADR 读取前是否明确读取目标；
2. ADR 读取结果是否按状态区分适用性；
3. 是否只将 `accepted` ADR 作为当前执行依据；
4. ADR 创建时是否检查了准入条件（21 §3.3）；
5. ADR 初始状态是否为 `proposed`，未直接创建为 `accepted`；
6. ADR 状态变更是否合法（21 §5.2）；
7. 需要 Human Gate 的操作是否经用户确认；
8. ADR 推翻时是否创建了新 ADR 并在旧 ADR 中填写 `superseded_by`；
9. 状态变更和规范变更是否按事实源回写要求记录 Change。【暂缓：Change 记录机制待替换，见 L1 规则】
10. 可机械化读取或写入动作是否优先由 ADR Tools 在边界内执行；
11. 使用 ADR Tools 写入命令时是否传入显式 Human Gate 确认参数；
12. AI 是否未自行执行需要 Human Gate 确认的操作。
