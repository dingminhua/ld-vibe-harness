## 1. 定位

本文承载 07 授权的事实源查询、定位和读取粒度核对表。

07 正文定义事实源读取策略；本文只提供核对表，不得替代行动编排的读取步骤、Code 的查询输出 Schema 或知识地图运行时能力。

## 2. 读取策略

AI 查询和读取事实源时，应遵循读取精准原则，避免上下文过载。

| 策略 | 要求 |
|---|---|
| 查询优先于全文读取 | 先使用 Code、搜索工具、索引工具或 Git 查询定位事实源、对象、章节和关系 |
| 定位优先于全文 | 先定位目标段落、对象字段或引用关系，再按行范围读取 |
| 章节锚点 | 先搜索章节标题、对象 ID、字段名或 `§` 锚点，再读取目标段落 |
| 工具辅助查询 | 可使用规范索引、对象列表、对象详情、关键词搜索、状态统计、关联关系、保障要求聚合和环境清单检查定位事实源 |
| 查询输出边界 | 工具输出应能回指事实源类型、权威路径、对象 ID、章节锚点、状态摘要、关联对象、引用关系、诊断信息或建议读取位置 |
| 读取粒度 | 简单事实查询使用定位和行范围读取；跨章节理解任务逐步扩展；完整上下文构建任务才考虑全文读取 |

AI 不得在未定位的情况下全文读取超过 200 行的规范文档。需要超过该范围时，应说明为什么需要完整上下文。

## 3. 辅助核对表

| 核对项 | 标准 |
|---|---|
| 先定位 | 已先查章节、字段、对象 ID 或关系 |
| 范围最小 | 读取范围与任务复杂度匹配 |
| 工具有回指 | 工具输出能回到权威路径、对象 ID 或章节锚点 |
| 不替代事实源 | 工具输出没有替代原文判断 |
| 扩展有理由 | 超过 200 行全文读取有明确原因 |
