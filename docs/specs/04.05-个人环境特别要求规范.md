# 个人环境特别要求规范

> 创建日期：2026-06-11
> 定位：登记当前个人或维护者环境中不应提升为 LDVH 通用规则、但会影响当前执行和验证的特别要求
> 适用范围：LDVH 自身项目当前执行环境、当前个人命令约定、Human 明确授权的临时执行场景
> 上位依据：`docs/specs/04-规范落地与环境适配基础规范.md`、`docs/specs/04.02-LDVH能力保障规范.md`
> 参考来源：旧个人落地特别要求正文，已收口为本文

---

## 1. 本文解决的问题

本文解决个人或当前维护者环境中的特殊约定如何登记和限制的问题。

个人环境特别要求不是 LDVH 通用规范，也不自动进入所有管辖项目。它只用于让 AI 在当前个人执行环境中避免误用命令、路径或环境约定。

如果某项个人环境约定需要影响特定项目，必须由项目自身 README、依赖管理说明、项目事实源或 Human 明确指令确认。本文不得覆盖项目自身约定。

---

## 2. 与环境适配的关系

个人环境特别要求不同于 04.03 的环境适配规范和 04.04 的适配措施：

| 项目 | 04.03 环境适配规范 / 04.04 适配措施实践 | 本文个人环境特别要求 |
|---|---|---|
| 来源 | 环境官方资料、refs、当前配置、实测证据 | 当前个人或维护者环境约定 |
| 作用 | 支持 LDVH 环境适配 | 限制当前执行命令和验证方式 |
| 范围 | 环境级或项目接入级 | 当前个人执行环境 |
| 是否通用 | 可作为环境适配输入 | 不得自动提升为通用规范 |
| 冲突处理 | 由 04.03 和 42 判断降级 | 项目 README、依赖说明和 Human 指令优先 |

## 3. 当前个人环境特别要求

| 编号 | 要求 | 内容 | 适用范围 | 默认效力 | 适用位置 | 风险控制 | 退出条件 |
|---|---|---|---|---|---|---|---|
| PE-01 | Python 解释器命令要求 | AI 执行 Python 工具或脚本时应使用 `python3` 命令，不用 `python` 指代 Python 3；仅限执行场景，不要求文档或规范正文中使用 `python3` 字面量 | 当前个人执行环境 | 启用 | 命令入口、42 流程、人工提醒 | 不替代依赖管理、虚拟环境说明或测试验证 | 若当前环境稳定采用其他解释器入口，应更新本文或对应 Code 使用说明 |
| PE-02 | 统一入口提示要求 | AI 进入当前 LDVH 自身项目、当前工作区级薄入口或当前环境用户级入口展示场景时，首句问候使用固定字面量"Hello，LDVH" | 当前个人执行环境、当前 LDVH 工作区、Human 明确授权的入口展示场景 | 启用 | 工作区规则、环境用户级规则、当前 42 过程报告、人工提醒 | 只作为当前个人环境提示，不作为 LDVH 通用运行纪律或规范正文替代 | 若 Human 取消该问候要求，或后续确认其应成为通用运行纪律，应更新本文并按 04.02 触发 Human Gate |

## 4. 启用与使用规则

PE-01 默认启用。AI 在执行 Python 辅助程序、校验脚本或测试命令时，应使用 `python3`。

PE-02 默认启用。AI 进入当前 LDVH 自身项目、当前工作区级薄入口或当前环境用户级入口展示场景时，首句问候应使用固定字面量"Hello，LDVH"。PE-02 只约束当前个人执行环境和当前入口展示场景，不要求所有管辖项目、所有环境或所有正式规范正文使用该问候。

PE-01 仅限执行场景：AI 在终端、命令入口或 Code 中调用 Python 时应遵守；文档、规范正文、注释或说明文字中不要求使用 `python3` 字面量。

若当前项目 README、依赖管理说明或 Human 明确约定使用其他解释器入口，如虚拟环境、`python` 别名、`uv`、`poetry` 或 `pipenv`，应优先遵守项目约定，并在必要时记录降级方式。

若 Human 明确要求取消、替换或暂停 PE-02 的问候方式，应以 Human 当前指令优先，并在必要时更新本文。

## 5. 新增个人要求规则

新增个人环境特别要求时，应同时满足：

1. 只影响当前个人、维护者或当前执行环境；
2. 不应提升为 LDVH 通用跨环境规则；
3. 需要 AI 在当前执行中持续注意；
4. 可以通过命令入口、Code 使用说明、42 流程或人工提醒形成适配措施；
5. 不覆盖项目自身 README、依赖管理、环境官方文档或 Human 明确指令。

新增要求应包含编号、要求、内容、适用范围、默认效力、适用位置、风险控制和退出条件。

## 6. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 将个人环境要求提升为 LDVH 通用跨环境要求；
2. 改变 PE-01 的默认效力或适用范围；
3. 改变 PE-02 的默认效力、适用范围或将其提升为 LDVH 通用运行纪律；
4. 允许个人环境约定覆盖项目自身依赖管理或命令约定；
5. 删除仍被命令入口、42 流程、入口展示或人工提醒消费的要求；
6. 新增会影响写入位置、权限、密钥、网络、环境长期配置的个人要求。

个人环境特别要求检查至少包括：

| 检查项 | 标准 |
|---|---|
| 适用范围 | 已明确为当前个人执行环境 |
| 默认效力 | 已明确启用、禁用或条件启用 |
| 项目优先 | 项目 README、依赖管理说明和 Human 指令优先于本文 |
| 命令验证 | 当前环境执行前有命令验证或等价验证方式 |
| 非通用化 | 个人环境约定未被写成 LDVH 通用跨环境规则 |
| 退出条件 | 已说明何时更新、删除或迁移该要求 |

## 7. 规范落地要求

| 落地要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 入口可见要求 | AI 执行 Python 工具或脚本时应能定位 PE-01；AI 进入当前 LDVH 入口展示场景时应能定位 PE-02 | 04 父文档、命令入口摘要、入口展示摘要、42 流程或人工提醒 | AI 执行入口提示 | 本文标题、定位、当前登记表、PE-01 或 PE-02 内容变化时 |
| 确定性执行要求 | 当前环境中的 Python 命令调用应可通过实际命令、测试或等价验证确认 | `python3 --version`、工具 `--help`、测试命令或等价验证 | 命令验证 | Python 工具入口、测试命令、依赖管理方式或执行环境变化时 |
| Human 交互要求 | 将个人要求通用化、覆盖项目约定或删除被消费要求前应暂停确认 | Human Gate、对话确认、42 报告 | 个人环境治理确认 | 个人要求影响范围扩大或退出时 |
| 生命周期触发要求 | 当前环境命令约定变化后，应检查本文、命令入口、42 流程或人工提醒是否同步 | 现场检查、命令入口检查、人工降级检查 | 触发保障 | 解释器入口、虚拟环境、依赖管理或运行环境变化时 |

## 8. 待补齐事项

1. 当前登记 PE-01 和 PE-02；未来新增要求时应先判断是否属于项目说明、环境适配、LDVH 运行纪律或个人环境；
2. 若后续 Code 运行时规范稳定定义解释器入口，应评估 PE-01 是否吸收到 07 Code 或继续保留为个人环境要求；
3. 后续应确认个人环境要求是否需要与 Code 运行时解释器入口形成更稳定的校验契约。
