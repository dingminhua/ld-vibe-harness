## 1. 结论摘要

Codex CLI 是 OpenAI 推出的命令行 AI 编程助手，通过 npm 安装，支持 OAuth 和 API Key 两种认证方式。核心命令包括交互式 TUI、单次执行（exec）、代码审查（review）和 MCP 管理。配置采用 TOML 格式，支持系统级、用户级和项目级三层覆盖。默认使用 GPT-5.4 模型，上下文窗口 272K tokens，最大可配置 1M tokens。

## 2. 安装

```bash
npm install -g @openai/codex
```

## 3. 认证

```bash
# OAuth 登录
codex login

# 或使用环境变量
export OPENAI_API_KEY="sk-..."
export CODEX_API_KEY="sk-..."
```

认证文件位置：~/.codex/auth.json

## 4. 核心命令

| 命令 | 说明 |
|------|------|
| codex | 启动交互式 TUI |
| codex exec "prompt" | 单次执行，完成后退出 |
| codex exec resume <session-id> "prompt" | 恢复之前的会话 |
| codex review | 代码审查 |
| codex review --base origin/main | 对比基准分支审查 |
| codex login | OAuth 认证 |
| codex mcp add <name> -- <command> | 添加 MCP Server |
| codex mcp-server | 启动 MCP Server 模式 |
| codex plugin marketplace add openai-curated | 添加插件市场 |
| codex plugin install <name> | 安装插件 |

## 5. 关键命令行参数

| 参数 | 说明 |
|------|------|
| -m <model> | 指定模型（如 -m gpt-5.4） |
| -c 'key="value"' | 覆盖配置 |
| -C <path> | 指定工作目录 |
| -s <sandbox> | 指定沙箱模式（read-only/workspace-write） |
| --full-auto | 沙箱内全自动 |
| --yolo | 无沙箱无审批 |
| --json | JSONL 输出（用于程序化解析） |
| --enable web_search_cached | 启用网络搜索 |

## 6. 配置文件

### 6.1 分层配置

| 层级 | 路径 | 优先级 |
|------|------|--------|
| 系统级 | /etc/codex/config.toml | 最低 |
| 用户级 | ~/.codex/config.toml | 中 |
| 项目级 | .codex/config.toml | 较高 |
| CLI -c 覆盖 | 命令行参数 | 最高 |

### 6.2 config.toml 示例

```toml
# 模型配置
model = "gpt-5.4"
model_context_window = 272000
model_reasoning_effort = "high"  # low / medium / high

# 沙箱配置
default_permissions = ":workspace"
network_access = false

# MCP Server 配置
[mcp_servers.sequential-thinking]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-sequential-thinking"]

# 插件配置
[plugins."github@openai-curated"]
enabled = true
```

## 9. 常见问题

1. **Codex 挂起**：常见原因包括模型 API 停滞、长 prompt、网络问题。检查 ~/.codex/logs/
2. **认证失败**：运行 codex login 刷新 OAuth token
3. **空响应**：检查 stderr 中的错误信息
4. **Git 仓库必须**：Codex 拒绝在非 Git 目录运行。临时任务用 mktemp -d && git init
5. **xhigh 推理强度**：使用约 23 倍 token，可能导致 50+ 分钟挂起
