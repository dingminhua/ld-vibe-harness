## 2. 当前推进方式：主线、subagent 与独立并行开发

本节记录 Human 当前确认的 V4 工作方式，不是正式 Specs，也不把开发环境中的 subagent、新对话、模型或 worktree 定义为 LDVH 架构概念。是否创建新对话，先由任务能否形成真正独立的本地 Git 开发与提交决定，不能为了并行或使用不同模型而反向制造 worktree。

### 2.1 主线责任

主线单线承担：

1. 依据 00 作架构判断和范围取舍；
2. 起草、修改、复核并激活正式 Specs；
3. 定义或修改公共 Schema、Helper 共同契约和跨模块共享接口；
4. 确定并行实现的文件所有权、输入、输出、验收标准和合并顺序；
5. 审核独立提交、处理冲突、完成跨模块集成、完整验证和最终结论。

主线默认使用 `gpt-5.6-sol` 与 `high` 推理强度，不使用 `xhigh` 或 `pro`。正式来源、公共契约和最终结论不得因其它任务已经输出而自动成立。

### 2.2 subagent 使用范围

单线程推进中不需要独立 Git 提交的内部工作使用 subagent，包括：

1. 只读调查与历史证据盘点；
2. 辅助分析、方案比较和 Code 影响分析；
3. 术语审核、表达检查和独立复核；
4. 不需要独立提交、结果直接回到主线上下文的其它内部子任务。

这些工作不创建新对话、不人为建立 worktree，也不要求切换模型。subagent 只提供待主线核对的输入，不修改正式 Specs、公共 Schema、共享接口或最终结论；需要写文件或独立提交时，必须重新判断是否已经满足下一节的全部条件。

### 2.3 新对话、不同模型与 worktree 的准入条件

只有某项工作能够通过独立本地 Git worktree 真正并行开发，并同时满足以下条件，才创建新对话并设置不同模型：

1. 文件修改范围与主线及其它并行实现互斥；
2. 输入、输出和验收标准已经明确；
3. 不依赖主线尚未形成的架构、Specs、公共 Schema 或共享接口决定；
4. 能够独立实现、测试和形成提交，并由主线按明确顺序审核与合并。

一般独立实现可以使用 `gpt-5.6-terra` + `high`；低风险、机械性强且验收确定的独立实现可以使用 `gpt-5.6-luna` + `high`。模型不可用或当次工具不能指定模型时必须报告实际安排。新对话的完成声明只证明其分支结果，不能替代主线审核、合并、完整回归或能力完成声明。

任务不满足任一条件时保持主线单线推进，必要的只读或复核工作交给 subagent。worktree 是已经确认能够独立开发后的隔离手段，不是新对话、模型切换或表面并行的目的。

### 2.4 共同边界与本次修正

无论采用哪种方式，都不得降低 00、当前有效 Specs、Human Gate、Stop Conditions、术语审计和未覆盖范围如实声明的要求。架构不确定、来源冲突、需要 Human 选择或会修改共同维护位置时，受影响范围回到主线。

2026-07-13 Human 明确修正了此前对“多模型并行”的扩大理解：V3 规则读取经验审核、V4 事实类型候选盘点和 L3/L4 Code/tests 影响分析属于只读内部工作，本应使用 subagent，不应创建新对话和 worktree。三项任务已经完成，其结果可以保留为主线输入，但后续不得复用这种执行方式。V4 推进网页原计划能够独立修改 Web 文件、独立测试和提交，因此创建新对话与 worktree 的判断本身合理；Human 后续接受了仓库外临时 HTML 并停止该实现，不形成 V4 Web 功能完成声明。

## 3. V4 全局推进路线与并行边界

V4 不是把 V3 文件和实现复制到新目录，而是按照 00 重新建立规则、事实、行动、确定性能力和 Human 呈现之间的完整工作链路。V3 资产逐项作为历史问题、实践证据和实现参考接受保留、重写、合并、取消或延后判断；只有进入当前规则源、实现、验证和实际接入的范围，才能形成 V4 能力声明。

目标工作链路为：

```text
当前任务与工作对象
→ 解析管辖范围
→ 定位相关规则、事实、状态和能力
→ 展开足够的规则上下文
→ 判断适用要求、Human Gate 和 Stop Conditions
→ 使用适用行动结构和 Code 能力
→ 执行、验证、回写事实源
→ Web 向 Human 呈现状态、风险和证据
→ 后续 AI 从事实源恢复并接续
```

当前已知风险包括：大型页面同时承担数据转换、领域判断和呈现；前后端仍硬编码 V3 类型、字段、状态和目录；部分读取失败可能被空集合或零计数隐藏；Docs/ProjectFiles 存在真实路径、符号链接和允许目录边界风险；Spark 写入没有 V4 来源与受控 Code 能力；小屏没有经真实测试确认的等价导航；lint 债务和 bundle 警告仍在。具体实现文件和历史设计证据由 `web/docs/` 与当前源码承担，不在本文复制。

Web 工作线按以下 Gate 顺序推进：

1. 保持已恢复的 `web/tests/` 和首批 API 特征测试可执行；
2. 在改动受影响页面前补齐范围匹配的页面、路由、交互、错误/空态、复制、i18n、键盘和代表性桌面/窄屏基线；
3. 先为路径穿越、符号链接、部分读取和遗漏报告建立失败测试，再修复高风险读取边界；
4. 在具体事实来源与 Code 受控能力成立前，对 Spark 写入的保留、隔离、替换或重新开放只做调查；可见入口变化进入 Human Gate；
5. 再按纯转换与重复呈现、数据读取层、API 路由、页面和大组件的顺序分批整治；
6. 对实际声明支持的语言、视口、键盘和辅助技术范围补齐证据，未覆盖部分继续标记未验证。

当前 Web 不是活跃实现增量。任何新 Web 增量开始前，必须在本文记录当次保持对象、观察范围、已知缺口、实现边界、模块责任、依赖、风险匹配测试与完成条件。
