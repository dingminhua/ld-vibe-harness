# 环境入口适配与部署规范

> 创建日期：2026-06-13
> 定位：定义各 AI 开发环境如何通过环境入口接入、部署并适配检查 LDVH 能力资产，以及个人环境特别要求如何写入对应环境入口
> 适用范围：环境入口、薄引用、环境适配、部署步骤、适配检查、个人环境特别要求写入、成功条件、失败处理、降级方式、Human Gate
> 上位依据：`specs/04-规范落地与环境适配基础规范.md`、`specs/04.02-LDVH能力资产与落地保障规范.md`、`specs/02-术语规范.md`
> 相关规范：`specs/07-Code确定性执行实现规范.md`、`specs/08-Web信息同步实现规范.md`、`specs/09-事实源边界与承载规范.md`

本文是 AI 帮用户执行环境接入和部署的直接依据。本文不定义 LDVH 能力资产本身，不记录长期用户本地安装状态，不把一次适配检查结果写成环境类型结论，不为个人环境特别要求新增独立事实源。

---

## 1. 本文解决的问题

本文解决以下问题：

1. 某个 AI 开发环境提供哪些环境入口；
2. 这些环境入口如何接入 04.02 定义的 LDVH 能力资产；
3. AI 如何在授权边界内帮助用户执行部署；
4. 部署前、部署后和声明完成前如何执行适配检查；
5. 创建或更新环境入口时，个人环境特别要求如何写入 AI 可见入口；
6. 接入失败、环境不支持、权限不足或证据不足时如何降级或 Human Gate。

用户本地状态不是长期事实源。它只能来自本文定义的适配检查，并由 Code 输出、Web 当前视图、Human Gate 记录、Task、Memo、Pitfall 或 ADR 按性质承载。

## 2. 环境适配字段

每个环境入口适配项至少包含：

| 字段 | 必填 | 含义 |
|---|---|---|
| 环境类型 | 是 | 适用的 AI 开发环境类型 |
| 环境入口 | 是 | 该环境实际读取、加载、调用、触发、配置、展示或执行某类环境能力的位置或机制 |
| 对应 LDVH 能力资产 | 是 | 04.02 中定义的 Rules、Skill、Agent、Hook 或其它能力资产 |
| 接入方式 | 是 | 薄引用、配置、安装、软链、受控复制、人工降级等 |
| 部署步骤 | 是 | AI 如何帮用户接入该资产 |
| 写入权限 | 是 | 是否可自动写入，是否需要 Human Gate |
| 适配检查 | 是 | 如何现场判断接入已生效 |
| 成功条件 | 是 | 满足什么才能声明本次接入有效 |
| 失败处理 | 是 | 缺入口、无权限、不可读、环境不支持时如何处理 |
| 适配降级 | 是 | 无原生入口时如何模拟或人工降级 |
| 禁止声明 | 是 | 哪些情况下不得声明原生完整支持或部署完成 |
| 证据输出 | 是 | 应呈现给 Human 的证据 |
| 证据状态 | 是 | 已验证、待验证、仅参考、待补齐或不适用 |

`docs/sources/` 和外部资料只能作为输入证据或待吸收材料，不能作为 specs 上位依据。正式适配结论必须写成已吸收结论、实测证据摘要、Human Gate 记录引用或待补齐事项。

## 3. 适配状态

| 状态 | 含义 |
|---|---|
| 原生承载 | 环境提供原生入口或机制承载对应能力资产 |
| 配置适配 | 通过配置、安装、路径、软链或等价方式接入 |
| 指令适配 | 通过环境指令、会话提示或薄引用显式引导 |
| 人工降级 | 缺少稳定环境入口，通过人工检查或手动命令替代 |
| 仅作参考 | 当前信息只能作为候选输入，不能声明可用 |
| 待确认 | 缺少来源证据、实测证据或 Human Gate 确认 |

适配状态不是用户本地安装状态，也不表示当前机器已经部署成功。

## 4. 部署与适配检查规则

### 4.1 部署前检查

部署前必须确认当前环境类型、当前工作区和目标项目边界、环境入口是否存在、目标 LDVH 能力资产是否存在、是否有写入权限、是否存在用户已有配置需要保护、是否存在需要写入对应环境入口的个人环境特别要求、是否触发 Human Gate。

### 4.2 部署执行

部署执行应优先使用薄引用、配置、软链或安装方式。只有在环境明确无法引用、Human 授权且有退出方式时，才允许受控复制。

部署不得复制完整 specs 正文，不得创建第二事实源，不得覆盖用户已有配置而不保留说明。

创建或更新环境入口时，应同步处理个人环境特别要求；需要 AI 进入环境后直接看见并执行的个人设置，应写入对应环境入口的“个人环境特别要求”段落，而不是新增 specs 子文档或独立事实源。

### 4.3 部署后适配检查

部署后必须检查环境入口文件、配置或机制是否存在，薄引用是否指向正确的 LDVH 能力资产，目标资产是否可读，是否复制了不应复制的完整正文，是否满足成功条件，是否仍需 Human Gate。

### 4.4 声明完成前检查

AI 声明部署完成前必须输出证据摘要。证据至少包含环境类型、环境入口、对应 LDVH 能力资产、检查时间、检查方式、检查结论、失败项和降级项。

未完成适配检查时，不得声明部署完成。适配检查失败时，不得把失败写成环境类型不支持，也不得把人工降级写成原生完整支持。

## 5. 个人环境特别要求写入规则

个人环境特别要求是当前个人、维护者、工作区或 Human 授权场景中的特殊命令、路径、权限、安全、网络或工具约定。它们的目标是让 AI 在进入环境时直接看见并执行，不是新增 specs 子规范，也不是新增独立事实源。

创建或更新环境入口时，AI 应将 Human 明确确认、当前项目 README、依赖管理说明或当前工作区配置中需要长期对 AI 可见的个人环境特别要求写入对应环境入口的“个人环境特别要求”段落。该段落可以位于 LDVH 管理入口 Rules、工作区级入口、项目级入口、Skill 入口或其它 AI 可见环境入口中，按实际生效范围选择。

个人环境特别要求写入环境入口时至少应说明：

| 字段 | 必填 | 含义 |
|---|---|---|
| 要求 | 是 | 要求名称 |
| 内容 | 是 | AI 需要直接遵守的具体约束 |
| 适用范围 | 是 | 个人、维护者、当前工作区、当前环境或 Human 授权场景 |
| 影响动作 | 是 | 影响部署、写入、适配检查、命令执行或 Human Gate |
| 优先级 | 是 | 与 Human 当前指令、项目 README、依赖管理说明冲突时如何处理 |
| 退出条件 | 是 | 何时取消、替换或迁移该要求 |

以下类型可以写入对应环境入口：

| 类型 | 示例 | 对部署和检查的影响 |
|---|---|---|
| 写入约束 | 不允许自动写 IDE 配置目录 | 部署步骤必须 Human Gate 或降级为手动说明 |
| 路径约束 | 某目录不可访问或必须使用特定路径 | 适配检查需使用当前可访问路径 |
| 命令约束 | 默认使用 `python3`，或按项目约定使用虚拟环境、`python`、`uv`、`poetry`、`pipenv` | Code 检查和部署命令需按约束执行 |
| 权限约束 | 不允许跨工作区写入 | 环境入口部署不得越界 |
| 网络约束 | 不允许联网或访问外部服务 | sources 查询或安装步骤需降级 |
| 安全约束 | 不允许写入密钥、Hook 或自动触发配置 | 相关部署必须暂停或降级 |

使用个人环境特别要求时应遵守：

1. Human 当前指令优先于环境入口中既有个人环境特别要求；
2. 项目 README、依赖管理说明或项目配置优先于个人默认命令约定；
3. 未写入对应环境入口且未被 Human 当前确认的个人要求不得假定启用；
4. 个人环境特别要求不得升级为 LDVH 通用跨环境规则；
5. 修改会影响写入位置、权限、密钥、网络或长期配置的个人要求前，必须暂停并经过 Human Gate；
6. 删除仍被部署、适配检查、Code 或人工提醒消费的个人要求前，必须确认没有当前入口依赖。

## 6. 平台环境入口适配矩阵

本节只覆盖当前已纳入适配范围的 Trae Work CN 与 Codex App。LDVH 通用环境入口默认写入用户级或系统级目录，不以项目目录作为默认入口；项目目录只承载项目专属入口、兼容入口、测试入口或显式降级入口。候选入口可以写入本文，但必须标注证据状态、适配检查、禁止声明和降级路径；不得把候选入口写成本机已部署状态或平台完整支持结论。

### 6.1 Trae Work CN

Trae Work CN 的 LDVH 通用入口应优先写入用户级或系统级入口。项目 Rules、项目 Skill、AGENTS / CLAUDE 兼容入口只用于项目专属约束、兼容读取或显式降级，不作为 LDVH 通用入口默认落点。Trae Work CN 的环境入口应区分 Rules、Skill、Commands、自动运行设置、AGENTS / CLAUDE 兼容入口和无 Hook 降级流程。Trae Work CN 当前不应声明存在与 Codex lifecycle hooks 等价的用户可配置 Hook 机制。

#### 6.1.1 Rules / Instructions 入口

| 能力意图 | 环境入口 | macOS / Linux 位置 | Windows 位置 | 证据来源 | 证据状态 | 接入方式 | 适配检查 | 禁止声明 |
|---|---|---|---|---|---|---|---|---|
| LDVH 用户级 Rules | Trae 全局或用户级规则入口 | 具体文件路径待 Trae Work CN 当前版本确认 | 具体文件路径待 Trae Work CN 当前版本确认 | Trae Rules 机制资料、Human 确认 | 已有资料，具体系统目录待实测 | 薄引用 / 配置适配 | 检查用户级规则入口可定位、规则生效方式明确、内容通过薄引用指向 LDVH Rules 资产且未复制 specs 正文 | 不得在未确认 Trae 读取位置、未开启新会话或未实测加载前声明已生效 |
| 项目 Rules | Trae 项目规则目录 | `<repo>/.trae/rules/` | `<repo>/.trae/rules/` | Trae Rules 机制资料 | 已有资料，仍需当前项目实测 | 项目专属薄引用 / 显式降级 | 检查规则文件存在、front matter 生效方式明确、内容指向项目专属约束或 LDVH 管辖提示 | 不得把项目 Rules 当作 LDVH 通用入口默认落点 |
| 子目录 Rules | 子目录 `.trae/rules/` | `<repo>/<subdir>/.trae/rules/` | `<repo>/<subdir>/.trae/rules/` | Trae Rules 机制资料 | 已有资料，需按目录实测 | 薄引用 / 配置适配 | 检查规则目录不超过 3 层嵌套，且只在相关目录文件被读取或提及时声明生效 | 不得声明对子目录无关文件全局生效 |
| AGENTS 兼容入口 | AGENTS 兼容文件 | 仓库根目录 AGENTS 兼容文件 或相关子目录 AGENTS 兼容文件 | 仓库根目录 AGENTS 兼容文件 或相关子目录 AGENTS 兼容文件 | Trae Rules 机制资料 | 已有资料，需确认 Trae 导入开关 | 薄引用 / 指令适配 | 检查文件存在、入口内容只导航到 LDVH Rules 资产、Trae 设置已开启包含 AGENTS | 未确认导入开关前不得声明 Trae 已自动读取 |
| CLAUDE 兼容入口 | CLAUDE 兼容文件 / CLAUDE 本地兼容文件 | 仓库根目录 CLAUDE 兼容文件、仓库根目录 CLAUDE 本地兼容文件 | 仓库根目录 CLAUDE 兼容文件、仓库根目录 CLAUDE 本地兼容文件 | Trae Rules 机制资料 | 已有资料，需确认 Trae 导入开关 | 兼容入口 / 指令适配 | 检查文件存在、入口边界清楚、Trae 设置已开启包含 CLAUDE | 不得把兼容入口写成 LDVH 首选入口 |

Rules 环境入口中的薄引用内容应只承担发现、导航、约束提醒和交还职责。LDVH 通用 Rules 薄引用默认写入用户级或系统级 Rules 环境入口；只有项目专属规则、仓库内兼容入口或 Human 明确要求时，才写入项目目录。需要 AI 直接看见的个人环境特别要求可写入用户级或系统级 Rules 环境入口；长期规范正文仍以 `specs/` 为准。

#### 6.1.2 Skill 入口

LDVH 在 Trae Work CN 中的 Skill 适配应声明为全局 Skill 优先。项目级 Skill 只用于项目专属能力，不作为 LDVH 通用能力的默认承载位置。

| 能力意图 | 环境入口 | macOS / Linux 位置 | Windows 位置 | 证据来源 | 证据状态 | 接入方式 | 适配检查 | 禁止声明 |
|---|---|---|---|---|---|---|---|---|
| LDVH 全局 Skill | Trae 全局技能目录 | `~/.trae-cn/skills` | `%userprofile%/.trae-cn/skills` | Trae Skills 机制资料、Human 确认 | 已有资料，需本机路径检查 | 安装 / 配置适配 | 检查 Skill 目录存在、每个 Skill 含 Skill 入口文件、元数据完整、description 能触发正确任务 | 不得把未安装的全局 Skill 声明为可用 |
| 项目 Skill | Trae 项目技能目录 | `<repo>/.trae/skills/` | `<repo>/.trae/skills/` | Trae Skills 机制资料 | 已有资料，需当前项目实测 | 项目专属安装 / 显式降级 | 检查是否确为项目专属能力、没有覆盖全局 LDVH 通用 Skill 意图 | 不得把项目 Skill 当作 LDVH 通用全局 Skill 默认入口 |
| Agent Skills 兼容入口 | `.agents/skills/` | `<repo>/.agents/skills/` | `<repo>/.agents/skills/` | Trae Skills 机制资料 | 已有资料，需重名优先级检查 | 兼容入口 / 人工降级 | 检查与 `.trae/skills/` 是否重名，重名时按 Trae 优先级处理 | 不得忽略 `.trae/skills/` 对同名 Skill 的优先级 |

Trae Skill 写作和检查应吸收 Trae Skill 写作最佳实践资料 的稳定结论：Skill 入口文件 应保持单一职责，声明正向触发和负向排除，输入输出结构化，步骤可执行，失败策略明确，并采用渐进式披露。Skill 不得写成知识库全集，也不得把 Skill 模拟写成 Hook 原生能力。

#### 6.1.3 Commands、自动运行设置与无 Hook 降级

| 能力意图 | Trae 可用机制 | 证据来源 | 证据状态 | 适配方式 | 适配检查 | 禁止声明 |
|---|---|---|---|---|---|---|
| 重复流程触发 | Commands / 显式会话指令 | Trae 无 Hook 与 Codex Hook 对照资料 | 已有资料，需当前环境确认 | 指令适配 / 人工降级 | 检查命令或显式步骤是否能被 Human 或 AI 主动触发 | 不得声明为自动生命周期 Hook |
| 风险操作控制 | 自动运行 MCP、自动运行命令、Human Gate | Trae 无 Hook 与 Codex Hook 对照资料 | 已有资料，需当前设置确认 | 安全配置 / Human Gate | 检查自动运行模式、白名单、黑名单和需确认操作 | 不得把自动运行设置写成自定义审批 Hook |
| Hook 意图降级 | Rules、Skill、Commands、checklist、外部脚本 / CI | Trae 无 Hook 与 Codex Hook 对照资料 | 已有资料 | 人工降级 / 显式流程 | 检查每个 Hook 意图是否有不可模拟声明和收口检查 | 不得声明 Trae 可自动拦截工具调用生命周期 |

Trae Work CN 中模拟 Codex Hook 意图时，应使用“目的、可用机制、显式步骤、Human Gate、校验收口、不可模拟能力”的模板。任何 Skill、Command、Rule 或 checklist 都只能表达显式流程，不能表达 `PreToolUse`、`PostToolUse`、`Stop`、`PreCompact` 或 `PostCompact` 等事件级自动触发。

#### 6.1.4 压缩备忘与上下文恢复

Trae Work CN 中的压缩备忘和上下文恢复应按显式流程处理：阶段性总结、Todo 状态、Memo、Task、上下文暂存文件或正式事实源回写。Trae Work CN 当前不得声明存在 `PreCompact` 或 `PostCompact` 等压缩生命周期 Hook。

| 能力意图 | Trae 处理方式 | 事实源边界 | 适配检查 | 禁止声明 |
|---|---|---|---|---|
| 压缩前保留上下文 | 显式阶段总结、Todo、Memo、Task、上下文暂存 | 稳定事实写回 Git 文件；临时上下文不得替代正式事实源 | 检查总结是否包含当前目标、已完成、未完成、风险和下一步 | 不得声明平台会自动在压缩前执行 |
| 压缩后恢复 | Rules 环境入口、上下文摘要、Memo / Task / Git 文件 | 正式规则以 `specs/` 为准，运行入口以环境入口中的薄引用为投影 | 检查恢复信息是否来自可读文件或 Human 当前输入 | 不得把聊天记忆当作长期事实源 |

### 6.2 Codex App

Codex App 的 LDVH 通用入口默认写入用户级或系统级目录。项目级 `.codex/` 只用于项目专属约束、仓库内测试、受信项目配置或显式降级，不作为 LDVH 通用入口默认落点。Codex App 的配置路径、Hook 事件和软入口可作为候选适配项写入本文。未经过当前环境实测或 Human Gate 确认前，应标注待确认或候选，不得声明当前机器已部署或完整支持。

#### 6.2.1 配置路径与软入口

| 能力意图 | 环境入口候选 | macOS / Linux 位置 | Windows 位置 | 证据来源 | 证据状态 | 接入方式 | 适配检查 | 禁止声明 |
|---|---|---|---|---|---|---|---|---|
| 用户级配置 | Codex 配置 | `~/.codex/config.toml` | 待实测确认 | Trae 无 Hook 与 Codex Hook 对照资料 | 候选，需 Codex App 实测 | 配置适配 / Human Gate | 检查文件存在、格式有效、配置层级清楚 | 不得在未确认 Codex App 读取前声明生效 |
| 用户级 Hooks | Codex hooks | `~/.codex/hooks.json` | 待实测确认 | Trae 无 Hook 与 Codex Hook 对照资料 | 候选，需 Codex App 实测 | Hook 配置 / Human Gate | 检查 hooks 文件存在、事件名有效、命令可信 | 不得声明未信任 hook 已自动运行 |
| 项目级配置 | 项目 `.codex/config.toml` | `<repo>/.codex/config.toml` | `<repo>/.codex/config.toml` | Trae 无 Hook 与 Codex Hook 对照资料 | 候选，需项目 trust 确认 | 项目专属配置 / 显式降级 | 检查项目配置层是否被信任和读取，且不承载 LDVH 通用入口默认职责 | 不得把未信任项目配置写成已加载，不得把项目级配置当作通用入口默认落点 |
| 项目级 Hooks | 项目 `.codex/hooks.json` | `<repo>/.codex/hooks.json` | `<repo>/.codex/hooks.json` | Trae 无 Hook 与 Codex Hook 对照资料 | 候选，需项目 trust 确认 | 项目专属 Hook / 显式降级 | 检查 hooks 定义、命令来源、权限和信任状态，且不承载 LDVH 通用入口默认职责 | 不得绕过用户审查和信任流程，不得把项目级 Hooks 当作通用入口默认落点 |
| 软入口 | instructions、AGENTS、项目说明、会话入口 | 依当前 Codex App 支持确认 | 依当前 Codex App 支持确认 | 当前资料仅作候选 | 待确认 | 指令适配 / 人工降级 | 检查 Codex App 是否稳定读取该入口 | 不得声明持久入口完整支持 |

#### 6.2.2 Lifecycle Hook 事件候选

| Hook 事件 | 典型能力意图 | 适配检查重点 | LDVH 使用边界 | 禁止声明 |
|---|---|---|---|---|
| `SessionStart` | 会话启动或恢复时注入上下文 | 检查事件是否支持、matcher 是否有效、输出是否进入模型上下文 | 可候选承接入口加载和恢复摘要 | 未实测前不得声明稳定加载 |
| `UserPromptSubmit` | Prompt 提交前检查或补充上下文 | 检查是否支持阻断、补充或提示 | 可候选承接输入澄清和风险提示 | 不得假定可改写所有用户输入 |
| `PreToolUse` | 工具调用前检查、阻断或改写部分输入 | 检查 matcher、工具覆盖范围、返回 JSON 语义 | 可候选承接危险命令、路径越界和权限检查 | 不得声明覆盖所有 shell、Web 或非 MCP 工具 |
| `PermissionRequest` | 权限请求前自动决策或交回审批 | 检查 allow / deny / abstain 语义和冲突优先级 | 可候选承接审批策略辅助 | 不得绕过 Human Gate 或平台审批 |
| `PostToolUse` | 工具调用后审查输出或反馈 | 检查是否能替换工具结果反馈、是否无法撤销副作用 | 可候选承接校验结果审查 | 不得声明能撤销已发生副作用 |
| `Stop` | 回合停止前决定是否继续 | 检查 continuation / block 语义 | 可候选承接最终验收、失败测试续跑 | 不得声明可以替代任务验收事实源 |
| `SubagentStart` | 子智能体启动前补上下文 | 检查子智能体类型和上下文注入方式 | 可候选承接 Agent 输入契约 | 不得声明未验证 Agent 能力 |
| `SubagentStop` | 子智能体结束后要求收口或继续 | 检查输出回主控和阻断语义 | 可候选承接 Agent 输出审查 | 不得让子 Agent 输出直接生效 |
| `PreCompact` | 上下文压缩前处理 | 检查 manual / auto matcher 和持久化输出 | 可候选承接压缩备忘、Memo / Task / Git 回写提醒 | 不得把压缩备忘写成聊天记忆长期事实源 |
| `PostCompact` | 上下文压缩后恢复处理 | 检查压缩后注入内容和恢复边界 | 可候选承接恢复摘要读取 | 不得声明恢复内容天然完整 |

Codex Hook 适配必须同时检查配置层级、项目 trust、命令来源、权限范围、事件覆盖范围和失败输出。未确认当前 Codex App 版本支持时，只能标注候选或待确认。

#### 6.2.3 压缩事件与备忘处理

Codex App 可把 `PreCompact` 和 `PostCompact` 作为压缩备忘与恢复的候选事件；但 LDVH 的稳定事实仍必须进入 specs、Task、Memo、ADR、Pitfall、Change、Git 文件或对应权威事实源。Hook 输出只能作为执行期辅助，不得替代事实源回写。

| 能力意图 | Codex 候选机制 | 适配检查 | 降级路径 | 禁止声明 |
|---|---|---|---|---|
| 压缩前备忘 | `PreCompact` | 检查事件支持、matcher、输出位置和失败处理 | 显式阶段总结、Memo、Task、上下文暂存 | 未实测前不得声明自动执行 |
| 压缩后恢复 | `PostCompact` | 检查恢复内容是否注入、是否可追溯到文件事实源 | Rules / instructions / Git 文件 / Human 当前输入 | 不得把恢复摘要写成完整事实源 |
| 长期记忆 | Memo / Task / Git 文件 | 检查是否符合对应事实源字段契约 | Human Gate 后回写正式对象 | 不得只依赖 Hook 输出或聊天记忆 |

### 6.3 跨平台兼容原则

Trae Work CN 与 Codex App 的适配不得互相冒充：Trae 的 Rule、Skill、Command、checklist 只能表达显式流程和人工降级；Codex 的 Hook 候选可以表达 lifecycle 意图，但仍需证据、信任和适配检查。LDVH 通用环境入口默认写入用户级或系统级目录；项目目录只用于项目专属环境入口、兼容入口、测试入口或显式降级入口。任何跨平台模板都必须列出“可承载能力”“不可模拟能力”“验证方式”“降级路径”和“禁止声明”。

## 7. Human Gate 与检查要求

以下情况必须评估 Human Gate：

1. 写入、覆盖或删除用户环境入口；
2. 修改长期环境配置；
3. 启用自动触发、危险权限或跨工作区写入；
4. 受控复制 LDVH 能力资产全文；
5. 覆盖用户已有 Rules、Skill、Agent、Hook、instructions 或配置；
6. 声明任一环境完整支持 LDVH；
7. 将一次用户本地适配检查结果写成环境类型结论；
8. 新增、修改或删除环境入口中的个人环境特别要求。

检查要求：

| 检查项 | 标准 |
|---|---|
| 入口定位 | 环境入口可定位或明确待确认 |
| 资产接入 | 对应 LDVH 能力资产存在且接入方式明确 |
| 部署权限 | 写入权限和 Human Gate 边界明确 |
| 适配检查 | 有部署前、部署后和声明完成前检查方式 |
| 降级说明 | 无原生入口时有适配降级和残留风险 |
| 个人环境特别要求 | 写入环境入口的位置、适用范围、优先级和退出条件明确 |
