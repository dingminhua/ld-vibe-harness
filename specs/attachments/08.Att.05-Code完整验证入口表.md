## 1. 定位

本文承载 08 授权的 LDVH Code 当前完整验证入口。

本文只记录当前参考实现的验证入口和受限说明，不限定未来 Code 的实现语言、测试框架、包管理器、命令组织或技术栈。若 Code 实现域调整验证入口，应同步本文、`code/docs/` 和 08 主体，但不得把当前命令反向写成长期技术选型义务。

## 2. 入口表

| 入口 | 当前性质 | 最低要求 |
|---|---|---|
| `npm run test:code` | Code 日常完整测试入口 | 同时运行 `tests/code` 自动化测试和 `python3 code/specs_validate.py all --fail-on-diagnostics` |
| `npm run test:code:unit` | Code 快速单元测试入口 | 只覆盖 `tests/code` 时，验证声明必须说明未覆盖综合入口的风险 |
| `python3 code/specs_validate.py all --fail-on-diagnostics` | active specs 综合检查入口 | 当前默认读取 active `specs/` |
| `python3 code/specs_validate.py v2-check --fail-on-diagnostics --format text` | active specs 诊断和只读知识地图预览入口 | 不替代完整运行时知识地图能力、Web 接入验证或 Git 原生命令历史追溯 |
| `python3 code/specs_validate.py knowledge-map --format text` | active specs 知识地图只读投影入口 | 只验证默认输入范围投影，不覆盖管辖项目或 raw 原文层 |
| `python3 code/specs_validate.py v2-check --input-scope runtime_extensions --fail-on-diagnostics --format text` | 固定运行时扩展自描述只读投影验证入口 | 不替代 active specs 默认诊断，不写入缓存，不决定 Rules 正文如何修改 |
| `python3 code/specs_validate.py capability-environment --format text` | 固定能力资产与环境保障矩阵验证入口 | 只验证固定资产到环境落地边界的只读矩阵；不写入环境入口，不声明环境已安装 |
| `python3 code/specs_validate.py knowledge-map --input-scope governed_projects --format text` | 管辖项目事实对象图谱投影验证入口 | 输出可能暴露事实对象缺失引用诊断；不修改管辖项目配置或事实源 |
| `python3 code/specs_validate.py knowledge-map --layer raw --start-node <node> --format text` | raw 原文片段层验证入口 | 只返回受控片段，不作为全文事实源缓存 |
| `python3 -m pytest -q tests/code/specs_validate_checks/test_preflight.py` | 受控写入 preflight 专项测试入口，覆盖 Rules 入口同步审查提示 | 不替代完整 Code 回归或事实源写入授权；Rules 同步提示不授权自动修改 Rules |
| `python3 -m pytest -q tests/code/specs_validate_checks/test_v2.py tests/code/specs_validate_checks/test_preflight.py tests/code/specs_validate_checks/test_deployment_entries.py tests/code/specs_validate_checks/test_capability_environment.py` | active specs、runtime_extensions、governed_projects、raw、preflight 字段归口和 Rules 入口同步审查提示、固定运行时扩展登记和能力环境矩阵联合验证入口 | 不替代完整 Code 回归 |
| `git diff --check` | 空白和补丁格式检查 | 只能证明 diff 格式无空白错误，不能替代业务测试 |

## 3. 受限与问题分流规则

只运行局部入口时，应在验证声明中说明未运行完整入口的原因、影响范围和残留风险。Code 关键 CLI、诊断 Schema、目录假设、写入行为或下游消费合同变化时，不得只用 smoke test 作为完整验证。
