## 1. 本文解决的问题

本文是 Codex CLI 对 LDVH 要求响应矩阵的当前填写实例。

本文不以 Codex CLI 的平台能力为主轴。AGENTS.md、config.toml、sandbox、approval、exec、subagents、MCP、web_search、review、hooks、skills、OpenTelemetry 和 shell 工具只是承接方法候选。本文的主轴是：LDVH 对 AI 执行者提出什么支持要求，LDVH 正式规范提出什么落地要求，Codex CLI 逐项用什么方法实现。

本文不是 Codex 官方文档，不替代 OpenAI Codex CLI 官方说明，不替代实际 `~/.codex/`、项目 `.codex/`、AGENTS.md、CLI 配置或本次 Codex 会话工具权限。Codex 官方资料和仓库 refs 只作为平台事实证据输入；当前是否真实可用仍需 42 LDVH落地与检查现场确认。

当前 Codex 清单不声明以下能力已完整支持：

1. 当前用户本机 Codex CLI 已按本文完成 42 LDVH落地与检查；
2. 当前项目 AGENTS.md、AGENTS.override.md 或 fallback 入口已经存在并被 Codex 实测加载；
3. 项目 `.codex/config.toml` 已存在、已被信任加载且安全配置符合 LDVH；
4. hooks、skills、MCP、subagents、web_search、review 或 OTel 已在当前环境可用并完成检查；
5. 自动无确认启用 hooks、MCP、网络访问、危险沙箱、`--yolo` 或跨工作区写入；
6. session history、OTel、JSONL、review 输出或工具缓存可以替代 Git 文件事实源；
7. 无证据宣称完整支持或通过。

降级原则：能用 Codex 平台实体承接时使用平台实体；平台实体不可用时回到 LDVH 统一入口、Git 文件事实源、主控 AI、对话 Human Gate、显式命令校验和 42 当前过程报告。涉及网络、MCP、hooks、danger-full-access、跨工作区写入、密钥、凭据或长期配置变更时，默认降级为 Human Gate。
