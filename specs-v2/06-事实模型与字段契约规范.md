## 4. 公共字段稳定机制

公共字段不靠各模型复制文本保持一致，而靠“中央语义定义 + 具体模型显式采用 + Code 矩阵校验”保障。

### 5.1 公共字段基线

以下字段拟作为所有事实模型必须具备的模型身份基线：

1. `id`；
2. `type`；
3. `title`；
4. `status`；
5. `created`；
6. `updated`。

这些字段保障 Code、Web、知识地图、引用关系和状态判断具有稳定入口。具体模型仍必须声明 ID 格式、状态枚举、必填性和状态条件。

### 5.2 公共字段不是默认可用字段池

公共字段表示语义字典，不表示每个模型都能默认采用。具体模型采用字段时，必须在本模型字段契约中显式声明。

公共字段候选应覆盖 v1 已治理字段，包括但不限于：

1. `description`；
2. `source`、`source_detail`、`source_objects`、`source_sparks`、`source_docs`；
3. `acceptance`、`verification`、`verification_evidence`、`closure_evidence`；
4. `closed_at`、`archive_reason`、`deprecated_reason`、`discard_reason`；
5. `notes`；
6. `related_docs`、`related_rules`、`related_workcases`、`related_adrs`、`related_sparks`、`related_studies`、`related_pitfalls`；
7. `urls`；
8. `resolved_to`、`superseded_by`；
9. `evolution`、`lessons`、`transition_reasons`。

Study 等模型可以明确禁止某些公共字段；公共字段注册不得反向推导模型可写字段。

### 5.3 具体模型采用声明

具体事实模型不重新定义公共字段语义，只声明采用关系和本模型约束：

| 字段 | 来源 | 是否必填 | 状态条件 | 本模型约束 |
|---|---|---|---|---|
| `id` | 公共基线 | 是 | 全状态 | 具体模型定义 ID 格式 |
| `status` | 公共基线 | 是 | 全状态 | 状态枚举归具体模型定义 |
| `verification` | 公共字段 | 条件必填 | 由具体模型定义 | 必须包含验证命令、结果或人工验证记录 |
| `goal` | 模型特有字段 | 是 | 由具体模型定义 | 由具体模型定义 |

字段注册表只说明“字段若被采用，应如何理解和消费”，不构成字段存在性、必填性、状态条件或对象内完整 schema 的依据。

### 5.4 Code 字段矩阵校验

Code v2 应能从 06、授权附件和 20-29 具体字段表生成“字段 x 模型”矩阵，并检查：

1. 每个模型是否都有基线字段；
2. 每个被采用字段是否已在 06 或授权附件注册；
3. 同名字段是否出现语义漂移；
4. 同名字段的值形态是否冲突；
5. 具体模型是否声明必填性和状态条件；
6. 废弃字段是否还被新模型使用；
7. Code/Web 消费字段是否能回到同一字段注册来源；
8. 注册表是否被错误用来反推模型字段存在性。

公共字段变更应触发 Human Gate，并检查 20-29、Code、Web、测试和知识地图派生是否需要同步。
