## 1. 定位

本文承载 07 授权的 commit message 字段契约。

07 正文定义 commit message 本体规则；本文只说明标准格式中的字段含义和出现要求，不得维护 type 闭集、scope 推荐表、body 必填条件、提交样例或 AI 提交流程。

## 2. 字段表

标准格式如下：

```text
<type>[optional scope][!]: <description>

[optional body]

[optional footer(s)]
```

| 字段 | 要求 | 说明 |
|---|---|---|
| `type` | 必填 | 提交类型，使用 `07.Att.02` 的英文枚举；type 是严格闭集，不得使用枚举外值 |
| `scope` | 可选 | 影响范围，优先使用 `07.Att.03` 推荐值；无合适值时可使用项目内稳定、名词性的扩展值 |
| `!` | 可选 | 破坏性变更标记，对应 Conventional Commits 的 breaking change |
| `description` | 必填 | 简体中文简短说明，推荐不超过 72 字符 |
| `body` | 条件必填 | 使用简体中文说明做了什么、为什么做、影响范围、关键取舍和必要上下文；是否必填按 `07.Att.04` 判断 |
| `footer` | 可选 | 遵守 Conventional Commits 和 git trailer 风格；可以使用 `BREAKING CHANGE:`、`Refs:`、`Co-authored-by:` 等行业兼容 footer，但不得替代 body 的语义清单 |

## 3. 单主语义

首行只表达本次提交的主意图和主承载域，不表达 touched files 的全量分类。

`type` 只能有一个，表示本次提交的主变更意图或动作类别。`scope` 最多一个，表示名词性的主承载域或最重要的事实源边界。一次提交可以跨多个目录完成同一闭环，但首行只选择主 type 和零个或一个主 scope；其它受影响范围写入 body。

首行不得使用多个 type、多个 scope、斜杠拼接、逗号拼接或“全都写上”的方式规避取舍。例如 `feat+docs(web/specs): ...`、`feat,fix(web): ...`、`feat(web,code): ...` 都不符合 LDVH 的单主语义。

## 4. 辅助核对表

| 核对项 | 标准 |
|---|---|
| 格式可解析 | 首行符合 Conventional Commits 1.0.0 兼容格式 |
| 字段完整 | `type` 和 `description` 必填；`body` 按条件必填 |
| 单主语义 | type 和 scope 没有多值拼接 |
| footer 不替代 body | footer 不承担动机、影响和验证结论的主要语义 |
