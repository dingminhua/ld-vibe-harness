## 1. 价值判断

本文的价值，是把环境接入反复出现且容易漏失的“确认目标与现状、形成可检查方案、保护用户资产、取得副作用授权、执行、静态回读、实际适用入口直调、真实事件验证、断点恢复、失败回滚和如实交还”组织成一条稳定行动结构。

没有本模板时，AI 容易把包或 Hook 文件存在写成接入完成，把手工调用写成自动触发，把安装授权扩大为管辖配置修改，或者在失败后只报告命令错误而不检查用户资产和残留触发。模板通过精确回指 09 和具体环境来源减少这些遗漏，不固定厂商事件、命令、路径、UI 或步骤数量。

只询问安装概念、只直接调用实际适用的 LDVH 核心、Helper、Git Gate 或 Hook Gate 核心、编写新的 adapter、修改厂商协议映射，或者当前事项不产生环境安装副作用时，继续使用相应来源和普通求解，不因本模板存在而强制进入安装流程。

## 2. 规范依据

本文直接依据：

1. `action-template-foundation`：规定具体模板的准入、适用、授权、共同结构、验证、回写和交还边界；
2. `environment-integration`：唯一规定单一接入单元、输入与结果映射、安装生命周期、静态观察、真实触发、环境证据和回滚成立条件。

02 的管辖配置和工作对象规则、03 的信息作用与来源回指、04 的 Helper 服务契约、07 的 Code/tests 要求、Human 当前指令、具体环境当前资料、具体 adapter 来源及实际安装能力按当次目标提供输入。本文只组织消费，不复制其字段、协议、算法或成立条件。

## 3. 职责边界

本文负责定义：

1. 一次环境接入安装、检查、升级、修复、禁用、卸载或回滚行动的适用与排除边界；
2. 目标环境、工作对象、当前安装、用户资产、实际适用的 LDVH 核心、Helper、Git Gate 或 Hook Gate 核心、具体 adapter、授权和验证入口之间的稳定行动关系；
3. 只读发现、方案形成、写入授权、执行、静态回读、实际适用入口直调、真实环境触发和回滚的步骤依赖；
4. 需要 Human 操作目标环境时的断点恢复和最小观察交还；
5. 成功、部分完成、失败、不可验证、回滚和残留的分流及最终交还。

本文不负责定义：

1. 环境接入成立条件、管辖项目配置、Helper 字段、厂商事件、manifest、payload、权限或安装接口；
2. adapter 的设计、编写、重构、发布或平台兼容策略；
3. 具体命令、文件路径、UI 操作、安装器参数、日志格式或测试实现；
4. 自动发现工作区、自动登记项目、初始化事实源或修改事实对象；
5. Human 是否已经授权安装、平台信任、重启、覆盖、卸载或风险接受；
6. 安装运行状态、永久 receipt、事实对象或另一套环境状态机；
7. Git commit、push、发布、marketplace 提交或其它后续行动。

具体环境来源定义“如何连接”；09 定义“什么条件下接入声明成立”；本文只定义“如何组织一次接入安装与验证行动”。

## 4. 适用范围

当 Human 目标涉及以下一项，并且已经能够识别具体目标环境与候选接入单元时，本模板进入候选：

1. 首次安装或启用 LDVH 环境接入；
2. 检查既有安装是否仍能连接当前实际适用的 LDVH 核心、Helper、Git Gate 或 Hook Gate 核心；
3. 升级、修复或迁移接入单元和显式安装配置；
4. 禁用、卸载或回滚环境接入；
5. 继续一次因重启、新窗口、新任务、信任或 Human UI 操作而中断的真实验证。

具体 adapter 或其它候选接入单元尚不存在、目标环境协议或安装接口不清楚、只需要修改 adapter Code、只调用实际适用的 LDVH 核心、Helper、Git Gate 或 Hook Gate 核心、不涉及环境连接，或没有写入/安装授权时，不执行安装分支。可以继续只读调查、形成方案、准备 Human Gate，或转交独立的 adapter 编写与更新行动。需要新增 manifest、启动脚本或薄 adapter 时，必须先按具体环境来源、07 和普通 Code 计划完成该对象；本模板不得在安装步骤中顺带设计或生成。

## 5. 环境接入安装与验证行动模板定义

### 行动模板声明

| template_key | summary | definition_ref |
|---|---|---|
| `environment-integration-installation-verification` | 围绕一个明确目标环境安装、检查、变更或移除单一 LDVH 接入单元，分别完成静态回读、实际适用的 LDVH 核心、Helper 或原生 Gate 核心直调、真实触发与回滚验证并如实交还 | `environment-integration-installation-verification-action-template::5. 环境接入安装与验证行动模板定义` |

### 5.1 输入与前置条件

执行者必须取得并区分：Human 当前目标与副作用授权；目标环境名称、版本和实际运行位置；安装位置及其可触发会话范围；目标环境当前官方或实际权威资料及观察时间；能够自动触发的扩展或事件机制、必需输入与反馈能力；工作区根、实际工作对象和 02 管辖解析输入；当前实际适用的 LDVH 核心可执行入口及其内部 Helper 入口，或原生 Gate 核心入口；已经存在的候选 adapter 或其它接入单元的当前正式来源与安装对象；现有 Hook、插件、配置、权限、信任和用户资产；计划使用的安装/卸载能力；静态、直接调用、真实触发和回滚验证入口。涉及原生 Git Gate 时，还必须确定实际 Git worktree、有效 Hook 路径是否位于其中，以及与 common Git directory 或外部路径的关系。

除非 Human 明确指定不同的目标环境或工作区，执行者应把当前可观察的运行环境和工作区作为候选目标，并优先通过只读观察、当前环境资料和实际安装对象取得上述信息；不得把可观察的信息先要求 Human 转述。只有目标不可观察或无法识别、Human 指定不同目标，或者需要选择安装范围、授权写入、接受权限或信任、处理冲突时，才向 Human 请求相应信息或决定。

历史安装记录、聊天记忆、包管理器状态、文件存在、旧截图、fixture 或模板命中不能替代当前输入。缺少具体环境来源、adapter 或实际执行能力时，只能形成缺口和方案，不能用模板补造。

执行者按 09 §5.6 形成能力状态，保存当次具体环境来源并交还输入或证据缺口；本模板不替执行者研究全部厂商，也不把模拟 fixture 当作真实环境证据。

### 5.2 参与者、能力与授权

AI 负责回读来源、识别适用范围、核对现状和用户资产、形成方案、判断授权覆盖、调用实际能力、解释验证结果和交还未验证范围。Human 只承担当前来源或环境保留的安装/删除授权、平台信任、权限、重启、UI 操作、冲突取舍和风险接受。

Helper/Code/安装器只执行其当前声明且实际可用的机械检查、配置写入、安装对象变更、调用和回读。具体环境只提供其真实支持的事件与反馈；环境能力不足不能由模板伪造成已保障。委派执行或观察时，主控 AI 仍负责来源、授权、证据和最终结论。

Human 已明确授权某一项目×环境的确定性工作树创建或设置流程时，AI 可以对该流程明确交付且逐个解析为 `governed_single` 的实际 worktree 复用该授权，但必须逐个核对 09 所要求的目标、管辖、用户资产和实际写入；这只是当次行动范围，不建立长期授权状态或项目登记。

### 5.3 行动步骤与分支

#### A. 建立目标与当前基线

1. 明确目标是安装、检查、升级、修复、禁用、卸载还是恢复验证，并固定目标环境、版本、安装位置和可触发会话范围；工作区、工作对象与该安装范围分别记录，不相互推定；
2. 回读 09、LDVH 当前接入面说明（`specs/attachments/09.Att.01-环境接入面.md`）、具体环境来源、具体 adapter 或接入单元来源及实际安装能力，不沿用历史命令或路径；
3. 只读检查当前规则源、实际适用的 LDVH 核心入口及其内部 Helper 入口，或原生 Gate 核心入口、显式工作区根、02 配置存在性、当前接入对象、权限、信任、用户资产、旧版本和冲突；
4. 把 LDVH 管理对象、确认保留的用户对象、身份未知对象和当前不可观察范围分开；
5. 研究目标环境当前官方或实际权威资料，确认是否存在能够自动触发外部命令或扩展、传递当前工作对象所需输入、并将完整结果或可回查诊断反馈给 AI/Human 的机制；按功能判断，不只看 "Hook" 这个名称。记录资料 URL 或稳定定位、观察时间、产品版本和平台；
6. 对照 09.Att.01 判断原生事件是否与某个既有 LDVH 入口语义对应，列出实际输入、输出、partial/error、超时、权限、用户资产和回滚；
7. 按 09 §5.6 形成能力状态：
   - 尚未调查、资料未找到、版本不明、权限不足或不可观察 → `unverified`
   - 找到候选自动机制但尚未安装或真实触发 → `unverified`
   - 肯定依据证明不存在能承接必需输入与反馈的自动机制 → `unsupported`
   - 静态安装或核心直调通过，但没有真实环境事件 → 对应子范围已观察，完整接入仍为 `unverified`
   - `partial` 只能说明已完成的子范围，不能覆盖 `unsupported` 或 `unverified`；
8. 若目标环境可直接配置到已有 LDVH 入口（无需新增 manifest、脚本或薄 adapter），继续形成安装方案；
9. 若必须新增 manifest、启动脚本或薄 adapter，记录缺口并分流到独立 Code 计划，按具体环境资料和 07 建立独立 Code 计划，不继续安装；
10. 若目标实质是编写 adapter、修改管辖配置或其它独立行动，分流而不继续安装。

#### B. 形成方案并取得授权

1. 列出将创建、修改、替换、禁用或删除的对象，以及明确不改变的对象；
2. 对每项变化给出来源、实际能力、预期结果、静态/真实验证入口和失败回滚方向；
3. 分开列出安装配置、可选的 02 管辖配置变化、环境信任/权限、重启和后续真实触发，不把它们捆绑为一次默认授权；
4. 对未知用户资产、覆盖/合并、不可完整回滚、所需能力无法成立且可能需要接受受影响保障或残留风险，或跨用户/工作区扩大进入 Human Gate；
5. Human 未授权时停在只读方案；授权只覆盖明确环境、对象和副作用。

#### C. 执行并完成静态回读

1. 在执行前重新检查方案依赖、目标对象和当前基线；变化使方案过期时停止并重做差异；
2. 调用实际安装或配置能力，只改变授权范围，不隐式登记项目、初始化事实源、提交 Git 或安装其它工具；
3. 每项写入后回读实际文件、配置、manifest、Hook、权限或安装器结果，以及由实际安装配置限定的可触发会话范围，并记录与方案的净差异；原生 Git Gate 还须确认有效 Hook 路径位于目标实际 worktree 内，未改变 common Git directory、外部路径或未知用户 Hook；
4. 执行 LDVH 核心或 Helper 直接可调用检查、原生 Gate 核心直调和 adapter 手工/fixture 检查时，明确它们分别只证明对应入口；
5. 静态失败、部分写入、结果不可观察或与方案不一致时，不进入成功分支，转入失败与回滚。

#### D. 完成真实环境触发或建立恢复断点

1. 按具体环境来源选择代表性真实事件，检查普通接入是否自动进入同一接入单元，经稳定薄引用调用相应 LDVH 核心并忠实映射核心结果；原生阻断型机械 Gate 是否在同一实际候选上调用唯一核心并忠实返回 allow/block；
2. 同时覆盖至少一个主要成功路径和一个与当前接入风险匹配的输入缺失、能力缺口、失败、映射拒绝或未验证范围；
3. 需要 Human 信任、权限、重启、新窗口、新任务或 UI 观察时，交还最小验收说明：目标环境、动作、正常表现、应返回的原始结果、复跑入口和未验证范围；
4. 恢复后先重新检查当前安装与来源，再消费 Human 原始观察；不把断点前计划当作当前结果；
5. 当前执行环境不能触发目标环境时，只交还真实验证入口，保持相应范围未验证。

#### E. 失败、禁用、卸载与回滚

1. 根据实际变化和变更前基线选择停止、修复、禁用、卸载或回滚，不对未改变对象执行恢复；
2. 只处理可证明由 LDVH 管理或 Human 明确授权处理的对象，保留未知用户资产；
3. 回滚后重新检查安装对象和目标环境，证明接入不再自动触发或已恢复变更前连接；经授权正常删除实际 worktree 时，只把其中 LDVH 管理 Hook 安装对象的物理消失作为对应范围的移除证据，不把它扩大为完整禁用/卸载、其它 worktree、common Git directory 或外部配置已清理；
4. 无法恢复原内容、权限、信任、运行环境或用户配置时，明确残留和影响范围，不能把命令成功写成回滚完成；
5. 修复后需要重新执行静态与真实验证，不能沿用失败前证据。

### 5.4 输出、验证、回写与交还

交还至少区分：目标环境、版本、安装位置、可触发会话范围及其与工作对象范围的区别；模板适用理由；当前基线和用户资产；方案、授权和实际变化；明确未变化对象；静态安装观察；LDVH 核心或 Helper 直接调用，或原生 Gate 核心直调；adapter 手工检查；真实环境事件与结果；成功、失败、部分结果、输入或能力缺口、映射拒绝或 no-op 的原因；Human 断点及恢复入口；回滚/卸载入口和实际结果；已验证、未验证、残留风险和后续行动。

安装配置只写入具体环境来源和实际安装能力允许的位置。模板不另建永久 receipt 或环境状态对象；需要长期保留的稳定事实必须重新按事实模型判断。Git commit、发布和 marketplace 提交不因安装成功自动执行。

### 5.5 组合、变更与退出

本模板可以消费已经完成的 adapter 编写结果，但不把编写与安装合成一个成功声明。Human 另行授权修改 02 管辖配置时，配置变化作为独立计划项按 02 执行并验证；环境安装和管辖配置仍分别成立。

模板稳定步骤关系、适用或失败边界改变时按 06 重审。若未来不同环境安装行为不再共享稳定结构，或确定性安装服务能够在不损失 Human Gate、真实触发和失败交还的前提下更低成本承接，应缩减、拆分或退出本模板。

| 验证对象 | 验证时机 | 成立条件 | 可接受依据 | 验证入口 | 可证明范围 | 未满足时的处理 |
|---|---|---|---|---|---|---|
| 模板身份与边界 | 新建、修改或发现模板时 | 声明唯一有效；只组织安装验证，不复制 09、02、04 或厂商协议 | 06、09、本文、准入记录与模板解析结果 | 规范回读、声明解析和来源比较 | 当前模板定义 | 暂停发现或激活，修正身份、重复或越界 |
| 目标与当前基线 | 形成方案前 | 环境、版本、作用范围、实际适用的 LDVH 核心、Helper 或原生 Gate 核心、adapter、安装对象、用户资产和未知范围为当前 | 当前来源、环境和只读检查结果 | 来源回读、安装检查和对象回读 | 当次目标环境与已观察对象 | 补充依据、缩小范围或只交还方案 |
| 方案与授权 | 产生副作用前 | 实际变化、保护对象、验证、回滚和不可恢复风险清楚；Human 授权覆盖实际范围 | 方案、Human 当前指令、环境与安装来源 | AI 对照审核和安装器 plan | 当次授权对象与副作用 | 不执行；拆分、修正方案或进入 Human Gate |
| 静态安装与直接调用 | 写入后或检查现状时 | 安装对象与配置完整回读；LDVH 核心、Helper、原生 Gate 核心和 adapter 中实际适用的入口在检查范围内可调用 | 文件/配置、安装器、LDVH 核心及其内部 Helper 或 Gate 核心与手工 adapter 输出 | check/verify、LDVH 核心或 Helper 或 Gate 核心直调和 fixture | 当次静态对象与直接入口 | 修复、回滚或保持对应范围不可用；不声明真实触发 |
| 真实环境触发 | 准备声明接入或完成时 | 普通接入由目标环境代表性事件经稳定薄引用调用相应 LDVH 核心并如实映射核心结果；原生阻断型机械 Gate 在同一候选上调用唯一核心并忠实返回 allow/block；主要成功和风险路径有当次依据 | 环境事件、Hook 输出、核心及其内部 Helper 请求/结果或 Gate 输入/诊断和 Human 原始观察 | 目标环境新会话、恢复或实际事件 | 当次环境、版本、入口和事件 | 保持未验证，交还断点或修复后重测 |
| 禁用、卸载与回滚 | 失败处置或移除连接后 | 目标环境不再自动触发或已恢复基线；无关用户资产未受损；残留已披露 | 前后对象、环境事件和残留检查 | 卸载/回滚后回读与真实触发反例 | 当次实际变化和可观察环境 | 不声明回滚完成；继续修复或交还残留 |
| 最终交还 | 结束本次行动时 | 实际变化、静态/直接/真实验证、失败、断点、回滚、未验证和后续行动分别表达 | 当次全部来源、调用、回读和观察 | AI 最终对照 09 审核 | 当次行动与证据范围 | 缩小结论，补齐结果或保持行动未完成 |

## 7. Human Gate

本文不新增脱离 09 的统一 Human Gate；环境接入的 Human Gate 按 09 §11 及当前实际适用的其它来源执行。

Human 决定的复用按 00 §10 执行；Human 当前指令已经授权某一对象和副作用，且适用于该行动的全部来源规则许可条件已经成立时不重复索取同一决定，但该授权不替代静态回读、实际适用的 LDVH 核心或 Helper 调用，或原生 Gate 核心直调、真实环境触发或回滚验证，也不自动包含 Git commit、发布和其它环境。

## 8. Stop Conditions

09 §12 的环境接入停止条件全部适用于本模板；此外，出现以下任一模板特有情况时，暂停能够包含风险的最小环境、安装对象、事件或声明：

1. 候选 adapter 或其当前正式来源无法确定，或者事项实质是编写 adapter、修改厂商协议或其它独立行动，却准备由安装模板补造；
2. 当前安装、用户资产、权限、信任、冲突或未知范围未检查；
3. 方案没有分开安装对象、可选管辖配置变化、权限/信任、重启、明确不变对象和回滚，或把其中一项授权扩大到其它项、Git commit 或发布；
4. 静态写入失败、部分成立、不可观察或与方案不一致，却准备继续真实环境验证；
5. 需要 Human 断点，但恢复入口、原始观察要求或未验证范围不清楚；
6. 实际失败、部分结果、输入或能力缺口、映射拒绝或 no-op 的原因、回滚或未验证范围没有进入最终交还。

暂停期间允许的行动与恢复按 00 §11 和 09 §12 执行。
