## 0. 上位规范

`specs/08-Web信息同步实现规范.md` 是 LDVH Web 信息同步构成要素、派生视图、Human Gate UI、受控轻写入白名单和 Web 文档边界的权威规范。`specs/11-测试基础规范.md` 是跨构成要素测试治理、验证声明、测试实现归属和测试证据事实源边界的权威规范。

本文只定义 `web/` 参考实现的页面级设计约束、组件风格、布局规则和交互细节，不替代 `specs/08-Web信息同步实现规范.md`、`specs/11-测试基础规范.md`、工作模型规范、工作流程规范或事实源对象契约。

当本文与 `specs/08-Web信息同步实现规范.md` 或 `specs/11-测试基础规范.md` 存在冲突或解释不一致时，一切以 specs 为准；Web 页面、API、组件和 `web/docs/` 文档不得越过 `08` 定义的事实源边界、Human Gate 边界、Code / Web 协作边界、写入白名单和 `11` 定义的测试治理边界。

## 1. 全局设计约束

### 1.1 技术栈

| 层 | 技术 |
|---|---|
| 框架 | React 18 + TypeScript |
| 样式 | Tailwind CSS（darkMode: class） |
| 构建 | Vite（端口 5173，strictPort: true） |
| 后端 | Express 4（端口 3001） |
| 路由 | React Router v6 |
| 图标 | lucide-react |
| Markdown | react-markdown + remark-gfm |
| 代码高亮 | react-syntax-highlighter（Prism + oneDark） |

### 1.2 主题系统

- 三态切换：system / light / dark
- CSS 变量使用 RGB 通道值（如 `248 249 251`），支持 Tailwind 透明度修饰符
- 所有颜色通过 `ldvh-*` 命名空间引用

### 1.3 国际化

- React Context 轻量实现，localStorage 持久化
- 所有用户可见 UI 文案必须通过 `useI18n()` 的 `t()` 获取；组件内不得直接写中文或英文句子
- 状态文本必须通过 `getStatus()` 获取，不展示 raw status 值
- 标题必须通过 `getLocalizedTitle()` 获取（优先 title_en/title_zh，回退 title）
- 字段名必须通过 `FIELD_LABEL_LOCALES` 或全局 i18n key 映射，不展示 raw snake_case 字段名
- 类型标签必须通过 `TYPE_LOCALES` 或 `nav.*` 映射，不展示 raw type 值
- 枚举值必须通过语义映射本地化，例如 priority、importance、category、owner_area、validation status；Pitfall `tags` 属于事实源英文索引标签，按原值展示，不做 UI 翻译。
- 字段和枚举映射必须遵守工作对象字段契约：`priority` 只适用于 WorkCase 和 Spark；ADR、Pitfall、WorkCase 和 Study 不得因 UI 信号标签需要而展示或补写 priority 或 importance；importance 字段已由 priority 统一承载，不再作为独立字段维护
- `priority` 属于轻量信号语言，不属于流程状态或告警；列表和详情中应使用弱边框、透明背景、短文本或点状提示，不得使用大面积实心色块、强告警色或影响卡片主边框来表达普通优先级
- 空状态、加载失败、占位动作、按钮、tooltip、面板标题和辅助提示都必须有中英文版本
- 绝对时间统一使用 `formatDateTime()`，显示为 `YYYY-MM-DD HH:mm`；事实源中的 `datetime` 字段必须记录至少包含小时和分钟的 ISO 8601 时间戳，不得写 date-only 后由 Web 补出 `00:00`；相对时间由 API/i18n 提供，不在组件内拼接
- 对象详情页和右侧扩展阅读区的对象身份头部必须复用同一套字段顺序：`类型标签 + 状态标签 + object-id`、标题行、创建/更新时间、右上复制入口；状态不得漂移到右上操作区或另起 MetaChip 行
- 允许例外：代码块、YAML 原文、文件路径、命令、ID、哈希、第三方 Markdown 内容和事实源正文；这些内容作为事实数据展示，不由 UI 翻译

**新增/修改页面的多语言检查清单：**

1. 切换到英文后，页面框架、按钮、筛选、状态、字段名、空状态、错误兜底和 tooltip 不得混入中文 UI 文案。
2. 切换到中文后，状态、枚举、分类和字段名不得展示 raw snake_case / raw enum；未知值可回退为原值，但必须使用元信息样式或 tooltip 保留诊断属性。
3. API 派生字段属于 UI 枚举时必须前端映射，例如 `owner_area`、`subcategories`、`remediation`、`writeback_targets`、`validation_plan` key。
4. API 事实正文属于证据内容时不翻译，例如校验器 message、文档标题、Git message、Markdown 正文、路径和命令输出。
5. 不允许在 JSX 中用 `locale === 'zh' ? '中文文案' : 'English copy'` 临时分支；语言名称、枚举映射等也必须进入 i18n key 或显式 mapping 表。
6. 新增字段、重命名字段或调整字段适用对象时，应同步检查 `web/src/utils/fieldFormats.ts`、`web/src/utils/objectSignals.ts`、`web/src/i18n/locales.ts` 和对应页面文档，不得用 Web 文案反向定义对象契约。

### 1.4 排版系统

所有页面必须使用语义排版类表达文本角色，不再在业务组件里临时选择字号。除特殊图表、代码高亮和第三方 Markdown 样式外，新增 UI 不允许直接使用 `text-[10px]`、`text-[11px]` 等任意字号。

|---|---|---|---|---|

| 页面说明 | `ldvh-page-subtitle` | 14px / 24px | 400 | 页面标题下方说明 |
| 区块标题 | `ldvh-section-title` | 14px / 20px | 600 | 页面大区块标题 |
| 卡片标题 | `ldvh-card-title` | 14px / 20px | 500 | 卡片、面板、列表项标题 |
| 正文 | `ldvh-body` | 14px / 24px | 400 | 普通阅读文本 |
| 次级正文 | `ldvh-body-muted` | 14px / 24px | 400 | 说明、空状态、辅助描述 |
| 辅助标签 | `ldvh-caption` | 12px / 20px | 400 | 时间、状态提示、短辅助信息 |
| 强辅助标签 | `ldvh-caption-strong` | 12px / 20px | 500 | 字段名、表单标签、卡片内小标题 |

### 1.5 固定切换区

- 页面中承担视图切换、对象切换、返回、关闭、上一个/下一个等导航职责的顶部控制区，不得随长正文滚出当前滚动容器。
- 中间主内容区域如存在 `tablist`、对象详情身份区或同等切换入口，应使用当前主滚动容器内的 sticky 顶部区域；内容正文在其下方继续滚动。
- 右侧扩展阅读区和移动端底部阅读面板的头部控制区必须固定在面板顶部，面板正文使用独立滚动区域。
- sticky / fixed 控制区必须有不透明或半透明背景、合适的 `z-index` 和底部分隔线，避免滚动内容穿透或遮挡切换按钮。
- 移动端底部阅读面板不额外占用单独拖动把手行；标题区域本身承担拖动职责，导航按钮和关闭按钮保留在同一固定控制区。有标题时标题显示在可拖动区域内，无标题时该区域显示居中拖动把手。

**约束：**

1. 页面级标题只使用 `ldvh-page-title`，面板内标题不得使用页面级字号。
2. 卡片、列表、表格内文本默认使用 `ldvh-body` / `ldvh-body-muted`，不要在局部混用 `text-sm` 和 `text-xs` 表达同一语义。
3. `ldvh-caption` 只用于辅助信息，不承载主要内容；如果用户需要阅读或点击，至少使用 `ldvh-body`。
4. `ldvh-chip` 只用于短标签，不用于长句、按钮主文案或段落。
5. 筛选、视图切换和同层 tab 控件统一使用 `ldvh-tab-list`、`ldvh-tab-button`、`ldvh-tab-button-active` 和 `ldvh-tab-button-idle`；tab 内数量使用 `ldvh-tab-count` 并继承 tab 文字字体、字号和字重，不得在对象页、提交页或工具页局部发明胶囊、分段控件、计数间距、独立数字字体或其他 tab 外观。
6. 数字指标只允许使用 `text-xl` 或 `text-2xl`，并限定在 Metric/Stats 组件内。
7. Markdown 阅读区使用 `MarkdownPreview`，基于 `github-markdown-css`，正文基准为 14px；表格、代码块、引用块和任务列表样式由 `index.css` 中的 `.ldvh-markdown-preview` / `.ldvh-inline-markdown` 统一控制，不得在业务组件里手写 Markdown 标签样式。
8. 绝对时间统一使用 `formatDateTime()`，显示为 `YYYY-MM-DD HH:mm`；页面不直接展示 raw ISO、秒、小数秒或 locale 自动格式。date-only 只允许出现在字段契约明确为 `date` 的事实中，不能作为 `datetime` 字段的正常输入。
9. UI 字距保持默认 0，不使用 `tracking-*` 做装饰性字距。

### 1.5 布局

- 单一 App Shell：左侧导航 + 中间主内容 + 右侧扩展阅读区。
- 主导航固定在左侧，不提供顶部导航、对象类型标签页或底部 Tab 作为替代主导航。
- 左侧导航默认展开，可折叠为 56px 图标 rail；折叠状态写入 `localStorage`。
- 折叠/展开控件位于左侧导航头部，不悬浮在主内容中线。
- 中间主内容使用 `ldvh-page-frame` 或等价页面框架，默认 `p-4 sm:p-6`。
- 右侧扩展阅读区属于 App Shell，不属于单个页面内部卡片；对象引用和文档引用优先在扩展区打开。
- 右侧扩展阅读区遵循同一内容点击切换规则：首次点击打开，点击不同内容切换预览，再次点击当前内容关闭扩展阅读。
- 右侧扩展阅读区的对象内容必须与对象详情页同源：同一对象的字段顺序、字段标签、字段过滤和字段渲染不得在 `ReadingPanel` 中另起一套摘要实现。
- 对象列表页 `/objects/:type` 是主选择面，不保留右侧扩展阅读；从详情页或跨类型详情返回列表页时，App Shell 必须主动关闭扩展阅读区。
- 右侧扩展阅读区会改变主内容可用宽度，仪表盘、卡片组、列表组不得只依赖 `lg:` / `xl:` 视口断点决定列数。
- 密集卡片布局优先使用 `auto-fit + minmax()` 或容器查询，让列数由容器实际宽度决定；统计卡最小宽度不低于 192px，主面板卡片最小宽度不低于 320px。
- 页面最小宽度：375px（StatCounter 2025-2026 数据：375×812 占 4.23%，是当前在售最低 CSS viewport，对应 iPhone SE 2/3）。
- 设计基准：390px（iPhone 12~16 主力）/ 393px（iPhone 14 Pro~16 Pro）/ 412px（Pixel/Samsung 主力）。

**当前实现的硬约束：**

1. 不把主导航改回顶部 Tab；对象类型切换由左侧导航承载。
2. 不把右侧扩展阅读区改成对象列表；扩展区只保留上一个/下一个访问对象导航和当前内容阅读。
3. 不把右侧扩展阅读区做成只开不关的单向入口；同一入口再次点击必须关闭当前扩展阅读。
4. 不让对象列表页继承详情页留下的扩展阅读状态；回到列表页时必须收起右侧区域。
5. 不把对象详情页改成 YAML 查看器；YAML 源码只能作为折叠兜底。
6. 不在 `ReadingPanel` 里维护独立的对象字段顺序、字段 label map 或字段渲染器；扩展阅读只能复用详情页阅读布局或详情页字段组件。
7. 不在页面内部再创建一套浮动侧栏、二级全局导航或营销式首页。

### 1.6 移动端适配策略

采用一套代码、响应式渐进增强方案，不做独立移动站。

**数据依据**（StatCounter 2025-2026 全球手机屏幕分辨率 Top 6）：

| 分辨率 | 市场份额 | CSS viewport 宽度 | 代表设备 |
|---|---|---|---|
| 414×896 | 12.7% | 414px | iPhone XR/11 |
| 360×800 | 9.23% | 360px | Android 主力 |
| 390×844 | 6.71% | 390px | iPhone 12/13/14 |
| 375×812 | 4.23% | 375px | iPhone SE 2/3、X/11 Pro |
| 384×832 | 4.03% | 384px | 部分 Android |
| 393×873 | 4.02% | 393px | Pixel 3~8a |

**断点体系**（对齐 Material Design 3 WindowSizeClass + Tailwind v4）：

| 级别 | M3 SizeClass | 宽度范围 | Tailwind 映射 | 设备场景 |
|---|---|---|---|---|
| 紧凑 | Compact | 375–599px | 默认（无前缀） | 手机竖屏（99.96% 手机） |
| 中等 | Medium | 600–839px | `sm:` 640px | 手机横屏 / 小平板竖屏 |
| 展开 | Expanded | 840–1199px | `md:` 768px / `lg:` 1024px | 平板横屏 / 笔记本 |
| 较大 | Large | 1200–1599px | `xl:` 1280px | 大平板 / 桌面 |
| 超大 | X-Large | ≥ 1600px | `2xl:` 1536px | 宽屏桌面 |

> 注：M3 Compact/Medium/Expanded 三级断点（600dp/840dp）是布局决策的核心分界线；Tailwind 断点更细粒度，两者配合使用：M3 决定布局结构（单栏/双栏/三栏），Tailwind 决定组件级微调。

**适配原则**：

1. **移动优先**：默认样式面向 Compact（375px），通过 `sm:` / `md:` / `lg:` 逐步增强
2. **容器查询优先**：组件级响应式优先使用 CSS `@container` 查询（2026 主流浏览器已全面支持），视口级布局仍用 `@media`
3. **导航保持一致**：当前实现所有宽度都保留左侧导航；Compact 下不得新增底部 Tab 或顶部类型标签页作为主导航替代。
4. **内容优先**：Compact 隐藏次要信息，保留核心操作路径
5. **触摸友好**：可点击区域最小 44×44px（Apple HIG）/ 48×48dp（Material），列表项间距 ≥ 8px
6. **面板降级**：桌面端右侧扩展阅读区 → 移动端底部抽屉（50vh + 拖拽关闭）。

**各页面移动端要点**：

| 页面 | Compact (≤599px) | Medium (600–839px) | Expanded (≥840px) |
|---|---|---|---|
| 仪表盘 | 统计卡片 2 列，待推进/最近活动单列堆叠 | 统计卡片 3 列，双列布局 | 统计卡片 5~7 列，双列布局 |
| 对象列表 | 卡片视图，左侧导航保留 | 卡片自适应列数 | 卡片自适应列数，不切成表格 |
| 对象详情 | 字段单列，元信息换行，YAML 横向滚动 | 字段单列，右侧面板可展开 | 语义字段布局 + 右侧阅读面板 |
| 提交记录页 | 提交列表单列 | 提交列表单列 | 双列布局 |

### 1.8 数据源

所有页面数据来自 `ldvh-base/` 目录下的工作对象事实源；多数对象是 YAML，Study 是 Markdown frontmatter，Express API 负责读取并暴露派生视图。

### 1.9 工作对象卡片通用交互

- 所有工作对象卡片、工作对象行、工作对象引用卡片和对象预览头部都必须提供复制对象路径图标。
- 复制入口统一使用 `CopyPathButton`，图标为 lucide `Copy`，复制成功后短暂切换为 `Check`。
- 对象复制内容必须是事实对象文件的完整路径；优先使用 API 返回的 `path` / `data.path`，只有缺失时才降级使用对象详情 `target`。
- 复制按钮必须按复制内容语义命名：对象为“复制对象路径”，文档为“复制文档路径”，URL 为“复制链接”，普通引用为“复制引用”，提交卡片为“复制提交上下文”，提交详情为“复制提交 hash”。不得用“复制完整路径”覆盖所有场景。
- 复制按钮只使用 icon + tooltip，不在卡片内增加解释性文字。
- 复制按钮默认使用透明 ghost icon，不使用常驻边框或重底色；只有 hover、focus 或复制成功时给轻量反馈，避免在状态徽章和辅助阅读图标旁边抢视觉层级。
- plain 列表行、对象引用行和无状态背景的关联材料行中，复制图标、扩展阅读图标、进入箭头等操作 icon 必须保持同一套中性 ghost 表现；对象类型色只用于左侧类型识别、ID 或短标签，不扩散到右侧操作 icon。
- 只有当行本身已经处于明确状态色背景中，例如活跃工作项组、待确认工作项组、风险或验证状态行，右侧操作 icon 才允许继承该行状态色；此时同一行内复制图标和扩展阅读图标必须颜色一致。
- 进入箭头默认与复制图标同级，使用弱灰色；hover/focus 时可轻微位移并切换 accent 色，但不得常驻使用状态色抢占内容层级。
- 复制按钮点击必须 `stopPropagation()`，不得触发卡片跳转、右侧扩展阅读或选择对象。
- 当外层卡片需要点击且内部包含复制按钮时，外层不得使用 `<button>` 嵌套按钮，应使用可键盘触发的卡片容器。

### 1.10 工作对象语义设计语言

工作对象页面不是通用数据表，也不是 YAML 字段浏览器。页面设计必须先判断对象在 LDVH 工作链路中的语义位置，再决定信息层级、卡片结构和状态表达。

**当前已完善的五个基准模块：**

当前 Web 的设计语言以提交、研究、决策、火花、经验五个已经完善的模块为中心。后续修改这五个模块时，必须一起检查共同语言；改造其他页面时，应优先向这五个模块靠拢，而不是按单页重新发明卡片、标题、操作或折叠结构。

| 入口 | 路由 | 页面定位 | 必须共享的设计语言 |
|---|---|---|---|
| 提交 | `/changelog`、`/changelog/:hash` | Git commit records 证据追溯 | 筛选 tab、卡片网格、标题带、复制入口、扩展阅读入口、标准身份头部、圆点正文节点 |
| 研究 | `/objects/study`、`/objects/study/:id` | 报告阅读界面 | 对象列表卡片、状态筛选 tab、标准身份头部、圆点正文节点、关联区统一行 |
| 决策 | `/objects/adr`、`/objects/adr/:id` | 决策补丁阅读页 | 对象列表卡片、状态筛选 tab、标准身份头部、圆点正文节点、Markdown 分段正文 |
| 火花 | `/objects/spark`、`/objects/spark/:id` | 待分流信息阅读页 | 对象列表卡片、状态筛选 tab、标准身份头部、圆点正文节点、闭环分流事实弱表达 |
| 经验 | `/objects/pitfall`、`/objects/pitfall/:id` | 可复用经验阅读页 | 对象列表卡片、状态筛选 tab、标准身份头部、圆点正文节点、非活跃原因弱表达 |

统一要求：

1. 列表页顶部切换区必须固定，使用 `ldvh-tab-list` / `ldvh-tab-button`，数字计数与文字同字体、同字号、同字重。
2. 列表主体使用 `ldvh-section-grid`，卡片允许一行多个；卡片标题必须完整展示，宽度不足时换行，不截断。
3. 卡片右上角只保留复制入口；如存在扩展阅读入口，应放在标题带、引用行或材料行右侧，复制与扩展阅读图标保持同尺寸、同中性 ghost 表达。
4. 卡片标题带使用弱背景、内圈边框和左侧语义短线；对象类型色只用于左侧识别，不扩散为大面积背景。
5. 时间信息使用统一格式：对象卡片和提交卡片底部右侧显示更新时间，并使用 `formatDateTime()` 绝对时间；详情页绝对时间同样使用 `formatDateTime()`。
6. 详情页和右侧扩展阅读必须复用同一套身份头部和正文节点；不得出现“详情页一套、扩展阅读一套”的字段顺序、标题、折叠行为或正文样式漂移。
7. 右侧扩展阅读顶部导航栏不展示当前内容标题；内容标题只出现在正文身份区或文档正文中，顶部栏只保留前后导航、拖拽和关闭控制。
8. 主正文节点统一使用小圆点标题、整行点击折叠、`ChevronDown` / `ChevronUp` 图标和 `.ldvh-study-node-content` Markdown 阅读样式。
9. 复制内容必须服务 Human 与 AI 快速定位：对象复制完整事实源路径，提交卡片复制完整提交上下文，提交详情复制 hash。
10. 新页面或旧页面改造应先阅读 [`10-Web开发现状与设计语言基线.md`](./10-Web开发现状与设计语言基线.md)，判断目标页面和五个基准模块的关系。

**对象语义分工：**

| 对象 | 页面关注点 | 不应突出 |
|---|---|---|
| WorkCase | 长期范围、工作项入口、当前有哪些工作项需要关注 | 任务明细、关闭判断、执行进度 |
| WorkCase | 一次目标、执行态势、成功标准、验证证据、关闭证据是否齐备 | 长期范围定义、工作项属性、独立执行对象细节 |
| 执行项 | WorkCase 内部推进态势、局部等待、验证或风险提示 | 一级对象导航、独立事实源、独立关闭判断 |
| 决策 / 踩坑经验 / 火花 | 决策、可复用踩坑经验、未计划化信息的阅读和追溯 | 强行映射成执行进度 |

**身份区：**

1. 身份区回答“这是什么对象”，不是摘要卡，也不是状态看板。
2. 标题永远是身份区第一视觉层，使用 `ldvh-page-title`；辅助数字、ID、时间、状态说明不得超过标题层级。
3. ID、路径、时间属于定位信息，使用 `ldvh-meta` / `ldvh-meta-muted`，不得做大号文本。
4. 状态徽章只表达事实状态，例如 `活跃`、`待关闭`、`已关闭`、`已归档`；解释性状态文案只在能帮助 Human 做关闭判断时显示。
5. WorkCase 的 `活跃` 已足够表达当前可承载工作项，不再补充“进行中”等通用状态 hint。
6. 创建/更新时间用于追溯，不作为独立决策信息。若页面需要更紧凑的身份区，可把创建/更新时间收进身份区弱信息行。

**内容结构：**

1. 每类对象都应有主阅读路径，不按 YAML 字段顺序机械堆叠。
2. WorkCase 的主路径是“工作项组 → 目标 / 范围 / 约束 / 来源 → 文档 / 决策 / 火花 / 踩坑经验”；定义事实和关联材料都应按语义拆成同级模块，避免在右侧扩展阅读区形成狭长的大区块。
3. WorkCase 的主路径是“执行态势 → 成功标准 / 验证证据 / 关闭证据 → 目标 / 工作项 / 来源 → 文档 / 决策 / 火花 / 踩坑经验”；成功标准和证据不再收进“关闭判断”总盒子，定义事实和材料集合也不再收进“属性/关联材料”总盒子。关联提交由提交记录视图派生，不从 WorkCase 字段手写维护。
4. 执行项只作为 WorkCase 内部态势和辅助阅读内容呈现，不拥有独立对象详情主路径。
5. 关联对象入口应作为下一层对象入口展示，避免在上层对象里展开下层对象的完整细节。
6. 核心定义类字段，例如 WorkCase 的目标、范围、约束、来源，不使用默认折叠隐藏事实；多行内容应拆成可扫描的语句列表。含 `包含：`、`不包含：` 等短前缀的事实行使用语义标签，普通事实行使用轻量圆点锚点。

**卡片和行：**

1. 卡片用于承载一个明确语义单元，例如工作项组、目标、范围、约束、任务拆解、证据材料；不得为了装饰把页面区块层层套卡片。
2. 列表行应突出可点击对象的标题；ID、更新时间、状态和复制路径是辅助信息。
3. 对象列表卡片外层可作为当前对象详情入口，进入时保留当前筛选 query；卡片必须提供统一 hover/focus 反馈。内部复制按钮、工作项行、信息框、区块标题、态势条和普通信息区域必须显式阻止外层点击，避免用户阅读内部关系或复制路径时误进入外层对象。
4. 卡片内部的下一层对象行同样只把该对象标题 + 箭头作为跳转入口；行背景、ID、状态、态势条和复制按钮都不是主路由入口。复制按钮只复制路径，不触发跳转。
5. 详情页内的关联对象入口只打开右侧扩展阅读区，不改变当前主详情页；同一个关联对象或文档入口再次点击，应关闭右侧扩展阅读区。若入口使用扩展阅读图标，图标方向必须随当前行是否已在右侧展开而变化。
6. 组标题用于表达集合状态和数量，例如 `1 个活跃工作项`，组内行不重复展示相同状态标签。
7. 已完成或已闭合的历史集合默认降权，可折叠或汇总；当前需要推进或需要判断的集合默认展开。

**色彩和状态：**

1. 颜色表达状态和对象类型，不作为装饰性主角。
2. 活跃使用绿色系，待关闭/待判断使用紫色系，已关闭/已归档使用灰色系。
3. 红色只用于错误、风险、失败或阻断，不用于普通归档。
4. 同一页面不应由单一色相支配；对象类型色、状态色和背景色必须互相节制。
5. 对象类型色优先用于“识别这个对象是什么”，状态色优先用于“判断这个对象处于什么状态”；操作 icon 默认属于交互层，不承担对象类型或状态表达。

**密度和响应式：**

1. 工作对象页面面向重复阅读和判断，优先信息密度、扫描效率和稳定布局，不做营销式留白或英雄区。
2. 移动端保留同一语义顺序，先身份，再当前关注点，再事实详情；弱信息可换行但不能溢出。
3. 任何固定格式 UI 元素都应有稳定尺寸或响应式约束，避免加载数字、状态标签或长标题造成跳动。
