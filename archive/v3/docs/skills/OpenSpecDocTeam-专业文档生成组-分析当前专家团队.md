# 技能：分析当前专家团队（OpenSpecDocTeam）

> 目标：当用户发起文档生成/审阅任务时，快速进入标准化协作流程，并在一个对话中产出可直接交付的文档。

## 1. 触发条件
- 用户提出“帮我写/生成/审查/补写/按模板生成”类技术文档。
- 或要求“分析当前专家团队”“按固定流程处理文档”时。

## 2. 执行角色（固定）
- **主理人**：章成文（doc-team-lead）
- **检索员**：doc-researcher
- **生成员**：doc-generator
- **审核员**：doc-auditor

## 3. 任务前置
1. 记录用户原始目标、行业、文档类型、范围、质量要求。
2. 建议建立团队：
   - 团队名默认：`OpenSpecDocTeam-团队-专业文档生成组`。
   - 若用户未另有命名，可直接使用该名。
3. 初始化“项目参数卡”（项目基本参数 + 已完成章节摘要 + 约束）。

## 4. 路由规则
- 仅检索资料：`doc-researcher`
- 仅写文档章节：`doc-generator`
- 仅审核现稿：`doc-auditor`
- 默认完整写作：按 Workflow A（需求分析→检索→生成→审核→汇编→交付）
- 用户要求草稿免审核：按 Workflow E
- 用户要求补章：按 Workflow C
- 用户要求模板填充：按 Workflow B

## 5. 按章节执行闭环（A/B/C 默认）
对每一章按顺序执行：
1. **Phase 2 检索**（doc-researcher）
2. **Phase 3 生成**（doc-generator）
3. **Phase 4 审核**（doc-auditor）
4. 不通过则回传修订，最多 2 次；第 3 轮仍不通过时强制通过并追加审核警告

## 6. 质量与一致性约束
- 无检索结果不得编造；明确标注 `[待填写]`。
- 规范引用统一写法：`《规范名称》(编号) 第X.X.X条`。
- 统一阶段产物格式与编号；最终汇编保持目录、术语、交付说明一致。

## 7. 交付
- 输出完整 Markdown（含封面、目录、正文、待完善事项、免责声明），或按用户要求输出目标章节。
- 若有信息缺口，聚合到文末“待完善事项”。

## 8. 失败兜底
- 成员调度失败：重试一次；仍失败则按最小可用模式继续并告知降级。
