# Trae Skills 技能机制

> 创建日期：2026-06-04
> 来源：Trae 官方文档
> 定位：外部资料引用，不直接成为 LDVH 强制规则
> 官方地址：https://docs.trae.cn/ide/skills | https://docs.trae.cn/solo/skills

---

## 1. 结论摘要

Trae Skills 通过 SKILL.md 文件定义，封装指令、脚本及相关资源，为智能体提供可复用、面向特定场景的专业能力。技能采用动态按需加载机制，智能体先扫描简要描述，仅在判断与当前任务高度相关时才加载详细内容，减少 Token 消耗。技能支持项目级（`.trae/skills/`）和全局级两级管理。官方提供 8 项最佳实践，涵盖元数据精准、边界明确、输入输出结构化、步骤明确可执行、失败策略完备、职责单一、渐进式披露和评测驱动。

## 2. 官方定位

技能（Skill）通过 SKILL.md 文件进行定义和管理。每个技能封装了指令、脚本及相关资源，用于为智能体提供可复用、面向特定场景的专业能力。一个技能可被视为提供给智能体的一套"专业能力说明书"（类似用户手册或操作指南）。

## 3. 主要特点

- **结构化**：一个技能对应一个 SKILL.md 文件，以结构化方式描述任务目标与适用场景、关键约束与注意事项、推荐流程或操作步骤、可选的脚本/模板/示例
- **动态按需加载**：智能体不会一次性读取所有技能完整内容，而是先扫描简要描述，仅当判断当前任务与某技能高度相关时才加载详细内容，减少 Token 消耗、避免无关信息干扰
- **可复用**：将个人经验或团队规范封装为技能，在不同时间、不同任务中复用
- **可共享**：将技能在社区、交流群等公共平台分享，跨智能体、项目、团队复用

## 4. 技能 vs 规则 vs MCP Server

| 对比维度 | 技能（Skill） | 规则（Rule） | MCP Server |
|---|---|---|---|
| 加载机制 | 按需加载，仅在实际需要时加载到上下文 | 全量加载，开启对话后所有规则持续占用上下文 | 按需调用 |
| 核心作用 | 向 AI 描述如何完成任务 | 约束 AI 的行为规范 | 向 AI 提供可调用的工具 |
| 示例 | 约定测试工程结构、POM 设计规范 | 代码风格、命名规范 | Playwright 提供页面操作能力 |

## 5. 技能类型

| 类型 | 描述 |
|---|---|
| 项目技能 | 在项目内创建，仅在当前项目中生效。存放于 `.trae/skills/` 目录 |
| 全局技能 | 在设置中心创建，在所有项目中生效。macOS/Linux 存放于 `~/.trae-cn/skills`，Windows 存放于 `%userprofile%/.trae-cn/skills` |

## 6. SKILL.md 文件格式

SKILL.md 由 YAML frontmatter 和 Markdown 正文组成：

```markdown
---
name: 技能名称
description: 简要描述这个技能的功能和使用场景
---

# 技能名称

## 描述
描述这个技能的作用。

## 使用场景
描述触发这个技能的条件。

## 指令
清晰的分步说明，告诉智能体具体怎么做。

## 示例 (可选)
输入/输出示例，展示预期效果。
```

## 7. 目录结构

一个技能必须包含 SKILL.md 文件，可选添加其他资源文件：

```
skill-name/
├── SKILL.md          # （必须）智能体的核心指令
├── examples/         # （可选）输入/输出示例
│   ├── input.md
│   └── output.md
├── templates/        # （可选）可复用的模板
│   └── component.tsx
└── resources/        # （可选）参考文件、运行脚本或素材
    └── style-guide.md
```

## 8. 创建方式

1. **AI 自动创建**：通过对话描述需求，AI 自动生成 SKILL.md 文件
2. **手动创建**：在 设置 > 技能与命令 中选择技能类型（全局/项目），填写技能名称、描述和指令
3. **导入外部技能**：上传 SKILL.md 文件或包含 SKILL.md 的 .zip 文件，Trae 自动解析并填充字段

## 9. 启用/禁用机制

- 通过技能面板的开关启用/禁用技能
- 禁用项目技能后，Trae 在 `.trae/` 目录下创建 `skill-config.json` 文件记录被禁用的项目技能
- 被禁用的全局技能不会出现在 skill-config.json 中

## 10. 调用方式

- **手动调用**：向 AI 发送指令明确告知调用某技能，或在技能面板点击"运行技能"
- **AI 自动调用**：AI 结合当前任务内容与技能 description 判断相关性，自动加载并使用

## 11. .agents 技能目录

- `.agents/skills/` 是由 Agent Skills 规范约定的目录，用于存放技能
- 若 `.trae/skills/` 与 `.agents/skills/` 中技能重名，优先调用 `.trae/skills/` 中的技能
- 可通过"find-skills"技能从 Agent Skills 生态中搜索和安装技能

## 12. 官方最佳实践

基于 Trae 官方文档"如何写好一个 Skill：从创建到迭代的最佳实践"：

1. **元数据精准**：名称使用简洁、无歧义、行业通用术语；描述明确说明核心功能、适用场景和技术栈，避免模糊词汇
2. **边界明确**：显式定义失败条件和拒绝执行场景，避免过度泛化
3. **输入输出结构化**：明确定义输入（Input）和输出（Output）的结构化格式，补充关键示例
4. **步骤明确可执行**：复杂任务必须显式定义工作流和检查清单，建立反馈闭环，避免步骤跳跃
5. **失败策略完备**：脚本需显式处理错误、输出自解释日志、避免魔法数字
6. **职责单一**：单个 Skill 仅解决一个明确问题，避免上下文污染
7. **渐进式披露**：SKILL.md 主体控制在 500 行以内，详细内容拆分到引用文件，保持一层引用深度
8. **评测驱动**：先建立"无 Skill"基线识别问题，针对真实失败点编写最小化规则，所有新增规则均需对应评测用例

## 13. SOLO 独立端技能

SOLO 独立端与 IDE 模式在技能上的差异：

- **技能市场**：SOLO 独立端提供技能市场，可直接搜索和安装技能
- **上传本地技能**：支持上传包含根级 SKILL.md 的 zip 或 .skill 文件
- **运行环境区分**：技能可区分本地/云端环境，本地技能仅对桌面版本地任务生效，云端技能对网页版和桌面版云端任务生效
- **安装后默认启用**：从技能市场安装或上传的技能默认被启用
