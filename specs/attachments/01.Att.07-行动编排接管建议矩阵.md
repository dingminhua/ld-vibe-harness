## 1. 定位

本文承载 01 授权的行动编排接管建议矩阵和接管建议辅助核对表。

01 正文定义规范保障要求的声明原则、五字段契约和行动编排接管边界；`attachments/01.Att.03-规范保障要求类型表.md` 承载保障要求类型闭集和保障声明辅助写法。本文只维护建议接管矩阵和辅助核对信息，不得定义接管原则、保障声明写法、具体行动流程、Scenario、Context、Gate、证据位置、回写规则或成员自描述。

本文中的行动编排名称均为建议实例，不占用编号，不表示 active，不表示必须拆分为独立流程。后续是否合并、拆分、改名或不创建，由 01 主文档和后续行动编排规范统一判断。

## 2. 建议矩阵字段说明

建议矩阵只回答“某类保障需求未来可能由哪类行动编排接管”。它不定义接管责任已经成立，也不定义保障机制正文写法。

建议矩阵字段如下：

| 字段 | 含义 |
|---|---|---|
| 建议行动编排实例 | 候选流程名称；不占用编号，不表示 active |
| 建议接管的保障需求 | 来源保障要求中可能需要行动编排组织的需求摘要 |
| 建议覆盖内容 | 若未来成为 active 行动编排，可能覆盖的 Context、Gate、证据、验证、同步或缺口分流方向 |
| 典型触发 | 未来判断是否需要创建、合并、拆分或废止该建议实例时可参考的触发场景 |

## 3. 建议行动编排实例矩阵

以下是 01 当前建议的行动编排实例。它们只用于说明保障机制可如何被行动编排接管，不表示 v2 已创建对应规范，不表示编号已占用，也不表示必须拆成独立流程。

| 建议行动编排实例 | 建议接管的保障需求 | 建议覆盖内容 | 典型触发 |
|---|---|---|---|
| 规范创建与修改行动编排 | 创建、修改、迁移、拆分、合并、重命名规范时的 00/01/active 原文核对、附件拆分判断和 Human Gate | 未来可覆盖 Context、Scenario、执行顺序、Gate、证据、Code 诊断、回写和同步检查 | 新建 v2 规范、迁移 v1 原文、修改身份块、改变编号或附件授权 |
| 规范审核行动编排 | 审计规范是否偏离 00、是否重复维护、是否缺保障、是否可被 AI 稳定执行 | 未来可覆盖价值一致性审查、职责边界审查、事实源单一性审查、附件越界审查、Code 诊断复核和后续分流 | 单篇规范完成后、跨规范冲突、价值判断争议、长期未审计 |
| 保障准备度审核行动编排 | 检查规范保障要求是否已有入口、能力资产、Code、Web、Human Gate、环境适配或人工降级路径 | 未来可覆盖保障要求准备度判断、能力缺口识别和接管缺口分流 | 保障机制声明变更、能力资产变化、环境适配前、声明 ready 前 |
| 规范生命周期同步行动编排 | 规范、附件、编号、身份块、保障要求、知识地图输入或 Code 消费入口变化后的联动复查 | 未来可覆盖目录、附件、知识地图、Code、Web、运行时扩展、相关规范和待补齐事项同步核对 | active 切换、重命名、废弃、合并、拆分、保障要求类型变化、关系类型变化 |

若某个建议行动编排实例未来成为 active 行动编排，应在其成员自描述中登记接管来源，并在自身正文中说明接管范围、输入来源、执行边界、验证方式、证据位置、Human Gate 条件和失败降级方式。

## 4. 接管建议辅助核对表

接管建议辅助核对至少包括：

| 检查项 | 标准 |
|---|---|
| 建议状态清晰 | 建议实例没有被写成 active 行动编排 |
| 接管边界回指 | 接管责任边界能回到 01 正文 |
| 类型回指 | 被建议接管的保障要求类型能回到 `01.Att.03` |
| 流程不越界 | 本文未定义行动编排 Context、Scenario、Gate、执行步骤、证据位置或回写规则 |
| 能力不替代流程 | Skill、Agent、Code、Web、Hook、CI 或环境入口没有替代行动编排接管责任 |

本核对表用于发现建议接管被误写成 active 接管、附件越界和能力资产替代流程的风险；核对结论不能替代 01 主文档规定的高影响确认。

## 5. 待补齐事项

1. 后续创建行动编排规范时，应逐项核对本文建议实例是否需要合并、拆分、改名或废止；
2. v2 Code 解析实现后，应检查接管建议矩阵是否需要输出诊断状态；
3. 若某类保障要求在实践中反复需要同一流程接管，应优先考虑建立或激活对应行动编排，而不是继续扩大来源规范正文。
