## 1. 定位

本文承载 v2 术语表、推荐表达、不推荐表达和替代写法。01 正文定义术语归口、术语应用关系和变更治理；本文只承载可被 AI、Code、Web、运行时扩展和知识地图读取的术语条目。

术语条目只定义名称、推荐表达、边界和禁止误用，不定义事实模型字段契约、状态机、流程 Gate、事实源回写规则、Code 输出 Schema、Web 页面契约或运行时扩展适配细则。

## 2. 术语条目结构

术语表使用以下结构：

| 字段 | 含义 |
|---|---|
| `术语` | 推荐中文表达 |
| `类别` | 术语所属范围 |
| `含义` | 术语本体定义 |
| `边界` | 不应混同或不得用于指代的内容 |
| `迁移来源` | 对应 v1 术语来源或本轮新增来源 |
| `状态` | draft、confirmed、needs_review 或 removed |

不推荐表达表使用以下结构：

| 字段 | 含义 |
|---|---|
| `不推荐表达` | 应避免的新正文表达 |
| `推荐表达` | 应替换为的表达 |
| `处理方式` | 改写、按上下文拆分、保留历史原文或待确认 |
| `说明` | 为什么不推荐或如何判断 |

## 4. 不推荐表达与替代写法

| 不推荐表达 | 推荐表达 | 处理方式 | 说明 |
|---|---|---|---|
| 知识图谱 | 知识地图 | 改写 | v2 推荐“知识地图”，强调由规范结构和 Code 派生的定位关系 |
| 图谱投影 | 知识地图 / 派生视图 | 按上下文拆分 | 指整体关系视图时用知识地图；指展示结果时用派生视图 |
| 工作闭环 | 运行闭环 | 改写 | v1 已要求优先使用运行闭环；v2 00 不展开生命周期细则 |
| 平台 | 环境 | 改写或保留历史原文 | 吸收到规范正文时应改写为环境 |
| 平台能力 | 环境能力 | 改写 | 避免把外部产品能力误写成 LDVH 全局能力 |
| 能力项 | 环境能力 / 适配项 / 适配措施 | 按上下文拆分 | 区分环境客观能力、适配卡片条目和具体适配措施 |
| 承接机制 | 保障机制 / 适配方式 / 适配措施 | 按上下文拆分 | 规范层用保障机制，环境层用适配方式，具体结果用适配措施 |
| 机制混同关系 | 规范保障要求 + 能力保障 + 环境适配 | 拆分 | 不得把三层机制写成一个关系 |
| 机制承接关系 | 规范保障要求 + 能力保障 + 环境适配 | 拆分 | 无法确认环境实体时先进入待补齐事项 |
| 事实对象 | 工作对象 / 工作对象实例 | 改写 | 避免与事实源混淆 |
| 状态 | 对象状态 / 集合状态 / 检查过程状态 / 派生状态 / 适配措施状态 | 加限定词 | 状态必须说明类型 |
| 检查报告 | 具体检查结果 / 部署适配检查报告 | 按上下文拆分 | 不作为固定流程输出名称 |
| 待补齐项 | 待补齐事项 | 改写 | 中文显示统一使用待补齐事项 |
| 输入材料 | 参考与研究材料 | 改写 | 不作为正式层级使用 |
| 来源文档 | 来源 | 改写 | 来源可能包括规范、sources、studies、命令输出、Human Gate 记录或其他事实源 |

## 5. 中文定语规则

中文“规则”“技能”“代理”“智能体”“工具”“程序”“展示”“机制”等词不得裸用，除非上下文已经通过标题、表格字段或段落首句明确限定其语义。

| 场景 | 推荐用语 | 避免裸用 |
|---|---|---|
| specs 中的稳定条款 | 正式规范、规范规则、规范要求 | 规则 |
| 事实模型字段、状态、验收、检查 | 字段规则、状态规则、验收规则、对象检查 | 规则 |
| 行动编排 Context、Scenario、Gate、执行、回写、证据 | 行动规则、Scenario 识别条件、Gate 条件、回写要求 | 规则、触发规则 |
| 检查、校验、验证、审计 | 检查方式、校验命令、验证证据、审计范围 | 检查、校验、验证、审计裸用且无上下文限定 |
| 写入和回写 | 写入动作、受控写入、事实源回写、回写位置 | 写入、回写裸用且无事实源或权限限定 |
| AI 泛称 | AI 执行者、AI 代理能力、子 Agent | 代理、智能体 |
| 确定性实现 | Code 实现、工具、脚本、校验器、命令入口 | 程序 |
| Web 能力 | Web、Human-facing 页面、信息同步、受控交互 | 展示 |
| 运行时扩展 | Rules、Skills、Agents、Hooks、运行时扩展承载物 | 机制、能力裸用且无上下文限定 |

## 6. 术语变更影响检查

新增、改名、废止或改变术语边界时，应检查：

1. 是否影响 00 的存在理由、AI 第一服务对象、六类构成要素、事实源底层原则或 V1-V10；
2. 是否影响 01 的规范身份、附件授权、知识地图关系、引用纪律或 Code 消费入口；
3. 是否影响事实模型、行动编排、Code、Web、运行时扩展、事实源、Git 追溯或测试验证规则；
4. 是否需要同步不推荐表达、中文定语规则、Code 常量、知识地图节点类型或 Web 展示文案；
5. 是否触发 Human Gate。

## 7. Human Gate

以下情况应评估 Human Gate：

1. 改变 00 已确认的核心术语，例如六类构成要素、事实源、运行时扩展、V1-V10；
2. 允许非 01 规范维护本文已定义术语的权威定义；
3. 删除不推荐表达而不提供替代写法；
4. 将知识地图、派生视图、Web 页面状态或工具输出升级为事实源；
5. 将环境、环境能力、环境入口或适配措施写成 LDVH 构成要素。

Human Gate 只能由 Human 完成确认、授权、方向校正或验收。AI 可以准备术语影响范围、替代写法、风险和待确认事项，但不得把术语检查结果替代 Human Gate。

## 8. AI 检查要求

检查至少包括：

| 检查项 | 标准 |
|---|---|
| 术语归口 | 术语定义进入 01 和本文；其他规范只说明应用关系 |
| 表达一致 | 新正文优先使用推荐表达 |
| 不推荐表达 | 不推荐表达已改写、拆分或保留为历史原文 |
| 中文定语 | 高风险裸词已有上下文限定 |
| 上位一致 | 未反向改写 00 的最高价值锚点 |

AI 检查要求用于发现术语漂移、不推荐表达残留、裸词风险和上位概念冲突；检查结论不能替代 Human 对核心术语变更的确认。
