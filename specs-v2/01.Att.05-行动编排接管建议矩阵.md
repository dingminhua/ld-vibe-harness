## 1. 定位

本文承载 01 授权的普通保障要求与行动编排接管关系、建议行动编排实例矩阵和接管写法。

01 正文定义规范保障要求的声明原则、五字段契约和行动编排接管边界；`01.Att.03-规范保障要求类型表.md` 承载保障要求类型闭集。本文只维护建议接管矩阵和非 active 声明口径，不得定义具体行动流程、Scenario、Context、Gate、证据位置、回写规则或成员自描述。

本文中的行动编排名称均为建议实例，不占用编号，不表示 active，不表示必须拆分为独立流程。后续是否合并、拆分、改名或不创建，由 01 主文档和后续行动编排规范统一判断。

## 2. 普通保障要求与行动编排接管

普通保障要求描述需要保障的维度。行动编排接管负责把一个或多个保障要求组织成可执行闭环。

| 普通保障维度 | 普通保障要求回答的问题 | 何时建议行动编排接管 |
|---|---|---|
| 上位约束承接 | 谁必须承接本规范，如何避免反向补全和第二事实源 | 承接判断需要在创建、修改、迁移或审计规范时重复执行 |
| 入口可见 | AI/Human 如何定位本规范、入口摘要或授权附件 | 入口读取顺序、恢复重读、STOP 点或环境入口需要稳定执行 |
| 流程复用 | 哪些判断、顺序或步骤需要复用 | 流程跨多个步骤、多人/多 AI 会话或多个能力资产 |
| 子 Agent 思考 | 哪些争议、高风险或跨规范冲突需要独立视角 | 独立审查需要明确输入、输出、主控回收和 Gate 条件 |
| 确定性执行 | 哪些结构、引用、状态或输出可机械检查 | Code 结果需要和 AI 判断、证据、Gate 或回写组成闭环 |
| Human 交互 | 哪些确认、授权、验收或高影响选择不能由 AI 自行推进 | Human Gate 需要明确触发条件、确认事项、证据和回写位置 |
| 生命周期触发 | 哪些变化后需要复查、同步、迁移或降级判断 | 变化影响多个规范、附件、能力资产、Code、Web 或运行时入口 |

以下写法只辅助表达 01 正文已经定义的接管边界，不独立规定接管责任。接管关系成立后，来源规范的保障机制写法应只保留规则来源、保障要求来源和接管引用；执行步骤、检查清单、验证责任、证据组织、Human Gate、缺口分流、关闭判断和后续同步责任由 active 接管行动编排在自身规范中定义。

无 active 行动编排可定位时，保障机制写法应标注为“建议由某行动编排接管”“待接管缺口”或“人工降级检查”，不得写成已经接管或已经 ready。

## 3. 建议行动编排实例矩阵

以下是 01 当前建议的行动编排实例。它们只用于说明保障机制可如何被行动编排接管，不表示 v2 已创建对应规范，不表示编号已占用，也不表示必须拆成独立流程。

| 建议行动编排实例 | 建议接管的保障需求 | 应承担的责任 | 典型触发 |
|---|---|---|---|
| 规范创建与修改行动编排 | 创建、修改、迁移、拆分、合并、重命名规范时的 00/01/active 原文核对、附件拆分判断和 Human Gate | 组织 Context、Scenario、执行顺序、Gate、证据、Code 诊断、回写和同步检查 | 新建 v2 规范、迁移 v1 原文、修改身份块、改变编号或附件授权 |
| 规范审核行动编排 | 审计规范是否偏离 00、是否重复维护、是否缺保障、是否可被 AI 稳定执行 | 执行价值一致性审查、职责边界审查、事实源单一性审查、附件越界审查、Code 诊断复核和后续分流 | 单篇规范完成后、跨规范冲突、价值判断争议、长期未审计 |
| 保障准备度审核行动编排 | 检查规范保障要求是否已有入口、能力资产、Code、Web、Human Gate、环境适配或人工降级路径 | 按保障要求类型判断 ready/partial/blocked/needs_human_gate，识别能力缺口和接管缺口 | 保障机制声明变更、能力资产变化、环境适配前、声明 ready 前 |
| 规范生命周期同步行动编排 | 规范、附件、编号、身份块、保障要求、知识地图输入或 Code 消费入口变化后的联动复查 | 触发目录、附件、知识地图、Code、Web、运行时扩展、相关规范和待补齐事项同步核对 | active 切换、重命名、废弃、合并、拆分、保障要求类型变化、关系类型变化 |

若某个建议行动编排实例未来成为 active 行动编排，应在其成员自描述中登记接管来源，并在自身正文中说明接管范围、输入来源、执行边界、验证方式、证据位置、Human Gate 条件和失败降级方式。

## 4. 接管建议辅助核对表

接管建议辅助核对至少包括：

| 检查项 | 标准 |
|---|---|
| 建议状态清晰 | 建议实例没有被写成 active 行动编排 |
| 接管边界回指 | 接管责任边界能回到 01 正文 |
| 类型回指 | 被建议接管的保障要求类型能回到 `01.Att.03` |
| 流程不越界 | 本文未定义行动编排 Context、Scenario、Gate、执行步骤、证据位置或回写规则 |
| 能力不替代流程 | Skill、Agent、Code、Web、Hook、CI 或环境入口没有替代行动编排接管责任 |

本核对表用于发现建议接管被误写成 active 接管、附件越界和能力资产替代流程的风险；核对结论不能替代 01 主文档规定的高影响确认。

## 5. 待补齐事项

1. 后续创建行动编排规范时，应逐项核对本文建议实例是否需要合并、拆分、改名或废止；
2. v2 Code 解析实现后，应检查接管建议矩阵是否需要输出诊断状态；
3. 若某类保障要求在实践中反复需要同一流程接管，应优先考虑建立或激活对应行动编排，而不是继续扩大来源规范正文。
