> 创建日期：2026-06-08
> 定位：定义 docs/specs 中具体工作模型规范文档的写作骨架、章节边界、引用规则和检查要求
> 适用范围：`docs/specs/21-39` 具体工作模型规范文档
> 上位依据：`docs/specs/03-文档基础规范.md`
> 相关规范：`docs/specs/03.01-规范文档规范.md`、`docs/specs/03.03-索引文档规范.md`、`docs/specs/05-工作模型基础规范.md`、`docs/specs/05.01-工作字段内容格式规范.md`、`docs/specs/09-事实源边界与承载规范.md`

---
## 1. 本文解决的问题

本文解决具体工作模型规范文档应如何书写的问题，包括文档骨架、章节边界、字段契约表达、事实源边界表达、机制适配摘要、规范落地要求和检查要求。

本文只规定工作模型规范文档的写作方式。工作模型的定义、准入、通用规则、状态流转原则和实例边界由 `docs/specs/05-工作模型基础规范.md` 定义；字段内容格式由 `docs/specs/05.01-工作字段内容格式规范.md` 定义。

---
## 2. 与 00 和 05 的关系

00 定义工作模型是 LDVH 五类构成要素之一。05 定义工作模型基础规则和具体工作模型的标准组成。本文承接 03 的文档治理规则和 05 的模型组成要求，把具体工作模型应包含的规则转换为可写、可审、可校验的文档骨架。

具体工作模型规范不得通过文档结构反向改变 05 的通用规则；如具体模型确需例外，应在对应章节说明例外原因，并按 05 的 Human Gate 要求处理。

---
## 3. 适用文件

20 是工作模型集合索引，按 `docs/specs/03.03-索引文档规范.md` 编写。21-39 是具体工作模型规范，按本文编写。

具体工作模型规范文件名采用：

```text

```

文件名不得重复“工作模型规范”字样。新增具体工作模型规范时，不默认创建 `NN.01` 至 `NN.06` 固定机制子文档。

## 5. 字段契约表达

字段契约应使用稳定表格或结构化代码块表达，至少说明字段名、含义、类型、是否必填、默认值或状态约束、内容格式和消费方。

字段契约不得把字段内容格式、Web 渲染组件或 Code 校验实现写成字段定义本身。字段内容格式应引用 `docs/specs/05.01-工作字段内容格式规范.md`；Code 和 Web 只作为消费方或实现方。

---
## 6. 适配规则表达

适配规则用于说明 AI、Rules / Instructions、Skill、Agent、Code、Web 或契约能力如何消费该工作模型。

适配规则应只保留摘要和引用关系，不得复制完整运行投影、Skill 正文、Code 实现说明或 Web 设计稿。需要实现或投影时，应回到 04 系列、07、08 或对应运行实体处理。

## 8. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 改变具体工作模型规范的标准骨架；
2. 允许具体工作模型规范省略标准组成且无说明；
3. 恢复固定机制子文档作为工作模型完整性要求；
4. 将 Code、Web、Skill 或 Agent 实现说明提升为字段契约权威来源；
5. 改变字段契约、状态机、事实源边界或对象关系表达方式。

工作模型文档检查至少包括：

| 检查项 | 标准 |
|---|---|
| 骨架 | 覆盖本文 §4 标准章节，缺项已说明 |
| 上位依据 | 上位依据指向 05，相关规范按内容引用 02、03、05.01、09、07、08 |
| 字段契约 | 字段名、类型、必填性、内容格式和消费方清晰 |
| 事实源边界 | 实例位置、权威字段和派生视图边界清晰 |
| 固定子文档 | 未恢复 `NN.01` 至 `NN.06` 固定机制子文档 |
| 适配摘要 | 适配规则只保留摘要和引用，不复制实现正文 |
