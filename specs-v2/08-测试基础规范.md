## 1. 本文解决的问题

本文定义 LDVH 中测试、验证和回归如何跨规范体系、事实模型、行动编排、Code、Web、运行时扩展和事实源保持一致。

本文解决：

1. 自动化测试、命令校验、等价验证、Human 验收和回归验证如何分层；
2. 测试要求、测试实现细则、测试代码和测试输出分别归属于哪里；
3. AI 何时可以声明“已验证”、何时必须声明“未验证”或“等价验证”；
4. 测试证据、测试输出、覆盖率、截图、trace、缓存和报告为什么不能替代事实源；
5. 规范、Code、Web、行动编排或事实源规则变化后，如何触发测试同步；
6. 测试与 Code 确定性执行、Web Human-facing 展示、行动编排可测试性锚点和 Git 追溯之间如何分工。

本文不定义具体测试框架、测试文件清单、命令实现、Web 页面测试细节或 Code 输出 Schema。具体实现细节由对应实现域和测试文件承接。

## 2. 上位依据

本文承接 `00-LDVH理念与价值标准.md` 的验证闭环要求。测试是 LDVH 让 AI 输出可验证、Human 判断有证据、Code 提供确定反馈、Web 展示可信状态的方法之一。

本文承接 `01-规范体系基础规范.md` 的规范结构要求。本文必须声明测试治理的权威域、迁移来源、active 事实源、相关规范、Code 消费入口、保障要求、Human Gate 和待补齐事项。

若本文与 00 的价值判断、01 的规范治理规则或 07 的事实源边界冲突，以 00、01 和 07 为准。

## 3. 构成要素归属与价值判断

本文是跨构成要素验证基础规范，不是第七类或第八类构成要素。测试服务六类构成要素的可验证性，但不替代任何构成要素的本体规则。

正向价值判断：

| 价值 | 本文如何服务 |
|---|---|
| V4 稳定执行 | 通过测试入口、验证声明和回归要求让 AI 不只依赖主观判断 |
| V5 Human Gate | 区分自动化验证、等价验证和 Human 验收，避免机械检查替代高影响确认 |
| V6 结果可验证 | 规定“已验证”必须有可复现入口、关键输出或明确等价步骤 |
| V7 证据沉淀 | 规定测试证据如何回指命令、样例、输出和事实源，而不成为第二事实源 |
| V9 Human 可见 | 让 Web 或过程输出展示验证状态时能区分通过、失败、未运行和残留风险 |

逆向价值判断：

| 反模式 | 本文必须阻止 |
|---|---|
| 用未运行测试冒充已验证 | 未执行、失败或不可复现的验证不得写成完成结论 |
| 用测试输出替代事实源 | 覆盖率、截图、trace、缓存和报告不能替代规范、对象或 Git 记录 |
| 用测试实现反向定义规则 | 测试代码不能反向定义字段契约、状态机、Human Gate 或行动流程 |
| 把测试归入单一 Code 附件 | 测试是跨构成要素验证治理，不是 Code 附件 |
| 忽略 Web 或行动编排测试 | Web 暂不实施不等于 Web 契约和行动可测试性可以丢失 |

## 5. 测试治理分层

测试治理按三层分工：

| 层级 | 承载位置 | 职责 |
|---|---|---|
| 上层测试要求 | 本文和对应构成要素规范 | 定义验证纪律、事实源边界、测试归属、同步触发和 Human Gate |
| 实现测试细则 | Code、Web、运行时扩展或对应实现域文档 | 定义当前实现的测试入口、命令、夹具组织、执行方式和失败处理 |
| 测试实现 | `tests/` 或对应实现域测试目录 | 承载可执行测试代码、最小夹具、正反样例和回归样例 |

同一规则不得在 specs、实现文档和测试代码中复制维护为多个权威来源。

## 6. 验证声明与证据边界

LDVH 认可以下验证方式：

| 验证方式 | 适用场景 | 声明要求 |
|---|---|---|
| 自动化测试 | 成功条件、失败条件和输入输出可机械复现 | 说明测试入口、关键覆盖点和结果 |
| 命令校验 | 文档结构、引用、构建、格式、类型或 CLI 行为可由命令稳定反馈 | 说明命令、退出状态和关键输出 |
| 等价验证 | 自动化测试暂不可行，但可通过最小样例、人工检查或现有工具复现关键风险 | 说明原因、替代步骤和残留风险 |
| Human 验收 | 涉及授权、确认、体验判断或高影响选择 | 说明确认对象、影响范围、用户选择和证据位置 |
| 回归验证 | 修复问题、迁移结构或改变输入输出后防止复发 | 说明复现样例、失败前表现和通过条件 |

AI 只能在验证方式、关键输出和残留风险可复现时，把变更表述为已验证。无法建立完整测试时，应说明原因、采用的等价验证方式和残留风险。

测试证据用于支持判断，不成为最终事实源。测试输出、覆盖率、截图、缓存、Mock 数据、浏览器 trace 和临时报告不得替代 Git 文件事实源、规范正文、工作对象或 Human Gate 记录。

## 7. 同步触发规则

以下变化应检查测试要求、实现测试细则和测试实现是否需要同步：

1. 规范身份、编号、引用关系、章节结构、保障要求或 Human Gate 变化；
2. 事实模型字段契约、状态机、对象关系、事实源边界或受控写入规则变化；
3. 行动编排的 Context、Scenario、Gate、执行流程、回写、证据或可测试性锚点变化；
4. Code CLI、输入输出、错误码、诊断格式、写入行为、目录假设或知识地图投影变化；
5. Web API、页面、组件、派生视图、写入白名单、Confirm UI、i18n 或来源呈现变化；
6. 运行时扩展入口、Skill、Agent、Hook、Rules 或环境适配方式变化；
7. 测试目录、测试命令、测试夹具、Mock 数据、构建入口或验证入口变化；
8. 工作项关闭、验收、发布、迁移或删除实现前，需要确认验证证据是否仍可复现。

## 8. 规范保障要求

本文通过以下规范保障要求说明相关要求的同步、检查或审计触发条件。

| 保障要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 上位约束承接要求 | Code、Web、行动编排、运行时扩展和事实源相关测试治理应遵守本文定义的验证声明、测试归属和测试证据边界 | 本文、对应构成要素规范、07、实现域文档、测试实现 | 测试治理 | 测试归属、验证声明或证据边界变化时 |
| 入口可见要求 | AI 执行需要验证、回归或验收的任务时应能定位本文 | Rules 入口、行动编排 Context、Code/Web 实现文档、人工降级检查 | AI 执行入口提示 | 测试基础规范文件名、定位、适用范围或入口引用变化时 |
| 确定性执行要求 | 可机械化的测试目录、测试归属、文档引用和验证入口应由 Code 检查或记录缺口 | Code 检查、测试、CI、人工降级检查 | 校验实现 | 测试目录规则、测试命令、测试文件映射或验证入口变化时 |
| Human 交互要求 | 改变测试归属、验证声明标准、测试结果事实源性质或验收证据边界前应评估 Human Gate | Human Gate、影响范围说明、确认记录 | 测试治理确认 | 测试结果可能影响任务关闭、验收、事实源回写或高影响发布时 |
| 生命周期触发要求 | 规范、Code、Web、行动编排、运行时扩展或测试实现变化后，应检查本文和对应实现文档是否需要同步 | 规范修改执行顺序、实现文档联动检查、测试回归、人工降级检查 | 触发保障 | §7 任一同步触发场景发生时 |

## 9. Human Gate 与检查要求

以下情况必须暂停并等待 Human 确认：

1. 改变 `tests/` 或长期测试分区的目录定位、事实源性质或构成要素归属；
2. 将测试结果、测试缓存、覆盖率、截图、Mock 数据、trace 或测试报告提升为稳定事实；
3. 改变“已验证”“等价验证”“完整验证”“未验证”的声明标准；
4. 删除高价值测试、回归样例或验收证据且缺少替代验证方式；
5. 用测试实现反向定义 specs 规则、对象字段契约、状态机、Human Gate 或行动编排；
6. 接受测试治理、关键验证或回归入口长期降级。

测试治理检查至少包括：

| 检查项 | 标准 |
|---|---|
| 分层归属 | 上层要求在 specs，当前实现细则在实现域文档，可执行测试在测试实现目录 |
| 验证声明 | 已验证、等价验证、残留风险和未验证状态表达准确 |
| 事实源边界 | 测试输出、缓存、夹具和报告未替代 Git 文件事实源 |
| 同步联动 | 规范、实现、文档和测试变更后已检查对应联动 |
| 失败处理 | 测试失败或关键验证未运行时未关闭任务、验收或提交完成结论 |
