## 机器输入与输出

| 入口 | `operation_key` | 标准输入 | 默认标准输出 |
|---|---|---|---|
| `ldvh capabilities` | 无；响应为 `null` | 零个或一个 UTF-8 JSON 请求对象；空输入等同 `{}` | 一个 UTF-8 JSON 响应对象 |
| `ldvh capabilities <operation_key>` | 命令位置必填 | 零个或一个 UTF-8 JSON 请求对象；空输入等同 `{}` | 一个 UTF-8 JSON 响应对象 |
| `ldvh call <operation_key>` | 命令位置必填 | 零个或一个 UTF-8 JSON 请求对象；空输入等同 `{}` | 一个 UTF-8 JSON 响应对象 |

默认机器输出不得在 JSON 对象前后混入提示、进度、日志或第二个结果对象。可选 Human 文本模式必须由显式输出选项选择，并与机器结果保持相同语义；标准错误不得承载机器调用方取得完整结果所必需的唯一信息。

Helper 进程已经开始处理但请求 JSON 无法解析、顶层不是对象、出现未知共同字段或字段类型错误时，仍返回 `invalid_request` 机器响应。可执行文件不存在、进程无法创建或进程在形成响应前被操作系统终止，不属于已经形成 Helper 服务响应的情况。

## 共同请求字段

请求对象使用下列字段闭集。默认值只用于字段没有出现；显式 `null` 只在表中允许时有效。

| 字段 | JSON 类型 | 要求与默认值 | 含义与边界 |
|---|---|---|---|
| `task` | string | 可选；出现时非空 | 当次目标描述；不成为稳定事实或规则 |
| `work_object_locators` | array | 可选；默认为空列表；成员为 string 或 object | 语义服从 02；保留每个原始定位符，不由 `cwd` 静默覆盖 |
| `arguments` | object | 可选；默认为空对象 | 具体操作来源定义其字段闭集；通用发现时必须为空对象 |
| `requested_disclosure` | string 或 null | 可选；默认为 `null`；非空时只允许 `L0`、`L1`、`L2`、`L3`、`L4` | 语义服从 01；不要求逐层请求 |
| `response_profile` | string | 可选；默认为 `compact`；只允许 `compact` 或 `diagnostic` | 选择共同证据与诊断信息的组织粒度；不得改变领域结果、范围、外层结果或实际读写行为 |
| `observed_context` | object | 可选；默认为空对象 | 只承载操作确需的当次可观察输入；具体字段由操作来源定义。<br/>受控事实写入使用 `signature` 子字段：object，闭集恰为 `product_name`、`model_name`、`agent_runtime_name`；每项为 string 或 null，三项均为 null 时不可写入。该完整快照按 05 §11.0 的判定与 05.Att.01 `change-log-signature` 的取值约定替换注入最新 `change_log` 条目的 `signature`，不得从草稿、Git 身份或字段默认值推断。创建与 update 类写入的最新流水必须使用当前形状；历史 `agent_id` / `host_environment`、`model_id` / `host_name`、`model_id` / `agent_workbench` 形状仅供读取。事实写入（create/update/close）操作要求 `observed_context` 必须提供当前环境署名；调用方必须逐项确认三字段，任一项为 null 时在本次写入前向 Human 明确告知缺失项及原因，不得静默遗漏或推断替代。任一但非全部字段为 null 时，该披露不是阻断条件；结构完整且非全空的快照仍是有效写入输入。只有快照缺失、缺键、混入未知键、非 null 值不是非空 string / 归一后为空，或三项全为 null 时写入不可用（create 返回 `invalid_request`，update/close 返回 `unavailable`）。非写入操作（读取、发现、迁移、规范化、治理、precheck 等）由各自操作来源要求 `observed_context` 为空。该子字段不构成新的顶层共同字段 |
| `authorization_reference` | array | 可选；默认为空列表；成员使用“来源回指字段” | 只引用已经存在且作用范围明确的 Human 决定或授权来源，不证明技术结果 |

`operation_key` 不在 JSON 请求对象中重复出现。厂商 payload 或环境侧数据不得被直接提升为共同请求字段。

命令位置中的 `operation_key` 必须匹配 `[a-z][a-z0-9]*(?:-[a-z0-9]+)*`。该格式只约束公开操作标识的稳定机器表示，不从名称推断领域语义、版本、实现模块或环境。

## 公开操作声明字段

定义领域公开操作的当前来源在正文中至多设置一个标题为 `Helper 公开操作` 的 H3，并在标题后紧接下列固定 Markdown 表格：

| `operation_key` | `summary` | `effect` | `arguments_contract` | `result_contract` |
|---|---|---|---|---|
| `example-operation` | 说明该公开操作提供什么服务 | `read` | `example-source::输入字段` | `example-source::结果字段` |

上述示例只展示结构，不定义 `example-operation`。每一行使用字段闭集：

| 字段 | 值类型 | 要求 | 含义与边界 |
|---|---|---|---|
| `operation_key` | string | 必填；匹配 `[a-z][a-z0-9]*(?:-[a-z0-9]+)*` | 在全部当前公开操作中唯一且不可改派的标识 |
| `summary` | string | 必填非空 | 说明该操作提供什么服务，不声明实现或当次可用 |
| `effect` | string | 必填；`read` 或 `may_change_state` | 与父规范的读取和受控状态变更边界一致 |
| `arguments_contract` | string | 必填；使用 `<source_key>::<精确标题文本>` | 回指同一当前来源正文或其授权附件中输入字段、类型、必填性、空值和闭集所在的完整标题章节 |
| `result_contract` | string | 必填；使用 `<source_key>::<精确标题文本>` | 回指同一当前来源正文或其授权附件中结果字段、类型、必填性、空值和闭集所在的完整标题章节 |

`source_key` 必须是声明操作的规范自身 `spec_key`，或者该规范当前授权附件的 `attachment_key`。精确标题文本必须在对应当前文件中唯一，表示从该标题到下一个同级或更高层级标题之前的完整章节；标题文本不得包含分隔符 `::`。引用无法唯一定位、指向草案或未获授权附件、或者目标章节缺少所声明的输入或结果契约时，操作声明不成立。

Code 只把当前规则源中符合上述固定 H3、表头和字段契约的表格行作为领域公开操作声明。草案中的表格、其它标题下的普通示例、实现注册表、tests 或缓存不能补造公开操作。`capabilities` 是父规范直接定义的服务发现入口，不作为领域操作写入该表格。

## 共同响应字段

共同响应对象使用下列字段闭集，全部字段必填：

| 字段 | JSON 类型 | 空值规则 | 含义与边界 |
|---|---|---|---|
| `contract` | string | 固定为 `ldvh-helper-cli/2` | 当前共同机器契约标识 |
| `response_profile` | string | `compact` 或 `diagnostic` | 回显实际采用的响应档位；无有效请求对象可供读取时固定为 `compact` |
| `request_kind` | string | `capabilities` 或 `call` | 标识实际处理的服务入口种类 |
| `operation_key` | string 或 null | 通用发现为 `null`；其它入口回显请求提供的非空 string | 无效 key 的回显只用于诊断，不使该值取得公开操作身份 |
| `outcome` | string | 不允许 `null` | 只允许父规范 §7.2 的七个 Helper 服务结果值 |
| `summary` | string | 必填非空 | Human 与 AI 可快速阅读的结果摘要，不替代结构化字段 |
| `result` | object 或 null | 没有结果时为 `null` | `capabilities` 使用本附件定义；`call` 由具体操作来源定义 |
| `scope` | object | 不允许 `null` | 使用“范围字段”；没有对象时使用空列表和 `null` |
| `sources` | array | 没有来源时为空列表并在 `gaps` 解释 | 成员使用“来源回指字段” |
| `disclosure` | object 或 null | 没有返回规范信息时为 `null` | 使用“披露字段” |
| `gaps` | array | 没有缺口时为空列表 | 成员使用“缺口字段” |
| `changes` | array | 读取和发现入口为空列表 | 成员使用“变化字段” |
| `verification` | array | 没有执行检查时为空列表 | 成员使用“验证字段” |
| `diagnostics` | array | 没有诊断时为空列表 | 成员使用“诊断字段” |
| `follow_up` | object | 不允许 `null` | 使用“后续字段”；没有 Helper 专属后续时各列表为空 |

共同响应不得增加未在本附件登记的顶层字段。具体操作只能在自身 `result` 对象内使用其当前来源定义的字段；`diagnostics[].details` 和来源回指的 `details` 只承载补充信息，不得用来绕过共同字段或领域 `result` Schema。

`compact` 与 `diagnostic` 都必须返回上述全部共同字段；没有内容的字段仍按表中空值规则返回。`compact` 可以把内容相同、作用范围一致且不会改变调用方决定的来源、资格缺口和机械检查聚合为集合级条目；资格缺口按规范化 `(code-or-null, normalized-summary, canonical-scope, canonical-source_refs)` 聚合，同一 key 最多一项，必须给出精确 `member_count` 并保留可回读的共同来源。`diagnostic` 应在 Code 实际掌握明细时逐项返回，不得为了填充档位制造不存在的检查或证据，其展开 gap 禁止出现 `member_count`。响应档位不得改变领域 `result`、顶层 `scope`、`outcome`、`changes`、实际执行行为或一次受控写使用的事件时点。

## 来源回指字段

| 字段 | JSON 类型 | 要求 | 含义与边界 |
|---|---|---|---|
| `kind` | string | 必填；去除首尾空白后至少保留一个字符 | 说明该来源是规则、事实源、Human 指令、配置、当次观察、外部来源或实现依据等实际种类；本附件不建立跨来源权威顺序 |
| `locator` | string | 必填；去除首尾空白后至少保留一个字符 | 按当前判断所需精度重新定位来源的位置或引用 |
| `version` | string | 可选；出现时去除首尾空白后至少保留一个字符 | 结论依赖特定版本、commit 或 ref 时提供。对有 Git 锚点的来源，应写实际 commit SHA（如 `d4677530`），不写 `当前 working tree` 等无法重建当时内容的占位文本；对无稳定版本含义的会话级或快照级来源，省略 version。|
| `observed_at` | string | 可选；出现时去除首尾空白后至少保留一个字符，并使用 [RFC 3339 Internet Date/Time Format](https://www.rfc-editor.org/rfc/rfc3339#section-5.6) | 来源会变化且结论依赖观察时点时提供；必须包含相对 UTC 的偏移 |
| `details` | object | 可选；默认为空对象 | 保留重新定位所需且不适合放入前三项的结构化上下文 |

来源回指对象使用字段闭集。这里及本附件其它位置所称 RFC 3339 时间，完整采用 05 §11 “Helper 公开操作”定义的当前严格常规形态：允许任意位小数秒的精确比较，要求已知 UTC 偏移而拒绝 `-00:00`，且不接受 `:60` 闰秒或其它未定义时间尺度；不得把它表述为已完整支持 RFC 3339 的全部闰秒语义。上述非空判断只用于拒绝纯空白值；Helper 不因该判断 trim 或改写含有实际内容的原字符串。`kind` 只区分实际来源身份，不自动决定权威、可信度或规则效力。

## 范围字段

| 字段 | JSON 类型 | 要求 | 含义与边界 |
|---|---|---|---|
| `requested` | array | 必填 | 当次请求明确包含或能够从当前操作确定的范围；成员为 string 或 object |
| `completed` | array | 必填 | 已经按本次服务契约完成的范围；成员为 string 或 object |
| `not_completed` | array | 必填 | 尚未完成、被拒绝、不可用、出错或未检查的范围；成员为 string 或 object |
| `governance_resolution` | object 或 null | 必填 | 其它操作需要携带 02 管辖解析结果时承载其完整结果；不需要、未形成，或具体操作的领域 `result` 本身就是该完整结果时为 `null` |

范围对象使用字段闭集。`completed` 只表示 Helper 服务在该范围形成了相应结果，不表示上层任务、Human Gate、测试或交付完成。

## 披露字段

| 字段 | JSON 类型 | 要求 | 含义与边界 |
|---|---|---|---|
| `requested` | string 或 null | 必填；只允许 `L0`–`L4` 或 `null` | 回显当次请求层级 |
| `parts` | array | 必填 | 每项包含 `level`、`source_refs` 和 `reason`，分别说明实际披露层级、来源回指和展开原因 |

`parts[].level` 只允许 `L0`–`L4`；`source_refs` 为非空来源回指列表；`reason` 为非空 string。同一响应混合多个层级时必须逐项区分，不能只返回一个最高层级覆盖其它部分。

## 缺口、变化、验证与诊断字段

四类条目均使用字段闭集：

| 条目 | 必填字段 | 可选字段 | 边界 |
|---|---|---|---|
| `gaps[]` | `summary`：非空 string；`scope`：array；`source_refs`：array | `code`：非空 string；`member_count`：正 integer | `code` 只有在当前 Helper 契约或具体操作来源已经定义其机器语义时才出现；`member_count` 只在 compact 聚合项中必填，diagnostic 展开项禁止出现 |
| `changes[]` | `summary`：非空 string；`status`：非空 string；`target`：string 或 object；`source_refs`：array | — | `status` 由具体状态变更操作来源定义；必须区分计划、实际发生、未发生和无法回读的情况 |
| `verification[]` | `check`：非空 string；`status`：非空 string；`scope`：array；`evidence`：array | — | `status` 与证据语义由具体操作来源定义；没有执行检查时不创建伪造条目 |
| `diagnostics[]` | `summary`：非空 string；`details`：object | `code`：非空 string；`source_refs`：array | `code` 只有在当前 Helper 契约或具体操作来源已经定义其机器语义时才出现；诊断只提供定位信息，不改变 `outcome`、来源规则或领域结果 |

`source_refs` 和 `evidence` 的成员使用“来源回指字段”。`code` 出现时必须通过条目的 `source_refs` 或共同 `sources` 回到定义其机器语义的当前来源；机器调用方不得脱离该来源跨操作解释。条目的本地 `code` 或 `status` 不形成全 LDVH 统一枚举；需要跨操作复用时必须先由相应当前来源定义。

compact gap 的 `member_count` 是聚合前 diagnostic-granularity 成员数，不是 scope 成员数；`normalized-summary` 是 summary 的当前 UTF-8 string，不作自然语言同义改写；`scope` 是全部成员 scope 按稳定 JSON identity 去重后的并集，`source_refs` 是共同来源的 canonical 投影。聚合不得吞掉 code、summary、来源或未完成范围不同的缺口，也不得用于全局合并具体操作自身已经具有独立领域语义的 gaps。

## 后续字段

| 字段 | JSON 类型 | 要求 | 含义与边界 |
|---|---|---|---|
| `summary` | string | 必填非空 | 简要说明是否存在 Helper 能够明确的后续信息 |
| `required_inputs` | array | 必填；成员使用“后续条目字段” | 继续同一请求仍需补充的输入 |
| `required_human_decisions` | array | 必填；成员使用“后续条目字段” | 已由来源规则识别且需要 Human 决定的事项；不得把普通缺口改写成 Human Gate |
| `resume_conditions` | array | 必填；成员使用“后续条目字段” | 暂停、拒绝、不可用或失败范围重新处理前必须满足的实际条件 |
| `suggested_operations` | array | 必填；成员使用“建议操作字段” | 来源和结果支持的可选后续公开操作 |

“后续条目字段”使用 `summary`：必填非空 string、`scope`：必填 array、`source_refs`：必填非空来源回指列表三个字段的闭集。“建议操作字段”在上述三个字段之外增加 `operation_key`：必填且匹配公开操作标识格式。每项 Human 决定、恢复条件和建议操作必须分别绑定其来源与受影响范围，不能只依赖顶层来源或总范围推断。

后续对象使用字段闭集。所有列表为空表示 Helper 没有能够从当前来源和结果确定的专属后续信息，不表示 AI 的普通求解路径必须停止或当前工作已经完成。建议操作必须已经由当前规则源定义，但不证明其当次可用，也不形成行动授权。

## capabilities 结果字段

`capabilities` 的 `result` 使用字段闭集：

| 字段 | JSON 类型 | 要求 | 含义与边界 |
|---|---|---|---|
| `mode` | string | 必填；`discovery` 或 `request_check` | 分别对应通用发现或针对单项操作的可用性检查 |
| `operations` | array | 必填 | 通用发现可以包含多项；单项检查恰好包含一个已定义操作 |

针对未知或格式无效 `operation_key` 的单项请求返回 `invalid_request`，共同响应回显请求值，`result` 为 `null`；不形成 `request_check` 结果，也不使该值取得公开操作身份。

`operations[]` 使用下列字段闭集：

| 字段 | JSON 类型 | 要求 | 含义与边界 |
|---|---|---|---|
| `operation_key` | string | 必填；匹配 `[a-z][a-z0-9]*(?:-[a-z0-9]+)*` | 当前来源定义的公开操作标识 |
| `summary` | string | 必填非空 | 当前来源中该公开操作的服务说明 |
| `sources` | array | 必填非空；成员使用“来源回指字段” | 至少回到定义公开操作语义的当前来源 |
| `effect` | string | 必填；`read` 或 `may_change_state` | 公开读取或可能改变状态的边界 |
| `required_inputs` | array | 必填；成员为非空 string | 当前来源定义的必需输入名称 |
| `optional_inputs` | array | 必填；成员为非空 string | 当前来源定义的可选输入名称 |
| `input_examples` | array | 必填；没有可用示例时为空数组 | 当前实现能够给出的、受来源约束的可组合输入片段；不构成完整请求、能力状态或行动授权 |
| `implementation` | object | 必填 | 使用“实现字段”；不构成长期能力状态 |
| `availability` | string 或 null | 通用发现必须为 `null`；单项检查必填非空 | 非空时只允许 `unavailable_for_request`、`partially_available`、`available_for_request` |
| `available_scope` | array | 必填 | 通用发现为空；单项检查记录可以调用的独立范围 |
| `unavailable_scope` | array | 必填 | 通用发现为空；单项检查记录不可调用或无法判断的范围 |
| `gaps` | array | 必填；成员使用“缺口字段” | 实现、证据、输入、配置、环境、授权或范围缺口 |
| `observed_at` | string | 必填非空；使用 [RFC 3339 Internet Date/Time Format](https://www.rfc-editor.org/rfc/rfc3339#section-5.6) | 本次发现或检查的观察时间；必须包含相对 UTC 的偏移 |

“实现字段”使用字段闭集：

| 字段 | JSON 类型 | 要求 | 含义与边界 |
|---|---|---|---|
| `present` | boolean | 必填 | 只说明当次是否发现对应实际实现 |
| `evidence` | array | 必填；成员使用“来源回指字段” | 支持实现存在及其范围的可复核依据；`present: false` 时为空列表 |

`input_examples[]` 使用字段闭集：`summary`、`arguments_fragment`、`source_refs`、`composition_note`。`summary` 与 `composition_note` 均为必填非空 string；`arguments_fragment` 为必填 object，只包含可与调用者已知范围组合的领域 `arguments` 片段，不复制共同请求字段，也不得假定或编造调用者尚未提供的实例值；`source_refs` 为必填非空“来源回指字段”列表，至少回指该片段所使用的领域输入契约。调用者仍须按该操作的共同与领域请求契约补齐其它必需输入、实际范围和授权；示例中的字段闭集、枚举和嵌套结构以所回指的操作来源为准，本附件不另建领域 Schema。

通用发现不计算当次操作可用性；单项检查必须使用实际提供的请求内容和范围。没有当前来源的内部实现不得进入 `operations`，只能在共同 `diagnostics` 中报告契约缺口，且不得为其补造 `operation_key`。

## 具体操作结果与扩展

`call` 的 `result` 必须是对象或 `null`。具体操作来源负责定义对象字段、类型、必填性、空值、闭集和兼容边界；Code、tests、环境入口和 Web 不得另建第二份领域结果 Schema。

具体操作来源需要返回 full-v4 Working Tree 证据 DTO 时，只在自身 `result` 中声明一个 object 字段，并精确回指 `working-tree-test-evidence-fields::Working Tree 证据 DTO 字段`；该字段的值必须原样符合所回指契约。本附件不复制该 DTO 的任何成员、枚举或指纹规则，也不改变共同 `verification[].evidence` 仍只使用“来源回指字段”的现有结构。

共同请求与响应顶层、各共同嵌套对象和 `capabilities` 结果都是闭集。需要新增共同字段时先修改父规范及本附件；只属于某项公开操作的数据进入该操作的 `arguments` 或 `result`，不得塞入 `diagnostics.details`、来源 `details` 或 Human 文本模式绕过契约。

`contract: "ldvh-helper-cli/2"` 是当前共同机器契约的唯一值。该值不表示产品、规范或事实版本；没有当前来源支持时，不建立多版本共存机制。`ldvh-helper-cli/1` 不与当前契约并行提供；调用方必须按当前来源同步共同请求与响应字段。

### 时间字段 Canonical 与兼容边界

Helper 新生成的 `observed_at`、事件时间及其它带时刻语义的输出统一使用 RFC 3339 UTC `Z` 形式。读取既有事实或调用方传入的明确 UTC 偏移值时必须保持兼容，并按 instant 解释；本兼容规则不要求、不授权迁移或重写历史事实。纯日期不作为 instant 解析；无法解析的时间必须作为诊断暴露，不能伪造当前时间。
