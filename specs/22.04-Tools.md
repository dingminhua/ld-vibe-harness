## 1. 本文定位

本文是 `specs/22-Change-变更记录.md` 的附件型实践子文档（编号 22.04），承接 Tools 契约式校验实践。本文不是独立事实模型，不得重新定义 Change 的对象定位、准入条件、状态机、对象关系、Human Gate、字段契约、事实源回写或证据留存。发生冲突时，以 22 主文档和上位基础规范为准。

本文是 Change Tools 命令、参数、测试和能力声明的权威位置。Change 的 commit message 格式校验依据 `specs/22.06-Contract.md`。

---

## 2. 实践目标

为 Change 提供可重复、可校验的 Tools 辅助能力，帮助 AI 和人在提交前检查 commit message 是否符合 `specs/22-Change-变更记录.md` §8 定义的格式规范，以及是否与 `specs/22.06-Contract.md` 定义的契约一致。

当前 Tools 为只读校验，不执行任何写入操作。commit 写入由 Git 原生命令执行，不需要 Tools 受控写入。

---

## 3. 适用场景

1. AI 在 commit 前自检 commit message 格式是否合规；
2. 落地审计时批量检查历史 commit 是否符合格式规范；
3. 持续检查项目中最近 N 条 commit 的格式合规率。

---

## 4. 实践边界

1. 当前 Change Tools 实体路径为 `tools/check_22_commit_format.py`；
2. 当前 Change Tools 为只读校验工具，不执行写入操作；
3. 当前 Change Tools 通过 `git log --format` 读取 commit 历史，按 `specs/22.06-Contract.md` 定义的格式契约进行校验；
4. Change Tools 输出属于运行时派生结果，不是最终事实源；Git commit 历史是 Change 的最终事实源；
5. Change Tools 字段校验依据 `specs/22.06-Contract.md`，不得自行扩张契约；
6. Change Tools 不替代 Human Gate，不执行 commit 操作。

---

## 5. 实践内容

`tools/check_22_commit_format.py` 当前提供以下能力：

| 能力 | 说明 |
|---|---|
| 格式解析 | 通过 `git log --format` 读取最近 N 条 commit，解析 header/body/Refs |
| type 校验 | 检查 type 是否在 `specs/22.06-Contract.md` 定义的有效枚举中 |
| scope 校验 | 检查 scope 是否在推荐枚举中（非强制，warning） |
| subject 长度校验 | 检查 subject 是否超过 72 字符 |
| Refs 存在性检查 | 检查是否包含 Refs: 行（非强制，warning） |

### 5.1 命令参数

| 参数 | 说明 |
|---|---|
| `-n N` / `--count N` | 检查最近 N 条 commit（默认 10） |
| `--no-warnings` | 只显示 error，不显示 warning |

### 5.2 命令调用示例

```bash
# 检查最近 10 条 commit
python3 tools/check_22_commit_format.py

# 检查最近 20 条 commit，只显示 error
python3 tools/check_22_commit_format.py -n 20 --no-warnings
```

### 5.3 测试

测试文件路径：`tests/tools/test_check_22_commit_format.py`

测试命令：

```bash
python3 -m pytest tests/tools/test_check_22_commit_format.py -v
```

测试覆盖范围：
- type 有效/无效枚举校验
- scope 有效/无效推荐值校验
- subject 长度超限校验
- 第一行格式解析（含/不含 scope）
- Refs 缺失 warning
- 空 subject 检测

---

## 6. Human Gate

以下情况应评估 Human Gate：

1. Change Tools 扩展为执行 commit 写入操作；
2. Change Tools 改变 commit message 格式校验依据；
3. Change Tools 将运行时派生结果持久化为新的事实源。

---

## 7. 检查项

检查 Change Tools 契约式校验实践是否合规时，应确认：

1. `tools/check_22_commit_format.py` 是否读取 Git commit 历史并将校验结果输出为运行时结果；
2. Change 格式校验是否依据 `specs/22.06-Contract.md`；
3. Tools 输出是否未被当作 Change 最终事实源；
4. Tools 是否未替代 Human Gate、未执行 commit 操作；
5. 新增或修改 Tools 能力时是否同步更新 `tests/tools/test_check_22_commit_format.py`；
6. 契约子文档变更后，Change Tools 实现和测试是否已同步更新（依据 `specs/04-LDVH模型子文档规范.md` §7.4、§8）。
