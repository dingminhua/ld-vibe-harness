四项工作中的“管辖配置”不新增独立环境入口：其配置来源、字段与解析算法唯一回指 02，当次解析经已交付的 `helper-cli` 公开操作执行。`helper-cli` 源码 launcher 未交付时，管辖配置的源码模式验证同样保持迁移缺口，不得借此新建另一 AI 路由或环境 adapter。

## Helper 最小调用形态

稳定源码 Helper launcher 交付后，请求 JSON 经 stdin 传入；最小形态如下（占位符不是当前可执行命令）：

```bash
echo '{"arguments": {}}' | <RESOLVED_SOURCE_HELPER> call <operation_key>
```

无请求输入的入口（如通用 capabilities）同样无条件读 stdin 至 EOF：交互终端之外的调用必须闭合 stdin。源码 launcher 尚未交付时不得执行该占位形态，也不得把不明 PATH 命令写成当前入口。

共同请求字段闭集与默认值以 `specs/attachments/04.Att.01-Helper CLI 请求与响应字段表.md` 的当次内容为准；源码 Helper launcher 交付后，各操作自己的必填与可选参数先经该 launcher 的通用 capabilities 或指定操作 capabilities 现取，再按回指章节的当次内容构造 `arguments`。试调返回 `invalid_request` 时读取响应 `gaps` 与 `diagnostics` 中的契约问题并据以修正，不得变换参数值盲目重试。

## 技能登记字段值

目标环境登记技能要求提供字段时，各字段值的权威来源：技能名称、描述与指令正文照抄 `skill/SKILL.md`（`skill-template` 行）frontmatter 与正文的当次内容，不重述不改写；许可证与作者署名见源码仓库 `LICENSE` 当次版权声明行；源码身份与版本以 `git remote`（存在时）、当前 revision 和工作树状态为准；图标素材见 `skill-icons` 行。环境私有扩展字段（厂商专属 frontmatter 键或 sidecar 文件）不由 LDVH 预填，按目标环境当次官方资料在接入时判定。本附件不登记任何厂商目录、表单或字段名。

## 入口选择

目标环境 AI 必须先读取当前环境资料，再判断原生事件与上述入口的语义是否对应：

1. 宿主原生提供生命周期事件及所需对象时，才可把该对象传给 `work-context-core`；宿主不提供时，薄 Skill 按 09 §5.4 精确读取规则引导，不新增环境 Hook 或 adapter。不得仅因事件、cwd 或任务文字调用 `context-recovery`。
2. AI 在理解 Human 目标后明确需要项目事实时，才可使用 `context-recovery`；也可以按来源定义直接使用相应 Helper 事实读取能力。两种入口都不判断事实适用、行动允许或完成。
3. AI 主动读取或变更 LDVH 能力时，使用已解析且状态为已交付的源码 Helper launcher，不从环境事件猜测 Helper 字段，也不使用不明 PATH 命令。
4. 只有实际 Git `commit-msg` 事件才能连接 `git-commit-msg-gate`；AI 环境中名称相似的阻断事件不能自动视为等价。每次事件必须保留 actual worktree、当次 Index 与 commit message 的独立绑定。
5. `git-hook-manager` 只管理承接 Git Gate 的 Git Hook，不是通用 AI 环境 adapter。目标能力按 common-dir 部署并覆盖共享它的主/现有/后续 linked worktree；纳入接入目标的独立 clone 必须单独部署。
6. 具体环境来源必须先声明当前单元实际承接的原生事件及版本/范围；每次行动再按 `specs/33-环境接入行动模板.md` 为四项工作与这些事件形成一次性的验证矩阵。入口清单不维护跨厂商事件登记，也不证明任何事件已真实触发。
7. 只有环境接入、管辖配置、Git Hook 部署与验证所需的当前入口和链路都可成立，才按 `specs/09-环境接入规范.md` 和 Human Gate 形成完整方案；任一必需入口尚未交付或链路缺失时保持 `unverified`/`unsupported`，不得以 manifest、环境 Hook、插件、启动脚本或 adapter 补造另一接入层。

不得为了适配方便另造统一厂商 payload、通用事件路由、默认语义或 adapter 登记。若当前入口不能承接目标环境真实输入和反馈，应保持 `unverified` 或依据肯定证据报告 `unsupported`，不能改写入口契约；`context-recovery` 不是环境 Hook 对新能力不兼容时的替代路径。

## 环境侧实现边界

LDVH 接入面不存在环境 Hook、插件或 adapter 层（`specs/09-环境接入规范.md` §5.1）；本仓库不收纳、不维护任何具体 AI 环境的环境侧实现。目标环境不能直接加载 canonical SKILL.md 或连接所需原生 Git 事件时，按 09 §8 如实判定能力，不新增并行接入形态。
