# V4 历史事实对象选择性吸收决定

> 记录性质：本文记录 Human 对 V2、V3 历史事实实例进入 V4 的当前范围决定。它不是规则源，不授权写入，也不使任何历史内容自动取得 V4 身份。
> 决定日期：2026-07-19
> 当前状态：全量逐项处置进行中；尚未完成对象级选择或实例吸收。

## 1. Human 决定

V4 的迁入收口范围包含两份彼此独立的历史事实源，并对每一份来源输入完成处置：

1. V2：`dev-v2@f5f117fe7f4e7d905adcf9034b48fc7d5de115ed` 的 75 项末次 V2 事实对象（39 Spark、21 WorkCase、14 Study、1 Pitfall）；
2. V3：当前仓库 `archive/v3/ldvh-base` 中已冻结的 92 项历史事实对象（49 Spark、24 WorkCase、17 Study、2 Pitfall）。

两份来源合计 167 条待评估的来源输入。这个数字只表示审计覆盖面，不表示 167 项必须承接，也不表示将创建 167 个 V4 对象。V2 与 V3 应先按问题、证据和后续责任识别谱系；同一持续问题可以由一个最小的 V4 当前事实承接多个来源输入，但每个来源输入仍必须得到可回读的单独处置结论。

历史对象不继承 V4 的 Schema、字段、状态、路径、身份、时间、关系、实现或历史生命周期效力。只有 Human 确认仍具当前价值且需要继续推进的最小内容，才依据当时有效的 V4 来源重新建立当前事实。旧 WorkCase 默认先作为 Spark 候选重新判断；除非 Human 另行确认它是当前真实责任，才建立新的 V4 WorkCase。

判断“仍具当前价值”的主标准是它对 LDVH **未来**是否具有明确净价值，而不是旧对象是否完成、是否与 V4 存在字面等价实现，或是否能原样复制。评估必须依次回答：

1. 它是否会带来未来仍需要的新能力、风险降低、决策依据或可复用经验；
2. 这些价值是否尚未被当前 V4 来源以足够方式承接；已有部分承接只能缩小内容，不能自动否定其余未来价值；
3. 是否能在当前边界下收敛为一个最小、可读、可继续判断的 Spark，或在 Human 已确认目标、范围和成功标准时成为 WorkCase；
4. 其收益是否大于恢复旧架构、旧状态机、兼容层或无目标建设带来的成本与风险。

“仅保留 archive”或“已经过时”只适用于无法通过上述未来价值判断的内容。历史 WorkCase 已关闭、V4 已有部分能力、旧环境未选择或实现路径已经变化，都不是单独充分的排除理由。

对 Pitfall 适用更严格的吸收规则：若其中的失败模式对 LDVH 未来仍有价值，必须提炼并吸收进职责相符的当前 Specs，作为稳定的边界、反例、禁止条件、验证要求或停止条件；需要机械落实时再由相应 Code/tests 承接。不得只把有未来价值的 Pitfall 复制为新的 V4 Pitfall 而不形成当前规则。原 Pitfall 留在 archive，作为该规则的历史动机和追溯证据；无法提炼为稳定规则的内容才只保留 archive。

## 2. 逐项处置口径

每个 V2 或 V3 来源输入都必须形成下列四种结论之一：

1. **建立当前 V4 事实**：具有当前价值且存在明确的后续推进需要；
2. **已由 V4 承接**：其最小当前价值已被现有 V4 规则、实现、验证或事实覆盖；
3. **仅保留 archive**：具备历史、研究或证据价值，但不形成当前工作；
4. **已经过时**：前提、方案或问题已不再成立，不形成当前工作。

处置可以收窄、拆分、合并或改用另一合法事实类型。来源之间的同题合并必须保留各自的来源回指和各自处置结论，不能用“与另一版本重复”省略评估。未被选择的对象继续留在原历史位置，不产生待办、缺口或 V4 承接义务。

## 3. 迁入与推进边界

实际写入不由本决定授权。任何已选择的最小内容仍须通过当时有效的 V4 合法创建边界，并完成回读、验证和 Git 留痕。如果现有来源或 Code 不能合法承载所选范围，应停止该项并单独评估缺口；不得以迁入为由自动新增兼容层、迁移状态机、中央登记、专用行动模板、批处理 Code 或 Web 写入能力。

当前顺序是：

1. 完成 167 条 V2/V3 来源输入的逐项处置，并由 Human 确认实际拟吸收的最小范围；
2. 对已选择、仍具当前价值且需要继续推进的最小范围，使用现有 V4 合法创建边界重新建立当前事实；
3. 迁入收口后恢复 V4 Web 只读观察，以当前 V4 事实源呈现所选对象的列表、详情与状态；
4. 随后由 Human 选择真实受管辖工作，进行纵向 dogfood；
5. 再依据实测决定其它 Web V4 bridge 范围、原生 Windows、LDVH 自身 CI 和发布准备。

## 4. 与既有 V3 决定的关系

`V4-V3事实对象选择性吸收决定.md` 保留 V3 来源的既有审计依据和当时边界。自本决定起，其中仅以 V3 92 项作为当前迁入收口完整范围、或据此表达当前顺序的表述，由本文的 V2+V3 范围替代；其余 V3 历史事实不变。
