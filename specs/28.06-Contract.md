## 1. 本文定位

本文定义 TaskSet 事实模型使用的结构化数据契约。本文解决 TaskSet YAML 实例应包含哪些字段、字段类型和约束是什么、文件命名规则是什么、状态流转契约是什么，以及工具实现应如何消费本契约的问题。

本文是 TaskSet 事实模型契约字段的权威位置。本文是 `specs/28-TaskSet-任务集.md` 的附件型契约子文档，不是独立事实模型。本文不得重新定义 TaskSet 的对象定位、准入条件、状态机语义、Human Gate、事实源回写或证据留存要求。发生冲突时，以 28 主文档和上位基础规范为准。

本文不承载执行逻辑、流程步骤或 Human Gate 条款（依据 `specs/04-LDVH模型子文档规范.md` §7.1）。

## 2. TaskSet YAML Schema

### 2.1 基础字段

TaskSet 基础字段遵循 `specs/13-LDVH事实模型基础规范.md` §7.3 的字段契约原则，所有事实模型应包含基础字段。

| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | TaskSet 对象 ID，格式为 `taskset-{NNNN}` |
| `type` | string | 是 | 固定为 `taskset` |
| `title` | string | 是 | 任务集标题 |
| `status` | string | 是 | TaskSet 状态，必须属于标准状态枚举 |
| `created` | date | 是 | 对象创建日期 |
| `updated` | date | 是 | 最近更新日期 |

### 2.2 扩展字段

| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `description` | string | 是 | 任务集详细描述 |
| `scope` | string | 是 | 任务集范围描述 |
| `background_doc` | string | 否 | 背景文档路径，指向描述任务集背景、目标和约束的 Markdown 文件 |
| `source_intent` | string | 否 | 关联 Intent ID |
| `related_profile` | string | 否 | 关联 Profile ID |
| `tasks` | list of string | 是 | 关联 Task ID 列表，默认空列表 |
| `related_adrs` | list of string | 否 | 关联 ADR ID 列表 |
| `related_evidence` | list of string | 否 | 关联 Evidence ID 列表 |
| `closed_at` | date | 条件必填 | 仅当 `status` 为 `closed` 时必须填写 |
| `closure_evidence` | string | 条件必填 | 仅当 `status` 为 `closed` 时必须填写，关闭证据摘要 |

### 2.3 完整 YAML 示例

```yaml
id: taskset-0001
type: taskset
title: LDVH 核心事实模型建设
status: active
created: 2026-06-04
updated: 2026-06-04
description: 承载 LDVH 核心事实模型（Intent、Task、TaskSet、Evidence）的规范编写和实例验证工作
scope: LDVH 事实模型规范体系中的核心执行实体模型，包括 Intent、Task、TaskSet 和 Evidence
background_doc: docs/tasksets/core-fact-model-background.md
source_intent: intent-0001
related_profile:
tasks:
  - task-0001
  - task-0002
related_adrs: []
related_evidence: []
closed_at:
closure_evidence:
```

## 3. 字段约束

1. `status` 必须属于 TaskSet 标准状态枚举：`planned`、`active`、`review_needed`、`closed`；
2. `type` 必须固定为 `taskset`；
3. `closed_at` 仅在 `status: closed` 时必填，其他状态下不得填写；
4. `closure_evidence` 仅在 `status: closed` 时必填，其他状态下不得填写；
5. `source_intent` 应引用已存在的事实模型 ID，引用无效时应标记为校验警告；
6. `related_profile` 应引用已存在的事实模型 ID，引用无效时应标记为校验警告；
7. `tasks` 应引用已存在的事实模型 ID，引用无效时应标记为校验警告；
8. `related_adrs` 应引用已存在的事实模型 ID，引用无效时应标记为校验警告；
9. `related_evidence` 应引用已存在的事实模型 ID，引用无效时应标记为校验警告；
10. `id` 格式必须为 `taskset-{NNNN}`，编号固定 4 位，从 `0001` 起递增；
11. `created` 和 `updated` 使用 ISO 8601 日期格式（`YYYY-MM-DD`）；
12. `closed_at` 使用 ISO 8601 日期格式（`YYYY-MM-DD`）；
13. `tasks`、`related_adrs`、`related_evidence` 为列表类型，可为空列表，不得省略字段后以 null 替代空列表；
14. `background_doc` 引用的文件路径应存在，引用无效时应标记为校验警告。

## 4. 文件命名契约

TaskSet 实例文件命名规则：

```text
taskset-{NNNN}-short-title.yaml
```

约束：

1. 编号从 `0001` 起递增，固定 4 位；
2. 英文短标题使用小写短横线命名；
3. 每个项目独立编号，不使用跨项目全局编号；
4. 文件存放位置为 `ldvh-base/tasksets/`；
5. 文件名变化必须同步检查所有引用该 TaskSet 的 `tasks` 字段（在 Task 实例中为 `taskset` 字段）和其他关联字段。

## 5. 状态流转契约

TaskSet 状态语义和流转规则由 `specs/28-TaskSet-任务集.md` §5 定义，本文只提供结构化枚举和流转矩阵供 Tools 校验消费。

### 5.1 标准状态枚举

| 标准状态 |
|---|
| `planned` |
| `active` |
| `review_needed` |
| `closed` |

状态含义依据 `specs/28-TaskSet-任务集.md` §5.1。

### 5.2 合法状态流转

| 当前状态 | 可流转至 |
|---|---|
| `planned` | `active` |
| `active` | `review_needed` |
| `review_needed` | `closed`, `active` |
| `closed` | 无 |

`review_needed` → `active` 为退回流转，应记录退回原因。

流转语义和约束依据 `specs/28-TaskSet-任务集.md` §5.2。

## 6. 契约消费声明

1. Tools 辅助程序解析 TaskSet 时应依据本文定义的 YAML schema 和字段约束，不得自行扩张格式契约（依据 `specs/12.01-Tools辅助规范.md` §6.1）；
2. Tools 辅助程序校验 TaskSet 时应覆盖字段完整性、状态合法性、条件必填和引用有效性；
3. Tools 辅助程序读取 TaskSet 时可依据本文状态枚举和字段契约执行状态筛选、详情解析和关联字段解析，但 TaskSet 读取结果是否可作为当前执行依据由 28 主文档和 Skill 流程判断；
4. 实践子文档和工具可以消费本文契约，但不得复制维护契约字段第二事实源（依据 `specs/04-LDVH模型子文档规范.md` §7.2）；
5. 修改本文契约属于规范变更，应评估 Human Gate 并记录 Change（依据 `specs/04-LDVH模型子文档规范.md` §7.3）（依据 specs/22-Change-变更记录.md）；
6. 契约子文档应先于工具实现创建，工具实现不得在没有契约子文档的情况下自行定义字段名、字段类型或字段约束（依据 `specs/04-LDVH模型子文档规范.md` §7.4）；
7. 本文契约变更时，消费本文的 Tools 实现和对应测试必须同步更新（依据 `specs/04-LDVH模型子文档规范.md` §7.4、§8）。

## 7. 检查项

检查本文是否被正确使用时，应确认：

1. TaskSet YAML 实例字段是否完整，必填字段是否齐全；
2. `status` 是否属于标准状态枚举；
3. `type` 是否固定为 `taskset`；
4. `closed` 状态的 TaskSet 是否已填写 `closed_at` 和 `closure_evidence`；
5. `source_intent` 引用的事实模型 ID 是否有效；
6. `related_profile` 引用的事实模型 ID 是否有效；
7. `tasks` 引用的事实模型 ID 是否有效；
8. `related_adrs` 引用的事实模型 ID 是否有效；
9. `related_evidence` 引用的事实模型 ID 是否有效；
10. `background_doc` 引用的文件路径是否有效；
11. 文件命名是否符合 `taskset-{NNNN}-short-title.yaml` 格式；
12. 状态流转是否合法，是否存在非法流转；
13. 终态 TaskSet 是否存在重开情况；
14. 退回流转是否记录了退回原因；
15. 工具实现是否依据本文 schema 解析和校验，未自行扩张格式契约；
16. 修改本文是否记录 Change，并在必要时触发 Human Gate（依据 specs/22-Change-变更记录.md）
