# 环境入口适配与部署规范

> 创建日期：2026-06-13
> 更新日期：2026-06-17
> 所属主文档：`specs/04-规范落地与环境适配基础规范.md`
> 关系：专题子文档
> 定位：定义各 AI 开发环境如何通过环境入口接入、部署并适配检查 LDVH 能力资产
> 适用范围：环境入口、薄引用、环境适配、部署步骤、适配检查、成功条件、失败处理、降级方式、Human Gate
> 上位依据：`specs/04-规范落地与环境适配基础规范.md`、`specs/04.02-LDVH能力资产与落地保障规范.md`、`specs/02-术语规范.md`

本文是 AI 帮用户执行环境接入和部署的直接依据。本文不定义 LDVH 能力资产本身，不记录长期用户本地安装状态，不把一次适配检查结果写成环境类型结论。

---

## 1. 本文解决的问题

本文解决以下问题：

1. 某个 AI 开发环境提供哪些环境入口；
2. 这些环境入口如何接入 04.02 定义的 LDVH 能力资产；
3. AI 如何在授权边界内帮助用户执行部署；
4. 部署前、部署后和声明完成前如何执行适配检查；
5. 接入失败、环境不支持、权限不足或证据不足时如何降级或 Human Gate。

用户本地状态不是长期事实源。它只能来自本文定义的适配检查，并作为当前过程输出、Code 输出、Web 当前视图或对话证据摘要呈现；不得把这些输出保存为长期“已安装 / 已启用 / 已验证”状态。若适配检查形成需要长期追溯的稳定结论、后续工作、决策、风险、经验或变更，必须按 `specs/09-事实源边界与承载规范.md` 的事实源归属和 `specs/06-工作流程基础规范.md` 的 Human Gate 最小证据结构，回写到对应工作对象、Change / Git commit records、Human Gate 证据落点或其他 Git 文件事实源。

## 2. 环境适配字段

每个环境入口适配项至少包含：

| 字段 | 必填 | 含义 |
|---|---|---|
| 环境类型 | 是 | 适用的 AI 开发环境类型 |
| 环境入口 | 是 | 该环境实际读取、加载、调用、触发、配置、展示或执行某类环境能力的位置或机制 |
| 对应 LDVH 能力资产 | 是 | 04.02 中定义的 Rules、Skill、Agent、Hook 或其它能力资产 |
| 接入方式 | 是 | 薄引用、配置、安装、软链、受控复制、人工降级等 |
| 部署步骤 | 是 | AI 如何帮用户接入该资产 |
| 写入权限 | 是 | 是否可自动写入，是否需要 Human Gate |
| 适配检查 | 是 | 如何现场判断接入已生效 |
| 成功条件 | 是 | 满足什么才能声明本次接入有效 |
| 失败处理 | 是 | 缺入口、无权限、不可读、环境不支持时如何处理 |
| 适配降级 | 是 | 无原生入口时如何模拟或人工降级 |
| 禁止声明 | 是 | 哪些情况下不得声明原生完整支持或部署完成 |
| 证据输出 | 是 | 应呈现给 Human 的证据 |
| 证据状态 | 是 | 已验证、待验证、仅参考、待补齐或不适用 |

`docs/sources/` 和外部资料只能作为输入证据或待吸收材料，不能作为 specs 上位依据。正式适配结论必须写成已吸收结论、实测证据摘要、Human Gate 记录引用或待补齐事项。

## 3. 适配状态

| 状态 | 含义 |
|---|---|
| 原生承载 | 环境提供原生入口或机制承载对应能力资产 |
| 配置适配 | 通过配置、安装、路径、软链或等价方式接入 |
| 指令适配 | 通过环境指令、会话提示或薄引用显式引导 |
| 人工降级 | 缺少稳定环境入口，通过人工检查或手动命令替代 |
| 仅作参考 | 当前信息只能作为候选输入，不能声明可用 |
| 待确认 | 缺少来源证据、实测证据或 Human Gate 确认 |

适配状态不是用户本地安装状态，也不表示当前机器已经部署成功。

## 4. 部署与适配检查规则

### 4.1 部署前检查

部署前必须确认当前环境类型、当前工作区和目标项目边界、环境入口是否存在、目标 LDVH 能力资产是否存在、是否有写入权限、是否存在用户已有配置需要保护、是否触发 Human Gate。

Rules 环境入口部署前只检查 Trae Work 环境族和 Codex App 两类环境；其中 Trae Work 环境族包含 Trae CN 与 Trae 国际版两个入口变体。AI 应先检查用户环境是否存在对应入口或入口目录：Trae CN 检查用户主目录下 `.trae-cn/` 与 `.trae-cn/user_rules/ldvh_rules.md`，Trae 国际版检查用户主目录下 `.trae/` 与 `.trae/rules/ldvh_rules.md`，Codex App 检查用户主目录下 `.codex/` 与 `~/.codex/AGENTS.md`。若上述环境入口均未发现，应停止部署并提示 Human 当前没有发现可部署的环境入口；不得创建未发现环境的入口目录来制造“已发现”结论。若发现一个或多个环境入口，应通过 Human Gate 以多选方式确认安装到哪些入口；不得默认全选，不得静默写入。

Rules 环境入口部署不记录长期“已写入本机入口”状态，也不把本次写入结果写入 specs、docs、Task、Memo、ADR 或其它长期事实源。AI 只能在当前对话中说明本次操作结果和检查结论；环境是否在后续会话中实际读取，必须以后续现场检查为准。

### 4.2 部署执行

部署执行应优先使用薄引用、配置、软链或安装方式。只有在环境明确无法引用、Human 授权且有退出方式时，才允许受控复制。

部署不得复制完整 specs 正文，不得创建第二事实源，不得覆盖用户已有配置而不保留说明。

部署 AI 必须先定位当前 LDVH 仓库根目录，定义 `<LDVH_REPO_ROOT>` 为当前被部署的 LDVH 仓库根目录绝对路径，定义 `<LDVH_RULES_ENTRY>` 为 `<LDVH_REPO_ROOT>/rules/LDVH-AI-ENTRY.md`。写入薄引用前，AI 必须确认 `<LDVH_RULES_ENTRY>` 存在且可读；若不存在或不可读，应停止部署并提示 Human 当前 LDVH Rules 资产不可定位。规范模板中的 `<LDVH_RULES_ENTRY>` 只用于表达部署变量，实际写入环境入口时必须替换为当前机器上的真实绝对路径；不得把示例路径、其它用户机器路径或相对路径写入用户环境入口。

薄引用正文只应包含入口指向、压缩或恢复后的重读提示、以及用于区分 LDVH 管理段的开始和结束标记。部署约束、禁止声明、事实源边界、Human Gate 要求、恢复上下文的详细来源和适配检查要求不得混入薄引用正文。

### 4.3 部署后适配检查

部署后必须检查环境入口文件、配置或机制是否存在，薄引用是否指向正确的 LDVH 能力资产，目标资产是否可读，是否复制了不应复制的完整正文，是否满足成功条件，是否仍需 Human Gate。

### 4.4 声明完成前检查

AI 声明部署完成前必须输出证据摘要。证据至少包含环境类型、环境入口、对应 LDVH 能力资产、检查时间、检查方式、检查结论、失败项和降级项。

未完成适配检查时，不得声明部署完成。适配检查失败时，不得把失败写成环境类型不支持，也不得把人工降级写成原生完整支持。

## 5. 环境入口适配矩阵

本节只覆盖当前已纳入适配范围的 Trae Work 环境族与 Codex App。Trae Work CN 与 Trae Work 国际版视为同一环境族下的两个入口变体，默认共用 Trae Work 的环境能力边界；只有路径、加载行为、权限、配置或适配检查存在差异时，才在表格中单列变体，避免重复维护通用能力说明。LDVH 通用环境入口默认写入用户级或系统级目录，不以项目目录作为默认入口；项目目录只承载项目专属入口、兼容入口、测试入口或显式降级入口。候选入口可以写入本文，但必须标注证据状态、适配检查、禁止声明和降级路径；不得把候选入口写成本机已部署状态或环境完整支持结论。

### 5.1 Trae Work 环境族

Trae Work 环境族的 LDVH 通用入口应优先写入用户级或系统级入口。项目 Rules、项目 Skill、AGENTS / CLAUDE 兼容入口只用于项目专属约束、兼容读取或显式降级，不作为 LDVH 通用入口默认落点。Trae Work 环境族的环境入口应区分 Rules、Skill、Commands、自动运行设置、Hook（`.trae/hooks.json`）、AGENTS / CLAUDE 兼容入口。已吸收的外部资料和实测摘要显示，Trae Work 环境族可通过 `.trae/hooks.json` 配置生命周期事件（SessionStart、UserPromptSubmit、PreToolUse、PostToolUse、Stop、Notification）；外部资料只作为输入证据，不作为本文上位依据。但具体环境是否安装、启用或支持仍需现场实测验证，不得仅凭外部资料声明当前机器已完整支持。

#### 5.1.1 Rules / Instructions 入口

| 能力意图 | 环境入口 | macOS / Linux 位置 | Windows 位置 | 证据来源 | 证据状态 | 接入方式 | 适配检查 | 禁止声明 |
|---|---|---|---|---|---|---|---|---|
| LDVH 用户级 Rules | Trae CN 用户级 Rules 入口 | 用户主目录下 .trae-cn/user_rules/ldvh_rules.md | 用户主目录下 .trae-cn/user_rules/ldvh_rules.md | Trae Rules 机制资料、Human 确认 | Human 已确认 CN 路径；仍需当前机器实测加载 | 薄引用 / 配置适配 | 检查用户当前使用 Trae CN 而非国际版、文件存在、内容只通过薄引用指向 LDVH Rules 资产且未复制 specs 正文 | 不得把 Trae CN 路径套用于国际版；不得在未开启新会话或未实测加载前声明已生效 |
| LDVH 用户级 Rules | Trae 国际版用户级 Rules 入口 | 用户主目录下 .trae/rules/ldvh_rules.md | 用户主目录下 .trae/rules/ldvh_rules.md | Human 确认 | Human 已确认国际版路径；仍需当前机器实测加载 | 薄引用 / 配置适配 | 检查用户当前使用 Trae 国际版而非 Trae CN、文件存在、内容只通过薄引用指向 LDVH Rules 资产且未复制 specs 正文 | 不得把 Trae 国际版路径套用于 Trae CN；不得在未开启新会话或未实测加载前声明已生效 |
| 项目 Rules | Trae 项目规则目录 | `<repo>/.trae/rules/` | `<repo>/.trae/rules/` | Trae Rules 机制资料 | 已有资料，仍需当前项目实测 | 项目专属薄引用 / 显式降级 | 检查规则文件存在、front matter 生效方式明确、内容指向项目专属约束或 LDVH 管辖提示 | 不得把项目 Rules 当作 LDVH 通用入口默认落点 |
| 子目录 Rules | 子目录 `.trae/rules/` | `<repo>/<subdir>/.trae/rules/` | `<repo>/<subdir>/.trae/rules/` | Trae Rules 机制资料 | 已有资料，需按目录实测 | 薄引用 / 配置适配 | 检查规则目录不超过 3 层嵌套，且只在相关目录文件被读取或提及时声明生效 | 不得声明对子目录无关文件全局生效 |
| AGENTS 兼容入口 | AGENTS 兼容文件 | 仓库根目录 AGENTS 兼容文件 或相关子目录 AGENTS 兼容文件 | 仓库根目录 AGENTS 兼容文件 或相关子目录 AGENTS 兼容文件 | Trae Rules 机制资料 | 已有资料，需确认 Trae 导入开关 | 薄引用 / 指令适配 | 检查文件存在、入口内容只导航到 LDVH Rules 资产、Trae 设置已开启包含 AGENTS | 未确认导入开关前不得声明 Trae 已自动读取 |
| CLAUDE 兼容入口 | CLAUDE 兼容文件 / CLAUDE 本地兼容文件 | 仓库根目录 CLAUDE 兼容文件、仓库根目录 CLAUDE 本地兼容文件 | 仓库根目录 CLAUDE 兼容文件、仓库根目录 CLAUDE 本地兼容文件 | Trae Rules 机制资料 | 已有资料，需确认 Trae 导入开关 | 兼容入口 / 指令适配 | 检查文件存在、入口边界清楚、Trae 设置已开启包含 CLAUDE | 不得把兼容入口写成 LDVH 首选入口 |

Rules 环境入口中的薄引用内容应只承担发现、导航、约束提醒和交还职责。LDVH 通用 Rules 薄引用默认写入用户级或系统级 Rules 环境入口；只有项目专属规则、仓库内兼容入口或 Human 明确要求时，才写入项目目录。长期规范正文仍以 `specs/` 为准。

Trae 用户级 Rules 薄引用模板如下。实际写入时应将 `<LDVH_RULES_ENTRY>` 替换为当前机器上的真实绝对路径：

```markdown
#### LDVH AI 入口引用开始

读取并遵守：

<LDVH_RULES_ENTRY>

发生上下文压缩、会话恢复或规则重新加载后，重新读取上述 LDVH AI 入口。

#### LDVH AI 入口引用结束
```

#### 5.1.2 Skill 入口

LDVH 在 Trae Work CN 中的 Skill 适配应声明为全局 Skill 优先。项目级 Skill 只用于项目专属能力，不作为 LDVH 通用能力的默认承载位置。

| 能力意图 | 环境入口 | macOS / Linux 位置 | Windows 位置 | 证据来源 | 证据状态 | 接入方式 | 适配检查 | 禁止声明 |
|---|---|---|---|---|---|---|---|---|
| LDVH 全局 Skill | Trae 全局技能目录 | `~/.trae-cn/skills` | `%userprofile%/.trae-cn/skills` | Trae Skills 机制资料、Human 确认 | 已有资料，需本机路径检查 | 安装 / 配置适配 | 检查 Skill 目录存在、每个 Skill 含 Skill 入口文件、元数据完整、description 能触发正确任务 | 不得把未安装的全局 Skill 声明为可用 |
| 项目 Skill | Trae 项目技能目录 | `<repo>/.trae/skills/` | `<repo>/.trae/skills/` | Trae Skills 机制资料 | 已有资料，需当前项目实测 | 项目专属安装 / 显式降级 | 检查是否确为项目专属能力、没有覆盖全局 LDVH 通用 Skill 意图 | 不得把项目 Skill 当作 LDVH 通用全局 Skill 默认入口 |
| Agent Skills 兼容入口 | `.agents/skills/` | `<repo>/.agents/skills/` | `<repo>/.agents/skills/` | Trae Skills 机制资料 | 已有资料，需重名优先级检查 | 兼容入口 / 人工降级 | 检查与 `.trae/skills/` 是否重名，重名时按 Trae 优先级处理 | 不得忽略 `.trae/skills/` 对同名 Skill 的优先级 |

Trae Skill 写作和检查应吸收 Trae Skill 写作最佳实践资料 的稳定结论：Skill 入口文件 应保持单一职责，声明正向触发和负向排除，输入输出结构化，步骤可执行，失败策略明确，并采用渐进式披露。Skill 不得写成知识库全集，也不得把 Skill 模拟写成 Hook 原生能力。

#### 5.1.3 Hook、Commands、自动运行设置与降级处理

| 能力意图 | Trae 可用机制 | 证据来源 | 证据状态 | 适配方式 | 适配检查 | 禁止声明 |
|---|---|---|---|---|---|---|
| 生命周期事件自动触发 | `.trae/hooks.json` 原生 Hook（SessionStart、UserPromptSubmit、PreToolUse、PostToolUse、Stop、Notification） | Trae Hook 机制外部资料 | 已有第三方实测报告（OODER A2UI 团队 2026-06-15），需当前环境实测 | 原生 Hook 配置 / 指令适配 | 检查 hooks.json 存在、事件名有效、命令可信、enabled 为 true；实测验证事件可按预期触发 | 不得仅凭外部资料声明当前机器已完整支持；未实测前不得声明 PreToolUse 覆盖所有工具 |
| 重复流程触发 | Commands / 显式会话指令 | Trae Hook 机制外部资料 | 已有资料，需当前环境确认 | 指令适配 / 人工降级 | 检查命令或显式步骤是否能被 Human 或 AI 主动触发 | 不得声明为自动生命周期 Hook |
| 风险操作控制 | 自动运行 MCP、自动运行命令、Human Gate、PreToolUse Hook | Trae Hook 机制外部资料 | 已有资料，需当前设置确认 | 安全配置 / Human Gate / Hook 配置 | 检查自动运行模式、白名单、黑名单、需确认操作；若使用 PreToolUse Hook，需额外检查 matcher 精准度和 deny 语义 | 不得把自动运行设置写成自定义审批 Hook；PreToolUse deny 不能覆盖所有 shell 或非 MCP 工具 |
| 不可模拟的 Hook 意图降级 | Rules、Skill、Commands、checklist、外部脚本 / CI（针对 SubagentStart/Stop、PreCompact/PostCompact、PermissionRequest 等 Trae 不支持的事件） | Trae Hook 机制外部资料 | 已有资料 | 人工降级 / 显式流程 | 检查每个不可模拟 Hook 意图是否有不可模拟声明和收口检查 | 不得声明 Trae 可自动拦截未支持的事件类型 |

Trae Work 环境族中已支持的 Hook 事件（SessionStart、PreToolUse、PostToolUse、Stop 等）应优先使用原生 `.trae/hooks.json` 配置，而不是用 Skill 模拟或 checklist 降级。对于 Trae 不支持的 Hook 事件（SubagentStart/Stop、PreCompact/PostCompact、PermissionRequest），仍应使用"降级模板"：目的 + 可用机制 + 显式步骤 + Human Gate + 校验收口 + 不可模拟能力。Hook 原生配置不得规避 Human Gate、Code 校验和事实源回写。

#### 5.1.4 压缩备忘与上下文恢复

Trae Work 环境族中的压缩备忘和上下文恢复应按显式流程处理：阶段性总结、Todo 状态、Memo、Task、上下文暂存文件或正式事实源回写。Trae Work 环境族当前不得声明存在 `PreCompact` 或 `PostCompact` 等压缩生命周期 Hook（Trae 当前不支持这两类事件），但不影响其他已支持 Hook 事件（SessionStart、PreToolUse、PostToolUse、Stop 等）的原生使用。

| 能力意图 | Trae 处理方式 | 事实源边界 | 适配检查 | 禁止声明 |
|---|---|---|---|---|
| 压缩前保留上下文 | 显式阶段总结、Todo、Memo、Task、上下文暂存 | 稳定事实写回 Git 文件；临时上下文不得替代正式事实源 | 检查总结是否包含当前目标、已完成、未完成、风险和下一步 | 不得声明环境会自动在压缩前执行 |
| 压缩后恢复 | Rules 环境入口、上下文摘要、Memo / Task / Git 文件 | 正式规则以 `specs/` 为准，运行入口以环境入口中的薄引用为投影 | 检查恢复信息是否来自可读文件或 Human 当前输入 | 不得把聊天记忆当作长期事实源 |

### 5.2 Codex App

#### 5.2.2 Lifecycle Hook 事件候选

> 注：本节表格列出 Codex App 的完整 Hook 事件候选。其中 `SessionStart`、`UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`Stop` 五个事件 Trae Work 环境族也已原生支持（见 §5.1.3），其余事件（`PermissionRequest`、`SubagentStart/Stop`、`PreCompact/PostCompact`）为 Codex App 专属或两平台均不支持。本节适配规则以 Codex App 为准。

| Hook 事件 | 典型能力意图 | 适配检查重点 | LDVH 使用边界 | 禁止声明 |
|---|---|---|---|---|
| `SessionStart` | 会话启动或恢复时注入上下文 | 检查事件是否支持、matcher 是否有效、输出是否进入模型上下文 | 可候选承接入口加载和恢复摘要 | 未实测前不得声明稳定加载 |
| `UserPromptSubmit` | Prompt 提交前检查或补充上下文 | 检查是否支持阻断、补充或提示 | 可候选承接输入澄清和风险提示 | 不得假定可改写所有用户输入 |
| `PreToolUse` | 工具调用前检查、阻断或改写部分输入 | 检查 matcher、工具覆盖范围、返回 JSON 语义 | 可候选承接危险命令、路径越界和权限检查 | 不得声明覆盖所有 shell、Web 或非 MCP 工具 |
| `PermissionRequest` | 权限请求前自动决策或交回审批 | 检查 allow / deny / abstain 语义和冲突优先级 | 可候选承接审批策略辅助 | 不得绕过 Human Gate 或环境审批 |
| `PostToolUse` | 工具调用后审查输出或反馈 | 检查是否能替换工具结果反馈、是否无法撤销副作用 | 可候选承接校验结果审查 | 不得声明能撤销已发生副作用 |
| `Stop` | 回合停止前决定是否继续 | 检查 continuation / block 语义 | 可候选承接最终验收、失败测试续跑 | 不得声明可以替代任务验收事实源 |
| `SubagentStart` | 子智能体启动前补上下文 | 检查子智能体类型和上下文注入方式 | 可候选承接 Agent 输入契约 | 不得声明未验证 Agent 能力 |
| `SubagentStop` | 子智能体结束后要求收口或继续 | 检查输出回主控和阻断语义 | 可候选承接 Agent 输出审查 | 不得让子 Agent 输出直接生效 |
| `PreCompact` | 上下文压缩前处理 | 检查 manual / auto matcher 和持久化输出 | 可候选承接压缩备忘、Memo / Task / Git 回写提醒 | 不得把压缩备忘写成聊天记忆长期事实源 |
| `PostCompact` | 上下文压缩后恢复处理 | 检查压缩后注入内容和恢复边界 | 可候选承接恢复摘要读取 | 不得声明恢复内容天然完整 |

Codex Hook 适配必须同时检查配置层级、项目 trust、命令来源、权限范围、事件覆盖范围和失败输出。未确认当前 Codex App 版本支持时，只能标注候选或待确认。

#### 5.2.3 压缩事件与备忘处理

Codex App 可把 `PreCompact` 和 `PostCompact` 作为压缩备忘与恢复的候选事件；但 LDVH 的稳定事实仍必须进入 specs、Task、Memo、ADR、Pitfall、Change、Git 文件或对应权威事实源。Hook 输出只能作为执行期辅助，不得替代事实源回写。

Codex 官方最佳实践将 `AGENTS.md` 作为自动进入上下文的 durable guidance，建议保持简短、准确、可执行；当 `AGENTS.md` 变大时，应保留主入口简洁并引用任务专属 Markdown 文件。Codex 还提供 `/compact`，且会自动 compact 长对话；长任务应保持一条线程对应一个连贯工作单元，必要时 fork，而不是把一个项目所有工作堆入同一线程。

Codex 用户级 AGENTS 薄引用模板如下。实际写入时应将 `<LDVH_RULES_ENTRY>` 替换为当前机器上的真实绝对路径；若 `~/.codex/AGENTS.md` 已存在，应替换 LDVH 开始与结束标记之间的内容，或在不存在 LDVH 管理段时追加该段，不得覆盖用户已有内容：

```markdown
#### LDVH AI 入口引用开始

读取并遵守：

<LDVH_RULES_ENTRY>

发生 `/compact`、自动上下文压缩、线程恢复或上下文恢复后，重新读取上述 LDVH AI 入口。

#### LDVH AI 入口引用结束
```

| 能力意图 | Codex 候选机制 | 适配检查 | 降级路径 | 禁止声明 |
|---|---|---|---|---|
| 压缩前备忘 | `PreCompact` | 检查事件支持、matcher、输出位置和失败处理 | 显式阶段总结、Memo、Task、上下文暂存 | 未实测前不得声明自动执行 |
| 压缩后恢复 | `PostCompact` | 检查恢复内容是否注入、是否可追溯到文件事实源 | Rules / instructions / Git 文件 / Human 当前输入 | 不得把恢复摘要写成完整事实源 |
| 长期记忆 | Memo / Task / Git 文件 | 检查是否符合对应事实源字段契约 | Human Gate 后回写正式对象 | 不得只依赖 Hook 输出或聊天记忆 |

### 5.3 跨环境兼容原则

Trae Work 环境族与 Codex App 的适配不得互相冒充：Trae Work 的 Rule、Skill、Command、checklist 只能表达显式流程和人工降级；Codex App 的 Hook 候选可以表达 lifecycle 意图，但仍需证据、信任和适配检查。LDVH 通用环境入口默认写入用户级或系统级目录；项目目录只用于项目专属环境入口、兼容入口、测试入口或显式降级入口。任何跨环境模板都必须列出“可承载能力”“不可模拟能力”“验证方式”“降级路径”和“禁止声明”。

## 7. Human Gate 与检查要求

以下情况必须评估 Human Gate：

1. 写入、覆盖或删除用户环境入口；
2. 修改长期环境配置；
3. 启用自动触发、危险权限或跨工作区写入；
4. 受控复制 LDVH 能力资产全文；
5. 覆盖用户已有 Rules、Skill、Agent、Hook、instructions 或配置；
6. 声明任一环境完整支持 LDVH；
7. 将一次用户本地适配检查结果写成环境类型结论。

检查要求：

| 检查项 | 标准 |
|---|---|
| 入口定位 | 环境入口可定位或明确待确认 |
| 资产接入 | 对应 LDVH 能力资产存在且接入方式明确 |
| 部署权限 | 写入权限和 Human Gate 边界明确 |
| 适配检查 | 有部署前、部署后和声明完成前检查方式 |
| 降级说明 | 无原生入口时有适配降级和残留风险 |
