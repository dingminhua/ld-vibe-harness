## 1. 定位

本文件后续拟作为 AI 的系统地图入口，并承接知识地图作为价值实现方法的规范归口。它回答：

1. 当前 LDVH 有哪些权威事实源；
2. 当前工作区有哪些管辖项目；
3. specs 编号和成员区如何定位；
4. 知识地图如何由结构构件和 Code 实时派生；
5. AI 如何通过知识地图获得最小读取包。

本文不展开字段契约、事实源回写、行动编排步骤或 Code 实现细节。它只负责地图、入口、归口、关系和最小读取路径。

知识地图服务 00 中的 V1、V2、V3、V9 和 V10。02 负责定义知识地图的定位边界、关系类型归口和最小读取路径；01 负责文档结构构件；08 负责 Code 输出契约；09 负责 Web 展示边界。

## 2. 02 回答的问题

1. LDVH 由哪些稳定构件组成；
2. `specs/`、`rules/`、`code/`、`web/`、`ldvh-base/`、`LDVH-GOVERNED-PROJECTS.yaml` 和 Git commit records 的事实源边界是什么；
3. 每类问题应进入哪个 v2 权威文档；
4. 知识地图可以从哪些结构构件派生，并如何服务 V1/V2/V3/V9/V10；
5. AI 遇到任务时如何按场景入口、必读规范、可选附件和 Code 派生索引最小读取；
6. 管辖项目命名空间如何进入知识地图。

## 3. 知识地图非目标

02 应明确知识地图不做以下事情：

1. 不成为新事实源；
2. 不成为缓存数据库；
3. 不替代 specs 原文；
4. 不替代 Git commit records；
5. 不替代 `ldvh-base/`；
6. 不因图中缺少某项就否定原始事实源存在。
