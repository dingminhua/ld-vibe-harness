## 一、本文定位

本文定义多角色思考行动模型如何适配 Trae Rules 机制。本文中的 Rules 专指 Trae Rules 机制，不指多角色思考行动自身的 Scenario 识别条件、行动进入条件、执行流程、角色矩阵或报告模板。

本文不重新定义多角色思考行动模型，不替代 `specs/41-multi-role-thinking-多角色思考.md`。完整 Scenario 识别条件、Gate、执行流程、事实源回写和证据留存要求均以 41 主文件为准。

---

## 二、术语边界

| 术语 | 本文含义 |
|---|---|
| Rules | Trae Rules 机制 |
| Rules 适配 | 多角色思考行动如何通过 Trae Rules 提供短提示、入口约束和机制边界 |
| 规范规则 | specs 中定义的稳定条款，不等同于 Rules 文件 |
| Scenario 识别条件 | 41 主文件中定义的行动进入判断，不由本文完整维护 |
| 行动进入条件 | 用户输入或事实源状态触发行动评估的条件，不等同于 Rules 机制 |

本文遵守 `specs/01-specs文档结构与术语规范.md` 的术语边界：英文 Rules 专指 Trae 机制；中文“规则”必须加定语或由上下文明确限定。

## 三、是否需要制定 Rules

多角色思考不要求每个接入项目都必须新增 Rules。是否制定 Rules，应按以下条件判断：

| 条件 | 建议 |
|---|---|
| 多角色思考仅在用户明确要求时使用 | 不必新增 Rules，可由主行动模型和用户输入触发 |
| 项目频繁进行规范、Rules、Skill、Agent、工具或跨模块变更 | 可在 L1 或 L2 放置短摘要 |
| 项目有规范重构、AI 协作治理或高风险操作场景 | 可制定 L2 场景 Rules |
| 需要强制所有任务前都多角色思考 | 不建议，会造成过度分析 |
| 需要完整角色矩阵或报告模板 | 不应进入 Rules，应保留在 41 主文件、Skill 或Tools 辅助中 |

Rules 的目标是提供短提示和边界约束，不是让 Rules 承载完整行动流程。

---

## 四、Rules 放置位置

| 放置位置 | 适用情况 | 内容边界 |
|---|---|---|
| L1 项目规则 | 项目整体需要提醒复杂变更前评估多角色思考 | 只放一句压缩摘要和 41 引用 |
| L2 场景 Rules | 特定场景需要更明确提示，如规范重构、Skill / Agent 设计、工具写入 | 只放场景入口、禁止事项和主文件引用 |
| `#Rule` 手动触发 | 用户或 AI 需要临时显式加载多角色思考提醒 | 指向 L2 场景 Rules 或 41 主文件 |
| `scene: git_message` | 不适用 | 多角色思考不是 Git 提交消息生成规则 |
| 41.01 本文件 | 机制适配规范 | 定义如何制定 Rules，不作为 Trae Rules 实体文件 |

新增或修改实际 `.trae/rules/` 文件必须依据 `specs/04.01-Rules机制规范.md` 评估 Human Gate，并记录 Change。

---

## 五、Rules 生效方式

| Trae 生效方式 | 多角色思考适用性 | 说明 |
|---|---|---|
| alwaysApply | 谨慎使用 | 仅适合极短的项目级提醒，避免所有任务都过度分析 |
| globs | 可用于文档或规范文件 | 适用于 specs、rules、Skill、Agent、工具规范等文件类型 |
| description | 推荐用于场景 Rules | 适合“复杂变更、多角色分析、规范重构、Skill / Agent 设计”等场景 |
| 手动 `#Rule` | 可用 | 用户或 AI 明确需要多角色思考提醒时使用 |
| scene: git_message | 不适用 | 不承载多角色思考行动 |

Rules 生效方式应与实际使用场景匹配，不得为了提高触发率而把完整行动流程写入 alwaysApply。

---

## 六、推荐 Rules 摘要

可在 L1 或 L2 中使用以下压缩摘要：

```text
复杂变更、规范/Rules/Skill/Agent/工具调整、跨模块影响或高风险操作前，应评估是否进入 41 多角色思考。完整 Scenario、Gate、执行流程和回写要求以 specs/41-multi-role-thinking-多角色思考.md 为准。多角色思考输出默认不是事实源；稳定结论必须按事实源边界回写。Skill 不得调度 Agent；Agent 增强模式仅在相关 Trae 预制 Agent 已安装且可调用时执行，未满足时降级。
```

该摘要只能作为 Rules 通道提示，不得替代 41 主文件或 41.02、41.03、41.04 等模型实践子文档。

---

## 七、不得写入 Rules 的内容

以下内容不得进入实际 Rules 文件：

1. 完整 Scenario 识别条件；
2. 完整角色矩阵；
3. 完整多角色思考报告模板；
4. Agent 调度细节；
5. Skill 输入输出完整 SOP；
6. Tools 辅助 schema 或校验算法；
7. Web 展示结构；
8. 对象字段规则、状态规则或验收规则；
9. 长篇背景说明；
10. 早期 `pm-kit-multi-role-analysis` Skill 的完整正文。

这些内容应留在 41 主文件、对应模型实践子文档、04 机制规范、05 工具规范或 10-39 生产对象规范中。

---

## 八、Rules 变更 Human Gate

以下情况必须暂停确认：

1. 新增、删除、重命名或改变 L0/L1/L2 Rules 文件；
2. 将多角色思考 Rules 从 L2 升级为 alwaysApply；
3. 在 Rules 中复制 41 主文件完整流程；
4. 让 Rules 承载 Agent 调度或权限调整；
5. 让 Rules 将多角色思考输出直接提升为稳定事实；
6. 改变 Rules、Skill、Agent 机制名含义。

---

## 九、检查要求

| 检查项 | 标准 |
|---|---|
| 机制名 | Rules 专指 Trae Rules 机制 |
| 放置位置 | L1/L2/#Rule/description/globs 选择合理 |
| 短小稳定 | Rules 只放摘要和引用，不复制完整 SOP |
| 主文件引用 | 完整 Scenario、Gate、执行流程和回写要求指向 41 主文件 |
| Agent 边界 | Rules 未调度 Agent，未绕过 Agent 前提检查 |
| Skill 边界 | Rules 未替代 Skill 流程，也未让 Skill 调度 Agent |
| 事实源边界 | Rules 未将报告输出直接作为稳定事实 |
| Human Gate | Rules 文件变更已评估 Human Gate 并记录 Change |
