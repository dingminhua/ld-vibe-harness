## 适用边界

本附件只适用于 Web 直接读取当前 Working Tree 事实载体的对象列表和对象详情结果。它不适用于 05 的 Helper 精确读取、发现、关系导航或受控写入结果；那些结果中的 `check_status` 仍完全服从 05。字段语义、必填性、类型、详情区段标题和状态词仍分别回到 05.Att.01 与 20–25 的类型规范；本附件中的字段集合只是页面消费投影和传输结构，不形成第二份事实定义。

## 共同直读结果

字段级直读结果的外层字段闭集为 `ok`、`command`、`action`、`target`、`summary`、`issues`、`data`。`change_log` 是六类事实对象共用的可选记录数组，页面只呈现实际可读成员，不将其转化为机械校验或完整历史结论。`ok` 为 true 的结果使用本附件；运行时、范围或其它未形成直读结果的失败不伪造本结构。

`command` 固定说明字段级直读实现；`action` 为 `list` 或 `show`；`target` 是请求的类型或稳定对象 ID，只作控制定位，不是来源路径。`summary` 只提供集合计数、类型或对象 ID 等辅助信息；`issues` 是读取、集合和字段问题的规范化汇总镜像，成员使用下文 `code`、`message`、`path` 形状，并可带 `object_ref` 说明所属对象；它不携带字段问题的 `expected` 或 `raw_value`，也不得替代 `data` 中的逐项位置。

所有可读或不可读对象的来源元数据使用下列字段闭集：

| 字段 | JSON 类型 | 要求与闭集 | 边界 |
|---|---|---|---|
| `object_ref` | object | 必填；使用 05 的稳定对象引用三元组 | 只回指当前对象，不构成对象字段 |
| `canonical_path` | string | 必填；当前预期 Git 相对 POSIX 路径 | 预期权威位置，不单独证明存在或有效 |
| `carrier` | string | 必填；`yaml` 或 `markdown` | 说明当前载体解释方式 |
| `read_status` | string | 必填；`readable` 或 `unreadable` | 只表示文件是否可读且可作字段级解析；不得使用 `check_status` 或暗示机械校验结论 |
| `read_issues` | array | 必填；成员使用“读取问题” | 无读取问题为空数组 |
| `field_issues` | array | 必填；成员使用“字段问题” | 无字段问题为空数组 |
| `unparsed_structures` | array | 必填；成员使用“未解析结构” | 无未解析结构为空数组 |

`read_status: "readable"` 时，`data` 可包含下文登记的页面消费字段；字段缺失或类型不符仍保留 `readable`，并由 `field_issues` 表示。`read_status: "unreadable"` 时，不得生成或拼装消费字段，`data` 使用 `fact_read_failure: true` 连同共同来源元数据与 `read_issues`。`read_status` 不得作为 05 `check_status` 的别名、兼容字段或降级值。

`read_status=readable` 的 WorkCase 列表项与详情必须包含 `current_snapshot_projection` object；其字段闭集、resolved/unresolved 条件和枚举只回指 21 §9.3，不在本附件重定义。该 object 内的 `source_content_fingerprint` 是 Web 对当次原始载体 bytes 计算的 SHA-256，只绑定来源快照，不表示 Helper `mechanically_valid`。unreadable 对象不输出该字段；readable 但 `status + phase` 缺失、类型不符或组合非法时必须输出 21 定义的 unresolved projection，并同时保留本附件的 `field_issues` 与 `unparsed_structures`。兼容字段 `progress_group` 与 `progress_step` 只可从同一 resolved projection 取得：前者在 resolved 时必填，后者只在 projection 中非 null 时出现；不得从 raw phase 再派生。

## 读取问题、字段问题与未解析结构

### 读取问题

`read_issues[]`、`collection_issues[]` 和外层 `issues[]` 的成员字段闭集为 `code`、`message`、`path`；外层汇总成员可额外带 `object_ref`。`path` 与 `object_ref` 可省略，其余字段必填。字段问题进入外层汇总时，`code` 使用其 `reason`，`message` 说明字段路径与期望，`path` 保留字段路径。

| `code` | 适用范围 |
|---|---|
| `read_failed` | IO 读取失败、预期对象不存在或类型目录未接入 |
| `yaml_parse_failed` | YAML 无法解析或顶层不是键值映射 |
| `frontmatter_missing` | Markdown 缺少 frontmatter |
| `frontmatter_unclosed` | Markdown frontmatter 未闭合 |
| `frontmatter_parse_failed` | Markdown frontmatter 无法解析或顶层不是键值映射 |
| `unexpected_fact_carrier` | 类型目录中出现不符合正式载体命名或后缀的候选 |
| `type_not_integrated` | 列表读取的类型目录尚未接入 |

`message` 说明当次实际失败，不得以空字符串、空列表或“无差异”替代；`path` 出现时必须是实际相关的项目相对路径或该对象的 `canonical_path`。

### 字段问题

`field_issues[]` 的成员字段闭集为 `path`、`reason`、`expected`、`raw_value`；前三项必填，`raw_value` 只在实际值已读取且可安全呈现时出现。

| `reason` | 含义 |
|---|---|
| `missing` | 页面消费的必填字段不存在或为 null |
| `type_mismatch` | 已出现的页面消费字段不符合其来源登记的类型 |
| `identity_mismatch` | 已读出的 `object_id` 或 `fact_type_key` 与请求对象身份不一致 |

字段问题只说明字段级读取，不构成对象 `invalid` 或整体读取失败。

### 未解析结构

`unparsed_structures[]` 的成员字段闭集为 `path`、`reason`、`raw_value`；前两项必填，`raw_value` 可选。

| `reason` | 含义 |
|---|---|
| `unconsumed_field` | 来源中存在但当前页面不消费的字段，包括旧字段 |
| `unparseable_member` | 页面消费的记录数组中存在无法归入该数组成员结构的元素 |

未解析结构只记录实际读取到的值；不得因未知结构而丢弃其它可解析字段或升级读取状态。

## 列表与详情结构

列表 `data` 的字段闭集为 `items`、`coverage_status`、`collection_issues`。`coverage_status` 只允许 `complete` 或 `type_not_integrated`；后者必须有非空 `collection_issues`，且 `items` 为空。`items[]` 每项使用共同直读结果中的 `read_status`、`read_issues`、`field_issues` 和 `unparsed_structures`；可读项再加其列表投影字段，WorkCase 可按上文增加当前快照派生字段。列表候选不承诺 `canonical_path`、`carrier` 或正文。

详情 `data` 的字段闭集为页面消费字段、共同直读结果字段和可选 `fact_read_failure`。可读详情不输出 `fact_read_failure`；不可读详情必须输出 `fact_read_failure: true`，不得输出页面消费字段。详情的 `canonical_path` 与 `carrier` 始终来自实际直读结果，不能由路由参数或对象 ID 补造。

## 页面消费字段投影

下表中的每个名称均是 05.Att.01 的 `field_key` 去掉类型前缀后的实际载体键。共同身份字段 `object_id`、`fact_type_key`、`title`、`status`、`created_at`、`updated_at` 的身份和类型回指 05.Att.01；`urls`、`relations` 只在对应类型绑定允许时消费。各类型字段的身份、必填性、阅读顺序和标题回指对应类型规范的阅读投影章节。列表投影只是详情消费集的子集，不得自行增加字段。

| 类型 | 列表消费字段 | 详情额外消费字段 | 语义来源 |
|---|---|---|---|
| WorkCase | `goal`、`scope`、`phase`、`summary`、`resume_from`、`waiting_on`、`blocking_summary`、`priority`、`success_criterion_definitions`、`work_items`、`change_log` | `success_criterion_results`、`plan_version`、`creation_reviews`、`execution_authorization`、`execution_approval`、`result_version`、`result_summary`、`controller_check_summary`、`result_reviews`、`validation_summary`、`closure_proposal`、`closure_outcome`、`disposition_summary`、`residual_responsibilities`、`spark_suggestions` | 05.Att.01；21 §9.3、08 §7.4 |
| ADR | `decision_question`、`decision`、`applicability`、`rationale`、`consequences`、`change_log`、`disposition_summary` | 无 | 05.Att.01；22 §5 下“面向 Human 的详情阅读投影” |
| Pitfall | `symptoms`、`trigger_conditions`、`applicability`、`validation_summary`、`root_cause`、`resolution`、`avoidance`、`change_log`、`disposition_summary` | 无 | 05.Att.01；23 §5 下“面向 Human 的详情阅读投影” |
| Spark | `intent`、`summary`、`evolution`、`change_log`、`disposition_summary`、`priority` | 无 | 05.Att.01；20 §5 下“面向 Human 的详情阅读投影” |
| Study | `report_kind`、`research_intent`、`research_question`、`abstract`、`recommendation_summary`、`change_log`、`disposition_summary` | `input_refs`、`report_body` | 05.Att.01；24 §5 下“阅读语义与逐层展开” |

字段期望的运行时表示必须逐项回指本表和 05.Att.01；若类型来源改变字段、类型或必填性，先同步本表与契约测试，再改变 Web 实现。`current_snapshot_projection`、`progress_group` 与 `progress_step` 是上文单独登记且回指 21 §9.3 的 WorkCase 派生字段，不是下表所列载体消费字段。`report_body` 仅是 Study Markdown 正文的页面消费投影，其 frontmatter 字段身份仍回到 24；它不创建新的事实字段。

## 契约验证

Web API contract tests 至少覆盖：可读对象、必填字段缺失、字段类型不符、额外/旧字段、无法归类的数组成员、不可解析载体、类型未接入、列表项目读取失败，以及 `read_status` 与 05 `check_status` 不混用。WorkCase 另须覆盖 raw载体指纹、resolved/unresolved 投影、blocked 的可见覆盖、兼容 progress 字段同源，以及 unresolved 不隐藏其它字段问题。测试必须断言字段问题、读取问题和未解析结构分别位于本附件登记的位置；不得以外层汇总 `issues` 存在替代逐项断言。
