## 1. 本文解决的问题

本文解决 LD Vibe Harness 中哪些内容可以成为最终事实源、同一事实只能由哪里权威承载、聊天、工具缓存、数据库派生视图和 UI 状态为什么不能替代 Git 文件事实源，以及事实应如何选择 Markdown、YAML 或其他介质承载的问题。

LD Vibe Harness 的核心目标之一，是让 AI 不依赖聊天记忆持续推进项目，而是围绕 Git 可追踪文件读取、执行、检查和回写。本文为这一目标定义事实源边界和承载原则。

各目录在事实源体系中的性质声明，由 `specs/01-目录说明.md` 依据本文原则承载。

---

## 2. 与 00 总纲的关系

00 定义 LD Vibe Harness 的价值实现标准和五类构成要素，并要求 AI 的执行结果能留下可追溯证据、稳定事实能按边界回写到 Git 文件事实源。本文承接该要求，专门定义最终事实源、非事实源边界、单一事实源原则、事实承载方式和工具输出回写规则。

本文是 LD Vibe Harness 事实源权威性判断原则的权威位置。00 只保留事实源闭环的顶层价值要求；01 依据本文原则声明各目录在事实源体系中的性质，但不定义判断原则本身。

## 4. 最终事实源原则

LD Vibe Harness 的最终事实源必须是 Git 可追踪文件。一个事实只有写入其对应权威文件位置后，才成为可追溯、可审查、可被 AI 稳定读取和可被工具解析的 LD Vibe Harness 事实。

基础原则：

1. 事实必须能被 AI 读取；
2. 事实必须能被人审查；
3. 事实必须能被工具解析或聚合；
4. 事实必须能通过 Git 追溯变化；
5. 同一事实只能有一个权威位置，原则上不能出现多个事实源。

聊天记录、临时 UI 状态、工具缓存、数据库派生视图、运行时索引、命令输出、模型临时上下文、安装 / 初始化过程状态和环境观察状态都不能成为 LD Vibe Harness 的最终事实源。

LD Vibe Harness 只保存具备证据生命周期、状态机和权威承载位置的状态，例如 WorkArea、WorkPlan、ADR、Pitfall、Memo、Study 或其他已由工作模型规范定义的对象状态。这类状态必须写入对应 Git 文件事实源，并满足对象准入条件、状态流转规则、证据字段和必要 Human Gate。Git 提交记录用于追溯事实源修改，不是工作对象状态。安装、初始化、环境确认、入口存在性、工具可用性、适配措施现场状态、检查过程状态和环境能力观察不具备独立长期生命周期，只能在执行时即时读取为当前检查结果；若观察结果形成可复查的后续工作、长期决策、经验、提醒或正式规则，应按内容性质另行分流为 WorkPlan、ADR、Memo、Pitfall、Study、正式规范、Git 提交记录或环境能力清单 open_items，而不是保存为“当前环境状态”“初始化状态”或“检查状态”。

## 5. 单一事实源规则

同一事实只能有一个权威定义位置。其他文件、工具页面、缓存、报告或实践说明需要使用该事实时，只能引用、摘要或聚合权威位置，不得复制并维护一份独立事实。引用、索引、反向引用、关联字段、聚合摘要、展示入口、检查报告或其他过程输出只建立导航、消费、审计或展示关系，不改变被引用事实、被摘要事实或输出内容的权威归属。

典型规则：

1. specs/ 定义 LDVH 规范和状态判定方法，不承载具体事实实例、历史过程或状态实例；
2. ldvh-base/承载结构化对象实例，不承载规范正文；
3. docs/ 根目录 Markdown 文档承载用户资产或项目文档资产，不替代 ldvh-base/中的动态对象状态；
4. docs/studies/ 和 docs/sources/ 不直接成为 LD Vibe Harness 强制规则；
5. docs/studies/ 和 docs/sources/ 不直接成为管辖项目正文事实源；
6. web/ 和 code/ 可以实现工具能力，但不能独立维护与 Git 文件事实源冲突的状态。

specs 是规范事实源，不是运行状态事实源。AI 判断当前规范集合、流程状态、环境适配状态、能力缺口、检查结果或执行完成状态时，应查询目录、成员主文件自描述、对应事实源、Code 校验、环境适配记录或 Human Gate 记录，不得依赖 specs 中手写状态清单。

当两个位置出现同一事实的不同表述时，应依据本文和对应对象规范判断权威位置，非权威位置应改为引用、摘要或删除重复事实。不得因为某个非权威位置被更多文档引用、被索引收录、被工具展示、被摘要引用、被报告收录或被流程读取，就把它升级为事实源。

### 5.1 引用、摘要和过程输出不改变事实源归属

引用关系用于表达读取入口、依赖关系、关联对象、集合成员、审计线索或展示来源。摘要用于压缩表达、提高可读性或说明当前判断依据。过程输出用于交还分析、展示结果、提出候选、记录检查过程或辅助下一步行动。引用关系、摘要关系和过程输出本身可以成为承载方的结构事实或过程事实，但被引用、被摘要或被输出内容的事实源归属不随之发生变化。

引用、摘要和过程输出必须遵守以下规则：

1. 规范引用工作对象时，只能指向对象事实源；对象状态、证据、负责人、验收和关闭判断仍由 `ldvh-base/` 中对应对象实例承载；
2. 成员主文件自描述承载该成员自身集合事实；Code 派生集合索引引用或摘要成员规范、工作对象、参考材料、落地输入或过程输出时，只承载集合清单、状态摘要、读取建议和权威出口，不承载被引用或被摘要内容的详细事实；
3. Code 工具、Web、报告或检查结果引用、摘要或展示 Git 文件事实源时，只形成派生展示或过程输出，稳定事实仍以 Git 文件事实源为准；
4. 反向引用、相关规范、关联对象、related 字段、搜索结果、报告小结或过程输出不得被解释为事实迁移、状态流转、授权确认、验收完成或归属变更；
5. 若引用方、摘要方或过程输出需要采纳其中的结论，应按正文区吸收、工作对象更新、WorkPlan、ADR、Memo、Pitfall、Study、Git 提交记录或其他对应规范完成受控回写；只增加路径引用、摘要段落或输出记录不构成吸收；
6. 若引用、摘要或过程输出暴露事实源冲突，应回到权威位置修正事实，或将非权威位置改为摘要、候选、导航、过程材料或删除重复内容；
7. 工作对象不得手写维护提交记录清单；对象相关提交应按 `specs/09.01-Git提交记录与变更追溯规范.md` 从 Git 历史、`Refs:`、路径和对象 ID 派生。

## 6. 事实承载介质选择

YAML、Markdown、Python、JavaScript 等文件格式和编程语言是 LD Vibe Harness 使用的行业标准承载形式。LD Vibe Harness 不重新定义这些介质本身的语法，只定义事实承载选择原则。

### 6.1 Markdown

Markdown 更适合承载：

1. 背景、原因、解释和设计语境；
2. 理念、规范说明、项目资料、调研和报告；
3. 人类需要阅读、审查和理解的长文本内容；
4. 不需要高频程序解析的说明性事实。

### 6.2 YAML

YAML 更适合承载：

1. 工作计划、状态、结构化关系和审计字段；
2. 可解析决策、证据摘要和对象实例；
3. 需要被工具校验、聚合、筛选或受控写入的事实；
4. 高频被 AI 读取且需要稳定字段契约的事实。

### 6.3 代码文件

Python、JavaScript 或其他代码文件主要用于 Code 实现、校验器、聚合器、Web 信息同步实现和辅助脚本。代码文件可以是工具实现事实，但不能替代规范、对象实例、证据、决策或工作计划状态的权威事实源。

### 6.4 派生数据

JSON、数据库表、运行时索引、页面状态、缓存文件和命令输出可以作为工具运行过程中的派生数据或中间结果，但不得成为唯一事实源。派生数据必须能从 Git 文件事实源重新生成，或在形成稳定事实后回写到对应权威位置。

### 6.5 事实源查询与读取策略

AI 查询和读取事实源时，应遵循读取精准原则（依据 `specs/06-工作流程基础规范.md` §6.1.1），避免上下文过载。

1. **查询优先于全文读取**：AI 应先使用 Code、搜索工具或索引工具定位事实源、对象、章节和关系，再按最小必要范围读取权威文件原文；
2. **定位优先于全文**：AI 应先定位目标段落、对象字段或引用关系，再按行范围读取；不得在未定位的情况下全文读取超过 200 行的规范文档；
3. **章节锚点**：LDVH 规范文档使用 `§` 编号体系，章节标题可作为精准读取入口；AI 应先搜索章节标题（如 `^## `、`^### `），再读取目标段落；
4. **工具辅助事实源查询**：AI 可通过 Code 或脚本生成规范索引、工作对象列表、对象详情、关键词搜索、状态统计、关联关系、落地要求聚合、环境清单检查和管辖项目配置检查，辅助定位事实源；
5. **查询输出边界**：事实源查询工具输出应能回指事实源类型、权威路径、对象 ID 或章节锚点、状态摘要、关联对象、引用关系、诊断信息或建议读取位置；查询输出只作为导航、聚合和诊断结果，不替代 Git 文件事实源；
6. **事实源读取粒度**：AI 应根据任务复杂度选择读取粒度——简单事实查询使用工具定位、搜索定位和行范围读取；跨章节理解任务可逐步扩展读取范围；完整上下文构建任务才考虑全文读取。

## 7. 工具输出回写规则

工具可以查询、读取、解析、校验、聚合、展示和受控写入 Git 文件事实源。工具的价值是降低人和 AI 操作事实源的成本，而不是替代事实源，也不是替代 AI 对事实语境、规范边界、风险影响和执行路径的综合判断。

工具输出只有满足以下条件后，才成为 LD Vibe Harness 稳定事实：

1. 已写入对应权威事实源文件；
2. 写入位置符合本文和对应对象规范的事实源边界；
3. 必要时通过对应 Human Gate；
4. 可以被 Git 追溯；
5. 不与已有权威事实冲突。

工具缓存、数据库派生视图、运行时索引和页面状态不得成为工作计划状态、证据、决策、规则或审计结果的唯一来源。安装、初始化和环境观察状态不得作为稳定事实保存，只能作为当前检查结果；需要追溯的后续工作、长期决策或经验应按工作模型准入条件另行保存。

### 7.1 过程输出回写边界

过程输出包括聊天答复、Skill 输出、Agent 输出、工具报告、Web 视图、检查摘要、候选草案、风险提示、下一步建议和临时分析结论。过程输出默认不是最终事实源，只能作为当前工作流程的中间结果、展示材料、交还主控材料或受控写入候选。

过程输出可以引用、摘要或聚合 Git 文件事实源，但这种表达只证明过程输出消费了对应事实源，不改变被消费事实的权威归属。过程输出中的内容满足以下任一条件时，应按对应规范判断是否回写 Git 文件事实源：

1. 形成任务、决策、经验、风险、缺口、备忘、验收、关闭判断或事实源修改追溯；
2. 形成规范规则、目录边界、对象字段、状态机、Human Gate 条件或长期协作约束；
3. 形成管辖项目配置、正式报告正文、长期资料或可复用项目事实；
4. 形成验证结论、测试证据、失败诊断、降级说明或残留风险，且后续流程需要稳定追溯；
5. 形成需要 Human 确认、授权、接受或驳回的事实性记录。

回写时应遵循单一事实源规则：工作对象实例按 20-39 对应工作模型进入 `ldvh-base/`，事实源修改追溯进入 Git commit records，规范规则进入 `specs/`，管辖项目正式文档进入 `docs/` 根目录，外部资料进入 `docs/sources/`，内部分析按 03 和具体工作流程判断进入 `docs/studies/` 或其他授权位置。过程输出被回写后，原过程输出只能作为说明、摘要、导航或审查材料，不得继续并行维护同一稳定事实。

以下内容不得直接回写为稳定事实：

1. 未标明来源或无法复查的模型判断；
2. 未通过必要 Human Gate 的授权、验收、状态流转或高影响结论；
3. 未验证且被表述为已验证的测试结果、检查结论或完成判断；
4. 与现有权威事实冲突且未完成冲突处理的候选内容；
5. 只为当前对话可读性生成的摘要、排序、筛选、UI 状态或缓存内容；
6. 安装、初始化、环境确认、工具可用性、入口存在性或适配措施现场状态的长期登记。

无法完成回写时，应在过程输出中说明未回写原因、残留风险、建议权威位置和后续分流方式，不得把“已展示”“已输出”或“已生成候选草案”表述为稳定事实已形成。

## 9. 规范落地要求

本文通过以下规范落地要求说明相关要求的同步、检查或审计触发条件。

## 10. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 改变某类事实的权威位置；
2. 改变目录是否为最终事实源的判断原则；
3. 将原本属于 `ldvh-base/`、Git commit records 或其他工作对象权威位置的对象实例事实改放到 specs/、docs/、web/ 或 code/；
4. 将工具缓存、数据库派生视图、运行时索引或 UI 状态提升为唯一事实源；
5. 将 docs/sources/ 外部资料直接作为 LDVH 强制规范依据；
6. 将 docs/studies/ 或 docs/sources/ 直接作为管辖项目正文事实源；
7. 在多个位置并行维护同一稳定事实。

当 AI 识别到上述情况时，至少必须暂停当前变更动作，向人提醒该操作可能触发 Human Gate，并说明涉及的目录、事实源、影响范围和建议确认事项。

事实源检查至少包括：

| 检查项 | 标准 |
|---|---|
| 最终事实源 | 稳定事实已写入 Git 可追踪文件 |
| 单一事实源 | 同一事实只有一个权威位置 |
| 引用边界 | 引用、索引、摘要、聚合、过程输出或展示未改变被引用事实的权威归属 |
| 目录事实源性质 | 写入位置符合 01 目录事实源性质声明 |
| 承载介质 | Markdown、YAML 或代码文件选择符合事实类型 |
| 工具边界 | 工具缓存和派生视图未成为最终事实源 |
| 过程输出回写 | 过程输出中的稳定事实已分流到唯一权威位置，未回写内容已标注候选或临时性质 |
| sources/studies 边界 | 外部资料和内部分析未直接成为强制规则或正文事实源 |
