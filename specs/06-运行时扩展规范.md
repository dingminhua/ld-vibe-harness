## 1. 本文解决的问题

本文定义 LDVH 如何把内部运行需求接入不同 AI 协作环境，并通过固定运行时扩展承载物提供入口、规则加载、流程复用、Agent 调度、Hook 触发、工具调用和适配措施承接。

本文解决：

1. 规范保障要求如何从声明走向能力保障；
2. Rules、Skills、Agents、Hooks 等运行时扩展承载物如何登记、验证和同步；
3. 环境入口、薄引用、部署适配和适配检查如何保持边界清晰；
4. 本地环境观察、适配检查结果和能力 ready/blocked 判断为什么不能直接成为长期状态事实；
5. 运行时扩展如何服务内部运行需求，而不把外部开发环境本身写成 LDVH 构成要素。

本文不定义全局事实源规则、Git 提交契约、Code 输出 Schema、Web 页面契约、测试治理或具体行动流程。

本文定义固定运行时扩展承载物、入口接入、薄引用、环境适配、适配检查和能力保障边界。运行时扩展不随 Code 或 Web 的实现语言、框架、依赖、模块结构或技术栈变化而变化；外部环境的插件机制、Hook 语义、配置路径或安装方式只属于适配对象和现场检查内容，不构成 06 对 Code、Web 或外部环境实现方案的要求。

## 4. 运行时扩展定义与边界

开发环境本身不是 LDVH 构成要素。Codex、Claude Code、CI、IDE、Shell 等外部环境是运行时扩展的接入与适配对象。

LDVH 维护的是面向内部运行需求提供能力保障、并能被外部环境加载、调用、触发或检查的运行时扩展承载物及其适配规则。

典型运行时扩展承载物包括：

| 类型 | 性质 | 典型职责 |
|---|---|---|
| Rules | 持久指令和上下文入口 | 入口路由、最小读取顺序、STOP 点和事实源边界提示 |
| Skills | 按需加载的可复用流程能力包 | 可复用执行步骤、输入输出、失败处理、验证和交还 |
| Agents | 隔离上下文的专项执行者 | 专项探索、并行审查、争议分析和权限边界不同的子任务 |
| Hooks | 生命周期事件触发器 | 在会话、工具调用、提交、停止或其它事件点触发检查、提示、阻断或记录 |

Rules、Skills、Agents、Hooks 是运行时扩展的典型承载物，不代表全部资产类型，也不与 Code、Web、规范、事实模型或行动编排等同。

承载物类型边界矩阵由 `attachments/06.Att.03-承载物类型边界矩阵.md` 承载。运行时扩展承载物不得因目录存在、文件同名、环境机制存在或对话结论而自动成为 fixed/active 承载物。

LDVH Rules 入口采用双入口模型：工作区级入口负责管辖项目识别和 `ldvh-base/` 工作对象，维护入口负责 LDVH 产品资产维护。`ldvh-base/` 即使位于 LDVH 源码仓库内，也只有在工作区根目录 `LDVH-GOVERNED-PROJECTS.yaml` 把 LDVH 登记为 dogfood 管辖项目时，才按管辖项目工作对象处理。Codex `.rules`、sandbox、approval、permission profiles、MCP 授权、插件安装状态、Claude path rules、Git Hook 管理器配置和 CI branch protection 属于环境接入、运行约束、工具能力或部署事实，不自动成为 LDVH `rules/` 文本能力资产。

## 5. 保障声明、接管与能力保障链路

规范保障要求的表格结构和声明契约归 01。06 不重新定义保障要求格式，只负责判断“需要被看见、执行、复用、检查、触发、确认或实现的要求”是否需要固定运行时扩展承载物、环境适配或人工降级检查承接。涉及 Code、Web、行动编排或测试的需求，只能分流回对应构成要素规范，不由 06 定义或实现。

能力保障链路必须区分：

1. 来源规范提出保障要求；
2. 行动编排决定是否接管为执行闭环；
3. 06 判断是否需要 Rules、Skill、Agent、Hook 或环境适配承载；
4. 04 判断是否需要 Code 命令、校验、诊断或 Hook 调用；
5. 05 判断是否需要 Web Human-facing 展示或交互入口；
6. 08 判断是否需要测试、等价验证或回归入口；
7. 07 判断能力输出、检查结果和证据是否需要回写事实源或 Git 追溯。

保障声明不得写成“已经支持”或“完整生效”的空泛结论。必须区分要求本身、保障机制、当前可用承载物、验证方式、同步触发、缺口、降级路径和 Human Gate 条件。

06 维护的保障承载关系只覆盖固定运行时扩展、环境适配和人工降级检查方向；Code、Web、测试、CI、命令或行动编排只作为外部归口和缺口分流方向出现，不成为 06 的实现责任、资产清单、部署状态或行动编排接管事实。保障要求承载矩阵由 `attachments/06.Att.05-保障要求承载矩阵.md` 承载；能力缺口分流核对表由 `attachments/06.Att.06-能力缺口分流核对表.md` 承载。

行动编排接管执行闭环时，06 只维护运行时扩展和环境适配承载物；执行步骤、证据组织和关闭判断由 03 与成员主文件承接。若行动编排需要 Rules、Skill、Agent 或 Hook，但承载物不存在或不可用，行动编排必须记录运行时扩展缺口、降级路径和后续创建、登记或验证需求。若缺口属于 Code、Web、测试或 CI，应分流回对应构成要素，不得把这些缺口写成 06 的实现责任。

## 6. 运行时扩展承载物自描述

固定运行时扩展承载物必须声明自描述信息，至少包括：

1. 资产 ID；
2. 类型；
3. 状态；
4. canonical path；
5. 来源规范；
6. 消费场景；
7. 输入；
8. 输出；
9. 验证方式；
10. 同步触发；
11. 废弃或替代规则。

自描述不是简单目录清单。它用于让 AI、Code 和 Human 判断该承载物为什么存在、由哪些规范授权、服务什么场景、如何验证、何时同步和如何废弃。

运行时扩展承载物与 Code、Web、规范、事实模型和行动编排不是同一层资产。Code 与 Web 是六类构成要素中的独立要素；Rules、Skills、Agents、Hooks 是运行时扩展的典型承载物，用于接入环境和保障内部运行需求。

自描述字段表由 `attachments/06.Att.01-运行时扩展自描述字段表.md` 承载。固定运行时扩展登记表由 `attachments/06.Att.02-固定运行时扩展登记表.md` 承载。登记表只做 v2 基线回指；资产文件自身的 `ldvh_asset` 或等价自描述才是实例权威。Code 可以据此派生资产索引，Web 可以只读展示资产状态和缺口；不得由 06 附件长期手写维护所有资产实例状态。

运行时扩展承载物应满足薄引用、执行转换清晰、上下文经济、发现条件明确、自由度匹配风险、输入输出明确、权限与审批分层、失败和降级可见、可观测与可验证、多视角审查、事实源不分叉和环境中立等最佳实践。承载物最佳实践核对表由 `attachments/06.Att.04-承载物最佳实践核对表.md` 承载。

## 7. 环境入口、薄引用与适配检查

环境入口用于让外部 AI 协作环境找到 LDVH 的运行时入口。环境入口接入必须保持薄引用。

薄引用正文只能包含：

1. LDVH 入口文件指向；
2. 压缩、恢复或线程恢复后的重读要求；
3. LDVH 管理段开始和结束标记。

场景路由、最小读取顺序、STOP 点、事实源边界、管辖项目判断和维护入口判断必须放在被引用的 Rules 文件中，不得复制到薄引用正文里。

交付给用户的薄引用文本必须把模板变量替换为当前机器上的真实绝对路径；不得把示例路径、其他用户机器路径或相对路径写入候选入口文本。薄引用模板由 `attachments/06.Att.09-薄引用模板.md` 承载。

Rules、Skills、Agents 或 Hooks 可以提供知识地图查询入口、读取建议或降级提示，但只能指向 04 授权的 Code 投影入口，不得缓存或复制知识地图输出为运行时事实。Code 不可用、投影降级或来源不可回指时，运行时扩展必须提示 AI 退回 README、01、对应构成要素规范、07 和 Git 文件事实源。

部署适配和检查必须区分：

1. 官方维护的入口模板；
2. 用户自行安装或复制的现场配置；
3. 当前现场检查结果；
4. 长期适配措施；
5. 环境类型能力判断。

当前现场检查结果只能说明“本次检查的这个环境、这个路径、这个版本、这个配置是否可用”，不得写成“该环境类型完整支持 LDVH”的长期状态事实。需要长期追溯的缺口、决策、经验或后续工作，应分流到 WorkCase、ADR、Pitfall、Spark、正式规范、适配措施或 Git commit records。

环境适配字段表由 `attachments/06.Att.07-环境适配字段表.md` 承载，适配状态表由 `attachments/06.Att.08-适配状态表.md` 承载。部署前、部署执行、部署后和声明完成前检查由 `attachments/06.Att.10-部署检查核对表.md` 承载。

LDVH 官方维护的环境适配目标为 Codex App。Codex 环境入口候选矩阵由 `attachments/06.Att.11-Codex环境入口候选矩阵.md` 承载，Codex Hook 事件候选矩阵由 `attachments/06.Att.12-CodexHook事件候选矩阵.md` 承载。非 Codex 环境自助适配核对表由 `attachments/06.Att.13-非Codex自助适配核对表.md` 承载。权威资产副本分层核对表由 `attachments/06.Att.14-权威资产副本分层核对表.md` 承载。

## 11. Human Gate

以下情况必须暂停并等待 Human 确认：

1. 新增、删除、移动或重命名固定运行时扩展承载物；
2. 修改用户环境入口、项目规则、工作区规则或等价配置；
3. 声明某环境完整支持 LDVH 或某能力已部署生效；
4. 将一次本地适配检查结果写成长期环境状态；
5. 扩大 Skill、Agent、Hook、Rules 或命令入口权限；
6. 接受运行时扩展、适配措施、环境入口或能力资产长期降级；
7. 覆盖用户已有 Rules、Skill、Agent、Hook、instructions、AGENTS、配置或等价入口；
8. 受控复制 LDVH 能力资产全文，而不是使用薄引用、软链、安装脚本或可复查配置；
9. 启用自动触发、危险权限或跨工作区写入；
10. 允许 Skill 新增稳定规则、字段、状态或 Human Gate 条件；
11. 允许 Agent 输出直接生效，或让子 Agent 拥有独立事实源状态；
12. 声明 Hook、人工降级、候选配置或未实测环境能力具有完整支持、原生支持或等价状态；
13. 将工作区级入口和 LDVH 项目级维护入口重新合并为单一入口；
14. 新增、删除、重命名或改变本文授权附件的信息对象；
15. 发现本文与 active 04 系列、07 事实源边界或实际环境入口冲突。

## 12. 运行时扩展检查要求

运行时扩展检查至少包括：

| 检查项 | 标准 |
|---|---|
| 承载物自描述 | ID、类型、状态、路径、来源、场景、输入输出、验证和同步触发完整 |
| 薄引用 | 环境入口只指向入口、重读要求和管理段标记，不复制 specs 正文 |
| 适配边界 | 当前检查结果未被写成长期环境状态 |
| 权限边界 | Skill/Agent/Hook/Rules 没有越过授权范围 |
| 知识地图入口 | 只指向 04 Code 投影入口，工具不可用时能退回事实源和规范 |
| 能力缺口 | 缺失能力已分流到行动编排、Code、Web、测试或人工降级检查 |
| 同步关系 | 规范、行动、Code、Web、事实源和测试变化后有联动检查 |
| 权威副本分层 | 权威资产与环境部署副本未混同 |
| Codex 边界 | Codex AGENTS、`.codex/`、Hook 候选和配置路径未被写成当前已部署状态 |
