## 1. 本文解决的问题

本文解决 LD Vibe Harness 中 Web 构成要素如何承载信息同步、派生视图、状态和缺口呈现、Human Gate UI、受控编辑入口、人类确认工作台和 Web 实现文档的问题。

Web 的目标不是替代 specs、Code、Rules、Skill、Agent 或事实实例，而是把 Git 文件事实源及其派生状态以人可读、可确认、可操作的方式同步给人，并在必要时提供受控编辑和确认入口。

本文只定义 Web 信息同步层相关内容。Code 辅助、确定性校验、受控写入和测试实现由 `docs/specs/07-Code实现规范.md` 独立承载。

## 2. 与 00 总纲的关系

00 定义 Web 是 LD Vibe Harness 的五类构成要素之一。Web 负责面向人同步事实源状态、缺口、验证结果和确认项，并提供 Human Gate UI 与受控编辑体验。

本文承接 00 对 Web 的定位，定义 Web 与 Git 文件事实源、Specs、Code、测试、缓存、数据库、Human Gate 和实现文档的边界。稳定规则仍由 specs 定义，稳定事实仍由 Git 文件事实源承载，Web 页面状态、缓存和数据库派生视图不得反向替代规范正文或事实实例。

## 3. Web 权威领域

本文是 LDVH Web 构成要素、Web 信息同步层、派生视图、状态和缺口呈现、Human Gate UI、受控编辑入口、缓存和数据库边界、Web 与 Code 协作关系、Web 实现文档边界以及 Web Human Gate 检查要求的权威规范。

本文不定义 Code 命名、CLI、输出结构、测试、更新维护或确定性校验算法；这些内容由 `docs/specs/07-Code实现规范.md` 承载。

## 4. Web 与事实源边界

Web 可以展示、同步、筛选、解释和辅助编辑 Git 文件事实源及其派生状态。Web 的价值是降低人理解、确认和操作事实源的成本，而不是替代事实源。

Web 治理原则如下：

1. **Web 不等于事实源**：页面状态、缓存、数据库派生视图、运行时索引和 UI 展示都不能成为最终事实源。
2. **展示来自事实源**：Web 展示的稳定事实必须可追溯到 Git 文件事实源。
3. **派生状态必须可识别**：Web 展示的派生视图必须标注数据来源、同步时间或可追溯依据。
4. **写入必须受控**：Web 可以提供受控编辑入口，但不得绕过事实源边界、对象规范、Code 校验、工作流程或 Human Gate。
5. **实现不替代规范**：`web/`、`web/docs/`、缓存和数据库不能替代 docs/specs/、ldvh-base/ 或 docs/ 中的权威事实。

---

## 5. Web 信息同步层规则

Web 信息同步层面向人可读、可确认、可操作的界面，包括派生视图、状态和缺口呈现、Human Gate UI、受控编辑入口和人类确认工作台。

### 5.1 允许职责

1. 展示事实实例、规范状态、引用关系、验证结果、缺口和待确认项；
2. 展示 Code 生成的确定性诊断、聚合结果和派生数据；
3. 提供 Human Gate UI，承载人类确认、取消、暂缓或修改反馈；
4. 提供受控编辑入口，并把写入交给受控写入链路执行；
5. 展示同步延迟、数据来源、最近更新时间和错误状态；
6. 提供面向人的筛选、导航、对比和审查体验。

### 5.2 禁止职责

1. 定义事实源权威规则、对象字段契约或状态机；
2. 直接绕过 Code 校验修改 Git 文件事实源；
3. 将页面状态、缓存或数据库派生视图提升为稳定事实；
4. 直接调用 AI、Skill 或 Agent；
5. 用 UI 展示替代验证证据或事实源回写；
6. 在 Web 中维护独立于 Git 文件事实源的权威状态。

---

## 6. 信息同步原则

1. Web 页面展示的事实以 Git 文件事实源为准，同步延迟应可识别和可追溯；
2. 派生视图必须明确标注数据来源和同步时间；
3. 派生视图不得维护独立于 Git 文件事实源的权威状态；
4. Web 可调用 Code 获取派生数据，但不得在 UI 中另建权威事实；
5. Web 展示的错误、缺口和建议必须能追溯到事实源、工具输出或明确的人工输入；
6. Web 与事实源冲突时，以 Git 文件事实源和对应 specs 为准。

---

## 7. 缓存和数据库边界

Web 可以使用缓存或数据库改善同步效率和交互体验，但缓存和数据库只能承载派生数据。

缓存和数据库规则如下：

1. 缓存和数据库不得作为事实实例、决策、状态或审计的唯一来源；
2. 缓存和数据库数据必须能追溯到 Git 文件事实源、Code 输出或明确的人工输入；
3. 缓存和数据库内容与事实源冲突时，以事实源为准；
4. 缓存失效、同步失败或派生数据过期时，Web 必须可识别地呈现状态；
5. 引入持久化数据库并影响事实源读取、信息同步或写入链路时，应评估 Human Gate。

---

## 8. Human Gate UI 与受控编辑

Human Gate UI 可用于展示事实实例状态、缺口、风险和待确认项，供人类确认后触发受控写入。

Human Gate UI 规则如下：

1. UI 必须清楚展示确认对象、影响范围、风险和可选操作；
2. UI 必须区分确认、取消、暂缓和修改反馈；
3. UI 只能承载人的确认结果，不得自动生成授权；
4. 受控编辑入口应提供基于 Contract 或对象规范的字段校验；
5. 受控编辑入口不得绕过 Code 受控写入层直接修改事实源；
6. 编辑入口应区分可编辑字段和只读字段，只读字段以对应对象规范为准；
7. 写入后应能展示验证结果、错误状态或回写证据。

## 9. Web 与 Code 的关系

Web 和 Code 是独立构成要素，但允许协作。

| 事项 | Web | Code |
|---|---|---|
| 人可读展示 | 负责 | 不负责 |
| Human Gate UI | 负责 | 不负责 |
| 受控编辑体验 | 负责 | 执行已授权写入 |
| 确定性解析 | 可消费结果 | 负责 |
| 校验算法 | 展示结果 | 负责 |
| 派生数据 | 展示和同步 | 生成或聚合 |
| 权威事实 | 不承载 | 不承载 |
| 测试算法行为 | 不负责 | 负责 |

Web 需要确定性数据时，应优先调用 Code 或后端聚合逻辑。Web 不得在 UI 中另建权威事实，不得绕过 Code 的校验和受控写入边界直接修改 Git 文件事实源。

## 10. Web 使用场景

Web 使用场景必须由对应规范、产品设计、工作流程或实现文档声明。未声明场景时，AI 应根据本文判断能力是否属于面向人同步、确认、编辑或协同。

当前通用场景如下：

| 场景 | Web 职责 | Code 职责 |
|---|---|---|
| 展示事实实例状态 | 展示、筛选、导航 | 解析和聚合事实实例 |
| 展示校验结果 | 呈现问题、严重级别和修复入口 | 执行确定性校验 |
| Human Gate | 展示确认项并收集人类选择 | 执行已授权写入或验证 |
| 受控编辑 | 提供表单和字段交互 | 校验并写入事实源 |
| 缺口审查 | 展示缺口和关联对象 | 生成缺口诊断 |
| 运行态监控 | 展示同步状态和错误 | 提供可追溯输出 |

Web 不可用时，不得视为事实源缺失或检查通过。AI 应回到 Git 文件事实源、Code 工具和对象规范执行人工或命令行检查。

---

## 11. Web 文档边界

Web 可以拥有自己的实现文档，但 Web 文档不替代 specs。

Web 文档可以承载：

1. 页面信息架构；
2. API 使用说明；
3. 同步策略；
4. 组件说明；
5. 部署和运行说明；
6. 故障排查；
7. UI 状态和交互设计；
8. Backlog 和产品设计草案。

Web 文档不得承载：

1. LDVH 稳定规范规则；
2. 对象字段契约；
3. 状态机权威定义；
4. Human Gate 权威条件；
5. 事实源最终结论；
6. 与 specs 冲突的行为定义。

Web 实现文档应进入项目文档工作区或项目约定的实现文档位置，并遵守 03 系列文档规范。`web/` 目录优先承载 Web 实现本身；旧 `web/docs/` 只作为迁移素材或实现说明识别，不得替代 docs/specs、docs 正文或工作对象。若 Web 文档中的内容具有长期规范效力，应回写 docs/specs；若形成事实实例、决策或任务，应回写 ldvh-base。

## 12. Web 测试与验证要求

Web 变更应根据影响范围执行测试和验证。测试不通过时不得提交相关 Web 变更。

Web 测试至少关注：

1. 页面或组件是否正确展示数据来源；
2. 派生视图是否正确处理同步延迟、错误和空状态；
3. Human Gate UI 是否区分确认、取消、暂缓和修改反馈；
4. 受控编辑是否阻止只读字段编辑；
5. 受控编辑是否调用校验和受控写入链路；
6. 缓存或数据库派生视图是否不替代事实源；
7. Web 消费的 Code 输出结构变化后是否同步适配。

Web 测试夹具、Mock 数据、缓存和截图不得成为稳定事实源。

---

## 13. Web 更新、维护与删除

### 13.1 更新触发条件

以下变更会影响 Web 实现或 Web 文档，AI 必须同步检查 Web：

1. 事实源目录结构变更；
2. 对象字段契约或状态机变更；
3. Human Gate 条件、确认内容或确认流程变更；
4. Code 输出结构变更；
5. Web 展示的数据来源、缓存策略或同步策略变更；
6. 受控编辑字段、只读字段或写入链路变更；
7. 页面信息架构、API 或后端聚合方式变更。

### 13.2 联动检查内容

Web 相关规格变更后，AI 应检查：

1. `web/` 中是否存在受影响的页面、组件、API 或状态逻辑；
2. Web 是否继续正确展示数据来源、同步时间和错误状态；
3. Web 是否继续调用正确的 Code 输出或后端聚合结果；
4. Web 测试是否需要同步；
5. Web 文档是否需要同步；
6. Rules、Skill 或工作流程是否依赖该 Web 能力。

### 13.3 删除 Web 能力

删除 Web 页面、接口或能力前必须确认：

1. 没有工作流程、Rules、Skill 或用户操作路径继续依赖；
2. 替代入口或命令行降级路径已明确；
3. 对应测试已删除、迁移或改写；
4. Web 文档和引用已同步；
5. 如影响 Human Gate、受控编辑或事实源同步，应触发 Human Gate。

## 14. 规范落地要求

本文通过以下规范落地要求说明相关要求的同步、检查或审计触发条件。

| 落地要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 上位约束承接要求 | Web 只能承接 Human-facing 信息同步、确认、验收和受控轻写入，不得替代事实源或规范正文 | 09 事实源边界、07 Code、工作模型与工作流程规范、Human Gate | Web 治理 | Web 边界、信息同步、缓存数据库或受控编辑规则变化时 |
| 确定性执行要求 | Web 消费的事实源解析、校验、聚合和受控写入应由 Code 或后端确定性逻辑提供 | `docs/specs/07-Code实现规范.md`、测试或等价验证、输出契约 | 实现承接 | Web 消费 Code 输出、展示工具诊断或触发受控写入时 |
| Human 交互要求 | Human Gate UI 应清楚展示确认对象、影响范围、风险和用户选择 | Web / Human 入口、Human Gate、受控写入链路 | Human 协同 | Human Gate UI、确认流程、受控编辑入口或验收入口变化时 |
| 生命周期触发要求 | Web 页面、API、缓存、受控编辑或 Code 输出消费变化后，应检查 Web 测试和文档是否同步 | Web 测试、Code 回归、文档联动检查 | 触发保障 | Web 页面、API、状态呈现、受控编辑或 Code 输出消费变化时 |

具体工作模型或工作流程如需 Web 能力，应在对应主规范中说明 Web 适配边界、消费契约、验证入口和降级方式。

## 15. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 新增、删除、重命名或改变本文定义的 Web 信息同步职责分工；
2. 改变 `web/`、`web/docs/`、缓存或数据库的目录定位、事实源性质或同步分工；
3. Web 写入或覆盖 Git 文件事实源；
4. Web 改变事实源归属；
5. Web 将派生数据、缓存、数据库视图或 UI 状态提升为稳定事实；
6. Web 绕过 Rules、对象状态机、Code 校验、工作流程或 Human Gate；
7. Web 引入持久化数据库作为派生层并影响事实源读取、信息同步或写入链路；
8. 删除被工作流程、Human Gate 或受控编辑依赖的 Web 能力。

Web 一致性检查至少包括：

| 检查项 | 标准 |
|---|---|
| Web 边界 | Web 只承载信息同步、派生视图、Human Gate UI、受控编辑和人类确认工作台 |
| 事实源边界 | 页面状态、缓存、数据库和 UI 展示未替代 Git 文件事实源 |
| 数据来源 | 派生视图标注数据来源、同步时间或可追溯依据 |
| 受控编辑 | 写入目标、字段校验、只读字段、写入前校验和写入后验证已识别 |
| Human Gate | UI 明确确认对象、影响范围、风险和用户选择 |
| Code 协作 | Web 消费 Code 输出或触发受控写入时未绕过 Code 校验边界 |
| AI 协作边界 | Web 未直接调用 AI、Skill 或 Agent |
| Web 文档 | Web 文档未替代 specs、事实实例或对象契约 |
