## 1. 本文解决的问题

本文解决 LDVH 自己设定的落地特别要求应如何登记、启用、映射和检查的问题。

这些要求不是平台客观能力，也不是对某项上位规范的豁免。它们是 LDVH 为避免运行投影膨胀、Skill 命名混乱、入口摘要变成第二事实源而设定的运行纪律。具体环境如何承接这些要求，仍按 `docs/specs/04.02-环境适配与运行投影规范.md`、`docs/specs/04.03-环境能力承接边界规范.md` 和当前平台适配清单处理。

## 2. 与 00 总纲的关系

00 要求 LDVH 围绕稳定事实源、Human Gate、验证纪律和运行闭环约束 AI 行动。本文承接这些上位原则，防止 Rules、Instructions、Skill、Agent、Hook、命令入口或 Web 入口在环境适配后替代正式规范、事实源或 Human Gate。

当 LDVH 落地特别要求与具体环境的默认习惯冲突时，应优先保持 LDVH 的事实源边界和运行闭环要求；环境不支持时，应记录降级方式和残留风险，不得把运行投影改写成第二套规范正文。

## 3. 术语应用关系

本文使用的 LDVH 落地特别要求、个人落地特别要求、运行投影、环境实体、Skill、Rules / Instructions 等术语，按 `docs/specs/02-术语规范.md` 定义。以下小节只说明这些术语在本文中的应用关系，不另行维护术语权威定义。

### 3.1 LDVH 落地特别要求

本文登记 LDVH 自行设定、跨环境落地时需要遵守的特殊运行纪律。

这类要求应同时满足：

1. 来源于 LDVH 自身治理目标；
2. 需要环境适配或运行投影承接；
3. 不适合写成某个平台的能力说明；
4. 不应散落在具体运行投影中重复维护。

### 3.2 薄入口

薄入口的术语边界按 `docs/specs/02-术语规范.md`。本文对薄入口的执行要求是：运行投影中的入口内容只承担发现、触发、导航、提醒和交还职责，不复制完整规范正文，不维护第二事实源。

薄入口不等于信息不足。入口应足够让 AI 知道何时进入、读哪里、检查什么、何时暂停和如何交还，但细则必须回到正式规范、平台适配清单、管辖项目配置、42 流程、Code 实现或其他权威位置读取。

### 3.3 LDVH 自建 Skill

LDVH 自建 Skill 的术语边界按 `docs/specs/02-术语规范.md`。本文对其治理要求是：由 LDVH 为承接自身工作流程、治理动作、检查步骤或运行投影而创建或要求维护的 Skill，应遵守本文的命名、正文边界、触发说明和 Human Gate 要求。

LDVH 自建 Skill 不等于管辖项目业务 Skill，也不等于第三方平台 Skill。管辖项目业务 Skill 不得占用 LDVH 自建 Skill 的命名前缀和治理身份。

## 5. 薄入口细则

LDVH 运行投影中的入口内容可以包含：

1. 入口身份、适用范围和权威来源；
2. 触发条件和不适用场景；
3. 必读正式规范、平台适配清单、管辖项目配置、42 流程、Code 入口或工作对象路径；
4. 关键检查项、STOP 点、Human Gate 提醒和降级方式；
5. 输入、输出、交还主控或回写出口；
6. 运行投影与正式规范之间的路径或版本关联。

LDVH 运行投影中的入口内容不得包含：

1. 完整规范正文、字段契约、状态机、工作流程全文或平台教程；
2. 未被正式规范吸收的 evals、refs 或输入材料结论；
3. 与正式规范并行维护的规则正文；
4. 未经 Human Gate 授权的写入、覆盖、删除或状态流转规则；
5. 稳定事实、决策或验收结论的唯一记录。

本文不把固定字符数写成跨环境硬标准。若某个规则型入口的有效正文超过约 1000 个汉字，或超过对应平台建议的入口长度，应评估是否拆分、转为引用、吸收到正式规范、封装为 Skill / Code / Web，或记录降级方式。

工作区入口视角和 LDVH 管理入口视角的边界如下：

1. LDVH 默认只维护一个位于自身项目根目录的 AI 统一入口文件 `../../LDVH-AI-ENTRY.md`，不为工作区入口和 LDVH 管理入口拆分两个入口文件；
2. 工作区级入口只负责让用户当前开发环境中的 AI 知道“这个工作区应进入 LDVH-AI-ENTRY.md，并按工作区入口视角识别管辖项目、事实源和执行边界”，不得承载管辖项目规则正文；
3. 工作区入口视角是所有管辖项目共同遵守和使用的内容，应说明如何定位 `LDVH-GOVERNED-PROJECTS.yaml`、管辖项目自身 `docs/`、管辖项目自身 `ldvh-base/`、当前平台适配清单、42 流程和必要 STOP 点；
4. LDVH 管理入口视角只用于维护 LDVH 自身项目，应说明如何进入 `docs/specs/`、`tools/`、`tests/`、`web/`、根目录配置、平台适配清单和运行投影治理；
5. 管辖项目和 LDVH 自身项目均不创建项目级平台规则文件、项目指令或等价项目级入口；所有项目统一通过平台用户级/系统级薄入口进入 LDVH-AI-ENTRY.md，避免项目级入口与用户级入口重复维护或漂移；
6. 管辖项目可以在自身 `docs/`、`ldvh-base/` 或其他权威 Git 文件中创建项目事实、工作对象实例和按 LDVH 规范治理的记录，因为这些内容属于管辖项目自身事实源，不接管用户项目入口；
7. 平台用户级/系统级入口的写入位置、格式和持久化方式由具体环境决定，应在 Human 授权下处理；以下平台路径只作为当前平台清单索引，权威证据和可用性判断以 `docs/specs/04.06-平台适配清单规范.md` 及对应平台清单为准：
   - Trae 国际版：在用户级系统目录 ~/.trae/rules/ 下创建规则文件 ldvh-entry.md，内容为指向 LDVH 项目根目录 LDVH-AI-ENTRY.md 的薄引用；不在任何项目（含 LDVH 自身项目）的 .trae/rules/ 下创建项目级规则；上下文压缩保护或等价持久规则保护机制由 Trae 平台清单记录和检查
   - Trae 中文版：在用户级系统目录 ~/.trae-cn/rules/ 下创建规则文件 ldvh-entry.md，其余同 Trae 国际版
   - Codex CLI：在用户全局 ~/.codex/AGENTS.md 中加入指向 LDVH 项目根目录 LDVH-AI-ENTRY.md 的薄引用；不在任何项目根目录创建项目级 AGENTS.md；加载、compaction 和增强持久性候选由 Codex 平台清单记录和检查
   - 其他平台：按 `docs/specs/04.06-平台适配清单规范.md` 和对应平台适配清单确定入口位置，原则相同——只在用户可及的最外层创建一个薄引用，不在项目内重复创建；上下文压缩保护或等价机制由对应平台清单记录和检查
8. LDVH-AI-ENTRY.md 发生职责、结构或入口角色边界变化时，应评估 Human Gate，并同步检查 04.02、本文、01、41、42、40 中的 removed 43 槽位说明和平台薄入口。

AI 统一入口的默认文件为 LDVH 自身项目根目录的 `../../LDVH-AI-ENTRY.md`。该文件不得放入隐藏目录、工具缓存、平台私有目录、docs/specs 正文区、docs/evals 或 docs/refs。它只承载入口角色区分、最小启动顺序、场景路由、STOP 点和权威路径；不得复制正式规范正文，不得维护管辖项目状态，不得替代平台适配清单、42 流程、工作区根目录管辖项目配置、工作对象事实源、Code 校验或 Human Gate。

平台薄入口只应醒目指向 LDVH-AI-ENTRY.md，不复制 LDVH-AI-ENTRY.md 正文，也不直接维护正式规范清单。管辖项目一般不创建自己的 AI 统一入口文件；确需在管辖项目内创建平台入口或等价文件时，必须由 Human 明确授权，并记录影响范围和退出方式。

### 5.1 薄引用内容模板

薄引用正文应正式、简洁，只承载身份声明和权威引用路径。引用路径必须是完整真实的绝对路径，确保 AI 在任何工作目录下都能直接定位 LDVH-AI-ENTRY.md。

**Trae 规则文件 ldvh-entry.md 模板：**

```markdown
本环境已接入 LDVH（LD Vibe Harness）。AI 处理本环境任务时，必须先读取 LDVH AI 统一入口：
<LDVH项目根目录绝对路径>/LDVH-AI-ENTRY.md
按工作区入口视角识别管辖项目、事实源和执行边界。
```

落地示例（路径须替换为当前用户真实绝对路径）：

```markdown
本环境已接入 LDVH（LD Vibe Harness）。AI 处理本环境任务时，必须先读取 LDVH AI 统一入口：
/Users/dmh2002/poker_hud_projects/ld-vibe-harness/LDVH-AI-ENTRY.md
按工作区入口视角识别管辖项目、事实源和执行边界。
```

**Codex ~/.codex/AGENTS.md 薄引用模板（追加到已有内容末尾）：**

```markdown
## LDVH

本环境已接入 LDVH（LD Vibe Harness）。AI 处理本环境任务时，必须先读取 LDVH AI 统一入口：
<LDVH项目根目录绝对路径>/LDVH-AI-ENTRY.md
按工作区入口视角识别管辖项目、事实源和执行边界。
```

落地示例：

```markdown
## LDVH

本环境已接入 LDVH（LD Vibe Harness）。AI 处理本环境任务时，必须先读取 LDVH AI 统一入口：
/Users/dmh2002/poker_hud_projects/ld-vibe-harness/LDVH-AI-ENTRY.md
按工作区入口视角识别管辖项目、事实源和执行边界。
```

**关键要求：**
- 引用路径必须使用完整绝对路径（如 /Users/xxx/ld-vibe-harness/LDVH-AI-ENTRY.md），不得使用相对路径（如 `../../LDVH-AI-ENTRY.md`），确保 AI 在任何工作目录下都能直接定位
- 不同用户的绝对路径不同，落地时须替换为当前用户真实路径
- 薄引用正文不使用问候语，不复制规范正文，不维护第二事实源

## 6. LDVH 自建 Skill 细则

LDVH 自建 Skill 的稳定标识应遵守：

1. 使用 `ldvh-` 前缀；
2. 前缀后使用表达能力或治理动作的短名；
3. 只使用小写字母、数字和连字符；
4. 不绑定具体业务项目名、个人名、平台名或临时阶段名；
5. 不使用版本号、状态词或营销式名称作为稳定标识。

若平台支持目录名、文件名、元数据 `name` 或命令入口，以上标识应尽量保持一致。具体部署路径由环境适配映射决定，不在本文写死为某个平台目录。

管辖项目业务 Skill、第三方 Skill 和一次性实验 Skill 不得使用 `ldvh-` 前缀。确需创建、修改、删除、重命名、搬移或启用 / 禁用 LDVH 自建 Skill 时，应评估 Human Gate。

Skill 的 `description` 或等价元数据应说明：

1. 该 Skill 能承接什么能力；
2. 何时使用；
3. 何时不使用；
4. 关键触发词或生命周期阶段；
5. 需要读取的权威入口。

Skill 正文应使用中文，除非平台字段、技术标识或外部工具要求使用英文。若平台元数据必须使用英文，Skill 正文中仍应保留中文可读的定位、触发条件和边界说明。

## 7. 启用与环境适配

LDR-01 至 LDR-04、LDR-06 和 LDR-07 是 LDVH 自建运行投影的默认要求。AI 创建、修改、审计或搬移 LDVH 运行投影时，应先按本文检查，再按 `docs/specs/04.02-环境适配与运行投影规范.md` 映射到具体环境。

LDR-05 默认启用。LDVH 自身项目入口、工作区级薄入口或平台用户级/系统级入口展示场景中，首句问候应使用固定字面量"Hello，LDVH"；薄引用正文应正式、简洁，只承载身份声明和权威引用路径，不使用问候语替代正式表述。若当前环境或项目明确不适用，应记录退出方式和残留风险。

若当前环境无法完整承接本文要求，应按以下顺序处理：

1. 先确认是否可以通过环境适配映射、入口摘要、平台适配清单、管辖项目配置、42 流程或管辖项目自身事实源满足；
2. 仍不能满足时，记录降级方式和残留风险；
3. 若会削弱事实源边界、Human Gate 或验证纪律，应触发 Human Gate；
4. 不得通过复制规范正文、放宽 Skill 命名或让入口自成事实源来规避缺口。

## 8. 规范落地要求

本文通过以下规范落地要求说明相关要求的同步、检查或审计触发条件。

## 9. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 新增、删除或改变本文登记的 LDVH 落地特别要求；
2. 放宽薄入口要求，允许运行投影复制完整规范正文；
3. 改变 `ldvh-` 前缀的适用范围；
4. 允许管辖项目业务 Skill 使用 `ldvh-` 前缀；
5. 创建、修改、删除、重命名、搬移或启用 / 禁用 LDVH 自建 Skill；
6. 允许 Skill 新增稳定规则、字段、状态或 Human Gate 条件；
7. 删除、重命名或移动 LDVH-AI-ENTRY.md，或改变 AI 统一入口的默认职责。

LDVH 落地特别要求检查至少包括：

| 检查项 | 标准 |
|---|---|
| 薄入口 | 运行投影只保留入口摘要、触发、检查、STOP、引用、交还和降级信息 |
| 入口分层 | 工作区级入口、工作区入口视角、LDVH 管理入口视角和管辖项目自身事实源未混同；管辖项目和 LDVH 自身项目根目录均未创建项目级平台规则文件 |
| AI 统一入口 | 平台入口只指向 LDVH-AI-ENTRY.md，未复制规则正文 |
| 权威引用 | 入口摘要能追溯到正式规范、平台适配清单、管辖项目配置、42 流程、管辖项目自身事实源或 Code 入口 |
| 非事实源 | 运行投影、Skill 正文和入口摘要未替代 docs/specs 正文或工作对象 |
| Skill 命名 | LDVH 自建 Skill 使用 `ldvh-` 前缀、小写字母、数字和连字符 |
| 业务隔离 | 管辖项目业务 Skill 未占用 LDVH 前缀 |
| 触发边界 | Skill description 或等价元数据同时声明触发条件和不适用场景 |
| Human Gate | 高影响变更已评估 Human Gate |
