> 创建日期：2026-05-28

## 一、对象定位与准入

### 1.1 对象定义

Memo 是尚未任务化但有保留价值的输入、发现和提醒。

Memo 不是 AI 长期记忆，不是垃圾桶，不是需求池，不是任务池，不是知识库，不是对话历史归档，不是项目背景资料库。

### 1.2 Memo 与临时信息的区别

| 维度 | 临时信息 | Memo |
|---|---|---|
| 影响范围 | 当前执行上下文 | 跨对象、跨会话或需要后续梳理 |
| 持续时间 | 一次性 | 需要保留至梳理或转化 |
| 追踪需求 | 不需要独立追踪 | 需要独立追踪、状态流转或关闭证据 |

### 1.3 Memo 与 Task 的边界

| | Memo | Task |
|---|---|---|
| 本质 | 未任务化输入记录 | 已拆解的可执行对象 |
| 是否一定需要行动 | 不一定 | 一定需要执行或关闭 |
| 是否必须有完成标准 | 不必须 | 必须有可检查完成标准 |
| 是否需要验收 | 通常不需要 | 需要验证和关闭证据 |
| 典型内容 | 发现、提醒、约束、想法、审计中无法任务化的发现 | 有明确目标、完成标准、归属和验证方式的工作 |
| 来源 | 人类输入、AI 记录、审计发现、工具观察 | AI 从 Memo 或直接输入拆解构建 |

如果一个输入已经有明确目标、执行边界、完成标准和需要追踪的状态，它就不应该继续叫 Memo，而应该转 Task。

### 1.4 准入条件

只有满足以下全部条件的输入，才应创建 Memo：

1. 有保留价值，但当前无法或不应直接任务化；
2. 来源可追踪；
3. 后续可被梳理、关闭或转化；
4. 不属于已有 Task、ADR、Risk、Dependency 或 Pitfall 的范围。

### 1.5 不应创建 Memo 的场景

以下场景不应创建 Memo：

1. 可以在当前对话中直接回答或处理的信息；
2. 已经有明确目标、执行边界和完成标准，应直接创建 Task；
3. 属于长期规则或决策，应写入 Rules 或 ADR；
4. 属于需求或专题目标，应写入 Requirement；
5. 属于已确认的风险或依赖，应创建 Risk 或 Dependency；
6. 属于已理解的踩坑经验，应沉淀为 Pitfall；
7. 对话背景、项目知识、历史经验等不需要独立追踪的信息；
8. AI 的推理过程、分析步骤或中间结论；
9. 纯粹的确认、同意或否定回复。

AI 不得因为某个信息"有价值"就自动创建 Memo。只有需要保留但暂时无法任务化的输入，才应创建 Memo。

## 二、事实源边界

> 事实源边界声明：本文档是 Memo 对象实践的权威事实源。本文档定义 Memo 的准入条件、状态机、字段契约、对象关系和适配规则。本文档不重新定义管理对象语义（见 14）、事实源载体规则和格式契约（见 10）、AI 协作总原则（见 11）、程序辅助总原则（见 12）、工具展示总原则（见 13）。

### 2.1 事实源载体

Memo 的事实源载体为 `pm-kit-base/memos/`，以 YAML 结构化文件承载。目录命名和文件命名格式依据 10 §12.1。

### 2.2 与 docs 的关系

当项目已经存在 Memo 结构化事实源时，docs 中的文档不得重复维护 Memo 正文、动态状态或关闭结果，只能作为说明、历史材料、轻量入口或工具生成视图。

## 三、状态机

### 3.1 状态定义

| 标准状态 | 英文标识 | 含义 |
|----------|----------|------|
| 未处理 | open | 尚未梳理 |
| 已转化 | converted | 已转为 Task、ADR、Risk、Dependency 或 Pitfall |
| 已关闭 | closed | 已梳理或已过期，无需进一步行动 |

converted 和 closed 都是终态。converted 表示 Memo 已经转化为其他对象，closed 表示 Memo 经梳理后不再需要行动。

### 3.2 合法状态流转

```text
open → converted（满足转化条件，记录关联对象 ID）
open → closed（满足关闭条件，记录关闭原因）
```

终态对象不得重开。如需重新处理，必须新建 Memo 承接。

### 3.3 关闭条件

Memo 关闭必须满足以下任一条件：

1. 已转为 Task（记录 `linked_task_id`）；
2. 已转为 ADR（记录 `linked_adr_id`）；
3. 已转为 Risk 或 Dependency（记录关联对象 ID）；
4. 已转为 Pitfall（记录关联对象 ID）；
5. 已记录为约束或发现，无需进一步行动（记录 `close_reason`）；
6. 已过期或不再相关（记录 `close_reason`）。

关闭 Memo 时必须记录关闭原因或关联对象 ID，不得无理由关闭。

## 四、字段契约

### 4.1 基础字段

Memo YAML 文件必须包含 10 §12.2 定义的基础字段：`id`、`type`、`title`、`status`、`created`、`updated`。

### 4.2 Memo 扩展字段

10 尚未定义 Memo 格式契约，本文档定义 Memo 扩展字段如下：

| 字段 | 必须 | 约束 |
|---|---|---|
| `content` | 是 | 备忘内容 |
| `priority` | 否 | 合法值：P0、P1、P2、P3 |
| `source` | 是 | 来源，合法值：manual、conversation、audit、tool |
| `closed_at` | 条件必须 | 仅当 status 为 closed 或 converted 时必须填写，格式 YYYY-MM-DD |
| `close_reason` | 条件必须 | 仅当 status 为 closed 时必须填写 |
| `linked_task_id` | 条件必须 | 仅当转化为 Task 时必须填写 |
| `linked_adr_id` | 条件必须 | 仅当转化为 ADR 时必须填写 |

### 4.3 文件命名

文件命名格式：

```text
pm-kit-base/memos/memo-{NNNN}.yaml
```

- 编号从 0001 开始递增，固定 4 位
- 每个项目独立编号

## 五、与其他对象的关系

### 5.1 转化关系

Memo 可转化为以下对象：

1. **Task**：当 Memo 中的输入已经有明确目标、执行边界、完成标准和需要追踪的状态时；
2. **ADR**：当 Memo 中的输入涉及需要长期追溯的判断或选择时；
3. **Risk**：当 Memo 中的输入涉及不确定性或潜在影响时；
4. **Dependency**：当 Memo 中的输入涉及外部依赖或阻塞因素时；
5. **Pitfall**：当 Memo 中的输入已经是可复用的踩坑经验时。

转化后 Memo 状态应变为 converted，并记录关联对象 ID。

转化原则依据 14 §5.1：转化必须满足目标对象的准入条件；转化后源对象状态应标记为已转化，并记录关联目标对象 ID；转化不得丢失源对象的背景和原因；转化操作须经 Human Gate 评估。

### 5.2 不得转化的对象

Memo 不得转化为 Requirement。如果 Memo 中的输入已经沉淀为需求或专题目标，应直接写入 Requirement 文档，Memo 关闭并记录 `close_reason`。

### 5.3 最低颗粒度

Memo 不要求可独立执行、可独立验证或可独立关闭。Memo 的颗粒度由保留价值决定，不由执行需求决定。

但单个 Memo 不应承载多个不相关的输入。如果一条 Memo 包含多个独立发现或提醒，应拆分为多条 Memo。

### 5.4 Memo 不删除

Memo 不应被删除来消除历史。关闭和转化都应通过状态、关闭原因或关联对象 ID 表达。

如果 Memo 被误创建，应关闭并记录 `close_reason`，而不是删除。

## 六、初始化检查项

创建本文档时必须确认以下事项，对齐 14 §3.2 初始化维度：

1. Memo 是否满足 14 §9.2 的准入条件：Memo 已出现稳定的状态机（open/converted/closed）、字段定义可定义、需要独立追踪和校验、实践规则具有跨项目复用价值；
2. Memo 的状态机是否稳定：三个状态和两条合法流转路径已验证；
3. Memo 的字段契约是否可定义：基础字段对齐 10 §12.2，扩展字段在本文档 §4.2 完整定义；
4. Memo 的初始化检查项和审计检查项是否可声明：本文档 §6 和 §7 完整列出；
5. Memo 与 10-13 的适配关系是否可表达：本文档 §8、§10、§11 分别声明适配关系。

## 八、AI 协作适配

本节声明 Memo 对象如何适配 11 定义的 AI 协作规则，不重新定义 11 的规则。

### 8.1 AI 如何读取 Memo

1. AI 依据 L1 必读文档索引判断是否需要读取 Memo 事实源；
2. AI 读取 Memo 时应优先关注 open 状态的 Memo，判断是否满足转化或关闭条件；
3. AI 不得将 Memo 作为项目背景知识库或长期记忆读取。

### 8.2 AI 如何创建 Memo

1. AI 识别到需要保留但暂不任务化的输入时，应先判断是否满足 §1.4 准入条件；
2. 不满足准入条件的信息应留在当前对话上下文中，不写入 Memo 事实源；
3. AI 创建 Memo 时必须填写全部必填字段，不得省略 content 和 source；
4. AI 不得因为某个信息"有价值"就自动创建 Memo。

### 8.3 AI 如何处理 Memo 转化

1. AI 发现 open 状态的 Memo 满足转化条件时，应建议转化为目标对象；
2. 转化操作须经 Human Gate 评估（见 §九）；
3. 转化后 AI 必须更新 Memo 状态为 converted 并记录关联对象 ID。

### 8.4 Skill 适配

1. Skill 可将对话、审计发现整理为 Memo，但必须先判断是否满足 §1.4 准入条件；
2. Skill 不得绕过 Memo 准入条件自动创建 Memo；
3. Skill 发现 Memo 满足转化条件时，应建议转化而非自动执行。

### 8.5 需求增加识别

AI 在对话中识别到需求增加时，依据 11 §6.7 的识别标准判断是否需要整理为 Memo 或 Task。

## 九、Human Gate

以下 Memo 相关操作应评估 Human Gate：

1. 将重要 Memo 转为 Task 或 ADR；
2. 批量关闭未梳理的 Memo；
3. 改变 Memo 的事实源归属。

Human Gate 的执行规则依据 11 §12.3：AI 检测到 Human Gate 场景时必须暂停并等待用户确认；违反 Human Gate 的操作必须回滚并记录到 Change 记录。

## 十、程序辅助适配

本节声明 Memo 对象如何适配 12 定义的程序辅助规则，不重新定义 12 的规则。

### 10.1 解析

1. 程序可解析 `pm-kit-base/memos/` 下的 YAML 文件；
2. 解析依赖 10 §12.2 定义的基础字段和本文档 §4.2 定义的扩展字段；
3. 解析失败时应报告具体的失败位置和期望格式，不得静默跳过。

### 10.2 校验

程序可对 Memo 执行以下校验：

| 校验类型 | 校验对象 | 校验依据 |
|---|---|---|
| 字段完整性 | Memo 必填字段 | 本文档 §4.2 |
| 状态合法性 | Memo 状态值和流转路径 | 本文档 §3 |
| 条件必填 | closed/converted 状态的关联字段 | 本文档 §4.2 |
| 引用有效性 | linked_task_id、linked_adr_id | 项目文件存在性 |

### 10.3 聚合

1. 程序可聚合 Memo 状态分布、未关闭 Memo 列表和转化统计；
2. 聚合输出属于派生视图数据，不是事实源；
3. 聚合输出必须包含来源引用，每个数据项必须能追溯到 Git 文件事实源。

### 10.4 受控写入

1. 程序可提供 Memo 的受控写入入口，写入目标为 `pm-kit-base/memos/`；
2. 写入前必须校验字段完整性、状态合法性和是否触发 Human Gate；
3. 写入后必须记录变更记录。

## 十一、工具展示适配

本节声明 Memo 对象如何适配 13 定义的工具展示规则，不重新定义 13 的规则。

### 11.1 展示范围

工具可展示以下 Memo 信息：

1. Memo 状态分布（open / converted / closed 数量）；
2. 未关闭 Memo 列表及摘要；
3. Memo 转化路径和关联对象；
4. Memo 创建时间线。

### 11.2 展示约束

1. 工具展示的 Memo 信息必须可追溯到 `pm-kit-base/memos/` 中的 Git 文件事实源；
2. 工具不得维护与 Git 文件不一致的 Memo 权威状态；
3. 工具展示的 Memo 列表属于派生视图，不得替代结构化事实源。

### 11.3 受控写入

1. 工具可通过受控写入入口创建、更新或关闭 Memo；
2. 工具写入必须遵守 12 定义的受控写入原则；
3. 工具写入后必须触发 Change 记录。
