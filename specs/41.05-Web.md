## 一、本文定位

Web 展示层是多角色思考的**派生视图**，用于展示角色结论、分歧、风险、回写建议和 Human Gate 待确认项，帮助人类审查和确认。**页面状态不是事实源。**

---

## 二、Web 应展示的核心内容

| 区域 | 展示内容 |
|---|---|
| 概览 | 主题、模式、触发原因、Agent 前提 |
| Context | 输入来源、读取事实源、适用规范规则 |
| 角色分析 | 各角色结论、风险、建议动作 |
| 分歧对比 | 一致结论、分歧点、待确认问题 |
| 风险汇总 | 高/中/低风险列表 |
| 回写建议 | 候选事实源、对象类型、是否需要 Change |
| Human Gate | 待确认事项、影响范围、建议确认内容 |
| 证据链 | 关联文件、对象、报告、变更记录 |

## 三、硬性边界

Web 展示层**不得维护**：

1. 与 Git 文件事实源冲突的报告状态
2. 只存在于 UI 中的确认结果
3. 只存在于缓存中的角色结论
4. 只存在于页面状态中的回写结果
5. 无法追溯来源的风险或建议

**当展示结果与 Git 文件事实源不一致时，以 Git 文件事实源为准，并提示刷新或重新读取。**

## 四、受控操作入口

Web 可提供：复制或导出报告摘要、生成回写候选、投递给 AI 对话层继续处理、发起创建 Task/Memo/ADR/Risk/Evidence/Change 的请求、标记需要 Human Gate 确认的事项。

**不得：** 直接调用 AI/Skill/Agent、绕过 Tools 校验、将按钮点击结果替代 Git 文件事实源中的证据/决策/变更记录。

## 五、展示刷新

Web 展示层应支持：从 Git 文件事实源重新读取、写入后刷新关联对象和 Change、标记派生视图生成时间和数据来源、在源文件变化后提示重新生成视图。

缓存或数据库只可作为派生层，**必须可重建且不可成为唯一事实源**。

## 六、门禁

新增高影响受控编辑入口、Web 展示层写入或覆盖 Git 文件事实源、将 UI 状态或缓存升级为稳定事实、直接调用 AI/Skill/Agent、绕过 Tools 校验或门禁时，必须暂停确认。
