## 目录使用边界

每一条 `rule_key` 表示一个不可静默省略的 Code 机械规则族；具体字段、枚举、状态和关系含义仍唯一由当前规范正文及 `fact-object-field-registry` 定义。`owner` 是唯一的实现责任域，不是来源权威。`entry_coverage` 列出只要该规则族适用于对象即必须一致覆盖的公开消费或受控写入路径；不适用的操作必须以来源明确的能力边界说明，不能在目录外静默跳过。

`unavailable_boundary` 的 `required` 表示：规则尚未实现、所需输入/全集/预算/安全读取无法完成，或实现无法形成可信结果时，读取、候选或写前检查不得把受影响对象报告为 `mechanically_valid`，并必须把相应范围标记为 `unavailable` 或 `partial`。它不把已完成的 `invalid`、`not_found` 或独立对象失败改写为不可用，也不授权 Code 裁决自然语言语义。

`coverage_status` 只表示当前 Code 映射是否已完整覆盖该规则族的全部 `entry_coverage`，闭集为 `complete` / `incomplete`。`complete` 必须有可定位的实现和正反测试，且没有未覆盖范围；`incomplete` 必须明示尚不可用的入口或规则范围，可以保留已存在的局部实现与测试引用，但不得因此宣称整行已完整覆盖。实现或测试完全不存在时使用字面量 `unavailable`，不得填入计划中的函数、入口或测试名。

`test_obligation` 是范围匹配测试的最小闭集。新增、删除或收紧任何 `rule_key`、来源定位或入口范围时，必须在同一变更同步更新实现映射和正反测试；三张表的 `rule_key` 与 `coverage_status` 必须分别精确一致。检查、入口或测试缺任一项时，该规则族只能登记为 `incomplete`，不具备 `mechanically_valid` 声明资格。

下列判断不得被目录、validator、operation 或测试冒充为机械通过：是否应创建对象、自然语言摘要是否充分、来源真实性与证据充分性、关系是否在领域上合理、审核是否独立、Human 决定含义、风险接受、以及事实是否当前适用。它们仍分别由 AI 或 Human 承担。外部直写防护属于环境接入与写入边界，由相应环境规范和实现承接，不属于上述语义判断列表。本目录也不授权批量改写或修复既有对象。
