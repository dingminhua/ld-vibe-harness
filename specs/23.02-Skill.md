## 1. 本文定位

本文是 `specs/23-Pitfall-踩坑记录.md` 的历史机制文件（编号 23.02），承接 Skill 契约式行动实践。本文不是独立工作模型，不得重新定义 Pitfall 的对象定位、准入条件、状态机、对象关系、Human Gate、字段契约、事实源回写或证据留存。发生冲突时，以 23 主文档和上位基础规范为准。

---

## 2. 当前状态与未来能力定义

### 2.1 当前状态

Pitfall 专用 Skill 当前未创建（active-prep），原因：

1. Pitfall 实例数量不足，尚未形成稳定的整理和筛选模式；
2. 踩坑经验的输入来源（Task、Evidence、对话）的整理路径尚未充分实践验证；
3. Pitfall 读取后的筛选逻辑（按标签、适用范围、关联对象）需要更多实例后才能确定稳定规则；
4. 在不具备足够实例的前提下，Skill 可能过度设计或过早固化。

### 2.2 未来能力定义

Pitfall 整理 Skill 应具备以下能力：

1. **经验整理**：将对话、Task 执行结果、Evidence 或审计发现中的踩坑信息整理为 Pitfall draft YAML；
2. **准入判断辅助**：根据 23 主文档 §3.3 准入条件，判断输入信息是否可能满足 Pitfall 准入条件；
3. **字段预填**：提取对话或执行记录中的问题现象、触发条件、根因、解决方式和验证结果，预填到 YAML 字段；
4. **关联对象发现**：识别来源 Task、Evidence、Memo 或 Change 并填入 `source_objects`；
5. **状态筛选**：按状态、标签、适用范围或关联对象筛选 Pitfall 供参考；
6. **分流建议**：识别 Pitfall 中可分流为 Rules、Skill 或 Tools 的规避策略和流程修正；

Skill 不得自动创建 active Pitfall，不得绕过 Human Gate 创建、激活、归档或替代 Pitfall，不得判断经验是否最终满足准入条件（应提示用户确认）。

---

## 3. 实现前提

在创建 Pitfall 整理 Skill 之前，应满足以下前提：

1. Pitfall 实例积累到一定数量（建议不少于 3 个），输入模式和字段稳定；
2. `ldvh-base/pitfalls/` 存在实例，可用于验证 Skill 的整理和筛选逻辑；
3. 23.06-Contract 字段稳定，无大范围变更；
4. Pitfall Tools 至少具备 YAML 解析和字段校验能力后，Skill 可在此基础上组合；
5. Pitfall 与其他对象（Task、Evidence、Memo）的关联引用路径至少有实例验证。

---

## 4. 边界约束

1. Skill 只整理、筛选和建议，不替代 Human Gate；
2. Skill 可输出 draft YAML，但不得直接写入 active 状态；
3. Skill 不得修改 specs、Rules、Task、Evidence、ADR 或其他工作模型；
4. Skill 不得成为 Pitfall 第二事实源，写入必须通过 Tools 受控写入或人工写入回写 `ldvh-base/pitfalls/`；
5. Skill 不得创建、修改或删除其他 Skill、Agent 或 Rules 实体。

---

## 5. 检查项

检查 Pitfall Skill 当前 active-prep 状态是否合规时，应确认：

1. Pitfall 整理 Skill 是否未在实现前提满足前创建；
2. 当前是否有 Pitfall 实例可能被误用 Skill 进行自动写入；
3. 当前 AI 是否按 23 主文档和 23.01-Rules.md 的人工方式处理 Pitfall 创建和读取。

---

## 6. 待补齐事项

1. Pitfall 实例积累后，应重新评估实现前提是否满足；
2. 实现前提满足后，应经 Human Gate 将本文升级为 active 并创建 Skill 实体；
3. Pitfall 输入模式（对话→→Task→→Pitfall 还是对话→→Pitfall 直写）待实践经验后固化。
