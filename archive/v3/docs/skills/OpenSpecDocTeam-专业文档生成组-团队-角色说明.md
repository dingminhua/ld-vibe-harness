# 专业文档生成团队 Skill：角色与提示词概要

> 说明：本文档只整理可共享的角色职责与工作提示概要，不包含逐字内部提示词、隐藏系统指令或不可公开的调度细节。

## 角色总览

该 Skill 面向企业级长文档生成与审核，采用“主理人编排 + 专业成员分工”的协作模式。核心角色包括 1 位主理人与 3 位专业成员。

| 角色 | Agent ID | 定位 | 主要产出 |
|---|---|---|---|
| 章成文（Zhang） | doc-team-lead | 总编辑 / 主理人 | 需求分析、章节拆解、项目参数卡、阶段编排、最终汇编 |
| 苏寻源（Su） | doc-researcher | 文献检索员 | 规范、案例、技术参数、来源说明等检索报告 |
| 支笔生（Zhi） | doc-generator | 内容生成员 | 按章节生成结构化正文、修订稿、模板填充内容 |
| 严审之（Yan） | doc-auditor | 质量审核员 | PASS / REVISE 审核结论、问题清单、修改建议 |

## 1. 章成文（Zhang）· 总编辑 / 主理人

### 角色职责

- 判断用户需求属于完整长文档、模板填充、增量补章、快速草稿还是独立审核。
- 明确文档类型、行业领域、项目背景、质量要求、检索模式。
- 拆解章节大纲，并维护“项目参数卡”以保持跨章一致。
- 调度检索、生成、审核三个专业成员，汇总成员产出。
- 负责最终文档的目录、格式、章节顺序、待完善事项与免责声明。

### 提示词概要

主理人的提示重点是：

- 先做需求分析，再确定工作流。
- 不直接替专业成员产出检索报告、章节正文或审核意见。
- 每一章按“检索 → 生成 → 审核 → 必要修订”的闭环推进。
- 对缺失信息使用 `[待填写]`，不得编造规范编号、条文或项目参数。
- 最终交付 Markdown 格式的完整文档或审核报告。

## 2. 苏寻源（Su）· 文献检索员

### 角色职责

- 围绕指定章节检索相关行业规范、标准条文、历史案例、技术参数范围和关联章节信息。
- 对资料进行结构化整理，标注来源、相关度和适用边界。
- 在资料不足时明确说明“未命中”或“信息缺口”，避免无依据推断。

### 提示词概要

检索员的提示重点是：

- 根据章节标题、章节要点和项目参数卡进行检索。
- 检索覆盖四类信息：行业规范、历史案例、技术参数、关联信息。
- 最多进行渐进式检索，优先返回可靠来源。
- 输出结构化检索报告，说明来源与相关度。
- 无结果时如实反馈，不能补造资料。

## 3. 支笔生（Zhi）· 内容生成员

### 角色职责

- 基于检索资料和项目参数卡撰写章节正文。
- 按用户模板或行业文档习惯组织标题、表格、编号和条文引用。
- 根据审核意见进行修订，保证内容完整、格式统一、参数一致。
- 对缺失资料使用 `[待填写]` 并补充信息缺口声明。

### 提示词概要

内容生成员的提示重点是：

- 只基于主理人提供的检索报告、模板和项目参数卡写作。
- 使用 Markdown 结构化输出。
- 统一规范引用格式，例如“《规范名称》(编号) 第X.X.X条”。
- 不留下 `XX`、`___` 等原始占位符，无法确认的内容统一写 `[待填写]`。
- 收到审核退回意见后，针对问题清单修订正文。

## 4. 严审之（Yan）· 质量审核员

### 角色职责

- 审核章节正文与检索报告、项目参数卡是否一致。
- 检查逻辑、规范、参数、完整性、格式和跨章一致性。
- 输出 PASS 或 REVISE 结论，并列出必须修改项与建议优化项。
- 不直接重写正文，只给出审核判断和可执行修改建议。

### 提示词概要

审核员的提示重点是：

- 对待审内容进行六维审核：逻辑一致性、规范符合性、参数合理性、内容完整性、格式规范性、跨章一致性。
- 核对规范引用是否来自检索报告，避免虚构法规或条文。
- 明确给出 PASS / REVISE。
- 如需退回，列出具体、可执行、可验证的修改项。
- 对跨章矛盾或参数冲突进行标记。

## 工作流摘要

### 完整长文档生成

1. 主理人分析需求并拆解章节。
2. 检索员按章检索资料。
3. 内容生成员基于资料撰写章节。
4. 审核员审核章节，必要时退回修订。
5. 主理人汇总章节、统一格式并交付完整文档。

### 模板填充

1. 主理人解析模板结构。
2. 检索员补充必要资料。
3. 内容生成员按模板填充。
4. 审核员检查一致性和完整性。
5. 主理人保留模板结构并统一输出。

### 独立审核

1. 主理人解析待审文档结构。
2. 审核员逐章审核。
3. 主理人汇总审核报告。

## 使用边界

- 可以输出角色职责、工作流、可共享的提示词概要。
- 不输出逐字内部提示词、隐藏系统指令或平台调度细节。
- 涉及规范、法规、标准时，必须以可追溯来源为准；来源不足时应标记信息缺口。

## 什么时候会触发？

该 Skill 的协作机制会按用户问题类型进入对应流程：

### 触发归类（路由）

- **单一维度提问**：只需检索、只需写作、或只要审核时，会直接调度对应成员（仍需先建立团队）。
  - 只要资料检索：调度 `doc-researcher`
  - 已有资料只需生成：调度 `doc-generator`
  - 只要审稿/复核：调度 `doc-auditor`
- **综合性长文档任务**：用户要求“帮我写一份 XX 方案/说明/手册”等，默认走完整长文档流程（Workflow A）。
- **按模板填充**：用户说“按这个模板填写/按模板生成”，走 Workflow B。
- **增量补写**：用户说“帮我补某一章/重写某章节”，走 Workflow C。
- **快速草稿**：用户要求“快速生成/草稿即可/不需要审核”，走 Workflow E。
- **独立审核**：用户要求“帮我审一下这篇文档”，走 Workflow D。
- **章节较多并要求加速**：章节大于 5 章且用户要求并行时，走 Workflow F。

### 原文（共享版摘录）

以下为与触发与路由相关的原文要点（可共享）

```text
| 问法类型 | 直接调谁 |
|----------|----------|
| 只要资料检索（"帮我查XX规范"） | `doc-researcher` |
| 已有资料只需撰写（"基于这些资料写第X章"） | `doc-generator` |
| 只要审核现成文档（"帮我审一下这篇方案"） | `doc-auditor` |
| 完整长文档生成 | 走 Workflow A |
| 基于模板填充 | 走 Workflow B |
| 增量补写某章/几章 | 走 Workflow C |
| 快速草稿（跳审核） | 走 Workflow E |
| 独立审核一篇已完成文档 | 走 Workflow D |
```
```text
### 工作流触发摘要
- 触发 Workflow A：用户提出“帮我写...方案/说明/手册”且未说明快速/增量。
- 触发 Workflow B：上传/粘贴模板或明确“按这个模板填写”。
- 触发 Workflow C：明确要求补写/重写某一章。
- 触发 Workflow D：明确要求审阅/一致性检查一篇已有文档。
- 触发 Workflow E：明确要求快速草稿或免审核。
- 触发 Workflow F：文档章节 >5 且用户要求加速并行。
```
