## 1. 定位

本文承载 07 授权的关联提交派生优先级。

07 正文定义 Git commit records 的事实源修改追溯性质；本文只说明使用 Git 原生命令查询时如何判断“关联提交”，不得要求工作对象手写提交清单，不得定义 Git 查询实现、Web DTO 或知识地图输出 Schema。

## 2. 派生优先级

工作对象、规范、Code 和 Web 需要“关联提交”时，应按以下优先级派生：

1. commit touched files 与对象事实源路径、规范路径、Code/Web 文件路径的匹配；
2. commit description 或 body 中自然出现的对象 ID、规范编号、规范路径或文件路径；
3. Git 提交时间线、相邻提交、分支上下文和 Human 审查结论；
4. 必要时由用户或 AI 在当前分析中临时筛选，但不得回写为手填提交字段。

对象 ID、规范编号或路径可以出现在 description 或 body 中，但不得要求 AI 为了追溯而补写固定 `Refs:` 字段。Git 变更由 Git 自身的 hash、文件路径、diff 和时间线追踪。

## 3. 禁止事项

1. 不得在工作对象中手写维护 `related_changes` 或等价提交清单字段；
2. 不得把 Web 展示的关联提交列表回写为对象事实；
3. 不得把知识地图派生边写回 Git commit records；
4. 不得把一次临时筛选结果写成永久关联事实；
5. 不得用固定 `Refs:` trailer 替代 body 自然语义。

## 4. 辅助核对表

| 核对项 | 标准 |
|---|---|
| 来源可追溯 | 派生结果能回到 commit hash、文件路径、diff 或正文自然文本 |
| 优先级清楚 | touched files 和自然文本优先于当前分析中的临时筛选 |
| 不手写字段 | 对象事实源没有维护提交清单字段 |
| 不强制 trailer | 不要求固定 `Refs:` 字段作为唯一追溯入口 |

## 5. 待补齐事项

1. commit message 契约、type/scope、body 条件或提交语言规则变化后，应检查本文派生优先级是否仍能支持原生 Git 查询；
2. Web 提交展示确认后，应检查关联提交显示是否仍回指 Git commit records；
3. 本文只作为派生原则，不要求 LDVH 建立 Git 图谱、专用 Git 查询层或运行时图谱实现。
