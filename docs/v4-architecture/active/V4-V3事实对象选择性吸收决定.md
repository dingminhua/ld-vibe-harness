# V4 V3 事实对象选择性吸收决定

> 记录性质：本文记录 Human 对 V3 事实实例进入 V4 的当前范围决定。它不是规则源，不授权写入，也不使任何 V3 内容自动取得 V4 身份。
> 决定日期：2026-07-15
> 当前状态：选择性吸收；当前未选择具体来源，未开始实例吸收

## 1. Human 决定

V4 对 V3 事实对象采取选择性吸收，不再以 92 项全部逐条形成 V4 承接为当前目标，也不把全量迁移作为 bootstrap/resume、真实 dogfood 或发布的前置条件。

已经冻结的 92 项不可变基线与 decision-independent source characterization 继续作为可回读的历史库存和机械调查证据。它们只证明 V3 历史输入的范围与形态，不表示任何一项必须进入 V4，也不构成迁移进度。

该决定不恢复 V3 Schema、字段、状态、路径、身份、时间、关系、实现或历史生命周期效力。V3 内容只有在 Human 选择后，才可能依据当时有效的 V4 来源重新判断。

## 2. 选择与吸收边界

每次吸收只处理 Human 明确选择的具体来源、当前价值和用途，并遵守以下边界：

1. 重新读取所选 archive 源、当前规则和必要证据，不从旧状态、旧计划或 characterization 推断 V4 结论；
2. 只吸收满足当前用途的最小内容，可以不吸收、收窄、拆分、合并或改用另一合法事实类型；
3. 旧 WorkCase 不携带当前工作意图；是否建立新的 V4 WorkCase 必须由 Human 依据当前工作另行决定；
4. 选择本身不授权创建或更新。实际写入必须使用当时已有且适用的 V4 合法边界，并完成回读、验证和 Git 留痕；
5. 如果现有来源或 Code 不能合法承载所选最小范围，停止该项并单独评估缺口，不以迁移为由自动新增兼容层、迁移状态机、中央登记、专用行动模板或批处理 Code。

未被选择的 V3 对象继续留在 archive，不产生待办、缺口或 V4 承接义务。

## 3. 与当前推进路线的关系

当前工作顺序是：

1. 优先组合已有管辖解析、能力摘要、F0/F1 和来源指针，建立低成本 bootstrap/resume；只有真实使用证明现有公开操作不能形成稳定边界时，才评估新的 Helper 能力；
2. 由 Human 选择真实受管辖工作，完成事实读取、必要创建、CAS 更新、强制中断、换会话恢复、验证、Git 留痕、结果交还和关闭的纵向 dogfood；不得为证明流程制造事实；
3. 当 Human 选定具体 V3 来源及当前用途时，再按 §2 吸收相应最小范围；选择性吸收不阻断前两项；
4. dogfood 后依据实测决定必要的减法或修正，再恢复 Web V4 bridge、原生 Windows、LDVH 自身 CI 和发布准备。

Web、Windows、CI 或环境工作不会因某个 V3 对象提及它们而自动恢复。现有 92 项机器基线、characterization 和只读验证器继续保留，但不再承担当前路线 Gate。

## 4. 证据与变更关系

本决定由 `../investigations/V4-V3事实对象选择性吸收审计结论.md` 的逐项审计支持，并替代此前“92 项全部逐条迁移后再 bootstrap/resume”的实施顺序。旧全量迁移决定及其契约候选由 Git 历史保留，不再代表当前范围或完成条件。

本文只校正工作范围与顺序，不修改 Specs、Helper、tests、生产 Code、Web 或任何事实实例。
