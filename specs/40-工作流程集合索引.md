## 1. 本文解决的问题

本文原用于解决 LDVH 中工作流程区段如何登记、讨论、检查和被后续落地检查、工作流程设计、能力资产建设和执行闭环消费的问题。ADR-0007 接受后，本文不再作为工作流程集合事实源，仅作为旧手写索引迁移说明和历史参考。

迁移期间，AI 和 Human 进入具体工作流程前，应优先读取 40-59 成员主文件自描述和 Code 派生工作流程集合索引；在 Code 派生索引尚未完成前，本文仅可作为历史参考，不得覆盖成员主文件事实。旧内容曾用于确认：

1. 哪些编号已经占用；
2. 哪些工作流程是 active、unclear、next、planned、candidate、reserved 或 removed；
3. 哪些底层治理流程应优先创建；
4. 哪些执行阶段候选尚未生效或已被合并；
5. 每个候选流程在正式创建前需要先讨论哪些边界；
6. 后续落地检查、能力资产建设和工作流程设计应读取哪些 active 工作流程，并把哪些 planned 或 candidate 工作流程作为讨论输入。

本文不定义具体工作流程的 Context、Scenario、Gate、执行流程、证据规则、事实源回写要求或行动特有检查。这些内容由 41-59 具体工作流程规范承载。

## 2. 与 00 和 06 的关系

00 定义 LDVH 工作流程是五类构成要素之一，用于控制 AI 如何读取、判断、执行、验证、回写和暂停。06 定义工作流程的基础规则、标准组成、准入条件、主控调度、事实源回写和检查要求。

本文承接 00 和 06，将 41-59 的优先级调整为先建立 LDVH 自身底层治理流程，再承接执行阶段流程。底层治理流程优先服务 specs、Code、Rules 入口、能力资产、事实源、变更影响和工作流程自身设计的审查，目标是让 AI 能先判断 LDVH 规则和能力是否可信、可用、可验证，再进入具体任务执行。

本文只维护工作流程集合的清单、状态、候选来源、讨论顺序和落地检查候选输入。本文不得反向改写 06 的通用规则，也不得替代 41-59 具体工作流程规范。

## 5. 工作流程集合闸门

创建、删除、恢复或调整工作流程前，必须先通过本文判断集合状态，再决定是否创建或修改 41-59 文档。

集合闸门规则如下：

1. `active` 项可以作为当前权威工作流程入口；
2. `next` 项是下一优先讨论对象，不表示对应主文档已经生效；
3. `planned` 项已确认需要成为具体工作流程，但创建主文档前仍需讨论 Context、Scenario、Gate、事实源回写、环境适配和测试锚点；
4. `candidate` 项不得因为已有 Skill 或临时参考资料而自动生效；
5. `candidate` 项在正式创建前必须先判断是否应归为工作流程、Skill、Code、Web、最佳实践、工作对象规则或一次性执行策略；
6. `reserved` 编号不得绕过 Human Gate 占用；
7. 临时参考资料和临时 Skill 只能作为候选输入，不自动成为当前权威规范。

每个候选流程进入讨论时，至少应确认：

1. 该事项是否满足 06 的工作流程准入条件；
2. 是否需要独立主文档，还是应并入已有流程、工作模型、Code、Web、最佳实践或适配措施；
3. 该流程的核心 Context、Scenario、Gate、执行、回写、证据和失败降级是什么；
4. 是否需要 Skill、Agent、Rules / Instructions、Code、Web、Hook、CI 或人工降级共同承接；
5. 是否存在临时 Skill、临时路径、不推荐表达或与当前规范不一致的内容；
6. 行动特有可测试性锚点如何写入主文档；
7. 创建或修改该流程是否触发 Human Gate。

## 6. 参考与研究材料吸收边界

工作区根目录 `临时参考/`、`docs/studies/` 中的回退资料和工作流程重建设计评估是候选输入，不属于 LDVH 权威事实源，也不属于管辖项目安装后默认存在的目录。

吸收参考与研究材料时，应遵守以下规则：

1. 只吸收目标、流程经验、触发场景、输入输出和风险提示，不复制临时路径或临时编号；
2. 临时 Skill 不直接定义工作流程，必须回到 06、03.04、本文和 41-59 主文档重写；
3. 临时 Skill 中涉及非当前路径的内容，应按 `specs/` 和 20-39 工作模型规范重新定位；
4. 临时 Skill 与当前规范冲突时，以 `specs/` 正式规范为准；
5. 临时 Skill 内部如果出现互相冲突的 Human Gate 描述，应在具体流程讨论时重新判定，不得按临时 Skill 原文执行；
6. 临时 Skill 中“Skill 调用 Agent”“Skill 内部链式调度 Skill”等写法，应按 06 的主控唯一调度原则改写；
7. 本次工作流程重建设计评估文档只作为 40 重建的设计评估和 Human 确认记录，不替代 41-59 主流程规则；
8. 参考与研究材料中的完成勾选、验证结论或候选建议，不等于当前正式规范已创建或已生效。

1. 40 集合索引是否存在且与 01、03.02、06、03.04 一致；

## 11. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 新增、删除、重命名或重排 40-59 编号；
2. 改变某个编号对应的工作流程归属；
3. 将 unclear 或 candidate 项升级为 planned、next 或 active；
4. 将 planned 项降级为 candidate、removed 或 reserved；
5. 占用 59 保留编号；
6. 改变集合状态的含义；
7. 让本文定义具体流程的 Context、Scenario、Gate、执行流程、证据规则或事实源回写要求；
8. 将 `临时参考/` 或 docs/studies 中未吸收的内容直接视为当前权威规范。

工作流程集合索引检查至少包括：

| 检查项 | 标准 |
|---|---|
| 索引范围 | 已声明 40-59 编号范围 |
| 文档清单 | 每个编号的文档名、类型、集合状态、候选来源和定位清晰 |
| 状态边界 | unclear、next、planned、candidate 和 reserved 未被误当成 active 工作流程 |
| 讨论顺序 | 讨论顺序不自动改变编号或生效状态 |
| 规则边界 | 未承载具体流程 Context、Scenario、Gate 或执行正文 |
| 落地与检查输入 | 已说明后续落地检查、能力资产建设和工作流程设计如何消费本文 |
| Human Gate | 编号、状态、升级和降级场景已声明 Human Gate |
