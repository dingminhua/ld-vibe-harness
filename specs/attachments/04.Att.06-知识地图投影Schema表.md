## 3. 任务导航字段

知识地图面向 AI 入口导航时，`nodes` 和 `edges` 不能作为唯一行动输出。Code 必须同时生成以下任务导航字段，供 Rules 入口、AI 审核、行动编排和 Human-facing 摘要消费：

| 对象 | 字段 |
|---|---|
| `navigation` | `task_type`、`start_node`、`resolved_start_node`、`input_scope`、`effective_input_scope`、`layer`、`project_scope`、`degraded`、`summary` |
| `read_plan[]` | `path`、`node_id`、`title`、`priority`、`role`、`reason`、`source_relation`、`source_refs`，必要时补充 `suggested_sections`、`project_namespace`、`object_id` 或 `field_path` |
| `next_queries[]` | `purpose`、`command`、`input_scope`、`layer`、`start_node`、`reason` |
| `stop_conditions[]` | `condition`、`reason`、`fallback`、`source_refs` |
| `impact_summary` | `node_type_counts`、`relation_type_counts`、`affected_specs`、`affected_runtime_extensions`、`affected_fact_objects` |

`read_plan.priority` 至少应能区分 `P0`、`P1`、`P2` 和 `P3`：`P0` 表示任务起点或必须先读的权威原文，`P1` 表示上位依据、父规范、source_specs、Human Gate 或直接影响判断所需原文，`P2` 表示关联上下文、附件、消费方或验证入口，`P3` 表示可选扩展和后续调查。`read_plan.role` 至少应覆盖 `start`、`authority`、`context`、`impact`、`verification` 和 `fallback`。

`next_queries` 用于渐进式获取信息，不得鼓励一次性全量上下文注入。若当前 `input_scope` 无法定位 `start_node`，或任务同时涉及 Rules 入口、active specs 和工作对象，Code 应优先提示 `entry_navigation` 或等价组合查询；若工具降级、来源回指缺失或输出与原文冲突，`stop_conditions` 必须提示退回 active specs、事实对象、Rules 入口、07 Git 文件事实源或 Human Gate。

## 4. 当前实现边界

当前 `v2-check` 与 `knowledge-map` 已能输出 active specs、runtime extensions 和 governed projects 显式范围内的只读投影目标顶层字段、节点字段、边字段和来源回指。该输出仍是当次 Code 实时投影，不得被称为事实源、缓存或长期运行状态。

未实现的历史规范输入、Web 接入能力或其它后置能力，仍必须用诊断、review hints 或 `degraded` 暴露。Git history 不属于知识地图输入范围，历史追溯使用 Git 原生命令按需展开。
