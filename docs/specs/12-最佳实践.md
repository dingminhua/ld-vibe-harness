> 创建日期：2026-06-08
> 定位：记录 LDVH 使用过程中经过实践验证、可复用但不直接产生强制规则的最佳做法、案例和经验入口
> 适用范围：LDVH 自身项目和管辖项目中的最佳实践记录、案例沉淀、使用经验和非强制性操作建议

## 1. 本文解决的问题

本文解决 LDVH 最佳实践如何记录、分类、引用和升级的问题。

最佳实践用于记录已经在使用中证明有帮助的工作方式、对象组合、流程模式、外部能力接管经验、风险处置经验和用户接入经验。最佳实践帮助 AI 和 Human 少走弯路，但不直接定义新的强制规则、字段契约、状态机、事实源边界、Human Gate 或 Code 实现要求。

---
## 2. 与 00 总纲的关系

00 定义 LDVH 的顶层价值标准和运行闭环。本文承接该目标，通过记录可复用经验帮助 AI 更快进入有效工作方式。

本文不替代 00 或其他正式规范。最佳实践中的做法只有在被吸收到对应正式规范、工作对象、Code、Web、测试或其他权威位置后，才具备对应强制效力。

---
## 3. 最佳实践定位

最佳实践术语以 `docs/specs/02-术语规范.md` §10 为准。最佳实践是经验记录，不是规范规则。

最佳实践可以说明：

1. 某种工作方式适合什么场景；
2. 典型步骤如何安排更顺；
3. 常见风险如何提前规避；
4. 需要读取哪些规范或事实源；
5. 何时降级、暂停或触发 Human Gate；
6. 哪些经验已经适合升级为正式规范候选。

最佳实践不得直接定义：

1. 新的工作模型；
2. 新的工作流程；
3. 新字段、状态机或对象验收标准；
4. 新事实源权威位置；
5. 新 Code、Web 或运行投影硬规则；
6. 新 Human Gate 必须触发条件。

如果最佳实践反复承担强制规则功能，应回到对应正式规范吸收。

---
## 4. 实践分类

最佳实践可按以下类型记录：

| 类型 | 内容 | 示例 |
|---|---|---|
| 工作方式实践 | 对象组合、流程节奏、执行顺序和协作模式 | Memo 驱动调研、TaskPlan 到 Task 闭环 |
| 接管实践 | 非 LDVH 来源内容、第三方能力、用户既有资产的接管经验 | 外部脚手架接管复盘 |
| 验证实践 | 测试、校验、审阅和闭环验证经验 | 先跑最小验证再扩大改动 |
| 接入实践 | 既有项目、既有文档、既有工具纳入 LDVH 的经验 | README、CI、docs 逐步归属 |
| 风险实践 | 常见失败、误触发、绕过事实源或绕过 Human Gate 的处置经验 | 候选产物直接写入事实源的处置经验 |
| 工具实践 | Code、Web、Skill、Agent 或环境能力的稳定使用方式 | 外部生成器候选材料接管经验 |

## 5. 实践文档规则

最佳实践子文档可以使用“NN.SS-标题”加 `.md` 后缀命名。

最佳实践子文档应至少说明：

1. 实践适用场景；
2. 不适用场景；
3. 推荐路径；
4. 需要遵守的正式规范；
5. 关键检查点；
6. 常见失败方式；
7. 是否有待吸收为正式规范的硬规则候选。

最佳实践子文档不得以“规范”“规则”“要求”等标题包装强制约束。需要强制约束时，应回到对应正式规范。

## 7. 实践升级

最佳实践可以升级，但必须先判断升级位置。

| 发现 | 升级位置 |
|---|---|
| 术语反复使用且容易误读 | 术语规范 |
| 实践中的硬边界反复出现 | 对应正式规范 |
| 实践影响工作模型字段、状态或验收 | 工作模型规范 |
| 实践影响 AI 执行流程、Gate 或回写 | 工作流程规范 |
| 实践需要确定性检查、脚本或测试 | Code 或运行闭环测试 |
| 实践影响 Web 呈现或受控交互 | Web 规范或 Web 实现 |
| 实践只是经验或案例 | 保留在最佳实践 |

实践升级前应说明升级原因、影响范围和是否需要 Human Gate。

| 落地要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 上位约束承接要求 | 最佳实践不得替代正式规范、事实源边界、Human Gate、Code 验证或工作对象事实 | 本文 §2-§7、11 非 LDVH 来源内容治理、Human Gate | 最佳实践治理 | 新增、修改、引用、升级或删除最佳实践时 |

## 9. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 将最佳实践升级为正式规范规则；
2. 删除或重命名已被多个文档引用的最佳实践；
3. 将未经验证的一次性经验写成推荐路径；
4. 让最佳实践绕过正式规范、事实源边界、Human Gate 或验证要求；
5. 最佳实践影响多个工作模型、工作流程、Code、Web 或运行投影。

最佳实践检查至少包括：

| 检查项 | 标准 |
|---|---|
| 非强制性 | 未直接定义新规范、字段、状态、事实源或 Human Gate |
| 场景清晰 | 已说明适用和不适用场景 |
| 依据清晰 | 已说明需要遵守哪些正式规范或事实源 |
| 经验来源 | 来自实践、案例、接入或 Dogfood，不是纯理论推导 |
| 升级出口 | 发现硬规则时已指向正式规范吸收路径 |
