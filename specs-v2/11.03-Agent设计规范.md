## 一、Agent 创建前检查

Agent 是高级可选能力。PM Kit 不默认内置项目业务 Agent，也不要求受管理项目创建 Agent。创建或调用 Agent 前，应先完成以下检查：

| 检查项 | 判断问题 |
|---|---|
| 独立上下文 | 是否需要读取大量事实源，主上下文难以承载？ |
| 结论隔离 | 是否需要不同角色独立形成结论？ |
| 并行委派 | 是否需要多个角色同时分析？ |
| 工具权限 | 是否需要与主上下文不同的工具能力？ |
| 轻量替代 | 多角色讨论是否已经足够？ |
| Human Gate | 是否涉及创建、启用、修改、删除 Agent 或调整工具权限？ |

若以上必要条件不成立，应优先使用主上下文分析、Skill 或 11-AI协作规范 §八 多角色讨论。Agent 不适合承载稳定规范正文、项目事实源正文、完整流程教程或低频一次性任务。

## 二、Agent 定义文件模板

### 2.1 必须包含的段落

每个 Agent 定义文件建议包含以下段落：

```text
1. 角色定位
   - 覆盖项目
   - 核心职责
   - 调度方

2. 触发场景
   - 明确的触发条件列表
   - 触发频率预期

3. 分析关注点
   - 必须分析的技术/治理维度
   - 必须输出的判断项

4. 职责边界
   - 默认只读分析，除非主控明确授权写入
   - 不分析非职责范围内的实现细节
   - 必须标注上下游传播影响
   - 发现 Human Gate 场景时必须标注并停止修改

5. 必读文档
   - 分析前必须读取的事实源
   - 受管理项目资产使用受管理项目根相对路径，引用 PM Kit 基础规范时使用带 `trae-pm-kit/` 前缀的工作区路径

6. 输入/输出格式
   - 输入：用户 @ 调用时提供的需求上下文，或 SOLO Agent 调用时传递的上下文包
   - 输出：结构化分析结论

7. Trae 平台配置映射
   - Trae 名称
   - 提示词来源
   - 是否可被其他智能体调用
   - 英文标识名
   - 何时调用
   - MCP Server
   - 内置工具
   - 分享前脱敏要求
   - 高风险工具 Human Gate 范围
```

### 2.2 推荐边界声明

```markdown
## 职责边界

- 本 Agent 被动响应用户显式要求或 SOLO Agent 主控编排。
- 本 Agent 不自行触发，不调度其他 Agent。
- 本 Agent 发现 Human Gate 场景时必须标注并停止修改。
- 本 Agent 默认只读分析，除非主控明确授权写入。
- 本 Agent 使用 MCP 时必须遵守 11-AI协作规范 §十 的工具非事实源、最小授权和高风险 Human Gate 规则。
```

## 三、Agent 类型模板

| 类型 | 典型角色 | 适用模板重点 |
|---|---|---|
| 技术架构 Agent | 客户端架构师、服务端架构师、训练工程师、数据架构师 | 技术影响、接口兼容、上下游传播 |
| 治理/流程 Agent | 治理 Agent、安全工程师、检查 Agent | 规则合规、Human Gate、事实源归属、检查证据 |

PM Kit 不内置具体 Agent 角色模板，也不要求受管理项目默认创建 Agent。需要创建 Agent 时，应先证明主上下文、Skill 或多角色讨论不足，再依据本文维护项目内 Agent 定义摘要。

---

## 四、Agent 定义维护流程

产品项目需要创建或导入 Agent 时建议按以下步骤执行：

1. 先阅读 Trae 官方可一键导入的自定义智能体示例。
2. 判断是否满足 11-AI协作规范 §七 的 Agent 创建或调用门槛。
3. 按 11-AI协作规范 §十二 触发 Human Gate。
4. 用户确认后，在 Trae 中创建或导入自定义智能体。
5. 在产品项目 `docs/agents/` 目录维护 Agent 定义摘要。
6. 记录 Trae 平台配置映射：名称、Prompt、是否可被其他智能体调用、英文标识名、何时调用、MCP Server 和内置工具。
7. 检查职责边界是否仍符合 11-AI协作规范 §七 的 Agent 调度规则。
8. 追加 Change 记录。

## 五、Agent 生命周期

### 5.1 创建

1. 完成创建前检查。
2. 按 11-AI协作规范 §十二 触发 Human Gate。
3. 用户确认后，在 Trae 中创建或导入自定义智能体。
4. 将 Agent Prompt 或定义摘要写入项目 `docs/agents/`。
5. 更新 `docs/agents/README.md` 或项目索引。
6. 追加 Change 记录。

### 5.2 修改

1. 判断修改是否影响职责边界、调度方式、工具权限或触发条件。
2. 涉及规则边界变化时按 11-AI协作规范 §十二 触发 Human Gate。
3. 同步修改平台 Agent Prompt 和项目定义文件。
4. 检查引用和索引。
5. 追加 Change 记录。

### 5.3 删除

1. 确认该 Agent 不再被任何流程引用。
2. 按 11-AI协作规范 §十二 触发 Human Gate。
3. 从平台删除或禁用 Agent。
4. 归档或删除项目定义文件。
5. 更新索引。
6. 追加 Change 记录。

## 六、Agent 项目结构

### 6.1 存放位置

```text
{project}/docs/agents/README.md       # Agent 索引
{project}/docs/agents/agent-{role}.md # Agent 定义文件
```

### 6.2 命名格式

```text
agent-{role}.md
```

`{role}` 使用小写连字符格式，如 `governance`、`client-architect`、`security-officer`。

### 6.3 README.md 格式规范

README.md 作为 Agent 索引，必须包含以下内容：

**使用原则**：

- 说明 PM Kit 不预设具体 Agent 模板
- 说明创建 Agent 前应先阅读 Trae 官方自定义智能体示例
- 说明创建/修改 Agent 调度边界必须触发 Human Gate
- 说明 Agent 定义文件应记录 Trae 平台配置映射

**Agent 列表格式**：

README.md 必须包含结构化表格，列出所有已定义的 Agent：

| 字段 | 含义 | 必填 | 示例 |
|---|---|---|---|
| Agent 名称 | Trae 平台显示名称 | 是 | 示例治理 Agent |
| 英文标识 | Agent 的唯一英文标识 | 是 | governance-agent |
| 是否可被调用 | 是否允许其他智能体调用 | 是 | 是（SOLO Only） |
| 触发方式 | Agent 的触发条件 | 是 | 用户显式要求或 SOLO 主控编排 |
| MCP Server | 配置的 MCP Server | 是 | 文件系统 |
| 内置工具 | 配置的工具权限 | 是 | 代码搜索、文件读写 |
| 定义文件 | Agent 定义文件的相对链接 | 是 | [agent-governance.md](agent-governance.md) |

### 6.4 Agent 定义文件格式规范

每个 `agent-{role}.md` 必须包含以下章节：

| 章节 | 内容要求 | 说明 |
|---|---|---|
| 角色定位 | 覆盖项目、核心职责、调度方 | 定义 Agent 的角色和职责 |
| 触发场景 | 触发条件列表、触发频率预期、即时停止条件 | 定义何时触发及停止规则 |
| 分析关注点 | 技术/治理维度、必须输出的判断项 | 定义检查分析的范围 |
| 职责边界 | 只读/写入权限、上下游影响、Human Gate 处理 | 定义 Agent 的行为边界 |
| 必读文档 | 分析前必须读取的事实源路径 | 确保 Agent 能获取权威信息 |
| 输入/输出格式 | 输入参数、输出结构定义 | 定义数据接口格式 |
| Trae 平台配置映射 | 名称、提示词来源、是否可被调用、英文标识名、何时调用、MCP Server、内置工具 | 记录 Trae 平台配置 |
| 提示词模板 | 可直接复制到 Trae 平台的提示词入口 | 只引用定义文件和执行约束，不复制定义全文 |

### 6.5 提示词设计原则

**单一事实源原则**：提示词不得重复 Agent 定义文件、PM Kit specs 或受管理项目事实源正文，必须引用 `docs/agents/agent-{role}.md` 作为权威事实源，只保留角色入口、执行约束和输出格式说明。

**提示词结构**：

```text
你是 {Agent 名称}。

## 核心指令
1. 执行前必须读取权威事实源：`docs/agents/agent-{role}.md`
2. 根据该文档定义的角色定位、触发条件、分析关注点、职责边界和输出格式执行
3. 严格遵守文档中定义的即时停止条件
4. 输出必须符合文档规定的结构化格式

## 执行流程
{简要流程说明}

## 必读文档清单
- `docs/agents/agent-{role}.md`（本 Agent 定义，权威事实源）
- `specs-v2/11-AI协作规范.md`（AI 协作规则事实源）
- `pm-kit-base/tasks/{TASK-ID}.yaml`（当前任务详情，需替换实际任务 ID）
- `docs/20-89/`（相关需求与专题文档）
```

**路径引用规范**：

受管理项目资产路径必须相对于受管理项目根目录。引用 PM Kit 基础规范时，必须使用带 `trae-pm-kit/` 前缀的工作区路径，不得用"当前项目 specs"指代 PM Kit 基础规范。

| 文档类型 | 路径格式 | 说明 |
|---|---|---|
| Agent 定义 | `docs/agents/agent-{role}.md` | 必须包含文件名，相对于 PM 项目根 |
| 规范文档 | `docs/NN-名称.md` | 必须包含文件名，相对于 PM 项目根 |
| 任务文件 | `pm-kit-base/tasks/{TASK-ID}.yaml` | 运行时替换实际任务 ID，相对于 PM 项目根 |
| 需求文档 | `docs/20-89/` | 目录路径，相对于 PM 项目根 |

**提示词编写要求**：

1. 路径必须完整：所有文档引用必须包含完整的相对路径（基于项目根目录）
2. 使用反引号包裹：路径必须用反引号（`` ` ``）包裹，便于 Agent 识别
3. 变量标记清晰：如 `{role}`、`{TASK-ID}` 等变量需用大括号标记，便于替换
4. 说明用途：每个文档后需简要说明其用途，帮助 Agent 理解为何需要读取

## 七、Agent 定义检查项

| 检查项 | 标准 |
|---|---|
| 单一事实源 | Agent 行为规则引用 11-AI协作规范 §七，不另写第二套调度规则 |
| 调度边界 | 明确用户显式要求或 SOLO Agent 主控编排 |
| 禁止自触发 | 明确 Agent 不自行触发 |
| 禁止调度链 | 明确 Agent 不调度其他 Agent，检查 Agent 也不需要 Agent 链 |
| Human Gate | 引用 11-AI协作规范 §十二，不维护第二套清单 |
| 必读文档 | 列出角色分析前必须读取的事实源 |
| 输出格式 | 输出结构化、可汇总、可审计 |
| Trae 配置映射 | 名称、Prompt、是否可被其他智能体调用、英文标识名、何时调用、MCP Server、内置工具、分享前脱敏要求已记录 |
| MCP 边界 | MCP 仅作为工具能力，已明确最小授权和高风险 Human Gate 范围 |
| 索引同步 | `docs/agents/README.md` 已更新 |
| Change 记录 | 创建、修改、删除均已记录 |
