> 创建日期：2026-06-08
> 定位：定义 specs 中具体工作流程规范文档的写作骨架、章节边界、可测试性锚点和检查要求
> 适用范围：`specs/41-59` 具体工作流程规范文档
> 上位依据：`specs/03-文档基础规范.md`
> 相关规范：`specs/03.01-规范文档规范.md`、`specs/03.02-索引文档规范.md`、`specs/06-工作流程基础规范.md`、`specs/09-事实源边界与承载规范.md`

---
## 1. 本文解决的问题

本文解决具体工作流程规范文档应如何书写的问题，包括文档骨架、Context、Scenario、Gate、执行流程、回写证据、环境适配边界、行动特有可测试性锚点和检查要求。

本文只规定工作流程规范文档的写作方式。工作流程的定义、准入、通用规则、主控调度和回写原则由 `specs/06-工作流程基础规范.md` 定义。

---
## 2. 与 00 和 06 的关系

00 定义工作流程是 LDVH 五类构成要素之一，并要求形成可读取、可执行、可验证、可回写的运行闭环。06 定义工作流程基础规则。工作流程测试机制是否存在 active 入口，应查询 40 工作流程集合索引。

本文承接 03 的文档治理规则和 06 的流程组成要求，规定具体工作流程规范如何把行动规则和行动特有可测试性锚点写入同一主文档。具体测试用例、预期行为矩阵、失败诊断和回归用例暂不由正式规范定义统一事实源；每个流程不另设测试子文档。

## 3. 适用文件

40 是工作流程集合索引，按 `specs/03.02-索引文档规范.md` 编写。41-59 是具体工作流程规范，按本文编写。

具体工作流程规范文件名采用：

```text
NN-{英文名}-{中文名}.md
```

文件名不得重复“工作流程规范”字样。新增具体工作流程规范时，不默认创建 `NN.01` 至 `NN.06` 固定能力子文档，也不默认创建独立测试子文档。

## 5. 行动特有可测试性锚点

具体工作流程规范必须包含行动特有可测试性锚点，用于说明该流程哪些关键行为需要能被验证。行动特有可测试性锚点至少覆盖：

1. 正向场景：满足 Scenario 时应进入流程；
2. 负向场景：不满足 Scenario 时不得进入流程；
3. Gate 场景：应暂停、确认或降级的条件；
4. 回写场景：稳定事实应写入哪里；
5. 失败降级：缺少上下文、工具失败、权限不足或 Human Gate 未确认时如何停止；
6. 回归风险：修改该流程后应重新检查哪些已有行为。

这些锚点是工作流程设计的一部分，不承载具体测试用例、预期行为矩阵、失败诊断或回归用例，也不替代 40 工作流程集合索引中的 active 流程判定。

## 6. 环境适配边界表达

具体工作流程规范可以说明 Rules / Instructions、Skill、Agent、Code、Web、Hook 或 CI 如何参与，但不得把适配措施正文、Skill 全文、Agent 完整提示词、Code 实现说明或 Web 设计稿搬入流程规范。

环境适配边界应回答：

1. 是否需要某类能力参与；
2. 能力参与的输入、输出、停止点和交还方式；
3. 不能由该能力承接的内容；
4. 当前能力缺口和降级方式；
5. 需要同步检查的 Code、Web、适配措施或环境适配项。

## 8. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 改变具体工作流程规范的标准骨架；
2. 允许具体工作流程规范省略标准组成且无说明；
3. 恢复固定能力子文档作为工作流程完整性要求；
4. 将工作流程测试用例分散到每个流程的测试子文档；
5. 改变 Context、Scenario、Gate、回写要求或行动特有可测试性锚点的表达方式。

工作流程文档检查至少包括：

| 检查项 | 标准 |
|---|---|
| 骨架 | 覆盖本文 §4 标准章节，缺项已说明 |
| 上位依据 | 上位依据指向 06，相关规范按内容引用 02、03、09、07、08；若后续存在 active 的工作流程测试规范或 40 登记的 active 流程测试入口，再按需引用 |
| Scenario | 场景识别条件明确，避免凭感觉进入流程 |
| Gate | 停止、确认、降级和 Human Gate 条件明确 |
| 可测试性锚点 | 行动特有可测试性锚点留在主文档；具体测试用例进入后续重新设计并正式生效的测试事实源，或进入 Code 测试实现/待补齐事项 |
| 固定子文档 | 未恢复 `NN.01` 至 `NN.06` 固定能力子文档 |
| 适配摘要 | 环境适配只保留边界和引用，不复制实现正文 |
