## 1. 本文定位

本文定义 Change 事实模型使用的 commit message 格式契约。本文解决 commit message 应包含哪些部分、各部分格式约束是什么、type 和 scope 枚举有哪些，以及工具实现应如何消费本契约的问题。

本文是 Change 事实模型契约字段的权威位置。本文是 `specs/22-Change-变更记录.md` 的附件型契约子文档，不是独立事实模型。本文不得重新定义 Change 的对象定位、准入条件、状态机、Human Gate、事实源回写或证据留存要求。发生冲突时，以 22 主文档和上位基础规范为准。

本文不承载执行逻辑、流程步骤或 Human Gate 条款（依据 `specs/04-LDVH模型子文档规范.md` §7.1）。

## 2. Commit Message 格式 Schema

### 2.1 格式结构

```text
<type>(<scope>): <subject>

<body>

Refs: <object-refs>
```

### 2.2 各部分说明

| 部分 | 必填 | 说明 |
|---|---|---|
| `type` | 是 | 变更类型，必须属于 type 枚举 |
| `scope` | 否 | 影响范围，推荐值见 scope 枚举 |
| `subject` | 是 | 简短描述，不超过 72 字符 |
| `body` | 否 | 详细说明变更原因和内容 |
| `Refs` | 否 | 关联对象，格式为 `Refs: <object-refs>`，多个对象用逗号分隔 |

### 2.3 格式正则

第一行格式正则：

```regex
^([a-z]+)(?:\(([^)]+)\))?:\s+(.+)$
```

Refs 行格式正则：

```regex
^Refs:\s*(.+)$
```

## 3. 字段约束

### 3.1 type 枚举

| type | 含义 |
|---|---|
| `feat` | 新增功能或对象 |
| `fix` | 修复缺陷 |
| `docs` | 文档修改 |
| `refactor` | 重构，不改变外部行为 |
| `test` | 测试相关 |
| `chore` | 构建、配置或辅助工具修改 |
| `spec` | specs 规范文档修改 |
| `rule` | Rules 文件修改 |
| `adr` | ADR 实例创建或状态变更 |
| `revert` | 回退之前的变更 |

### 3.2 scope 枚举（推荐值，非强制）

| scope | 含义 |
|---|---|
| `specs` | specs 规范文档 |
| `rules` | Rules 文件 |
| `adr` | ADR 实例 |
| `tools` | Tools 辅助程序 |
| `web` | Web Tools |

### 3.3 subject 约束

| 约束 | 值 |
|---|---|
| 最大长度 | 72 字符 |
| 不可为空 | 是 |

### 3.4 Refs 约束

| 约束 | 值 |
|---|---|
| 格式 | `Refs: <object-refs>` |
| 分隔符 | 逗号 |
| 不可为空 | Refs 行存在时，object-refs 不可为空 |

## 4. 契约消费声明

| 消费者 | 消费方式 | 消费内容 |
|---|---|---|
| `tools/check_22_commit_format.py` | 校验 | type 枚举、scope 推荐值、subject 长度、Refs 格式、中文字符检测 |
| L0 Rules | 提醒 | commit message 格式规范、中文强制要求 |
| AI | 遵守 | 在 commit 时按本契约生成中文 commit message |

### 4.1 中文字符检测规则

subject 和 body 中必须包含至少一个中文字符（Unicode 范围 `\u4e00-\u9fff`）。type 和 scope 不要求中文。

正则实现参考：

```python
HAS_CHINESE_RE = re.compile(r'[\u4e00-\u9fff]')
```

检查范围：subject 中 type 和 scope 之后的内容部分，以及 body 全文。缺少中文字符视为 error。

## 5. 检查项

检查 Change 契约是否合规时，应确认：

1. type 枚举是否与 `specs/22-Change-变更记录.md` §8.2 一致；
2. scope 枚举是否与 `specs/22-Change-变更记录.md` §8.3 一致；
3. subject 约束是否与 `specs/22-Change-变更记录.md` §8.1 一致；
4. `tools/check_22_commit_format.py` 是否依据本契约进行校验，未自行扩张契约；
5. 契约变更后，Tools 实现和测试是否已同步更新（依据 `specs/04-LDVH模型子文档规范.md` §7.4、§8）。
