## 1. 定位

本文承载 01 授权的知识地图关系类型表、类型级误用诊断提示和关系辅助核对表。

01 正文定义知识地图的治理原则、最小关系闭集、关系判定顺序、误升级边界、回指要求和事实源边界；本文只能维护这些已授权的关系类型表、类型级提示、状态、正反例和诊断辅助信息，不得单独改变关系原则、关系闭集、事实源边界或知识地图输出用途。

知识地图关系只用于定位、最小读取、影响判断、诊断回指和派生展示。关系边不得替代规范正文、附件授权、成员主文件、Code 校验原始结果或 Git 文件事实源。

## 3. 关系类型使用提示

关系判定顺序和误升级边界以 01 主文为准。本文只维护关系类型表中的类型级含义、来源结构、方向和误用诊断提示。

使用本文时应遵守：

1. 不得因为某关系类型在本文出现，就把未回指来源的关系边写成事实；
2. 不得把表格中的误用诊断提示解释为新的关系原则；
3. 不得把 `parse_status` 解释为通用 Code 诊断状态；
4. 新增关系类型前，必须先回到 01 主文确认不能由现有类型表达。

## 4. 关系解析状态表

`parse_status` 闭集用于描述关系条目的解析状态：

| 状态 | 含义 |
|---|---|
| `parsed` | 关系已解析，方向和目标可判断 |
| `partial` | 关系来源可解析，但目标、锚点或部分字段不完整 |
| `missing_target` | 目标路径、节点或锚点不存在 |
| `invalid_direction` | 关系方向与本文定义不一致 |
| `invalid_type` | 关系类型不在本文闭集中 |
| `misused_relation` | 存在关系升级、反向补全或来源误用 |

本文只定义关系条目内部使用的解析状态闭集，不定义 Code 输出 Schema、字段名、数据类型、诊断字段或命令入口。相关解析与诊断要求由 01 主文档和后续 Code 规范统一承接。

## 5. 关系辅助核对表

关系辅助核对至少包括：

| 检查项 | 标准 |
|---|---|
| 类型闭集 | 关系类型属于本文定义范围 |
| 状态闭集 | `parse_status` 属于本文定义范围 |
| 方向一致 | 关系方向符合本文表格 |
| 来源可回指 | 每条边能回指字段、章节、表格行、Code 输出或事实源路径 |
| 目标存在 | 目标节点、路径或锚点真实存在，或被诊断为缺失 |
| 未误升级 | 未把导航、来源、展示、影响或消费关系升级为上位依据、父子关系或事实源 |

本核对表用于发现关系方向错误、目标缺失、误升级和反向补全风险；核对结论不能替代 01 主文档规定的高影响确认。
