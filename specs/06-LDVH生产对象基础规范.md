## 三、生产对象的定义与定位

### 3.1 生产对象的定义

LDVH 生产对象是 LDVH 对工程生产事实的自定义建模，将项目中的意图、任务、决策、风险、依赖、证据、变更、产物、检查项和经验沉淀等内容，抽象为具有明确字段契约、状态流转和验收标准的结构化对象。

### 3.2 生产对象的核心特征

生产对象必须具备以下核心特征：

1. **规范由 LDVH 定义**：对象的准入条件、字段契约、状态流转、事实源边界和验收规则由 LDVH 规范体系定义；
2. **实例由项目拥有**：每个项目按规范创建的对象实例属于项目，存放在项目的结构化事实源目录中；
3. **服务工程生产**：对象用于让 AI、人和工具围绕同一组项目事实协作，支持任务拆解、状态追踪、证据回写、决策追溯和变更审计；
4. **Git 可追溯**：对象实例必须以 Git 可追踪文件的形式承载，优先使用 YAML 格式（适合结构化字段）或 Markdown 格式（适合说明性内容）；
5. **单一事实源**：每个对象实例只能有一个权威承载位置，其他位置只能引用或聚合，不得复制并维护独立事实。

### 3.3 生产对象与临时信息的区别

| 维度 | 临时信息 | 生产对象 |
|---|---|---|
| 性质 | 执行过程中的局部选择、临时判断、聊天内容 | 结构化、可追溯、可验证的工程事实 |
| 持续时间 | 一次性，仅在当前执行上下文中有效 | 长期，可跨会话、跨执行轮次追踪 |
| 复用价值 | 无，仅服务当前执行 | 有，可被其他对象引用、可被 AI 后续执行参考 |
| 追踪需求 | 不需要独立追踪 | 需要独立追踪、状态流转和验收标准 |
| 承载位置 | 聊天记忆、工具缓存、命令输出等临时位置 | Git 文件事实源（specs/、ldvh-base/、docs/ 等） |

## 四、生产对象准入与分类原则

### 4.1 对象分类原则

LDVH 生产对象可按治理用途分为以下几类：

1. **核心执行实体**：最小可执行、可追踪、可验证、可关闭的对象；
2. **意图和入口**：承载人的目标、范围、成功标准和约束，以及未任务化但有保留价值的输入；
3. **决策和风险**：已确认的决策记录、已识别的风险、前置条件或外部约束；
4. **支撑和记录**：执行摘要、验证结果、关闭证据、验收记录、可引用产物、检查项、变更记录和踩坑经验。

### 4.2 对象清单归属

具体生产对象清单、编号归属、维护状态和区段关系由 `specs/10-生产对象集合索引.md` 维护。本文只定义生产对象的通用分类和准入原则。

### 4.3 预留编号区段

编号区段 23-39 预留用于未来新增生产对象，不得未经 Human Gate 确认提前占用。

## 五、生产对象的通用规范

### 5.1 准入条件原则

一个内容需要满足以下条件之一，才应成为生产对象：

1. **需要独立追踪状态**：该内容有明确的状态流转，需要跨会话或跨执行轮次追踪；
2. **需要可验证的完成标准**：该内容有明确的验收条件，需要验证是否完成；
3. **需要关闭证据**：该内容完成后需要记录证据，供后续追溯或审计；
4. **需要关联其他对象**：该内容需要被其他对象引用，或引用其他对象；
5. **需要被工具展示、排序、过滤、聚合或审计**：该内容需要被工具处理，以降低人和 AI 的维护成本；
6. **不成为生产对象就会导致进度、责任、完成标准或验证结果不可追踪**：该内容如果不结构化，就会导致项目事实漂移或不可追溯。

不满足以上条件的内容，应按其性质分流：
- 可以在当前对话中直接回答或处理的信息 → 留在聊天记忆中，不写入事实源；
- 已有明确目标和完成标准，但不需要独立追踪 → 作为现有 Task 的子步骤，不单独创建对象；
- 属于长期规则或决策，但不需要独立状态机 → 写入 specs/ 或 .trae/rules/；
- 属于项目背景或参考资料 → 写入 docs/ 或 references/；
- 属于临时执行策略 → 留在当前执行上下文中。

### 5.2 事实源边界原则

生产对象的事实源边界遵循以下原则：

1. **Git 可追溯**：生产对象实例必须以 Git 可追踪文件的形式承载；
2. **单一事实源**：每个对象实例只能有一个权威承载位置，其他位置只能引用或聚合；
3. **介质选择原则**：
   - Markdown 更适合承载背景、原因、解释和设计语境；
   - YAML 更适合承载任务、状态、结构化关系和审计字段；
4. **目录归属原则**：
   - specs/10-39 承载生产对象规范，不承载具体对象实例；
   - ldvh-base/ 承载结构化生产对象实例；
   - docs/ 承载管辖项目资料和非结构化内容；
   - references/ 承载外部资料，不直接构成强制规则。

### 5.3 状态流转原则

生产对象的状态流转遵循以下原则：

1. **状态变更先于执行**：执行者在执行对象相关操作时，必须同步更新事实源中的对象状态；
2. **终态不可重开**：对象进入终态后，不得直接重开；如需重新处理，必须新建对象承接；
3. **状态流转可追溯**：状态变更必须留下可追溯的记录，包括变更时间、变更人和变更原因；
4. **Human Gate 触发原则**：关键状态流转必须触发 Human Gate，等待人类确认后方可继续。

### 5.4 字段契约原则

生产对象的字段契约遵循以下原则：

1. **基础字段对齐**：所有生产对象应包含基础字段（id、type、title、status、created、updated）；
2. **扩展字段明确**：具体对象的扩展字段由该对象的规范明确定义，包括字段名、类型、是否必填、约束条件；
3. **字段语义一致**：相同字段名在不同对象中的语义应保持一致；
4. **引用完整性**：引用其他对象的字段应确保引用的对象存在且有效。

### 5.5 验收标准原则

生产对象的验收标准遵循以下原则：

1. **可验证**：验收标准必须是可验证的，不能是模糊的主观判断；
2. **明确**：验收标准必须明确，不能有歧义；
3. **可追溯**：验收完成后必须记录验收证据，包括验收时间、验收人和验收结果。

## 六、与 10-39 具体对象规范的关系

### 6.1 10 生产对象集合索引

10 是生产对象集合索引，不定义对象字段、状态机或行动流程，只提供该区段内文档的清单、关系映射、状态和维护信息。

### 6.2 11-39 具体对象规范

11-39 是具体生产对象规范，每个规范定义一个生产对象的以下内容：
1. 对象定位与准入条件；
2. 事实源边界；
3. 状态机；
4. 字段契约；
5. 与其他对象的关系；
6. 初始化检查项；
7. 审计检查项；
8. AI 协作适配；
9. Human Gate；
10. 程序辅助适配；
11. 工具展示适配；
12. 待补齐事项。

### 6.3 关系原则

本文与 10-39 具体对象规范的关系遵循以下原则：
1. 本文定义生产对象的通用规则，10-39 定义具体对象的规则；
2. 具体对象规范不得与本文的通用规则矛盾；
3. 具体对象规范可以在本文的通用规则基础上，定义更具体的规则；
4. 发生冲突时，以本文的通用规则为准，除非具体对象规范明确说明例外情况并经 Human Gate 确认。

## 七、Human Gate 与检查要求

### 7.1 Human Gate 触发条件

以下情况应评估 Human Gate：
1. 新增生产对象；
2. 删除生产对象；
3. 重命名生产对象；
4. 重排生产对象编号区段；
5. 改变生产对象的通用规则；
6. 改变生产对象的事实源边界原则；
7. 将原本不属于生产对象的内容升级为生产对象；
8. 将原本属于生产对象的内容降级为非生产对象。

当 AI 识别到上述情况时，至少必须暂停当前变更动作，向人提醒该操作可能触发 Human Gate，并说明涉及的事实源、影响范围和建议确认事项。

### 7.2 检查要求

生产对象规范写作检查至少包括：
| 检查项 | 标准 |
|---|---|
| 上位依据 | 已声明上位依据 |
| 对象定位 | 头部定位、适用范围、上位依据和相关规范清晰 |
| 引用纪律 | 未复制其他权威文档的规则正文 |
| 架构术语一致性 | 与五类构成要素、生产对象和行动模型术语一致 |
| 事实源边界 | 符合 `specs/03-事实源边界与承载规范.md` 的事实源边界原则 |
| 目录归属 | 符合 `specs/02-LDVH文件夹说明.md` 的目录规划 |
