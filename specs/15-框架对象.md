# 框架对象

## 一、概述

### 1.1 什么是框架对象

框架对象是 PM Kit 框架提供的基础设施，不属于核心管理对象（14 号文档管理）。它们为 AI、人和工具提供执行能力、约束规则和支撑服务。

### 1.2 框架对象与核心管理对象的区别

| 维度 | 核心管理对象（14 号文档） | 框架对象（本文档） |
|---|---|---|
| 定义 | 项目需要主动创建和维护 | 框架提供，项目按需使用 |
| 定位 | 承载业务事实 | 提供基础设施和服务 |
| 状态 | 有状态机 | 无独立状态机或相对稳定 |
| 引用 | 被其他管理对象引用 | 不被管理对象直接引用 |
| 管理 | 需要完整生命周期管理 | 由框架控制 |
| 示例 | Task、ADR、Risk | Rules、Skill、Profile |

### 1.3 框架对象列表

| 对象 | 一句话定位 |
|---|---|
| Rules | AI、人和工具必须遵守的行为边界 |
| Skill | AI 可使用的技能和工具 |
| Agent | AI 代理执行能力 |
| Profile | 项目配置档案 |
| Context | AI 执行上下文 |
| Scenario | 场景识别 |
| Gate | 确认门禁 |

---

## 二、Rules（规则）

### 2.1 定义

Rules 是 AI、人和工具必须遵守的行为边界。它定义了项目规范、约束条件和执行标准。

### 2.2 定位

- **不是业务实体**：不承载项目业务事实
- **是约束机制**：为所有对象提供行为边界
- **可被引用**：ADR 可以升级为 Rules

### 2.3 Rules 类型

| 类型 | 说明 | 示例 |
|---|---|---|
| 行为规则 | 约束 AI 和人的行为 | 人机协作规范 |
| 格式规则 | 约束文档和代码格式 | 命名规范 |
| 流程规则 | 约束操作流程 | Human Gate 触发条件 |
| 质量规则 | 约束质量标准 | 验收标准 |

### 2.4 存放位置

```
{target_project}/
├── .trae/
│   └── rules/
│       ├── project_rules.md    # 项目级规则
│       ├── product_rules.md    # 产品级规则
│       └── ...
```

### 2.5 与核心管理对象的关系

- ADR 可升级为 Rules（`adr → rules`）
- Rules 约束所有核心管理对象的行为

---

## 三、Skill（技能）

### 3.1 定义

Skill 是 AI 可使用的技能和工具，扩展 AI 的执行能力。

### 3.2 定位

- **不是业务实体**：不承载业务事实
- **是执行工具**：提供特定能力
- **可组合**：多个 Skill 可组合使用

### 3.3 Skill 类型

| 类型 | 说明 | 示例 |
|---|---|---|
| 分析技能 | 分析和推理能力 | 代码分析 |
| 生成技能 | 内容生成能力 | 文档生成 |
| 执行技能 | 操作执行能力 | 文件操作 |
| 集成技能 | 外部系统集成 | API 调用 |

### 3.4 与核心管理对象的关系

- Skill 可用于处理核心管理对象
- Skill 不是核心管理对象的事实源

---

## 四、Agent（代理）

### 4.1 定义

Agent 是 AI 代理执行能力，可以自主或半自主地完成任务。

### 4.2 定位

- **不是业务实体**：不承载业务事实
- **是执行能力**：提供任务执行能力
- **可编排**：多个 Agent 可协同工作

### 4.3 Agent 类型

| 类型 | 说明 | 示例 |
|---|---|---|
| 任务代理 | 执行特定任务 | 任务执行代理 |
| 审查代理 | 执行审查任务 | 代码审查代理 |
| 协调代理 | 协调多个代理 | 任务协调代理 |

### 4.4 与核心管理对象的关系

- Agent 可操作核心管理对象
- Agent 不是核心管理对象的事实源

---

## 五、Profile（档案）

### 5.1 定义

Profile 是产品、项目、项目集和接入关系的身份与配置档案。

### 5.2 定位

- **是配置信息**：定义项目基本属性
- **是基础设施**：为所有对象提供项目归属
- **不被直接引用**：其他对象通过路径间接关联

### 5.3 Profile 类型

| 类型 | 说明 |
|---|---|
| Product Profile | 产品级配置 |
| Project Profile | 项目级配置 |
| Portfolio Profile | 项目集级配置 |

### 5.4 存放位置

```
{target_project}/
├── .pmkit/
│   └── profile.yaml
```

### 5.5 与核心管理对象的关系

- Profile 为所有核心管理对象提供项目归属
- 核心管理对象通过路径归属到项目

---

## 六、Context（上下文）

### 6.1 定义

Context 是由事实源组织出的 AI 执行输入、任务背景和行动依据。

### 6.2 定位

- **不是业务实体**：不独立承载事实
- **是组织机制**：动态组织事实源
- **动态生成**：根据场景动态生成

### 6.3 Context 内容

| 内容 | 说明 |
|---|---|
| 项目背景 | 项目基本信息和目标 |
| 任务背景 | 当前任务的相关信息 |
| 行动依据 | 可用的 Rules、ADR 等 |

### 6.4 与核心管理对象的关系

- Context 引用核心管理对象
- Context 不被核心管理对象引用

---

## 七、Scenario（场景）

### 7.1 定义

Scenario 是 AI 当前所处的任务类型、协作模式和执行入口。

### 7.2 定位

- **不是业务实体**：不承载业务事实
- **是识别机制**：识别当前执行场景
- **动态切换**：根据任务类型切换

### 7.3 Scenario 类型

| 类型 | 说明 |
|---|---|
| 开发场景 | 开发相关任务 |
| 审查场景 | 审查相关任务 |
| 规划场景 | 规划相关任务 |
| 运维场景 | 运维相关任务 |

### 7.4 与核心管理对象的关系

- Scenario 为核心管理对象提供执行入口
- Scenario 不被核心管理对象引用

---

## 八、Gate（门禁）

### 8.1 定义

Gate 是需要人确认或满足条件后才允许继续的控制点。

### 8.2 定位

- **不是业务实体**：不承载业务事实
- **是控制机制**：保障关键节点可控
- **可嵌入**：可嵌入核心管理对象

### 8.3 Gate 类型

| 类型 | 说明 |
|---|---|
| 确认门禁 | 需要人确认后继续 |
| 条件门禁 | 满足条件后继续 |
| 审批门禁 | 需要审批后继续 |

### 8.4 与核心管理对象的关系

- Task 可包含 Gate
- Gate 不是核心管理对象的事实源

---

## 九、框架对象之间的关系

```text
Profile
    ↓（提供配置）
Rules / Skill / Agent / Context / Scenario / Gate
    ↓（支撑）
核心管理对象（Task、ADR、Risk 等）
```

## 十、初始化和审计

### 10.1 初始化检查项

| 检查项 | 标准 |
|---|---|
| 配置完整性 | 所有必需字段已配置 |
| 路径正确性 | 存放在正确路径 |
| 规则一致性 | 规则定义与框架规范一致 |
| 能力可用性 | Skill 和 Agent 可正常使用 |

### 10.2 审计检查项

| 检查项 | 标准 |
|---|---|
| 配置有效性 | 配置信息有效 |
| 规则合规性 | 规则符合规范 |
| 引用完整性 | 引用的对象存在 |
| 变更可追溯 | 变更已记录 |
