## 1. 价值判断

本文存在的价值，是把重复出现的 AI 行动沉淀成可复用结构，让 AI 在相似任务中能少猜步骤、少漏验证、少丢证据，并知道何时暂停、分流或交还 Human。

行动模板服务 00 的行动模板构成要素和 01 的行动指南承接。行动模板不是规则源，也不是授权器；它组织来源规则、当前上下文、执行步骤、验证和回写。

## 2. 权威依据

本文承接 `specs/00-理念与构成.md` 的行动模板定位、`specs/01-保障与衔接.md` 的行动指南和消费时机规则、`specs/02-AI行为规范.md` 的主控责任、`specs/03-事实源与Git溯源规范.md` 的证据回写边界，以及 `specs/04-Specs基础规范.md` 的结构规则。

若行动模板与来源规范冲突，以来源规范和上位规范为准。若行动模板需要授权、风险接受或验收，必须进入 Human Gate。

## 3. 归口边界

本文归口定义行动模板的基础结构、能力输出交还、问题分流、验证和回写边界。

本文不归口定义事实对象字段、Code 输出 schema、Web 页面、runtime payload、Hook 安装、commit message 契约或测试治理。这些内容分别由 05、07、08、01/07、03 和 09 承接。

## 4. 适用范围

本文适用于：

1. AI 反复执行、需要稳定步骤和验证入口的任务；
2. Action Guide 生成后需要进一步组织 Context、Scenario、Gate 和执行顺序的任务；
3. Git 提交行动、Rules 同步审查、环境适配、研究输出、工作对象承接等 V2 行动成员迁移候选；
4. Skill 工作流能力转写为行动模板步骤或外部包装候选的判断。

## 5. 行动模板结构

行动模板应至少表达以下结构：

| 结构 | 职责 |
|---|---|
| Context | 当前行动前最小必要事实源、对象、证据和约束。 |
| Scenario | 何时适用该模板，AI 如何识别进入信号。 |
| Gate | 必须暂停、分流、验证或进入 Human Gate 的条件。 |
| 执行 | 可复用的步骤顺序、能力调用和失败处理。 |
| 验证 | 完成声明前需要的测试、命令、回读、Human 确认或等价验证。 |
| 回写 | 哪些结论、证据、风险或缺口需要回到事实源。 |
| 交还 | 向 Human 或下一轮 AI 交还的状态、证据和残留风险。 |

行动模板应引用来源规则，不复制来源规则。模板不能用自身步骤重定义 specs、事实对象、Code、Web、测试或事实源规则。

## 6. 能力输出与主控责任

行动模板可以组织 Code、Web、测试、Hook、子 Agent、外部工具或环境包装的输出，但这些输出都必须交还主控 AI 判断。

| 输出来源 | 可提供 | 不得替代 |
|---|---|---|
| Code | 解析、诊断、read_plan、preflight、runtime receipt | 事实源、Human Gate、完成结论 |
| 子 Agent | 旁路审查、专题分析、候选建议 | 主控责任、最终判断 |
| 测试 | 验证证据、失败信号、回归样例 | 规则正文、Human 验收 |
| Web | Human-facing 状态、风险、证据展示 | 事实源和行动判断 |
| Skill 或外部包装 | 可复用步骤和环境入口 | V3 顶层机制和规则权威 |

能力输出不可回指来源规则、事实源或验证范围时，只能作为过程输出，不得作为完成证明。

## 7. 模板候选与迁移边界

V2 `03-行动编排规范.md`、30-36 行动成员和 Skill 文件中的能力可以作为行动模板来源，但不得整体复制。

当前迁移判断：

1. `31-git-commit-action` 的状态读取、diff 判断、验证证据、提交后交还，可转为 Git 提交行动模板候选；
2. `30-rules-entry-sync-review` 的入口影响评估，可转为 Rules 同步审查模板候选；
3. `32-environment-entry-adaptation` 的薄引用和部署检查，只能作为环境适配候选，涉及安装或覆盖入口时必须 Human Gate；
4. `skills/ldvh-git-commit/SKILL.md` 只能转为行动模板步骤或外部环境包装候选，不作为 V3 顶层规则源；
5. WorkCase 创建、执行推进、结果复核和关闭确认可转为最小手动行动模板；它只组织现有 WorkCase 事实对象状态、Human Gate、验证和回写，不启用 Web 写入、Hook、runtime 自动触发或完整字段表；
6. V2 30-59 成员全文、状态枚举和资产清单暂留 `_migration`。

模板候选只有在有正式规则来源、验证方式、回写边界和测试闭环后，才能成为正式行动模板。

除 Git 提交和 WorkCase 最小手动行动模板外，后置候选不阻断 V3 主线切换。它们不得被写成已启用能力、默认流程、Hook 拦截结果或 Human Gate 完成；在正式迁入前，只能作为 Action Guide 提示、迁移记录、当前对话中的手动等价步骤或后续工作项来源。

Git 提交行动模板示范是本文首个可消费模板示范。它只组织一次提交行动如何按既有规则执行，不定义 commit message 字段、type、scope、body 条件、验证声明字段、Hook 安装或提交门禁。

| 结构 | 最小要求 |
|---|---|
| Context | 读取用户提交目标、当前 Git 仓库、`git status --short --untracked-files=all`、staged/unstaged/untracked 状态、必要 diff、source_refs，并回指 `specs/03-事实源与Git溯源规范.md`、`specs/attachments/03.Att.01-Commit-Message契约字段表.md`、`specs/09-测试与验证规范.md`、`specs/attachments/09.Att.01-验证声明字段表.md` 和 `specs/07-Code确定性执行规范.md`。 |
| Scenario | 用户明确要求提交、修复提交消息、拆分 staged changes、提交前预检或事实源修改追溯时适用；用户只是询问提交规则时，只回答 03/09 边界，不创建提交。 |
| Gate | staged changes 与用户目标不一致、提交拆分边界不清、需要 destructive Git 操作、需要绕过 commit validator 或失败测试、存在 Human Gate 风险、需要安装 Hook/commit gate/环境入口时暂停。 |
| 执行 | 检查 status 和 diff，只 stage 本次范围内文件；判断是否拆分；按 `03.Att.01` 选择单一 type 和零个或一个 scope；写含 `关键变更` 的 body；运行 commit validator 或等价 hook 检查；通过后才创建 commit；不安装 Hook、commit gate 或 CI。 |
| 验证 | 运行与变更面匹配的测试或命令；验证声明使用 `09.Att.01` 的验证目标、验证入口、输入范围、关键输出、结论、残留风险和证据回指；失败、未运行或不可复现时不得声明完整验证。 |
| 回写 | 提交流程输出默认是过程输出；需要长期追溯的验证结论、风险、缺口或经验按 03/05/09 分流到对应事实源、事实对象或迁移材料；Git commit records 只溯源文件修改，不替代事实对象或验证声明。 |
| 交还 | 提交后交还 commit hash、提交 message 摘要、验证摘要、残留风险、剩余 `git status --short`、source_refs 和执行方式；未提交时交还阻断原因、未验证范围和后续分流。 |

Action Guide / 行动指南承接 V2 知识地图的任务导航能力。Git 提交行动模板可以消费 Action Guide 的 read_plan、stop_conditions、validation_guard 和 source_refs，但 Action Guide 不替代主控 AI 判断、事实源、Human Gate、验证声明或行动模板执行结果。

`skills/ldvh-git-commit/SKILL.md` 只能作为 V2 来源和外部包装候选。若后续环境真实提供该 Skill，行动模板仍必须区分 `skill_runtime_invoked`、`manual_equivalent_execution` 和 `skill_unavailable`，不得恢复 Skill 顶层机制或用 Skill 输出替代主控 AI 判断。

### WorkCase 最小行动模板

WorkCase 最小行动模板只支持 `manual_equivalent_execution`：由主控 AI 按 21 的状态闭集、Human Gate、验证和回写边界手动推进。它不启用 Web 写入，不安装 Hook，不声明 runtime 自动触发，不创建完整 Confirm UI，也不得替代 Human Gate。

| 结构 | 最小要求 |
|---|---|
| Context | 读取用户目标、WorkCase ID 或拟创建路径、当前状态、对象化价值、成功标准、验证证据、关闭证据、source_refs，并回指 `specs/05-事实模型基础规范.md`、`specs/06-行动模板基础规范.md`、`specs/21-WorkCase-工作项.md`、`specs/09-测试与验证规范.md` 和 `specs/03-事实源与Git溯源规范.md`。 |
| Scenario | 创建 WorkCase、执行推进、结果复核或关闭确认时适用；用户只是询问 WorkCase 规则时，只回答 21/06/09 边界，不创建或改写实例。 |
| Gate | 创建 WorkCase、从 `human_plan_confirming` 进入执行、从 `human_closure_confirming` 关闭、缺少验证证据、缺少后续分流 / 收口结果、需要 Web 写入、需要安装 Hook 或需要声明 runtime 自动触发时，必须暂停或进入 Human Gate。 |
| 执行 | 新建实例时写入 `subagents_plan_reviewing` 并保留对象化价值；方案确认后才能进入 `executing`；执行完成后进入 `result_self_checking`；独立复核进入 `subagents_result_reviewing`；提交 Human 关闭判断进入 `human_closure_confirming`；Human 确认后才能进入 `closed`。 |
| 验证 | 使用 `09.Att.01` 的验证声明字段说明验证目标、验证入口、关键输出、结论、残留风险和证据回指；检查状态闭集、成功标准、验证证据和 `后续分流 / 收口结果`；未验证时不得声明可关闭或已关闭。 |
| 回写 | 只写回 `ldvh-base/workcases/` 下的 WorkCase 实例字段；长期证据进入 `verification_evidence`、`closure_evidence`、`human_closure_confirmation`、`residual_risks`、`followup_refs` 或相关事实对象；Git commit records 只溯源文件修改，不替代 WorkCase 事实。 |
| 交还 | 交还 WorkCase ID、当前状态、变更摘要、验证摘要、残留风险、下一步 Human Gate、source_refs 和未完成分流；阻断时交还阻断原因、缺少证据和建议的下一步。 |

## 8. 保障措施

| 保障要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 来源回指要求 | 行动模板必须回指来源 specs、事实对象或 Human 决策 | 本文、03 source_refs、07 Code | 模板治理 | 新建或迁移模板时 |
| Gate 显式要求 | 模板必须写出暂停、分流和 Human Gate 条件 | 本文、01、02 | 门禁治理 | 模板涉及写入、提交、验收或风险接受时 |
| 验证要求 | 模板必须说明完成声明前的验证入口或不可验证说明 | 本文、09 | 验证治理 | 模板声明完成、提交或关闭时 |
| 能力输出边界 | Code、Skill、Agent、Web、Hook 输出必须交还主控 | 本文、02 | 主控治理 | 模板使用外部能力时 |

## 9. 验证方法

验证本文规则时应检查：

| 检查类别 | 检查内容 | 不满足时 |
|---|---|---|
| 结构检查 | 模板是否具备 Context、Scenario、Gate、执行、验证、回写和交还 | 保持为候选，不进入正式模板 |
| 来源检查 | 模板是否回指来源规则，不复制来源规则 | 回到来源规范或模板重写 |
| 能力边界检查 | 外部输出是否只作为过程输出并交还主控 | 停止完成声明或转为 diagnostic |
| 验证检查 | 完成声明是否有测试、命令、回读、Human 确认或等价验证 | 按 09 写为未验证或阻断 |

## 10. Human Gate

以下情况必须进入 Human Gate：

1. 将候选行动模板提升为正式可执行模板；
2. 改变模板 Gate、风险接受、提交拆分、事实源回写或完成判断；
3. 安装、覆盖或扩大外部环境入口、Hook、Rules、Skill 包装能力；
4. 允许能力输出跳过主控 AI、事实源边界或验证声明；
5. 接受模板长期缺少验证、回写或失败分流的风险。

## 11. Stop Conditions

出现以下情况时，AI 必须暂停：

1. 模板无法说明来源规则或减少的 AI 负担；
2. 模板复制来源 specs 长文形成第二事实源；
3. Skill、Hook、Rules 或 Agent 被写成 V3 顶层机制；
4. Gate 或 Human Gate 被模板步骤绕过；
5. 无验证证据却声明模板执行完成。

## 12. 待补齐事项

1. Git 提交行动模板和 WorkCase 最小手动行动模板已作为正文示范；后续只在真实入口、验证和回写闭环明确时，才继续迁入其它正式行动模板；
2. 后续从 V2 30-36 和 WorkCase 流程中逐项筛选正式行动模板候选；
3. 后续 Code 应让 Action Guide 与行动模板候选建立可解析回指；
4. 后续 tests 应覆盖模板缺少来源、缺少 Gate、能力输出替代事实源和未验证完成的负例；
5. WorkCase 自动创建、Web 写入、完整 Confirm UI、外部环境触发、字段表细化和批量状态迁移仍后置；启用前必须重新进入 Human Gate、测试和环境适配边界判断。
