# 非LDVH来源内容治理规范

> 创建日期：2026-06-08
> 定位：定义平台提供、第三方提供、用户既有、项目既有和自动生成等非 LDVH 来源内容进入 LDVH 管辖时的识别、准入、隔离、接管、验证、回写和废弃规则
> 适用范围：LDVH 自身项目和管辖项目中所有非 LDVH 来源内容、能力、资产、产物和候选输入
> 上位依据：`docs/specs/00-LD-Vibe-Harness理念与纲要.md`

## 1. 本文解决的问题

本文解决非 LDVH 来源内容如何进入 LDVH 管辖的问题。

非 LDVH 来源内容包括平台提供能力、第三方内容、用户既有内容、项目已有资产、自动生成内容和外部调研材料。这些内容可以提高效率、补充上下文或提供候选产物，但它们默认不了解 LDVH 的事实源边界、工作模型、工作流程、Code 验证、Web 边界、Human Gate 和运行闭环要求。

本文定义共同治理规则：

1. 如何识别非 LDVH 来源内容；
2. 如何判断其用途、风险和信任等级；
3. 何时可以读取、参考、调用、执行或写入；
4. 如何由 LDVH 主控接管其输出；
5. 如何验证、记录、回写或废弃；
6. 如何避免非 LDVH 来源内容绕过 LDVH 规范、事实源、状态机、Human Gate 或验证纪律。

本文不定义具体平台能力的官方行为，不复制第三方教程，不替代 Code、Web、事实源、工作模型或工作流程规范。

---
## 2. 与 00 总纲的关系

00 定义 LDVH 以 Git 可追踪事实源、工作模型、工作流程、Code、Web 和 Human Gate 形成可读取、可判断、可执行、可验证、可回写、可演进的 AI 工程闭环。

非 LDVH 来源内容可以成为 LDVH 的输入、候选材料、能力供给或待接管产物，但不能直接成为 LDVH 的规则、事实源、状态、结论或交付结果。

本文承接 00 的原则，确立以下核心规则：

```text
非 LDVH 来源内容可以被读取、参考、调用、转换，但不能直接生效；必须经过 LDVH 主控接管、验证，并按归属回写。
```

## 3. 术语应用关系

本文使用的非 LDVH 来源内容、已接管、未接管、主控接管和信任等级等术语，以 `docs/specs/02-术语规范.md` §10 为准。本文只说明这些术语在非 LDVH 来源内容治理场景中的应用关系，不并行维护术语权威定义。

### 3.1 识别口径

判断非 LDVH 来源内容时，重点不是“内容来自哪里”，而是“它是否已经被 LDVH 规范、事实源和验证纪律接管”。

### 3.2 来源分类

非 LDVH 来源内容至少包括以下类型：

| 类型 | 示例 | 典型风险 |
|---|---|---|
| 平台提供能力 | 平台内置 Skill、Agent、Hook、MCP、插件、搜索、浏览器、自动化工具 | 平台能力被误认为 LDVH 授权 |
| 第三方内容 | 外部文档、开源项目、教程、社区经验、第三方模板、第三方生成器 | 外部结论未经吸收直接生效 |
| 用户既有内容 | 用户已有提示词、规则、脚本、工具、文档、项目习惯、私有知识 | 用户习惯与 LDVH 事实源或流程冲突 |
| 项目已有资产 | 代码、README、配置、测试、CI、设计稿、历史文档、业务约束 | 既有资产被误认为已经符合 LDVH |
| 自动生成内容 | 脚手架、候选代码、候选配置、候选文档、模型输出 | 生成结果未经验证直接进入交付 |
| 外部调研材料 | 资料摘录、竞品分析、第三方 API 说明、调研报告 | refs 或 evals 结论绕过吸收 |

### 3.3 已接管与未接管

非 LDVH 来源内容只有在满足以下条件后，才可被视为已接管：

1. 来源、用途和影响范围已记录；
2. 是否影响事实源、规范、代码、状态、工作流程、Web 或 Human Gate 已判断；
3. 输出已由 LDVH 主控重新审查、筛选和归属；
4. 必要验证已完成，或验证缺口已记录；
5. 稳定事实已写入对应 Git 可追踪事实源；
6. 高影响事项已通过 Human Gate 或明确暂停。

未满足上述条件时，该内容只能作为候选输入、参考材料、临时能力或待验证产物。

## 4. 治理原则

### 4.1 可用不等于生效

AI 可以读取、参考或调用非 LDVH 来源内容，但不得因为其可用、方便、看似正确或由平台提供，就把它直接作为 LDVH 规则、事实、状态、证据或验收结果。

### 4.2 来源必须可追踪

使用非 LDVH 来源内容时，应尽量记录来源、访问位置、调用方式、产出位置、影响范围和验证方式。

如果来源不可追踪、实现不可审计、行为不可解释或结果不可复现，应降低信任等级，并限制其只能作为候选输入。

### 4.3 主控接管

非 LDVH 来源内容的输出必须回到 LDVH 主控。主控负责判断是否采纳、如何验证、是否触发 Human Gate、写入何处、是否需要记录任务、决策、变更、风险或经验。

平台能力、第三方 Skill、外部工具、脚本、Web 页面或自动化流程不得替代主控进行跨流程调度、最终验收、事实源归属判断或 Human Gate 决策。

### 4.4 默认隔离

非 LDVH 来源内容默认先隔离为候选材料或临时能力，不得直接进入核心事实源、状态机、规范正文、工作流程、受控写入链路或发布链路。

隔离方式可以包括：

1. 放入 refs、evals、临时草稿或候选目录；
2. 只读调用，不授予写入权限；
3. 限制输入上下文和输出目录；
4. 先生成候选产物，再由 LDVH 主控审查；
5. 在 Task、ADR、Memo、Change 或后续记录中保留接管结论。

### 4.5 风险升级

只要非 LDVH 来源内容会写文件、改规范、改状态、装依赖、执行代码、访问网络、影响事实源、改变工作流程、改变用户项目结构或成为持续开发基础，就应升级风险等级。

风险升级后，AI 应检查 Human Gate、验证方式、可回滚路径和事实源回写位置。

## 5. 信任等级

非 LDVH 来源内容按信任等级使用。

| 等级 | 名称 | 含义 | 允许行为 |
|---|---|---|---|
| T0 | 未识别 | 来源、用途或影响范围不清楚 | 不得采纳；先识别来源和用途 |
| T1 | 可参考 | 可作为阅读、理解或候选判断输入 | 可引用为参考，但不得生效 |
| T2 | 可调用 | 可在受限输入、受限输出下调用 | 可生成候选材料或辅助分析 |
| T3 | 可接管 | 输出可被 LDVH 主控审查、验证和归属 | 可进入接管流程 |
| T4 | 可纳入事实源 | 已验证、已归属、已通过必要 Human Gate | 可写入对应权威事实源 |
| T5 | 可稳定复用 | 多次接管有效，边界和验证方式稳定 | 可沉淀为 LDVH 自建 Code、包装 Skill、规范规则或最佳实践 |

信任等级只能由接管、验证和回写证据提升，不能由平台知名度、用户偏好、模型自信或一次成功结果直接提升。

## 6. 准入与禁止

### 6.1 允许场景

非 LDVH 来源内容可用于以下场景：

1. 提供外部资料、候选解释、候选方案或候选文案；
2. 生成脚手架、样例代码、候选配置或初始页面；
3. 辅助理解平台、第三方库、API、工具或用户既有资产；
4. 提供临时分析、格式转换、结构化建议或审查视角；
5. 在受控范围内执行局部工具能力；
6. 为后续 LDVH 自建 Code、包装 Skill、Web 能力或最佳实践提供 Dogfood 素材。

### 6.2 禁止直接生效场景

非 LDVH 来源内容不得直接执行以下行为：

1. 直接定义或修改 LDVH 正式规范规则；
2. 直接创建、修改、删除或迁移工作对象事实实例；
3. 直接修改对象状态、状态机、字段契约或 Human Gate 条件；
4. 直接替代 ADR、Task、Change、Pitfall、Memo 或 Profile 的事实记录；
5. 直接把缓存、数据库、平台状态或 Web 状态变成最终事实源；
6. 直接执行提交、推送、发布、删除、安装、远程控制或权限授权；
7. 直接绕过 Code 校验、工作流程、事实源边界或 Human Gate；
8. 直接成为持续开发基础而没有接管记录和验证证据。

如确需利用非 LDVH 来源内容处理上述领域，只能让其生成候选材料，并由 LDVH 主控按对应规范完成接管。

## 7. 标准接管流程

### 7.1 识别来源

AI 使用非 LDVH 来源内容前，应先判断来源类型：

1. 平台提供；
2. 第三方提供；
3. 用户既有；
4. 项目既有；
5. 自动生成；
6. 外部调研；
7. 混合来源。

来源不清楚时，应停留在 T0，不得继续采纳或执行高影响动作。

### 7.2 判断用途

AI 应说明该内容准备用于什么目的：

1. 信息参考；
2. 候选产物生成；
3. 工具调用；
4. 代码、配置或依赖变更；
5. 事实源写入；
6. 工作流程辅助；
7. Web 或 Human 入口辅助；
8. 最佳实践沉淀。

用途越接近写入、执行、发布、状态流转或事实源归属，接管要求越高。

### 7.3 限制权限

调用或使用非 LDVH 来源内容时，应限制：

1. 输入上下文；
2. 输出目录；
3. 写入权限；
4. 网络访问；
5. 依赖安装；
6. 可执行命令；
7. 可修改文件范围；
8. 可见敏感信息。

如果无法限制范围，应触发 Human Gate 或降级为只读参考。

### 7.4 主控接管

非 LDVH 来源内容产出后，LDVH 主控应完成：

1. 明确产出内容、产出位置和变更范围；
2. 判断是否影响规范、事实源、Code、Web、状态机、工作流程或 Human Gate；
3. 检查是否存在绕过 LDVH 治理的逻辑；
4. 运行可用的验证；
5. 记录未验证项和残留风险；
6. 按归属写回或丢弃。

### 7.5 验证与回写

接管后的稳定结论必须经过验证或记录验证缺口。

验证可以包括：

1. 文档结构和引用检查；
2. 字段、状态、事实源或对象检查；
3. lint、typecheck、test、build、格式化或运行验证；
4. 安全、依赖、权限或供应链检查；
5. Web 页面、交互、同步或受控写入验证；
6. Human Gate 确认；
7. 独立、并行或专项子 Agent 审阅。

验证通过后，稳定事实应按归属进入正式规范、docs、refs、evals、工作对象、Code、Web 文档、测试或最佳实践。验证不通过时，应进入修正、降级、废弃或后续任务。

## 8. 归属分流

非 LDVH 来源内容接管后，应按内容性质分流。

| 内容性质 | 归属 |
|---|---|
| 稳定规范规则 | 正式规范正文 |
| 外部资料引用 | refs |
| 内部分析、方案比较或迁移评估 | evals |
| 用户项目正文资料 | docs 正文区 |
| 工作事实、任务、决策、变更、经验 | 对应工作对象 |
| 可执行工具、脚本、校验器、测试程序 | Code 实现 |
| Web 页面、交互、同步、Human 入口 | Web 实现或 Web 文档 |
| 可复用流程入口 | LDVH 自建 Skill 或包装 Skill |
| 多次验证有效的使用方式 | 最佳实践 |
| 不可验证或不再适配的内容 | 废弃、降级或保留为参考 |

分流时不得为了方便把稳定规则放进最佳实践，也不得把候选材料写成事实源。

## 9. 安全与供应链边界

以下内容应按高风险处理：

1. 外部脚本、插件、依赖、二进制文件、生成器或自动化配置；
2. 需要安装依赖、访问网络、调用远程服务或读取敏感路径的能力；
3. 会修改文件、删除文件、提交、推送、发布或迁移项目结构的能力；
4. 难以审计实现、版本不可锁定、行为不可复现或带有自动更新能力的内容；
5. 可能输出密钥、令牌、隐私数据或本地敏感路径的内容；
6. 可能替代 Human Gate、事实源、状态机或验证流程的内容。

高风险内容必须至少说明来源、版本或入口、权限范围、验证方式、回滚方式和是否需要 Human Gate。

## 10. 与 11.01 和最佳实践的关系

`docs/specs/11.01-第三方Skill接管落地选项.md` 是本文的专题子文档，负责定义第三方 Skill 作为默认可用接管路径时的启用、取消、降级和重新启用规则。

最佳实践可以记录非 LDVH 来源内容的稳定使用经验，但不得新增强制规则。

适合进入最佳实践的内容包括：

1. 第三方 Skill 接管成功或失败后的经验；
2. 平台能力的稳定接管经验；
3. 用户既有脚本逐步纳入 LDVH 的经验；
4. 既有项目迁入 LDVH 的案例；
5. 脚手架生成、治理接管、验证和废弃的经验；
6. 常见风险案例和推荐处置方式。

如果最佳实践中反复出现同一硬边界，应回到本文、11.01 或对应正式规范吸收，不得长期留在最佳实践中作为隐性规则。

## 11. 规范落地要求

本文通过以下规范落地要求说明相关要求的同步、检查或审计触发条件。

| 落地要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 上位约束承接要求 | 非 LDVH 来源内容不得直接替代 LDVH 规范、事实源、状态、验证或 Human Gate | 本文接管流程、事实源检查、Human Gate、相关规范引用 | 文档治理 | 新增、调用、接管或废弃非 LDVH 来源内容时 |
| 入口可见要求 | AI 使用平台能力、第三方内容、用户既有内容或项目已有资产前，应能定位本文作为共同治理入口 | 规范入口摘要、后续环境适配映射、人工检查 | AI 执行入口提示 | 处理非 LDVH 来源内容、第三方 Skill、外部工具或既有项目资产时 |
| 流程复用要求 | 非 LDVH 来源内容接管应形成可复用的识别、用途判断、权限限制、验证和回写步骤 | 工作流程、接管检查清单、后续 Code 或测试支持 | 流程复用 | 多次出现相同接管场景或接管失败时 |
| 确定性执行要求 | 可机械检查的来源记录、引用边界、文件变更、依赖和验证结果应由 Code 或等价验证支持 | Code 检查、测试、正反样例、人工降级检查 | 校验实现 | 外部内容影响 Code、依赖、文件结构、事实源或运行投影时 |
| Human 交互要求 | 高风险接入、写入、执行、发布、权限授权或事实源变化应评估 Human Gate | Human Gate、影响范围说明、验证证据 | 人工确认 | 接入行为影响规范、事实源、状态、代码执行、依赖或用户项目结构时 |

## 12. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 非 LDVH 来源内容将改变正式规范、事实源边界、工作模型、工作流程、Code、Web 或状态机；
2. 非 LDVH 来源内容将写入、覆盖、删除、迁移或发布 Git 文件事实源；
3. 非 LDVH 来源内容需要安装依赖、访问网络、读取敏感信息或获得高权限；
4. 非 LDVH 来源内容将成为持续开发基础、长期工具入口、包装 Skill 或运行投影；
5. 来源、用途、影响范围或验证方式无法判断；
6. 外部内容与 LDVH 规范或用户明确要求冲突；
7. AI 准备把最佳实践、外部资料、平台输出或用户习惯升级为强制规则。

非 LDVH 来源内容检查至少包括：

| 检查项 | 标准 |
|---|---|
| 来源识别 | 已识别来源类型、入口和可追踪信息 |
| 用途判断 | 已说明是参考、候选、调用、执行、写入还是实践沉淀 |
| 信任等级 | 已按 T0-T5 判断当前可用等级 |
| 权限限制 | 已限制输入、输出、写入、网络、依赖和敏感信息范围 |
| 主控接管 | 输出已回到 LDVH 主控判断，不由外部能力直接生效 |
| 事实源边界 | 稳定事实已按归属回写，候选内容未冒充事实源 |
| 验证证据 | 已完成验证或记录验证缺口和残留风险 |
| Human Gate | 高风险事项已暂停确认或说明不触发原因 |
