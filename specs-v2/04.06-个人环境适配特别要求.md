# 个人环境适配特别要求

> 创建日期：2026-06-08
> 定位：登记当前个人或维护者环境中不应提升为 LDVH 通用规则、但会影响当前执行和验证的环境适配特别要求
> 适用范围：LDVH 自身项目当前执行环境、当前个人命令约定、由当前环境初始化记录显式启用的管辖项目环境约定

> 相关规范：`specs-v2/00-LD-Vibe-Harness理念与纲要.md`、`specs-v2/02-术语规范.md`、`specs-v2/04.02-环境适配与运行投影规范.md`、`specs-v2/04.03-环境适配映射与运行投影记录模板.md`、`specs-v2/04.05-LDVH环境适配特别要求.md`、`specs-v2/14-Code实现规范.md`

## 1. 本文解决的问题

本文解决个人或当前维护者环境中的特殊约定如何登记和限制的问题。

个人环境适配特别要求不属于 LDVH 通用规范，也不自动进入所有管辖项目。它只用于让 AI 在当前项目、当前平台或当前命令环境中执行时避免误用命令、路径或平台约定。若某项个人环境约定需要进入用户项目，必须由当前环境初始化记录或对应环境适配映射显式启用。

---
## 2. 与 00 总纲的关系

00 要求 LDVH 的稳定规则进入 Git 文件事实源，并围绕验证纪律和 Human Gate 运行。本文承认当前环境会影响 AI 执行命令和验证方式，但不允许个人环境约定反向改写 LDVH 通用规则。

当个人环境约定与管辖项目自身约定冲突时，以管辖项目当前环境初始化记录、项目事实源和 Human 明确说明为准。本文不得替代项目依赖管理、平台官方文档或 Code 测试验证。

---
## 3. 术语应用关系

本文使用的个人环境适配特别要求、当前环境初始化记录、环境适配映射、运行投影、Code、命令入口等术语，按 `specs-v2/02-术语规范.md` 定义。以下小节只说明这些术语在个人环境登记中的应用关系，不另行维护术语权威定义。

个人环境适配特别要求应同时满足：

1. 只影响当前个人、维护者或当前执行环境；
2. 不应提升为 LDVH 通用跨环境规则；
3. 需要 AI 在当前执行中持续注意；
4. 可以通过当前环境初始化记录、命令入口、Code 使用说明或人工提醒承接。

## 5. 启用与使用规则

AI 在 LDVH 自身项目中调用 Python 辅助程序、校验脚本或测试命令时，应优先使用 `python3`。

AI 在管辖项目中执行 Python 命令前，应先读取当前环境初始化记录、项目 README、依赖管理说明或 Human 明确指令。若项目明确使用虚拟环境、`python` 别名、`uv`、`poetry`、`pipenv` 或其他入口，应优先遵守项目自身约定，并在必要时记录降级方式。

本文不要求所有 LDVH 用户都使用 `python3`。安装到用户项目后，若当前环境初始化记录不存在或未适配当前平台，AI 不得把 PE-01 当成用户项目已经启用的规则。

本文通过以下规范落地要求说明相关要求的同步、检查或审计触发条件。

| 落地要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 入口可见要求 | AI 在当前环境执行 Python 工具或脚本时应能定位 PE-01 | 04 系列父规范、Code 使用入口摘要、当前环境初始化记录 | AI 执行入口提示 | 本文标题、定位、当前登记表或 PE-01 内容变化时 |

| Human 交互要求 | 管辖项目是否启用个人环境特别要求，应由 Human 或当前环境初始化记录确认 | 当前环境初始化记录、Human Gate、人工确认 | 初始化确认 | 安装 LDVH、切换项目、切换开发平台或执行项目 Python 命令前 |

## 7. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 将 PE-01 提升为 LDVH 通用跨环境要求；
2. 将管辖项目默认视为已启用 PE-01；
3. 改变 PE-01 的默认效力或适用范围；
4. 允许个人环境约定覆盖管辖项目自己的依赖管理或命令约定；
5. 删除本文中仍被当前环境初始化记录或 Code 入口消费的要求。

个人环境适配特别要求检查至少包括：

| 检查项 | 标准 |
|---|---|
| 适用范围 | 已区分 LDVH 自身当前环境和管辖项目环境 |
| 默认效力 | 已明确管辖项目默认不启用 |
| 项目优先 | 管辖项目自身环境记录和依赖管理优先于本文 |
| 命令验证 | 当前环境执行前有命令验证或等价验证方式 |
| 非通用化 | 个人环境约定未被写成 LDVH 通用跨环境规则 |

## 8. 待补齐事项

1. 当前仅登记 PE-01；如未来出现更多个人环境约定，应先判断是否属于当前环境初始化记录，而不是直接扩展本文；
2. 若后续 Code 运行时规范稳定定义解释器入口，应评估 PE-01 是否迁入 `specs-v2/14-Code实现规范.md` 或只保留为当前环境初始化记录；
3. 若用户项目通过初始化实践证明不同 Python 入口更常见，应避免把本文约定推广为默认安装规则。
