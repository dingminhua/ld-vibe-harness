# 管辖项目初始化流程

> 创建日期：2026-05-28
> 定位：PM Kit 管辖项目（trae-pm-kit）自身的初始化流程
> 适用范围：PM Kit 管辖项目（specs-v2 规范体系、pm-kit-base 事实源实例）
> 上位依据：`specs-v2/00-PMKit理念与纲要.md`、`specs-v2/10-事实源规范.md`、`specs-v2/11-AI协作规范.md`、`specs-v2/14-管理对象规范.md`

---

## 一、流程定义与触发条件

### 1.1 流程定义

管辖项目初始化是确保 PM Kit 规范体系自身完整、自洽、可执行的检查与补齐流程。

管辖项目初始化与受管理项目初始化（50）的区别：

| 维度 | 受管理项目初始化（50） | 管辖项目初始化（本文） |
|---|---|---|
| 目标 | 为业务项目搭建 PM Kit 基础设施 | 确保 PM Kit 规范体系自身完整、自洽、可执行 |
| 检查对象 | 业务项目的事实源与规则 | specs-v2 规范体系与 pm-kit-base 实例 |
| 产出 | 业务项目的 pm-kit-base 初始结构 | 规范缺口任务、歧义备忘、违规回退任务、初始化报告 |
| 触发者 | 项目首次接入 PM Kit | 规范体系发生结构性变更 |

### 1.2 触发条件

以下任一条件满足时，应执行管辖项目初始化流程：

1. specs-v2 新增或重组规范文档后
2. 对象实践文档（20-49）新增后
3. 流程文档（50-69）新增后
4. PM Kit 版本发布前
5. 规范体系发生结构性变更后（包括编号段调整、事实源边界重定义、管理对象增删）

---

## 二、执行步骤

### 2.1 规范体系完整性检查

检查 specs-v2 规范体系的结构完整性，确保各层规范之间无缺口、无冲突。

1. 检查 specs-v2/ 编号段是否连续、无冲突
   - 00 总纲段：00
   - 基础规范段：10-14
   - 对象实践段：20-49
   - 流程段：50-69
   - 编号不得跳号、不得重复、不得超出所属段范围
2. 检查 00 总纲与 10-14 各层规范的事实源边界是否一致
   - 每层规范的事实源边界声明应与 00 §七的分层定义对齐
   - 不得出现跨层定义或边界重叠
3. 检查 14 管理对象总表与 20-49 对象实践文档是否对齐
   - 14 总表中声明的每个管理对象都应有对应的对象实践文档
   - 对象实践文档不得定义 14 总表未声明的管理对象
4. 检查 14.01 载体映射与各对象实践的适配声明是否一致
   - 14.01 中声明的载体映射应与对象实践文档中的适配声明双向一致
   - 不得出现载体映射声明了但对象实践未适配、或对象实践适配了但载体映射未声明的情况

### 2.2 对象实践合规检查

检查每个对象实践文档是否遵守 14 §9 管理对象实践文档规范。

1. 检查每个对象实践文档是否遵守 14 §9.6 章节骨架
   - 对象实践文档必须包含：定义与事实源边界、与 14 的关系、字段契约、状态机或生命周期、转化关系、初始化检查项、审计检查项、Human Gate 声明、待补齐事项
   - 缺少必备章节的对象实践文档应标记为规范缺口
2. 检查每个对象实践文档是否遵守 14 §9.8 禁止扩张规范
   - 对象实践文档不得重新定义基础规范已定义的语义
   - 对象实践文档不得扩展基础规范的事实源边界
   - 对象实践文档不得引入基础规范未声明的管理对象
3. 检查对象实践文档的上位依据是否仅引用 specs-v2/
   - 上位依据不得引用 specs/（旧规范）或其他非 specs-v2 文档
   - 上位依据的引用路径应可解析到实际存在的 specs-v2 文档
4. 检查字段契约是否与 10 §12 格式契约对齐
   - 对象实践文档中声明的字段格式应与 10 事实源规范的格式契约一致
   - 不得出现字段格式与格式契约冲突的声明

### 2.3 流程文档合规检查

检查流程文档（50-69）是否与基础规范一致。

1. 检查流程文档是否与 10-14 各层规范一致
   - 流程文档引用的对象、状态、字段应与基础规范定义一致
   - 流程文档不得重新定义基础规范已定义的语义
2. 检查流程文档的 Human Gate 声明是否与 14 §十 一致
   - 流程文档中声明的 Human Gate 应与 14 管理对象规范的 Human Gate 原则一致
   - 不得出现流程文档的 Human Gate 与基础规范冲突的情况

### 2.4 pm-kit-base 实例一致性检查

检查 pm-kit-base/ 作为规范定义的项目事实源实例，是否符合对应对象实践文档的要求。

1. 检查 pm-kit-base/ 中的 Task/Memo/ADR/Pitfall/Change 是否符合对应对象实践文档
   - Task 实例应符合 21-Task 对象实践的字段契约和状态机
   - Memo 实例应符合 22-Memo 对象实践的字段契约
   - ADR 实例应符合 20-ADR 对象实践的字段契约
   - Pitfall 实例应符合 23-Pitfall 对象实践的字段契约
   - Change 实例应符合 24-Change 对象实践的字段契约
2. 检查 pm-kit-base/audits/ 快照是否与当前规范口径一致
   - 审计快照的检查项应与当前对象实践文档的审计检查项对齐
   - 过时的审计快照应标记为需更新
3. 检查 pm-kit-base/changes/ 是否覆盖近期实际修改
   - 近期对 specs-v2 文档的修改应有对应的 Change 记录
   - 近期对 pm-kit-base 实例的修改应有对应的 Change 记录

### 2.5 交叉引用一致性检查

检查规范文档之间的引用关系是否双向对齐、无断裂。

1. 检查对象实践文档之间的转化关系声明是否双向对齐
   - 若对象实践 A 声明可转化为对象实践 B，则 B 的转化关系章节应声明可由 A 转化而来
   - 单向声明视为规范缺口
2. 检查流程文档引用的对象实践是否与实际文档一致
   - 流程文档中引用的对象实践编号和名称应与 specs-v2/ 中的实际文件一致
   - 引用不存在的对象实践文档视为规范缺口

## 三、产出与分流

管辖项目初始化流程的产出按以下规则分流：

| 产出类型 | 分流目标 | 说明 |
|---|---|---|
| 规范缺口 | Task | 需补齐的规范内容，如缺少必备章节的对象实践文档、编号段冲突 |
| 规范歧义 | Memo 或 ADR | 需确认的规范解释，如事实源边界重叠、语义冲突 |
| 禁止扩张违规 | Task | 需回退到基础规范的扩张内容，如对象实践文档重新定义了基础规范语义 |
| 实例不一致 | Task | pm-kit-base 实例需更新以符合当前对象实践文档 |
| 交叉引用断裂 | Task | 需补齐的双向引用或修正的错误引用 |

流程完成后，产出初始化报告，内容包括：

1. 执行日期与触发条件
2. 各步骤检查结果摘要
3. 发现的问题清单及分流结果
4. 待补齐事项

---

## 四、Human Gate

以下操作需经人确认后方可执行：

1. 新增规范文档或对象实践文档
2. 修改规范体系编号段分配
3. 改变规范文档的事实源边界
4. 发现禁止扩张违规需要回退

---

## 五、检查要求

管辖项目初始化流程完成后，应满足以下检查要求：

1. 规范体系编号段无冲突
2. 14 总表与对象实践文档对齐
3. 14.01 映射与对象实践适配声明一致
4. 对象实践文档未违反禁止扩张规范
5. pm-kit-base 实例符合对象实践文档

---
