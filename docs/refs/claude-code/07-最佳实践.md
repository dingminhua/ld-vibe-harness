## 1. 结论摘要

Claude Code 的最佳实践围绕 CLAUDE.md 写法、成本控制、上下文健康管理和安全配置四个核心维度。CLAUDE.md 应具体而非抽象，包含关键命令、架构说明和编码标准。成本控制需关注 --max-turns、--max-budget-usd 和模型选择。上下文使用超过 70% 时应考虑压缩。安全方面推荐使用 PreToolUse Hook 阻止危险命令和 deny 规则保护敏感文件。

## 2. CLAUDE.md 写法

### 2.1 要具体

不要写"写好代码"，而应写"JS 使用 2 空格缩进"或"测试文件以 .test.ts 后缀命名"。具体的指令可以减少纠错循环。

### 2.2 推荐内容结构

```markdown
# Project: My API

## Architecture
- FastAPI backend with SQLAlchemy ORM
- PostgreSQL database, Redis cache
- pytest for testing with 90% coverage target

## Key Commands
- make test -- run full test suite
- make lint -- ruff + mypy
- make dev -- start dev server on :8000

## Code Standards
- Type hints on all public functions
- Docstrings in Google style
- 2-space indentation for YAML, 4-space for Python
- No wildcard imports
```

## 3. 成本与性能建议

1. 在 print 模式中使用 --max-turns 防止失控循环，大多数任务从 5-10 开始
2. 使用 --max-budget-usd 设置成本上限（最低约 $0.05）
3. 简单任务使用 --effort low（更快、更便宜），复杂推理使用 high 或 max
4. CI/脚本使用 --bare 跳过插件/hook 发现开销
5. 使用 --allowedTools 限制为任务实际需要的工具
6. 交互会话中上下文变大时使用 /compact
7. 已知内容分析时使用管道输入而非让 Claude 读取文件
8. 简单任务使用 --model haiku，复杂多步骤工作使用 --model opus
9. print 模式中使用 --fallback-model haiku 处理模型过载
10. 为不同任务开启新会话（会话持续 5 小时，新鲜上下文更高效）
11. CI 中使用 --no-session-persistence 避免磁盘积累

## 4. 上下文窗口健康管理

使用 /context 监控上下文使用情况：

- < 70% —— 正常运行，完整精度
- 70-85% —— 精度开始下降，考虑使用 /compact
- > 85% —— 幻觉风险显著上升，必须使用 /compact 或 /clear

## 5. 安全建议

1. 使用 PreToolUse hook 阻止危险命令（rm -rf、git push --force 等）
2. 在 settings.json 中配置 deny 规则保护敏感文件（如 .env）
3. 使用 --allowedTools 最小权限原则
4. 设置 CLAUDE_CODE_SUBPROCESS_ENV_SCRUB 从子进程中清除凭据
5. 避免使用 --dangerously-skip-permissions（除非在 CI 等受控环境中）

## 6. 专业技巧

- 在 prompt 中使用关键词 ultrathink 可在该轮次获得最大推理 effort
- 使用 Shift+Tab 快速切换权限模式
- 使用 ! 前缀直接执行 bash 命令绕过 AI
- 使用 @ 前缀引用文件/目录（带自动补全）
- 使用 # 前缀快速添加到 CLAUDE.md 记忆

## 7. 常见陷阱

1. 交互模式需要 tmux —— Claude Code 是完整的 TUI 应用
2. --dangerously-skip-permissions 对话框默认为 "No, exit" —— 必须按 Down 再按 Enter
3. --max-budget-usd 最低约 $0.05
4. --max-turns 仅限 print 模式 —— 交互会话中被忽略
5. Claude 可能使用 python 而非 python3 —— 首次会失败但会自我纠正
6. 会话恢复需要相同目录
7. 上下文退化是真实存在的 —— 超过 70% 使用率时输出质量明显下降
