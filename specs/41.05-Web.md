## 一、本文定位

本文定义多角色思考行动模型在 Web 展示层的适配内容。Web 展示层可以展示多角色思考的主题、模式、角色结论、分歧、风险、回写建议和 Human Gate 待确认项，帮助人类审查和确认。

本文不定义具体页面设计、组件、API 或代码实现。具体实现应进入 `web/` 或相关产品文档，并遵守 `specs/05.02-Web展示规范.md`。

---

## 二、展示对象

多角色思考 Web 适配可展示：

1. 分析主题；
2. 触发原因；
3. 分析模式；
4. Agent 前提状态；
5. 参与角色；
6. 各角色影响范围、结论、风险和建议动作；
7. 一致结论和分歧点；
8. 风险汇总；
9. 建议执行顺序；
10. 事实源回写建议；
11. Human Gate 待确认事项；
12. 关联 Change、Task、ADR、Memo、Risk 或 Evidence。

---

## 三、派生视图边界

多角色思考 Web 展示是派生视图，不是最终事实源。

Web 展示层不得维护：

1. 与 Git 文件事实源冲突的报告状态；
2. 只存在于 UI 中的确认结果；
3. 只存在于缓存中的角色结论；
4. 只存在于页面状态中的回写结果；
5. 无法追溯来源的风险或建议。

当展示结果与 Git 文件事实源不一致时，以 Git 文件事实源为准，并提示刷新或重新读取。

---

## 四、展示结构

多角色思考 Web 展示建议分为以下区域：

| 区域 | 内容 |
|---|---|
| 概览 | 主题、模式、触发原因、Agent 前提 |
| Context | 输入来源、读取事实源、适用规范规则 |
| 角色分析 | 各角色结论、风险、建议动作 |
| 分歧对比 | 一致结论、分歧点、待确认问题 |
| 风险汇总 | 高 / 中 / 低风险列表 |
| 回写建议 | 候选事实源、对象类型、是否需要 Change |
| Human Gate | 待确认事项、影响范围、建议确认内容 |
| 证据链 | 关联文件、对象、报告、变更记录 |

---

## 五、Human Gate 展示

Web 展示层在以下情况下应突出显示 Human Gate：

1. 报告建议修改 specs、Rules、Skill、Agent、Tools、Web 或行动模型；
2. 报告建议创建、导入、启用或修改 Agent；
3. 报告建议将过程分析升级为 ADR、规范规则或长期规范；
4. 报告建议改变事实源归属；
5. 报告建议执行跨项目、高风险或远程操作；
6. Agent 增强模式前提不满足但用户希望继续。

Human Gate 展示应说明确认原因、影响文件、影响范围、风险和建议选项。

---

## 六、受控操作入口

Web 展示层可以提供以下受控操作入口：

1. 复制或导出报告摘要；
2. 生成回写候选；
3. 投递给 AI 对话层继续处理；
4. 发起创建 Task、Memo、ADR、Risk、Evidence 或 Change 的请求；
5. 标记需要 Human Gate 确认的事项。

Web 展示层不得直接调用 AI、Skill 或 Agent，不得绕过 Tools 校验，不得将按钮点击结果替代 Git 文件事实源中的证据、决策或变更记录。

---

## 七、展示刷新

Web 展示层应支持：

1. 从 Git 文件事实源重新读取；
2. 写入后刷新关联对象和 Change；
3. 标记派生视图生成时间；
4. 标记数据来源；
5. 在源文件变化后提示重新生成视图。

缓存或数据库只可作为派生层，可重建且不可成为唯一事实源。

---

## 八、Human Gate

以下情况必须暂停确认：

1. 新增高影响受控编辑入口；
2. Web 展示层写入或覆盖 Git 文件事实源；
3. Web 展示层将 UI 状态或缓存升级为稳定事实；
4. Web 展示层直接调用 AI、Skill 或 Agent；
5. Web 展示层绕过 Tools 校验或 Human Gate。

---

## 九、检查要求

| 检查项 | 标准 |
|---|---|
| 来源 | 展示数据可追溯到 Git 文件事实源或当前报告输入 |
| 派生边界 | 页面状态、缓存和数据库不是最终事实源 |
| Gate 展示 | 高影响建议明确提示 Human Gate |
| 回写建议 | 候选事实源、对象类型和 Change 要求清晰 |
| AI 边界 | Web 展示层未直接调用 AI、Skill 或 Agent |
| 刷新 | 写入或源文件变化后可刷新视图 |
| 一致性 | 展示与事实源冲突时以事实源为准 |

---

## 十、待补齐事项

1. 多角色思考 Web 页面是否建设待 Web Tools 产品规划确认；
2. 报告展示组件和风险分组样式待产品设计后定义；
3. Human Gate 工作台与多角色思考报告的衔接待工具实践验证；
4. Web 展示层与 Tools 辅助层的数据契约待实现方案稳定后补齐。
