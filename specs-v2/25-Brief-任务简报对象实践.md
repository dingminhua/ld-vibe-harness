# Brief-任务简报对象实践

> 创建日期：2026-05-28
> 对象名：Brief / 任务简报
> 适用范围：所有接入 PM Kit 且需要承载 TaskSet 背景信息的项目
> 上位依据：`specs-v2/00-PMKit理念与纲要.md`、`specs-v2/14-管理对象规范.md`、`specs-v2/10-事实源规范.md`、`specs-v2/11-AI协作规范.md`、`specs-v2/12-程序辅助规范.md`、`specs-v2/13-工具展示规范.md`

## 一、对象定位与准入

### 1.1 对象定义

Brief 是承载 TaskSet 背景信息的文档对象。Brief 说明为什么做、做什么、范围是什么、成功标准是什么，并为 TaskSet 提供背景依据和执行对象索引。

Brief 的核心特征：

1. Brief 是 TaskSet 的**规范面**，pm-kit-base/tasksets/ 是 TaskSet 的**执行面**；
2. Brief 包含**背景说明 + 执行对象表**（任务 ID + 目标索引）；
3. Brief 是相对稳定的文档，动态字段（状态、优先级、完成标准）只维护在 pm-kit-base；
4. Brief 与 pm-kit-base 是同级事实源，职责不同。

### 1.2 与临时判断的区别

| 维度 | 临时判断 | Brief |
|---|---|---|
| 性质 | 执行过程中的局部选择 | TaskSet 的背景依据和执行对象索引 |
| 持续时间 | 一次性 | 长期，与 TaskSet 生命周期一致 |
| 复用价值 | 无 | 为 TaskSet 提供背景和索引 |
| 追踪需求 | 不需要独立追踪 | 需要独立追踪、与 TaskSet 双向关联 |

### 1.3 准入条件

一个文档需要满足以下条件之一，才应成为 Brief：

1. 该文档承载了至少一个 TaskSet 的背景信息和执行对象表；
2. 该文档是某批任务的来源或起因（如需求、审计报告、技术方案评估）；
3. 该文档需要被 Task 通过 `requirement_doc` 字段关联。

不满足 Brief 准入条件的文档，应按其性质分流：

1. 不承载执行对象表的专题研究 → 留在 docs/ 但不是 Brief；
2. 已有明确目标和完成标准 → 直接创建 Task；
3. 未任务化但有保留价值 → Memo；
4. 已确认的决策 → ADR。

### 1.4 Brief 不应被误用为

1. 专题研究——不承载执行对象表的文档不是 Brief；
2. Task 的详细描述——Task 的动态字段在 pm-kit-base/tasks/；
3. 知识库或参考文档——Brief 必须关联 TaskSet；
4. 需求池——Brief 是已沉淀的背景，不是待评估的需求列表。

### 1.5 Brief 的典型实例

| Brief 类型 | 内容 | 关联的 TaskSet |
|---|---|---|
| 需求简报 | 需求背景、目标、范围、成功标准 + 执行对象表 | 需求实施任务集 |
| 审计简报 | 审计发现、合规状态、缺失项 + 执行对象表 | 审计整改任务集 |
| 技术方案简报 | 方案对比、选型依据、实施计划 + 执行对象表 | 方案实施任务集 |
| 初始化简报 | 初始化评估、缺失项、补齐计划 + 执行对象表 | 初始化补齐任务集 |

### 1.6 Brief 与 Requirement 的关系

Requirement 是旧命名，现更名为 Brief。两者是同一对象的名称变更：

- Requirement → Brief：语义从"需求"扩展为"任务简报"，覆盖审计报告等非需求内容
- `requirement_doc` 字段名保持不变，避免破坏已有 Task YAML 的兼容性
- docs/20-59 编号段继续作为 Brief 的存放位置

## 三、生命周期

Brief 无状态机。Brief 的生命周期与 TaskSet 一致：

1. **创建**：当一批任务需要背景文档时，创建 Brief 并写入背景说明和执行对象表；
2. **追加**：新任务加入 TaskSet 时，追加执行对象表条目（仅 ID + 目标）；
3. **关闭**：当关联的 TaskSet 全部关闭后，Brief 自然归档，不需要显式关闭操作。

Brief 写入后可以修改（追加执行对象表、更新背景说明），但不得删除已关联的执行对象表条目。

## 四、字段契约

### 4.1 Brief 文档结构

每个 Brief 文档应包含以下章节：

| 章节 | 必须 | 内容 |
|---|---|---|
| 头部 | 是 | 编号、标题、创建日期、最后更新、关联 TaskSet |
| 背景 | 是 | 为什么做、来源、依据 |
| 目标与范围 | 是 | 做什么、不做什么、边界 |
| 成功标准 | 是 | 验收条件 |
| 执行对象表 | 是 | 任务 ID + 目标索引（仅 ID 和目标，动态字段在 pm-kit-base） |
| 约束与风险 | 否 | 已知约束、风险和依赖 |

### 4.2 执行对象表格式

```markdown
## 执行对象表

| 任务 ID | 目标 | 状态查询 |
|---|---|---|
| {TASK-ID} | {一句话目标} | 见 pm-kit-base/tasks/{TASK-ID}.yaml |
```

执行对象表只维护任务 ID 和目标，不维护状态、优先级、完成标准等动态字段。

### 4.3 写入规则

1. 对话中确认的新任务必须先追加到 Brief 的执行对象表（仅 ID、目标），再创建 pm-kit-base/tasks/ YAML；
2. 任务状态、优先级、完成标准等动态字段只维护在 pm-kit-base，不得回写 Brief；
3. Brief 与 pm-kit-base 是同级事实源，职责不同，不得互相替代；
4. Brief 中的执行对象表是索引，不是任务的完整定义。

## 五、与其他对象的关系

### 5.1 转化关系

```text
Intent → Brief → Task
Memo → Brief（当 Memo 沉淀为可执行的背景文档时）
Audit 发现 → Brief（审计简报）→ Task
```

### 5.2 依赖关系

- Brief 依赖 Profile（需要知道项目归属和 docs 路径）
- Task 依赖 Brief（通过 `requirement_doc` 字段关联）

### 5.3 引用关系

- Task 通过 `requirement_doc` 字段引用 Brief
- Brief 通过执行对象表引用 Task（双向索引）

## 七、审计检查项

| 检查项 | 标准 |
|---|---|
| 禁止扩张 | 未新增、扩张、重写或替代基础规范 |
| 上位依据 | 已声明 00、14、10-13 为上位依据 |
| 事实源边界 | 核心规则章节开头已声明事实源边界 |
| 单一事实源 | 动态字段只在 pm-kit-base，不在 Brief 中重复维护 |
| 写入顺序 | 新任务先追加执行对象表，再创建 pm-kit-base/tasks/ YAML |
| 关联 TaskSet | Brief 必须关联至少一个 TaskSet |
| 执行对象表 | 包含任务 ID 和目标索引，不包含动态字段 |
| 路径归属 | Brief 路径使用受管理项目路径，不使用 PM Kit 项目路径 |

---

## 八、AI 协作适配

1. AI 创建 Task 前应先确认是否有 Brief 可关联；若无，应询问用户是否创建 Brief；
2. AI 不得在 Brief 中维护动态字段，只能追加执行对象表条目；
3. AI 读取 Task 时，应通过 `requirement_doc` 字段定位并读取关联 Brief 的背景信息；
4. AI 发现新任务应追加到 Brief 执行对象表时，必须先追加再创建 Task YAML。

---

## 九、Human Gate

1. 创建 Brief 应评估是否触发 Human Gate；
2. 修改 Brief 的目标与范围章节应触发 Human Gate；
3. 删除 Brief 中已关联的执行对象表条目应触发 Human Gate。

---

## 十、程序辅助适配

1. 程序可校验 Brief 执行对象表中的任务 ID 是否在 pm-kit-base/tasks/ 中存在；
2. 程序可校验 Brief 与 pm-kit-base 之间不存在动态字段重复维护；
3. 程序可聚合 Brief 的执行对象表，生成任务集进度概览。

---

## 十一、工具展示适配

1. 工具可展示 Brief 列表及其关联的 TaskSet 状态；
2. 工具可展示 Brief 的执行对象表，链接到 Task 详情；
3. 工具不得在 Brief 展示中维护动态字段。

---

## 十二、待补齐事项

1. Brief 的 Markdown 模板待更多实践后标准化；
2. Brief 与 TaskSet 的一对一/一对多关系待实践确认；
3. `requirement_doc` 字段是否需要更名为 `brief_doc` 待兼容性评估；
4. Brief 的编号规则是否需要与 TaskSet ID 对齐待实践确认；
5. Brief 是否需要支持版本管理（如需求变更后 Brief 是否需要修订记录）待实践确认。
