## 1. 本文解决的问题

本文解决以下问题：

1. 某个 AI 开发环境提供哪些环境入口；
2. 这些环境入口如何接入 04.02 定义的 LDVH 能力资产；
3. AI 如何在授权边界内帮助用户生成候选薄入口文本和执行适配检查；
4. 部署前、部署后和声明完成前如何执行适配检查；
5. 接入失败、环境不支持、权限不足或证据不足时如何降级或 Human Gate。

LDVH 官方维护的环境适配目标为 Codex App。其他 AI 开发环境只按本文 §5.3 提供自助适配方向：用户或维护者可依据环境自身入口能力手动接入薄入口，但 LDVH 不承诺维护这些环境的完整路径、加载行为、Hook 事件、安装状态或本机实测结论。

用户本地状态不是长期事实源。它只能来自本文定义的适配检查，并作为当前过程输出、Code 输出、Web 当前视图或对话证据摘要呈现；不得把这些输出保存为长期“已安装 / 已启用 / 已验证”状态。若适配检查形成需要长期追溯的稳定结论、后续工作、决策、风险、经验或事实源修改，必须按 `specs/09-事实源边界与承载规范.md` 的事实源归属和 `specs/06-工作流程基础规范.md` 的 Human Gate 最小证据结构，回写到对应工作对象、Git commit records、Human Gate 证据落点或其他 Git 文件事实源。

## 2. 环境适配字段

每个环境入口适配项至少包含：

| 字段 | 必填 | 含义 |
|---|---|---|
| 环境类型 | 是 | 适用的 AI 开发环境类型 |
| 环境入口 | 是 | 该环境实际读取、加载、调用、触发、配置、展示或执行某类环境能力的位置或机制 |
| 对应 LDVH 能力资产 | 是 | 04.02 中定义的 Rules、Skill、Agent、Hook 或其它能力资产 |
| 接入方式 | 是 | 薄引用、配置、安装、软链、受控复制、人工降级等 |
| 部署步骤 | 是 | AI 如何帮用户接入该资产 |
| 写入权限 | 是 | 是否允许 AI 代写，是否需要 Human Gate；默认由用户手动加入入口 |
| 适配检查 | 是 | 如何现场判断接入已生效 |
| 成功条件 | 是 | 满足什么才能声明本次接入有效 |
| 失败处理 | 是 | 缺入口、无权限、不可读、环境不支持时如何处理 |
| 适配降级 | 是 | 缺少环境入口、入口不可稳定调用或环境能力不足时如何模拟或人工降级 |
| 禁止声明 | 是 | 哪些情况下不得声明完整支持、资产已部署或环境能力已覆盖 |
| 证据输出 | 是 | 应呈现给 Human 的证据 |
| 证据状态 | 是 | 已验证、待验证、仅参考、待补齐或不适用 |

`docs/sources/` 和外部资料只能作为输入证据或待吸收材料，不能作为 specs 上位依据。正式适配结论必须写成已吸收结论、实测证据摘要、Human Gate 记录引用或待补齐事项。

## 3. 适配状态

| 状态 | 含义 |
|---|---|
| 环境能力承载 | 环境提供可确认的入口或机制承接对应能力资产 |
| 配置适配 | 通过配置、安装、路径、软链或等价方式接入 |
| 指令适配 | 通过环境指令、会话提示或薄引用显式引导 |
| 人工降级 | 缺少稳定环境入口，通过人工检查或手动命令替代 |
| 仅作参考 | 当前信息只能作为候选输入，不能声明可用 |
| 待确认 | 缺少来源证据、实测证据或 Human Gate 确认 |

适配状态不是用户本地安装状态，也不表示当前机器已经部署成功。LDVH 环境适配不得使用“原生支持”“天然支持”或等价说法；只能描述当前环境观察到的入口、机制、能力、调用方式、适配检查、降级路径和证据状态。

## 4. 部署与适配检查规则

### 4.1 部署前检查

部署前必须确认当前环境类型、当前工作区和目标项目边界、目标 LDVH 能力资产是否存在、环境入口是否由用户自行维护、是否存在用户已有配置需要保护、是否触发 Human Gate。

LDVH 不默认自动写入用户环境入口。AI 可以检查 Codex App 的用户级 AGENTS 候选位置，生成可复制的薄入口文本，并说明应由用户自行加入系统级、用户级、工作区级或项目级规则入口。除非 Human 明确要求 AI 代写并确认影响范围，AI 不得静默创建、覆盖或维护任何用户环境入口。

Rules 环境入口接入不记录长期“已写入本机入口”状态，也不把本次写入结果写入 specs、docs、WorkPlan、Spark、ADR 或其它长期事实源。AI 只能在当前对话中说明候选文本、用户确认、检查结论和残留风险；环境是否在后续会话中实际读取，必须以后续现场检查为准。

### 4.2 部署执行

接入执行应优先由用户手动放入薄引用文本。AI 的默认职责是生成候选文本、说明放置位置、提示风险和提供检查步骤。只有在 Human 明确授权 AI 代写、目标入口已定位、已有内容已保护且有退出方式时，才允许 AI 执行受控写入。

接入不得复制完整 specs 正文，不得创建第二事实源，不得覆盖用户已有配置而不保留说明。

AI 生成薄入口文本前必须先定位当前 LDVH 仓库根目录，定义 `<LDVH_REPO_ROOT>` 为当前 LDVH 仓库根目录绝对路径，并按入口目标选择真实 Rules 入口：

| 入口目标 | 变量 | 真实路径 |
|---|---|---|
| 工作区级管辖治理入口 | `<LDVH_WORKSPACE_ENTRY>` | `<LDVH_REPO_ROOT>/rules/LDVH-WORKSPACE-ENTRY.md` |
| LDVH 源码仓库项目级维护入口 | `<LDVH_MAINTAINER_ENTRY>` | `<LDVH_REPO_ROOT>/rules/LDVH-MAINTAINER-ENTRY.md` |
生成候选文本前，AI 必须确认所选 Rules 入口存在且可读；若不存在或不可读，应停止并提示 Human 当前 LDVH Rules 资产不可定位。规范模板中的变量只用于表达路径占位，交给用户的文本必须替换为当前机器上的真实绝对路径；不得把示例路径、其它用户机器路径或相对路径写入候选入口文本。

薄引用正文只应包含入口指向、压缩或恢复后的重读提示、以及用于区分 LDVH 管理段的开始和结束标记。部署约束、禁止声明、事实源边界、Human Gate 要求、恢复上下文的详细来源和适配检查要求不得混入薄引用正文。

### 4.3 部署后适配检查

接入后检查只说明当前现场观察。AI 应检查用户提供或授权检查的环境入口内容是否包含正确薄引用，薄引用是否指向正确的 LDVH 能力资产，目标资产是否可读，是否复制了不应复制的完整正文，是否满足成功条件，是否仍需 Human Gate。

### 4.4 声明完成前检查

AI 声明本次接入建议或授权写入完成前必须输出证据摘要。证据至少包含环境类型、用户选择的环境入口、对应 LDVH 能力资产、检查时间、检查方式、检查结论、失败项和降级项。

未完成适配检查时，不得声明接入完成。适配检查失败时，不得把失败写成环境类型不支持，也不得把人工降级写成完整支持或资产已部署。

## 5. 环境入口适配矩阵

本节只维护 Codex App 官方适配路径。非 Codex 环境不在本文维护具体路径、目录、Hook 事件或安装步骤；需要接入时，用户或维护者应按 §5.3 的自助适配方向处理。

### 5.1 Codex App

Codex App 是 LDVH 当前官方维护的环境适配目标。LDVH 通过 Codex AGENTS 薄入口让 AI 定位对应 Rules 入口，但默认不由 AI 自动写入该入口。工作区级 AGENTS 应指向 `../rules/LDVH-WORKSPACE-ENTRY.md`，用于管辖项目识别和工作对象治理；LDVH 源码仓库项目级 AGENTS 应指向 `../rules/LDVH-MAINTAINER-ENTRY.md`，用于维护 LDVH 产品资产。用户可以将本文提供的薄入口文本手动加入自己的 Codex 用户级、工作区级或项目级入口；AI 只有在 Human 明确授权代写、目标入口已定位、已有内容已保护且影响范围已说明时，才可执行受控写入。

项目级 `.codex/` 只用于项目专属约束、仓库内测试、受信项目配置或显式降级，不作为 LDVH 通用入口默认落点。Codex App 的配置路径、Hook 事件和软入口可作为候选适配项写入本文。未经过当前环境实测或 Human Gate 确认前，应标注待确认或候选，不得声明当前机器已部署或完整支持。

#### 5.1.1 配置路径与软入口

| 能力意图 | 环境入口候选 | macOS / Linux 位置 | Windows 位置 | 证据来源 | 证据状态 | 接入方式 | 适配检查 | 禁止声明 |
|---|---|---|---|---|---|---|---|---|
| 用户级配置 | Codex 配置 | `~/.codex/config.toml` | 待实测确认 | 当前 Codex App 资料和本机检查 | 候选，需 Codex App 实测 | 配置适配 / Human Gate | 检查文件存在、格式有效、配置层级清楚 | 不得在未确认 Codex App 读取前声明生效 |
| 用户级 Hooks | Codex hooks | `~/.codex/hooks.json` | 待实测确认 | 当前 Codex App 资料和本机检查 | 候选，需 Codex App 实测 | Hook 配置 / Human Gate | 检查 hooks 文件存在、事件名有效、命令可信 | 不得声明未信任 hook 已自动运行 |
| 用户级 AGENTS 入口 | Codex 用户级 AGENTS | `~/.codex/AGENTS.md` | 待当前 Codex App Windows 用户目录确认 | Codex 官方最佳实践、当前环境检查 | 官方资料确认 AGENTS 可作 durable guidance；本机仍需检查文件和加载行为 | 用户手动薄引用 / Human Gate | 检查用户主目录下 `.codex` 存在、AGENTS 入口可定位、已有内容未被覆盖、LDVH 段落只指向 LDVH Rules 资产 | 不得把 AGENTS 写成 LDVH Rules 资产，不得覆盖用户既有 AGENTS 内容，不得默认由 AI 写入 |
| 项目级配置 | 项目 `.codex/config.toml` | `<repo>/.codex/config.toml` | `<repo>/.codex/config.toml` | 当前 Codex App 资料和本机检查 | 候选，需项目 trust 确认 | 项目专属配置 / 显式降级 | 检查项目配置层是否被信任和读取，且不承载 LDVH 通用入口默认职责 | 不得把未信任项目配置写成已加载，不得把项目级配置当作通用入口默认落点 |
| 项目级 Hooks | 项目 `.codex/hooks.json` | `<repo>/.codex/hooks.json` | `<repo>/.codex/hooks.json` | 当前 Codex App 资料和本机检查 | 候选，需项目 trust 确认 | 项目专属 Hook / 显式降级 | 检查 hooks 定义、命令来源、权限和信任状态，且不承载 LDVH 通用入口默认职责 | 不得绕过用户审查和信任流程，不得把项目级 Hooks 当作通用入口默认落点 |
| 软入口 | instructions、AGENTS、项目说明、会话入口 | 依当前 Codex App 能力确认 | 依当前 Codex App 能力确认 | 当前资料仅作候选 | 待确认 | 指令适配 / 人工降级 | 检查 Codex App 是否稳定读取该入口 | 不得声明持久入口完整支持 |

#### 5.1.2 Lifecycle Hook 事件候选

> 注：本节表格列出 Codex App 的 Hook 事件候选。Hook 候选只表达 Codex 方向的适配可能性，不表示当前用户环境已经安装、启用或完整支持。

| Hook 事件 | 典型能力意图 | 适配检查重点 | LDVH 使用边界 | 禁止声明 |
|---|---|---|---|---|
| `SessionStart` | 会话启动或恢复时注入上下文 | 检查事件是否支持、matcher 是否有效、输出是否进入模型上下文 | 可候选承接入口加载和恢复摘要 | 未实测前不得声明稳定加载 |
| `UserPromptSubmit` | Prompt 提交前检查或补充上下文 | 检查是否支持阻断、补充或提示 | 可候选承接输入澄清和风险提示 | 不得假定可改写所有用户输入 |
| `PreToolUse` | 工具调用前检查、阻断或改写部分输入 | 检查 matcher、工具覆盖范围、返回 JSON 语义 | 可候选承接危险命令、路径越界和权限检查 | 不得声明覆盖所有 shell、Web 或非 MCP 工具 |
| `PermissionRequest` | 权限请求前自动决策或交回审批 | 检查 allow / deny / abstain 语义和冲突优先级 | 可候选承接审批策略辅助 | 不得绕过 Human Gate 或环境审批 |
| `PostToolUse` | 工具调用后审查输出或反馈 | 检查是否能替换工具结果反馈、是否无法撤销副作用 | 可候选承接校验结果审查 | 不得声明能撤销已发生副作用 |
| `Stop` | 回合停止前决定是否继续 | 检查 continuation / block 语义 | 可候选承接最终验收、失败测试续跑 | 不得声明可以替代任务验收事实源 |
| `SubagentStart` | 子智能体启动前补上下文 | 检查子智能体类型和上下文注入方式 | 可候选承接 Agent 输入契约 | 不得声明未验证 Agent 能力 |
| `SubagentStop` | 子智能体结束后要求收口或继续 | 检查输出回主控和阻断语义 | 可候选承接 Agent 输出审查 | 不得让子 Agent 输出直接生效 |
| `PreCompact` | 上下文压缩前处理 | 检查 manual / auto matcher 和持久化输出 | 可候选承接压缩火花、Spark / WorkPlan / Git 回写提醒 | 不得把压缩火花写成聊天记忆长期事实源 |
| `PostCompact` | 上下文压缩后恢复处理 | 检查压缩后注入内容和恢复边界 | 可候选承接恢复摘要读取 | 不得声明恢复内容完整或替代事实源 |

Codex Hook 适配必须同时检查配置层级、项目 trust、命令来源、权限范围、事件覆盖范围和失败输出。未确认当前 Codex App 版本支持时，只能标注候选或待确认。

#### 5.1.3 压缩事件与火花处理

Codex App 可把 `PreCompact` 和 `PostCompact` 作为压缩火花与恢复的候选事件；但 LDVH 的稳定事实仍必须进入 specs、WorkPlan、Spark、ADR、Pitfall、Study、Git 文件或对应权威事实源。Hook 输出只能作为执行期辅助，不得替代事实源回写。

Codex 官方最佳实践将 `AGENTS.md` 作为自动进入上下文的 durable guidance，建议保持简短、准确、可执行；当 `AGENTS.md` 变大时，应保留主入口简洁并引用任务专属 Markdown 文件。Codex 还提供 `/compact`，且会自动 compact 长对话；长任务应保持一条线程对应一个连贯工作单元，必要时 fork，而不是把一个项目所有工作堆入同一线程。

Codex 工作区级 AGENTS 薄引用模板如下。AI 应把 `<LDVH_WORKSPACE_ENTRY>` 替换为当前机器上的真实绝对路径后交给用户自行加入 Codex 工作区级环境入口。若用户明确授权 AI 代写，且目标 `AGENTS.md` 已存在，应只替换 LDVH 开始与结束标记之间的内容，或在不存在 LDVH 管理段时追加该段，不得覆盖用户已有内容；若目标文件不存在，只能在 Human 明确授权、目标路径和影响范围已确认后创建最小薄入口文件：

```markdown
#### LDVH AI 入口引用开始

读取并遵守：

<LDVH_WORKSPACE_ENTRY>

发生 `/compact`、自动上下文压缩、线程恢复或上下文恢复后，重新读取上述 LDVH AI 入口。

#### LDVH AI 入口引用结束
```

LDVH 源码仓库项目级 AGENTS 薄引用模板如下。它只应用于维护 LDVH 产品资产，不用于直接处理管辖项目 `ldvh-base/` 工作对象：

```markdown
#### LDVH AI 入口引用开始

读取并遵守：

<LDVH_MAINTAINER_ENTRY>

发生 `/compact`、自动上下文压缩、线程恢复或上下文恢复后，重新读取上述 LDVH AI 入口。

#### LDVH AI 入口引用结束
```

| 能力意图 | Codex 候选机制 | 适配检查 | 降级路径 | 禁止声明 |
|---|---|---|---|---|
| 压缩前火花 | `PreCompact` | 检查事件支持、matcher、输出位置和失败处理 | 显式阶段总结、Spark、WorkPlan、上下文暂存 | 未实测前不得声明自动执行 |
| 压缩后恢复 | `PostCompact` | 检查恢复内容是否注入、是否可追溯到文件事实源 | Rules / instructions / Git 文件 / Human 当前输入 | 不得把恢复摘要写成完整事实源 |
| 长期记忆 | Spark / WorkPlan / Git 文件 | 检查是否符合对应事实源字段契约 | Human Gate 后回写正式对象 | 不得只依赖 Hook 输出或聊天记忆 |

### 5.2 Codex 接入检查摘要

Codex 接入检查至少包括：

1. 所选入口变量是否已替换为真实绝对路径；
2. `../rules/LDVH-WORKSPACE-ENTRY.md` 或 `../rules/LDVH-MAINTAINER-ENTRY.md` 是否按目标存在且可读；
3. 用户选择的 AGENTS 或等价入口是否由用户自行维护，或是否已明确授权 AI 代写；
4. 薄入口内容是否只包含入口指向、恢复后重读提示和 LDVH 管理段标记；
5. 是否复制了 specs 正文、部署约束、禁止声明或其它不应进入入口的内容；
6. 工作区级入口和 LDVH 源码仓库项目级入口是否没有互相替代，尤其是 `ldvh-base/` 工作对象是否仍通过工作区级管辖治理入口处理；
7. 是否需要在新线程、上下文恢复或 `/compact` 后重新现场检查入口是否被读取。

### 5.3 非 Codex 环境自助适配方向

非 Codex 环境不由 LDVH 官方维护完整适配。用户或维护者为其它 AI 开发环境接入 LDVH 时，应自行确认该环境是否存在可持久读取的规则、instructions、AGENTS、项目说明、配置、Hook、Skill、Command 或等价入口，并按以下方向处理：

1. 入口只放薄引用，不复制 LDVH 正文；
2. 薄引用必须按目标指向 `../rules/LDVH-WORKSPACE-ENTRY.md` 或 `../rules/LDVH-MAINTAINER-ENTRY.md` 的真实路径或该环境可稳定读取的等价位置；
3. 环境缺少持久入口时，只能使用会话提示、项目 README、人工步骤或显式降级；
4. Hook、Skill、Command、自动运行和权限机制必须分别验证，不得互相冒充；
5. 自助适配结果只说明当前用户当前环境的观察结论，不得写成 LDVH 官方支持声明；
6. 如需把自助适配经验沉淀为 LDVH 规则，必须先形成 ADR、Spark、Pitfall 或 specs 变更，并经过 Human Gate。

| 确定性执行要求 | Code 应能按本文字段执行或辅助适配检查 | Code、命令、测试样例 | 校验实现 | 字段稳定后 |

## 7. Human Gate 与检查要求

以下情况必须评估 Human Gate：

1. 代写、覆盖或删除用户环境入口；
2. 修改长期环境配置；
3. 启用自动触发、危险权限或跨工作区写入；
4. 受控复制 LDVH 能力资产全文；
5. 覆盖用户已有 Rules、Skill、Agent、Hook、instructions 或配置；
6. 声明任一环境完整支持 LDVH；
7. 将一次用户本地适配检查结果写成环境类型结论。

检查要求：

| 检查项 | 标准 |
|---|---|
| 入口定位 | 环境入口可定位或明确待确认 |
| 资产接入 | 对应 LDVH 能力资产存在且接入方式明确 |
| 部署权限 | 写入权限和 Human Gate 边界明确 |
| 适配检查 | 有部署前、部署后和声明完成前检查方式 |
| 降级说明 | 缺少环境入口时有适配降级和残留风险 |

## 8. 待补齐事项

1. Codex App 用户级或系统级配置入口、用户级或系统级 Hooks 入口、项目级 `.codex/` 降级边界需补官方来源、当前版本证据和 trust 规则；

4. Web 可展示 Codex 入口候选、证据状态、适配降级和待补齐事项的派生态势；
5. Code 使用入口需要同步本文对解释器、命令、权限和 Hook 安全的查询规则。
