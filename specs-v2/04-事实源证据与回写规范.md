## 1. 定位

本文是 v1 `09` 全局事实源原则的候选承接位置，不是 v1 `04` 保障机制的前移。

v2 若把 v1 `09` 的全局事实源原则迁入本文，属于高影响重构。迁入前必须逐条核对 v1 `01`、`03`、`05`、`06`、`10`、`20-59` 和 Code/Web 对 `09` 的依赖。

本文拟回答：

1. 什么是最终事实源；
2. 工具输出、AI 过程输出、Web 展示和知识地图投影为什么不是最终事实源；
3. 稳定事实何时需要回写；
4. 验证证据、关闭证据和长期经验如何进入事实源；
5. studies、sources、聊天过程或工具输出如何被吸收为正式事实；
6. 回写和吸收如何与 Git commit records 追溯衔接。

## 2. 与 05、06、07 的分工

05、06、07 和 20-59 只能维护本领域差异规则，不得重定义全局事实源原则。

| 文档 | 可承接内容 | 不得承接内容 |
|---|---|---|
| 05 | 保障机制、资产登记、Code/Web/运行时扩展消费边界、环境入口和适配检查相关事实边界 | 全局事实源原则 |
| 06 | 事实模型实例、字段证据和对象回写差异 | 工具输出回写总规则 |
| 07 | 行动执行过程中的回写触发、Gate 联动和证据要求 | 最终事实源定义 |
| 20-59 | 对象或流程特有证据、输出和回写差异 | 单一事实源原则 |

## 3. 知识地图边界

知识地图输出属于派生导航、聚合和诊断结果，不是事实源。知识地图可以帮助 AI 定位事实源和关系，但不得替代原始规范、工作对象、管辖项目配置或 Git commit records。
