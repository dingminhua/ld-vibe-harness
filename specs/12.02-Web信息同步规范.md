## 1. 本文定位

本文定义 LD Vibe Harness 如何使用 Web 信息同步层承载派生视图、状态和缺口呈现、Human Gate UI、受控编辑入口和人类确认工作台。

Web 信息同步层面向人可读、可确认、可操作的界面。Web 信息同步不是事实源，页面状态、缓存和数据库派生视图不替代 Git 文件事实源。

## 2. 父规范关系

`specs/12-LDVH工具基础规范.md` 定义 LDVH 工具体系总边界、事实源回写总原则和 Tools 辅助层 / Web 信息同步层选择边界。本文只展开 Web 信息同步层。

当需要判断某项工具能力应进入 Tools 辅助层还是 Web 信息同步层时，必须以 `specs/12-LDVH工具基础规范.md` 第五节为准；本文只检查已拟使用 Web 信息同步层时是否满足派生视图、信息同步、确认、受控编辑和缓存治理要求。

Web 信息同步层与其他机制的关系：

| 对象 | 关系 |
|---|---|
| Tools 辅助层 | Web 信息同步层可调用 Tools 辅助层获取派生数据和受控写入能力 |
| Git 文件事实源 | Web 信息同步层同步和写入的稳定事实必须可追溯到 Git 文件事实源 |
| Rules / Skill / Agent | Web 信息同步层可提供结构化上下文和执行请求，但不得直接调用 AI、Skill 或 Agent |
| 事实模型 | Web 信息同步层可同步事实模型状态、关系和缺口，但对象语义以 20-49 规范为准 |
| 行动模型 | Web 信息同步层的人类确认、验收和回写提示应服从 50-79 行动模型 |

## 3. Web 信息同步层内部设计检查

跨工具层选择依据 `specs/12-LDVH工具基础规范.md` 第五节，本文不另行判断某项能力是否应优先进入 Tools 辅助层或 Web 信息同步层。已拟使用 Web 信息同步层时，应检查该能力是否满足以下内部设计条件：

1. 面向人同步、确认、操作或协同；
2. 同步内容可追溯到 Git 文件事实源；
3. 页面状态不作为权威事实；
4. 编辑入口写入目标明确；
5. 高影响操作能够提示 Human Gate；
6. 写入后可刷新并回读 Git 文件事实源；
7. 缓存和数据库只作为派生层；
8. 不直接调用 AI、Skill 或 Agent；
9. 不绕过 Tools 辅助层的校验和受控写入边界。

## 4. 信息同步定位与职责

Web 信息同步层是面向人的执行型工作台，核心交互模式是“看见 → 确认 → 操作 → 协同”。

Web 信息同步层可以承担：

| 职责 | 说明 |
|---|---|
| 同步状态 | 同步对象状态、关系、缺口和检查结果 |
| 同步证据 | 同步可追溯到事实源的证据和变更摘要 |
| 提示 Gate | 标识需要人确认的操作、风险和影响范围 |
| 受控编辑 | 提供受控编辑入口，写入 Git 文件事实源 |
| 协同入口 | 为 AI 对话层提供结构化上下文或可投递执行请求 |
| 刷新视图 | 写入后重新读取或刷新派生视图 |

Web 信息同步层不得承担：

1. 成为最终事实源；
2. 绕过 Git 文件写入；
3. 绕过 Human Gate；
4. 将缓存或数据库作为权威状态；
5. 直接定义事实模型字段、状态机或行动流程；
6. 直接调用 AI、Skill 或 Agent；
7. 将页面状态作为任务状态、证据、决策、规则或审计的唯一来源。

## 5. 信息同步原则与派生视图边界

### 5.1 信息同步范围

Web 信息同步层可以同步：

1. 事实模型状态和关系；
2. 初始化缺口和合规缺口；
3. 校验结果和检查清单；
4. 待确认事项和 Human Gate；
5. 证据、变更和审计摘要；
6. AI 可使用的结构化上下文；
7. 受控写入的影响范围和回写结果。

### 5.2 派生视图边界

派生视图是从 Git 文件事实源读取、解析、聚合后生成的信息同步结果。

派生视图不得维护：

1. 与 Git 文件不一致的权威状态；
2. 无法追溯来源的事实；
3. 只存在于 UI 中的关闭证据；
4. 只存在于缓存中的决策或规则；
5. 绕过项目事实源的项目记录。

当 Web 信息同步结果与 Git 文件事实源不一致时，以 Git 文件事实源为准。

## 6. 缓存和数据库边界

Web 信息同步层可以使用缓存或数据库提高性能，但缓存和数据库只能是派生层。

缓存或数据库中的内容必须满足：

1. 可由 Git 文件事实源重新生成，或明确标记为运行时临时状态；
2. 不作为任务状态、证据、决策、规则或审计的唯一来源；
3. 失效、删除或重建后不影响事实源完整性；
4. 不保存敏感凭据或不应持久化的信息；
5. 不改变项目事实归属。

## 7. 人类确认入口

### 7.1 Human Gate 在 Web 信息同步层中的体现

Web 信息同步层应在以下情况暂停并提示用户确认：

1. 写入或覆盖 Git 文件事实源；
2. 改变事实源归属；
3. 将派生数据升级为稳定事实；
4. 绕过 Rules、对象状态机、行动模型或证据门禁；
5. 迁移旧结构化事实源；
6. 引入影响事实源链路的缓存或数据库机制。

### 7.2 确认信息同步原则

1. Web 信息同步层应明确提示用户需要确认的操作、目标文件、影响范围和风险。
2. 确认结果应可追溯，必要时回写到对应 Git 文件事实源。
3. Web 信息同步层不得用按钮点击结果替代应写入 Git 文件事实源的证据、决策或变更记录。

## 8. 受控编辑入口

### 8.1 写入原则

1. Web 信息同步层的任何写入操作，实际写入目标必须是项目的 Git 文件事实源。
2. 写入后必须触发对应变更证据要求（依据 specs/22-Change-变更记录.md）
3. 写入不得只停留在 Web 数据库、缓存或 UI 状态。

### 8.2 写入前检查

受控编辑至少应检查：

1. 写入目标事实源明确；
2. 写入内容符合对象格式规范；
3. 写入前已判断是否已有权威事实；
4. 写入前已判断是否触发 Human Gate；
5. 写入动作不会绕过 Tools 辅助层校验边界。

### 8.3 写入后验证

1. 写入后可通过 Git 追溯；
2. 写入后 Web 信息同步视图应从事实源重新读取或刷新；
3. 写入结果不得只停留在 Web 数据库或 UI 状态。

## 9. Web 信息同步层与 AI 协作

1. Web 信息同步层可以为 AI 对话层提供结构化上下文；
2. Web 信息同步层可以同步 AI 执行前需要的人类确认事项；
3. Web 信息同步层可以生成可投递给 AI 的执行请求或上下文摘要；
4. Web 信息同步层不得直接调用 AI、Skill 或 Agent；
5. AI 产生的稳定事实仍必须按事实源边界写回 Git 文件事实源。

## 10. Web 信息同步层与 Tools 辅助层关系

1. Web 信息同步层可以调用 Tools 辅助层获取解析、校验、聚合和派生视图数据。
2. Web 信息同步层可以调用 Tools 辅助层执行受控写入准备或写入操作。
3. Web 信息同步层不得因调用 Tools 辅助层而绕过事实源原则和 Human Gate。
4. Tools 辅助层的缓存、数据库和派生数据边界同样适用于 Web 信息同步层。
5. Web 信息同步层负责人类可读和可操作体验，Tools 辅助层负责确定性处理。

## 11. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. Web 信息同步层写入或覆盖 Git 文件事实源；
2. Web 信息同步层改变事实源归属；
3. Web 信息同步层将派生数据、缓存、数据库视图或 UI 状态提升为稳定事实；
4. Web 信息同步层绕过 Rules、对象状态机、行动模型或 Human Gate；
5. Web 信息同步层引入持久化数据库作为派生层并影响事实源读取、同步或写入链路；
6. Web 信息同步层新增高影响受控编辑入口。

Web 信息同步层检查至少包括：

| 检查项 | 标准 |
|---|---|
| 来源可追溯 | 视图数据可追溯到 Git 文件事实源 |
| 写入可追溯 | Web 写入落到 Git 文件并可通过 Git 追溯 |
| 缓存非权威 | 缓存和数据库可重建且非唯一事实源 |
| 项目归属 | 写入目标属于正确项目 |
| Gate 判断 | 高影响写入已评估 Human Gate |
| 同步一致性 | Web 信息同步结果与 Git 文件事实源一致或明确提示刷新 |
| AI 边界 | Web 信息同步层未直接调用 AI、Skill 或 Agent |
