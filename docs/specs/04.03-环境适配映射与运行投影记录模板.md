> 适用范围：LDVH 自身环境初始化记录、运行投影同步、环境能力核验记录、降级记录和运行投影漂移审计

## 1. 本文解决的问题

本文解决 LDVH 在具体环境中如何记录环境适配映射和运行投影的问题。

`docs/specs/04.02-环境适配与运行投影规范.md` 规定通用规则；本文只规定记录模板和填写顺序。LDVH 自身项目的具体环境适配结果应使用本文模板登记某个环境如何承接规范落地要求、形成哪些运行投影、如何验证、如何降级。

本文使用的当前环境初始化记录、环境适配映射、运行投影、运行投影状态、降级记录和漂移检查记录等术语，按 `docs/specs/02-术语规范.md` 定义。本文只规定记录模板和填写顺序，不另行维护术语权威定义。当前环境初始化记录只是 LDVH 自身项目环境适配的前置准备或组成部分，不等同于产品初始化完整落地。

本文不维护 Codex、Trae、Claude Code、Cursor 或其他平台的能力清单，也不把任何平台能力直接提升为 LDVH 规范规则。平台客观能力应由官方文档、refs、当前配置或实际运行投影核验；LDVH 自身项目实际适配判断应写入当前环境初始化记录、Task、Memo、ADR 或对应正式规范。

## 2. 与 00 总纲的关系

00 要求 LDVH 通过开发环境、工作模型、工作流程、Code 和 Web 共同形成可规划、可执行、可验证、可沉淀、可演进的 AI 工程闭环。

本文承接 00 的事实源边界：环境适配映射和运行投影记录只说明规范如何进入具体环境，不替代 docs/specs 正式规范、工作对象、Code 验证结果或 Human Gate 判断。

## 3. 使用原则

环境适配映射与运行投影记录应遵守以下原则：

1. **先核验能力**：登记前先确认当前环境真实支持什么；
2. **先映射要求**：从规范落地要求和保障机制出发，不从环境偏好出发；
3. **再登记投影**：只有实际存在、计划创建或明确降级的入口、配置、命令、Skill、Agent、Hook、Web 页面或 CI 检查，才登记为运行投影；
4. **保留降级**：环境不支持或尚未创建投影时，应记录降级方式和残留风险；
5. **支持漂移检查**：记录应能帮助 AI、Code 或 Human 判断规范变化后运行投影是否需要同步。

模板字段可以按具体环境裁剪，但不得省略规范来源、落地要求、保障机制、运行投影实体或位置、运行投影状态、验证方式和降级方式。

LDVH 自身环境初始化记录的默认位置和英文文件名如下：

```text
LDVH-ENVIRONMENT-INITIALIZATION.md
```

该文件应放在 LDVH 自身项目根目录。环境初始化记录用于让用户和 AI 看见 LDVH 自身项目如何完成环境适配准备、哪些环境能力已被核验、哪些运行投影已存在或缺失，因此不应默认放入隐藏目录。隐藏目录更适合工具缓存、索引、平台私有配置或机器状态；根目录可见文件更适合用户需要阅读、审阅和信任的项目入口级说明。

该文件是 LDVH 自身项目的环境初始化结果物，不属于 docs/specs 正式规范，也不属于 docs 正文。用户打开该文件时，应能立即看出它用于说明当前 LDVH 环境初始化结果、已核验能力、适配映射、运行投影状态、缺口和降级方式。该文件不是规范文档，也不等同于产品初始化完整落地，但其结构由本文模板约束。正文应使用中文；英文文件名只作为稳定入口。

AI 初始化或维护 LDVH 自身项目的环境适配和运行投影时，应先检查该文件是否存在。若不存在，应视为尚未完成 LDVH 自身环境适配，并持续提醒用户先按本文模板创建并完成适配；在此之前只能调研、草拟和记录临时降级方式，不得创建、修改或删除 LDVH 自身项目的持久运行投影。若已存在，应读取后增量更新。除非 Human 明确要求重置，不得覆盖已有记录。

该文件不作为管辖项目默认安装文件。管辖项目接入 LDVH 时，应通过 LDVH 根目录 `LDVH-GOVERNED-PROJECTS.yaml`、对应项目的 `ldvh-base/`、`docs/` 和工作区级薄入口建立管理关系，不要求在管辖项目根目录创建本文件。AI 每次准备在 LDVH 自身项目中映射或实现环境功能、创建或修改持久运行投影、登记环境能力承接方式前，必须检查该文件的存在性和适配状态。若文件不存在、适配状态不是“已适配 LDVH 自身项目与当前开发环境”，或项目、平台、权限边界、Human 授权状态、能力来源、Human 确认状态不匹配，AI 应持续提醒用户创建或修改该文件，直到用户完成确认或改写。

当前环境初始化记录还应区分工作区级入口、LDVH 自身项目级入口和管辖项目 LDVH 事实源。工作区级入口是用户开发环境中的单句薄引用，用于把 AI 引向 LDVH 管理入口、管辖项目配置或 LDVH 事实源；AI 只能在 Human 授权下提示或协助添加，不得把它写入 LDVH 项目版本库。LDVH 自身项目级入口只用于 LDVH 自身项目；管辖项目一般不创建平台规则文件、项目指令或等价项目级入口，避免和用户项目原有入口冲突。LDVH 项目事实源和工作对象实例可以在管辖项目中创建，因为它们是受控记录，不是平台入口。

AI 统一入口运行投影的默认位置和英文文件名如下：

```text
LDVH-AI-ENTRY.md
```

该文件是 LDVH 自身项目根目录的运行投影，结构和内容边界由 `docs/specs/04.07-AI统一入口运行投影规范.md` 约束。当前环境初始化记录应登记该投影是否存在、由哪些平台薄入口指向、验证方式和漂移风险；但当前环境初始化记录不替代 AI 统一入口正文，AI 统一入口也不替代当前环境初始化记录。

## 4. 环境能力核验模板

环境能力核验用于记录某个环境是否具备承接规范落地要求所需的能力。

| 字段 | 填写要求 |
|---|---|
| 环境 | Codex、Trae、Claude Code、Cursor、CI、Web、命令行或其他环境 |
| 核验对象 | Rules / Instructions、Skill、Agent、Hook、Code、Web、配置、命令或其他能力 |
| 核验来源 | 官方文档、refs、当前配置、实际文件、命令输出或 Human 明确说明 |
| 能力结论 | 支持、不支持、部分支持、未知或待核验 |
| 适合承接 | 可承接的规范落地要求类型 |
| 限制 | 触发、权限、上下文、并行、写入、可见性或稳定性限制 |
| 降级建议 | 能力不足时的替代方式 |
| 最近核验 | 日期、执行者或核验方式 |

能力核验记录不得复制完整平台手册。若平台说明较长，应进入 refs；若结论会影响 LDVH 使用规则，应吸收到 LDVH 自身环境初始化记录、Task、Memo、ADR 或对应正式规范。

## 5. 环境适配映射模板

环境适配映射用于登记某项规范落地要求在具体环境中的承接方式。

| 字段 | 填写要求 |
|---|---|
| 映射编号 | 稳定编号，例如 `MAP-CODEX-01` |
| 环境 | 被适配的环境 |
| 规范来源 | 正式规范、章节、对象或上位规则来源 |
| 落地要求 | `docs/specs/04.01-规范落地要求规范.md` §4 定义的落地要求类型 |
| 要求内容 | 该要求具体要落地什么 |
| 保障机制 | 规则、流程、Code、Human Gate、子 Agent 思考、生命周期触发或组合机制 |
| 能力承接判断 | 按 `docs/specs/04.04-环境能力承接边界.md` 判断采用哪些能力 |
| 环境实体 | 具体环境中可被定位、配置、调用或维护的入口、文件、配置、命令、Skill、Agent、Hook、Web 页面、CI 或降级记录 |
| 运行投影实体或位置 | 适配后实际存在、计划创建或用于降级的入口、文件、配置、命令、Skill、Agent、Hook、CI、Web 页面、摘要或降级记录 |
| 运行投影状态 | 已存在、待创建、缺失、部分可用、已废止或不适用 |
| 验证方式 | 如何确认映射存在、可用、未漂移 |
| 降级方式 | 环境不支持或投影缺失时如何处理 |
| Human Gate | 是否需要 Human 确认、授权或验收 |

一个规范落地要求可以存在多个环境适配映射。多个环境适配映射不得互相覆盖，也不得因为某个环境能力不足而改写正式规范。

## 6. 运行投影登记模板

运行投影登记用于记录环境适配后实际存在或被调用的实体。

| 字段 | 填写要求 |
|---|---|
| 投影编号 | 稳定编号，例如 `PROJ-CODEX-01` |
| 环境 | 投影所在环境 |
| 投影类型 | AI 统一入口、入口摘要、规则、配置、命令、Skill、Agent、Hook、CI、Web、降级记录或其他 |
| 入口层级 | 工作区级入口、LDVH 自身项目级入口、会话级降级方式、管辖项目配置、管辖项目 LDVH 事实源或不适用 |
| 投影位置 | 文件路径、配置位置、命令入口、页面入口、环境说明或降级检查位置 |
| 来源映射 | 对应环境适配映射编号或规范落地要求 |
| 当前状态 | 已存在、计划创建、缺失、部分可用、已废止或不适用 |
| 维护方式 | 手动维护、Code 生成、CI 同步、环境配置、Human 选择或其他方式 |
| 验证方式 | 检查命令、人工核验、环境启动检查、Hook 触发记录或降级检查 |
| 漂移风险 | 可能与正式规范不同步的风险 |
| 回写出口 | 发现稳定结论后回写到正式规范、Task、Memo、ADR 或其他事实源的位置 |

运行投影登记应避免长篇复制规范正文。若需要给 AI 提供入口摘要，应保留摘要与权威规范的路径关系，而不是把摘要当成新事实源。

## 7. 使用顺序

创建或修改 LDVH 自身环境初始化记录时，应按以下顺序使用本文模板：

1. 先确认当前记录是否存在，并匹配 LDVH 自身项目、当前开发环境、权限边界和 Human 授权状态；
2. 若不存在或不匹配，先提醒用户创建、确认或改写，不得继续创建 LDVH 自身项目的持久运行投影；
3. 按 §4 记录环境能力核验；
4. 按 §5 从规范落地要求生成环境适配映射；
5. 按 §6 登记运行投影实体、位置和状态；
6. 对缺失、部分支持或未知能力记录降级方式；
7. 判断是否需要 Code 检查、Human Gate、子 Agent 思考或生命周期触发；
8. 修改完成后检查运行投影是否与正式规范保持一致。

若本次任务只是在评估能力而不建立运行投影，可以只填写能力核验和降级建议。若本次任务要真正创建、修改或删除运行投影，应同步填写环境适配映射和运行投影登记。

LDVH 自身环境初始化记录必须至少包含以下章节：

| 章节 | 用途 |
|---|---|
| 这个文件是什么 | 让用户知道该文件是 LDVH 自身项目根目录可见的环境初始化结果物，不是隐藏工具状态、缓存或规范正文 |
| 适配状态与持续提醒 | 记录适用项目、适用环境、LDVH 当前项目、当前开发环境、权限边界、Human 授权状态、适配状态、最近 Human 确认和未适配时的持续提醒规则 |
| 初始化摘要 | 记录环境、项目、日期、模板来源、能力来源、当前投影状态和降级模式 |
| 能力核验来源 | 记录平台能力核验来源、日期、覆盖范围和摘要 |
| 环境适配映射 | 记录落地要求如何映射到当前环境 |
| 当前运行投影状态 | 区分 LDVH 自身项目级投影、已存在 LDVH Code、缺失项和会话级降级方式 |
| 初始化动作 | 记录初始化已完成动作 |
| 更新规则 | 说明何时增量更新、何时需要 Human 明确重置 |
| Human Gate 与检查 | 说明创建、修改或删除持久投影前的检查和 Human Gate |
| 未决限制与后续事项 | 记录尚未落地、尚未核验或需要后续回写的限制 |

## 8. 不得写入模板的内容

以下内容不得作为模板记录本身的权威内容：

1. 平台完整手册、参数表或教程；
2. 未被正式规范吸收的 evals 或 refs 结论；
3. 工作对象状态、负责人、验收或关闭证据；
4. 未经 Human Gate 授权的自动写入计划；
5. 只服务未来假想环境的能力清单；
6. 与 docs/specs 正式规范冲突的运行说明。

模板记录发现稳定规范缺口时，应回到对应正式规范；发现 Code 缺口时，应按 `docs/specs/07-Code实现规范.md` 处理；发现 LDVH 落地特别要求缺口时，应按 `docs/specs/04.05-LDVH落地特别要求.md` 处理；发现个人落地特别要求缺口时，应按 `docs/specs/04.06-个人落地特别要求.md` 处理。

## 9. 规范落地要求

本文通过以下规范落地要求说明相关要求的同步、检查或审计触发条件。

| 落地要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 上位约束承接要求 | LDVH 自身环境初始化记录登记环境适配映射和运行投影时，应使用本文字段和填写顺序 | 本文 §4-§7、`docs/specs/04.02-环境适配与运行投影规范.md`、Human Gate | 环境治理 | 新增、修改或审计 LDVH 自身环境初始化记录时 |
| 入口可见要求 | AI 处理环境适配或运行投影记录时应能定位本文作为记录模板入口 | 规范文档入口摘要、04 系列父规范、LDVH 自身环境初始化记录 | AI 执行入口提示 | 本文定位、模板字段或使用顺序变化时 |
| 流程复用要求 | 环境能力核验、映射登记和投影登记应形成可复用检查步骤，并能生成用户可读的 LDVH 自身环境初始化记录 | 本文 §4-§7、LDVH 自身环境初始化记录、人工降级检查 | 流程复用 | 初始化或审计 LDVH 自身环境适配、批量检查运行投影或接管既有环境机制时 |

| 确定性执行要求 | Code 应能检查 LDVH 自身项目根目录环境初始化记录是否存在、是否中文可读、是否包含适配状态字段，并在后续读取或检查环境适配映射、运行投影状态和缺失字段 | `tools/specs_validate.py env-init`、`tools/specs_validate.py` 扩展、后续漂移检查 Code、正反样例 | 校验实现 | 模板字段、适配状态字段、投影状态枚举、引用规则或检查范围变化时 |
| 生命周期触发要求 | 正式规范、环境能力或运行投影变化后，应检查对应模板记录是否需要同步 | 环境适配流程、漂移检查 Code、CI、Hook 或人工降级检查 | 触发保障 | 正式规范新增、重命名、删除、落地要求变化、环境能力变化或运行投影漂移时 |

## 10. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 新增、删除或重命名环境适配映射和运行投影模板字段；
2. 允许缺失验证方式或降级方式的记录被视为完整落地；
3. 允许运行投影登记替代正式规范；
4. 将平台能力核验记录直接提升为 LDVH 规则；
5. 批量创建、修改或删除运行投影；
6. 让自动触发、自动写入或自动同步影响 Human Gate、事实源边界或 Code 验证；
7. 在 LDVH 自身项目缺少当前环境初始化记录时继续创建持久运行投影；
8. 将 LDVH 自身环境初始化记录视为管辖项目默认环境适配记录。

环境适配记录检查至少包括：

| 检查项 | 标准 |
|---|---|
| 文件存在 | LDVH 自身项目根目录存在 `LDVH-ENVIRONMENT-INITIALIZATION.md`；不存在时视为未完成 LDVH 自身环境适配 |
| 中文可读 | 当前环境初始化记录正文使用中文，用户无需理解平台英文术语即可判断用途和状态 |
| 适配状态 | 已记录适用项目、适用环境、LDVH 当前项目、当前开发环境、权限边界、Human 授权状态、适配状态和最近 Human 确认 |
| 能力核验 | 环境能力结论有来源、有日期或核验方式 |
| 要求映射 | 映射从规范落地要求出发，不从环境偏好出发 |
| 能力边界 | 能力承接判断符合 `docs/specs/04.04-环境能力承接边界.md` |
| 投影状态 | 已说明已存在、待创建、缺失、部分可用、已废止或不适用 |
| 验证方式 | 已说明如何确认映射和投影未漂移 |
| 降级方式 | 环境不支持或投影缺失时有降级处理 |
| 事实源边界 | 运行投影未替代 docs/specs 正式规范 |
