# LDVH 文件夹说明

> 创建日期：2026-05-29
> 定位：LD Vibe Harness 项目文件夹规划说明
> 适用范围：LD Vibe Harness 项目及所有接入 LD Vibe Harness 的管辖项目
> 上位依据：`specs/00-LD-Vibe-Harness理念与纲要.md`
> 相关规范：`specs/01-specs文档结构规范.md`、`specs/03-事实源边界与承载规范.md`

---

## 一、本文解决的问题

本文解决 LD Vibe Harness 项目有哪些主要文件夹、每个文件夹承载什么内容、AI 和人应如何根据目录定位快速找到对应材料的问题。

文件夹说明的目的不是定义事实源规则，而是提供项目结构地图。目录是否为最终事实源、同一事实的权威位置、工具输出何时成为事实等规则，由 `specs/03-事实源边界与承载规范.md` 定义。

---

## 二、与 00 总纲的关系

00 定义 LD Vibe Harness 的产品理念、价值实现标准、五类构成要素和基础规范索引。本文承接 00 中“介质、Trae Solo 环境机制、Harness 工具、Harness 生产对象、Harness 行动模型共同组成工程驾驭体系”的架构判断，专门定义这些内容在项目文件夹中的承载位置。

本文是 LD Vibe Harness 项目文件夹规划的权威位置。00 只保留基础规范索引，不重复维护项目目录说明；03 定义事实源边界，不重复维护目录用途说明。

---

## 三、文件夹规划边界

**事实源边界声明：** 本文的权威领域是 LD Vibe Harness 项目文件夹规划、一级目录用途、目录之间的内容归属关系和管辖项目定义。本文不定义 specs 文档编号、子文档、实践文档和引用纪律（见 `specs/01-specs文档结构规范.md`）；不定义最终事实源判断、单一事实源原则和事实承载规则（见 `specs/03-事实源边界与承载规范.md`）；不定义具体生产对象字段和状态机（见 10-39 Harness 生产对象）；不定义 AI 行动流程（见 40-69 Harness 行动模型）；不定义工具实现细节（见 `web/` 和 `tools/`）。

### 3.1 管辖项目定义

本文中的“管辖项目”，指接入并使用 LD Vibe Harness 进行需求、任务、证据、变更、审计或交付治理的实际项目。

### 3.2 一级目录说明

| 目录 | 定位 | 主要内容 |
|---|---|---|
| specs/ | LD Vibe Harness 规范目录 | 00-99 specs 文档，包括理念总纲、基础规范、生产对象规范、行动模型规范和内部调研 |
| docs/ | 管辖项目资料目录 | 管辖项目资料、管辖项目审计结果、报告、操作说明、产品资料和非规范性实践 |
| references/ | 外部资料目录 | 第三方文档、外部案例、外部方法资料和参考材料 |
| ldvh-base/ | 结构化对象实例目录 | Task、ADR、Evidence、Change、Pitfall 等 Harness 生产对象实例 |
| web/ | Web Tools 实现目录 | LD Vibe Harness Web Tools 的前端、后端、页面和相关实现 |
| tools/ | 程序辅助工具目录 | 脚本、校验器、聚合器、受控写入工具和其他程序辅助工具 |

### 3.3 specs 目录

specs/ 承载 LD Vibe Harness 的规范体系和内部调研文档，包括：

1. 00 理念与纲要；
2. 01-07 基础规范；
3. 10-39 Harness 生产对象规范；
4. 40-69 Harness 行动模型规范；
5. 70-89 内部调研；
6. 90-99 保留扩展。

specs/ 的编号、文档类型、子文档、实践文档和引用纪律由 `specs/01-specs文档结构规范.md` 定义。

### 3.4 docs 目录

docs/ 承载管辖项目资料、管辖项目审计结果、报告、操作说明、产品资料和非规范性实践。

docs/ 面向人的阅读、确认、审查和操作需要，不用于承载 LD Vibe Harness 基础规范正文。

### 3.5 references 目录

references/ 承载外部资料、第三方文档、外部案例、外部方法资料和参考材料。

references/ 下的文档可使用两位数字前缀按新增顺序自然增长；该编号只用于排序和引用便利，不属于 specs 规范编号体系。

### 3.6 ldvh-base 目录

ldvh-base/ 承载结构化 Harness 生产对象实例，例如 Task、ADR、Evidence、Change、Pitfall 等。

ldvh-base/ 下各对象实例的目录结构、字段、状态和验收规则由 10-39 Harness 生产对象规范定义。

### 3.7 web 与 tools 目录

web/ 承载 LD Vibe Harness Web Tools 的实现。

tools/ 承载程序辅助工具、脚本、校验器、聚合器和受控写入工具。

Web Tools 和程序辅助工具的角色边界由后续 `specs/05-LDVH工具基础规范.md` 定义。

## 五、Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 新增、删除、重命名或改变本文定义的一级目录；
2. 改变一级目录的定位；
3. 将某类内容迁移到与本文目录规划不一致的位置；
4. 将目录用途说明扩展为事实源规则、对象规则或行动流程规则。

当 AI 识别到上述情况时，至少必须暂停当前变更动作，向人提醒该操作可能触发 Human Gate，并说明涉及的目录、影响范围和建议确认事项。

文件夹规划检查至少包括：

| 检查项 | 标准 |
|---|---|
| 目录存在性 | 一级目录规划清晰 |
| 内容归属 | 文件放置符合本文目录用途说明 |
| 边界不扩张 | 本文未替代事实源、对象或行动模型规则 |
| 引用一致性 | specs 文档结构和事实源规则指向对应权威规范 |

## 六、不进入本文的内容

以下内容不进入本文：

1. specs 文档编号体系、子文档、实践文档、引用纪律和写作骨架；
2. 最终事实源判断、事实源边界、结构化承载和工具输出回写规则；
3. Markdown、YAML、Python、JavaScript 等介质的详细使用规则；
4. 具体 Harness 生产对象的字段、状态机和准入条件；
5. AI 如何读取上下文、识别场景、进入 Skill、调度 Agent 或回写事实源；
6. Web Tools 和 Python 辅助程序的具体实现；
7. 管辖项目的具体业务资料正文；
8. 外部资料原文。
