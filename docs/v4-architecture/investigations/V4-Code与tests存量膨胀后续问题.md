# V4 Code 与 tests 存量膨胀后续问题

> 记录性质：本文只记录不阻塞当前主路线的低优先级后续问题，不是规则源、审计登记或当前实施计划。
> 最近核验日期：2026-07-16。

## 1. 当前结论

2026-07-16 对 `code/tests/` 完成一次存量最小化审核。审核基线为 62 个测试文件、17,227 行和 802 个收集用例；全量运行当时为 792 passed、10 个原生 Windows 用例按既有平台条件 skipped，耗时约 360 秒。数量本身不证明膨胀，判断依据是正式来源、检查范围、缺陷敏感性、独立失败价值和测试辅助设施是否成为第二套业务逻辑。

与 01、07 新边界直接冲突的高优先级问题已经在三层一致性收口增量中处理：

1. 删除 tests 内重新实现 Web capture canonicalization、再测试该测试侧算法的文件；生产实现的固定向量、非法输入、来源回指和事务边界测试继续保留；
2. 删除按规范中文原句切割、搜索并据此证明语义完整的断言；
3. 披露 `reason` 只按正式契约检查非空、层级和来源对应，不再固定当前实现文案；
4. 生产 Code、正式 Specs、Helper 字段和公开操作均未因测试收敛而改变。

收口后为 61 个测试文件、17,017 行和 797 个收集用例；全量结果为 787 passed、10 个原生 Windows 用例按既有条件 skipped，耗时 337.62 秒。减少的是五个无独立失败价值的测试侧自证用例及其文案绑定，没有按目录、行数或表面相似删除生产行为覆盖。因此，当前未处理项目只属于维护成本或运行成本优化，不构成规范、生产 Code 与 tests 三层不一致，也不阻塞 bootstrap/resume 和真实 dogfood。

| 范围 | 当前信号 | 暂不阻塞的理由 | 重新进入条件 |

打包生命周期的 wheel 与 sdist-derived wheel、Git/原子写/并发/路径安全、平台边界和公共响应契约虽然体量或耗时较高，但当前分别覆盖不同真实故障路径，不列为可删除冗余。

## 3. 后续处理边界

低优先级收敛按实际变更触发，不建立固定清理周期、状态机或中央登记，也不为了降低数字批量合并用例。每次只处理能够证明重复、过时、无缺陷敏感性或运行成本明显不成比例的最小范围；先保留来源定义的可观察边界，再减少重复断言或昂贵准备。

本文不改变 `V4-工作推进总纲.md` 的当前顺序。bootstrap/resume 和真实 dogfood 可以继续；后续使用证据如果表明某组 tests 妨碍反馈速度或频繁误伤，再把相应一行转成独立实施增量。
