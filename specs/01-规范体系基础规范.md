## 1. 本文解决的问题

本文解决一个问题：同一篇 Markdown 规范如何同时让 Human 可判断、AI 可行动、Code 可解析。

v3 不通过拆分多套事实源解决消费差异。v3 通过稳定结构解决：

| 消费方 | 从同一篇 Markdown 中读取 |
|---|---|
| Human | 目标、边界、风险、Gate、验收口径 |
| AI | 任务场景、读取对象、本地规则、停止条件、验证和回写要求 |
| Code | identity block、状态、父子关系、章节、表格、路径和 source refs |

## 2. Markdown 是唯一规范事实源

v3 spec 正文必须是 Markdown。普通 spec 不建立人工 YAML 孪生文件。

允许存在的机器内容只能是 Markdown 内部结构或 Code 输出：

| 内容 | 位置 | 地位 |
|---|---|---|
| identity block | Markdown fenced YAML | 正文的一部分 |
| 表格和列表 | Markdown 正文 | 正文的一部分 |
| source refs | Markdown 正文 | 正文的一部分 |
| Code 输出 | stdout、临时文件或测试输出 | 派生诊断，不是事实源 |

## 3. 正文稳定结构

每篇 v3 spec 至少保留以下稳定结构：

| 结构 | 作用 |
|---|---|
| H1 标题 | Human 和 Code 入口 |
| `v3_spec` identity block | 身份、状态、父子关系和消费类别 |
| 本文解决的问题 | 说明本 spec 减少哪类 AI 负担 |
| 上位依据 | 显式父规范和来源关系 |
| 本地规则 | 只写本 spec 的 delta、例外和更严格要求 |
| Human Gate / Stop Conditions | 本地暂停、分流和确认条件 |
| Code / 行动指南消费 | 可被 Code 解析并投影的结构 |
| 待补齐事项 | 生成 next queries 的未决内容 |

章节标题可以变化，但角色必须能从标题和上下文稳定识别。

## 4. 引用关系

引用关系必须显式写在 Markdown 中，不能靠 AI 猜测。

| 关系 | 推荐表达 |
|---|---|
| 父规范 | `parent_spec` 和上位依据 |
| 来源依据 | `basis` 和正文中的 source refs |
| 相关规范 | `related_specs` 或正文路径引用 |
| 附属材料 | 正文明确写“见附件/表/图” |
| 迁移证据 | `_migration/` 路径或 WorkCase / Spark 引用 |

Code 可以从这些引用生成关系、读取计划、影响判断和 next queries。

## 5. 附件边界

附件只是正文的附属内容，不是第二层正文。

只有以下内容可以进入附件：

1. 正文引用的表；
2. 正文引用的图；
3. 字段闭集或枚举；
4. 过长但纯数据化的矩阵；
5. 多篇正文复用且不承载规则解释的机器契约。

以下内容不得进入附件：

1. 上位原则；
2. 核心规则；
3. 行动流程；
4. Human Gate；
5. 事实源边界；
6. 大段解释；
7. 迁移过程和一次性审查。

能在正文稳定结构中表达的，不拆附件。能由 Code 从正文生成的，不手写附件。

## 6. 去冗余规则

去冗余不是把内容拆到附件，而是让重复内容回到合适位置。

| 重复内容 | 处理 |
|---|---|
| 上位通用规则 | 放父规范正文 |
| 子规范特有差异 | 留子规范正文 |
| 可机械检查内容 | 由 Code 诊断 |
| 读取路线、停止提醒、影响摘要 | 由行动指南生成 |
| 迁移扫描和过程证据 | 留在 `_migration/` |

不得删除本地 Human Gate、本地事实源边界、行动特有场景、验证要求和回写要求。

## 7. Code 消费边界

Code 只从 Markdown 稳定结构中解析：

1. identity block；
2. 标题和章节；
3. 表格；
4. 路径引用；
5. 状态和权威字段；
6. 父子关系和 basis；
7. source refs；
8. 明确的 Stop Conditions。

Code 不从散文中猜测未声明关系，不把诊断输出写成事实源，不输出授权语义。

## 8. 行动指南输入责任

行动指南应由 Code 从 Markdown 生成，不手写成规范正文或附件。

Markdown 应提供足够结构，让 Code 生成：

| 行动指南要素 | Markdown 来源 |
|---|---|
| relationships | `parent_spec`、`basis`、`related_specs`、路径引用 |
| read_plan | 上位依据、本地规则、显式引用 |
| impact_judgment | 构成要素、消费类别、相关规范 |
| stop_conditions | Human Gate、Stop Conditions、禁止项 |
| next_queries | 待补齐事项、缺失引用、未确认迁移项 |
| verification | Code 消费类别、测试或等价验证说明 |
| source_refs | canonical path、父规范、来源文件 |

## 9. Stop Conditions

AI 必须暂停：

1. 准备把正文级规则拆到附件；
2. 准备为 Human、AI、Code 建立并列事实源；
3. 准备用 YAML 孪生文件替代 Markdown 正文；
4. 准备手写可由 Code 生成的目录、图谱或检查清单；
5. 准备删除本地 Human Gate、事实源边界或行动特有 delta；
6. 准备顺手修改 Runtime、hook、dispatcher、rules、skills 或 Web。

## 10. 下一步读取

AI 读完本文后：

1. 要写 v3 规范，先保持单一 Markdown 事实源；
2. 要设计附件，先确认它只是正文引用的附属表、图、字段闭集或枚举；
3. 要设计 Code，先从 Markdown 稳定结构解析，不另建事实源；
4. 要设计行动指南，先从 Markdown 引用关系生成，不手写导航内容。
