# 个人落地特别要求规范

> 创建日期：2026-06-08
> 定位：登记当前个人或维护者环境中不应提升为 LDVH 通用规则、但会影响当前执行和验证的落地特别要求
> 适用范围：LDVH 自身项目当前执行环境、当前个人命令约定、Human 明确授权的临时执行场景
> 上位依据：`docs/specs/04-规范落地与环境适配基础规范.md`
> 相关规范：`docs/specs/00-LD-Vibe-Harness理念与纲要.md`、`docs/specs/02-术语规范.md`、`docs/specs/04.02-环境适配与运行投影规范.md`、`docs/specs/04.04-LDVH落地特别要求规范.md`、`docs/specs/07-Code实现规范.md`

---
## 1. 本文解决的问题

本文解决个人或当前维护者环境中的特殊约定如何登记和限制的问题。

个人落地特别要求不属于 LDVH 通用规范，也不自动进入所有管辖项目。它只用于让 AI 在当前个人执行环境中避免误用命令、路径或平台约定。若某项个人环境约定需要影响特定项目，必须由项目自身 README、依赖管理说明或 Human 明确指令确认。

---
## 2. 与 00 总纲的关系

00 要求 LDVH 的稳定规则进入 Git 文件事实源，并围绕验证纪律和 Human Gate 运行。本文承认当前环境会影响 AI 执行命令和验证方式，但不允许个人环境约定反向改写 LDVH 通用规则。

当个人环境约定与项目自身约定冲突时，以项目自身 README、依赖管理说明、项目事实源和 Human 明确说明为准。本文不得替代项目依赖管理、平台官方文档或 Code 测试验证。

---
## 3. 术语应用关系

本文使用的个人落地特别要求、环境适配映射、运行投影、Code、命令入口等术语，按 `docs/specs/02-术语规范.md` 定义。以下小节只说明这些术语在个人环境登记中的应用关系，不另行维护术语权威定义。

个人落地特别要求应同时满足：

1. 只影响当前个人、维护者或当前执行环境；
2. 不应提升为 LDVH 通用跨环境规则；
3. 需要 AI 在当前执行中持续注意；
4. 可以通过命令入口、Code 使用说明、42/43 流程输出或人工提醒承接。

## 4. 当前个人落地特别要求

| 编号 | 要求 | 内容 | 适用范围 | 默认效力 | 承接位置 | 风险控制 | 退出条件 |
|---|---|---|---|---|---|---|---|
| PE-01 | Python 解释器命令要求 | AI 执行 Python 工具或脚本时应使用 `python3` 命令，不用 `python` 指代 Python 3；仅限执行场景，不要求文档或规范正文中使用 `python3` 字面量 | 当前个人执行环境 | 启用 | 命令入口、42/43 流程输出、环境适配映射 | 不替代依赖管理、虚拟环境说明或测试验证；解释器变更需由现场检查或流程输出说明 | 若当前环境稳定采用其他解释器入口，应更新本文或对应 Code 使用说明 |

## 5. 启用与使用规则

PE-01 默认启用。AI 在执行 Python 辅助程序、校验脚本或测试命令时，应使用 `python3`。

PE-01 仅限执行场景：AI 在终端、命令入口或 Code 中调用 Python 时应遵守；文档、规范正文、注释或说明文字中不要求使用 `python3` 字面量。

若当前项目 README、依赖管理说明或 Human 明确约定使用其他解释器入口（如虚拟环境、`python` 别名、`uv`、`poetry`、`pipenv`），应优先遵守项目约定，并在必要时记录降级方式。

## 6. 规范落地要求

本文通过以下规范落地要求说明相关要求的同步、检查或审计触发条件。

| 落地要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 入口可见要求 | AI 执行 Python 工具或脚本时应能定位 PE-01 | 04 系列父规范、命令入口摘要、42/43 流程输出或人工提醒 | AI 执行入口提示 | 本文标题、定位、当前登记表或 PE-01 内容变化时 |
| 确定性执行要求 | 当前环境中的 Python 命令调用应可通过实际命令、测试或等价验证确认 | `python3 --version`、工具 `--help`、测试命令或等价验证 | 命令验证 | Python 工具入口、测试命令、依赖管理方式或执行环境变化时 |
| 生命周期触发要求 | 当前环境命令约定变化后，应检查本文、命令入口、42/43 流程输出或人工提醒是否需要同步 | 现场检查、命令入口检查、人工降级检查 | 触发保障 | 解释器入口、虚拟环境、依赖管理或运行平台变化时 |

## 7. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 将 PE-01 提升为 LDVH 通用跨环境要求；
2. 改变 PE-01 的默认效力或适用范围；
3. 允许个人环境约定覆盖项目自己的依赖管理或命令约定；
4. 删除本文中仍被命令入口、42/43 流程输出或人工提醒消费的要求。

个人落地特别要求检查至少包括：

| 检查项 | 标准 |
|---|---|
| 适用范围 | 已明确为当前个人执行环境，不区分项目类型 |
| 默认效力 | 已明确启用 |
| 项目优先 | 项目 README、依赖管理说明和 Human 指令优先于本文 |
| 命令验证 | 当前环境执行前有命令验证或等价验证方式 |
| 非通用化 | 个人环境约定未被写成 LDVH 通用跨环境规则 |
