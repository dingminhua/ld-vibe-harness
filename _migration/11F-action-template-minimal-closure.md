# 11F 行动模板最小闭环记录

阶段：11F

目的：回应“行动模板没有建立”的问题，同时避免在 Hook、Confirm UI 和写入闭环不足时过早迁入完整 WorkCase 行动模板。

## 当前正式模板

`specs/06-行动模板基础规范.md` 中的 Git 提交行动模板继续作为当前唯一正式可消费模板示范。

它具备：

1. Context；
2. Scenario；
3. Gate；
4. 执行；
5. 验证；
6. 回写；
7. 交还。

## WorkCase 候选处理

WorkCase 创建、方案审核、执行推进、结果复核和关闭确认继续作为后置候选，不在阶段 11 升级为正式行动模板。

原因：

1. 当前没有完整 Confirm UI；
2. 当前没有通用 Web 写入；
3. 当前没有 pre tool use / completion claim 自动 Hook；
4. WorkCase Human Gate 必须明确记录，不应由 AI 在模板中默认完成；
5. 事实对象状态机已存在，但如何推进状态仍需入口和验证闭环支撑。

## 最小迁移结论

阶段 11 的最小闭环是：保留 Git 提交模板正式地位，确认非提交 WorkCase 模板后置，并把后置进入条件回指到 01、06 和 21。

这不是放弃行动模板，而是防止在入口能力不足时把候选模板写成已启用流程。
