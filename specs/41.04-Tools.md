## 一、本文定位

Tools 辅助层为多角色思考提供**确定性校验能力**——读取、解析、校验报告结构、生成 Context 包、检查回写候选。它不做分析判断，只确保分析过程和结果满足规范要求。

---

## 二、Tools 在分析中的职责

| 职责 | 说明 |
|---|---|
| 读取 | 读取 41 主文件、41.01-41.05、用户指定的事实源 |
| Context 包生成 | 生成多角色思考 Context 包 |
| 报告结构校验 | 检查报告是否包含必要章节 |
| 角色字段校验 | 检查每个角色字段是否完整 |
| Agent 前提校验 | 检查 Agent 增强模式是否声明前提 |
| 回写候选检查 | 检查回写目标是否明确、是否触发门禁 |

**Tools 不得：** 自行决定角色结论、调用 AI/Skill/Agent、自动将报告写入稳定事实源、绕过门禁写入 specs/Rules/Skill/Agent、在校验失败时自动覆盖原始文件。

## 三、Context 包结构

```yaml
topic: "分析主题"
trigger: "触发原因"
mode_candidate: "light | skill | agent"
source_files: ["输入事实源列表"]
rules: "适用规范规则来源"
action_model: "41主文件和模型实践子文档来源"
agent_prerequisite: "Agent前提状态"
role_candidates: ["候选角色列表"]
gate_candidates: ["可能触发的Gate"]
writeback_candidates: ["可能回写的目标事实源"]
```

Context 包是派生数据，不是最终事实源。

## 四、Tools 校验清单

### 报告结构校验

报告必须包含：适用性判断、分析模式、Agent 前提、变更概述、各角色分析、一致与分歧、风险汇总、建议执行顺序、事实源回写建议、Human Gate 判断。

**校验失败时只报告缺失项，不自动修改报告。**

### 角色字段校验

每个角色分析至少应包含：角色名、适用性、影响范围、分析结论、风险等级、建议动作。

角色数超过 8 个时，可提示需要精简或合并，**但不得自行删除角色**。

### Agent 前提校验

报告声明使用 Agent 增强模式时，必须检查是否声明：

1. 相关 Trae 预制 Agent 已安装或可调用
2. 参与 Agent 类型列表
3. Agent 输入来源和输出返回主控汇总
4. Agent 输出不是最终事实源
5. 未满足前提时的降级方式

**未声明前提的报告不得通过 Agent 增强模式校验。**

### 回写候选检查

回写候选必须满足：回写类型明确、目标事实源明确、是否触发门禁已说明、是否需要 Change 记录已说明、过程分析未被标记为稳定事实。

## 五、门禁

Tools 准备写入或覆盖 Git 文件事实源、将过程分析升级为 ADR/规范/长期行动边界、发现 Skill 调度 Agent、发现输出将缓存/派生数据当作事实源时，必须提示 Human Gate。
