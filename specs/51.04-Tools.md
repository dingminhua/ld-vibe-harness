## 1. 本文定位

本文是 `specs/51-multi-role-thinking-多角色思考.md` 的附件型实践子文档（编号 51.04），承接 Tools 辅助实践。本文不是独立行动模型，不得重新定义多角色思考的行动定位、准入条件、Context、Scenario、Gate、执行流程、事实源回写、证据留存或 Human Gate。发生冲突时，以 51 主文档和上位基础规范为准。

---

## 2. 不创建 Tools 辅助的理由

多角色思考不需要创建专用 Tools 辅助，理由如下：

1. **核心能力是 AI 分析**：多角色思考的核心是角色视角选择、分角色分析、分歧汇总、风险判断、回写建议和 Human Gate 识别，这些属于 AI 主控和可调用 Agent 容器的分析职责，不适合交给确定性工具决定；
2. **输出在对话中同步即可**：多角色思考的角色结论、分歧点、风险汇总、回写建议和 Human Gate 待确认项，均可由主控在对话中直接同步，不需要专用工具生成或校验独立产物；
3. **外部行动模型负责自身格式**：当多角色思考被审计、Review、Task、ADR、Risk、Evidence、docs 报告等外部行动或事实模型消费时，最终输出格式应由对应行动模型或事实模型定义，多角色思考不创建专用工具去维护报告格式；
4. **两种模式均不依赖 Tools**：主上下文轻量模式由 AI 在主上下文中分析并汇总；多角色子 Agent 模式由主控注入角色参数并汇总子 Agent 输出，两种模式均不依赖 LDVH 专用 Tools 辅助；
5. **避免体系膨胀**：为多角色思考创建专用 Tools 会增加工具、契约校验和维护成本，但不提升多角色思考的可控性，违反价值与要素审查原则。

---

## 3. 边界说明

1. 本文不否认通用工具可用于搜索、读取、编辑、检查 Markdown 或执行命令；这些属于运行环境或通用工具能力，不构成多角色思考专用 Tools 辅助；
2. 多角色思考不得通过 Tools、MCP 或脚本直接触发、编排或启动多角色子 Agent 流程；子 Agent 模式只能由主控依据 51 主文档和 51.06 契约执行；
3. Tools 输出、工具缓存、派生视图或命令结果不得作为多角色思考的稳定事实源；
4. 如未来确需为多角色思考创建专用 Tools，应重新评估价值、事实源边界、行动模型关系和 Human Gate。

---

## 4. 检查项

检查 Tools 不创建决策是否合规时，应确认：

1. 多角色思考的角色选择、角色分析、分歧汇总、风险判断和 Human Gate 是否由 AI 主控负责，而非工具决定；
2. 主上下文轻量模式和多角色子 Agent 模式是否均不依赖专用 Tools 辅助；
3. 外部行动模型或事实模型是否负责自身最终输出格式，未由多角色思考 Tools 维护报告格式；
4. 是否未创建多角色思考专用 Tools、脚本、MCP Server 或工具校验 schema；
5. 如使用通用工具辅助读取、搜索或编辑，是否未将工具输出、缓存或派生视图当作稳定事实源。
