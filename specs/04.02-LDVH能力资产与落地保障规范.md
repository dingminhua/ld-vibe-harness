## 1. 本文解决的问题

04.01 说明正式规范提出了什么落地要求；本文说明 LDVH 用哪些能力资产和能力组合保障这些要求落地。

本文解决：

1. LDVH 有哪些能力资产；
2. 固定能力资产如何登记、审查、维护和同步；
3. 落地要求默认映射到哪些能力资产或能力组合；
4. 各能力资产的职责和边界；
5. 能力缺口和环境接入缺口如何分流；
6. 哪些能力边界变化必须 Human Gate。

Codex App 如何通过用户手动薄入口接入、检查和降级这些能力资产由 04.03 定义；非 Codex 环境只按 04.03 的自助适配方向处理。

## 2. LDVH 能力资产

LDVH 能力资产是 LDVH 自己定义和维护、用于保障规范落地的能力内容。能力资产不是环境入口，不表示用户本地已经部署、启用或验证。

固定能力资产是已登记、可定位、可审查、可验证、可同步维护的 LDVH 能力资产。一项 Rules、Skill、Agent 或 Hook 只有完成本文 §2.1 的登记要求后，才能被写成当前固定资产；未登记的内容只能作为候选资产、临时过程输出、人工降级步骤或环境适配候选，不得被 Code、Web、Rules 或工作流程当成稳定保障机制。

| 能力资产类型 | 当前固定资产 | 适合保障 | 不适合保障 | 边界 |
|---|---|---|---|---|
| Rules 资产 | `../rules/LDVH-WORKSPACE-ENTRY.md`、`../rules/LDVH-MAINTAINER-ENTRY.md` | AI 可见、硬约束摘要、事实源边界、STOP 点、最小读取顺序、入口分层路由 | 完整规范正文、长期状态、用户本地安装状态、工作对象事实本体 | 工作区入口处理管辖治理和 `ldvh-base/` 工作对象；维护入口处理 LDVH 产品资产；都不是事实源 |
| Code 能力资产 | `../code/`、测试目录、CI 或命令验证 | 解析、校验、聚合、受控写入前检查、漂移检查 | Human 授权、价值判断、复杂语义结论 | 按 07 Code 规范实现 |
| Web 能力资产 | `../web/`、Human Gate 流程 | Human-facing 态势、确认、授权、验收、派生展示 | 第二事实源、绕过 Code 校验的后台 | 按 08 Web 规范实现 |

Command、CLI、CI、MCP 和文档可以支撑能力保障、适配措施或检查执行，但不得被写成与 Rules、Skill、Agent、Hook 同级的 LDVH 文本能力资产类型。

### 2.1 固定能力资产登记

固定能力资产不得靠目录存在或对话结论自动成立。新增或升级固定 Rules、Skill、Agent、Hook 资产前，必须满足以下登记要求：

1. **来源规范**：能回指一个或多个 specs 正式规范中的落地要求、工作流程或能力边界；不得由临时对话、docs/studies、外部资料或工具输出直接升级为固定资产；
2. **权威路径**：资产文件位于 `rules/`、`skills/`、`agents/` 或 `hooks/` 对应目录，具备稳定文件名和稳定 ID；
3. **资产元信息**：资产文件应使用 `ldvh_asset` 元信息声明资产 ID、资产类型、状态、权威路径、来源规范、消费场景、输入输出、交还对象、验证方式、同步触发条件和废弃方式；
4. **边界说明**：资产正文必须说明它不替代 specs、Git 文件事实源、Code 校验、Human Gate、工作对象状态或 Web 派生视图；
5. **质量审查**：新增 active 资产前应经过 Human、Code、Web、AI 执行和行业实践角度的审查，至少确认不复制完整规范正文、不新增稳定规则、不制造第二事实源、不绕过主控或 Human Gate；
6. **同步责任**：来源规范、消费场景、输入输出、验证命令、入口路径、相关 Code/Web 行为或部署方式变化后，必须检查该资产是否需要同步；
7. **验证入口**：能由 Code 检查、命令检查、人工降级检查或对应工作流程确认资产存在、元信息完整、引用未漂移和边界未越权。

资产登记事实应优先由资产文件自身的元信息承载，Code 可以据此派生资产索引、Web 可以只读展示资产状态和缺口。04.02 不应长期手写维护所有资产实例清单；本文只定义登记规则、固定资产准入标准和当前必须存在的固定资产类型。若 Code 尚不能解析资产元信息，应按人工降级检查执行，并把 Code 缺口分流为 WorkPlan、Memo 或 Code 需求。

### 2.2 资产类型最佳实践标准

Rules、Skill、Agent 和 Hook 属于可由 AI 生成、Human 审查、Code/Web 辅助消费的文本能力资产。固定文本能力资产不仅要有文件格式，还必须满足最佳实践级别的生成和审查标准：

1. **薄引用优先**：资产正文应引用来源 specs、工作流程或工作对象，不复制完整规范正文、字段契约、状态机或长规则清单；
2. **执行转换清晰**：资产可以把正式规范转化为 AI 可执行步骤、检查顺序、STOP 点、输入输出和交还方式，但不得新增稳定规则；
3. **输入输出明确**：资产必须说明读取哪些事实源、接收哪些输入、产出什么结果、结果写回哪里，以及哪些情况必须交还主控或 Human Gate；
4. **失败和降级可见**：资产必须说明工具不可用、环境不支持、权限不足、引用缺失或校验失败时的降级方式，不得把沉默失败当作通过；
5. **多视角审查**：新增 active 资产前，应至少从 Human 可理解性、Code 可检查性、Web 可展示性、AI 执行稳定性和行业实践一致性审查；
6. **事实源不分叉**：资产不得把 specs 规则、工作对象状态、部署状态或环境检查结果复制成第二事实源；需要长期保留的事实必须回写到 specs、工作对象、Git 提交记录或对应权威位置；
7. **环境中立**：资产维护在 LDVH 仓库权威路径中，不默认等同于 Codex、Trae、Claude 或其它环境中的已安装文件；环境接入由 04.03 承接；
8. **可测试或可审计**：不能被 Code 机械验证的部分，应说明人工检查入口、审查清单或后续 WorkPlan/Memo 分流方式。

不同资产类型的补充标准如下：

| 资产类型 | 必须强化的最佳实践 | 禁止事项 |
|---|---|---|
| Rules | 入口路由、STOP 点、最小读取顺序、事实源边界和交还规则 | 复制完整 specs、维护长期状态、替代工作对象事实源 |
| Skill | 可复用执行流程、标准输入输出、失败处理、验证入口和主控交还 | 新增规范规则、默认调度 Agent、绕过 Human Gate 或 Code 校验 |
| Agent | 角色边界、输入上下文、输出格式、权限限制、主控复核和证据回写 | 让子 Agent 输出直接生效、继续无限分派子 Agent、拥有独立事实源状态 |
| Hook | 触发事件、调用命令、失败等级、输出去向、降级方式和误触发处理 | 把 Hook 触发当成检查通过、替代 Code 校验、替代 Human 授权或长期记忆 |

### 2.3 同步监督与漂移处理

固定能力资产一旦登记为 active，就必须随来源规范、消费场景和实现边界同步维护。同步监督遵守以下规则：

1. 来源 specs 的落地要求、字段契约、状态机、工作流程、目录边界或 Human Gate 条件变化时，应检查所有声明消费该来源的固定能力资产；
2. 资产的 `sync_triggers` 应覆盖来源规范变化、入口路径变化、Code/Web 行为变化、部署方式变化和废弃路径变化；
3. Code 能解析 `ldvh_asset` 时，应由 Code 派生资产索引、引用有效性、元信息完整性和漂移诊断；Code 尚不能覆盖时，执行人工降级检查并记录缺口；
4. Web 只能只读展示资产登记状态、来源规范、验证入口和缺口，不得维护手写资产总清单；
5. 发现资产正文与 specs、Code 校验、Web 展示或工作对象事实源冲突时，以 specs 和对应事实源为准，资产应暂停作为稳定保障并分流修复；
6. 新增、废弃、重命名或移动固定能力资产时，应同步检查 01 目录定位、04.03 环境接入边界、Rules 入口、Code 检查、Web 展示和相关 WorkPlan/Memo；
7. 高频重复的人工同步检查应优先沉淀为 Code 诊断、测试、工作流程或已登记 Skill，但沉淀前不得假定自动化已经存在。

### 2.4 权威资产与部署副本分层

LDVH 仓库内的 `rules/`、`skills/`、`agents/` 和 `hooks/` 承载权威能力资产；运行环境中的同名文件、配置片段、薄入口、软链、安装副本或 Hook 配置属于部署或适配层，不自动成为新的权威资产。

分层规则如下：

1. 权威资产以 LDVH 仓库中的登记文件为准，环境内复制件不得长期独立演化；
2. 环境入口应优先使用薄引用、软链、安装脚本或可复查配置指向权威资产；
3. 若环境必须复制资产正文，应记录复制原因、来源版本、更新方式、退出方式和漂移检查方法，并按 04.03 评估 Human Gate；
4. 环境接入结果只说明当前现场观察，不得写成“该环境天然完整支持 LDVH”；
5. 部署副本发现问题时，应先判断是权威资产问题、环境适配问题还是本地配置问题，再分别分流到 specs/能力资产、04.03 或当前环境处理；
6. 安装脚本、Hook 示例、环境配置模板和用户本地入口都不得反向改变权威资产字段契约或来源规范。

## 3. 要求到能力资产的默认映射

| 规范落地要求 | 默认能力资产或能力组合 | 常见补充 |
|---|---|---|
| 上位约束承接要求 | Rules 资产、规范引用、索引、Code 引用检查 | Human Gate、ADR、WorkPlan |
| 入口可见要求 | Rules 资产、AI 可见摘要、薄引用 | Web 展示、Command 提示 |
| 流程复用要求 | 工作流程、Command 包装、人工降级检查 | 已登记 Skill、Code wrapper、Web 表单、WorkPlan 模板 |
| 子 Agent 思考要求 | 主控多视角审阅、环境 Agent 能力或人工降级审查 | 已登记 Agent、Human Gate、审阅清单 |
| 确定性执行要求 | Code、测试、CI、命令验证 | Web 展示、Command 包装 |
| Human 交互要求 | Human Gate、Web、结构化问询、对话确认 | diff、预览、风险说明 |
| 生命周期触发要求 | CI、命令检查、入口 STOP 点、人工降级检查 | 已登记 Hook、已登记 Skill 提醒 |

默认映射只是落地保障起点。Codex App 如何接入这些能力资产，由 04.03 根据环境入口定义候选薄入口、手动接入和适配检查方式；非 Codex 环境不得被写成 LDVH 官方完整适配目标。

## 4. 能力资产边界

### 4.1 Rules 资产

Rules 资产允许承载入口摘要、事实源边界、STOP 点、权威引用和场景路由。Rules 资产不得复制完整 specs 正文、字段契约全文、状态机正文、长期过程状态或 Agent 结论。

LDVH Rules 入口采用双入口模型：

| Rules 入口 | 职责 | 边界 |
|---|---|---|
| `../rules/LDVH-WORKSPACE-ENTRY.md` | 工作区级入口、管辖项目识别、管辖项目 `ldvh-base/` 工作对象和 LDVH dogfood 管辖判断 | 不维护 LDVH 产品资产，不默认接管用户项目 docs |
| `../rules/LDVH-MAINTAINER-ENTRY.md` | LDVH 源码仓库项目级入口，维护 `specs/`、`rules/`、`skills/`、`agents/`、`hooks/`、`code/`、`tests/`、`web/` 等产品资产 | 不直接处理管辖项目工作对象，不把 LDVH 自身 dogfood 状态解释为安装用户默认管辖项目 |

`ldvh-base/` 始终是被管辖项目的工作对象事实源，归工作区级入口处理。即使 `ldvh-base/` 位于 LDVH 源码仓库内，也只有在工作区根目录 `LDVH-GOVERNED-PROJECTS.yaml` 把 LDVH 登记为 dogfood 管辖项目时，才按管辖项目工作对象处理。

### 4.2 Skill 资产

Skill 资产可以成为固定能力资产，但必须先完成 §2.1 的登记要求。当前仓库尚无已登记 active Skill 资产；后续只有当具体工作流程或正式规范要求已经稳定、存在明确消费场景、输入输出、失败处理和交还规则时，才应设计配套 Skill。

Skill 资产允许承载可复用流程、标准化输入输出、检查步骤、失败处理、STOP 点和交还方式。Skill 资产不得新增稳定规则、字段、状态、Human Gate 条件或默认调度 Agent。

LDVH 自建 Skill 的稳定标识应使用 `ldvh-` 前缀，前缀后使用小写字母、数字和连字符，不绑定具体业务项目名、个人名、环境名或临时阶段名。

### 4.3 Agent 资产

Agent 资产可以成为固定能力资产，但必须先完成 §2.1 的登记要求。当前仓库尚无已登记 active Agent 资产。环境或主控 AI 使用 Agent 能力时，可以承接独立上下文分析、专项审查、并行视角、复杂争议和权限边界差异判断。Agent 输出不得直接生效，必须回到主控或 Human，经必要验证和回写后才成为稳定事实。

### 4.4 Hook 资产

Hook 资产可以成为固定能力资产，但必须先完成 §2.1 的登记要求。当前仓库尚无已登记 active Hook 资产。Git `commit-msg` hook、Codex Hook 或其它环境 Hook 的语义必须分层处理：Git hook 属于仓库提交门禁资产，环境 lifecycle hook 属于 04.03 的环境入口适配对象。环境 Hook 必须在具体环境中实测、经 Human Gate 确认并与真实工作流程绑定后，才能形成配套适配措施。

Hook 资产允许承载生命周期检查入口、提交前后检查提示、工具调用前后检查提示、会话停止检查提示和降级提示。Hook 触发不等于检查通过，Hook 输出必须受 Code、Human Gate、事实源边界和降级记录约束。

## 5. 能力提供原则

1. 要求先行：先读取 04.01 或正式规范中的落地要求，再选择能力资产；
2. 组合优先：重要要求通常需要 Rules、Code、Human Gate、工作流程、CI、命令检查或人工降级组合保障；Skill、Agent、Hook 只有完成登记、审查和验证边界后，才能作为固定能力资产参与；
3. 资产清晰：能力资产由 LDVH 维护，不与环境入口混同；
4. 薄接入优先：能力资产进入环境入口时应优先薄引用、配置、安装或软链；
5. 确定性外移：能机械判断的规则应优先进入 Code、测试或 CI；
6. 授权前置：高影响写入、长期配置、权限扩大和完整支持声明必须 Human Gate；
7. 证据回写：过程输出中的稳定事实必须分流回 Git 文件事实源。

## 6. 缺口分流

| 缺口类型 | 含义 | 分流位置 |
|---|---|---|
| 能力资产缺口 | LDVH 缺少保障该要求的能力资产或能力组合 | WorkPlan、ADR、Memo、Code/Web 需求、正式规范 |
| 环境入口接入缺口 | Codex 环境不能接入现有 LDVH 能力资产，或非 Codex 环境需要自助适配方向 | 04.03 环境入口适配与部署规范 |
| 个人环境约束 | 当前用户或维护者环境限制部署、检查或命令执行 | 04.03 环境入口适配与部署规范 |
| 适配检查失败 | 当前部署或接入未通过现场检查 | Code 输出、Human Gate、WorkPlan、Memo、Pitfall |

不得通过删除正式规范中的落地要求、把弱环境限制写成 LDVH 全局限制、把人工降级写成完整支持、或把工具输出写成事实源来解决缺口。

## 7. 规范落地要求

| 落地要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 上位约束承接要求 | LDVH 能力资产与落地保障应承接 04.01 的落地要求声明 | 本文、04.01、Human Gate | 能力治理 | 能力资产、能力边界或默认映射变化时 |
| 入口可见要求 | AI 判断落地保障时应能定位本文、固定能力资产登记规则和对应 Rules 入口分层 | Rules 资产、04 父规范、人工降级检查 | AI 执行入口提示 | 本文文件名、标题、能力资产表、登记规则或入口分层变化时 |
| 流程复用要求 | 能力资产维护、登记审查和缺口分流应形成可复用流程 | Skill、Command、人工检查 | 流程复用 | 新增能力资产、登记固定资产或处理能力缺口时 |
| 确定性执行要求 | Code 应能检查能力资产存在、元信息、边界和引用关系 | Code、测试样例 | 校验实现 | 能力资产字段、登记规则或固定资产路径稳定后 |
| Human 交互要求 | 新增稳定能力资产、登记固定资产、改变能力边界或声明完整支持前应暂停确认 | Human Gate、Web、对话确认 | 能力治理确认 | 高影响能力建设、固定资产登记或边界变化时 |

## 8. Human Gate 与检查要求

以下情况必须评估 Human Gate：

1. 新增、删除或改变 LDVH 能力资产类型；
2. 登记、废弃、删除、重命名或移动固定能力资产；
3. 改变 Rules、Skill、Agent、Hook、Code、Web、Command 或 Human Gate 的能力边界；
4. 允许能力资产直接成为最终事实源；
5. 允许 Skill 新增稳定规则、字段、状态或 Human Gate 条件；
6. 允许 Agent 输出直接生效；
7. 声明 Hook 或人工降级具有原生完整支持；
8. 将工作区级入口和 LDVH 项目级维护入口重新合并为单一入口。

能力资产检查至少包括：

| 检查项 | 标准 |
|---|---|
| 要求来源 | 能力保障来自正式规范落地要求 |
| 资产登记 | 固定能力资产具备 ID、类型、状态、路径、来源规范、消费场景、输入输出、验证方式和同步触发条件 |
| 资产存在 | 当前固定能力资产路径存在且职责明确；未登记资产未被写成 active 保障机制 |
| 资产边界 | Rules、Skill、Agent、Hook 未互相替代或越权 |
| 入口分层 | 工作区入口和维护入口职责清晰；`ldvh-base/` 工作对象未被项目级维护入口直接接管 |
| 非事实源 | 能力资产未替代 specs、事实源、Code 校验或 Human Gate |
| 环境分流 | Codex 接入、手动薄入口、适配检查和非 Codex 自助适配方向由 04.03 承接 |
