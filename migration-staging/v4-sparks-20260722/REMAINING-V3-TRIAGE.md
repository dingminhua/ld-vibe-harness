## `0026` 当前来源命名审计

本节只记录当前来源中的词义分流，不改变任何 Specs、Code、Web 或事实对象，也不把 V3 的逐项结论视为当前规则。

| 当前位置 | 实际语义 | 审计结论 |
|---|---|---|
| 01、03、05、07、08、21、字段登记和测试中的“不得降级为” | 禁止把不可验证、失败、严格 profile 或确定结论弱化成 warning、相似匹配、空路径、旧 profile 或成功声明 | 不是“降级方案”；这是精确的禁止性动词，应保留，不纳入命名清理。 |
| 06 §8.1 的“降级到普通求解” | 缺少模板输入时退出模板分支，回到不受模板许可白名单约束的普通求解或交还 | 不是可执行的弱替代路径；候选改为“转回普通求解或交还”，但应先检查 06 与全部模板的一致用语。 |
| 09、33 中 no-op、拒绝、部分、失败、未验证、能力差异与“降级路径”并列 | 环境事件/输入/映射不足时的多种不同结果 | 当前混用最明显。应先定义何时才允许称为“受限替代”：必须有来源支持、保持的能力范围、失去的范围和可回查结果；否则分别使用 no-op、拒绝、部分、未验证、能力缺口或交还。 |
| Helper 事实写入的 Windows `file-only` 耐久“降级” | 已知较弱的耐久/并发保障替代，且当前操作明确要求 Human 决定是否接受 | 是潜在真实弱替代，不能机械改成“能力缺口”；需要单独明确所保持与失去的保障、适用平台和 Human Gate。 |
| Web 的 `degraded` 状态兼容 | 页面仍接受旧 backend 输入，但当前事实对象中没有 `status: degraded`，UI 已显示为“受限” | 只应作为迁移兼容层，不应重新成为事实类型状态或 Human 主状态。后续可在确认无生产输入后移除兼容分支。 |

**已创建的当前 Spark**

- `spark-0026`：`受限替代与能力缺口的语义边界`。
- 独立价值：收敛环境接入、受控写入和 Web compatibility 中仍混用的结果语义，避免把失败、未知或能力缺口表述为可接受的“降级”。
- 不处理：不批量替换普通中文动词；不改写 V3 历史；不把 `degraded` 重新加入事实对象状态；不决定 Windows `file-only` 耐久是否可接受。
- 后续进入逐处判断前：先形成 09、33、受控写入契约和 Web 兼容输入的当前目标快照；形成具体变更目标、范围和验收后，再分别取得相应授权。

## 新入口的门槛

新 Spark 必须确认：仍有当前问题、没有正确现有承接位置、存在可回指的当前来源、对象粒度单一，并能形成独立 `intent` 与当前摘要；不得仅凭 V3 文件、Git 历史或标题创建。`spark-0026` 已按此门槛创建；本审计材料不因此成为它的来源或第二权威。
