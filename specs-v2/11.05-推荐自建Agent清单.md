# 推荐自建 Agent 清单

> 创建日期：2026-05-28
> 最后更新：2026-05-28
> 定位：PM Kit 推荐自建 Agent 清单与不建议场景规范
> 上位依据：`specs-v2/11-AI协作规范.md` §七、`specs-v2/11.03-Agent设计规范.md`

---

## 一、评估依据

判断某个场景是否适合自建 Agent，应依据 11-AI协作规范 §七 的 Agent 创建或调用门槛。

若主上下文分析、多角色讨论或 Skill 能完成，应优先使用主上下文、11-AI协作规范 §八 定义的多角色讨论，或已有 Skill，不应升级为 Agent。

创建、启用、修改或删除 Agent 调度边界必须触发 Human Gate。Agent 只能由用户显式调用或 SOLO Agent 主控编排，不得自行触发，也不得由 Skill 调度。

---

## 二、总体判断

PM Kit 当前不适合大量预置自建 Agent，但适合建立少量治理、审计、工具、AI 协作和 WebTools 产品化方向的专用 Agent。

| 类型 | 推荐程度 | 原因 |
|---|------:|---|
| 规范治理 Agent | 强烈推荐 | PMKit specs 多、规则边界复杂，适合独立上下文审查 |
| 审计 Agent | 强烈推荐 | 审计需要读取大量事实源、分流发现、检查回链 |
| AI 协作资产 Agent | 推荐 | Rule / Skill / Agent / MCP 边界复杂，容易混淆 |
| PM WebTools 产品/UX Agent | 推荐 | PMKit 已有 WebTools 需求文档，需要产品化视角 |
| 工具/程序辅助 Agent | 推荐 | Python 校验、Context Pack、受控写入边界适合专岗 |
| 文档工程 Agent | 中度推荐 | 文档命名、引用、事实源归属维护成本高 |
| 通用代码开发 Agent | 不建议 PMKit 自建 | Trae 官方已有 Frontend / Backend / DevOps 等 Agent，可复用 |
| Task Review Agent | 谨慎，不默认配置 | PMKit 明确不要求配置任务检查 Agent |

## 三、推荐自建 Agent 清单

### 3.1 PMKit 规范治理审查员（P0，强烈推荐）

- 英文标识：`pmkit-governance-reviewer`
- 主要模式：默认只读分析
- 调度方式：用户显式调用或 SOLO Agent 主控编排
- 适用场景：修改 specs 管理对象和事实源治理规范；修改初始化和审计规范；修改 AI 协作、Rule、Skill、Agent、多角色讨论规范；修改 L0 / L1 / L2 规则模板；修改 Human Gate 规则；调整事实源归属规则；调整 docs 与 pm-kit-base 边界
- 核心职责：检查规范是否重复定义对象语义；检查事实源边界是否漂移；检查路径归属是否混淆 PMKit 项目与受管理项目；检查 Human Gate 是否被绕过；检查修改是否需要同步其他规范引用；输出是否可改、是否需 Human Gate、是否需 ADR 的结论
- 职责边界：不自行修改 specs、Rules、Skill 或 Agent；不替代用户决策；发现 Human Gate 场景时必须标注并停止写入建议

### 3.2 PMKit 审计员（P0，强烈推荐）

- 英文标识：`pmkit-auditor`
- 主要模式：只读审计，按授权输出分流建议
- 调度方式：用户显式调用或 SOLO Agent 主控编排
- 适用场景：对项目执行 PMKit 初始化后评估；对 PMKit 项目自身执行规范审计；对受管理项目执行技术审计或全量审计；将审计发现分流为 Task、待决策 Task 或 Memo
- 核心职责：执行规范审计、技术审计或全量审计；区分缺失、通过、不合规和不适用；判断审计发现归 Task、待决策 Task 或 Memo；检查审计发现回链闭环；标注 Human Gate 项；避免把审计变成自动修复
- 职责边界：不自动修复不合规内容；不替代 Human Gate；不作为 Task Review Needed 的默认强制 Agent

### 3.3 PMKit AI 协作架构师（P1，推荐）

- 英文标识：`pmkit-ai-collaboration-architect`
- 主要模式：只读架构审查
- 调度方式：用户显式调用或 SOLO Agent 主控编排
- 适用场景：设计或调整 Rule 分层；设计或调整 Skill；设计或调整 Agent 定义；评估 MCP 配置建议；调整 SOLO Agent 调度边界；判断多角色讨论是否应升级为 Agent
- 核心职责：检查 Rule / Skill / Agent / MCP 是否职责错位；检查是否违反 Skill 不得调度 Agent；检查是否把 MCP 输出当事实源；检查 Agent 是否满足创建门槛；检查 Agent Prompt 与定义摘要是否形成双事实源
- 职责边界：不直接创建或修改 Skill / Agent；不调度其他 Agent；不将社区实践直接升级为正式规范事实源

### 3.4 PMKit WebTools 产品审视员（P1，推荐）

- 英文标识：`pmkit-webtools-product-reviewer`
- 主要模式：产品、交互、治理边界审查
- 调度方式：用户显式调用或 SOLO Agent 主控编排
- 适用场景：设计 PM WebTools 页面；评估 WebTools 功能域边界；检查工具是否制造第二事实源；检查工具是否直接调用 AI、Skill 或 Agent；检查 Human Gate 在 UI 中的呈现
- 核心职责：评估页面设计是否符合 13-工具展示层；检查 UI 是否制造第二事实源；检查操作入口是否绕过 Human Gate；检查 Review Needed 子状态呈现是否正确
- 职责边界：不替代 UI Designer 或 Frontend Architect；不直接决定产品需求变更；不绕过需求文档与 Task 事实源

### 3.5 PMKit 工具链架构师（P1，推荐）

- 英文标识：`pmkit-tooling-architect`
- 主要模式：程序辅助与工具边界审查
- 调度方式：用户显式调用或 SOLO Agent 主控编排
- 适用场景：设计或实现 Python 校验器；设计 YAML schema 校验；设计 Context Pack 生成；设计 PM WebTools 后端 API
- 核心职责：检查程序设计是否违反事实源边界；检查 Context Pack 字段是否可追溯；检查写入前校验是否覆盖状态机、项目归属和 Human Gate；检查是否引入隐性数据库或缓存事实源
- 职责边界：不直接实现或修改业务事实；不让程序绕过对象状态机；不允许程序直接调用 AI、Skill 或 Agent

### 3.6 PMKit 文档工程师（P2，中度推荐）

- 英文标识：`pmkit-documentation-engineer`
- 主要模式：文档结构、引用和索引审查
- 调度方式：用户显式调用或 SOLO Agent 主控编排
- 适用场景：大规模重命名 docs 或 specs；拆分或合并规范文档；检查文档编号、引用路径、docs 与 specs 边界；检查 `project_rules.md` 必读索引是否同步
- 核心职责：检查文档命名是否符合规范；检查 specs 是否承载跨项目规范，docs 是否只承载 PMKit 项目事实；检查重命名后的引用完整性；检查新增 docs 文件后是否更新 L1 必读索引
- 职责边界：不直接变更规范正文；不替代治理审查；不把文档索引当作事实源正文

## 四、不建议自建 Agent 的场景

### 4.1 不建议为每个管理对象都创建 Agent

Task、Memo、ADR、Change、Pitfall 等对象的场景更适合 Skill 或程序校验，原因是流程稳定、上下文规模可控、通常不需要结论隔离，也不需要不同工具权限。

| 场景 | 推荐机制 |
|---|---|
| 将对话整理为 Task | Skill |
| 将对话写入 Memo | Skill |
| 校验 Task YAML 字段 | Python 程序 |
| 追加 Change 记录 | Skill 或受控写入程序 |
| 检查 ADR 字段 | Python 程序或主上下文审查 |

### 4.2 不建议默认配置 Task Review Agent

PM Kit 不要求配置任务检查 Agent。Task 进入 `Review Needed` 后，可以通过工具内置检查、SOLO 主流程检查或人类确认形成 `review` 结果。若项目自行创建 Review Agent，应定位为可选增强，不应成为任务关闭的强制流程，也不得替代 Human Gate。

### 4.3 不建议 PMKit 自建通用技术开发 Agent

PM Kit 不建议重复自建通用前端、后端、DevOps、API 测试、性能优化或 AI 集成 Agent。Trae 官方已经提供类似通用 Agent，可按需导入或由 SOLO Agent 主控编排。PM Kit 推荐自建的是懂 PM Kit 事实源、对象、治理边界和 Human Gate 的专用 Agent。

## 五、首批建设建议

三个 Agent 以内：

| 优先级 | Agent | 解决的问题 |
|---|---|---|
| P0 | PMKit 规范治理审查员 | specs / rules / facts 边界一致性 |
| P0 | PMKit 审计员 | 初始化、审计、发现分流、回链闭环 |
| P1 | PMKit 工具链架构师 | Python / Context Pack / WebTools 后端边界 |

五个 Agent 以内，再增加：

| 优先级 | Agent | 解决的问题 |
|---|---|---|
| P1 | PMKit AI 协作架构师 | Rule / Skill / Agent / MCP / SOLO 边界 |
| P1 | PMKit WebTools 产品审视员 | PM Web Tools 产品化、受控编辑、Human Gate UI |

后续增强：当 PMKit 频繁进行文档拆分、重命名、迁移或引用修复时，再增加 PMKit 文档工程师（P2）。

---

## 六、推荐调用方式

**用户显式调用**：用户可以通过 Trae 对话中的 `@Agent` 显式调用对应 Agent。

**SOLO Agent 主控编排**：复杂任务建议由 SOLO Agent 主控拆解并调用子 Agent。适合 SOLO 编排的场景包括：大规模规范重构；WebTools 新功能设计与实现；初始化或审计流程升级；Rule / Skill / Agent 体系升级；pm-kit-base schema 调整；Context Pack 设计。

---

## 七、落地约束

1. 本清单是推荐清单，不表示已创建任何 Trae Agent。
2. 创建、启用、删除或修改 Agent 调度边界必须触发 Human Gate。
3. Agent 定义摘要和 Trae 平台 Prompt 必须保持一致。
4. Agent 默认只读分析，除非主控明确授权写入。
5. Agent 不得自行触发，不得调度其他 Agent。
6. Skill 不得调度 Agent；Skill 只能建议用户调用 SOLO Agent。
7. PM Kit 不内置具体业务技术栈 Agent；业务项目如需专业技术 Agent，应在项目侧按需创建或导入。
8. PM WebTools 不直接调用 AI、Skill 或 Agent，只能提供结构化上下文、受控编辑入口、Human Gate 提示和可投递执行请求。

---

## 八、推荐自建 Agent 检查项

| 检查项 | 标准 |
|---|---|
| 创建门槛 | 已确认满足独立上下文、结论隔离、并行委派或工具权限差异之一 |
| Human Gate | 创建、启用、删除或修改 Agent 调度边界前已确认 |
| 职责边界 | Agent 只处理单一专业领域，不成为全能 Agent |
| 工具权限 | 仅配置完成职责所需的最小工具和 MCP |
| 事实源边界 | Agent 输出不是事实源，稳定事实必须回写 Git 文件事实源 |
| 调度边界 | 仅用户显式调用或 SOLO Agent 主控编排 |
| Skill 边界 | Skill 不直接调度 Agent |
| Prompt 一致 | Trae 平台 Prompt 与项目 Agent 定义摘要一致 |
| 安全 | 不暴露密钥、Token、内部敏感路径或生产权限 |
