---

## 三、未来 Web 展示能力定义

当项目具备 Web Tools 基础设施后，可考虑实现以下展示能力：

### 3.1 多角色报告展示

- 输入：MultiRoleReport 契约结构
- 展示：按角色分组显示适用性、影响范围、分析结论、风险和建议动作
- 用途：帮助人快速浏览各角色分析结果

### 3.2 分歧与一致展示

- 输入：MultiRoleReport 的 alignment 字段
- 展示：高亮一致结论和分歧点
- 用途：帮助人快速识别关键分歧

### 3.3 风险汇总展示

- 输入：MultiRoleReport 的 risk_summary 字段
- 展示：按高/中/低分级展示风险
- 用途：帮助人快速评估风险等级

### 3.4 Human Gate 待确认项展示

- 输入：MultiRoleReport 的 human_gate 字段
- 展示：列出需要人确认的事项和触发原因
- 用途：桥接 AI 分析结果和人类确认闭环

### 3.5 回写建议展示

- 输入：WriteBackSuggestion 契约结构
- 展示：列出应写回和不应写回的内容及原因
- 用途：帮助人理解哪些分析结果应成为稳定事实

---

## 四、Web 展示边界

Web 展示不得：

1. 将 UI 状态作为最终事实源；
2. 独立维护与 Git 文件事实源冲突的派生数据；
3. 替代 Human Gate；
4. 修改 41.06-Contract.md 中的角色语义；
5. 绕过事实源边界和回写规则。

---

## 五、实现前提

实现本文定义的 Web 展示能力前，应满足：

1. 项目已建立 Web Tools 基础设施；
2. 多角色思考执行频率足以支撑展示化投入；
3. Web 展示实现已按 05.02-Web展示规范.md 评估 Human Gate；
4. Web 展示数据必须能追溯到 41.06-Contract.md 契约字段和 Git 文件事实源。

---

## 六、检查项

检查 Web 展示是否合规时，应确认：

1. Web 展示是否未将 UI 状态作为最终事实源；
2. Web 展示是否未独立维护与事实源冲突的派生数据；
3. Web 展示是否未替代 Human Gate；
4. Web 展示数据是否能追溯到 41.06-Contract.md 契约字段和 Git 文件事实源。
