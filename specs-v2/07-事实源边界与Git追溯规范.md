## 1. 本文解决的问题

本文定义 LDVH 中稳定事实如何成立、哪些位置可以作为最终事实源、过程输出和工具输出如何受控回写，以及 Git commit records 如何作为事实源修改的追溯证据。

本文解决：

1. 最终事实源、单一事实源、事实承载介质和派生视图之间的边界；
2. 聊天、Skill 输出、Agent 输出、命令输出、Web 状态、缓存和运行时索引为什么不能直接替代 Git 文件事实源；
3. 过程输出和工具输出在什么条件下应回写、回写到哪里、不能回写成什么；
4. Git commit records 如何追溯事实源修改，但不成为工作对象或事实模型实例；
5. commit message 契约、type/scope、body、语言和派生关联规则的权威归口；
6. 事实源、Git 追溯、Code 解析、Web 展示、行动编排提交流程和运行时扩展之间如何避免互相越界。

本文不定义事实模型字段契约、行动编排执行流程、Code 输出 Schema、Web 页面布局、运行时扩展资产登记或测试实现细节。上述内容由对应规范承接。

## 2. 上位依据

本文承接 `00-LDVH理念与价值标准.md` 的事实源底层原则：事实源不是第七类构成要素，而是六类构成要素共同遵守的权威基础。规范体系、事实模型、行动编排、Code、Web 和运行时扩展都必须以可读取、可审查、可追溯的事实源为边界。

本文承接 `01-规范体系基础规范.md` 的规范结构要求：本文必须声明自身权威域、迁移来源、active 事实源、相关规范、Code 消费入口、保障要求、Human Gate 和待补齐事项。

若本文与 00 的价值判断或 01 的规范治理规则冲突，以 00 和 01 为准。

| 价值 | 本文如何服务 |

| 把环境观察写成长期状态 | 安装、入口存在性和工具可用性只能作为当前检查结果，需长期追溯时必须分流 |

## 5. 事实源分层

LDVH 的最终事实源必须是 Git 可追踪文件。一个事实只有写入其对应权威位置后，才成为可追溯、可审查、可被 AI 稳定读取和可被 Code 解析的稳定事实。

事实源分层如下：

| 类型 | 权威性质 |
|---|---|
| `specs/` 或切换后的 active 规范区 | 规范规则事实源 |
| `ldvh-base/` | 工作对象和事实模型实例事实源 |
| 管辖项目文档或 `docs/` 授权位置 | 项目正文、研究材料、来源材料或用户资产事实源 |
| Git commit records | 事实源修改追溯证据 |
| `code/`、`web/`、运行时扩展承载物 | 实现、入口、适配或能力承载事实源，但不替代规范和工作对象 |
| Code/Web/知识地图/命令输出 | 派生视图、诊断或过程输出，不是最终事实源 |

同一事实只能有一个权威位置。其它位置可以引用、摘要、聚合或展示该事实，但不得复制维护为第二事实源。

## 6. Git 追溯与提交契约

Git commit records 是事实源修改的追溯证据。它们服务于理解谁修改了什么、为什么修改、影响哪些事实源、是否经过验证和后续如何追溯，但不进入 20-29 事实模型集合，不创建 `ldvh-base/changes/`，也不作为对象字段手写维护。

commit message 契约包括：

1. 首行 type/scope/description 的可解析规则；
2. body 必填条件和语义清单要求；
3. 提交语言要求；
4. footer 与私有 trailer 的边界；
5. 关联提交的派生规则；
6. Code/Web 可消费字段和展示边界。

AI 如何准备、拆分、预检、执行和交还一次 commit，由行动编排承接。本文只定义 commit records 和 commit message 本体规则。

## 7. Code、Web 与知识地图消费边界

Code 可以读取 Git 文件事实源、解析 commit message、派生关联提交、生成知识地图边、检查事实源冲突和报告回写缺口。Code 输出必须能回指来源路径、commit hash、章节锚点或对象 ID。

Web 可以展示提交记录、最近提交、关联提交和事实源变更影响面。Web 不维护第二套提交事实源，不把页面状态、筛选状态或缓存写成稳定事实。

知识地图可以消费规范关系、对象字段、路径、Git commit records 和派生关联，但知识地图是只读投影，不落盘为事实源，不反向维护规范、对象或提交记录。

## 9. Human Gate 与检查要求

以下情况必须暂停并等待 Human 确认：

1. 改变某类事实的权威位置、最终事实源或单一事实源归口；
2. 将聊天、工具输出、Web 状态、缓存、测试输出或环境观察提升为稳定事实源；
3. 改变 commit message 契约、body 必填条件、type/scope 闭集或提交语言要求；
4. 删除、迁移、重命名或批量改写事实源目录、工作对象目录或规范路径；
5. 改变 Git commit records 与工作对象、规范、Code/Web 展示之间的派生关系；
6. 接受事实源规则、Git 追溯规则或提交校验长期降级。

事实源治理检查至少包括：

| 检查项 | 标准 |
|---|---|
| 权威归口 | 每类稳定事实只有一个权威位置 |
| 派生边界 | Code/Web/知识地图输出没有替代 Git 文件事实源 |
| 回写条件 | 过程输出和工具输出只有满足回写条件后才成为稳定事实 |
| Git 追溯 | 提交记录用于追溯事实源修改，不作为工作对象字段维护 |
| 提交契约 | commit message 契约有 Code 可检查入口和 Human 可读语义层 |
| 跨规范边界 | 02、03、04、05、06、08 没有复制维护本文本体规则 |
