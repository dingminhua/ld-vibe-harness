## 1. 价值判断

本文的价值，是把已经证明会重复出现的行动中相对稳定的部分组织成可复用结构，使 AI 能在适用场景中少做重复规划、少漏必要输入、失败分流、验证和交还，同时仍回到实际来源判断规则、授权、事实和能力。

本文主要服务：

1. V1 快速定位：为具体行动模板提供统一的发现和来源回指要求；
2. V2 充分理解：把进入条件、输入、前置条件、参与者、能力、授权、步骤、输出、验证和交还联系起来；
3. V3 边界识别：区分模板组织的行动结构与来源规则、事实、授权、当次计划和实现细节；
4. V4 稳定推进：在已经明确支持的重复场景中复用行动结构，并在能力不足或结果不完整时进入明确分流；
5. V5 据实判断：使模板选择、执行、验证和完成声明分别由实际依据支持；
6. V6 工作接续与 V7 清晰沟通：把当次结果、未完成范围、残留风险和待决定事项清楚交还；
7. V8 持续积累：让确有复用价值的行动结构可以更新或退出，而不是不断复制一次性流程。

行动模板会增加发现、维护和跨来源读取成本。只有可复用收益高于这些成本时才准入；格式相似、步骤较多、曾经执行过或可能被 Code 消费，都不能单独证明应建立行动模板。这里的准入是 LDVH 对内部行动能力的结构和来源质量审核，不表示让最终用户逐个安装、启用或选择模板。Human 已明确确认某组行动能力属于 LDVH 内部必需覆盖范围时，不再逐项询问用户“是否需要该功能”；后续审核只负责消除重复、决定合并或拆分、建立正确定义和验证边界，不得静默取消已确认的能力覆盖。

## 2. 规范依据

本文直接依据：

1. `ldvh-root` 对行动模板作为三类语义构成要素之一的定义：行动模板沉淀重复场景中的可复用行动结构，明确适用条件、关键步骤、验证入口和交还方式；
2. `specification-model-foundation` 对规则源资格、规范承载位置、渐进式披露、普通规范结构和新建责任判断的定义；
3. `source-of-truth-traceability` 对当前信息、来源回指、事实源写入与回读，以及当次结果不能自行成为稳定事实的定义。

本文不得改变或重新解释以下边界：

1. 具体规则的含义、适用范围、Human Gate、Stop Conditions 和验证成立条件由相应来源规范定义；
2. 行动模板是三类语义构成要素之一，不是新的规则源类型、事实类型、基础服务或授权机制；
3. 模板产生的当次计划、命令输出、诊断、测试结果和交还信息不会因模板结构完整而自行成为稳定事实；
4. 模板需要长期保留当次结果时，必须按适用来源规则及需要时事实模型写入事实源并回读当前 Working Tree；
5. `docs/`、归档、Code、tests、Skill、Agent、Hook、插件或环境配置不能反向定义行动模板的规则含义。

本文作为普通规范，持续受 01 的结构与治理规则约束；其它规范或材料可以为具体模板提供输入，但不因被模板引用而自动成为本文的直接 `basis`。

## 3. 职责边界

本文负责定义：

1. 候选行动结构成为具体行动模板前必须满足的准入条件；
2. 具体行动模板共同需要表达的适用场景、输入、前置条件、参与者、能力、授权、步骤与分支、输出、验证、回写和交还；
3. 模板选择、适用、执行、验证和完成之间的非等价边界；
4. Human、AI、Code、工具、环境能力以及受委派参与者在模板中的责任与能力表达边界；
5. 具体行动模板与来源规则、事实模型、一次性计划、Code/tests、实现说明和环境协议的分工；
6. 模板更新、复核和退出的共同要求。

本文不负责定义：

1. 任何具体行动模板的具体 `template_key`、载体、步骤、命令、字段、格式或当前效力；
2. 领域规则、项目强制规则、事实类型、Schema、状态闭集、证据充分性或完成条件；
3. Helper CLI 的请求、响应、能力发现接口或错误语义；
4. Code 模块、测试实现、工具参数、目录布局、缓存、receipt 或运行时状态；
5. 厂商事件、平台角色、Skill/Agent metadata、Hook payload、安装路径、权限映射或环境接入契约；
6. 单次实施计划、会话编排、执行日志、轮询状态或没有被具体事实类型独立准入的历史任务进度；具体事实类型为长期接续而定义的阶段目标、当前状态和质量关口仍由该类型来源负责。

## 4. 适用范围

本文适用于：

1. 识别重复场景中的候选可复用行动结构；
2. 审核候选是否应成为具体行动模板，以及比较普通说明、来源规范、事实对象、Code/tests 和其它承载位置；
3. 起草、修改、复核、退出或消费具体行动模板；
4. 具体模板需要表达执行者责任、所需能力、输入、写入范围、验证、失败分流、再委派或交还时；
5. Helper 或 Code 发现、读取、结构校验或呈现具体行动模板时；模板的语义适用判断仍由 AI 承担。

本文不适用于只服务当前事项的一次性计划、无需稳定复用结构的普通求解、平台自身的安装与触发配置，或仅用于说明某个实现的命令示例。当前事项没有适用的具体模板时，AI 的普通求解路径保持自主。

## 5. 行动模板准入、维护与退出

### 5.1 准入条件

一项候选行动结构只有同时满足以下条件，才可以进入具体行动模板的正式承载审核：

1. 有可回指的重复价值依据，能够说明相同或实质相近的行动场景会再次出现，以及复用结构减少了什么遗漏、试错、验证或交还成本；
2. 移除领域规则、项目强制要求、具体事实语义、平台协议、实现细节和单次计划后，仍存在相对稳定的进入条件、步骤关系、失败分流、验证入口或交还结构；
3. 能明确说明适用场景与不适用场景，不依赖模板名称、文件编号或“曾经这样做”反向证明适用；
4. 已有正式来源承担模板所引用的规则、授权、事实语义和验证成立条件；候选模板只组织行动，不补造缺失来源；
5. 能表达必要输入、前置条件、参与者、能力、授权、关键步骤与分支、预期输出、失败处理、验证、需要时的回写以及交还；
6. 能说明独立失败场景，例如进入条件错误、缺少必要输入、步骤关系错误、失败被吞掉、验证入口不匹配或交还遗漏；
7. 已比较普通说明、现有规范章节、事实对象、Code/tests、实现说明和一次性计划，确认行动模板是净负担最低的承载位置；
8. 具体模板的核心行动结构由符合 01 的当前规则源正文作为唯一定义来源承担：已有规范能够在自身责任内自然承接时放入该规范正文；确有独立规范责任时才按 01 §13 建立普通规范。该定义来源必须赋予模板稳定身份和发现入口；授权附件只能承载正文已经定义并授权的结构化细节，不能承载完整行动流程。

候选在唯一定义来源及其稳定身份、发现入口尚未成立时可以继续调查和起草，但只能保持候选或草案作用，不得作为当前适用模板约束行动。某项内部能力已由 Human 确认需要覆盖，只消除“是否保留这项能力”的重复取舍，不使具体模板的责任划分、定义来源、稳定身份、适用条件或验证自动成立；审核可以把同一能力合并到其它模板、拆成多个模板或改由普通规则与 Code 自然承接，但必须保持能力覆盖和承接位置清楚。

### 5.2 行动模板标识（Action Template Identifier）与声明

行动模板标识是具体行动模板的唯一定义来源赋予、用于跨规范、Helper、Code、tests 和环境入口稳定引用同一可复用行动结构的机器可读标识，机器字段为 `template_key`。它只识别具体行动模板，不识别承担定义责任的规范、模板标题、某次执行、Helper 公开操作或实现模块，也不证明该模板适用、已获授权、已经执行、验证通过、完成或具有可用实现。

`template_key` 使用小写 ASCII kebab-case，必须匹配 `[a-z][a-z0-9]*(?:-[a-z0-9]+)*`。它在全部当前具体行动模板中唯一；同一模板改名、移动到同一或其它定义来源时保持不变，模板取消后的 key 不得改派给其它模板。

定义一个或多个具体行动模板的当前来源，必须在正文中使用唯一一个标题文本完全为 `行动模板声明` 的 H3，并使用以下真实表头逐行声明：

| template_key | summary | definition_ref |
|---|---|---|

三个字段分别表示：`template_key` 是符合本节要求的行动模板标识；`summary` 是不替代正式定义的一句话模板摘要；`definition_ref` 使用 `<spec_key>::<exact-heading-text>` 指向同一当前来源正文中承担该模板完整行动结构的唯一 H2 或 H3。模板标题取自被引用章节的完整标题文本，不另设平行标题字段。

Code 按以下闭集规则解析声明：

1. 每份当前规则源至多出现一个标题文本为 `行动模板声明` 的 H3；该 H3 所属章节除空白行外必须直接以声明表开始，并在下一个 H2 或 H3 前只包含这一张表；
2. 声明表必须恰有 `template_key`、`summary`、`definition_ref` 三列，顺序与上述真实表头一致，不接受附加列、缺列、重复列或替代表头；
3. 每个数据行必须按 GFM 表格规则解析为恰好三个非空单元格；表格至少包含一个数据行，同一来源内不得重复 `template_key`；
4. `definition_ref` 在第一个 `::` 处分为两段；前段必须与声明所在规范的 `spec_key` 完全相同，后段必须非空且不得再包含 `::`；
5. 后段按去除 Markdown 标题标记和首尾空白后的完整标题文本，在声明所在规范全文中唯一匹配一个 H2 或 H3；不得指向 `行动模板声明` 自身；
6. 被引用定义章节的范围从匹配标题开始，到下一个同级或更高层级标题之前结束；H2 的范围到下一个 H2 前结束，H3 的范围到下一个 H2 或 H3 前结束。

声明表只是各模板唯一定义来源中的机器读取入口，不是平行登记表。只有声明所在规范进入当前规则源、`definition_ref` 目标存在且 §5.1 全部准入条件成立时，相应模板才进入当前具体行动模板集合。草案中的声明没有规则效力。声明 H3 后缺表、重复声明 H3、多表、空表、表头或数据行畸形时，该来源中的全部声明都不得进入派生视图；某一行的 key 格式错误、`definition_ref` 格式错误、越源、目标缺失、目标歧义或指向声明表自身时，只暂停该行对应模板；当前来源之间或同一来源内出现重复 `template_key` 时，所有重复项都暂停发现和消费。

稳定身份、发现和承接还必须满足：

1. 同一具体模板改名、移动到同一或其它定义来源时保持原 `template_key`；已经使用的 key 不得改派给不同模板；
2. 定义来源必须通过声明表使 `template_key`、模板标题、当前来源规范 `spec_key` 和具体正文位置能够一起定位；
3. Code 只扫描全部当前规则源中的声明表形成派生视图，不维护第二份手工模板目录，也不得让实现注册表、缓存或生成文件反向成为模板来源；
4. 定义来源不是 `active`、正文位置缺失、key 重复或映射冲突时，该模板不得作为当前可发现模板；
5. 模板拆分时，为新责任建立新 key，并由新定义来源说明原 key 的行动结构分别由哪些新 key 承接；模板合并时，保留能够准确表示合并后责任的一个既有 key，或建立新 key，并说明其它旧 key 的承接位置；
6. 模板被替代或取消后，旧 key 保留历史指向且不得重用；当前发现结果只返回仍由当前有效来源承担的模板，并能在需要时回到替代说明。

本节只定义稳定身份、来源定位与承接语义，不为模板建立独立生命周期状态，也不建立中央行动模板清单。04 的 `capabilities` 只发现已有当前来源的 Helper 公开操作；行动模板能否通过 Helper 读取由 §§9.5–9.6 的公开操作、当前实现与实际调用共同证明，声明表本身不得被冒充为 Helper 能力。

### 5.3 修改与复核

修改具体模板时，必须重新检查：重复场景是否仍成立；来源引用是否仍当前有效；适用与排除条件是否改变；角色、能力、写入范围、步骤、失败分流、验证、回写或交还是否受影响；以及修改是否已经越过模板责任而实质改变其它规范。

仅调整一次执行的顺序、命令、人员或临时环境，不应修改具体模板的共同规则。只有变化反复出现并重新满足 §5.1 时，才吸收为稳定模板内容。

### 5.4 退出条件

出现以下任一情况时，应审核具体模板退出、合并或缩减，而不是保留空壳：

1. 重复场景不再存在，或普通求解和现有来源已经能够以更低成本承接；
2. 模板与另一具体模板重复，分开维护只会造成来源和步骤漂移；
3. 模板长期依赖已经退出或无法回指的来源，且没有新的正式来源承接；
4. 移除一次性步骤、平台细节和重复规则后，已无独立可复用行动结构；
5. 实际使用持续表明模板增加的选择、读取和维护负担高于其复用价值。

具体模板停止使用、合并、替代或取消时，必须修改、替代或退出其唯一定义来源，并明确仍适用行动结构的承接位置。01 的 `draft`、`active`、`retired` 只描述规范文件状态，不自动成为模板生命周期状态；本文不另建模板状态闭集。

## 6. 适用判断与执行边界

### 6.1 适用判断

具体模板必须表达：

1. 进入信号：哪些当前目标、对象、事实或来源规则使其成为候选；
2. 适用条件：哪些输入、前置事实、规则、授权、环境和能力必须成立；
3. 排除条件：哪些相近场景不应使用该模板；
4. 不确定处理：哪些信息不足或冲突会阻止适用判断，以及需要补充什么；
5. 适用范围：当次判断覆盖哪些对象、行动、环境和时间范围。

发现模板、结构校验通过或名称相似，只能说明它是候选，不能证明已经适用。适用条件无法确认时，不得按最相近模板猜测执行；应补充依据、改用普通求解、选择其它已成立的模板，或按来源规则交还。

### 6.2 授权与规则边界

模板适用不等于行动允许。只有 Human 当前指令已经授权，且适用于该行动的全部来源规则许可条件已经成立，写入、删除、提交、发布、外部消息、环境安装、再委派、风险接受和 Human 决策等行动才获准。模板不得用“进入步骤”或默认选项扩张行动权限。

模板引用的规则、事实或能力发生冲突时，不得由模板自设优先级、静默选择或复制一份旧规则继续。应回到当前来源确认适用范围与权威关系，并暂停依赖冲突内容的最小行动范围。

### 6.3 选择、执行、验证与完成非等价

以下结论必须分别成立：

1. 模板被发现或选中，只表示准备进行适用判断；
2. 模板适用，只表示当次场景满足其进入边界；
3. 模板开始执行，只表示实际行动已经发生；
4. 某一步成功，只证明该步在当次观察范围内取得相应结果；
5. 验证通过，只证明来源规则和验证入口实际覆盖的对象与范围；
6. 模板行动完成，必须由具体模板引用的完成条件、实际结果、验证与交还共同支持。

模板静态存在、步骤全部打勾、工具返回成功、Human 已回应或 Git commit 已创建，都不得单独替代上述其它结论。

### 6.4 内部自动消费与用户边界

具体行动模板是 LDVH 的内部行动知识，不是要求最终用户逐个安装、启用、调用或在模板之间作产品级选择的环境 Skill。当前事项进入 LDVH 后，AI 应依据当前目标、事实、来源规则和能力结果自动召回相关模板并完成语义适用判断；确定性 Code 只能按来源已经定义的结构化条件辅助发现、过滤、读取和验证，不得根据自然语言猜测模板适用性。

用户只需表达目标并完成实际来源保留给 Human 的授权、方向、风险接受或验收。模板适用不新增一次“是否使用此模板”的 Human 选择；无适用模板、输入不足或语义冲突时，AI 应继续普通求解、补充来源或交还真正需要的决定，不得把内部模板选择转嫁给用户。

自动召回和适用不扩张行动授权；写入、删除、提交、发布、安装、外部消息、再委派和其它副作用仍须满足 §6.2 的行动允许条件。一个模板被自动选中也不证明其所需 Code 或环境能力当次可用。

## 7. 共同结构

具体行动模板至少应使下列内容可定位。本文定义的是语义要求，不强制所有模板使用同一表格、字段名、阶段数或线性顺序。

| 结构内容 | 必须表达 | 不得替代或扩张 |
|---|---|---|
| 定位与价值 | 在已审核唯一定义来源中的稳定身份、发现入口、模板解决的重复场景、净价值和当前来源回指 | 不用标题、编号或历史存在证明模板准入 |
| 适用边界 | 进入信号、适用条件、排除条件、不确定处理和当次作用范围 | 不把事件名称建立为所有模板共用闭集 |
| 输入与前置条件 | 必需与可选输入、来源、需要时的版本或观察范围、缺失和冲突处理 | 不复制领域字段、Schema 或状态定义 |
| 参与者、能力与授权 | 承担责任的参与者、所需能力、授权和写入范围、独立性要求及能力不足处理 | 不建立平台角色、工具或 Agent 固定枚举 |
| 步骤与分支 | 关键行动、先后或依赖关系、可并行部分、观察点、失败分流和停止位置 | 不恢复所有模板共用的固定阶段或生命周期 |
| 输出 | 预期结果、实际副作用、诊断、未产生结果和部分结果的区分 | 不把输出自动声明为稳定事实、验证通过或完成 |
| 验证 | 验证对象、入口、依据、可证明范围和未满足处理的来源回指 | 不自行定义领域成立条件或用 Human Gate 替代技术验证 |
| 回写 | 何种信息确需长期保留、目标来源规则、来源回指和回读要求 | 不把所有过程输出强制对象化或保存为事实 |
| 交还 | 当次状态、结果与证据、已验证和未验证范围、失败、残留风险、待决定事项和可继续入口 | 不用固定篇幅或固定机器字段制造新的服务契约 |

具体模板可以根据场景使用分支、循环、并行、重试或提前结束，但必须明确它们与输入、停止条件、验证和交还的关系。本文不建立 Context、Scenario、Gate 或其它固定阶段名称，也不要求具体模板采用统一的固定七段结构。

## 8. 输入、输出、步骤、验证、回写与交还

### 8.1 输入与前置条件

具体模板必须区分必需输入与可选输入，并说明输入来自当前规则源、事实源、Human 当前指令、当次观察还是能力结果。来源会变化且行动依赖特定版本、对象或观察时点时，应保留足以重新定位的来源信息。

缺少必需输入、输入冲突或输入无法回指时，模板必须给出补充、拆分、降级到普通求解或交还路径，不得用默认值、历史记忆或名称相似静默补齐。输入字段的类型与语义由其实际来源定义，具体模板不得建立平行 Schema。

### 8.2 步骤与失败分流

每个关键步骤应说明行动目的、所依赖的输入或前一步结果、要调用的实际能力或需要作出的判断、可观察结果，以及成功、部分结果、拒绝、失败或不可观察时如何继续。只对顺序有要求的步骤建立顺序；可以并行的行动不得为形式统一被强制串行。

具体步骤可以引用命令、工具或实现入口，但这些入口的参数、输出和能力边界仍由相应正式契约或实现证明。模板不得把当前命令名、厂商事件、工具列表或实现文件扩展为通用闭集。

### 8.3 输出

具体模板应区分预期输出与当次实际输出，并如实保留没有输出、部分输出、失败输出和副作用。输出只能在其来源与观察范围内被消费；如果准备形成稳定事实，必须另按 03 及实际适用来源规则写入并回读。

模板不得要求能力为了满足格式而伪造未知值、成功状态或完成结论。面向机器的固定输出 envelope 若具有稳定服务契约价值，应由承担相应外部契约的规范定义，不由具体模板反向规定。

### 8.4 验证

具体模板必须回指实际来源规定的验证对象、成立条件、依据、入口、可证明范围和未满足处理，并把验证安排到能够观察目标结果的位置。来源没有定义成立条件或当前入口不可用时，应报告未验证范围，不得由模板补造通用验证标准。

Human 确认只在来源规则将相应决定或验收保留给 Human 时承担该作用；它不能替代测试、实际调用、环境触发、回读或其它技术验证。模板执行验证的结果仍只覆盖当次对象、环境、入口和证据范围。

### 8.5 回写

只有确需跨行动、会话、执行者或阶段继续保留的信息才进入回写判断。具体模板必须指向已有来源规则允许的位置，按需要保留来源、当前状态和关系，并在写入后回读当前 Working Tree；需要对象化、状态化或证据化管理时，还必须等待相应事实模型和具体事实类型成立。

模板不得为保存执行进度而自行创建事实类型、运行对象、receipt、阶段状态或日志 Schema。单次计划、临时检查表和过程输出默认保持当次信息，除非另有适用来源证明其长期价值和承载位置。具体事实类型已经按 05 准入的阶段性目标、恢复快照、审核或 Human Gate 记录不属于模板自行创建的运行 Schema；模板只能按该类型来源组织回写，不能复制或扩张其字段和生命周期。

### 8.6 交还

具体模板的交还必须使 Human、当前负责事项的 AI 执行者或后续执行者能够区分：

1. 当次目标和实际作用范围；
2. 已执行、未执行、部分执行和被拒绝的内容；
3. 实际结果、来源回指和副作用；
4. 已验证范围、未验证范围及验证入口缺口；
5. 已回写内容、回读结果和尚未形成稳定事实的当次信息；
6. 当前失败、阻塞、残留风险和待 Human 决定事项；
7. 可以继续、重试、分流、回滚或保持暂停的入口。

交还结构可以按消费方和场景调整，不要求固定字数、固定段落或全局字段闭集。向外部调用方提供稳定机器响应时，应使用相应服务契约，不得把本节当作 Helper 或其它 API 的响应 Schema。

## 9. 角色、能力与委派表达

### 9.1 责任表达

具体模板应按行动责任表达参与者，而不是建立固定平台角色清单。需要参与者时，应说明：由谁承担什么判断或行动责任、需要什么输入和授权、允许影响什么范围、必须交还什么，以及失败或不可用时交给谁继续判断。

AI 执行者仍承担当前事项的理解、判断、行动和结果交付责任。调用 Code、工具、环境能力、Skill、Agent 或其它执行者可以提供确定性结果、专题分析或分工产出，但不能因模板存在而替代当前 AI 执行者对来源、范围、验证和最终交还的责任。Human 只承担来源规则明确保留的判断、授权、方向选择、风险接受或验收决定。

### 9.2 能力表达

模板对能力的表达至少包括：需要完成的能力作用、可接受输入与输出的来源、权限或副作用范围、当次可用性需要什么依据，以及能力缺失、部分可用、拒绝或结果不可观察时的分流。

能力名称、工具名、安装存在、配置声明或模板中的调用入口不能证明当次可用。实际能力必须由当前实现、实际调用、测试或环境触发等范围匹配依据证明；Helper 如果提供模板能力发现或报告，必须由适用契约和实际实现支持，模板不得自行声称已经自动完成发现。

### 9.3 委派与独立性

具体模板需要委派、并行工作或独立复核时，应表达任务边界、输入、允许写入范围、期望产出、独立性要求、冲突处理、回收时机和交还责任。是否使用线程、worktree、子 Agent、团队角色或某个平台能力属于具体模板、环境和当次能力选择，不形成所有模板共用的角色或事件闭集。

受委派参与者的中间过程、轮询状态和平台 receipt 属于当次信息。只有适用来源已经定义长期承载位置，并满足 03 及需要时事实模型时，才可以将其中确有接续价值的结果写入事实源。

### 9.4 统一来源、Helper 与单一环境入口

行动模板只在 LDVH 当前规则源中维护一份。各环境不得把模板正文复制为各自的 Skill、Agent prompt、Hook 脚本、插件配置或缓存权威；模板更新后，兼容的环境入口应继续通过同一 LDVH Helper 读取当前来源，不要求用户重新安装每个模板。

统一消费链路为：环境中的一个 LDVH 接入单元定位并调用同一 Helper；Helper 从当前规则源派生模板候选和内容；AI 完成任务理解、语义适用判断和行动编排；Code 执行来源已经授权且已实现的确定性操作并返回可回指结果。这里的“一个接入单元”表示用户在一个环境中只安装、启用或配置一次 LDVH adapter/Hook 包，不表示所有厂商使用相同 Hook 协议，也不限制该接入单元为承接环境 lifecycle 而注册多个原生事件。

每个环境仍可因 manifest、事件、payload、权限、阻断能力和安装位置不同而需要一个薄 adapter。adapter 只负责环境协议与 Helper 共同入口之间的定位、输入投影、调用和结果翻译；不得包含模板选择语义、模板正文、领域规则、事实 Schema 或另一套执行流程。环境不支持所需 Hook、无法稳定调用 Helper 或只能提供部分 lifecycle 时，必须报告相应能力缺口，不得通过安装多个环境 Skill 绕开统一入口。

Helper 通过下列公开操作从同一当前规则源形成模板候选并精确读取完整定义。候选结果只证明声明和来源通过当次已实现机械检查；AI 仍须读取定义中的适用、排除、输入、能力和停止条件，并完成语义适用判断。Helper 不自动选择、排序、执行或批准模板，环境 adapter 也不得把候选命中改写为适用或授权。

### Helper 公开操作

| `operation_key` | `summary` | `effect` | `arguments_contract` | `result_contract` |
|---|---|---|---|---|
| `read-action-template-candidates` | 从 LDVH 当前规则源的行动模板声明形成可精确定位的机械候选集合 | `read` | `action-template-foundation::9.5 行动模板候选读取输入与结果` | `action-template-foundation::9.5 行动模板候选读取输入与结果` |
| `read-action-template-content` | 按一个或多个稳定 template_key 精确读取当前定义章节及其来源范围 | `read` | `action-template-foundation::9.6 行动模板内容读取输入与结果` | `action-template-foundation::9.6 行动模板内容读取输入与结果` |

### 9.5 行动模板候选读取输入与结果

领域 `arguments` 只允许可选 `template_keys`：省略或空数组表示请求全部当前机械候选；出现成员时必须是 1–128 个互异、符合 §5.2 格式的非空 string，并保持请求顺序，不作模糊、别名或标题匹配。`work_object_locators`、`observed_context` 和 `authorization_reference` 必须为空，`requested_disclosure` 必须为 `null`；本操作只读取随 Helper 分发并与实现同源定位的 LDVH 当前规则源，不接受调用方路径或替代规则仓库。

结果字段闭集为 `items`、`unchecked_conditions`。`items` 为数组；每项字段闭集为 `template_key`、`summary`、`source_key`、`canonical_path`、`definition_ref`、`definition_heading`、`definition_start_line`、`definition_end_line`，均直接来自当前声明和定义范围。`unchecked_conditions` 列出当次 Code 没有自动证明的语义准入条件，不能为空数组来暗示语义适用、授权或可执行性已经成立。请求全部候选时按 `template_key` 升序；精确选择时保持请求顺序。

共同 scope 以 `template_key` 为成员。精确 key 未发现、声明无效或来源未进入当前规则源时进入 `not_completed`；部分匹配使用 `partial`，全部无匹配结果使用 `unavailable` 且 `result: null`。成功只证明候选声明和定位可读取，不证明模板适用、所需能力可用或行动获准。

### 9.6 行动模板内容读取输入与结果

领域 `arguments` 必须且只允许 `template_keys`，值为 1–64 个互异、符合 §5.2 格式的非空 string；保持请求顺序并只作稳定 key 精确匹配。共同其它输入边界与 §9.5 相同。

结果字段闭集为 `items`；每项在 §9.5 候选字段基础上增加 `content`、`content_sha256`、`source_content` 和 `source_content_sha256`。`content` 是 `definition_ref` 目标标题起至同级或更高层级下一标题前的当前 Markdown 原文，保持换行并包含定义标题；`source_content` 是承担该模板身份、依据、边界、定义、验证、Human Gate 和 Stop Conditions 的完整当前来源规范原文；两个 SHA-256 字段分别是相应 UTF-8 内容的 64 位小写十六进制指纹。Helper 必须从同一次规则源检查持有的内存文档读取，不在检查后按路径重新打开文件，避免候选、定义章节和来源全文来自不同 Working Tree 时点。

共同 scope、部分结果和无匹配结果语义沿用 §9.5。读取内容不解析自然语言适用条件，也不把来源全文中的其它模板或共同说明误报为当前模板定义；AI 必须同时消费精确 `content` 与 `source_content` 中适用于该模板的依据、边界、验证、Human Gate 和 Stop Conditions，并按来源位置继续读取基础规范和领域来源。

## 10. 具体行动模板的边界

### 10.1 内容归口

| 内容 | 正确承载位置 | 具体模板的作用 |
|---|---|---|
| 领域规则、项目强制规则、字段、状态、Human Gate 与完成条件 | 对应正式来源规范或其已授权结构 | 回指并组织何时消费，不复制或改写 |
| 行动模板共同准入与结构规则 | 本文 | 具体模板遵守，不重复建立另一套共同模型 |
| 某一重复场景的稳定进入条件、步骤关系、失败分流、验证安排与交还 | 经单独审核成立的当前规则源正文 | 作为该具体模板的唯一定义来源，赋予稳定身份和发现入口 |
| 单次目标、临时顺序、负责人、时间安排和运行进度 | 当次计划、Human 指令或普通工作记录；具体事实类型已独立准入的长期阶段目标与当前进度除外 | 不提升为模板共同规则，也不覆盖具体事实类型定义 |
| 需要长期保留的事实、状态、证据、决策和经验 | 适用来源规则及需要时事实模型允许的事实源位置 | 指向回写和回读，不复制事实 |
| Code、tests、命令、工具参数、目录和内部诊断 | Code/tests 与实现说明；稳定外部契约另由正式来源承担 | 只在实际能力范围内调用，不反向定义实现契约 |
| 厂商事件、安装接口、权限、payload 和环境触发 | 环境接入规则、具体 adapter 正式来源或实现 | 只组织已成立能力，不提升为通用枚举 |

### 10.2 内部能力覆盖与具体模板逐项定义

历史中存在或已被提出的行动结构，不得仅因名称、数量、编号、阶段、事件、步骤、字段、Gate、Hook 或旧实现存在而恢复为具体模板。

每个具体模板必须分别执行 §5 的结构和来源质量判断，并比较普通说明、正式规则来源、事实对象、Code/tests、环境实现和一次性计划。审核结果可以是把已确认能力合并到其它模板、拆分、缩减或建立一份新的具体模板；不得为恢复历史数量或编号而定义，也不得把“未单独建模板”误写成相应内部能力被取消。最终用户不参与逐模板安装或启用取舍；Human 只在改变已确认能力覆盖、正式责任或来源实际保留决定时进入相应 Gate。

### 10.3 禁止建立的通用闭集

本文和具体模板不得建立：

1. 所有行动共同使用的固定阶段、固定步骤数或生命周期；
2. 所有环境、工具、角色、事件、失败类型或能力的封闭枚举；
3. 用于保存所有行动单次执行进度的全局运行对象、receipt、阶段状态或事件流；本项不禁止具体事实类型为其自身长期责任独立准入最小阶段事实；
4. 由模板自行定义的规则优先级、授权模型、事实状态或完成状态；
5. 以格式完整为理由要求所有普通求解都先选择和执行模板。

## 12. Human Gate

本文不因候选行动结构的调查、草拟或普通求解新增全局 Human Gate。以下事项仍必须进入实际来源已经定义的 Human Gate：

1. 改变 00 对三类语义构成要素中行动模板的定义，或使行动模板脱离既有语义边界成为规则授权器、事实源或固定全局流程；
2. 具体模板需要改变正式规范责任或载体，且按 01 完成承载比较和独立复核后仍无法收敛；
3. 当次行动涉及来源规则保留给 Human 的授权、方向选择、风险接受、验收或其它决定；
4. 具体模板准备以 Human 决定解决事实冲突、来源缺失、多个权威位置或无法判断的长期承载方向时；
5. 准备接受具体模板长期缺少必要来源、验证、失败分流或交还所带来的重大残留风险。

Human 决定的复用按 00 §9 执行。Human 可以作出实际来源保留的授权、方向选择、风险接受或验收决定，其中风险接受必须明确未验证范围；其回应不能使不满足准入条件的模板自动成立，不能补造定义来源、能力或事实，也不能替代技术验证、事实源写入与回读。

## 13. Stop Conditions

出现以下任一情况时，必须暂停受影响具体模板的准入、使用、修改或相应结果声明：

1. 候选只有一次性步骤、格式相似或历史文件，没有可回指的重复价值和稳定剩余结构；
2. 模板正在定义或复制领域规则、项目强制要求、Schema、状态闭集、Human Gate、完成条件、服务契约或环境协议；
3. 模板引用的正式来源缺失、退出、无法回指或相互冲突，却准备继续按旧内容或任意优先级执行；
4. 适用条件、必需输入、授权、写入范围或对象范围无法确认，却准备按名称相似或默认值执行；
5. 必需能力未实现、未接入、被拒绝、部分可用或结果不可观察，却准备假定能力成功或跳过失败分流；
6. 模板准备把所有行动固定为同一阶段、事件、角色、工具或状态闭集，或者要求没有适用模板的普通求解也执行固定流程；
7. 单次计划、执行进度、轮询状态、receipt、命令或测试输出正在被模板直接保存为稳定事实，但没有适用来源规则、需要时事实模型和回读；
8. 模板选择、步骤完成、工具成功、Human 回应或 commit 正在被直接声明为验证通过或行动完成；
9. 实际失败、拒绝、部分结果、未验证范围、副作用或残留风险没有进入交还，却准备结束当次模板行动；
10. 具体模板的唯一定义来源尚未按 01 审核，行动模板声明结构畸形，`template_key` 重复、格式错误或被改派，`definition_ref` 越源、悬空、歧义或自指，却准备赋予相应模板当前规则效力。
11. Helper 模板操作接受调用方替代规则路径、模糊选择、重新打开不同快照，遗漏定义来源、验证、Human Gate 或 Stop Conditions，或者把机械候选冒充为语义适用、授权、能力可用或执行结果。

暂停范围与可继续行动按 00 §10 执行；对本文而言，只读核对来源、补充输入、缩小作用范围、比较其它承载位置、修正模板、收集能力和验证依据以及准备 Human Gate，可以在不越过受影响边界时继续。

受影响范围只能在重复价值和承载位置已经确认、唯一定义来源及稳定身份和发现映射已经恢复、来源冲突已经消除、适用与授权边界已经成立、必需输入和能力已经取得、事实回写条件已经满足、验证与交还已经补齐，或者声明已经缩小到现有依据实际支持的范围后恢复。
