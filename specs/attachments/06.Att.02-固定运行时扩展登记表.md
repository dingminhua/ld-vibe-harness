### 2.1 Runtime Protocol 允许内容白名单

`rules/LDVH-RUNTIME-PROTOCOL.md` 只允许包含以下内容：

1. `ldvh_asset` 自描述块，字段限于固定运行时扩展自描述字段；
2. 文件性质、迁移来源和规范来源的简短回指；
3. “这是什么”章节，说明该文件是固定 Rules 入口，只负责在 Rules 路径派发 canonical event 到 `hook_dispatch.py`，并声明不得自行判定放行、阻断或管辖命中；
4. 四事件触发表，事件限于 `session-start`、`acknowledge-read-plan`、`pre-tool-use`、`git.commit-msg`，命令限于调用 `code/hook_dispatch.py run <event>` 的 Rules 路径命令；
5. Hook 路径的泛化说明，限于“环境原生事件映射为 canonical event 并交给同一 dispatcher”，不得枚举环境 payload 字段；
6. 消费 dispatcher 输出的泛化说明，限于按 dispatcher 返回的 `read_plan`、`next_action`、`stop_conditions`、blocking 状态和回指路径行动；
7. STOP 泛化说明，限于 dispatcher 返回停止条件时停止当前动作并按 dispatcher 输出处理；
8. 指向 `source_specs` 的边界回指。

除上述白名单外，`rules/LDVH-RUNTIME-PROTOCOL.md` 一律不得出现其它规则正文。尤其不得写入 receipt 字段定义、管辖判定算法、fallback read_plan 规则、用户级运行时状态路径、PreToolUse 写入门禁细节、Git commit-msg 提交门禁细节、Skill 执行流程、commit message 契约、Code/Web Schema、环境 payload 字段清单、行动成员流程或长期环境安装状态。需要这些内容时，必须写入对应的 Code、Hook registry、Skill、行动编排、部署适配规范或其它来源 active specs。

`python3 code/specs_validate.py deployment-entries` 必须检查该白名单；检查失败表示固定运行时扩展登记不一致。

## 3. 使用规则

未登记的 Rules、Skill、Agent 或 Hook 只能作为候选资产、临时过程输出、临时核对步骤或环境适配候选，不得被 Code、Web、Rules 或行动编排当成稳定保障机制。

新增、删除、移动或重命名固定承载物必须回到 06 Human Gate，并同步 01、固定 Rules 入口、Code 检查和知识地图入口。

active specs、附件或成员主文件变化后，应检查本表登记的固定 Rules 资产是否受影响。检查以资产文件自身 `ldvh_asset.source_specs`、`sync_triggers`、职责正文和 06 正文为准；本文只提供固定承载物基线，不手写维护每次同步状态。

固定能力资产与环境落地边界可通过 `python3 code/specs_validate.py capability-environment` 生成只读矩阵，用于核对来源规范、同步触发、验证链、责任归口和环境安装状态声明边界。该矩阵不写入环境入口，不表示用户环境已安装，也不得替代资产文件自身 `ldvh_asset` 或 06 部署检查。

改变固定承载物职责、路径、固定身份、薄引用关系或 Human Gate 边界时，应同步本文；仅修改资产内部文案、读取顺序、STOP 点或验证入口时，若不改变登记基线，可只更新资产自身并说明影响评估结论。
