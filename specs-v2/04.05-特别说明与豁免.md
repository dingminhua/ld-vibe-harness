## 1. 本文解决的问题

本文解决 LDVH v2 中不适合放入通用正文规则、但又需要单独登记和检查的特别说明与豁免如何处理。

特别说明与豁免不能成为绕开正式规范、Human Gate、事实源边界或 Code 验证纪律的口袋。只有适用范围清楚、默认效力清楚、承接位置清楚、退出条件清楚的事项，才可以登记在本文。

---
## 2. 与 00 总纲的关系

00 要求 LDVH 以稳定事实源、Human Gate、验证证据和运行闭环约束 AI 行动。特别说明与豁免只能在不破坏这些上位原则的前提下存在。

当特别说明或豁免会弱化事实源边界、Human Gate、验证纪律、Code 确定性或环境适配边界时，应触发 Human Gate，并优先考虑回到对应正式规范重新定义规则，而不是在本文添加例外。

---
## 3. 基本概念

本文使用的特别说明、豁免、启用、旧规范迁移和运行投影等术语，按 `specs-v2/02-术语规范.md` 定义。本文只规定特别说明与豁免的登记、启用和回收规则。

### 3.1 特别说明

特别说明是对某个环境、项目、入口、命令或运行投影的补充说明。特别说明通常不是所有用户项目都必须启用的通用规则。

特别说明应说明：

1. 适用范围；
2. 默认效力；
3. 承接位置；
4. 与上位规范的关系；
5. 退出或迁移条件。

### 3.2 豁免

豁免是对某项既有要求的有限例外。豁免必须说明被豁免的上位要求、豁免原因、适用范围、风险控制方式和失效条件。

不得用文件扩展名、环境偏好、执行便利或旧习惯作为豁免的充分理由。涉及删除、覆盖、事实源改写、高影响变更或权限扩大时，应按影响范围评估 Human Gate。

### 3.3 启用

登记在本文的特别说明或豁免，不自动进入所有管辖项目。只有当环境适配映射、项目运行投影、工作区规则、项目规则、Code 配置或 Human 明确选择启用时，该事项才对对应环境或项目生效。

---
## 4. 登记规则

新增特别说明或豁免时，应使用登记表表达：

| 字段 | 含义 |
|---|---|
| 编号 | 稳定编号，例如 `SP-01` 或 `EX-01` |
| 类型 | 特别说明或豁免 |
| 内容 | 具体说明或豁免事项 |
| 适用范围 | 哪些环境、项目、入口或文件范围适用 |
| 默认效力 | 默认启用、默认不启用、仅迁移保留或已废止 |
| 承接位置 | 运行投影、环境适配映射、Code、Web、工作区规则或项目规则 |
| 风险控制 | 如何避免削弱 Human Gate、事实源边界或 Code 验证 |
| 退出条件 | 何时迁移、废止或回收到正式规范 |

特别说明如果变成长期、跨环境、普遍适用的稳定规则，应迁移到对应正式规范，本文只保留索引或迁移说明。豁免如果被反复使用，应重新评估上位规则是否需要调整。

## 6. 启用与环境适配

特别说明或豁免需要进入某个环境时，应按 `specs-v2/04.02-环境适配与运行投影规范.md` 建立环境适配映射。

启用时至少说明：

1. 对应登记编号；
2. 启用环境或项目；
3. 运行投影位置；
4. 验证方式；
5. 不启用时的降级方式；
6. 是否影响 Human Gate。

不得因为本文登记了某项特别说明，就默认所有环境都已经落地。未启用的特别说明不得被 AI 当成当前项目规则执行。

## 7. 规范落地要求

本文通过以下规范落地要求说明相关要求的同步、检查或审计触发条件。

| 落地要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 上位约束承接要求 | 新增、修改或废止特别说明与豁免时，不得削弱 00 的事实源、Human Gate、验证和运行闭环原则 | 本文 §4-§6、Human Gate、总纲一致性检查 | 文档治理 | 本文登记规则、默认效力、风险控制或退出条件变化时 |
| 入口可见要求 | AI 处理特别说明、豁免或旧规范迁移时应能定位本文作为登记入口 | 规范文档入口摘要、相关规范引用、环境适配映射引用 | AI 执行入口提示 | 本文定位、当前登记表或启用规则变化时 |
| Human 交互要求 | 新增或扩大豁免时应让 Human 看见被豁免的上位要求、风险控制和失效条件 | Human Gate、对话确认、审计记录 | 审批提示 | 新增豁免、扩大适用范围、改变默认效力或影响删除/覆盖/写入风险时 |
| 生命周期触发要求 | 环境适配映射或运行投影启用特别说明后，应在相关规范变更时检查是否需要同步 | `specs-v2/04.02-环境适配与运行投影规范.md`、人工降级检查、漂移检查 | 触发保障 | 特别说明内容、承接位置、默认效力或相关环境能力变化时 |

---
## 8. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 新增、删除或改变特别说明与豁免登记；
2. 将默认不启用改为默认启用；
3. 扩大特别说明或豁免的适用范围；
4. 让豁免影响删除、覆盖、写入、状态流转、验收或权限边界；
5. 将旧规范中的特别规则直接迁入 v2，而未重新评估适用范围和风险控制；
6. 允许未启用的特别说明被 AI 当成当前项目规则执行。

特别说明与豁免检查至少包括：

| 检查项 | 标准 |
|---|---|
| 适用范围 | 每项登记说明适用环境、项目或入口 |
| 默认效力 | 已明确默认启用、默认不启用、迁移保留或废止 |
| 承接位置 | 已说明运行投影、环境适配映射、Code、Web、工作区规则或项目规则位置 |
| 风险控制 | 未削弱事实源边界、Human Gate 或 Code 验证纪律 |
| 启用状态 | 未启用事项未被当成当前项目规则执行 |
| 退出条件 | 长期通用规则会迁移到对应正式规范，废止事项不会继续被引用 |
