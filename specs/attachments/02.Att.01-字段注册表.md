## 1. 定位

本文承载 02 授权的字段注册表结构、注册列闭集、字段生命周期、废弃/别名/替代关系和消费元数据。

02 正文定义字段契约原则、公共字段语义边界、具体模型采用规则和字段注册表权威边界；本文只能维护这些已授权的注册表字段、闭集、字段生命周期和消费元数据，不得单独定义具体模型字段存在性、必填性、状态条件、关闭条件、完整 schema、事实源边界、字段矩阵诊断、清退对象清单、Code 输出 Schema 或 Web 页面契约。

## 2. 注册表字段

字段注册表使用以下列：

| 列 | 含义 |
|---|---|
| `field_path` | 字段名或重要嵌套字段路径 |
| `scope` | 注册项适用范围 |
| `meaning` | 字段回答什么问题，以及不得承载什么内容 |
| `format_kind` | 字段内容格式类型 |
| `value_shape` | Code 可判断的值形态 |
| `ref_kind` | 引用或标识类型 |
| `enum_owner` | 枚举值归口 |
| `schema_owner` | 对象内结构约束归口 |
| `code_check_kind` | Code 可消费的校验维度 |
| `web_render_kind` | Web 派生展示语义 |
| `status` | 注册项生命周期状态 |
| `replacement` | 废弃、别名或替代关系 |

注册表列只说明字段若被采用时如何理解、消费和诊断，不表达字段在某个具体事实模型中是否存在、是否必填、是否条件必填、是否允许为空、何时关闭或如何流转。

## 3. 注册列闭集

注册表使用以下闭集。新增、删除、重命名或改变闭集含义前，必须回到 02 正文评估 Human Gate。

| 注册列 | 允许值或写法 |
|---|---|
| `field_path` | 字段名或点号路径；数组元素不写 `[]` |
| `scope` | `common`、具体事实模型名、具体事实模型编号或重要嵌套结构范围 |
| `format_kind` | `narrative`、`checklist`、`evidence`、`decision`、`reference`、`log`、`structured` |
| `value_shape` | `string`、`markdown`、`checklist_markdown`、`evidence_markdown`、`boolean`、`date`、`datetime`、`object`、`list_object`、`list_string`、`list_mixed` |
| `ref_kind` | `none`、`object_ref`、`workcase_ref`、`commit_ref`、`doc_path`、`mixed_ref`、`local_id`、`enum`、`url_ref` |
| `enum_owner` | `none`、`02`、`owner_model`、具体事实模型编号或后续 active 归口 |
| `schema_owner` | `none`、`02`、`owner_model`、具体事实模型编号或后续 active 归口 |
| `code_check_kind` | `none`、`format`、`ref`、`enum`、`structured`、`deprecated`、`owner_state` |
| `web_render_kind` | `summary`、`checklist`、`evidence`、`object_ref`、`doc_link`、`commit_ref`、`mixed_ref`、`structured_area`、`status_signal`、`enum_signal`、`metadata`、`deprecated`、`url_ref` |
| `status` | `active`、`deprecated`、`removed`、`alias` |
| `replacement` | 字段路径、对象名、规范路径或 `none` |

`owner_state` 表示状态条件、必填性或关闭条件由具体事实模型规范决定。本文不得用 `owner_state` 反向推导字段已经满足具体模型状态规则。

`code_check_kind` 语义如下：

| `code_check_kind` | 可机械消费维度 | 边界 |
|---|---|---|
| `none` | 不从本文派生校验 | 仍可由具体模型规范或实现自行校验 |
| `format` | 字段内容格式、YAML 块标量、Markdown/checklist/evidence 基础形态 | 不决定字段是否必填 |
| `ref` | 引用类型、引用前缀、路径或 commit 形态 | 引用存在性是否强制由具体模型规范或 Code 实现决定 |
| `enum` | 枚举值集合 | 枚举值以 `enum_owner` 指向的规范或具体模型为准 |
| `structured` | object / list[object] 形态和已注册嵌套路径 | 不替代 `schema_owner` 定义的完整对象内 schema |
| `deprecated` | 废弃字段、别名、替代字段、迁移提示 | 不自动执行迁移，迁移策略由事实模型或行动编排承接 |
| `owner_state` | 状态条件必填、关闭条件、对象内跨字段约束 | 本文只登记可被消费的维度；具体诊断级别归属具体模型和 Code 实现 |

`web_render_kind` 语义如下：

| `web_render_kind` | 派生视图语义 | 必须保持的契约 |
|---|---|---|
| `summary` | 摘要或正文区域 | 按字段内容展示；不得把摘要派生结果回写为事实 |
| `checklist` | 检查清单区域 | 保留每项检查状态和完成比例语义 |
| `evidence` | 证据区域 | 突出验证命令、路径、结果、结论、关闭判断和 Human Gate 结果 |
| `object_ref` | 对象引用 | 仅对可识别对象 ID 执行对象跳转；不可识别引用按普通引用显示 |
| `doc_link` | 文档或路径引用 | 按文件路径、规范路径或 URL 引用显示 |
| `commit_ref` | Git 提交引用 | 作为 Git commit 引用显示，不得误当事实模型实例 ID |
| `mixed_ref` | 混合引用列表或混合引用值 | 分类型识别对象 ID、路径、URL、命令和说明性文本；不可识别项按普通引用显示 |
| `structured_area` | 结构化区域 | 结构化对象或列表不得裸渲染为普通 Markdown 文本 |
| `status_signal` | 状态信号 | 用于对象状态、优先级和内部执行状态等带进展或风险含义的稳定枚举展示 |
| `enum_signal` | 普通枚举信号 | 用于不直接表示进展或风险的稳定枚举展示 |
| `metadata` | 元信息 | 用于时间、布尔、局部 ID 等不构成正文的字段 |
| `deprecated` | 废弃字段提示 | 读取历史字段时应提示替代关系，不应鼓励新写入 |
| `url_ref` | 外部 URL 引用 | 展示完整 URL、标题和中文用途摘要，不得替代报告正文 |

## 5. 字段注册辅助核对表

字段注册辅助核对至少包括：

| 核对项 | 标准 |
|---|---|
| 附件授权 | 注册项只回答 02 授权的问题 |
| 闭集有效 | 注册列取值属于本文 §3 |
| 语义回指 | 字段语义能回指 02 或具体模型规范 |
| 格式回指 | 内容格式属于 02 定义范围 |
| schema 归口 | 具体对象结构约束指向具体事实模型 |
| 生命周期清晰 | 废弃、别名、替代关系有明确 replacement |
| 不反推采用 | 未把注册项写成具体模型字段存在性或必填性 |
| 不替代实现规范 | 未定义 Code 输出 Schema、Web 页面契约或运行时适配方式 |

本核对表用于发现字段注册漂移、同义字段、消费元数据缺失和附件越界；核对结论不能替代 02 主文档规定的高影响确认。
