# PMKit 初始化流程

> 创建日期：2026-05-28
> 定位：受管理项目接入 PM Kit 的初始化流程
> 适用范围：所有首次接入 PM Kit 的受管理项目
> 上位依据：specs-v2/00、specs-v2/10、specs-v2/11、specs-v2/14

## 一、流程定义与触发条件

初始化是受管理项目首次接入 PM Kit 时"从无到有"的建设过程，不是检查过程。审计归 specs-v2/51-PMKit审计流程。

出现以下任一情况时，应执行初始化：

1. 新产品接入 PM Kit；
2. 新项目加入已有产品；
3. AI 首次对某个项目操作前；
4. 项目结构发生重大变更后重新初始化。

## 二、执行步骤

### 2.1 产品与项目类型判定

初始化前必须读取 `product.yaml` 并判定产品/项目角色。

#### 产品形态

| 产品/项目角色 | 判定方式 | 初始化策略 |
|---|---|---|
| 单项目产品 | `projects` 只有 1 个项目，且 `path` 为 `.` | 执行单项目初始化 |
| 多项目产品治理项目 | `projects` 数量 > 1，且存在 `id: product` 或 `path: .` | 执行产品级与跨项目治理初始化 |
| 多项目产品子项目 | 多项目产品中非治理项目 | 执行项目内部初始化，检查是否正确引用治理规则 |

#### 项目性质

| 项目性质 | 判定方式 | 初始化重点 |
|---|---|---|
| 业务代码项目 | 有应用代码和运行入口 | 04 开发实践事实源、05 交付实践事实源 |
| 工具项目 | 含 `tools/`、API、脚本或 Web 工具 | 启动、API、配置、YAML、错误处理 |
| 规范文档项目 | 主要为 docs / rules | YAML 模板、文档链接、规则引用 |
| 混合项目 | 同时包含工具与规范文档 | 同时覆盖工具和规范文档初始化 |

### 2.2 L0/L1 规则评估

#### L0 工作区规则

若工作区承载多个项目或存在跨项目通用约束，必须判断是否需要 L0。缺失时进入 Human Gate，用户确认后创建。

#### L1 项目规则

必须检查是否存在、是否覆盖项目定位、必读索引和项目专属硬约束。

#### L0 / L1 重复

若 L1 重复承载 L0 通用规则，应识别为规则边界重复。边界明确时可修改 L1，边界不明确时分类为待决策 Task 或 Memo。

### 2.3 Skill 与 Agent 评估

#### Skill

必须给出候选建议。用户选择某个 Skill 即视为确认，应立即创建工作区单份 Skill。创建完成后必须提示用户将该 Skill 应用到全局或确认当前工作区可用。

#### Agent

初始化时不得自动创建 Agent 或 Agent 定义。若用户需要 Agent，应提示用户先阅读 Trae 官方可一键导入的自定义智能体示例。创建、启用或修改 Agent 调度边界必须进入 Human Gate。

### 2.4 事实源目录评估

#### Memo 边界

若项目启用 `pm-kit-base/memos/`，必须检查 docs/03 是否只维护 Memo 索引，且未记录 Memo 文件位置、链接、状态、关闭原因、关联对象、负责人、处理进度或后续计划。边界规则见 specs-v2/10。

#### Change 记录目录

初始化时 AI 必须检查项目 Change 记录目录：

1. 检查 `pm-kit-base/changes/` 目录是否存在 → 判断项目是否已启用 Change YAML 记录

检测结果处理：

- 目录已存在 → 项目已启用 Change 记录，后续变更写入 `pm-kit-base/changes/`（YAML 格式，见 specs-v2/24）
- 目录不存在 → AI 提示用户是否创建 `pm-kit-base/changes/` 目录，所有项目均可产生 Change 记录

检测结果应写入初始化报告。

### 2.5 允许自动创建的内容

初始化场景中，以下缺失项允许自动创建：

- `product.yaml`
- `README.md`
- `docs/` 及相关审计文件（01/02/03/04/05/98/99/adr/bugs/）
- `.gitignore`
- `pm-kit-base/` 及子目录（tasks/tasksets/memos/changes/）

### 2.6 Human Gate 后创建的内容

以下缺失项必须先进入 Human Gate；用户明确确认后应直接创建正式资产，不停留在建议状态：

- L0 / L1 / L2 正式规则
- Skill

### 2.7 不得自动创建的内容

以下内容不得在初始化中自动创建，除非用户明确确认：

1. 20-89 需求文档；
2. ADR 正文；
3. 正式任务文件；
4. 跨项目契约文档；
5. 新依赖或新框架配置。

## 三、产出与分流

### 初始化报告

初始化完成后必须输出报告，至少包含：

```text
初始化完成：
- 产品：{product-name}（{项目数} 个项目）
- 产品类型：{单项目产品 / 多项目产品}
- 当前项目角色：{单项目产品 / 治理项目 / 子项目}
- 已存在：{数}
- 缺失（已自动创建）：{数}
- Human Gate 已确认并创建：{数和简要说明}
- Human Gate 未确认：{数和简要说明}
- Skill 建议：{已创建 / 未创建 / 不适用，列出名称；若已创建，说明是否已提示应用到全局}
- L0 / L1 边界：{清晰 / 存在重复已修正 / 存在重复待决策 / 不适用}
- Change 记录目录：{已存在 / 不存在（已提示创建）/ 不存在（用户未确认），所有项目均可产生 Change 记录}
- 建议下一步审计：规范审计 / 全量审计 / 不需要，并说明原因
```

### 缺口 → Task/Memo

初始化中发现的待决策事项（如 L0/L1 边界不明确、docs/03 与 Memo 边界问题），应分类为 Task 或 Memo，按 specs-v2/21、specs-v2/22 处理。

### 建议下一步审计

初始化报告必须明确建议用户是否执行审计。初始化创建或修改了 L0/L1 规则、Skill、04、98/99 或 pm-kit-base 时，默认建议执行规范审计；同时生成或变更 04 时，默认建议执行全量审计。审计流程见 specs-v2/51-PMKit审计流程。

## 四、Human Gate

以下操作必须等待人类确认后方可执行：

- 创建 L0 / L1 / L2 正式规则
- 创建 Skill
- 创建、启用或修改 Agent 调度边界
- L0 缺失时创建工作区规则

用户明确确认后应直接创建正式资产，不停留在建议状态。

## 五、检查要求

初始化完成后必须验证以下事项：

1. 不得自动创建需求文档、ADR 正文、正式任务文件或跨项目契约文档；
2. 不得自动创建 Agent 或 Agent 定义；
3. 不得自动添加新依赖或新框架配置；
4. 初始化结束不得只报告已创建资产，必须给出下一步审计建议；
5. Skill 创建完成后必须提示用户将该 Skill 应用到全局或确认当前工作区可用，不得只报告文件已创建；
6. 新建 docs 文件后必须更新该项目的 `project_rules.md` 必读文档索引；
7. 新建或修改文件后，必须创建 Change YAML 文件到 `pm-kit-base/changes/`（见 specs-v2/24）；所有项目均可产生 Change 记录。
