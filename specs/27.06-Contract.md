## 1. 本文定位

本文定义 Task 工作模型使用的结构化数据契约。本文解决 Task YAML 实例应包含哪些字段、字段类型和约束是什么、文件命名规则是什么、状态流转契约是什么，以及工具实现应如何消费本契约的问题。

本文是 Task 工作模型契约字段的权威位置。本文是 `specs/27-Task-任务.md` 的附件型契约子文档，不是独立工作模型。本文不得重新定义 Task 的对象定位、准入条件、状态机语义、Human Gate、事实源回写或证据留存要求。发生冲突时，以 27 主文档和上位基础规范为准。

本文不承载执行逻辑、流程步骤或 Human Gate 条款。

## 2. Task YAML Schema

### 2.1 基础字段

Task 基础字段遵循 `specs/07-工作模型基础规范.md` §7.3 的字段契约原则，所有工作模型应包含基础字段。

| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | Task 对象 ID，格式为 `task-{NNNN}` |
| `type` | string | 是 | 固定为 `task` |
| `title` | string | 是 | 任务标题 |
| `status` | string | 是 | Task 状态，必须属于标准状态枚举 |
| `created` | date | 是 | 对象创建日期 |
| `updated` | date | 是 | 最近更新日期 |

### 2.2 扩展字段

| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `description` | string | 是 | 任务详细描述 |
| `source_intent` | string | 否 | 关联 Intent ID |
| `source` | string | 是 | 来源（Intent ID 或用户直接指示） |
| `parent_task` | string | 否 | 父任务 ID，非空时表示本 Task 为子任务 |
| `sub_tasks` | list of string | 否 | 子任务 ID 列表 |
| `blocked_by` | list of string | 否 | 前置 Task ID 列表；列表中的 Task 全部关闭后，当前 Task 才允许进入执行态 |
| `acceptance` | string | 是 | 验收标准，必须使用检查列表格式（`- [ ]` / `- [x]`），每项为可独立验证的原子条件 |
| `verification` | string | 否 | 验证方式 |
| `assignee` | string | 否 | 执行者 |
| `related_adrs` | list of string | 否 | 关联 ADR ID 列表 |
| `related_changes` | list of string | 否 | 关联 Change ID 列表 |
| `closed_at` | date | 条件必填 | 仅当 `status` 为 `closed` 时必须填写 |
| `closure_evidence` | string | 条件必填 | 仅当 `status` 为 `closed` 时必须填写，关闭证据摘要 |

### 2.3 完整 YAML 示例

```yaml
id: task-0001
type: task
title: 创建 Intent 工作模型精简版规范
status: closed
created: 2026-06-03
updated: 2026-06-03
description: 按 21 ADR 结构创建 Intent 精简版规范，包含 7 个核心章节和 Contract 子文档
source_intent: intent-0001
source: intent-0001
parent_task:
sub_tasks: []
blocked_by: []
acceptance: |
  - [ ] 24-Intent-意图.md 文件存在且包含 7 个核心章节
  - [ ] 24.06-Contract.md 文件存在且包含完整 YAML schema
verification: 文件存在性检查 + 章节完整性检查
assignee:
related_adrs: []
related_changes: []
closed_at: 2026-06-03
closure_evidence: 24-Intent-意图.md 和 24.06-Contract.md 已创建，包含全部 7 个核心章节
```

## 3. 字段约束

1. `status` 必须属于 Task 标准状态枚举：`planned`、`executing`、`verifying`、`review_needed`、`closed`；
2. `type` 必须固定为 `task`；
3. `closed_at` 仅在 `status: closed` 时必填，其他状态下不得填写；
4. `closure_evidence` 仅在 `status: closed` 时必填，其他状态下不得填写；
5. `source_intent` 应引用已存在的工作模型 ID，引用无效时应标记为校验警告；
6. `related_adrs` 应引用已存在的工作模型 ID，引用无效时应标记为校验警告；
7. `related_changes` 应引用已存在的 Change ID，引用无效时应标记为校验警告；
8. `id` 格式必须为 `task-{NNNN}`，编号固定 4 位，从 `0001` 起递增；
9. `created` 和 `updated` 使用 ISO 8601 日期格式（`YYYY-MM-DD`）；
10. `closed_at` 使用 ISO 8601 日期格式（`YYYY-MM-DD`）；
11. `related_adrs`、`related_changes`、`sub_tasks`、`blocked_by` 为列表类型，可为空列表，不得省略字段后以 null 替代空列表；
12. `parent_task` 应引用已存在的 Task 工作模型 ID，引用无效时应标记为校验错误；
13. `parent_task` 不为空的 Task 不得被其他 Task 的 `parent_task` 引用（深度限制：子任务不能再有子任务）；
14. `sub_tasks` 应引用已存在的 Task 工作模型 ID，引用无效时应标记为校验警告；
15. `sub_tasks` 中的 Task ID 的 `parent_task` 必须等于本 Task 的 ID，否则标记为校验错误；
16. 父任务关闭前，所有 `sub_tasks` 中的 Task 必须已关闭（`status: closed`）；
17. `blocked_by` 应引用已存在的 Task 工作模型 ID，引用无效时应标记为校验错误；
18. `blocked_by` 不得引用当前 Task 自身；
19. Task 从 `planned` 进入 `executing` 前，`blocked_by` 列表中所有 Task 必须已关闭（`status: closed`）。

## 4. 文件命名契约

Task 实例文件命名规则：

```text
task-{NNNN}-short-title.yaml
```

约束：

1. 编号从 `0001` 起递增，固定 4 位；
2. 英文短标题使用小写短横线命名；
3. 每个项目独立编号，不使用跨项目全局编号；
4. 文件存放位置为 `ldvh-base/tasks/`；
5. 文件名变化必须同步检查所有引用该 Task 的 `related_tasks`、`source_intent` 和其他关联字段。

## 5. 状态流转契约

Task 状态语义和流转规则由 `specs/27-Task-任务.md` §5 定义，本文只提供结构化枚举和流转矩阵供 Tools 校验消费。

### 5.1 标准状态枚举

| 标准状态 |
|---|
| `planned` |
| `executing` |
| `verifying` |
| `review_needed` |
| `closed` |

状态含义依据 `specs/27-Task-任务.md` §5.1。

### 5.2 合法状态流转

| 当前状态 | 可流转至 |
|---|---|
| `planned` | `executing` |
| `executing` | `verifying` |
| `verifying` | `review_needed` |
| `verifying` | `executing`（退回） |
| `review_needed` | `closed` |
| `review_needed` | `executing`（退回） |
| `closed` | 无 |

退回流转应记录退回原因。流转触发规则和关闭条件依据 `specs/27.01-Rules.md`。

## 6. 契约消费声明

### 6.1 对象接口摘要

| 项 | 契约 |
|---|---|
| 对象类型 | `task` |
| 对象 ID | `task-{NNNN}` |
| 事实源目录 | `ldvh-base/tasks/` |
| 文件命名 | `task-{NNNN}-short-title.yaml` |
| 默认状态 | `planned` |
| 终态 | `closed` |
| 主要读取场景 | 执行上下文准备、状态检查、验收审计、关闭条件检查、Intent 级联检查 |
| 主要写入场景 | 创建 Task、状态流转、验收勾记、关闭证据回写、父子任务关联更新 |

### 6.2 Raw Object 接口

Task Raw Object 接口由本文 §2 至 §5 定义，包含：

1. 基础字段：`id`、`type`、`title`、`status`、`created`、`updated`；
2. 扩展字段：`description`、`source_intent`、`source`、`parent_task`、`sub_tasks`、`blocked_by`、`acceptance`、`verification`、`assignee`、`related_adrs`、`related_changes`、`closed_at`、`closure_evidence`；
3. 状态枚举：`planned`、`executing`、`verifying`、`review_needed`、`closed`；
4. 状态流转矩阵：本文 §5.2；
5. 条件必填：`status: closed` 时必须填写 `closed_at` 和 `closure_evidence`。

### 6.3 引用关系接口

| 引用字段 | 目标对象 | 必填 | 校验要求 |
|---|---|---|---|
| `source_intent` | Intent | 否 | 引用无效时标记为校验警告 |
| `parent_task` | Task | 否 | 引用无效时标记为校验错误 |
| `sub_tasks` | Task | 否 | 引用无效时标记为校验警告，且子任务 `parent_task` 必须等于当前 Task ID |
| `blocked_by` | Task | 否 | 引用无效时标记为校验错误；不得引用当前 Task 自身；当前 Task 进入 `executing` 前，列表中所有 Task 必须为 `closed` |
| `related_adrs` | ADR | 否 | 引用无效时标记为校验警告 |
| `related_changes` | Change | 否 | 引用无效时标记为校验警告 |

父子任务深度限制和父任务关闭前子任务状态要求依据本文 §3 和 `specs/27.01-Rules.md`。

### 6.4 消费者接口

| 消费者 | 消费方式 | 消费内容 | 测试或验证入口 | 同步触发 |
|---|---|---|---|---|
| `tools/ldvh_fact_validate.py` | 校验 | 文件命名、ID、type、status、必填字段、列表字段、closed 条件必填、`blocked_by` 引用和关闭状态 | `python3 -m pytest tests/tools/test_check_fact_model.py` | 本文字段、状态枚举、文件命名或条件必填变化时 |
| `tools/ldvh_fact_cli.py` | 创建、状态流转、删除、依赖查询 | 对象类型、目录、默认状态、必填字段、状态流转矩阵、前置任务阻塞、`blocked_by` / `blocks` 结构化查询、关闭条件 | `python3 -m pytest tests/tools/test_fact_model_cli.py` | 本文状态流转、必填字段、创建、查询或删除约束变化时 |
| `ldvh-close` Skill | 验收审计、关闭检查 | `status`、`acceptance`、`sub_tasks`、`closure_evidence`、`closed_at` | Skill 流程审查与实际 Task 关闭演练 | 关闭条件、状态流转或子任务规则变化时 |
| L0/L1 Rules | 运行时提醒 | 状态变更先于执行、前置任务阻塞、关闭条件、Human Gate 场景、子任务深度限制 | Rules 读取与执行检查 | Task 行为规则或 Contract 消费边界变化时 |
| AI | 遵守 | 创建、读取、更新、验收和关闭 Task 时按本文和 27.01 执行 | 当前 Task Dogfood 与 Fact Validator | 任一 Task 契约字段或状态规则变化时 |

### 6.5 通用消费声明

1. Tools 辅助程序解析 Task 时应依据本文定义的 YAML schema 和字段约束，不得自行扩张格式契约（依据 `specs/06-Python与Web工具规范.md §4` §6.1）；
2. Tools 辅助程序校验 Task 时应覆盖字段完整性、状态合法性、条件必填和引用有效性；
3. Tools 辅助程序读取 Task 时可依据本文状态枚举和字段契约执行状态筛选、详情解析和关联字段解析，但 Task 读取结果是否可作为当前执行依据由 27 主文档和 Skill 流程判断；
4. 实践子文档和工具可以消费本文契约，但不得复制维护契约字段第二事实源；
5. 修改本文契约属于规范变更，应评估 Human Gate 并记录 Change（依据 specs/22-Change-变更记录.md）；
6. 契约子文档应先于工具实现创建，工具实现不得在没有契约子文档的情况下自行定义字段名、字段类型或字段约束；
7. 本文契约变更时，消费本文的 Tools 实现和对应测试必须同步更新。

## 7. 检查项

检查本文是否被正确使用时，应确认：

1. Task YAML 实例字段是否完整，必填字段是否齐全；
2. `status` 是否属于标准状态枚举；
3. `type` 是否固定为 `task`；
4. `closed` 状态的 Task 是否已填写 `closed_at` 和 `closure_evidence`；
5. `source_intent` 引用的工作模型 ID 是否有效；
6. `blocked_by` 是否为 Task ID 列表、引用对象是否存在、是否避免自引用、当前 Task 进入执行态前前置 Task 是否均已关闭；
7. `related_adrs` 引用的工作模型 ID 是否有效；
8. `related_changes` 引用的工作模型 ID 是否有效；
9. 文件命名是否符合 `task-{NNNN}-short-title.yaml` 格式；
10. 状态流转是否合法，是否存在非法流转；
11. 终态 Task 是否存在重开情况；
12. 退回流转是否记录了退回原因；
13. 工具实现是否依据本文 schema 解析和校验，未自行扩张格式契约；
14. 修改本文是否记录 Change，并在必要时触发 Human Gate（依据 specs/22-Change-变更记录.md）；
16. `parent_task` 引用的 Task 工作模型 ID 是否有效（如有填写）；
17. `parent_task` 不为空的 Task 是否被其他 Task 的 `parent_task` 引用（深度限制）；
18. `sub_tasks` 中的 Task ID 的 `parent_task` 是否等于本 Task 的 ID；
19. 父任务关闭时，所有 `sub_tasks` 中的 Task 是否已关闭；
