# 环境入口适配与部署规范

> 创建日期：2026-06-13
> 定位：定义各 AI 开发环境如何通过环境入口接入、部署并适配检查 LDVH 能力资产，以及个人环境特别要求如何写入 Rules 入口
> 适用范围：环境入口、薄入口、环境适配、部署步骤、适配检查、个人环境特别要求写入、成功条件、失败处理、降级方式、Human Gate
> 上位依据：`specs/04-规范落地与环境适配基础规范.md`、`specs/04.02-LDVH能力资产与落地保障规范.md`、`specs/02-术语规范.md`
> 相关规范：`specs/07-Code确定性执行实现规范.md`、`specs/08-Web信息同步实现规范.md`、`specs/09-事实源边界与承载规范.md`

本文是 AI 帮用户执行环境接入和部署的直接依据。本文不定义 LDVH 能力资产本身，不记录长期用户本地安装状态，不把一次适配检查结果写成环境类型结论，不为个人环境特别要求新增独立事实源。

---

## 1. 本文解决的问题

本文解决以下问题：

1. 某个 AI 开发环境提供哪些环境入口；
2. 这些环境入口如何接入 04.02 定义的 LDVH 能力资产；
3. AI 如何在授权边界内帮助用户执行部署；
4. 部署前、部署后和声明完成前如何执行适配检查；
5. 创建或更新 Rules 入口时，个人环境特别要求如何写入 AI 可见入口；
6. 接入失败、环境不支持、权限不足或证据不足时如何降级或 Human Gate。

用户本地状态不是长期事实源。它只能来自本文定义的适配检查，并由 Code 输出、Web 当前视图、Human Gate 记录、Task、Memo、Pitfall 或 ADR 按性质承载。

---

## 2. 环境适配字段

每个环境入口适配项至少包含：

| 字段 | 必填 | 含义 |
|---|---|---|
| 环境类型 | 是 | 适用的 AI 开发环境类型 |
| 环境入口 | 是 | 该环境实际读取、加载、调用或触发的位置或机制 |
| 对应 LDVH 能力资产 | 是 | 04.02 中定义的 Rules、Skill、Agent、Hook 或其它能力资产 |
| 接入方式 | 是 | 薄入口、配置、安装、软链、受控复制、人工降级等 |
| 部署步骤 | 是 | AI 如何帮用户接入该资产 |
| 写入权限 | 是 | 是否可自动写入，是否需要 Human Gate |
| 适配检查 | 是 | 如何现场判断接入已生效 |
| 成功条件 | 是 | 满足什么才能声明本次接入有效 |
| 失败处理 | 是 | 缺入口、无权限、不可读、环境不支持时如何处理 |
| 适配降级 | 是 | 无原生入口时如何模拟或人工降级 |
| 禁止声明 | 是 | 哪些情况下不得声明原生完整支持或部署完成 |
| 证据输出 | 是 | 应呈现给 Human 的证据 |
| 证据状态 | 是 | 已验证、待验证、仅参考、待补齐或不适用 |

`docs/sources/` 和外部资料只能作为输入证据或待吸收材料，不能作为 specs 上位依据。正式适配结论必须写成已吸收结论、实测证据摘要、Human Gate 记录引用或待补齐事项。

---

## 3. 适配状态

| 状态 | 含义 |
|---|---|
| 原生承载 | 环境提供原生入口或机制承载对应能力资产 |
| 配置适配 | 通过配置、安装、路径、软链或等价方式接入 |
| 指令适配 | 通过环境指令、会话提示或薄入口显式引导 |
| 人工降级 | 缺少稳定环境入口，通过人工检查或手动命令替代 |
| 仅作参考 | 当前信息只能作为候选输入，不能声明可用 |
| 待确认 | 缺少来源证据、实测证据或 Human Gate 确认 |

适配状态不是用户本地安装状态，也不表示当前机器已经部署成功。

---

## 4. 部署与适配检查规则

### 4.1 部署前检查

部署前必须确认当前环境类型、当前工作区和目标项目边界、环境入口是否存在、目标 LDVH 能力资产是否存在、是否有写入权限、是否存在用户已有配置需要保护、是否存在需要写入 Rules 入口的个人环境特别要求、是否触发 Human Gate。

### 4.2 部署执行

部署执行应优先使用薄入口、配置、软链或安装方式。只有在环境明确无法引用、Human 授权且有退出方式时，才允许受控复制。

部署不得复制完整 specs 正文，不得创建第二事实源，不得覆盖用户已有配置而不保留说明。

创建或更新 Rules 入口时，应同步处理个人环境特别要求；需要 AI 进入环境后直接看见并执行的个人设置，应写入对应 Rules 入口的“个人环境特别要求”段落，而不是新增 specs 子文档或独立事实源。

### 4.3 部署后适配检查

部署后必须检查环境入口文件、配置或机制是否存在，薄入口是否指向正确的 LDVH 能力资产，目标资产是否可读，是否复制了不应复制的完整正文，是否满足成功条件，是否仍需 Human Gate。

### 4.4 声明完成前检查

AI 声明部署完成前必须输出证据摘要。证据至少包含环境类型、环境入口、对应 LDVH 能力资产、检查时间、检查方式、检查结论、失败项和降级项。

未完成适配检查时，不得声明部署完成。适配检查失败时，不得把失败写成环境类型不支持，也不得把人工降级写成原生完整支持。

## 5. 个人环境特别要求写入规则

个人环境特别要求是当前个人、维护者、工作区或 Human 授权场景中的特殊命令、路径、权限、安全、网络或工具约定。它们的目标是让 AI 在进入环境时直接看见并执行，不是新增 specs 子规范，也不是新增独立事实源。

创建或更新 Rules 入口时，AI 应将 Human 明确确认、当前项目 README、依赖管理说明或当前工作区配置中需要长期对 AI 可见的个人环境特别要求写入对应 Rules 入口的“个人环境特别要求”段落。该段落可以位于 LDVH 管理入口 Rules、工作区级薄入口或项目级入口 Rules 中，按实际生效范围选择。

个人环境特别要求写入 Rules 时至少应说明：

| 字段 | 必填 | 含义 |
|---|---|---|
| 要求 | 是 | 要求名称 |
| 内容 | 是 | AI 需要直接遵守的具体约束 |
| 适用范围 | 是 | 个人、维护者、当前工作区、当前环境或 Human 授权场景 |
| 影响动作 | 是 | 影响部署、写入、适配检查、命令执行或 Human Gate |
| 优先级 | 是 | 与 Human 当前指令、项目 README、依赖管理说明冲突时如何处理 |
| 退出条件 | 是 | 何时取消、替换或迁移该要求 |

以下类型可以写入 Rules 入口：

| 类型 | 示例 | 对部署和检查的影响 |
|---|---|---|
| 写入约束 | 不允许自动写 IDE 配置目录 | 部署步骤必须 Human Gate 或降级为手动说明 |
| 路径约束 | 某目录不可访问或必须使用特定路径 | 适配检查需使用当前可访问路径 |
| 命令约束 | 默认使用 `python3`，或按项目约定使用虚拟环境、`python`、`uv`、`poetry`、`pipenv` | Code 检查和部署命令需按约束执行 |
| 权限约束 | 不允许跨工作区写入 | 环境入口部署不得越界 |
| 网络约束 | 不允许联网或访问外部服务 | sources 查询或安装步骤需降级 |
| 安全约束 | 不允许写入密钥、Hook 或自动触发配置 | 相关部署必须暂停或降级 |

使用个人环境特别要求时应遵守：

1. Human 当前指令优先于 Rules 中既有个人环境特别要求；
2. 项目 README、依赖管理说明或项目配置优先于个人默认命令约定；
3. 未写入 Rules 且未被 Human 当前确认的个人要求不得假定启用；
4. 个人环境特别要求不得升级为 LDVH 通用跨环境规则；
5. 修改会影响写入位置、权限、密钥、网络或长期配置的个人要求前，必须暂停并经过 Human Gate；
6. 删除仍被部署、适配检查、Code 或人工提醒消费的个人要求前，必须确认没有当前入口依赖。

## 6. 环境适配项

### 6.1 Trae Work CN

| 能力资产 | 环境入口 | 接入方式 | 适配检查 | 适配降级 | 禁止声明 |
|---|---|---|---|---|---|
| Rules 资产 | Trae rules、AGENTS、用户级或工作区级可读规则入口，具体路径待验证 | 薄入口 / 配置适配 | 检查入口存在、薄入口指向 LDVH Rules 资产、未复制 specs 正文 | 会话显式要求 AI 读取 LDVH Rules 资产 | 未实测加载顺序和持久性前不声明完整支持 |
| Skill 资产 | Trae Skill 机制，具体目录和元数据要求待验证 | 安装 / 配置适配 / 薄入口 | 检查 Skill 入口存在、资产可读、描述保留边界 | 主控 AI 按 specs 手动执行 SOP | Skill 模拟 Hook 不得声明 Hook 原生完整支持 |
| Agent 资产 | Trae Agent / subagent / 独立上下文候选，待验证 | 配置适配 / 指令适配 / 人工降级 | 检查 Agent 输出是否回主控且不可直接生效 | 主控多视角审查 | 未验证独立上下文能力前不声明完整支持 |
| Hook 资产 | 原生 Hook / lifecycle 机制待确认 | 人工降级 / Command / Skill 提醒 / STOP 点 | 检查是否存在原生机制；若无，检查降级路径是否清楚 | 手动命令、Skill 提醒或人工清单 | Skill 模拟或人工提醒不得写成 Hook 原生完整支持 |

### 6.2 Codex App

Codex App 当前多数环境入口仍需证据和实测确认。未确认前，应以指令适配、待确认或人工降级表达，不声明完整支持。

| 能力资产 | 环境入口候选 | 接入方式 | 适配检查重点 | 禁止声明 |
|---|---|---|---|---|
| Rules 资产 | 项目说明、会话入口、instructions 候选 | 指令适配 / 待确认 | 是否可稳定加载薄入口 | 不声明持久入口完整支持 |
| Skill 资产 | 流程复用入口候选 | 指令适配 / 待确认 | 是否有稳定 SOP 调用机制 | 不声明原生 Skill 完整支持 |
| Agent 资产 | 子任务、独立视角或 Agent 候选 | 待确认 / 人工降级 | 输出是否回主控 | 不声明未验证 Agent 能力 |
| Hook 资产 | lifecycle / hook 候选 | 待确认 / 人工降级 | 是否有可验证触发机制 | 不声明未验证 Hook 能力 |

## 7. Human Gate 与检查要求

以下情况必须评估 Human Gate：

1. 写入、覆盖或删除用户环境入口；
2. 修改长期环境配置；
3. 启用自动触发、危险权限或跨工作区写入；
4. 受控复制 LDVH 能力资产全文；
5. 覆盖用户已有 Rules、Skill、Agent、Hook、instructions 或配置；
6. 声明任一环境完整支持 LDVH；
7. 将一次用户本地适配检查结果写成环境类型结论；
8. 新增、修改或删除 Rules 入口中的个人环境特别要求。

检查要求：

| 检查项 | 标准 |
|---|---|
| 入口定位 | 环境入口可定位或明确待确认 |
| 资产接入 | 对应 LDVH 能力资产存在且接入方式明确 |
| 部署权限 | 写入权限和 Human Gate 边界明确 |
| 适配检查 | 有部署前、部署后和声明完成前检查方式 |
| 降级说明 | 无原生入口时有适配降级和残留风险 |
| 个人环境特别要求 | 写入 Rules 的位置、适用范围、优先级和退出条件明确 |

## 8. 规范落地要求

| 落地要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 上位约束承接要求 | 环境入口适配与部署必须承接 04.02 的 LDVH 能力资产定义 | 本文、04.02、Human Gate | 环境部署治理 | 能力资产或部署字段变化时 |
| 入口可见要求 | AI 执行部署前应能定位本文和对应环境入口适配项 | Rules 资产、薄入口、人工提示 | AI 执行入口提示 | 环境入口或部署步骤变化时 |
| 确定性执行要求 | Code 应能按本文字段执行或辅助适配检查 | Code、命令、测试样例 | 校验实现 | 字段稳定后 |
| Human 交互要求 | 写入环境入口、声明完整支持或覆盖用户配置前必须暂停确认 | Human Gate、Web、对话确认 | 部署确认 | 高影响部署动作前 |
| 生命周期触发要求 | 环境入口、LDVH 能力资产或部署证据变化后应重新适配检查 | Hook 资产、CI、人工检查 | 触发保障 | 环境或资产变化时 |
| 入口可见要求 | 创建或更新 Rules 入口时，应把需要 AI 直接看见的个人环境特别要求写入对应入口 | Rules 资产、Human Gate、当前项目 README、依赖管理说明 | AI 执行入口提示 | 个人环境要求影响部署、写入、命令或检查时 |
| 确定性执行要求 | 受个人环境影响的命令调用应可通过实际命令或等价验证确认 | 命令验证、Code、人工检查 | 命令验证 | 工具入口、解释器、依赖管理变化时 |

## 9. 待补齐事项

1. Trae Work CN 真实 rules、Skill、Agent、Hook 入口路径和加载顺序需补 sources 和实测证据；
2. Codex App 的 instructions、Skill、Agent、Hook 候选入口需补 sources 和实测证据；
3. 后续 Code 应实现环境入口适配字段和适配检查输出；
4. Web 可展示环境入口适配项、适配降级和待补齐事项的派生态势；
5. Code 使用入口需要同步本文对解释器、命令和权限约束的查询规则。
