## 一、本文定位

本文是 `specs/21-ADR-决策记录.md` 的附件型实践子文档（编号 21.01），承接 Rules 入口实践。本文不是独立事实模型，不得重新定义 ADR 的对象定位、准入条件、状态机、对象关系、Human Gate、字段契约、事实源回写或证据留存。发生冲突时，以 21 主文档和上位基础规范为准。

---

## 二、实践目标

让 AI 在编辑 `ldvh-base/adrs/`下 YAML 文件或调用 ADR Tools 写入命令前，自动识别 ADR 准入条件、状态机约束、Human Gate 要求和 Tools 授权边界，减少违规创建、非法状态流转和未授权写入。

---

## 三、适用场景

1. AI 判断某个决策是否应创建 ADR 时；
2. AI 编辑 ADR YAML 实例的状态字段时；
3. AI 调用 ADR Tools 执行 `create`、`transition`、`link-rule`、`deprecate` 或 `supersede` 等写入命令时；
4. AI 尝试推翻、废弃或升级已 accepted ADR 时。

---

## 四、实践边界

1. 本实践只约束 Rules 层对 ADR 的入口提示和禁止承载内容；
2. ADR 的完整准入条件、状态机、Human Gate 和字段契约由 21 主文档定义；
3. ADR 的可复用创建/升级/推翻流程由 21.02-Skill.md 承载；
4. ADR Tools 写入命令的具体参数、校验和执行边界由 21.04-Tools.md 承载；
5. 本实践不替代 21 主文档的任何章节。

---

## 五、实践内容

### 5.1 L0 事实模型规则增强

在 `ldvh-l0-fact-model-rules.md` 中增加 ADR 相关约束：

1. 编辑 `ldvh-base/adrs/`下 YAML 文件时，应检查 ADR 准入条件（21 §3.3）；
2. ADR 状态流转必须合法（21 §5.2），终态不可重开；
3. ADR 状态变更先于执行（13 §6.2）；
4. `proposed → accepted`、`accepted → deprecated`、`accepted → superseded` 必须触发 Human Gate（21 §7.1）；
5. 调用 ADR Tools 写入命令前，应确认已获得 Human Gate，并显式传入授权参数；
6. 不得将 ADR Tools 的 `draft` 输出或 `proposed` ADR 当作执行依据。

### 5.2 禁止承载内容

Rules 入口不得承载以下内容：

1. ADR 完整准入条件列表；
2. ADR 状态机完整定义；
3. ADR 字段契约；
4. ADR 对象关系转化规则；
5. ADR 事实源回写规则；
6. ADR 证据留存要求。

以上内容由 21 主文档承载。

---

## 六、Human Gate

1. 将 ADR 相关约束从 L0 事实模型规则中移除时，应经 Human Gate 确认；
2. ADR 准入条件或状态机约束变更影响 L0 事实模型规则时，应经 Human Gate 确认。

---

## 七、检查项

检查 ADR Rules 入口是否合规时，应确认：

1. L0 事实模型规则是否包含 ADR 准入条件检查、状态机约束和 Human Gate 提示；
2. L0 事实模型规则是否未复制 21 主文档的完整准入条件、状态机或字段契约；
3. AI 编辑 ADR YAML 时是否自动检查状态流转合法性；
4. AI 调用 ADR Tools 写入命令前是否确认 Human Gate，并传入显式授权参数；
5. AI 是否未将 `proposed` 状态 ADR 或 ADR Tools `draft` 输出作为执行依据。

---
