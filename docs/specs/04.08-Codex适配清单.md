# Codex 命令行形态历史资料说明

> 收口日期：2026-06-11
> 定位：保留 Codex 命令行形态旧资料的历史入口，说明其与当前 Codex App 环境投射的边界
> 适用范围：Codex 命令行形态历史资料、旧 refs 线索、Codex App 投射待核对事项
> 上位依据：`docs/specs/04.03-环境能力清单与投射规范.md`、`docs/specs/04.06-环境能力清单规范.md`

---
## 1. 本文解决的问题

本文不再作为 Codex App 当前环境投射事实源，也不再维护独立 Codex 要求响应矩阵。

Codex App 当前环境能力清单、投射方式、投射检查、投射降级和待补齐事项，以 `docs/specs/04.03-环境能力清单与投射规范.md` 为准。

本文只保留为 Codex 命令行形态历史资料，用于后续核对：

1. 哪些旧入口、事实源边界、Human Gate、命令验证和降级原则可以抽象迁入 04.03；
2. 哪些命令行形态专属能力不得迁入 Codex App；
3. 哪些旧 refs 需要重新核对是否适用于 Codex App；
4. 哪些旧能力只能写为待确认、人工降级或不迁移。

---
## 2. 迁移边界

| 内容类型 | 处理方式 |
|---|---|
| 入口薄引用、事实源边界、Human Gate、命令验证、降级原则 | 可作为抽象迁移线索，需按 04.03 字段重写 |
| 命令行形态专属能力、专属配置路径、专属权限模型、专属自动化能力 | 不得直接迁入 Codex App 投射方式 |
| 旧完整支持类结论 | 不迁移为当前结论 |
| 非 LDVH 能力保障范围内容 | 不迁入 04.03 当前能力保障范围 |
| 旧承接口径 | 改写为 LDVH 主动环境投射口径 |

---
## 3. 使用规则

AI 需要处理 Codex App 环境投射时，应先读取 `docs/specs/04.03-环境能力清单与投射规范.md`。

只有在需要追溯 Codex 命令行形态历史资料时，才读取本文。读取本文后，AI 必须执行以下检查：

1. 该内容是否明确适用于 Codex App；
2. 是否有 Codex App refs、官方资料或当前实测证据支持；
3. 是否只是命令行形态专属能力；
4. 是否属于 LDVH 能力保障范围；
5. 是否需要写成待确认、人工降级或不迁移。

不得把本文中的命令行形态能力、配置路径、权限模型、自动化触发或工具连接描述直接写成 Codex App 当前支持证据。

---
## 4. Human Gate 与检查要求

以下情况必须触发 Human Gate：

1. 将本文重新作为 Codex App 当前事实源；
2. 声明 Codex App 已完整支持 LDVH；
3. 删除、重命名或移动本文；
4. 把命令行形态旧结论直接写成 Codex App 当前结论；
5. 启用长期入口、自动触发、跨工作区写入或高影响配置。

检查本文时，应确认：

| 检查项 | 标准 |
|---|---|
| 当前事实源 | Codex App 当前投射以 04.03 为准 |
| 历史边界 | 本文只作为命令行形态历史资料 |
| 证据状态 | 未把旧命令行形态资料写成 Codex App 已验证 |
| 投射主体 | LDVH 主动投射，Codex App 只提供客观能力清单 |
| 降级路径 | 证据不足时写为待确认或人工降级 |
