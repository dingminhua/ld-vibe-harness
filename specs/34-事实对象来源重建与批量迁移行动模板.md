## 1. 价值判断

来源重建和批量迁移会重复出现“冻结闭集、逐项语义审核、建立逻辑映射、全量无写预演、可恢复应用、回读、图检查、分批提交、锚定和重跑”这组稳定关系。缺少统一结构时，AI 容易把库存数量写成迁移完成，把 legacy 状态、时间与 `related_*` 直接复制为当前事实，或在部分失败后无法判断已写、未写和残留范围。

本模板用一条可复核的行动链保持源、语义决定、逻辑目标、实际新身份、载体 bytes、回读、提交与失败状态可追溯。它不把项目特定 ledger Schema、批次大小、具体命令、事实内容或类型判断固定成普遍规则。

只迁移一个对象时仍可以使用本模板中与实际风险匹配的最小切片；不涉及旧源承接、只是普通创建或更新时使用 31 或 32，不因本模板存在而扩张为批量迁移。

## 2. 规范依据

本文直接依据：

1. `action-template-foundation`：规定具体模板的准入、适用、授权、步骤、验证、回写与交还边界；
2. `fact-model-foundation`：规定来源派生新对象、当前类型/初态、新身份/时间、语义 payload、可恢复应用和无法承接时的成立边界；
3. `source-of-truth-traceability`：规定工作树、来源作用、Git 可追溯性、提交与引用范围。

具体事实类型的唯一来源、当次 Human 决定、项目级闭集/账本契约、实际工作树、实现能力和 Git 行动按当次作为输入。本文不复制它们的 Schema、状态、证据充分性或提交契约。

## 3. 职责边界

本文负责定义：

1. 一次来源重建或批量迁移的适用与排除边界；
2. 冻结源、逐项审核、logical target plan、dry-run、apply、回读、关系修复、Git anchor 与 no-op rerun 的稳定步骤依赖；
3. 1:1、1:N、N:1 和跨类型映射中防止源遗漏与目标漏回指的行动检查；
4. 分批执行、崩溃恢复、冲突、回读失败、部分成立与残留的分流；
5. 最终闭集、全图、Git 历史、幂等重跑和未完成范围的交还。

本文不负责定义：

1. 事实类型、字段、状态、初态、关系语义、证据充分性或召回逻辑；
2. 具体 ledger、journal、receipt、batch manifest 的 JSON/YAML 字段或路径；
3. allocator、文件锁、原子写入、CAS、图算法、指纹或恢复协议的实现；
4. 任一源的具体 V4 类型、目标内容、拆分/合并、关系或证据判断；
5. 自动把历史 ID、时间、状态、字段、路径或关系提升为当前 V4 事实；
6. Git commit、push、发布、删除旧源或扩大 Human 授权。

## 4. 适用范围

当 Human 要求把一个明确闭集的历史、旧版或外部结构化源按当前事实模型全量承接，且任务需要反复处理语义审核、拆分/合并、无写预演、分批应用、恢复和闭集证明时，本模板进入候选。

只是复制载体、改路径、导入同一对象身份、创建普通新对象、更新已有对象、只做调查或没有明确 Human 迁移目标时，不执行批量迁移分支。可以继续只读冻结、准备决策或转入 31、32 与普通 Git 行动。

## 5. 事实对象来源重建与批量迁移行动模板定义

### 行动模板声明

| template_key | summary | definition_ref |
|---|---|---|
| `fact-object-source-reconstruction-migration` | 对已冻结来源逐项审核并建立当前合法初态新对象，经全量 dry-run、可恢复分批应用、完整回读、Git anchor 和 no-op rerun 闭合全部源 | `fact-object-source-reconstruction-migration-action-template::5. 事实对象来源重建与批量迁移行动模板定义` |

### 5.1 输入与前置条件

执行者必须取得并区分：Human 对源闭集、目标范围和写入副作用的当前决定；实际管辖项目与 Git worktree/common-dir；冻结源集、版本、路径、内容指纹和闭集验证器；当前 05 与目标类型唯一来源；项目级 ledger 契约与当前状态；当次实际 dry-run/apply/recovery/readback/Git 能力；执行前已有的无关工作树变化。

数量统计、文件可解析、历史状态、机械候选、聊天记忆、旧迁移记录或模板命中不能代替上述输入。缺少语义 ledger、可验证 dry-run 或可恢复能力时，只能继续与缺口无关的只读阶段。

### 5.2 参与者、能力与授权

AI 负责展开当前来源、逐项语义审核、形成逻辑目标内容和映射、判断来源/证据/关系的实际作用、核对授权、解释机械结果并交还未决范围。Human 承担依当前规则必须由其决定的承接位置、无法归类、事实取舍、具体 WorkCase 建立意图、写入、提交与风险接受。

Code 只负责它的当前契约已明确交给机械检查的闭集、Schema、指纹、映射对称、分配、写入、回读、图、journal、幂等与锚定范围。subagent 审核不自动成为某个目标 WorkCase 的 `creation_reviews`、结果审核或 Human approval；每个目标仍须满足其类型当次真实条件。

### 5.3 行动步骤与分支

#### A. 固定授权、源闭集与无关基线

1. 明确项目、源集合、完成口径、是否要求每个源有实际 target，以及 Human 已决与未决范围；
2. 以不可变版本、路径、bytes 和指纹验证源闭集，拒绝重复、缺失、增量和漂移；
3. 记录执行前已有且不归迁移所有的工作树变化，后续只比较它们是否原样保持；
4. 无法确定管辖、版本或闭集时，停止语义进度与全部写入。

#### B. 逐项语义审核与 logical target plan

1. 按源稳定 key 逐项区分仍有价值的事实、应退出的旧实现细节、来源与证据缺口；
2. 按当前事实类型唯一来源判断不对象化、新对象、拆分、合并或跨类型承接；本模板的项目级要求可以排除“只保留 archive”作为完成结果；
3. 为每个逻辑目标分配与实际 V4 ID 无关的 stable logical target key，双向记录全部 source keys；
4. 为每个目标形成包含目标 `fact_type_key`、只排除 `object_id`、`created_at` 和 `updated_at` 的完整语义 payload，并记录当前合法初态、来源、证据候选和待建关系；
5. 旧终态只是源观察，不推导 V4 终态；旧时间不猜时区、不写入 V4 托管时间或 `observed_at`；
6. 一项无法合法承接时，只暂停该逻辑目标并进入 Human Gate，其它已独立完成审核的项仍可继续零写入准备。

#### C. 全量闭集检查与无写 dry-run

1. 检查每个源恰有一个主 ledger 项，每个 logical target 反列全部贡献源，1:N 与 N:1 两方向对称；
2. 验证目标类型、合法初态、Schema、必填语义、来源/证据 shape、logical relations 和待 Human 项；
3. 对每个包含目标 `fact_type_key`、只排除 `object_id/created_at/updated_at` 的 canonical 语义 payload 计算 `semantic_payload_sha256`，重跑必须一致；除类型外字段相同但 `fact_type_key` 不同的目标必须得到不同摘要，类型变化必须使旧 dry-run 与 intent 失效；
4. 明确 dry-run 不预留 ID、创建时间、路径或最终 bytes，不将候选 ID 写入关系或 receipt；
5. 任一闭集、映射、Schema、指纹或未决条件不成立时，零写入停止 apply。

#### D. 形成批次、应用与恢复

1. 按目标依赖和待建关系形成稳定 batch plan；先建立独立合法初态节点，目标存在后再处理当前类型允许的关系；
2. 每个批次实施前重新核对源、ledger、语义 payload、当前 Schema、工作树、授权和已有 journal；
3. 在 allocator 临界区消费实际新身份并取得当前创建时间，生成最终载体 bytes 与 `materialized_sha256`；如果此时崩溃且尚未建立 intent，只允许留下不复用的 allocator gap，不得发布目标；
4. 在目标发布前先持久化 durable attempt intent，绑定 logical target key、目标 `fact_type_key`、`semantic_payload_sha256`、实际稳定引用、已消费身份/时间和预期 `materialized_sha256`；intent 未持久化时不得写目标；
5. intent 持久化后才原子 no-overwrite 发布目标，并把写入结果推进到 journal；发布前目标已存在或发布结果不可确定时不覆盖，进入恢复检查；
6. 每次写后立即从实际 Working Tree 回读并推进 journal；回读失败时只能按当前恢复契约确认删除本次 bytes、保留残留或停止，不猜测回滚成功；
7. 进程崩溃或重启后先根据 intent/journal、目标文件和指纹确定无 durable binding、intent 已建但目标缺失、已物化、已回读、冲突或不可判断；已有相同 durable binding 使用原实际 ref 恢复/no-op，不重新分配，不同绑定 fail closed；
8. 一个批次部分成立时不继续下一批，保留精确的已消费身份、已建 intent、已写、未写、回滚、残留和不可判断范围。

#### E. 完整回读、关系与 Git anchor

1. 对当批全部实际 ref 使用当前事实读取边界完整回读，核对载体、Schema、指纹、来源和未完成范围；
2. 只在全部必需节点存在后建立已经逐项语义审核且当前类型允许的单向关系；不从 legacy `related_*` 自动生成，不用 `supersedes` 制造历史终态；
3. 执行当前项目全图检查，对缺失目标、类型/状态不符、基数、时间、自指和 DAG 失败 fail closed；
4. 组合 Git 提交行动时，只纳入当批所有的 facts、ledger/journal 状态与 batch digest，保留执行前无关 dirt；
5. batch commit 完成后回读 commit/tree/路径；由后续 anchor/finalization commit 回填并验证前一批 commit SHA，不让当批对象或 receipt 预写自身提交身份。

#### F. 闭集、no-op rerun 与交还

1. 验证全部源均完成语义审核且在项目契约要求时至少有一个实际 target，全部 target 反列完整源集；
2. 验证每个实际对象、来源、证据、关系、materialized digest、batch commit 与 anchor 均可回指；
3. 在相同源、ledger、Schema 和工作树上重跑完整 dry-run/apply，要求零新 ID、零新写入、零指纹漂移和零新 commit；
4. 对无法承接、未决、部分、冲突、残留、未验证或无锚定项逐一交还，不用总数、某一批成功或命令退出码覆盖；
5. 只有项目级完成契约的全部条件都有当前证据时，才声明迁移闭合。

### 5.4 输出、验证、回写与交还

交还至少区分：管辖项目与实际 worktree；冻结源版本、指纹与闭集；Human 已决/未决项；每个源的语义审核状态；logical target 及双向映射；semantic payload 与 dry-run 指纹；实际 ID、路径、载体指纹、journal 和回读；关系全图；batch commit 与 anchor；no-op rerun；无关 dirt 前后一致性；失败、残留、未决、未验证和后续行动。

语义决定只回写项目级稳定 ledger，实际事实内容只写入目标类型唯一允许位置，执行尝试只回写项目契约允许的 journal/receipt。账本不复制目标事实权威，对象不复制自身 commit SHA，archive 不因迁移完成自动删除。

### 5.5 组合、变更与退出

本模板可以组合 Git 提交模板，但映射/dry-run/apply 成立不使 commit 自动授权，commit 成功也不证明迁移闭合。单对象普通创建和后续生命周期变化可以复用 31/32 的当前边界，但不得用它们绕过本模板的源闭集、映射和恢复要求。

迁移稳定步骤、适用、失败或交还边界改变时按 06 重审。若未来确定性服务能在不丢失逐项语义判断、Human Gate、恢复和 Git 可追溯性的前提下更低成本承接，应缩减或退出本模板，不保留一套平行事实工作流。

## 7. Human Gate

以下事项按 05、具体类型来源和项目级契约进入 Human Gate：源闭集或完成口径改变；无法从当前类型合法承接；拆分/合并或取舍会丢失实质内容；来源或证据不足；新建某个 WorkCase 需要当前 Human 工作意图；执行生产写入；提交、删除旧源、接受不可恢复残留或扩大原授权范围。

Human 已对同一项和同一作用范围清楚决定时不重复请求；但 Human 决定不能代替逐项语义审核、Schema、合法初态、来源/证据充分性、写后回读、全图、恢复或 Git 验证。

## 8. Stop Conditions

出现以下任一情况时，暂停受影响的审核、dry-run、批次、写入、关系、提交或完成声明：

1. 管辖项目、实际 worktree/common-dir、Human 目标或写入授权无法确定；
2. 源闭集、版本、路径、bytes、指纹或数量漂移，却准备继续消费旧 ledger；
3. 把机械 characterization、类型/状态同名、标题相似或 legacy 关系写成语义审核完成；
4. 一个源没有主 ledger 项、一个目标没有反列全部源，或拆分/合并两个方向不对称；
5. 准备添加历史伪类型、专用终态、占位目标，或把旧状态直接导入 V4 终态；
6. 准备复用旧 ID，猜测缺失时区，或把旧时间/迁移时点冒充历史领域事件、`closed_at` 或 `observed_at`；
7. 目标不是当前类型合法初态，必填语义、来源或证据不成立，却准备为通过 Schema 补占位内容；
8. dry-run 产生副作用、预留 ID/时间，或把 semantic payload digest 声称为最终载体 digest；
9. 映射、Schema、语义 payload、授权或工作树已改变，却准备消费过期 dry-run；
10. apply 覆盖既有文件、重用已消费 ID、在 durable attempt intent 持久化前发布目标、写后未回读，或崩溃后准备猜测已完成状态；
11. 节点未完整建立就写关系，从 legacy `related_*` 自动生成关系，或用 `supersedes` 制造历史终态；
12. 批次部分成立、回读失败、指纹冲突、残留或不可判断后准备继续下一批；
