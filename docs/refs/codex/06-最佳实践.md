## 1. 结论摘要

Codex CLI 的最佳实践围绕四个核心原则：始终使用 PTY、Git 仓库必须、单次任务用 exec、构建任务用 --full-auto。AGENTS.md 应保持简洁、结构化、包含具体示例和明确禁止项。沙箱选择应根据场景匹配安全级别。并行执行可通过 worktree 和多进程实现。成本控制需关注推理强度和上下文窗口。

## 2. 官方推荐的使用方式

1. **始终使用 pty=true**：Codex 是交互式终端应用，没有 PTY 会挂起
2. **Git 仓库必须**：Codex 拒绝在非 Git 目录运行。临时任务用 mktemp -d && git init
3. **单次任务用 exec**：codex exec "prompt" 运行后干净退出
4. **构建任务用 --full-auto**：沙箱内自动批准变更
5. **长任务用后台模式**：background=true + process 工具监控
6. **不要干预**：用 poll/log 监控，耐心等待长任务完成
7. **并行执行**：可以同时运行多个 Codex 进程处理批量工作

## 3. AGENTS.md 写法建议

- 保持简洁，远低于 32KB 上限
- 用 ## 分区组织（Architecture / Conventions / Important Notes）
- 包含具体示例（代码模式、API 形状、命名约定）
- 明确说明"不要做什么"（如 "never modify migration files directly"）
- 列出关键路径和端口
- 随项目演进更新——过时的上下文比没有上下文更糟

### 3.1 子目录 AGENTS.md（monorepo）

```markdown
<!-- frontend/AGENTS.md -->
# Frontend Context
- Use pnpm not npm
- Components go in src/components/, pages in src/app/
- Use Tailwind CSS, never inline styles
```

## 4. 沙箱选择建议

| 场景 | 沙箱模式 | 审批策略 |
|------|----------|----------|
| 日常开发 | workspace-write | on-request |
| 探索陌生代码 | read-only | untrusted |
| CI/CD 自动化 | workspace-write | never |
| 高风险操作 | workspace-write | untrusted |

## 5. 并行执行模式

### 5.1 Worktree 模式

```bash
# 创建 worktrees
git worktree add -b fix/issue-78 /tmp/issue-78 main
git worktree add -b fix/issue-99 /tmp/issue-99 main

# 在每个 worktree 中启动 Codex
codex --yolo exec 'Fix issue #78. Commit when done.'  # workdir=/tmp/issue-78
codex --yolo exec 'Fix issue #99. Commit when done.'  # workdir=/tmp/issue-99
```

### 5.2 PR 审查

```bash
codex review --base origin/main
```

### 5.3 CI/CD 集成

```bash
codex exec "Run the full test suite and report any failures"
```

## 6. 成本控制

1. 推理强度：日常任务用 low/medium，复杂推理用 high，避免 xhigh（23 倍 token）
2. 上下文窗口：按需配置，不必总是使用最大值
3. 单次任务：使用 exec 模式避免交互式会话的额外开销
4. --max-turns：限制最大轮次防止失控循环

## 7. 常见陷阱

1. 非 Git 目录无法运行——需先 git init
2. 没有 PTY 会挂起——确保终端环境正确
3. xhigh 推理强度可能导致 50+ 分钟挂起
4. 过时的 AGENTS.md 比没有上下文更糟
5. --yolo 模式无沙箱无审批，仅适用于可信环境
6. v0.120.0-v0.120.2 存在 stdin 死锁问题，需升级
