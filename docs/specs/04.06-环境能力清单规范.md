# 旧环境清单迁移输入说明

> 创建日期：2026-06-09
> 收口日期：2026-06-11
> 定位：保留旧环境能力清单的迁移入口，说明旧环境清单如何迁入当前环境能力清单与投射规范
> 适用范围：旧环境清单迁移、旧 04.07 / 04.08 历史资料收口、42 与 Code 对齐前的引用保护
> 上位依据：`docs/specs/04-规范落地与环境适配基础规范.md`、`docs/specs/04.03-环境能力清单与投射规范.md`

---
## 1. 本文解决的问题

本文不再维护独立环境矩阵，也不再作为当前环境投射事实源。

当前环境能力清单、环境投射卡片、投射检查、投射降级和新增环境规则，以 `docs/specs/04.03-环境能力清单与投射规范.md` 为准。

本文只保留三个用途：

1. 说明旧环境清单已经收口为迁移输入；
2. 防止历史引用断裂；
3. 为后续删除、重命名或历史化旧 04.06 / 04.07 / 04.08 提供 Human Gate 边界。

---

---
## 3. 旧内容边界

旧环境矩阵中的旧环境分类、旧承接口径、未纳入当前环境范围的环境列、命令行形态专属能力、非 LDVH 能力保障范围内容和未实测完整支持结论，不再作为当前正式规范结论。

AI 处理旧引用时，应按以下顺序执行：

1. 先读取 `docs/specs/04.03-环境能力清单与投射规范.md`；
2. 再判断旧引用是否只是需要历史迁移线索；
3. 若需要 Trae 旧资料，读取 `docs/specs/04.07-Trae-Solo适配清单.md`；
4. 若需要 Codex 命令行形态历史资料，读取 `docs/specs/04.08-Codex适配清单.md`；
5. 不得把旧文件中的环境能力、旧矩阵列或旧工具能力直接写成当前环境投射结论。

---
## 4. 42 与 Code 对齐要求

42 和 Code 后续应从旧环境清单迁移到 `docs/specs/04.03-环境能力清单与投射规范.md`。

对齐完成前：

1. 旧 04.06 / 04.07 / 04.08 不得删除；
2. 旧文件不得作为当前完整支持依据；
3. 旧文件只作为迁移输入、历史资料或引用保护入口；
4. 42 报告若读取旧文件，应说明当前事实源是 04.03；
5. Code 校验应优先补齐 04.03 投射卡片字段、来源边界、待确认状态和降级字段检查。

---
## 5. Human Gate 与检查要求

以下情况必须触发 Human Gate：

1. 删除、重命名或移动旧 04.06 / 04.07 / 04.08；
2. 允许旧文件重新成为当前环境投射事实源；
3. 将旧文件中的未验证环境能力写成当前完整支持结论；
4. 在 42 或 Code 未完成对齐前移除引用保护入口；
5. 改变旧文件的迁移输入职责。

检查旧环境清单收口状态时，应确认：

| 检查项 | 标准 |
|---|---|
| 当前事实源 | 已指向 `docs/specs/04.03-环境能力清单与投射规范.md` |
| 旧内容边界 | 未把旧矩阵内容作为当前投射结论 |
| 引用保护 | 历史引用不会断裂，且能导向 04.03 |
| 删除条件 | 删除前需要引用迁移、Code 校验和 Human Gate |
| 42 对齐 | 42 后续消费 04.03，而不是消费旧矩阵正文 |
