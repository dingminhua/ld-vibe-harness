## 一、总览结论

1. **"单一薄 Skill 默认接入"的决策获得全环境实证支持**：七个环境（六份报告 + Kimi Work）全部具备已验证或可用的技能/指令文件机制，没有任何环境把插件作为信息层的唯一选择。六份报告一致推荐 Skill 为默认信息层。
2. **自动触发层分化明显**：SessionStart 真实注入已在 **Codex Desktop 与 ZCode** 两个环境获得当次 cold start 证据（`source=startup`、`outcome=ok`、`facts=not_requested`）；TRAE 因 hooks.json 格式错误实际未触发；Codex-Cindy 配置就绪但无法区分 hydrate；Claude Code 未配置；WorkBuddy 引擎可用但 LDVH 插件为 V3 遗留且已禁用。
3. **Git Gate 是唯一跨环境一致的阻断层**：四个报告独立确认本 worktree "LDVH owns the current Git commit-msg Hook"；但**真实 commit 阻断行为在所有环境均未实测**，且事实 Schema 校验缺口（spark-0039 第 1 项）在全环境一致存在。
4. **PreToolUse guardrail 全环境均未部署**，且 Codex 的 deny 能力出现报告间矛盾（见三.3），需以当前官方资料复核。
5. **现有共享 SKILL.md 内容已过期**：它声称"Claude Code 没有 SessionStart 自动注入插件"，被三个报告分别标记为不准确——这是当前最迫切的单项修正。

## 三、跨环境关键发现

### 1. Skill 已是事实上的跨环境通用层，但"一个文件"扛不住分环境状态差异

现有 `~/.claude/skills/ldvh/SKILL.md` 被 Claude Code 直接使用、被 TRAE/ZCode 经 `~/.agents/skills` 共享或符号链接复用——"只装一个"已经实际发生。但它的内容写了死的环境判断（"Claude Code 没有 SessionStart 自动注入插件"），在 ZCode/Codex Desktop（已验证有注入）和 TRAE（支持但未配置对）下均不准确。**结论：Skill 内容必须环境中性——只描述 LDVH 入口与纪律，不断言任何环境的自动触发状态**；分环境状态留给各环境接入验证报告或 `ldvh-doctor` 如实表达。

### 2. "必然注入"的验证证据首次转正，但覆盖仍薄

pitfall-0001 记录的"ZCode 已装已注册但零触发"已被 ZCode 报告当次 cold start 证据翻转（source=startup 真实触发）；Codex Desktop 同获证据。但六个环境只有两个拿到当次证据，且均标注"跨重启持续有效"未验证。这印证了形态决策的正确性：自动触发层可以work，但获得证据的成本就是高——Skill 默认、插件证据触发的分层不变。

### 3. Codex PreToolUse deny 能力出现报告间矛盾（未决）

- Codex Desktop 报告：环境能力**已验证支持**（可阻断或改写调用）；
- Codex-Cindy 报告：**"肯定不支持"**（当前 hook 机制无 deny 语义）；
- spark-0029（2026-07-24 官方资料）：PreToolUse 可 deny、注入 additionalContext、限范围内改写输入。

三者不一致，且"肯定不支持"是最强断言，按 09 §5.6 需要肯定性证据才能成立。**处理：以 Codex 当前官方 Hooks 资料复核为准，复核前 guardrail 相关设计不对 Codex 做任何假设。**

### 4. TRAE 的 Git Gate"未安装"判断是观察假象

TRAE 报告以 `ldvh-doctor` 的 `config_status=missing` 判 Git Gate 未安装；但 Codex Desktop、Claude Code、Codex-Cindy、WorkBuddy 四份报告均通过 `ldvh-git-hook status` 独立确认本 worktree Hook 由 LDVH 管理。差异来源是 doctor 需要父级工作区的管辖配置（TRAE 报告以仓库根为 workspace-root）。**教训：doctor 的 attention/unavailable 不等于入口不存在，与 09 §6.2 定位一致。**

### 5. 各环境特有的待处置项

| 环境 | 事项 | 处置 |
|---|---|---|
| TRAE | `~/.trae-cn/hooks.json` 格式错误（Claude Code 格式）+ 无效 SubagentStart 条目 | 修正为 TRAE 原生格式或移除；适配器失败路径 `systemMessage` TRAE 不识别，需兼容输出（环境侧 adapter 计划） |
| WorkBuddy | V3 遗留插件 `ldvh@ldvh-local`（含整套 V3 specs 副本，违反薄引用，已禁用） | 清理，进 Human Gate |
| WorkBuddy | shell 陷阱：LDVH CLI 不显式提供 stdin 会被 SIGKILL（exit 137） | 已实证；是合规的 Pitfall 候选（经 Helper 受控创建） |
| Codex Desktop | Skill 位于 `~/.claude/skills`，非 Codex 稳定发现位置 | 迁至 `.agents/skills/ldvh/SKILL.md`（仓库级或用户级） |
| 全环境 | Git Gate 真实 commit 阻断行为未实测 | 一次受控测试提交（含一个应被拒反例），各环境通用 |

### 6. Skill 分发方式仍是缺口

三份报告（WorkBuddy、Codex Desktop、TRAE）都触及同一问题：静态 Skill 必须写死本机绝对路径，升级后需人工同步；spark-0039 倾向的"Helper 生成式渲染"当前无公开入口。**这坐实了 spark-0039 第 4 项中"生成式分发"的必要性。**

## 四、对 spark-0039 决策的回验

| 决策点 | 六环境证据 | 结论 |
|---|---|---|
| 单一薄 Skill 默认接入 | 全环境技能机制可用；无任何环境需要插件作为唯一信息层 | **成立，维持** |
| 插件证据触发 | 2/6 环境已验证注入价值且已有部署；4/6 未验证或未配置 | **成立，维持**；TRAE 修复格式后可视同候选 |
