---

## 一、本文定位

本文定义多角色思考行动模型的功能审计检查。功能审计用于确认多角色思考行动在持续使用中是否仍符合 41 主文件、41.01-41.07 执行文件、04 AI 协作规范、05 工具规范和 07 行动模型基础规范。

本文不执行实际审计，不替代审计行动模型。本文只定义多角色思考功能本身的审计标准。

---

## 二、审计目标

多角色思考功能审计的目标是发现：

1. 是否滥用多角色思考；
2. 是否在简单场景过度分析；
3. 是否遗漏复杂场景中的多角色思考；
4. 是否让 Skill 调度 Agent；
5. 是否在未确认 Agent 前提时声称执行 Agent 增强分析；
6. 是否将报告输出直接当作稳定事实；
7. 是否绕过 Human Gate；
8. 是否缺少 Change 记录；
9. 是否存在 Rules、Skill、Agent、Tools 辅助或 Web 展示层与 41 主文件不一致。

---

## 三、审计范围

审计范围包括：

1. 41 主文件；
2. 41.01-41.07 执行文件；
3. 相关 Rules 摘要或 L2 场景规则；
4. 多角色思考 Skill 实体，若已创建；
5. 多角色思考 Agent 增强使用记录，若存在；
6. Tools 辅助实现，若存在；
7. Web 展示实现，若存在；
8. 相关 Change、Task、ADR、Memo、Risk、Evidence 或 docs 报告。

---

## 四、审计检查项

| 检查项 | 标准 | 风险等级 |
|---|---|---|
| 准入 | 多角色思考用于复杂、跨视角或高影响场景 | 中 |
| 反滥用 | 简单问题未被强制进入多角色思考 | 低 |
| Context | 分析来源可追溯到用户输入或 Git 文件事实源 | 高 |
| Scenario | 进入条件符合 41 主文件 | 中 |
| 模式选择 | 轻量、Skill、Agent 增强模式选择有理由 | 中 |
| Skill 边界 | Skill 未调度 Agent | 高 |
| Agent 前提 | Agent 增强模式已确认 Trae 预制 Agent 可用 | 高 |
| Agent 输出 | Agent 输出返回主控汇总，未直接成为事实源 | 高 |
| Tools 边界 | Tools 辅助未调用 AI、Skill 或 Agent | 高 |
| 展示边界 | Web 展示未直接调用 AI、Skill 或 Agent | 高 |
| 事实源 | 稳定结论已写入正确 Git 文件事实源 | 高 |
| 报告边界 | 过程分析未被冒充为稳定事实 | 高 |
| Human Gate | 高影响建议已暂停确认 | 高 |
| Change | 文件变更已创建 Change YAML | 高 |
| 一致性 | 41.01-41.07 与 41 主文件无冲突 | 中 |

---

## 五、漂移检查

以下情况表示功能发生漂移，应修正或触发 Human Gate：

1. Rules 摘要复制了完整 SOP；
2. Skill 实体开始调度 Agent；
3. Agent 增强模式不再检查 Trae 预制 Agent 前提；
4. Tools 辅助开始调用 AI 或自动写入事实源；
5. Web 展示层开始维护独立确认状态；
6. 报告输出被下游直接引用为稳定事实；
7. 旧版 `pm-kit-multi-role-analysis` 被当作当前 LDVH 权威规则；
8. 41.01-41.07 与 41 主文件规则冲突；
9. 新增 Skill、Agent 或工具实现没有 Change 记录。

---

## 六、审计流程

建议审计流程：

1. 读取 41 主文件和 41.01-41.07；
2. 读取相关 04、05、07 基础规范；
3. 查找实际 Rules、Skill、Agent、Tools 辅助和 Web 展示实现；
4. 抽样检查多角色思考报告或执行记录；
5. 检查 Agent 增强模式是否声明前提和降级；
6. 检查稳定结论是否正确回写；
7. 检查高影响动作是否有 Human Gate 证据；
8. 检查文件变更是否有 Change；
9. 输出审计结论、风险、修复建议和待确认事项。

---

## 七、审计输出格式

```text
多角色思考功能审计报告：
- 审计范围：{文件 / 实现 / 报告 / 对象}
- 总体结论：通过 / 部分通过 / 不通过
- 高风险问题：{列表}
- 中风险问题：{列表}
- 低风险问题：{列表}
- 漂移项：{列表}
- Human Gate 待确认：{列表}
- 修复建议：{列表}
- 需要回写的事实源：{列表}
```

审计报告若需要长期保留，应按事实源边界写入 docs/ 或对应对象实例；否则仅作为当前过程输出。

---

## 八、Human Gate

以下审计发现必须触发 Human Gate：

1. Skill 实体调度 Agent；
2. Agent 增强模式绕过前提检查；
3. 工具或展示层直接调用 AI、Skill 或 Agent；
4. UI 状态、缓存或报告输出被作为稳定事实；
5. 高影响建议已被执行但没有 Human Gate 证据；
6. 需要修改 41 主文件、执行文件、Rules、Skill、Agent 或工具边界。

---

## 九、检查要求

| 检查项 | 标准 |
|---|---|
| 审计完整 | 覆盖 41 主文件、执行文件和实际实现 |
| 风险分级 | 高 / 中 / 低风险明确 |
| 漂移识别 | 能识别 Skill、Agent、Tools、Web 和事实源漂移 |
| Human Gate | 高影响问题已列为待确认 |
| 回写 | 稳定审计结论按事实源边界处理 |
| 修复建议 | 建议动作明确且不越权执行 |

---

## 十、待补齐事项

1. 审计报告是否创建专门对象实例待对象规范完善后决定；
2. 审计抽样规则待实践验证；
3. 与项目审计行动模型的衔接待 48 项目审计规范创建后补齐；
4. 自动漂移检查工具待 `41.04-Tools.md` 和工具实现稳定后补齐。
