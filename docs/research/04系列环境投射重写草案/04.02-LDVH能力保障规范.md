# LDVH 能力保障规范

> 创建日期：2026-06-11
> 定位：定义 LDVH 如何建设、选择和组合能力，以保障正式规范提出的落地要求
> 适用范围：Rules / Instructions、Skill、Command、Agent、Hook、Code、Web、Human Gate、CI、工作流程、人工降级检查和能力缺口分流
> 草案性质：调研区重写草案，不是正式规范；正式吸收前不得替代 `docs/specs/04.02-环境适配与运行投影规范.md` 或 `docs/specs/04.03-环境能力清单与投射规范.md`
> 上位依据：`04-规范落地与环境投射基础规范.md`、`04.01-规范落地要求与类型规范.md`
> 参考来源：`docs/specs/04.02-环境适配与运行投影规范.md`、`docs/specs/04.03-环境能力清单与投射规范.md`、`docs/research/26-LDVH环境投射技术经验吸收研究.md`

---
## 1. 本文解决的问题

本文解决 LDVH 如何满足规范落地要求的问题。

04.01 只说明正式规范提出了什么要求；本文说明 LDVH 应准备哪些能力、如何组合这些能力、能力不足时如何形成建设需求或降级检查。环境能力清单和具体投射方式由 04.03 处理。

LDVH 能力保障不是平台能力盘点。即使当前主用平台缺少某项能力，LDVH 仍可以为了其他平台、Code、CI、Web 或后续演进建设该能力。

---
## 2. 能力保障池

LDVH 当前能力保障池包括以下类型：

| 能力 | 适合保障 | 不适合保障 | 边界 |
|---|---|---|---|
| Rules / Instructions / AI 入口 | 入口可见、硬约束摘要、事实源边界、最小读取顺序、STOP 点 | 完整规范正文、低频流程、临时判断、状态记录 | 只做薄入口和导航，不是事实源 |
| Skill | 流程复用、多步骤 SOP、稳定输入输出、检查步骤 | 稳定规则正文、Human Gate 判断本身、独立上下文 | Skill 不能替代正式规范，不能调度子 Agent 作为默认假设 |
| Command | 显式流程入口、重复 Prompt、命令包装、Code 调用 | 平台事实源、长期状态、绕过审批的自动写入 | Command 是入口或执行包装，不是事实源 |
| Agent / subagent | 独立上下文、专项审查、并行视角、复杂争议 | 简单问答、单文件小改、稳定结论直接生效 | 输出必须回主控，稳定结论回写后才生效 |
| Hook / lifecycle | 生命周期触发、提交前后检查、工具调用前后检查、会话停止检查 | 规范正文、语义判断、无授权写入 | 触发不等于通过，必须受 Human Gate 和 Code 约束 |
| Code / CI / 测试 | 解析、校验、聚合、受控写入、漂移检查、确定性执行 | Human 授权、价值判断、复杂语义结论 | Code 按 07 规范实现，输出需分流回事实源 |
| Web / Human 入口 | 态势呈现、确认、授权、验收、受控轻写入 | 第二事实源、绕过 Code 校验的后台 | Web 是派生视图和交互面，不维护独立事实 |
| 人工降级检查 | 平台能力不足、机制未实现、证据不足时的显式替代 | 假装完整支持、长期静默跳过 | 必须记录残留风险和后续补齐事项 |

## 3. 要求到能力的默认映射

| 规范落地要求 | 默认能力保障组合 | 常见补充 |
|---|---|---|
| 上位约束承接要求 | 规范引用、索引、入口摘要、42 检查、Code 引用检查 | Human Gate、ADR、Task |
| 入口可见要求 | Rules / Instructions、AI 统一入口、薄引用、40 索引 | Skill 入口、Command、平台说明 |
| 流程复用要求 | Skill、Command、工作流程、操作清单 | Code wrapper、Web 表单、Task 模板 |
| 子 Agent 思考要求 | Agent / subagent、44 多角色思考、主控汇总 | Human Gate、审阅清单、并行工作区 |
| 确定性执行要求 | Code、命令入口、CI、测试、结构化输出 | Web 展示、Command 包装、Task 验证 |
| Human 交互要求 | Human Gate、Web、结构化问询、对话确认 | diff、预览、审批提示、风险说明 |
| 生命周期触发要求 | Hook、CI、自动运行、命令检查、人工降级检查 | Skill 提醒、入口 STOP 点、42 增量检查 |

默认映射只是 LDVH 的起点。具体环境投射时，04.03 应根据平台客观能力清单决定原生投射、适配投射、指令投射、人工降级或待确认。

## 4. 能力选择原则

LDVH 选择能力保障时，应遵守以下原则：

1. **要求先行**：先读取 04.01 或正式规范中的落地要求，再选择能力；
2. **组合优先**：重要要求通常需要入口、流程、Code、Human Gate 或触发机制组合保障；
3. **强路径保留**：某平台缺少能力时，不删除 LDVH 对强平台或 Code / CI 的高质量能力路径；
4. **薄入口优先**：入口类能力只保留导航、触发、STOP 点和权威引用；
5. **确定性外移**：能机械判断的规则应优先进入 Code、测试或 CI；
6. **授权前置**：高影响写入、长期配置、权限扩大和完整支持声明必须 Human Gate；
7. **证据回写**：能力输出中的稳定事实必须回写到 Git 文件事实源。

---
## 5. 能力缺口处理

当 LDVH 能力不足以保障某项落地要求时，应按以下顺序处理：

1. 检查是否已有正式规范、Code、Skill、Command、Web、工作流程或人工检查可复用；
2. 若已有能力只需扩展，应形成最小扩展和验证方式；
3. 若能力不存在，应形成能力建设需求，说明来源要求、输入、输出、失败条件、验证方式和降级方式；
4. 若当前平台不支持，应在 04.03 对该平台记录投射降级，不降低 LDVH 要求；
5. 若涉及高影响写入、权限、长期配置或完整支持声明，应触发 Human Gate；
6. 稳定需求应分流到 Task、ADR、Memo、Code 需求、Web 需求或正式规范。

能力缺口不得通过以下方式解决：

1. 删除正式规范中的落地要求；
2. 把弱平台的限制写成 LDVH 全局限制；
3. 宣称 Skill 可以替代 Hook、Code、Human Gate 或 Agent；
4. 把人工降级写成完整支持；
5. 把 research、refs 或工具输出直接写成事实源。

---
## 6. 运行投影边界

能力保障进入平台后会形成运行投影。运行投影可以是：

1. 入口摘要或薄引用；
2. Skill、Command、Agent、Hook、CI 或 Web 入口；
3. Code 校验命令、测试入口或报告摘要；
4. Human Gate 提示、审批记录或对话确认证据；
5. 人工降级检查方式和残留风险说明。

运行投影不得承载：

1. 与正式规范冲突的规则；
2. 完整规范正文或字段契约全文；
3. 未被正式规范吸收的 research / refs 结论；
4. 未经 Human Gate 授权的自动写入；
5. 被当成最终事实源的缓存、页面、工具输出或聊天摘要。

---
## 7. Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 将某项能力提升为 LDVH 全局必须能力；
2. 改变 Rules、Skill、Agent、Hook、Code、Web、Command 或 Human Gate 的边界；
3. 允许能力输出直接成为最终事实源；
4. 新增稳定工具、自动触发或受控写入入口；
5. 允许平台能力不足时不记录降级；
6. 关闭关键能力缺口或声明能力完整可用。

能力保障检查至少包括：

| 检查项 | 标准 |
|---|---|
| 要求来源 | 能力选择来自正式规范落地要求 |
| 能力边界 | 各能力未互相替代或越权 |
| 组合完整 | 入口、流程、Code、Human Gate、触发和降级按需组合 |
| 强路径保留 | 弱平台降级未删除强平台能力路径 |
| 缺口分流 | 能力不足已进入 Task、Code、Web、ADR、Memo 或 open item |
| 回写边界 | 过程输出稳定后回写 Git 文件事实源 |

## 8. 规范落地要求

| 落地要求 | 要求内容 | 保障机制 | 同步类型 | 触发条件 |
|---|---|---|---|---|
| 上位约束承接要求 | LDVH 能力保障应遵守 04 父文档和 04.01 的要求先行原则 | 本文、04.01、Human Gate | 能力治理 | 能力池、能力边界或默认映射变化时 |
| 入口可见要求 | AI 判断能力保障时应能定位本文 | 04 父文档、入口摘要、42 引用 | AI 执行入口提示 | 本文标题、定位、能力表或映射表变化时 |
| 流程复用要求 | 能力选择和缺口处理应形成可复用流程 | Skill、Command、工作流程、人工检查 | 流程复用 | 新增能力类型或处理能力缺口时 |
| 确定性执行要求 | 后续 Code 应能检查能力字段、运行投影边界和缺口分流 | `tools/specs_validate.py` 扩展、测试样例 | 校验实现 | 能力保障字段稳定或正式吸收时 |
| Human 交互要求 | 新增稳定能力、自动触发、受控写入和完整支持声明前应暂停确认 | Human Gate、Web、对话确认 | 能力治理确认 | 高影响能力建设或长期运行投影创建时 |
| 生命周期触发要求 | 能力、规范、Code、Web、Skill、Agent、Hook 或平台 refs 变化后，应检查能力保障是否同步 | Hook、CI、42、人工降级检查 | 触发保障 | 能力边界或能力资产变化时 |
