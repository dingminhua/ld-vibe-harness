## 证据对象与作用边界

Working Tree 测试证据对象把一次 full-v4 运行开始前与结束后的同一实际 Git worktree 内容绑定到可比较指纹。机器契约值固定为 `ldvh-working-tree-evidence/1`。

该对象只证明固定政策覆盖的 Working Tree 普通文件 bytes 是否被完整观察且在两次观察之间保持不变。它不表示：

1. 文件已经 tracked、staged、committed 或进入 Git history；
2. 测试步骤已通过、原始输出完整、领域结论成立或工作已完成；
3. 被排除的工具环境、依赖安装、缓存、生成物或外部环境已被指纹绑定；
4. 文件内容在语义上正确、等价或有效。

`HEAD`、Index、Git status、`.gitignore`、tracked 集合和 `dirty` 标志都不参与确定覆盖文件或计算内容指纹。dirty、untracked、ignored、staged 和 committed 的文件只要命中纳入政策且未命中排除政策，就必须按实际 bytes 纳入。

## full-v4 Working Tree 覆盖政策

当前唯一政策标识为 `full-v4-working-tree-inputs`。政策条目的稳定引用使用 `<attachment_key>::<policy-key>`；纳入与排除引用分别进入 DTO 的 `include_policy_refs` 和 `exclude_policy_refs`。

| policy-key | effect | path-rules | 边界 |
|---|---|---|---|
| `full-v4-all-regular-files` | `include` | `ALL_REGULAR_FILES` | 实际 worktree root 内全部普通文件；未跟踪或被 Git ignore 不改变命中 |
| `full-v4-git-administration` | `exclude` | `ROOT:.git` | 排除 root 下名为 `.git` 的文件或完整子树，不读取 Git 管理内容 |
| `full-v4-run-evidence-output` | `exclude` | `ROOT:.ldvh-test-runs/**` | 排除当次及历史 full-v4 运行记录与原始输出，避免证据自指 |
| `full-v4-local-environments` | `exclude` | `ROOT:.venv/**`, `ROOT:web/node_modules/**` | 排除本地 Python 环境与 Web 依赖安装；锁文件及当前项目配置仍由纳入政策覆盖 |
| `full-v4-local-tool-state` | `exclude` | `ROOT:.zcode/**`, `ROOT:.githooks-v4/**` | 排除本地工具状态与已安装 Hook 副本 |
| `full-v4-generated-and-cache-output` | `exclude` | `ROOT:.pytest_cache/**`, `ROOT:.ruff_cache/**`, `ROOT:build/**`, `ROOT:dist/**`, `ROOT:web/dist/**`, `ANY_DIR:__pycache__/**`, `ANY_SUFFIX_DIR:.egg-info/**`, `ANY_SUFFIX_FILE:.pyc`, `ANY_SUFFIX_FILE:.pyo` | 排除可重建缓存与生成物；不因执行测试本身生成这些内容而过期 |
| `full-v4-platform-noise` | `exclude` | `ANY_FILE:.DS_Store` | 排除操作系统目录元数据文件 |

`ROOT:<path>` 从 worktree root 精确匹配规范化相对路径；`/**` 同时覆盖目标自身与全部后代。`ANY_DIR:<name>/**` 匹配任意层级下名称完全相同的目录及子树；`ANY_SUFFIX_DIR:<suffix>/**` 匹配任意层级下名称以该 suffix 结尾的目录及子树；`ANY_FILE:<name>` 与 `ANY_SUFFIX_FILE:<suffix>` 只匹配普通文件名。匹配区分大小写；排除先于目录下探执行。未出现在上表的 hidden 路径不得仅因 hidden 或 ignored 而排除。

已发布 policy-key 及 path-rule token 不得静默改派给其它语义。需要改变纳入或排除语义时，必须新建 policy-key 或升级契约，并使新旧政策指纹不同；不同政策指纹的 before/after 不可比较。

## Working Tree 证据 DTO 字段

DTO 是 JSON object，使用下列字段闭集，全部字段必填：

| 字段 | JSON 类型 | 要求 | 含义与边界 |
|---|---|---|---|
| `contract` | string | 固定为 `ldvh-working-tree-evidence/1` | 只标识本 DTO 契约，不是项目或测试版本 |
| `governed_project_id` | string | 非空 | 当次唯一管辖项目的配置身份 |
| `git_worktree_root` | string | 非空绝对路径 | 被采集的实际 Git worktree root；共享 common-dir 的其它 worktree 不得替代 |
| `git_common_dir` | string | 非空绝对路径 | 当次 Git 身份观察；不用于合并多个 worktree 内容 |
| `status` | string | `complete`、`stale` 或 `incomplete` | 按“状态与比较规则”确定 |
| `coverage` | object | 必填 | 使用“覆盖字段” |
| `before` | object | 必填 | 使用“Manifest 字段”；任何 full-v4 检查前的观察 |
| `after` | object 或 null | 必填 | 已尝试结束观察时使用“Manifest 字段”；尚未形成时为 `null` |
| `changes` | array | 必填 | 成员使用“变化字段”；只在两份完整 manifest 可比时承载完整机械差异 |

这些绝对路径只定位当次实际 worktree。Manifest 指纹不包含绝对路径，因此指纹相同不单独证明两个 DTO 属于同一 worktree；比较时必须同时核对项目、worktree、common-dir 和政策身份。

## 覆盖字段

`coverage` 使用以下字段闭集：

| 字段 | JSON 类型 | 要求 |
|---|---|---|
| `policy_key` | string | 固定为 `full-v4-working-tree-inputs` |
| `policy_fingerprint` | string | 64 位小写十六进制 SHA-256 |
| `include_policy_refs` | array | 非空、按 ASCII 升序、无重复；当前精确为 `working-tree-test-evidence-fields::full-v4-all-regular-files` |
| `exclude_policy_refs` | array | 非空、按 ASCII 升序、无重复；精确覆盖本附件全部当前 `exclude` 条目 |
| `status` | string | `complete` 或 `incomplete` |
| `gaps` | array | 成员使用“覆盖缺口字段”；`complete` 时为空，`incomplete` 时至少一项 |

`policy_fingerprint` 使用“指纹与路径规则”定义的 canonical JSON，对以下投影计算：`contract` 固定为 `ldvh-working-tree-coverage-policy/1`，加 `policy_key`，再加按 `policy_ref` ASCII 升序的 `rules[]`。每个 rule 精确包含 `policy_ref`、`effect` 和按 ASCII 升序的 `path_rules`；其值必须逐项等于本附件当前政策表，不对自然语言边界段落作指纹。

## Manifest 字段

`before` 和非 `null` 的 `after` 使用以下字段闭集：

| 字段 | JSON 类型 | 要求 |
|---|---|---|
| `observed_at` | string | 带 UTC 偏移的 RFC 3339 date-time |
| `status` | string | `complete` 或 `incomplete` |
| `manifest_fingerprint` | string 或 null | `complete` 时为 64 位小写 SHA-256；`incomplete` 时为 `null` |
| `file_count` | integer | 不小于 0；为当次已安全读取的 `files` 数量 |
| `byte_count` | integer | 不小于 0；精确等于 `files[].size_bytes` 之和 |
| `files` | array | 按 `path` UTF-8 bytes 升序、无重复；成员使用“Manifest 文件字段” |

Manifest 为 `incomplete` 时，`files` 可以保留确已安全读取的子集，但该子集不是完整 manifest，不计算 `manifest_fingerprint`，也不得用缺失条目推断文件不存在。

### Manifest 文件字段

`files[]` 使用字段闭集：

| 字段 | JSON 类型 | 要求 |
|---|---|---|
| `path` | string | 按“指纹与路径规则”规范化的 worktree-relative 路径 |
| `size_bytes` | integer | 不小于 0，等于被指纹原始 bytes 长度 |
| `sha256` | string | 对该文件安全读取的完整原始 bytes 计算的 64 位小写 SHA-256 |

DTO 不携带文件原文、Git 分类、mtime、权限或文本 diff。这不会把这些未绑定信息改写为已检查。

## 覆盖缺口字段

`coverage.gaps[]` 使用字段闭集：

| 字段 | JSON 类型 | 要求 |
|---|---|---|
| `stage` | string | `before`、`after` 或 `comparison` |
| `path` | string 或 null | 针对某路径时为规范化 worktree-relative 路径；针对项目、政策或整体观察时为 `null` |
| `code` | string | 只使用下表闭集 |
| `summary` | string | 非空、可定位的机械缺口说明，不推断语义结论 |

| `code` | 使用条件 |
|---|---|
| `policy_unavailable` | 当前覆盖政策或其指纹无法完整形成 |
| `traversal_unavailable` | 实际 worktree 的必需目录无法完整安全枚举 |
| `unsafe_entry` | 纳入范围出现符号链接、reparse 或无法稳定确认身份的条目 |
| `unsupported_entry` | 纳入范围出现非目录且非普通文件的条目 |
| `read_unavailable` | 命中纳入的普通文件无法完整读取 |
| `path_changed` | 路径、文件或目录在单次安全观察中变化 |
| `normalization_collision` | 两个观察路径规范化后冲突 |
| `identity_mismatch` | before/after 的项目、worktree 或 common-dir 身份不同 |
| `policy_mismatch` | before/after 的政策 key、指纹或引用集合不同 |

## 变化字段

`changes[]` 按 `path` UTF-8 bytes 升序、无重复，成员使用字段闭集：

| 字段 | JSON 类型 | 要求 |
|---|---|---|
| `path` | string | 规范化 worktree-relative 路径 |
| `kind` | string | `added`、`removed` 或 `modified` |
| `before_sha256` | string 或 null | `added` 时为 `null`；其它情况为 before 中的 64 位小写 SHA-256 |
| `after_sha256` | string 或 null | `removed` 时为 `null`；其它情况为 after 中的 64 位小写 SHA-256 |

`modified` 的两个指纹必须不同且都非 `null`。`changes` 只表达路径与 bytes 指纹差异，不从扩展名、内容或文件位置推断变化意图、实质性、责任归属或是否需要重新审核。

## 指纹与路径规则

路径先相对于 `git_worktree_root` 取得，再使用 `/` 作分隔符并转为 Unicode NFC。规范化后不得为空、绝对路径，不得包含反斜线、空或 `.`、`..` 路径段、连续 `/`；不同观察路径规范化成同一值时当次覆盖不完整。

只读取普通文件的完整原始 bytes，不转码、换行、解析或经过 Git filter。不跟随 symlink 或 reparse；文件 handle、路径拓扑或元数据不能在读取前后稳定对应时，不产生该文件的有效完整条目，并将当次 manifest 标为 `incomplete`。

Canonical JSON 对 object key 按 Unicode code point 升序，array 保持本契约指定的排序，使用 UTF-8、非 ASCII 字符不作 ASCII escape、成员与分隔符之间无空白、无末尾换行。所有指纹都对该 canonical JSON bytes 使用 SHA-256，表示为 64 位小写十六进制 string。

`manifest_fingerprint` 的指纹投影字段闭集为：`contract` 固定 `ldvh-working-tree-manifest/1`、`policy_fingerprint` 以及当次按 `path` UTF-8 bytes 升序的完整 `files`。它不包含观察时间、绝对路径、Git 状态、`HEAD`、run 状态或覆盖缺口。

## 状态与比较规则

DTO 必须符合下列唯一状态组合：

| DTO `status` | 成立条件 | `coverage.status` | `changes` |
|---|---|---|---|
| `complete` | before 和 after 均为 `complete`，项目、worktree、common-dir 与政策身份相同，且两个 manifest 指纹相同 | `complete` | 空 array |
| `stale` | before 和 after 均为 `complete` 且身份可比，但两个 manifest 指纹不同 | `complete` | 从两份完整 manifest 确定性得出的完整非空差异 |
| `incomplete` | after 为 `null`，任一 manifest 为 `incomplete`，身份或政策不可比，或比较未能完整形成 | `incomplete` | 空 array；不得把局部差异冒充完整差异 |

`stale` 只表示受覆盖内容在测试窗口中变化，不由 Code 判断哪一变化实质、是谁引入或是否可接受。`incomplete` 不表示内容一定已变，也不表示未观察路径不存在。

## 生产、纯函数与消费责任

1. 本次 A 增量可以为本契约建立最小纯函数：规范化或验证已提供路径，验证字段闭集与排序，对已提供政策投影和完整 manifest 计算 canonical 指纹，以及比较两份已提供 manifest 得出 `status` 和 `changes`。这些函数不读取文件系统、Git、进程、网络或测试记录，不判断变化的语义。
2. 后续 Working Tree 证据生产实现负责：解析当前政策，在任何 full-v4 检查前安全采集 before，在最后一个检查结束后安全采集 after，将 DTO 原样写入单一运行记录，并在 stale、incomplete 或回读不成立时按父规范降级全量运行结论。该责任不由本次 A 增量实现。
3. Human、Helper、Web 和 Codex 只消费已形成的 DTO。它们可以根据同一结构选择呈现粒度，但不得重算指纹、改写 `status`、遗漏排除范围或在自身类型、文档和页面中建立第二份 DTO Schema。这些投影不由本次 A 增量实现。
4. DTO 是测试运行的派生证据结构，不是事实对象字段或事实模型结构，不进入 `fact-object-field-registry`。需要跨行动长期保留测试结果时，仍按父规范与相应事实来源的稳定位置、引用和可证明范围处理。
