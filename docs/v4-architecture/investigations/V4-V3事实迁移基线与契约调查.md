# V4 V3 事实迁移基线与契约调查

> 记录性质：本文记录 92 个 V3 事实对象迁移的首阶段调查、PRE review 与后续契约候选。它不是规则源，不授权实例写入，也不改变 05、20–24、31 或 32。
> 调查日期：2026-07-15
> 当前阶段：正式 successor 契约与 34 行动模板；`facts/**` 必须保持为零

## 1. 当前 Human 目标与暂停边界

Human 已将当前目标调整为：暂停 Web V4 bridge 和原生 Windows 验证，把两者保留为发布前后续事项；先完成全部 92 个 V3 事实对象的逐条 V4 迁移与验证，再建立 bootstrap/resume，并完成真实跨会话 dogfood。Web bridge 的未提交工作、审核结论和残留缺口已经停放在独立本地分支，不合入 `dev-v4`、不推送。

本迁移线继续遵守两个执行约束：每阶段实施前必须由 subagent 只读 PRE review；每个完成阶段形成独立 Git 提交。暂停 Web bridge 不允许改动表现层，也不取消以后保持 UI、字段、文案和交互不变并接入 V4 Spark 的决定。暂停 Windows 不形成平台兼容结论。

## 2. PRE review 结论

首阶段审核结论为：直接写入 V4 实例 `REQUEST CHANGES`；只建立不可变基线 `PRE APPROVE`。审核确认：

- 权威输入固定为 `archive/v3/ldvh-base/` 在 commit `5c885d55a1b3fc511672f9b1007880d283382502` 的 tree `61fcd28ee85b8ae38956c644926a491006509628`；
- 闭集恰为 49 Spark、24 WorkCase、17 Study、2 Pitfall，共 92 项；
- 28 个对象、33 个时间字段缺少时区，`spark-0032.resolved_at` 只有日期；
- 13 个 closed WorkCase 中只有 6 个具有 V3 `human_closure_confirmation`，且这些记录也不等于 V4 当前版本绑定的创建/结果审核与 Human approval；
- 只有 `spark-0027` 与 `workcase-0009` 形成一组完全同标题的跨类型合并候选；
- 当前代表性 replay tests 只有四种反机械恢复样例，不能证明全量迁移。

Human 最新顺序决定足以覆盖此前“先接管 Web writer”的旧实施顺序。冻结输入位于 archive tree，生产 V3 writer 即使恢复也写根级 `ldvh-base/`，不会改写这 92 项；但验证器必须把根级新增 V3 对象报告为 `out-of-baseline`，最终收口不得静默忽略。

## 3. 不可变机器基线

`migration/v3-facts/baseline.json` 是首个机器闭集。每个源对象冻结：

- 排序稳定且唯一的 `source_key`；
- V3 类型、ID、原状态、POSIX 源路径和载体；
- byte size、SHA-256、Git blob OID、完整 snapshot commit；
- 原始 `created`、`updated` 和可取得的 `closed_at`/`resolved_at`，不修正、不补时区。

`tools/verify_v3_fact_baseline.py` 只读验证 manifest schema、commit/tree、92 项数量和状态分布、目录/文件名/type/ID 一致、YAML/Markdown 可解析、路径与 key 唯一、工作树 bytes 与冻结 blob/SHA 一致、没有源文件增删漂移，并拒绝 baseline-only 阶段出现 `facts/**` 文件。根级 `ldvh-base/` 出现旧载体对象时报告 `out-of-baseline`。

基线不包含语义映射、V4 target、状态结论或迁移完成声明；archive source 只能证明历史输入，不能单独证明当前结论、证据充分或终态成立。

## 4. 当前 blocker

Human 全局决定和 05 §7.4/34 已经关闭三个规则 blocker：V4 target 是新 successor，使用当前分配身份/创建时间；旧终态不导入 V4 终态，只能从当前类型合法初态建立；不新增历史伪类型或专用终态。closed WorkCase 仍不能直接复制为 V4 `closed`，也不得伪造 V4 review、approval、验证或当时生命周期；这已是明确规则边界，而不是待选策略。

当前仍阻断生产写入的是：

1. 尚无独立 semantic ledger Schema、source↔logical-target 双向 verifier 和稳定 `semantic_payload_sha256` dry-run；
2. 92 项尚未逐源完成类型、合法初态、保留/退出内容、证据、拆分/合并和 target 审核；
3. 尚无可恢复/幂等执行器、发布前 durable attempt intent/journal、完整回读、全图关系验证和批次 Git anchor 机制；
4. baseline/characterization verifier 仍把 zero-facts 首阶段 Gate 与永久 source-integrity 绑定，在首个实例前必须拆分。

在这些 blocker 关闭前不得创建生产 V4 迁移实例。

## 5. 后续契约候选

后续正式准入与实现应遵守：

1. 类型与状态不机械映射。`pending` 不自动为 `open`，`resolved` 不自动为 `routed`，`active` 不自动保持 current，closed WorkCase 默认重新分类其仍有价值的内容。
2. 每个 target 的 `source_refs` 至少回指全部贡献 V3 源文件及冻结 commit；archive 引用不替代当前 evidence。
3. 1:N 与 N:1 映射必须双向对称；每个 source 恰有一个主 ledger 项且最终 target 非空，每个 target 反列全部 source。
4. `related_*`、`resolved_to` 和 `input_refs` 只是关系候选；只有来源类型允许、方向真实且目标 current 时才形成 V4 relation，其它内容进入 source、正文或 ledger。
5. 全量无写 dry-run 必须稳定生成包含目标 `fact_type_key`、只排除 `object_id/created_at/updated_at` 的 canonical 语义 payload 与 `semantic_payload_sha256`，不预留最终 ID、路径或 bytes；类型变化必须使旧 dry-run 与 intent 失效。apply 消费 ID/时间并生成最终 bytes/`materialized_sha256` 后，必须先持久化绑定目标类型的 durable attempt intent，再发布 no-overwrite 目标；已有相同 durable binding 恢复/no-op，不同内容、类型、身份或指纹 fail closed，不覆盖、不盲重试。
6. 批次以稳定 batch ID 和输入/输出 tree digest 关联。对象提交不自写自身 commit SHA；最终收口提交回填前序 batch commit anchors。
7. pilot 必须同时覆盖非终态、resolved、discarded、closed WorkCase 有/无旧确认、缺时区、Study URL、拆分、合并和关系修复。

## 7. Human 全局决定

正式契约前的两个全局决定已于 2026-07-16 由 Human 明确回复“两个都按推荐”：

1. **历史身份与时间。** 推荐把全部 V4 target 视为当前新建 successor，使用新 V4 身份与迁移时点；V3 ID 和原始时间只保存在 immutable ledger/source refs，不猜测 28 个缺时区对象。
2. **无法合法归入五类型的历史对象。** 推荐坚持五类型语义重新分类，不新增“历史记录”伪类型或迁移专用终态；某项仍无合法承接时单项交还 Human。

这两个决定已解除正式契约准入前置，但不代替逐项语义审核，也不在 semantic ledger、dry-run 和可恢复能力成立前授权生产实例写入。

## 8. Decision-independent V3 source characterization

机器基线完成后，下一阶段 subagent PRE review 最初对“semantic ledger foundation”提出 `REQUEST CHANGES`：当前尚未逐项判断内容、target、状态、证据或拆分/合并，不能使用 semantic ledger 名称或完成口径。处置后，本阶段严格改为 `V3 source characterization`，不等待 §7 的两个 Human 决定即可机械建立，但不得进入正式迁移契约或实例写入。

`migration/v3-facts/source-characterization.json` 与 baseline 92 项 1:1 join，并由 `tools/verify_v3_fact_characterization.py` 确定性重建和验证。当前 artifact 只记录：

- 1,882 个顶层字段的完整 key、JSON kind、空值标志和内容 digest；
- 全部 797 个递归 time-shaped leaf，包括 `created`、`updated`、任意 `*_at` 和通用 `at`；其中 631 个带 offset、89 个 naive datetime、5 个 date-only、50 个空字符串、22 个 null，仅保留 pointer、kind、canonical digest/长度和分类，不复制原值、不补时区、不转换、不推断历史真实性；
- 3,353 个递归 legacy reference observations，按 exact fact ID、fact path、document path、URL、opaque、empty/null 等语法分类；只保留 pointer、kind、canonical digest/长度和语法分类，可唯一命中 baseline 的旧 ID 只回指 source key，全部固定 `v4_relation_decision: undecided`；
- frontmatter 与 Study body/H1/H2 section 的结构定位、长度和 digest，共 211 个 content regions，不复制或总结其语义；
- 唯一一组 exact title collision：`spark-0027` 与 `workcase-0009`，只记录机械碰撞，不形成合并候选决定；
- 每项原 V3 type/status 和“不得机械映射”的风险码。

artifact 顶层固定 `semantic_reviewed_count: 0`、`target_decided_count: 0`；每项固定 `review_state: not_started`，`target_identity`、`target_type`、`target_status` 和 `split_merge` 均为 `undecided`。验证器只读：它只能验证已有 artifact 或向 stdout render canonical JSON，不提供文件写入参数；并拒绝符号链接/非普通 artifact、任何字段增删、重复 JSON key、非 canonical bytes、baseline 漂移、观察遗漏/误分类或决策字段提前变化，并继续通过 baseline validator 保证 `facts/**` 为零。

该 characterization 只降低后续逐项审核的机械漏读风险。它不等于 semantic ledger，不表示 92 项中任何一项已经选择 V4 target、完成内容取舍、建立 V4 relation 或开始迁移。

## 9. 正式 successor 契约与 34 行动模板

Human 决定后，subagent 对 05、05.Att.01、20–24、31–33、当前 Code/tests 与迁移文档做了只读 PRE review，结论为 `APPROVE`。实施范围限定为 05 事实共同契约、05.Att.01 `created_at` 消歧、34 独立行动模板、项目决定记录和范围匹配规范/模板解析测试；明确排除 20–24、31–33、Web、Windows、executor、两个 canonical artifact 和 `facts/**`。

05 §7.4 现将来源派生的对象定义为当前新 successor：

- 只使用当前五类及其合法初态，旧终态不导入 V4 终态；
- Code 在实际创建临界区分配新 ID 与当前创建时点，旧 ID/时间只保留在冻结源和 ledger；
- 无写 dry-run 稳定的是包含目标 `fact_type_key`、只排除 `object_id/created_at/updated_at` 的 `semantic_payload_sha256`，不是最终 ID、路径或 bytes；
- apply 消费实际 ID/时间并生成 `materialized_sha256` 后，先持久化 durable attempt intent，再 no-overwrite 发布目标，并以 journal 推进、回读、冲突 fail-closed、Git anchor 和 no-op rerun 闭合；
- 不能合法承接的单项进入 Human Gate，不用伪类型、专用终态或占位内容豁免。

05.Att.01 同时明确：同一身份的载体迁移不改原 `created_at`，但依 05 §7.4 建立的 successor 使用自己实际受控创建时间；该时点不表示原始源或历史领域事件时间。

`fact-object-source-reconstruction-migration` 由 34 唯一定义，组织“冻结源核对 → 逐项语义审核 → logical target plan → 全量 dry-run → 可恢复分批应用 → 完整回读/全图 → Git anchor → no-op rerun”。它不定义 ledger Schema、allocator 算法或具体 92 项结果，也不扩张 31/32 的单对象契约。本阶段仍保持 semantic reviewed / target decided 为 0 且零生产实例；下一阶段才建立独立 semantic ledger Schema、verifier 与 source-integrity/zero-facts mode split。
