# 技能设计规范

> 创建日期：2026-05-28
> 最后更新：2026-05-28
> 定位：Skill 技能的设计模板、部署方式、创建判断流程、变更流程、检查项与标准技能目录规范
> 上位依据：`specs-v2/11-AI协作规范.md` §六

---

## 一、Skill 创建判断流程

```text
用户提出流程需求
  ↓
判断是否可复用？
  ├─ 否 → 直接在当前对话执行，不创建 Skill
  └─ 是
      ↓
判断是否需要标准化输入/输出或多步骤流程？
  ├─ 否 → 直接执行或写入 Rule 判断
  └─ 是
      ↓
判断是否需要独立上下文、结论隔离、并行委派或不同工具权限？
  ├─ 是 → 不创建 Skill，按 11-AI协作规范 §七 建议用户调用 SOLO Agent
  └─ 否 → 可设计为 Skill
```

不适合设计为 Skill 的流程：单步骤、无分支的简单操作；Human Gate 判断本身；需要独立上下文、隔离执行、并行委派或不同工具权限的流程；低频初始化子步骤。

## 二、Skill 文件结构

### 2.1 存放位置

PM Kit 提供或初始化生成的标准 Skill 统一放在工作区根，且不得在受管理项目内生成副本：

```text
.trae/skills/pm-kit-{skill-name}/SKILL.md
```

`{skill-name}` 使用小写连字符格式。PM Kit 标准 Skill 的目录名、YAML `name` 字段和规则索引引用名必须以 `pm-kit-` 开头，如 `pm-kit-multi-role-analysis`、`pm-kit-memo-writer`、`pm-kit-conversation-to-task`。受管理项目业务 Skill 不得使用 `pm-kit-` 前缀。

### 2.2 必须包含的段落

| 段落 | 必须 | 内容 |
|---|---|---|
| 定位 | 是 | Skill 解决什么问题、触发方式 |
| 触发条件 | 是 | 何时调用该 Skill |
| 执行流程 | 是 | 步骤化流程，含必要分支 |
| 必读文件 | 是 | 执行前必须读取的事实源 |
| 输出格式 | 是 | 标准化输出模板 |
| 边界声明 | 是 | 不处理的范围、Human Gate 和 Agent 边界 |

### 2.3 推荐模板

```markdown
# {Skill 名称}

> 创建日期：YYYY-MM-DD
> 最后更新：YYYY-MM-DD
> 触发方式：自动触发 / 人主动触发

## 定位

本文定义 {Skill 名称} 的触发条件、执行流程和输出规范。

## 触发条件

- 条件1：...
- 条件2：...

## 执行流程

1. 步骤1：...
2. 步骤2：...
3. 步骤3：...

## 必读文件

1. PM Kit 项目 `specs-v2/XX-XXX.md`（规范层，只读引用）
2. 受管理项目 `pm-kit-base/...`（读写目标）

## 输出格式

...

## 边界声明

- 本 Skill 不修改规则、Agent、product.yaml 或跨项目契约。
- 本 Skill 发现 Human Gate 场景时停止并提示用户确认。
- 本 Skill 不调度 Agent；需要独立上下文时建议用户调用 SOLO Agent。
```

## 三、Skill 部署检查项

Skill 创建或修改完成后，应检查：

| 检查项 | 标准 |
|---|---|
| 位置 | 位于 `.trae/skills/pm-kit-{skill-name}/SKILL.md` |
| 命名 | PM Kit 标准 Skill 使用 `pm-kit-` 前缀，小写字母、数字、连字符，目录名与 YAML `name` 一致 |
| YAML 头部 | 包含 `name` 和 `description` 字段；`description` 从模型视角描述能力和触发时机 |
| 语言约束 | `description` 字段必须使用中文 |
| 术语约束 | 所有章节标题必须使用中文，禁止使用英文术语 |
| 顺序约束 | 段落顺序符合标准：YAML 头部 → 元信息 → 定位 → 触发条件 → 不适用场景 → 必读文件 → 执行流程 → 输出格式 → 边界声明 |
| 格式约束 | 包含创建日期、最后更新、触发方式元信息 |
| 边界 | 明确不修改规则、Agent、product.yaml 等管理资产，并声明不适用场景 |
| Human Gate | 引用 11-AI协作规范 §十二，不维护第二套清单 |
| Agent 边界 | 明确不调度 Agent |
| 事实源 | 只读取或写入目标项目事实源，不自成事实源 |
| 路径归属 | 必读文件和执行流程中的路径必须区分 PM Kit 项目路径与受管理项目路径，不得用"当前项目"等模糊表述（见 11-AI协作规范 §四.6） |
| 失败处理 | 写入型 Skill 必须声明失败处理，重要 Skill 修改后需要评测回归 |
| 输出格式 | 能稳定复用 |
| Change 记录 | 创建或修改后已记录 |

## 四、Skill 变更执行流程

1. 判断是创建、修改还是删除 Skill。
2. 按 11-AI协作规范 §十二 触发 Human Gate。
3. 说明触发原因、影响范围和待修改文件。
4. 用户确认后执行修改。
5. 检查 Skill 边界声明和输出格式。
6. 追加 Change 记录。
7. 提示用户确认该 Skill 在全局或当前工作区可用。

## 五、标准技能目录

### 5.1 核心技能清单

| 技能名称 | 触发场景 | 核心职责 | 事实源依赖 |
|---|---|---|---|
| `pm-kit-conversation-to-task` | 用户要求整理对话为任务 | 将对话内容整理为结构化 Task/Memo | 14.02、14.03 |
| `pm-kit-memo-writer` | 用户要求记录备忘 | 将内容写入 pm-kit-base/memos/ 并更新索引 | 14.03、10 |
| `pm-kit-multi-role-analysis` | 用户要求多角色视角分析 | 对复杂变更进行多角色独立分析 | 11.04、14.02 |
| `pm-kit-task-review` | 用户要求验收任务 | 执行任务验收检查，验证完成标准和字段完整性，生成验收报告 | 14.02 §3.4、§3.7 |

### 5.2 pm-kit-conversation-to-task（对话转任务）

**定位**：将对话内容中的可执行项整理为结构化任务（Task）或备忘（Memo），自动结合上下文判断归属。

**触发条件**：

- 用户明确要求"整理对话""对话生成任务""把刚才说的记成任务"
- 用户提供一段对话内容或讨论要点，希望系统化地记录到 pm-kit-base
- 审计或对话中发现多个可执行项，需要批量分流

**必读文件**：

1. 受管理项目 `.trae/rules/project_rules.md`
2. 受管理项目 `product.yaml`
3. 受管理项目 `pm-kit-base/tasksets/` 下所有 YAML 文件
4. 受管理项目 `pm-kit-base/tasks/` 下所有 YAML 文件
5. 受管理项目 `pm-kit-base/memos/` 下所有 YAML 文件
6. 若存在 20-89 范围的需求文档，读取以判断 taskset 归属

**决策流程**：

1. 理解上下文：读取 product.yaml 和 pm-kit-base 结构
2. 提取可执行项：从对话中提取每条独立的可执行项
3. 判断现有归属：检查是否属于已有 Task/taskset/需求文档
4. 分类决策：按 Task 准入条件（目标明确、动作明确、归属明确、验证方式明确）分流为 Task 或 Memo
5. 创建对象：生成符合规范的 YAML 文件
6. 质量检查：验证输出是否符合规范
7. 写入与同步：创建文件并写入 Change 记录

**输出格式**：

```text
对话整理完成：
- 项目：{project-name}
- 新建 Task：{n} 条
  - {TASK-ID}: {title} (→ {taskset-id 或 独立})
- 更新已有 Task：{n} 条
- 新建 Memo：{n} 条
- 跳过：{n} 条（原因：{无记录价值 / 已覆盖 / 非可执行内容}）
- 已写入 Change 记录：是 / 否
```

**边界声明**：

- 本 Skill 不修改规则、Agent、product.yaml 或跨项目契约。
- 本 Skill 不调度 Agent；需要独立上下文时建议用户调用 SOLO Agent。

### 5.3 pm-kit-memo-writer（备忘写入器）

**定位**：将用户要求的备忘写入项目事实源，确保备忘内容正确归档。

**触发条件**：

- 用户明确要求"记一下""写入备忘""保存备忘""记录到 memo"
- 用户提供的信息尚未被拆解为正式 Task 或 ADR
- 审计发现或对话内容需要作为未任务化输入进入项目事实源

**必读文件**：

1. 受管理项目 `.trae/rules/project_rules.md`
2. 受管理项目 `product.yaml`
3. 受管理项目 `pm-kit-base/memos/` 下现有文件（生成下一个 Memo ID）

**决策流程**：

1. 确认用户是否明确要求记录备忘
2. 判断内容归属（Memo/Change 记录/踩坑记录/ADR/Task）
3. 优先写入 `pm-kit-base/memos/{MEMO-ID}.yaml`
4. 追加 `pm-kit-base/changes/`

**输出格式**：

```text
备忘已写入：
- 项目：{project-name}
- 位置：{path}
- Memo ID：{memo-id 或 不适用}
- 已写入 Change 记录：是 / 否
```

**边界声明**：

- 本 Skill 不修改规则、Agent、product.yaml 或跨项目契约。
- 本 Skill 不调度 Agent；需要独立上下文时建议用户调用 SOLO Agent。

### 5.4 pm-kit-multi-role-analysis（多角色视角分析）

**定位**：对复杂变更或决策进行多专业角色独立分析，产出结构化对比报告。角色矩阵和场景映射以 11.04-多角色讨论设计规范 为事实源。

**触发条件**：

- 用户要求"从不同角色角度分析一下"
- 架构变更需要评估对多个模块的影响
- 技术选型需要多维度对比
- 需求变更需要评估多方面影响

**必读文件**：

1. 受管理项目 `.trae/rules/project_rules.md`
2. 受管理项目 `product.yaml`
3. 受管理项目 `pm-kit-base/` 下相关 tasksets、tasks

**决策流程**：

1. 判断分析深度：根据变更复杂度选择轻量模式或 SOLO Agent 模式
2. 确定分析角色：根据变更类型自动匹配角色（读取 11.04 获取角色定义）
3. 执行多角色分析：按角色分别输出适用性判断、影响范围、结论、风险、建议
4. 汇总对比：产出结构化对比报告，包含一致性分析、风险汇总、建议执行顺序

**分析模式选择**：

| 模式 | 条件 | 行为 |
|---|---|---|
| 轻量模式 | 只读讨论、文件读取少，不需要独立上下文 | 在本 Skill 内执行多角色分析 |
| SOLO Agent 模式 | 影响 2 个以上项目/模块，需要独立上下文或并行分析 | 提示用户调用 SOLO Agent |

**边界声明**：

- 本 Skill 只产出分析报告，不修改任何代码文件。
- 本 Skill 不调度 Agent；需要 Agent 参与时提示用户调用 SOLO Agent。
- 角色矩阵和场景映射以 11.04-多角色讨论设计规范 为权威事实源。
- 本 Skill 不修改规则、Agent、product.yaml 或跨项目契约。

### 5.5 pm-kit-task-review（任务验收检查器）

**定位**：对处于 `Review Needed` 状态的 Task 执行自动化验收检查。检查完成后生成结构化验收报告，由用户审核确认，不自动关闭 Task。

**触发条件**：

- 用户明确要求"验收 PMKIT-018"、"检查这个任务"
- 用户提供多个任务编号要求批量验收（如"验收 PMKIT-018、PMKIT-019"）
- 用户询问某 Task 的完成质量是否可以关闭

**必读文件**：

1. 受管理项目 `product.yaml`（定位产品结构和项目路径）
2. 受管理项目 `pm-kit-base/tasks/{TASK_ID}.yaml`（验收目标）
3. 受管理项目 `pm-kit-base/tasksets/` 下所有 YAML（确认任务集归属）
4. 若存在 20-89 需求文档，读取确认任务目标和范围

**执行流程**：

1. 解析输入：接收用户提供的任务编号列表（支持单个或多个）
2. 定位任务文件：读取 `product.yaml`，遍历各项目 `pm-kit-base/tasks/` 目录定位任务 YAML
3. 前置校验：检查状态是否为 `Review Needed`、`review.required == true`、`review.status == pending`、`acceptance` 非空
4. 关闭字段校验：验证 4 个必填字段（`completion_summary`、`validation_result`、`closure_evidence`、`acceptance_result`）
5. 完成标准验证：逐条检查 `acceptance` 是否满足，读取实际文件验证变更状态
6. 生成验收报告：对每个 Task 输出结构化报告（完成标准检查表、字段完整性、发现的问题）
7. 更新 review 状态（需用户确认）：根据验收结果提示用户确认是否写入 `review` 字段
8. 输出汇总报告：批量验收时输出所有 Task 的验收汇总

**边界声明**：

- 本 Skill 不自动关闭 Task。检查完成后仅更新 `review` 字段，关闭需经 Human Gate 确认。
- 本 Skill 不修改代码。只读取和验证，不执行自动修复。
- 本 Skill 不修改规则、Agent、product.yaml 或跨项目契约。
- 本 Skill 不调度 Agent；需要独立上下文时建议用户调用 SOLO Agent。
