## 一、本文定位

本文定义 LD Vibe Harness 如何使用 MCP、Tool Calling、斜杠命令、上下文工具、Context7、Sequential Thinking、Web Search 和 Trae `.trae/specs/` 等机制，并明确这些机制的非最终事实源边界、授权边界和回写要求。

本文不重新定义 MCP 协议、Trae Tool Calling 或 Trae 斜杠命令的官方能力，只定义它们在 LDVH 中的使用约束。

## 二、父规范关系

`specs/04-LDVH-Trae机制规范.md` 定义 Trae 机制总边界和事实源回写总原则。本文只展开 MCP 与工具调用机制。

与其他机制关系：

| 对象 | 关系 |
|---|---|
| Rules | Rules 可声明高风险工具门禁和项目级 MCP 约束 |
| Skill | Skill 可使用工具能力，但不得绕过授权和 Human Gate |
| Agent | Agent 可配置 MCP 和工具权限，但应最小授权 |
| 事实源规范 | 工具输出必须按 `specs/03-事实源边界与承载规范.md` 回写后才成为稳定事实 |
| LDVH 工具 | 后续 05 定义 LDVH 自有工具实现边界，本文只定义 Trae 机制边界 |

## 三、MCP 边界

MCP 是连接外部工具和服务的协议层，不是规则、知识库或最终事实源。

LDVH 使用 MCP 时应遵守：

1. MCP Server 是工具供应链入口，应按外部依赖和权限边界管理；
2. 项目级 `.trae/mcp.json` 属于高影响配置，创建、修改、删除或启用应评估 Human Gate；
3. MCP 配置不得包含明文密钥、Token、Access Key 或其他秘密；
4. MCP Server 命令、包来源、远程 URL 和权限范围必须可信、最小必要；
5. MCP 返回内容默认是工具结果或外部资料，不是最终事实源；
6. MCP 输出形成稳定结论时，必须回写到 specs/、ldvh-base/、docs/ 或 references/ 对应位置。

高风险 MCP 包括但不限于：

| 类型 | 风险 |
|---|---|
| 文件写入 | 可能绕过事实源边界或覆盖项目文件 |
| 命令执行 | 可能执行破坏性命令或泄露环境信息 |
| 远程服务 | 可能泄露项目内容或依赖外部不稳定结果 |
| 凭据访问 | 可能暴露密钥、Token 或账号信息 |
| Git/发布 | 可能执行 commit、push、tag、release 等高影响操作 |

## 四、Tool Calling 边界

Tool Calling 是 AI 调用工具的执行机制。工具调用结果用于辅助读取、搜索、诊断、运行、验证或展示，不自动成为稳定事实。

使用 Tool Calling 应遵守：

1. 读取型工具可用于理解项目事实，但结论应以 Git 文件事实源为准；
2. 写入型工具必须遵守事实源边界和 Human Gate；
3. 运行命令、测试、构建或校验时，应记录可复查的命令和结果摘要；
4. 工具输出不得被编造成事实，不确定时应再次读取文件或运行校验；
5. 工具缓存、数据库派生视图、运行时索引和页面状态不得成为唯一事实源；
6. 涉及删除、发布、远程 Git、密钥、权限或不可逆操作时，应评估 Human Gate。

## 五、斜杠命令边界

Trae 斜杠命令可作为过程控制入口，例如计划、生成 Spec、继续任务、取消任务、调试、解释、生成文档、检查或清空上下文。

LDVH 对斜杠命令的使用边界：

1. 斜杠命令产生的计划、任务清单或解释默认是过程资产；
2. `/plan`、`/spec` 可作为需求澄清和任务拆解辅助，但不自动替代 specs/、ldvh-base/ 或 docs/；
3. `/debug`、`/lint`、`/explain` 等命令的输出应作为诊断或验证证据的输入，不直接成为最终事实；
4. `/docs` 生成的文档必须经事实源边界检查后，才能写入正式文档位置；
5. `/clear`、`/continue` 等命令只影响对话过程，不改变 Git 文件事实源。

## 六、上下文工具边界

Trae 上下文工具可将文件、目录、文档、问题、网页、代码片段、规则或历史对话注入当前上下文。

LDVH 使用上下文工具时应遵守：

| 上下文来源 | LDVH 处理原则 |
|---|---|
| `#File` / `#Folder` | 可作为读取入口，仍需确认文件所属项目和 L1 规则 |
| `#Doc` | 可作为外部资料或官方文档参考，不直接成为项目事实 |
| `#Problems` | 可作为诊断输入，修复结果需通过代码和验证回写 |
| `#Web` | 可作为外部资料，稳定引用应写入 references/ 或正式规范引用 |
| `#Code` | 可作为片段输入，不能替代仓库真实文件 |
| `#Workspace` | 上下文较大时应警惕过载，仍需按最小可行动上下文读取 |
| `#Rule` | 可手动触发规则，优先级高于自动匹配 |
| `#PastChats` | 历史对话不是最终事实源，稳定事实必须回写 Git 文件 |

## 七、Context7 与 Sequential Thinking

Context7 和 Sequential Thinking 等 MCP 或外部工具可用于提高资料检索和结构化推理质量，但它们的输出仍属于工具结果。

使用原则：

1. Context7 适合查询框架、库或工具的最新官方文档；
2. Sequential Thinking 适合复杂业务逻辑拆解、跨项目影响分析、Bug 根因排查、技术选型和数据流追踪；
3. 两者输出都应标注来源和适用范围；
4. 涉及稳定结论、方案、决策或规则时，必须写入对应 Git 文件事实源；
5. 外部文档与项目事实冲突时，以项目 Git 文件事实源为准；
6. 外部资料需要长期保留时，应进入 references/，不得直接作为强制规范。

## 八、Trae `.trae/specs/` 过程资产

Trae `.trae/specs/` 下的 spec、tasks、checklist 等文件是 Plan/Spec 过程资产。它们可以辅助需求澄清、方案设计、任务拆解和验收检查，但不自动替代 LDVH 正式事实源。

处理规则：

1. approved spec 可作为执行输入和任务范围依据；
2. tasks.md 可作为执行进度清单，但不替代 `ldvh-base/` 中的生产对象实例；
3. checklist.md 可作为检查输入，但不替代正式验收证据；
4. 过程资产中的稳定需求、决策、任务或证据，应按事实源边界回写到 specs/、ldvh-base/ 或 docs/；
5. 勾选 tasks.md 表示本次过程任务完成，不表示对应项目事实已稳定，除非已完成回写和验证。

## 九、Human Gate 与检查要求

以下情况应评估 Human Gate：

1. 创建、修改、删除或启用项目级 `.trae/mcp.json`；
2. 添加、移除或调整 MCP Server 权限、命令、远程 URL、环境变量或鉴权方式；
3. 使用工具执行删除、覆盖、发布、远程 Git、权限修改或不可逆操作；
4. 将 MCP、Tool Calling、斜杠命令、上下文工具或 Trae `.trae/specs/` 输出提升为稳定事实；
5. 把外部文档、网页或历史对话直接作为强制规范；
6. 在可提交文件中写入密钥、Token 或私密配置。

MCP 与工具调用检查至少包括：

| 检查项 | 标准 |
|---|---|
| 非事实源 | 工具输出未替代 Git 文件事实源 |
| 最小授权 | MCP 和工具权限最小必要 |
| 密钥安全 | 未写入明文密钥或 Token |
| 来源可信 | 外部工具、包、URL 或文档来源已评估 |
| Human Gate | 高风险操作已暂停确认 |
| 回写完成 | 稳定结论已写入对应事实源 |
| Change 记录 | 高影响配置或文档变更已记录 |
